# 目标导向设计 (Goal-Directed Design - GDD)

> 基于交互设计之父 Alan Cooper《About Face: 交互设计精髓》核心方法论。  
> **核心立意**：软件的存在是为了帮人类达成**最终目标 (End-Goal)**，而不是逼人类去理解程序员的**实现模型 (Implementation Model)**。

---

## 一、三模型黄金法则（The Three Models）

任何业务功能或交互设计，必须先过三模型对账：

```
┌─────────────────────────┐        ┌─────────────────────────┐
│ 用户心智模型             │        │ 程序员实现模型          │
│ (Mental Model)          │  VS    │ (Implementation Model)  │
│ 用户以为系统怎么运作    │        │ 数据库/表/接口实际长怎样│
└────────────┬────────────┘        └────────────┬────────────┘
             │                                  │
             │       ┌──────────────────┐       │
             └──────►│ 呈现模型 (UI/UX) │◄──────┘
                     │ (Represented)    │
                     └──────────────────┘
```

* **及格线 (30-60 分)**：呈现模型向「实现模型」妥协。
  * *典型翻车*：因为数据库分了 `fulfillment_appeals` 表和 `daily_reports` 表，所以让用户填完数据后被拦截，把数据丢了只交申请，批完还要用户再去填第二张表。
* **满分标准 (99-100 分)**：呈现模型 100% 映射「心智模型」。
  * *满分做法*：用户的心智是“我交的是日报”，系统在后台默默帮他把申请、暂存、审批、自动入库全链条串好，用户 0 感知。

## 二、残酷剔除「软件垃圾操作」(Eliminate Excise)

**Excise（额外消耗）**：指软件强加给用户的、对达成最终业务目标毫无价值的操作。**所有 Excise 均为 0 分设计，必须无情砍掉！**

### 1. 常见 Excise 违规清单与 100 分重构对照

| 违规类型 | 典型低级错误 (Excise) | 100 分 GDD 重构标准 |
| :--- | :--- | :--- |
| **二次输入 Excise** | 填好一整张表单被拦截，申请通过后要求用户重新填一遍。 | **数据自动暂存，审批通过瞬间后台原子入库，用户无需再填。** |
| **导航跳飞 Excise** | 审批人在待办卡片想看详情，点击直接整页跳到全站大盘。 | **原地展开 (In-place Expansion)，上下文 0 丢失，视线不离工作台。** |
| **确认确认再确认** | 领导点击“同意”，还要弹窗问“确定同意吗？”，同意完还要点“完成”。 | **一键决策即生效，提供 5 秒 Undo（撤回气垫），不弹多余确认窗。** |
| **多余通知回跳** | 审批通过后发通知：“请点击去上传”，用户点进去再点提交。 | **直接通知：“您的数据已通过并已自动录入”，提供“查看结果”即可。** |
| **状态孤儿** | 审批完之后，已审批的卡片依然挂在待办列表里。 | **即时消解 (Instant Dismiss)，关联同源待办全部自动关闭。** |

## 三、四大交互心流原则 (Flow & Harmony)

1. **就地解决原则 (In-place Interaction)**：
   * 所有针对单项任务的查看、修改、决策，优先在当前卡片/抽屉内完成，绝不无故进行整页路由跳转 (`router.push`)。
2. **主动性自动化 (Proactive Automation)**：
   * 凡是机器可以通过逻辑自动推导或自动完成的步骤，绝不推给人类去手动点击。
3. **确定性与安全感 (Deterministic Safety)**：
   * 操作前清楚告知后果（“驳回将附带原因通知成员”）；
   * 破坏性操作提供撤回能力或缓冲期，不给用户心理压力。
4. **状态与实体强一致 (State-Entity Fidelity)**：
   * 按钮文案必须精准对应真实发生的业务事实（例如：“同意补交” vs “直接改判”；决不能在数据未录入前谎报完成）。

## 四、GDD 验收自查清单 (Checklist)

在提交任何交互或业务流程设计前，逐条打勾：

- [ ] **最终目标对齐**：用户完成这个任务的真正目的是什么？当前流程是不是最直接的路径？
- [ ] **零重复输入**：是否有任何分支会让用户重复输入或重新选择已经提供过的信息？
- [ ] **零跳飞打断**：审批人/操作人是否能原地完成闭环而无需切换大页面？
- [ ] **机器代劳闭环**：在权限通过/状态变更时，后续的数据持久化是否已由系统自动完成？
- [ ] **心流连续性**：操作完成后，界面是否顺畅推进到下一个自然状态，而不是把用户甩在半空？
