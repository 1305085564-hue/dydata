## 一、最终架构（一句话版）

两张日报截图（互动图/留存图）→ 上传 Supabase storage → `/api/ocr-screenshot` → **百度网络图片文字识别提字（~0.3-0.7s）→ 文字大模型结构化成字段（~2.2s）** → 前端确认回填。视觉大模型链路完整保留为回退通道，后台一键切换。

## 三、运维要点（出问题按此排查）

### 通道切换（回滚保命符）

- 位置：后台 AI 配置 → 「截图识别·看图回退」设置弹窗 → 「识别通道」下拉
- 取值存 `ai_feature_bindings.channel_settings.ocr_screenshot_channel`（baidu | vision），**保存即生效无需发版**
- 已实测：vision ↔ baidu 双向切换均即时生效

### 模型绑定拆分（决策记录）

- `ocr_screenshot_structure` = 文字模型干"字段对号入座"
- `ocr_screenshot` = 视觉模型干"直接看图"，**这个绑定必须保持视觉模型，换便宜文本模型会让回退悄悄失效**
- 两键都在 `manage_ai_feature_lifecycle` 白名单里

### 错误码映射（百度 → 站内）

- 110/111 token失效 → 自动刷新重试一次（不是限流）
- 18 QPS超限 → RATE_LIMITED；17/19/216604 额度类 → 通道不可用告警
- 216201/216202/216205/282100 图片问题 → 提示重传/手填；282000 → 超时语义

## 四、踩坑记录（方法论级）

1. **百度传图必须 base64**：二进制 urlencode 实测报 282100 transcode error；且站内允许 8MB 但百度 base64 上限 4M，超限走前置拦截降级手填
2. **生产 API 是 cookie 鉴权不吃 Bearer**：脚本调接口要构造 `sb-<ref>-auth-token` cookie，值为 `base64url(session JSON)` 且带 `base64-` 前缀，路径校验要求图片属于当前登录用户
3. **`supabase db push` 会被乱序 migration 卡死**：076 文件时间戳早于远端最后一条导致 push 中止且不报错明显；解法是临时移开乱序文件→push→还原
4. **查 bindings 表别 select 不存在的列**：`is_active` 不存在（实际叫 `is_enabled`），整条查询静默返回 null，会误判成"没有这行数据"
5. **视觉链路和文字链路共用 featureKey 会互相误伤**：已拆双键解决；以后新增 AI 功能同理，"整理文本"和"看图"不要共用绑定
