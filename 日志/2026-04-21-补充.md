# 2026-04-21 补充日志

## 决策背景
原“数据录入与审核”页面的所有模块呈上下流式堆叠，用户操作时需要在图片和表单间反复滚动。为了提高录入比对体验，决定重构为 50/50 分栏，左侧放原始截图素材，右侧放数据表单，并加入输入焦点联动截图高亮功能。

## 问题经过 & 关键转折
1. **联动语义映射错误**：初步重构时，机械地把 `follower_convert`（导粉数）留在了高亮 `screenshot_1` 的分组中，导致焦点错位。Codex 审查指出后，单独拆出将其映射到 `screenshot_3`。
2. **折叠态高亮失效**：导粉截图（截图 3）根据需求设置为了“默认折叠”仅显示展开按钮。起初的联动高亮只写在展开后的卡片容器上。Codex 复审指出后，紧急给占位按钮也增加了 `isHighlighted` 的高亮边框样式。
3. **UI 库 API 误用（P1问题）**：起初试图在 `DialogTrigger` 上使用 `asChild` 挂载原生 `div` 作为 Lightbox 入口，触发了 TypeScript 报错（`TS2322`）。排查项目 `components/ui/dialog.tsx` 后发现，此项目基于 base-ui 的封装使用的是 `render={<div/>}`，而非 Radix 的 `asChild`。更换 API 后顺利解决。
4. **重构时的机械复制**：在将 `videoTitle` 和 `videoUrl` 分别套壳时，顺手复制了包裹层的 `data-missing` 校验条件，导致没填标题时，视频链接也会变红。排查后已清除非必填项的不当绑定。

## 被排除方案
- **直接使用三方 Lightbox 库**：由于项目内本身已有较完善的 Dialog 和动画体系，为了避免引入额外体积包，排除了三方库，选择基于现有的 `<Dialog>` 直接封装修饰。
- **Grid 硬分割**：排除了生硬的 `border` 分割线，选用背景色差、透明度 (`bg-white/70`) 和弥散阴影作软分隔，保证视觉轻量化。

- **视频提交页面 50/50 布局高度不对齐及视觉重构**:
  - **背景**：此前左右两列 50% 布局下，因左侧截图区域比右侧指标区高，导致跟着它们的下方组件（视频链接元数据 vs 文案提取区）基线完全错位，对齐度极差；此外悬浮提交条（FAB）过于扁平宽大缺乏高级感，且截图预览的四周留白过多压缩了图片可视面积。
  - **核心解法**：
    1. **横向切片**：抛弃左右列布局，改为上下分布的两行。第一行为“截图区+指标区”，第二行为“元数据+文案”。配合 `items-stretch` 实现了跨列绝对对齐。
    2. **降级卡片**：剥离 `指标分组区` 外层的 `MotionCard`，将标题和输入区域直接贴合背景，做到与左侧“截图槽位区”结构上的镜像对称。
    3. **极致压缩留白**：将 `截图槽位卡` 重组为左侧纯图片、右侧展示识别结果，将标签（必传、状态等）改为毛玻璃悬浮 Badge 悬浮于图片左上方，实现左侧容器被图片完全填满，可视面积显著提升。
    4. **优化 FAB**：在底部操作条引入毛玻璃（`backdrop-blur-2xl`）、深层弥散阴影和微边缘发光（border-white），同时收缩两侧冗余宽度，仅保留指示灯和报错文本。
  - **验证**：Codex 定点 Code Review，解决了一个由于重构产生的 JSX `div` 未闭合导致的解析错误。最终无任何冗余未使用变量，ESLint 零错误。
