# Antigravity 全量错误复盘提示词

## 使用方式
把下面这段提示词完整粘贴给 Antigravity IDE（或任何能读本地文件的 AI），它会自动扫描 138 份对话记录，提取所有犯过的错误。

---

## 提示词正文

```
你的任务：扫描 Antigravity 的全部历史对话记录，提取所有犯过的错误，生成一份结构化的错误复盘报告。

### 数据位置
所有对话记录存放在以下目录：
~/.gemini/antigravity/brain/

每个子目录对应一个对话，聊天记录在：
~/.gemini/antigravity/brain/<对话ID>/.system_generated/logs/transcript.jsonl

共 138 个对话，总计约 39.5 MB。

### 你要找的"错误"定义
以下任何一种都算"错误"，全部要抓：

1. **用户明确纠错** — 用户说了以下关键词的上下文：
   - "不对"、"错了"、"不是这样"、"不是这个"、"不是我想要的"
   - "还是有问题"、"还是不行"、"又坏了"
   - "改回去"、"撤销"、"回退"、"undo"、"revert"
   - "别这样"、"不要这样"、"不要"
   - "搞错了"、"弄错了"
   - "不行"、"没用"、"没效果"

2. **代码层面的错误**：
   - 构建失败（build error、compile error）
   - 测试失败（test failed、FAIL）
   - ESLint / TypeScript 类型错误
   - 代码被 revert 或回退的记录
   - 同一个文件被反复修改 3 次以上（说明方向反复）

3. **逻辑/方向错误**：
   - AI 理解错了用户意图（做了 A 但用户要的是 B）
   - AI 选错了技术方案（用了 X 但后来换成 Y）
   - AI 改了不该改的东西（破坏了其他功能）
   - AI 遗漏了用户明确要求的事项

4. **重复劳动**：
   - 同一个问题修了多次才修好
   - 同一个需求被重新做了（推翻重来）

### 输出格式
对每个错误，输出以下字段：

| 字段 | 说明 |
|------|------|
| 对话ID | 对话目录名（短ID即可，前8位） |
| 对话标题 | transcript 里的用户首条消息摘要 |
| 日期 | 对话发生时间 |
| 错误类型 | 从以下选：用户纠错 / 构建失败 / 测试失败 / 理解偏差 / 方案错误 / 遗漏需求 / 重复劳动 / 代码回退 |
| 错误描述 | 一句话说明犯了什么错（不超过50字） |
| 用户原话 | 用户纠错时的原话（如果是用户纠错类型） |
| 根因分析 | 为什么会犯这个错（缺信息？假设错？没读文档？赶时间？） |
| 后果 | 这个错误导致了什么（浪费时间？代码回退？功能损坏？） |

### 执行步骤
1. 先列出所有 138 个对话目录，按时间排序
2. 逐个读取 transcript.jsonl，提取其中的错误信号
3. 对于大文件（超过 200 行），重点关注：
   - 包含上述关键词的行
   - `source: "USER_EXPLICIT"` 的消息（用户输入）
   - `type: "CODE_ACTION"` 中被 revert 的记录
   - 测试运行结果中的 fail 信息
4. 汇总所有错误，按错误类型分组
5. 在报告末尾给出统计摘要：
   - 各类型错误数量
   - 最常犯的错误模式 Top 10
   - 哪个模块/页面的错误最密集
   - 高频出错的时间段

### 注意事项
- 不要跳过任何对话，138 个全部扫完
- 不要只看表面的 error 关键词，要结合上下文判断是不是真正的"犯错"
- 如果一个错误涉及多个对话（比如同一个 bug 在多个对话里反复出现），合并为一条并标注所有相关对话
- 如果对话中 AI 先做错了再自己修好了，也要记录（虽然最终修好了，但犯错本身值得复盘）
- 用中文输出报告
```
