## 执行摘要 Executive Summary

**总体评级：B-（73/100）**

### 核心发现
✅ **做对的事**：
- 归因逻辑映射清晰（[content-attribution-map.ts](../src/lib/content-attribution-map.ts)）
- 多参照系对比设计完整（近三条/7天均值/最高/指定成员）
- 键盘导航流畅（J/K/↑↓/Esc）
- 截图双屏对比有实用价值

❌ **致命伤**：
1. **归因结论不在第一眼** — 用户打开抽屉看到的是"核心诊断病因看板"，但归因数据要往下滚才能看到对比卡片
2. **AI 批注是干扰项** — "编辑部智囊·诊断思路批注"放在最下方，但产品定位说"AI只算/摆/提示，绝不下结论"，现在这个位置和文案都在暗示"AI是最终答案"
3. **入口混乱** — "待分析 vs 全部"的 Tab 和"今日异常细条提醒"同时存在，信息架构不清晰
4. **归因卡片信息过载** — 每个指标卡片同时展示 4 个参照系的对比，视觉密度过高

## 用户旅程地图 User Journey Map

### Persona：管理员（阿禅）— 财经自媒体公司负责人
**场景**：每天早上打开后台，查看昨天发布的视频表现，找出问题视频并定位原因

### 完整旅程拆解

#### 阶段 1：进入页面（Landing）
**操作**：访问 `/admin/content`

**看到什么**：
```
┌─────────────────────────────────────────────────────┐
│ [待分析(12)] [全部(45)]  [全公司▾]  🔴 今日异常(3) │
│  → 最需关注: 张三(删稿)、李四(腰斩) [直接去盘→]     │
└─────────────────────────────────────────────────────┘
│ 视频列表...                                          │
```

**情绪**：😐 **认知负荷中等** — 三个入口同时抢注意力
- "待分析" = 多少条？
- "今日异常" = 是待分析的子集还是独立维度？
- "直接去盘" = 跳到哪里？

**痛点**：
- **信息架构不清晰** — "待分析"和"今日异常"是什么关系？
- **CTA 冲突** — "直接去盘"按钮和列表点击哪个优先？

**对比 Best Practice**：
- Linear 的 Issue 列表：单一排序（Priority），单一筛选器（Assignee/Status）
- Notion Database：筛选器折叠在 Filter 按钮内，不抢主视觉

---

#### 阶段 2：选择视频（Video Selection）
**操作**：点击列表中的某条视频

**看到什么**：右侧滑出抽屉（760px），顶部：
```
┌──────────────────────────────────────────────────────┐
│ [X 关闭] [展开队列(23)] [← 1/23 →]  张三·抖音主号   │
│                            [已自动入选题库] [移出题库] │
└──────────────────────────────────────────────────────┘
```

**情绪**：😊 **流畅** — 键盘快捷键提示清晰，队列计数器可见

**做对的点**：
- **队列导航器** — "1/23" 计数器 + J/K 快捷键，效率高
- **选题库状态** — 放在右上角，不干扰核心信息

---

#### 阶段 3：阅读诊断（首屏信息）⚠️ **核心问题区**
**操作**：抽屉打开后，视线从上往下扫描

**首屏看到**（滚动前）：
```
┌─────────────────────────────────────────────────────┐
│ 一、核心诊断病因看板                                 │
│ ┌───────────────────────────────────────────────┐   │
│ │ [综合性差] 对比基准：近三条                    │   │
│ │ 开头2秒失守严重，中段拖沓观众提前流失         │   │
│ │ 2s跳出率 67% vs 自己近三条 45% (↑49%)        │   │
│ └───────────────────────────────────────────────┘   │
│                                                     │
│ 三、归因诊断与多参照系对比 ▼ （需要往下滚）         │
└─────────────────────────────────────────────────────┘
```

**情绪**：🤔 **困惑 + 认知负荷高**

**致命问题 #1：归因结论被埋了**
- **用户期望**：打开抽屉第一眼看到"这条视频哪个指标不行 + 对比谁不行"
- **实际情况**：首屏是"综合诊断"的文字描述，归因卡片要往下滚
- **违反原则**：**Progressive Disclosure 倒置** — 最重要的数据（归因对比）被次要的描述（AI 批注风格的文字）挤到下面

**问题根源**：
产品设计说"归因 80% 权重"，但 UI 实现时把"核心诊断病因看板"放在最上面，这个区块的设计语言（渐变背景 + 大段文字）抢了归因卡片的视觉权重。

**对比 Best Practice**：
- **Stripe Dashboard**：关键指标卡片永远在顶部，描述文字折叠在 "Learn more" 下
- **Datadog APM**：问题指标用红色高亮 + 数字，不是文字描述

---

#### 阶段 4：查看归因对比（需要滚动）
**操作**：往下滚动，看到"三、归因诊断与多参照系对比"

**看到什么**：
```
┌─────────────────────────────────────────────────────┐
│ 多参照系归因对比                                     │
│ [☑ 近三条] [☑ 7天均值] [☐ 7天最高] [☐ 指定成员]    │
│                                                     │
│ ┌──────────┬──────────┬──────────┐                 │
│ │ 2s跳出率 │ 5s完播率 │ 均播时长 │ ...              │
│ │ 67%      │ 23%      │ 8.5s     │                 │
│ │ 近三条45%│ 近三条38%│ 近三条12s│                 │
│ │ 7天均52% │ 7天均30% │ 7天均10s │                 │
│ │ ↑49%差   │ ↓39%差   │ ↓29%差   │                 │
│ └──────────┴──────────┴──────────┘                 │
└─────────────────────────────────────────────────────┘
```

**情绪**：😵 **信息过载**

**致命问题 #2：归因卡片密度过高**
- **单个卡片展示 4 个数据**：当前值 + 近三条 + 7天均值 + 变化百分比
- **同时展示 10 个指标** — 用户要对比 40 个数字才能找到"哪个最差"
- **违反原则**：**Hick's Law** — 选项越多，决策时间越长

**建议修复**：
1. **默认只显示"差异最大的 3 个指标"** — 其他折叠在 "查看全部 10 项" 下
2. **单卡片只展示当前激活的参照系** — 用户切换 [近三条/7天均值] 时，卡片只显示那一个对比

**对比 Best Practice**：
- **Google Analytics**：默认只显示 Top 3 Metrics，其他在 "See all metrics"
- **Mixpanel Funnels**：单次只对比一个 Cohort，切换 Cohort 时数据动态更新

#### 阶段 5：查看 AI 批注（最底部）
**操作**：继续往下滚，看到"编辑部智囊·诊断思路批注"

**看到什么**：
```
┌─────────────────────────────────────────────────────┐
│ ✨ 编辑部智囊 · 诊断思路批注                         │
│ ┌───────────────────────────────────────────────┐   │
│ │ 数据摘要：开头2秒跳出率高达67%...              │   │
│ │ 疑似阶段：开头钩子、中段节奏                   │   │
│ │ 关键指标证据：2s跳出率、均播时长偏低...        │   │
│ └───────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

**情绪**：🤨 **违和感**

**致命问题 #3：AI 批注位置和文案违反产品定位**
- **产品铁律**："AI 只算/摆/提示，绝不下结论、不替人决策"
- **实际呈现**："编辑部智囊·诊断思路批注" — 这个文案暗示"AI 已经给出结论"
- **位置问题**：放在最底部，暗示"这是最终总结"

**修复建议**：
1. **移到侧边栏 Tooltip** — 鼠标悬停在指标卡片上时，显示"这个指标通常指向什么问题"
2. **改文案** — "参考：常见归因方向"而不是"诊断思路批注"
3. **或者直接删掉** — 如果产品定位是"不替人决策"，那就不要给 AI 总结的位置

**对比 Best Practice**：
- **GitHub Copilot**：建议永远是 inline suggestion，不是"最终答案"
- **Grammarly**：语法建议是 underline + tooltip，不是顶部大段总结

---

#### 阶段 6：查看截图（如果有）
**操作**：继续往下滚，看到"四、手机端长屏截图对照"

**看到什么**：双屏对比（流量曲线 vs 留存脱落）

**情绪**：😊 **有用**

**做对的点**：

- **点击放大**，交互流畅
- **移动端单屏切换** — 小屏幕上不强行并排

**小问题**：
- **截图标签不够清晰** — "流量曲线 vs 留存脱落" 对新手不友好
- **建议**：改为"观看人数变化 vs 观众流失时间点"

## Nielsen's 10 Heuristics 逐条评分

### 1. Visibility of System Status（8/10）
✅ **做对**：
- 队列计数器 "1/23" 清晰
- 加载状态有 Skeleton
- 选题库状态实时更新

⚠️ **改进**：
- 归因数据加载时缺少 Loading 提示（现在是空白突然出现数据）

---

### 2. Match Between System and Real World（6/10）
⚠️ **问题**：
- "2s跳出率 67% ↑49% 差" — "↑49%" 是变化幅度还是变化百分点？
- "编辑部智囊" — 用户心智模型里没有"编辑部智囊"这个角色

✅ **做对**：
- "近三条 vs 7天均值" — 语言直白

---

### 3. User Control and Freedom（9/10）
✅ **优秀**：
- Esc 关闭抽屉
- J/K 快捷键切换视频
- 可以随时关闭 AI 批注

---

### 4. Consistency and Standards（7/10）
✅ **做对**：
- 色彩系统一致（红=差，绿=好）
- 按钮样式统一

⚠️ **不一致**：
- "核心诊断病因看板"用渐变背景 + 大段文字，归因卡片用纯白卡片 — 视觉权重不匹配产品优先级

---

### 5. Error Prevention（8/10）
✅ **做对**：
- "移出题库"操作有二次确认（Toast 提示）
- 队列到底时按钮 disabled

---

### 6. Recognition Rather Than Recall（5/10）❌ **核心问题**
⚠️ **问题**：
- 用户需要**记住**"2s跳出率指向开头钩子"，而不是系统直接告诉
- 归因映射表（[content-attribution-map.ts:41](../src/lib/content-attribution-map.ts:41)）里写了 `points_to: "封面/标题/前两句没抓住人"`，但 UI 里没有直接展示

**修复建议**：
在归因卡片上加 Tooltip：
```tsx
<Tooltip>
  <TooltipTrigger>2s跳出率 ❓</TooltipTrigger>
  <TooltipContent>
    通常指向：封面/标题/前两句没抓住人
  </TooltipContent>
</Tooltip>
```

---

### 7. Flexibility and Efficiency of Use（7/10）
✅ **做对**：
- 键盘快捷键（J/K/Esc）
- 多参照系切换（复选框）

⚠️ **改进**：
- 缺少"批量标记为已分析"
- 缺少"导出当前视频诊断报告"

---

### 8. Aesthetic and Minimalist Design（4/10）❌ **核心问题**
⚠️ **问题**：
- **信息过载** — 首屏同时展示 10 个指标卡片
- **AI 批注是冗余信息** — 用户已经看到归因数据，不需要 AI 再总结一遍
- **"核心诊断病因看板"抢视觉权重** — 渐变背景 + 大段文字，比归因卡片还显眼

**修复建议**：
1. 删掉"核心诊断病因看板"，直接从归因卡片开始
2. AI 批注改为 Tooltip，不占主视觉
3. 默认只展示"差异最大的 3 个指标"

---

### 9. Help Users Recognize, Diagnose, and Recover from Errors（8/10）
✅ **做对**：
- 归因数据加载失败时有明确错误提示
- Toast 提示清晰

---

### 10. Help and Documentation（6/10）
⚠️ **问题**：
- 缺少"这个页面是干什么的"引导（新手第一次进来会懵）
- "多参照系归因对比"没有解释"为什么要对比这 4 个维度"

**修复建议**：
加首次访问引导：
```
👋 这里可以快速找出视频问题：
1. 看红色卡片 = 哪个指标最差
2. 看对比基准 = 跟谁比差的
3. 看截图 = 观众在哪里流失
```

- **认知负荷曲线倒置** — 本应该越看越清晰，实际上越看越复杂

## Anti-Generic AI Design 检查清单

### ❌ 违反项
1. **过度依赖 AI 批注** — "编辑部智囊"是典型的 Generic AI 语言
2. **AI 总结放在最底部** — 暗示"AI 是最终答案"
3. **缺少克制** — 归因卡片全部展开，没有渐进式披露

### ✅ 符合项
1. **色彩克制** — 没有过度使用渐变
2. **按钮设计实用** — 没有无意义的装饰性图标
3. **文案简洁** — "2s跳出率"而不是"观众在视频开始的前两秒内离开的比例"

## 关键修复建议（按优先级）

### P0（必须修）
1. **首屏直接展示归因卡片** — 删掉"核心诊断病因看板"
2. **默认只展示差异最大的 3 个指标** — 其他折叠
3. **删掉或移走 AI 批注** — 改为 Tooltip 或完全删除

### P1（强烈建议）
4. **在归因卡片上加 Tooltip** — 展示 `points_to` 说明
5. **简化顶部控制栏** — "今日异常"和"待分析"合并
6. **单卡片只展示当前激活的参照系** — 不要同时显示 4 个对比

### P2（体验优化）
7. **加首次访问引导** — 3 步引导用户如何使用
8. **加"导出诊断报告"功能** — 方便分享给团队
9. **截图标签更友好** — "观看人数变化 vs 观众流失时间点"

## 总结

**当前最大问题**：产品设计说"归因是核心（80% 权重）"，但 UI 实现时归因数据被埋在第二屏，首屏是 AI 风格的文字描述。

**本质矛盾**：
- **产品定位**：数据归因工具，AI 只辅助
- **UI 呈现**：AI 批注抢视觉权重，归因卡片需要滚动才能看到

**修复方向**：
1. **首屏 = 归因卡片**（差异最大的 3 个指标 + 红色高亮）
2. **删掉 AI 批注区块**（或改为 inline Tooltip）
3. **减少信息密度**（默认折叠非关键指标）

**参考标杆**：
- Stripe Dashboard（指标卡片优先）
- Linear Issue List（单一筛选维度）
- Datadog APM（问题指标红色高亮）
