# 审美哲学

> **"最好的工具，是你用完之后只记得事情做完了，不记得工具长什么样。"**

这份文档定义产品的灵魂与骨架——它是什么气质、怎么说话、什么时候闭嘴，以及精确到像素怎么画。

---

## 1. 核心信念

我们的产品是一个**安静把活干完的搭档**，不是舞台，不是仪表盘，不是科技展示。

搭档的特征是：

- 在你忙的时候不打扰你
- 在你需要的时候已经准备好了
- 说的话你听得懂，不猜
- 做的事你信得过，不疑

一切设计决策，先问一个问题：**一个安静靠谱的搭档会这样做吗？**
如果答案是"不会"，那就不要做。

---

## 2. 五条信念

### 2.1 静默存在

界面存在感越低，工作完成感越强。

- 能用排版节奏解决的层次，不加线框
- 能用字深变化指示的状态，不加彩色图标
- 能用留白创造的秩序，不加分割线

静默不是"空"，是"对的事在对的位置，不需要喊"。

### 2.2 精确做减法

每次往页面上加一个元素，都要问自己：**删掉它，用户还能完成任务吗？**
如果能，就不加。不确定，也不加。

减法不是偷懒。加上去只需要一秒，删掉它需要理解整个场景才能判断——后者才是设计。

### 2.3 主动退场

一个元素完成了它的使命，就应该安静地消失。

- 加载完成，loading 不多留一毫秒
- 操作成功，Toast 自己会走，不等用户来关
- 选中一目了然，不需要再弹出确认框来强调

最好的反馈是：用户还没来得及注意到，事情已经完成了。

### 2.4 功能退化

界面的终极形态是**用不上界面**。

高频操作一旦被记住，就应该有更快的路径——键盘快捷键、记住上次筛选、列表内直接改。让用户从"看界面操作"进化到"肌肉记忆操作"，是设计的真正胜利。

### 2.5 情绪透明

不隐瞒，不夸大，不粉饰。

- 没有数据就说没有，不画一个空图表来撑场面
- 操作失败就说失败原因，不说"出了点问题"来糊弄
- 加载慢就诚实说在加载，不用假进度条来安慰

用户尊重诚实的工具，不尊重讨好的工具。

## 3. 产品怎么说话

### 3.1 人格

**角色定义**：安静的靠谱搭档——话不多，但说出来的话能信。

语气光谱：

| 场景 | 语气 | 示例 |
|---|---|---|
| 正常状态 | 安静，不废话 | 页面本身呈现信息，不需要额外提示 |
| 操作成功 | 确认即可，克制 | 「已保存」，不用「保存成功！」 |
| 操作失败 | 诚实直接，给出路 | 「保存失败，网络中断了。」配「重试」按钮 |
| 空状态 | 温和，不焦虑 | 「还没有内容，[创建第一篇]」 |
| 加载中 | 坦诚，不装 | 用骨架屏展示结构，不用旋转菊花 |

**语气规则**：
- 白话优先。"没拿到数据"比"数据拉取失败"好。
- 禁止感叹号。产品不需要情绪激动。
- 文案最长一句。超过一句就拆成结构化信息。
- 不用"亲"、"呢"、"哦"等拟人化语气词。搭档是专业关系，不是客服关系。

### 3.2 沉默比说话重要

能不出现的文案，就不出现。

- 表格有数据时，不需要标题说"以下是你的内容列表"
- 操作成功时，如果结果本身可见（数据变了），Toast 可以省略
- 说明文字只在**不读就会犯错**的时候出现，不为了"完整"而加

**判断标准**：这句话删掉，用户会出错吗？会→留下。不会→删掉。

### 3.3 空状态不是错误

空状态是产品的第一次自我介绍，语气决定了用户对这个工具的第一印象。

| 场景 | 不要这样 | 这样 |
|---|---|---|
| 无数据 | 空表格 + "暂无数据" | 安静的留白 + 一个温和的创建入口 |
| 无搜索结果 | "未找到匹配内容" | "没有找到，试试换个关键词？" |
| 首次进入 | 所有功能空壳全展示 | 只展示一个起点，其余等有了内容再出现 |

## 4. 节奏与留白

### 4.1 不是所有留白都是好的

留白分两种：

- **呼吸型留白**：两个信息块之间的间隙，告诉大脑"这里断一下，准备看下一块"。**好的。**
- **空洞型留白**：内容太少撑不起页面，留白变成了"什么都没有"。**不好的。**

区分方法：留白是有意图的（分隔、强调、呼吸）还是无意图的（没东西可填）？
前者保留，后者用内容填充或缩短页面。

### 4.2 信息密度的弹性

同一屏的信息量应该随任务阶段变化：

- **决策时**：密度可以高，因为用户在扫描和比较（数据表格场景）
- **执行时**：密度要低，因为用户需要专注（编辑/撰写场景）
- **确认时**：密度极低，只保留结果（提交成功后的页面）

不要用一个固定密度去覆盖所有场景。

## 5. 什么不该做

设计的品味不只体现在做了什么，更体现在**拒绝做什么**。

### 5.1 永远不做

| 拒绝 | 原因 |
|---|---|
| 用颜色表达一切 | 色盲用户存在；彩色一旦泛滥就失去信号价值 |
| 用动画证明"高级感" | 动画只有两种有用的：指示方向、掩盖加载。其他都是噪音 |
| 用弹窗打断流程 | 除非是破坏性操作前的确认，否则不应该打断用户正在做的事 |
| 用"温馨提示"来掩盖设计缺陷 | 不够好的交互不应该靠文字提示来弥补，应该重新设计 |
| 用网络语气词 | 专业工具说人话，不说网络话 |
| 用成功音效/振动庆祝常规操作 | 保存文件不需要被表扬 |

### 5.2 谨慎使用

| 元素 | 什么时候才用 |
|---|---|
| 彩色 | 只在必须区分同类数据系列时（图表）或指示状态时（成功/失败）|
| 弹窗 | 只在破坏性操作前（删除、退出未保存）|
| 确认框 | 只在"撤回成本 > 确认成本"时 |
| 帮助文字 | 只在"不读就会犯错"时 |

**判断标准**：如果不确定要不要加，就不加。等用户真的困惑了再加，而不是提前用噪音预防性安慰。

## 6. 质量标准——怎么判断"有没有灵魂"

像素级的验收标准在后面「尺度」章节，这里只管"对不对味"。

每完成一个页面，问自己这 7 个问题：

| # | 问题 | 通过标准 |
|---|---|---|
| 1 | 打开这一屏，感到**平静**还是**焦虑**？ | 平静。没有任何元素在无目的地跳动或闪烁 |
| 2 | 第一眼看到的是**内容**还是**框架**？ | 内容。边框、线、装饰都不应该比内容先抓住视线 |
| 3 | 五秒后能说出"这页是干什么的"吗？ | 能。标题 + 内容结构在一屏内自我解释 |
| 4 | 界面有没有比任务本身**更吸引注意力**的地方？ | 没有。一切视觉元素都在为任务服务 |
| 5 | 遇到问题时，产品**态度**是什么？ | 诚实 + 给出路，不说废话 |
| 6 | 空状态有没有**温度**？ | 有。不是"暂无数据"的冷漠，而是"可以开始了"的邀请 |
| 7 | 做完事情之后，你记得的是**事情**还是**界面**？ | 事情。好的界面会被忘记 |

如果 7 项全过，这个页面有灵魂。

## 7. 视觉骨架

颜色和层次共同构成页面的视觉骨架。

### 7.1 色彩系统

#### 行动色（暖橙 `#D97757`）—— "去操作"

- Hover：`#C46A4D`
- **主 CTA 按钮**：暖橙实底 + 白色文字，带 `shadow-sm` 浮起。每屏至多 1 个。

#### 位置色（暴雨灰蓝 `#43718E`）—— "你在这"

用于侧栏选中项、当前步骤指示、面包屑当前位置。同时承担表达色（图表数据系列之一）。

#### 状态色与行情色 —— "命名隔离"

必须严格区分**系统状态**与**行情/数据趋势**，命名完全隔离，代码中用不同 CSS 变量，禁止跨领域引用：

| 领域 Token | 色值 | 语义 | 适用场景 |
|---|---|---|---|
| `system.error` | `#DC2626` | 失败、拒绝、违规 | 系统报错，禁止用于数据下跌 |
| `system.success` | `#16A34A` | 通过、完成、合规 | 操作完成，禁止用于数据上涨 |
| `market.up` | `#DC2626` | 上涨 / 增长（A股惯例） | 仅用于行情与指标大盘增长 |
| `market.down` | `#16A34A` | 下跌 / 减少（A股惯例） | 仅用于行情与指标大盘下跌 |

#### 表达色 —— "区分同类"

用于图表数据系列、分类标签、图标。中低饱和度冷调。

| 色名 | 色值 |
|---|---|
| 苔藓深绿 | `#405740` |
| 紫罗兰 | `#7B6BA5` |

同一图表内最多使用 2 表达色 + 暴雨灰蓝（位置色参与图表）共 3 色。超过 3 条数据系列时拆分图表。

#### 灰阶 —— 层次骨架

| 用途 | 色值 | 说明 |
|---|---|---|
| 墨黑 / 聚焦 / 悬停 | `zinc-950` | 页面大标题、Hover 悬停态、Active 选中项（见 §9） |
| 核心正文 | `zinc-800` | 常规正文、输入框已填文字、按钮文字（见 §8.2） |
| 次级数据 / 表头 | `zinc-600` | 表格数据列、表头(TH)、时间戳、辅助说明（见 §8.2） |
| 占位 / 禁用 | `zinc-400` | 输入框 Placeholder、Disabled 禁用态文字 |
| 边框 / 结构线 | `zinc-200` | 表格行间 1px 分隔线（仅限表格防串行，不用于卡片边框） |
| 微底衬色 | `zinc-100` | Hover 衬底、标签背景（见 §9） |
| 页面背景 | `zinc-50` | 整个页面基底 |

### 7.2 层次系统

| 层 | 角色 | 色值 | 出现位置 |
|---|---|---|---|
| L0 基底 | 页面大背景 | `zinc-50` | 整个页面 |
| L1 容器 | 内容承载 | `white` | 卡片、面板、内容区 |
| L2 边界 | 分隔 | 色差 + 间距 | 卡片靠 L0/L1 底色差分层，仅表格行间保留 1px 线 |
| L3 焦点 | 行动/状态 | 品牌色/状态色 | 按钮、选中态、状态灯 |

## 8. 尺度

### 8.1 间距与圆角

**间距**：基于 4px 网格。全站统一使用：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px。

**圆角**：

| 级别 | Tailwind 类 | 像素 | 适用场景 |
|---|---|---|---|
| 行级 | `rounded-md` | 6px | 按钮、输入框、选择器等行高控件 |
| 小容器 | `rounded-lg` | 8px | 小卡片、Badge、弹层内容 |
| 大容器 | `rounded-2xl` | 16px | 模态框、主卡片、页面大容器 |
| 胶囊 | `rounded-full` | — | 状态标签、头像、圆形按钮 |

### 8.2 文字排版

字体栈：`Inter, -apple-system, BlinkMacSystemFont, 'PingFang SC', system-ui, sans-serif`

渲染：`-webkit-font-smoothing: antialiased`（macOS 上让笔画更锐利）

| 元素 | 字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|
| 页面标题 | 24px | 600 | 1.3 | 页面顶部主标题 |
| 区域标题 | 18px | 600 | 1.3 | 模块/区域标题 |
| 正文 | 14px | 400 | 1.6 | 主要内容文字 |
| 次级文字 | 13px | 400 | 1.5 | 辅助说明、时间戳 |
| 标签/徽章 | 12px | 500 | 1.3 | Tag、Badge、角标 |

### 8.3 中文排版铁律

1. **等宽隔离** — 含中文的容器禁止 `font-mono`，混排用 `tabular-nums`，仅纯数字/英文独立区块可用 `font-mono`
2. **行高保护** — 中文最小 12px，小字号必须 `leading-normal`，禁止 `leading-none`
3. **字重三锁死** — `600`（`font-semibold`）仅限页面大标题与核心区域标题；`500`（`font-medium`）用于列表行核心锚点（姓名/核心标题）、组件小标题与小 Badge；`400`（`font-normal`）覆盖全站常规正文、辅助说明与数据列
4. **非字重强调** — 需要强调时禁止提字粗（防止小字糊字），统一通过「字深跃迁（`zinc-600` → `zinc-950`）」、「留白聚光」或「微底衬垫」表达
5. **小字底线** — 所有需要阅读的文字（含 11px 时间戳、表头）用色最低不得浅于 `zinc-600`，`zinc-200` 严禁用于文字
6. **盘古间距** — 中文与英文/数字之间保留半角空格（`共 12 篇`，非 `共12篇`）

## 9. 组件规格

以下细节不写就会漂移，写了 AI 才能保持一致。

**交互状态（全站统一）**：所有可点击控件配备三层反馈，时间线不重叠：
- Hover：`text-zinc-600` 默认态 → `hover:bg-zinc-100 hover:text-zinc-950`，`transition-colors duration-100`
- Active：`active:bg-zinc-200` 色变触感，不缩放
- Selected 常规选择：菜单 `bg-zinc-100`；Tab `bg-zinc-100/70 p-1 rounded-xl` 微气垫，激活项 `bg-white`；列表行 `zinc-50`
- Selected 标题级：`text-zinc-950` + `font-semibold`

**表格密度**：数字右对齐等宽（`tabular-nums`），复合信息单行内联（用「·」连接），行高压紧（32~36px），宽屏平铺全部并行指标列。

**图表标注**：贴线直接标注 > 独立图例，仅在 ≥3 系列时才引入独立图例。面积图渐变保持极淡通透（强度 40% → 5%）。

**Toast**：仅在操作结果不可见时使用（结果本身可见则省略）。底部偏右（`bottom-6`），单行不超过 20 字，3 秒平滑消失，同位置自动替换。

**内联校验反馈**：校验失败时，在字段下方显示 `text-red-500 text-xs mt-1` 的辅助文字，不超过 10 字。字段边框加 `ring-1 ring-red-300`。校验通过后辅助文字和红框即时消失。

**Tag**：最小点击高度 20px，`rounded-md`。

**中心弹窗**：自适应内容高度 + `max-h-[85vh]` 边界约束，禁止硬套固定宽高比。浮层采用 `bg-white shadow-lg`。

**功能域隔离**：不同功能群之间插入 16px 淡灰微竖线（`h-4 w-px bg-zinc-200`），保持自然呼吸。

**平铺下拉**：一律无框平铺（`border-0 bg-transparent hover:bg-zinc-100 rounded-lg px-2 py-1.5 text-xs text-zinc-700`），配以统一 14px 微箭头。

**搜索微胶囊**：常态 `bg-zinc-100/70 border-0 text-xs rounded-lg`；聚焦时转为白底微光（`focus:bg-white focus:ring-1 focus:ring-zinc-300`）。
