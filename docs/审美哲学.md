# 审美哲学

> **"最好的工具，是你用完之后只记得事情做完了，不记得工具长什么样。"**

这份文档定义产品的灵魂与骨架——它是什么气质、怎么说话、什么时候闭嘴，以及精确到像素怎么画。

---

## 1. 核心信念

我们的产品是一个**安静把活干完的搭档**，不是舞台，不是仪表盘，不是科技展示。

搭档的特征是：

- 在你忙的时候不打扰你
- 在你需要的时候已经准备好了
- 说的话你听得懂，不猜
- 做的事你信得过，不疑

一切设计决策，先问一个问题：**一个安静靠谱的搭档会这样做吗？**
如果答案是"不会"，那就不要做。

---

## 2. 五条信念

### 2.1 静默存在

界面存在感越低，工作完成感越强。

- 能用排版节奏解决的层次，不加线框
- 能用字深变化指示的状态，不加彩色图标
- 能用留白创造的秩序，不加分割线

静默不是"空"，是"对的事在对的位置，不需要喊"。

### 2.2 精确做减法

每次往页面上加一个元素，都要问自己：**删掉它，用户还能完成任务吗？**
如果能，就不加。不确定，也不加。

减法不是偷懒。加上去只需要一秒，删掉它需要理解整个场景才能判断——后者才是设计。

### 2.3 主动退场

一个元素完成了它的使命，就应该安静地消失。

- 加载完成，loading 不多留一毫秒
- 操作成功，Toast 自己会走，不等用户来关
- 选中一目了然，不需要再弹出确认框来强调

最好的反馈是：用户还没来得及注意到，事情已经完成了。

### 2.4 功能退化

界面的终极形态是**用不上界面**。

高频操作一旦被记住，就应该有更快的路径——键盘快捷键、记住上次筛选、列表内直接改。让用户从"看界面操作"进化到"肌肉记忆操作"，是设计的真正胜利。

### 2.5 情绪透明

不隐瞒，不夸大，不粉饰。

- 没有数据就说没有，不画一个空图表来撑场面
- 操作失败就说失败原因，不说"出了点问题"来糊弄
- 加载慢就诚实说在加载，不用假进度条来安慰

用户尊重诚实的工具，不尊重讨好的工具。

## 3. 产品怎么说话

### 3.1 人格

**角色定义**：安静的靠谱搭档——话不多，但说出来的话能信。

语气光谱：

| 场景 | 语气 | 示例 |
|---|---|---|
| 正常状态 | 安静，不废话 | 页面本身呈现信息，不需要额外提示 |
| 操作成功 | 确认即可，克制 | 「已保存」，不用「保存成功！」 |
| 操作失败 | 诚实直接，给出路 | 「保存失败，网络中断了。」配「重试」按钮 |
| 空状态 | 温和，不焦虑 | 「还没有内容，[创建第一篇]」 |
| 加载中 | 坦诚，不装 | 用骨架屏展示结构，不用旋转菊花 |

**语气规则**：
- 白话优先。"没拿到数据"比"数据拉取失败"好。
- 禁止感叹号。产品不需要情绪激动。
- 文案最长一句。超过一句就拆成结构化信息。
- 不用"亲"、"呢"、"哦"等拟人化语气词。搭档是专业关系，不是客服关系。

### 3.2 沉默比说话重要

能不出现的文案，就不出现。

- 表格有数据时，不需要标题说"以下是你的内容列表"
- 操作成功时，如果结果本身可见（数据变了），Toast 可以省略
- 说明文字只在**不读就会犯错**的时候出现，不为了"完整"而加

**判断标准**：这句话删掉，用户会出错吗？会→留下。不会→删掉。

### 3.3 空状态不是错误

空状态是产品的第一次自我介绍，语气决定了用户对这个工具的第一印象。

| 场景 | 不要这样 | 这样 |
|---|---|---|
| 无数据 | 空表格 + "暂无数据" | 安静的留白 + 一个温和的创建入口 |
| 无搜索结果 | "未找到匹配内容" | "没有找到，试试换个关键词？" |
| 首次进入 | 所有功能空壳全展示 | 只展示一个起点，其余等有了内容再出现 |

## 4. 节奏与留白

### 4.1 不是所有留白都是好的

留白分两种：

- **呼吸型留白**：两个信息块之间的间隙，告诉大脑"这里断一下，准备看下一块"。**好的。**
- **空洞型留白**：内容太少撑不起页面，留白变成了"什么都没有"。**不好的。**

区分方法：留白是有意图的（分隔、强调、呼吸）还是无意图的（没东西可填）？
前者保留，后者用内容填充或缩短页面。

### 4.2 信息密度的弹性

同一屏的信息量应该随任务阶段变化：

- **决策时**：密度可以高，因为用户在扫描和比较（数据表格场景）
- **执行时**：密度要低，因为用户需要专注（编辑/撰写场景）
- **确认时**：密度极低，只保留结果（提交成功后的页面）

不要用一个固定密度去覆盖所有场景。

## 5. 什么不该做

设计的品味不只体现在做了什么，更体现在**拒绝做什么**。

### 5.1 永远不做

| 拒绝 | 原因 |
|---|---|
| 用颜色表达一切 | 色盲用户存在；彩色一旦泛滥就失去信号价值 |
| 用动画证明"高级感" | 动画只有两种有用的：指示方向、掩盖加载。其他都是噪音 |
| 用弹窗打断流程 | 除非是破坏性操作前的确认，否则不应该打断用户正在做的事 |
| 用"温馨提示"来掩盖设计缺陷 | 不够好的交互不应该靠文字提示来弥补，应该重新设计 |
| 用网络语气词 | 专业工具说人话，不说网络话 |
| 用成功音效/振动庆祝常规操作 | 保存文件不需要被表扬 |

### 5.2 谨慎使用

| 元素 | 什么时候才用 |
|---|---|
| 彩色 | 只在必须区分同类数据系列时（图表）或指示状态时（成功/失败）|
| 弹窗 | 只在破坏性操作前（删除、退出未保存）|
| 确认框 | 只在"撤回成本 > 确认成本"时 |
| 帮助文字 | 只在"不读就会犯错"时 |

**判断标准**：如果不确定要不要加，就不加。等用户真的困惑了再加，而不是提前用噪音预防性安慰。

## 6. 质量标准——怎么判断"有没有灵魂"

每完成一个页面，问自己这 7 个问题：

| # | 问题 | 通过标准 |
|---|---|---|
| 1 | 打开这一屏，感到**平静**还是**焦虑**？ | 平静。没有任何元素在无目的地跳动或闪烁 |
| 2 | 第一眼看到的是**内容**还是**框架**？ | 内容。边框、线、装饰都不应该比内容先抓住视线 |
| 3 | 五秒后能说出"这页是干什么的"吗？ | 能。标题 + 内容结构在一屏内自我解释 |
| 4 | 界面有没有比任务本身**更吸引注意力**的地方？ | 没有。一切视觉元素都在为任务服务 |
| 5 | 遇到问题时，产品**态度**是什么？ | 诚实 + 给出路，不说废话 |
| 6 | 空状态有没有**温度**？ | 有。不是"暂无数据"的冷漠，而是"可以开始了"的邀请 |
| 7 | 做完事情之后，你记得的是**事情**还是**界面**？ | 事情。好的界面会被忘记 |

如果 7 项全过，这个页面有灵魂。
