> 更新触发：角色、权限类别、审批边界、归档边界或鉴权入口变更时，必须同步更新本文件。

## 权限模型（2026年8月最终版）

### 三级角色体系

| 角色 | company_role | 说明 | 固定权限 |
|------|--------------|------|----------|
| 组员 | `member` | 只能提交申请，不能审批 | 无 |
| 主管 | `admin` | 管日常业务，不能碰人事 | `view_analytics`, `view_conversion`, `review_content`, `manage_fulfillment`, `manage_videos`, `review_violations`, `use_ai_copy`（共 7 项） |
| 公司所有者 | `company_owner` | 管本公司全部，包括人事和系统设置 | 主管的 7 项 + `export_data`, `manage_members`, `manage_system`, `use_ai_assist`（共 11 项） |

> 旧数据库 `role=owner` 只在迁移边界映射为 `company_owner`，不代表集团全局权限。

### 集团层（休眠状态）

- 代码保留在 `src/lib/group-mode-server.ts` 和 `src/app/api/group-mode/`
- 资格表 `group_permission_qualifications` 当前为空
- 物理上无法进入（`/api/group-mode/enter` 返回 403）
- 启用方法：服务端写入资格行到 `group_permission_qualifications`

### 数据范围

| 角色 | 可见范围 |
|------|----------|
| 组员 | 只能看自己的数据 |
| 主管 | 本公司在职成员（不含归档） |
| 公司所有者 | 本公司全部成员（含归档的历史数据） |
| 集团模式 | 跨公司（当前不可用） |

### 关键权限说明

**manage_system**（系统设置）：
- 只有 `company_owner` 拥有
- 控制：视频复盘阈值、飞书自动催交开关
- 接口：`/api/admin/system/settings`、`/api/admin/settings/thresholds`

**manage_members**（成员管理）：
- 只有 `company_owner` 固定拥有
- 可以：修改角色、归档、重置密码、恢复归档账号
- 接口：`/app/(app)/admin/modules` 页面 + server actions

**manage_fulfillment**（履约管理）：
- `admin` 和 `company_owner` 都有
- 可以：审批豁免申请、管理日报提交

## 常见问题排查

### Q1: 公司所有者打不开系统设置

**检查清单：**
1. 确认 `profiles.company_role = 'company_owner'`
2. 确认代码已部署（Vercel Ready）
3. 确认接口返回 200，不是 404 或 403
4. 查看 `src/lib/company-permissions.ts` 中 `DEFAULT_PERMISSIONS_BY_COMPANY_ROLE.company_owner` 是否包含 `manage_system`

**SQL 验证：**
```sql
SELECT id, email, company_role, role
FROM profiles
WHERE id = '<user_id>';
-- 预期：company_role = 'company_owner'
```

### Q2: 主管能看到"修改角色"按钮

**检查清单：**
1. 确认 `profiles.company_role = 'admin'`（不是 `company_owner`）
2. 查看 `src/app/(app)/admin/modules/modules-content-v2.tsx` 中 `canChangeRole` 的判断逻辑
3. 确认 admin 的固定权限不包含 `manage_members`

**SQL 验证：**
```sql
SELECT id, email, company_role, role, permissions->>'manage_members' as has_manage_members
FROM profiles
WHERE id = '<user_id>';
-- 预期：company_role = 'admin'，has_manage_members 为 null 或 false
```

### Q3: 截图返回 403 或 401

**检查清单：**
1. 确认已登录（cookie 有效）
2. 确认截图路径格式：`/api/submission-screenshots/file?path=<user_id>/...`
3. 确认 `<user_id>` 在当前用户的 `visibleUserIds` 范围内
4. 查看 `src/app/api/submission-screenshots/file/route.ts` 的鉴权逻辑

**调试命令：**
```javascript
// 浏览器 Console
fetch('/api/submission-screenshots/file?path=xxxxx')
  .then(r => console.log(r.status))
```

### Q4: 集团模式返回 404 而不是 403

**原因：** 集团模式路由存在，但请求路径错了。

**正确路径：**
- 状态查询：`GET /api/group-mode/status`
- 进入：`POST /api/group-mode/enter`
- 退出：`POST /api/group-mode/exit`

**验证集团模式是否可用：**
```sql
SELECT COUNT(*) FROM group_permission_qualifications
WHERE user_id = '<user_id>' AND revoked_at IS NULL;
-- 返回 0 = 无资格
```

### Q5: 某个接口谁都能进（越权排查）

**检查清单：**
1. 查该接口有没有等价鉴权：`requireAdminActor`（传对 `requiredPermission`）、`getUserPermissions` 自判、`requireAuth` + 对象归属校验、cron 密钥、或按 `visibleUserIds` 做范围过滤
2. 用了 `service role` 又完全没有上述校验 → 确认越权漏洞
3. 有 `requireAdminActor` 但没传 `requiredPermission` → 退化为"有任意管理权限就放行"
