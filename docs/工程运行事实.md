## 二、代码与目录事实

- 技术栈为 Next.js App Router、Tailwind CSS、shadcn/ui、Supabase、Vercel。
- 页面在 `src/app/(app)`、`src/app/(auth)`，接口在 `src/app/api`；可复用 UI 在 `src/components`，复用 hooks 在 `src/hooks`。
- `src/lib` 承载业务逻辑、数据加载和工具；新代码优先进入已有领域子目录，包括 `loaders`、`supabase`、`ai`、`admin-ai`、`admin-tools`、`case-library`、`conversion-hub`、`notifications`、`publish-drafts`、`rewrite`、`team-join`。
- 首屏加载器集中在 `src/lib/loaders`。当前实际存在的页面 loader 包括 dashboard、growth、admin-content、admin-videos、fulfillment、admin-modules；`admin/ai-config` 与 `admin/settings` 仍是页面内直查例外。已下线的 guidance、admin-advice 和 video-review 页面不得继续写入现行 loader 清单。
- `src/components` 默认不直连数据库；存量 `nav-bar.tsx` 服务端直查 Supabase 是已知例外。
- `src/middleware.ts` 负责登录校验、账号生命周期拦截、限流和清缓存；不负责角色或功能级细粒度权限。
- `visibleUserIds` 用于历史可见范围，`activeVisibleUserIds` 用于当前操作候选；二者不可混用。
- `lib/case-library` 与 `lib/conversion-hub` 虽属下线生态，仍被 `/api/video-submit` 依赖，不得按目录名删除。`lib/violations` 已删除。
- `/growth` 与 `/content-tools/rewrite` 已确定后续整体重做；重做前只处理必要故障，冻结性能深改和大范围清理。

## 三、性能契约与当前基线

### 正式预算（唯一权威）

| 页面 | 首屏目标 | 完整加载 | 首屏业务请求上限 | 单接口上限 |
|---|---:|---:|---:|---:|
| `/dashboard` | 2 秒 | 3 秒 | 15 | 600ms |
| `/growth` | 2 秒 | 3.5 秒 | 12 | 首屏 600ms；补全 1200ms |
| `/admin/content` | 2.5 秒 | 5 秒 | 20 | 1200ms |
| 其他登录后页面 | 2.5 秒 | 4 秒 | 20 | 800ms |

模块地图只保留页面模块和局部缓存摘要；上述预算数值及其解释只在本表维护，避免双重权威。

### 当前加载与缓存事实

- 站点以服务端组件和页面专属 loader 协调首屏；Topics 已由服务端 bootstrap 注入首屏，正常进入客户端不请求 `/api/topics/*`。
- `getCurrentUserContext()` 与权限相关 React `cache()` 提供请求内复用；权限上下文另有 30 秒 TTL 缓存，写路径需调用失效钩子。
- 独立查询通常使用 `Promise.all`；管理统计允许单块失败时使用 `Promise.allSettled`，但失败必须可观察。
- 现存页面接口缓存仅 `content/list` 的 60 秒内存缓存；`sidebar-badges` 接口已删除。导航豁免角标由客户端延后 2.5 秒拉取并做 60 秒模块缓存。
- `topics_pool_aggregates` RPC 已在线上库执行；pool 主路径使用聚合 RPC，失败回退内存路径。Topics detail 冷调用仍是已知超预算点。
- `/admin/content` 首屏只加载待盘队列；全量列表由用户点击触发，topic-library-status 使用 POST 正文承载最多 400 个视频 ID，禁止恢复超长 GET。
- `/admin/collaboration` 的当月日报数据集由共享加载器一次查询后复用；person 冷调用仍是已知超预算点。
- `/dashboard` 岗位成员在首次打开选择器时加载；Topics 详情作品由 detail 单一数据源提供，翻页或排序才请求 `/works`。

### 性能证据边界

- 性能结论必须注明开发模式、本地生产构建、Vercel 预览或 Vercel 生产；本地结果不能写成 Vercel 通过。
- `npm run gate:static` 是确定性必跑门禁；`npm run gate:browser` 是登录态显式门禁，首批覆盖 `/topics`、`/dashboard`、`/admin/content`、`/admin/collaboration`。
- 当前浏览器门禁对稳定规则硬阻断，时间预算先报告；没有浏览器报告不得宣称浏览器性能通过。
- `DYDATA_PERF_LOG=1` 用于 loader/API 分步耗时；门禁报告不得保存密码、Cookie、storage state、请求正文或用户 ID。

### 最近可用基线（仅本地生产构建）

| 页面 | 首屏绘制 | 完整加载 | 首屏业务请求 | 结论 |
|---|---:|---:|---:|---|
| `/topics` | 约 0.71 秒 | 约 0.73 秒 | 1 个 | 硬规则通过 |
| `/dashboard` | 约 0.23 秒 | 约 0.54 秒 | 2 个 | 硬规则通过 |
| `/admin/content` | 约 0.64 秒 | 约 0.78 秒 | 5 个 | 时间仅报警 |
| `/admin/collaboration` | 约 0.67 秒 | 约 0.78 秒 | 1 个 | 时间仅报警 |

- 以上基线来自 2026-08-30 的 company_owner 登录态；不能代表其他角色、Vercel 预览或 Vercel 生产。
- 同日 `/admin/content` 最慢业务接口约 2.91–3.11 秒，`/admin/collaboration` 约 0.94 秒；这些超时不因页面总请求数达标而自动消失。
- 需要历史前后对比时，读取 `docs/archive/性能优化历史-截至2026-08-30.md`；历史记录不构成当前改动授权。

### 当前性能债

- `/admin/content` 全量 topic-library-status 约 1.2–1.9 秒；已改为显式触发且每次只算一次，但仍超过通用 800ms 预算。
- Topics detail 冷调用、协作 person 冷调用仍可能超过单接口预算；属于预存问题，不能用缓存或测试通过掩盖。
- `/growth` 与 `/content-tools/rewrite` 的结构性性能治理随整体重做处理，不在冻结期扩张范围。

## 四、部署与运维事实

- 正式部署平台只有 Vercel；`main` push 触发部署。OpenNext/Cloudflare 仅为历史实验，不得恢复为正式入口。
- Supabase 主库为 `gcrhhxaopomtposmahsw`，区域为新加坡；数据库连通性可由 `/api/health?check=supabase` 探测。
- `/api/health` 无需登录，基础检查返回 200、`status:"ok"` 与 `checks.server:"up"`；带 `check=supabase` 时，依赖正常返回 200 和 `supabase:"up"`，连接失败返回 503、`status:"degraded"` 与 `supabase:"down"`，缺少配置则返回 503 和 `supabase:"unconfigured"`，均不暴露底层错误。
- `/api/supabase-keepalive` 由 Vercel cron 每天调用，正常返回 `ok:true`；Vercel cron 只有保活和清理过期通知两个任务。
- cron 鉴权兼容 `CRON_SECRET`、`REMIND_SECRET`；Vercel Cron 使用 `Authorization: Bearer`，手动触发可用对应 `?secret=`。
- 所有登录校验、限流和清缓存入口在 `src/middleware.ts`；单用户异常可用 `?__clear_site_data=1` 清理本地缓存和登录态。
- 公开环境变量以 `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY` 为主；服务端密钥不得写入代码、日志或文档样例。实际值只以 `.env.example` 与 `.env.local` 为准。
- 服务端关键变量包括 `SUPABASE_SERVICE_ROLE_KEY`、`FEISHU_WEBHOOK_URL`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_ENCRYPT_KEY`、`FEISHU_APP_VERIFICATION_TOKEN`、`CRON_SECRET`、`REMIND_SECRET`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`DYDATA_PERF_LOG`、`BAIDU_OCR_API_KEY`、`BAIDU_OCR_SECRET_KEY`；这里只维护名称和用途边界，不保存实际值。
- Git remote 使用 SSH：`git@github.com:1305085564-hue/dydata.git`；禁止改成 HTTPS，提交身份邮箱应为 `1305085564@qq.com`。
- `SUPABASE_DB_URL`、`SUPABASE_ACCESS_TOKEN` 只用于迁移或临时 SQL，不进入应用代码；`DYDATA_E2E_EMAIL`、`DYDATA_E2E_PASSWORD` 只由受控浏览器门禁读取。

## 五、发布硬边界

- 一次提交/上线只做一个领域；视觉、业务逻辑、性能、文件搬迁和 migration 分开。
- migration 只能新增，不能改旧文件；禁止数据库先行造成旧应用读取已删除结构的窗口。
- 含新字段的发布需依次完成 migration、刷新 PostgREST schema cache、真实角色请求验收；缺任一步不能称为完成。
- 生产回滚优先在 Vercel 将上一个 Ready 部署 Promote/Instant Rollback；代码层撤销和重新发布仍须单独核对变更范围。
- 健康检查只证明服务或数据库连通，不证明业务权限、业务口径或页面链路正确；这些必须按对应专项证据验收。
- 当前工作区可能有其他会话改动；提交只精确暂存本任务文件，禁止 `git add .`、`git add -A` 和 `git add -u`。
- `main` push 会上线；push 前必须有当前轮明确授权，并核对本地与远端 SHA。
- 代码治理、性能、运维类文档更新只修改本文件和必要索引；模块归属仍写入全站模块地图，权限契约仍写入权限与安全说明，指标含义仍写入数据口径。
