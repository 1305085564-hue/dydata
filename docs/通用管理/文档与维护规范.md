# DYData 文档与维护规范

> 任务从[产品全书](../DYData产品全书.md)进入。施工和发布纪律见[项目规则](../../AGENTS.md)。2026-11-09 更新文档归口。

| 目录 | 用途 |
| --- | --- |
| `docs/系统架构与设计/` | 当前业务流程、权限和口径，以及系统结构、工程事实、设计与实现规范 |
| `docs/reference/` | 以后还会用的已确认依据。按版本、日期和验收范围引用 |
| `docs/plans/` | 待做、在办方案与续工材料 |
| `docs/archive/` | 只供追溯的历史原稿和过程材料 |
| `docs/通用管理/`、`docs/ux-audit/` | 文档、待办和交接规范，以及独立的 UX 审计产物 |

1. 先查产品全书和现有原稿。同一现行结论维护一处，其他位置链接。业务规则写入架构与设计对应文档，模块入口与调用关系写入[模块地图](../系统架构与设计/全站模块与数据关系.md)。
2. 已拍板且需要追溯理由的取舍，记录在[架构决策](../reference/架构决策.md)。各条说明有效或被替代的状态。业务口径采用新依据时，更新现行原稿并链接依据。
3. 参考保留已确认、后续仍会用的接口、验收或调查结论。注明适用版本、日期或未覆盖范围。多份记录回答同一问题时，更新现有依据或合并独有事实，再归档旧稿。
4. 计划收尾按[计划目录约定](../plans/README.md)办理。已结束的材料退出计划区。能复用的结论归参考，只需追溯的原稿归档。
5. 交接传递续工上下文。能长期使用的事实先复核，再写入对应原稿。
6. 核实代码、运行记录或业务决定后，按实际范围更新文档。证据缺口标明待核。搬迁时同步更新可用引用，保留原始记录的日期与语境。
