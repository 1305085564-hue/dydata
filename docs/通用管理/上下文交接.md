# 上下文交接模板

> **本文件是永久模板，只用于生成新的交接文档。禁止修改、覆盖或把交接内容直接写入本模板。**

> **交接铁律（验收只认这三条）**
> - 缺强制字段 = 未交接
> - 只说"没问题"不给证据 = 拒收
> - 阿禅只看证据对，不被逼着看技术细节
>
> 检查方式：`node scripts/handoff-checklist.mjs <交接文档路径>`，只读只报警，红绿灯输出。

目标：让新的人工智能助手准确恢复上下文，并立即继续当前任务。

## 生成原则

1. **关键原话保留**：用户的要求、禁止项、偏好、否决、关键判断，优先逐字引用，避免转述失真。
2. **其余内容精炼总结**：删除重复、闲聊和无后续价值的过程。
3. **区分事实与推测**：已经验证的写“已确认”；未经验证的判断写“推测或待验证”。
4. **只记录有继承价值的信息**：不写流水账；检索、测试和工具操作只保留关键结果。
5. **同一信息只写一次**，避免重复。

## 交接结构

### 〇、强制字段（缺任何一项视为未交接）

1. **本轮允许上线的范围**：文件 / 模块 / 功能点，明确列出；本轮什么都不允许上线就写"无"。
2. **已改动清单**：文件 + 大致改了什么；不要求逐行，但要能让接手方快速定位。
3. **未完成事项**：明确列出；没有就写"无"。
4. **验收证据**：每项交付物一组证据对；只写"测试通过""没问题"等自报而无证据对 = 拒收。格式：

   > 要求：<用户原话或需求描述>
   > 实际：<命令 + 输出 / 截图 / 对比结果>
   > 覆盖范围：<测试了什么、没测什么>

以下第一至七节为上下文恢复内容，按原规则填写。

### 一、当前目标与状态

- 用户最终要什么
- 当前做到哪里
- 已完成什么
- 当前还存在什么问题

### 二、用户关键原话

> 保留会影响后续执行的原话，尤其是“必须、不要、优先、否决、偏好”等内容。

### 三、已确认事实与待验证判断

- **已确认：**
- **推测或待验证：**

### 四、已做决策与禁止重做

- 已确定的方案及原因
- 已失败、被否决或确认无效的方案及原因

### 五、当前关键上下文

只记录实际存在且后续有用的信息：

- 文件、路径、函数、变量
- 错误信息、配置、接口
- 关键检索、测试和工具结果

路径、变量、错误、代码等精确信息直接保留原文，不要自行改写。

### 六、待办与下一步

按优先级记录：

1. 下一步直接做什么
2. 其余未完成事项
3. 当前阻塞点

### 七、历史摘要

只记录理解当前任务所必需的历史。

近期关键变化可以详细保留；久远历史允许轻微压缩，保留仍影响当前任务的内容。禁止机械复制全部旧交接内容导致持续膨胀。

## 输出要求

- 直接对话输出完整交接内容，不写前言后语。
- 信息完整优先，但禁止啰嗦、重复和无价值过程。
- 新的人工智能助手读完后，应当做到：**不用重新问、不重复查、不把推测当事实，可以直接继续执行。**
- **如果强调文件，则存放在 `docs/plans/上下文交接` 目录下。**
- 交接文件名：`交接-日期-简短关键词.md`
