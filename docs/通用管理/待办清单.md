## 纪律与教训

### Git 与推送

- **共享工作树 `git commit <精确文件>` 不等于 index 纯净**：他人已暂存的删除/新增若路径落入提交范围会被一并扫入。commit 前必须 `git diff --cached --stat` 全量核对 index，发现非本会话暂存项先 `git restore --staged <路径>` 再提交
- **推送前逐笔声明将上线哪些提交 + 推送后必须补线上核对并留档**（`AGENTS.md` §四 部署节）

### 门禁与验收

- **`gate:maintainability` 在工作区干净时无可拦项**：发布流程书面固定"push 前跑 preflight 留档"为唯一判定证据；终态全勾需全站逐文件重扫核验
- **门禁绿灯不覆盖类型**：`next.config.ts` 的 `typescript.ignoreBuildErrors: true` 导致 `gate:roles`/`gate:browser` 通过时仓库可能根本编译不过。验收记录要区分"门禁绿"与"类型绿"
- **多会话共用同一个本地库与门禁端口**：重要 gate 读数仍须独占时段跑两次（分库落地前）
- **端到端测试用假响应冒充"注入"会造成门禁假绿**：凡"注入/真失败"类判据，必须证明服务端与数据库真实发生 + 回查库状态；`route.fulfill` 造的响应只能作为前端契约渲染证据

### 函数级时区设置

- **函数级 `SET timezone` 会被函数重建静默丢掉**：今后任何人重建含 CURRENT_DATE 的函数必须带 `set timezone = 'Asia/Shanghai'`，由门禁 CURRENT_DATE 无时区即拦持续兜底
