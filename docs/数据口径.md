# 数据口径

## 1. 6个核心指标

| 指标 | 定义 | 公式/口径 | 来源 |
|------|------|-----------|------|
| 24h播放量 | 视频发布满 24 小时后的播放量 | 原始值，无二次计算 | `play_count`，作为各比率分母与爆款系数分子 |
| 互动率 | 点赞、评论、收藏、分享总和占播放的比例 | `(点赞 + 评论 + 收藏 + 分享) / 播放` | `interactionRate()` |
| 粉转率 | 涨粉占播放的比例 | `涨粉 / 播放` | `followerConversionRate()` |
| 导粉率 | 导粉占播放的比例 | `导粉 / 播放` | `fanConversionRate()` |
| 主页访问率 | 主页访问占播放的比例 | `主页访问 / 播放` | `homepageVisitRate()` |
| 爆款系数 | 当前视频 24h 播放相对账号基线的倍数 | `本视频24h播放 / 基线中位数` | `breakoutCoefficient()` |

说明：
- 以上 6 项里，5 个计算公式来自 [src/lib/video-metrics.ts](../src/lib/video-metrics.ts)。
- `24h播放量` 是原始观测值，不在该文件里做函数计算，但它是所有比率指标的分母，也是爆款系数的分子。

## 3. 爆款判定标准

爆款判定口径：
- `24h播放 ≥ 账号近30条中位数 × 2`

等价表达：
- `爆款系数 ≥ 2`

说明：
- 账号基线优先取近 30 条视频的播放样本中位数。
- 若样本不足，按下文“爆款系数冷启动规则”处理。

## 4. 下滑判定标准

下滑判定口径：
- `近7条中位数较前7条下降30%`

公式：
- `(近7条中位数 - 前7条中位数) / 前7条中位数 ≤ -30%`

判定前提：
- 两个窗口都必须有足够样本。
- 若前7条中位数为 0 或为空，不判定下滑。

## 5. 异常状态枚举

| 状态 | 含义 |
|------|------|
| normal / 正常 | 数据处于正常波动区间，无明显异常信号 |
| abnormal / 异常 | 新提交统一异常标记；异常详情下沉到 `punish_type`、`platform_notice`、`appeal` |
| 限流 | 旧数据兼容状态，读模型映射为异常，处罚类型为 `limited` |
| 删稿 | 旧数据兼容状态，读模型映射为异常，处罚类型为 `deleted` |
| 投流 | 旧数据兼容状态，读模型映射为异常，处罚类型为 `paid_boost` |
| 活动干预 | 旧数据兼容状态，读模型映射为异常，处罚类型为 `campaign_intervention` |
| 未满24h | 视频尚未到 24h 观察点，暂不进入 24h 口径比较（自动写入避坑案例库的钩子已于 2026-08-22 移除） |

说明：
- 新写入只使用 `normal / abnormal` 两档。
- 视频提交链路的异常状态仍以 `videos.anomaly_status` 为准，用于视频复盘与历史异常详情兼容；避坑案例模块已于 2026-08-22 下线，`violation_cases` / `knowledge_cases` 不再有新写入，仅保留历史数据供查询。
- 历史数据口径：高转化话术曾写入 `knowledge_cases(status=submitted)`，违规话术曾写入 `violation_cases`；两条写入链路均已随避坑案例下线停止。

## 6. 业务日期、上传时点与观察窗口

本系统的管理口径不是“当天有没有提交”，而是按日报归属的业务日期进行周、月汇总。实际业务通常在视频归属业务日的次日上传数据：

| 名称 | 实际含义 | 不能解释为 |
|------|----------|------------|
| 业务日（D） | 视频发布并归属统计的自然日，对应 `daily_reports.report_date` | 系统必须在当天完成数据上传 |
| 次日上传（D+1） | 在业务日的次日提交基础信息和已具备的 24h 观察数据，`uploaded_at` 记录实际上传时间 | 新增第二条日报，或把上传日改成业务归属日 |
| 24h 观察数据 | 播放、点赞、评论、分享、收藏、涨粉，以及由这些数据计算的核心比率 | 以未满 24h 的即时数据参与统一比较 |

统一规则：
- `daily_reports.report_date` 是周、月统计使用的业务日期；`uploaded_at` 只记录实际上传时间，不改变业务归属日期。
- 正常流程按 D+1 上传 D 的数据。基础信息与 24h 数据可以在同一次补录中提交，不因分阶段观察而产生两条日报。
- 历史补录必须选择合法的历史业务日期；验收或补录不需要等待真实 24 小时，但数据仍归属于所选业务日。
- 同一账号同一业务日只允许一条日报；重复提交应被拒绝，而不是更新成第二条业务记录。
- 文档或页面中的 T+0/T+1 仅用于描述观察阶段：T+0 指业务日，T+1 指次日观察/上传阶段；不表示员工必须在当天提交，也不表示管理侧按日检查是否上传。
- 周、月管理视图统一按 `report_date` 聚合；不能用 `uploaded_at` 代替业务日期，也不能用“当天是否上传”替代作品数、应发目标或月度完成情况。

## 7. 爆款系数冷启动规则

账号基线由 `getAccountBaseline()` 计算，规则如下：

| 样本量 | 口径 | strategy |
|--------|------|----------|
| ≥10条 | 直接取账号自身播放中位数 | `self` |
| 3-9条 | 账号自身中位数 × 50% + 团队中位数 × 50% | `mixed` |
| <3条 | 不给基线，不计算爆款系数 | `insufficient` |

补充：
- 中位数函数见 [src/lib/video-metrics.ts:33-39](../src/lib/video-metrics.ts#L33-L39)。
- 基线策略见 [src/lib/video-metrics.ts:41-56](../src/lib/video-metrics.ts#L41-L56)。

## 8. 内容吸引力指标优先级

内容吸引力优先看“先吸引点击，再承接停留，再放大互动与转化”。建议优先级如下：

| 优先级 | 指标 | 作用 |
|--------|------|------|
| P1 | 24h播放量 | 最终结果指标，先看是否拿到分发 |
| P2 | 爆款系数 | 判断是否显著跑赢账号常态基线 |
| P3 | 互动率 | 判断内容是否激发反馈与参与 |
| P4 | 主页访问率 | 判断内容是否推动用户进一步了解账号 |
| P5 | 粉转率 | 判断内容是否带来直接涨粉 |
| P6 | 导粉率 | 判断内容是否完成更深层转化 |

使用建议：
- 看单条是否“爆”时，先看 `24h播放量 + 爆款系数`。
- 看内容本身是否“有吸引力”时，先看 `互动率`，再看 `主页访问率 / 粉转率 / 导粉率`。
- 若播放高但转化弱，优先排查内容承接问题；若播放低但转化高，优先排查分发与选题问题。

## 9. 个人成长页六维能力口径

成长页只允许使用以下一套能力六维，唯一代码来源是 `src/lib/growth-page.ts` 的 `GROWTH_DIMENSION_RULES` 与 `getDimensionValues`：

| 维度 | 计算 |
| --- | --- |
| 开头留人 | `completion_rate_5s` 平均值 |
| 中段跳出 | `max(5秒完播率 - 整体完播率, 0)`，越低越好 |
| 整体完播 | `completion_rate` 平均值 |
| 增长转化 | 每条 `follower_gain / play_count × 100` 后取平均 |
| 互动吸引 | 每条加权互动数除以播放后取平均；权重为评论 0.35、分享 0.25、点赞 0.25、收藏 0.15 |
| 话题爆点 | `play_count` 平均值 |

评级统一比较当前用户与其他同事团队均值：表现比例 `≥1.1` 为强、`≤0.9` 为弱，中间为中；中段跳出因越低越好，比例方向反转。完整空值、可信度、对标和前端字段约定见 `docs/reference/个人成长数据契约.md`。

## 10. 发布管理月度作品口径

- 实发作品数：页面统计范围内 `get_fulfillment_range.published_count` 求和；一天发布多条按真实条数累计，不能拿“发布天数”代替作品数。
- 应发目标：统计范围内自然日数，扣除状态为 `leave`、`waived`、`exempted` 的已批准请假/豁免日，并由成员入职日期裁剪。
- 还差作品数：`max(应发目标 - 实发作品数, 0)`；超发不显示负数。
- 达成率：`实发作品数 / 应发目标`；应发为 0 时记 0。
- `pending` 豁免申请只在月历显示为待审批黄色，不提前扣减应发目标；审批通过后由授权记录进入批准请假/豁免口径。
