## Findings

### Critical

无——核心任务（盘今日作品→定位异常→打开抽屉看证据→复制文案）全程可走通。

### High（困惑/摩擦/信任损伤）

- **H1. 375px 宽松视图表格内容严重重叠，标题不可读**
  - *Where*: `/admin/content` 列表，`content-list-table.tsx`——宽松模式 table 为 `min-w-full`（无最小宽度兜底），完整模式有 `min-w-[960px]` 可横向滚动，宽松模式没有
  - *现象*: 375px 下标题列被压垮至 0 宽，综合评级文字与状态徽章、核心指标互相叠印（截图行内可见「综合优」压在「已入库2.8%」上），视频标题完全不可见；768px 正常（容器横滚）
  - *Screenshot*: `docs/ux-audit/screenshots/C-content/t5-resp-375.png`（对照 `t5-resp-768.png`）
  - *Thread/Scenario*: 响应式扫描 375
  - *Fix*: 宽松模式补最小宽度（如 `min-w-[720px]`）让容器横向滚动，或 375 断点换卡片布局
- **H2. 「打开源视频网页」对脏 video_url 无校验，渲染成本站死链**
  - *Where*: `detail/content-detail-metrics.tsx` L129——`<a href={video.video_url} target="_blank">` 直接输出原值
  - *现象*: 实测 video_url="131"（测试数据）被浏览器解析为相对链接 `http://localhost:3000/admin/131`，新标签打开落在本站不存在路由；另一条 video_url 是整段分享文案（内嵌抖音短链未提取）。列表 API 抽扫 1980 条中至少 2 条此类脏值
  - *Screenshot*: `t6-source-link.png`（href 可见）
  - *Fix*: 渲染前校验 `^https?://`，非绝对 URL 不渲染按钮（或先做存量 video_url 清洗）
- **H3. 「异常提醒」分桶条在 10-01 重构中移除，删稿/限流/腰斩归因信息无处可看，遗留死代码**
  - *Where*: `content-page-client.tsx` L365-398
  - *现象*: git 考古实锤——b1b04a6d（10-01 筛选栏重构）删除了「异常提醒 (N)：N 异常 · N 删稿 · N 限流 · N 腰斩 · 最需关注: 名单」整条横幅，替代品「异常 294」开关只有一个总数；分桶计数 useMemo 至今还在每帧计算但 JSX 无人引用（死代码）。管理员要做异常归因（本页 persona 的核心动作）现在必须逐个点开抽屉才能区分删稿/限流/腰斩
  - *Screenshot*: 列表现状见 `t1-first-screen.png`（仅「异常 294」）；被删结构见 `git show b1b04a6d`
  - *Fix*: 二选一——把分桶计数还给「异常」开关的徽标或 hover 摘要；或删除死代码收敛口径。若恢复展示，沿用原「总数=各桶相加」互斥口径
- **H4. dev 实测：整包全量列表体量 7.65MB（list API）/ 初始文档 decoded 11.6MB**
  - *Where*: `/api/admin/content/list` + `/admin/content` RSC 直出
  - *实测*: 1980 视频 + 1951 快照；list API 7,646,160 字节 / dev 7.3s；初始导航 transferSize 3,208,440 / decodedBodySize 11,596,983；二次加载首屏表格可见 7.1s、networkidle 15.7s（dev 口径，生产会好于此但体量数字是真实的）；另每次进页 5 批 topic-library-status 请求（400 ID/批，符合分批上限设计）
  - *定性*: 这是登记在案的「进页面即全量列表」债的实测基线；dev 慢不作 bug，但 1980 条整包直出的生产体量值得关注（快照明细占了列表 payload 大头）
  - *Fix*: 快照明细延后到抽屉打开时按需取；或列表 payload 只保留列展示字段

### Medium（可用但有损耗）

- **M1. topic-library-status 批请求出现 2×500**——客户端按批容错，toast「选题库状态有 2 批未加载成功，未覆盖的视频暂不显示入库状态与评级」明确降级（t6 复现，dev 负载下）；建议查服务端日志确认是否有确定性错误
- **M2. 视图切换/归档加载态只有整区 65% 变暗+禁点，无进度指示**——dev 下归档首次切换实测 5.6s~30s+（首编译），期间点击被吞（pointer-events-none），用户会以为「点了没反应」；建议加行内 spinner 或「加载中…」文案
- **M3. 100 行长列表滚动时吸顶表头未吸住**——页容量 100 下滚过 3~4 行后列头消失（截图 `t5-100-rows.png`），宽表 12 列对数困难；`吸顶表头`注释与实测不符
- **M4. 页容量/排序/滚动位置刷新后不保留**——刷新后 URL 保留 view/scope/筛选但页容量回到 20（实测 100→20）；返回用户每次要重设
- **M5. 发布时间为空时显示「-」且抽屉大卡无占位说明**——审计B 测试视频（未发布）发布时间一栏空（截图 `t4-row0-drawer.png`），列表端为「—」，可接受但建议统一为「未发布」
- **M6. 术语并存：大盘卡「转粉率」与明细行「导粉量/导粉率」**（截图 `t4-row0-drawer.png` 两处相邻）——疑为两个口径，未查数据口径文档前不动工，登记待口径确认

### Low（打磨）

- **L1. 首访引导弹窗在 hydration 后才挂载**——若用户在弹出前已开始点击（自动化 2 次复现遮罩拦截、受控 3/3 干净），弹窗会叠在已打开的抽屉上；低频竞态，建议挂载后阻塞列表交互或提前到服务端
- **L2. 选题库状态文案「暂未取得选题库状态」偏黑话**——对管理员未解释是「还没到 24h」还是「识别失败」
- **L3. 数据卫生**：同账号 4 条同名同指标视频（明日振奋人心×4）、video_url 脏值（见 H2）——非本页 bug，建议数据治理
- **L4. 表头排序方向箭头「↕/▼」用字符拼进文本**，读屏与视觉都弱于图标
