## Findings

### High（5）

- **T7-1 搜索稳定失效：0 请求、列表不过滤**
  - *Where*: /topics 工具栏搜索框 → debounce → pool fetch effect（`src/lib/topics/data/hub.ts` L246-265、`hub-state.ts` L88-94）
  - *复现*: 干净会话逐键输入「黑匣子」/乱串，`/api/topics/pool` 请求 0 个、44 张卡不过滤；3/3 会话一致（t6-3a、t7-1a、t7-1b）。同会话分类 chip 点击正常（1 请求、44→6 张，同一 effect），失效被隔离在搜索 debounce→poolQueryKey→fetch 链路
  - *Screenshot*: `t7-07a-search-empty.png`
  - *影响*: 阿珂防撞车/查重复的核心工具等于没有
  - *修复*: 以 chip 触发路径为对照审查 debounce effect 交接；补"搜索必发请求"回归测试

- **T2-2 视图切换的首次点击可被静默吞掉**
  - *Where*: 同上 pool fetch effect 的 `previousPoolQueryKey === null` 首帧哨兵
  - *复现*: 进入 /topics 点「在写选题」→ **激活态已变**、请求 0、列表停留"全部"44 张；再点「全部选题」同样 0 请求；第三次才生效（t2j R1 铁证）。R2-R4 共 11 次正常；t2e/t2f/t2h 复现。dev 下复现率约 20-25% 会话，生产低概率但存在
  - *Screenshot*: `t2-02g-myclaims-with-claim.png`（激活"我的选题"却显示全池）
  - *修复*: mount 时同步哨兵（layoutEffect/初始化赋值），或点击 handler 直接触发 fetch

- **T2-5 认领后无释放入口**
  - *Where*: 「在写选题」视图卡片仅有「继续创作此题」；详情抽屉无释放按钮；全前端对 `/api/topics/sub-topics/[id]/return` **零调用**、UI 无"释放/退还"文案（端点本身 200 可用，本轮清理已实测）
  - *影响*: 认领错了无法自助退出；组员名下现存 8 条在写认领堆积（含 10-05 残留 2 条），只能永远挂着或等写完
  - *修复*: 在写卡/抽屉加"退还选题"按钮（二次确认），走现成 `/return` 端点

- **T2-1 切视图后「全部选题」计数显示其他视图总数**
  - *Where*: `PoolToolbar.tsx` 仅 all 视图渲染 `{totalCount}`，但 totalCount 是共享 `poolTotalCount`（hub-state.ts）
  - *复现*: 「全部选题 44」→ 点「我的选题」→ 显示「全部选题 1」（1 是我创建的总数）；切回恢复 44。稳定复现（t2c、t2g）
  - *Screenshot*: `t2-02b-myclaims-clicked.png`、`t2-02c-tab-count-after-mine.png`
  - *影响*: "全部选题 1"会被读成"题库只剩 1 条"，与撞车判断直接相关
  - *修复*: 各 Tab 显示各自计数，或非 all 视图隐藏该计数

- **T3-1 创建被服务端 400 拒绝后弹窗静默无反馈**
  - *Where*: TopicCreateModal `handleSubmit`（源码有 catch→setErrorMsg 路径但实测未呈现）
  - *复现*: 500 字标题+合法其余字段 → `POST /api/topics/sub-topics -> 400`（服务端正确拒绝、未入库）→ 弹窗保持打开、无错误文案、无 toast（弹窗全文实测仅相似建议+按钮）
  - *Screenshot*: `t3-03e-400-feedback.png`
  - *修复*: 核对 fetchTopicJson 对 400 的 message 传递与 errorMsg 渲染条件

### Medium（6）

- **T2-3「我的选题」标签语义与内容错位**: 「我的选题」=my_created（我创建的，实测仅 1 条），我认领在写的 4+ 条只在「在写选题」；写完/释放后两边都不出现，无"我最近处理过什么"入口。建议改名「我提交的」/「我的认领」或合并视图加状态标
- **T2-4 认领与跳飞书强耦合的静默失败面**: `runFeishuCreationFlow` 顺序为 复制提纲→校验飞书地址→markWriting→开窗；剪贴板失败或团队未配置飞书 URL 时**不认领**，仅一条 4 秒即逝的 error toast，列表无任何变化（headless 实测 0 API + 卡片无变化）。建议认领与跳转解耦或提供兜底动作
- **T3-2 归属母题 Select 选中后显示 UUID**: 弹窗 Select 内文本为 `6681a659-…`（实测 innerText），提交前无法确认选了哪个母题

- **T5-1 动态面板"往期成片产出 0 条"与上方"最新成品《龙头二进三》(07-27)"同屏矛盾**: "往期"疑有时间窗但无标注，用户读到自相矛盾的信息
- **T7-2 移动端认领按钮热区不足**: 375px 下 84×36px、768px 下 84×28px，低于 44×44 触控标准（认领是移动端主高频动作）

## Thread 结果

### T1: 正常进入 + 首屏 0 请求契约实测

**首屏 0 请求契约：✅ 实测通过。** 组员账号正常进入 /topics，从导航到 networkidle + 2s 静默，客户端 `/api/topics/*` 请求数 = **0**。首屏仅有的 API 请求来自全局布局：`POST /api/usage-events`（202）、`GET /api/dashboard/operator-members`（200）、`GET /api/action-center/summary`（200）。bootstrap 服务端注入契约成立。

- 首屏加载（dev 编译后）11.7s（dev-mode 观察）；title「选题库 - DYData」；首屏 4xx/5xx 0；console 错误 0
- 元素穷举：首屏可见可交互元素 79 个（导航 6、动态条 3、Tab 3、工具栏 7、chips 9、卡片按钮 ~39、分页 3）
- **预存问题**：池子第 1 条为 10-05 审计残留卡「审计E-20261005-RM2344 移出精查」

### T2: 认领 → 我的认领 → 释放 → 池子复原

**Tab 语义（源码+实测）**: 「全部选题」=all；「我的选题」=my_created（我创建）；「在写选题」=my_claims（我认领在写，服务端查 sub_topic_claims status=writing）。

- **认领主链路 ✓**: 点击卡片「去飞书创作」→ toast「提纲已复制，已标记在写，正在前往飞书」→ `POST /api/topics/sub-topics/[id]/start-scripting` → 卡片变「已在写 · 1人参与 · 1人在写 · 继续创作」→ 跨会话持久 ✓ → 团队动态条"最新在写"即时更新 ✓（截图 `t2-02m-claimed-card-new-session.png`）
- **认领成本**: 1 次点击；无确认弹窗（非破坏性，合理）；反馈即时
- **释放**: UI 无任何入口（见 T2-5）；本轮清理用 `/return` 端点释放成功并验证
- **池子复原**: 释放后列表是否自动刷新未验证（UI 无入口，只能 API 层释放）
- 发现 T2-1/2/3/4/5 见 Findings

### T3: 创建母题/子题 → 编辑 → 移出题库（自建数据）

- **表单**: 智能粘贴提取区 + 归属母题* + 子题标题* + 一句话 Hook* + 情绪/受众（可选）
- **空提交 ✓**: 「还有必填项没填：母题、子题标题、一句话 Hook」一次列全，表单保留，0 请求
- **相似选题防撞车 ✓**: 输入即调 suggest 接口，显示「发现相似选题 · 建议差异化切角…」+ 相似卡列表
- **500 字标题**: 服务端 400 拒绝（未入库）但前端静默（T3-1）；母题 Select 显示 UUID（T3-2）
- **作者可见性 ✓**: 自建题抽屉右上角有编辑/移出图标按钮（截图 `t6-06b-old-detail-redirect.png`）；编辑表单可打开
- ⚠ 编辑保存与移出确认完整链路被 dev 热更新两次中断，未走完（未覆盖项 2/3）

### T4: 他人选题详情抽屉（作品翻页与排序）

- **只读边界 ✓**: 非作者抽屉按钮仅 上一篇/下一篇/关闭/最高播放/最新发布/在工作台录入/去飞书创作——编辑、移出不可见（截图 `t4-04a-other-drawer.png`）

### T5: 横向对比与团队动态条口径

- 认领实时反映到动态条 ✓；动态展开 0 请求（bootstrap 注入 ✓）

### T6/T7: 深链、中断、搜索、键盘、响应式、错误巡检

- **深链 ✓**: `/topics?topic_id=<uuid>` 自动开抽屉（详情+claims 请求各 2 次——React StrictMode dev 双跑，生产无影响，dev-mode 观察）；`/topics/<uuid>` 旧详情页 200 重定向到 `?topic_id=` 形式并无缝开抽屉 ✓ 无 404；无效 id 静默回落（Low）

- **搜索**: T7-1 失效；chip 筛选 ✓
- **键盘**: Tab 焦点序列可见合理 ✓；ESC 未验证（未覆盖）
