## 零、开 PR 之前必须先对齐的四个前提

1. **PR ≠ 上线。** 本项目约定 `main` 一旦更新即触发 Vercel 生产部署（见仓库 `AGENTS.md`）。开 PR 只是把改动摆出来等评审；**合并到 `main` 才是上线动作，仍需当轮明确授权**。
2. **生产 migration 不进 PR、也不能靠 PR 执行。** `supabase/migrations/20261016090000_remove_group_mode.sql`（1211 行，含 `drop table ... cascade`）随 `edc1e50a` 的批次已到 `main`，但 `vercel.json` 无迁移钩子、`build` 仅 `next build`，**不会随部署自动执行**。执行它是一次独立的生产写操作，需单独一轮、单独授权、单独定回滚点。**本 PR 交付不代表它被执行。**
3. **分支与合并人要先定。** 当前本地与 `origin/main` 完全一致（`git log origin/main..HEAD` 为空），PR 需从当前 `main` 拉分支。请先确认：分支名、合并窗口、合并后由谁做线上核对。
4. **共享主干，禁止夹带。** 工作区还有别的会话未提交的改动（`日志/2026-10-15.md` 等）。PR 的提交必须逐个显式 `git add` 指定文件，**不得用 `git add -A`**；开 PR 前核对差异文件清单，确认没有夹带别人的改动。

## 一、剩余事项清单（已按用户代价排序，并标注真实工作量）

### 1.1 【必修 · 现在必然失败】角色验收用例仍在对已删除的接口断言

这是本次复核最要紧的发现，也是**唯一一个"不修就一定红"的项**：

`tests/roles/权限矩阵直接API.spec.ts` 里还有 7 处指向已删除路由的断言，最后改动停留在更早的提交（`70143fa5`），集团模式下线时**没有同步更新**：

| 行 | 现有断言 | 现状 |
|---|---|---|
| 80 | 组员 `POST /api/group-mode/enter` → 期望 403 | 路由已删，实际 404 → **必红** |
| 92 | 组长 `POST /api/group-mode/enter` → 期望 403 | 同上 → **必红** |
| 105 | 所有者 `POST /api/group-mode/exit` → 期望 200 | 同上 → **必红** |
| 106/111/115/120 | 所有者 enter/exit/status 闭环 | 同上 → **必红** |

**注意：`npm test` 全绿（2229/2229）抓不到这个。** Playwright 角色用例不在 `npm test` 的范围内，只在 `npm run gate:roles` 里跑。这正是这批失效引用一直没被发现的原因——**"全量单测通过"不能替代"角色验收通过"**。

修法：不是简单删断言，而是把这三条转成**"下线后不可再进入"的负向回归**——期望 `404`（而非 403），证明入口确实不存在、且不残留可直调的跨公司链路。

### 1.2 【已有现成用例 · 只需跑起来并留证】写拒绝 / API 直调 / 组员只读与范围

复核意见里列的"第一档"三项，实际上仓库早有对应用例，**不用重造**：

| 复核意见要求 | 现成用例 | 位置 |
|---|---|---|
| 组员写操作真实拒绝 | 组员视频生命周期写请求必须 403；发布管理无「批量标记」；抽屉内无任何写控件 | `tests/roles/数据管理作品复盘只读.spec.ts` 第 113–136、139–152 行 |
| API 直调越权 | 「组员域：读接口放行，管理配置与写接口拒绝」，直打读/写接口断言 200/403 | `tests/roles/权限矩阵直接API.spec.ts` 第 74–83 行 |
| 组员可见范围行为级验证 | 日历接口必须返回本公司**多名**成员（范围一旦退化成 "只剩自己" 即失败） | 同文件第 165–172 行 |

**这三项目前缺的不是用例，是"跑过并留下读数"。** 请执行 `npm run gate:roles`（真实角色 Playwright 验收，凭据取自 `.env.ai-test.local`），把通过的用例名与读数写进交付说明。

### 1.3 【确实还缺】导出范围 / 跨公司对象直链 / 响应式与键盘

- **导出范围**：验证导出结果不小于、也不大于该角色应有的范围。导出一旦发出就无法回收，优先级仅次于写拒绝。
- **跨公司对象直链**：组员（第二用户）打开所有者曾访问过的深链，验证页面、接口、对象详情、导出四者均不扩大范围。
- **响应式 / 键盘 / 刷新保持**：1440 / 1024 / 768 / 375，Tab 与 Escape，刷新与中断后范围是否保持。

### 1.4 【不进 PR，单独立项】

- 生产 migration 执行（见第零节第 2 条）。
- 真实账号人工复验中"必须有人来点"的部分。另：**测试组员 ≠ 真实组员**，请挑一个真实组员抽查一次（历史归档归属、待处理豁免申请有先例风险）。

## 四、纪律

- 只按本意见列的施工项动手，**不要顺手重构无关代码、不要动审批链等其他在办批次**。

- 提交前全量核对暂存区，确认未夹带其他会话的删除/修改。
- 交付前对照本意见第 1、2 节逐项自查，缺哪项就明写 BLOCKED，**不要用"已覆盖"含糊过去**。
