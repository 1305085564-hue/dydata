## 结论先行

- 当前有效权限模型只有组员、组长·管理、公司所有者和归档账号四类；公司所有者、组长和组员都按可信公司/团队归属工作，系统不再提供跨公司视角。
- 原审计中“96 条定向测试全部通过”、集团模式入口和集团令牌链路均属于旧快照结论。当前代码定向测试为 **76 条通过、0 失败**；集团模式相关测试已随功能删除。
- 本轮已删除集团模式 UI、三条 API、权限上下文与数据范围分支、相关服务端库和测试，并新增数据库收口 migration。历史 migration 仅作迁移历史保留，不代表当前运行入口。
- 真实 Chrome 证据仍只覆盖公司所有者和测试组员的既有主线；写接口拒绝、导出范围、API 直调、跨公司深链、生产 migration 后的真实页面行为尚未取得行为级证据。

## 产品边界基线

| 身份 | 应看到 | 应看到的历史 | 明确不能做 |
|---|---|---|---|
| 组员 `member` | 个人数据；数据管理、视频复盘、发布管理三页为本公司只读 | 本公司允许查询的历史记录 | 审批、成员管理、作品/发布写入、跨公司读取 |
| 组长 `admin` | 当前公司在职成员 | 当前公司历史记录 | 跨公司审批，管理组长/所有者/自己，升组员为组长 |
| 公司所有者 `company_owner` | 当前公司全部成员 | 当前公司含归档历史 | 跨公司读取或写入 |
| 归档账号 | 无当前操作范围；由有权人员查历史 | 保留历史记录 | 登录、提交、审批、指派、提醒、上传、修改、恢复 |

依据：[`docs/业务逻辑/权限与访问控制.md`](../业务逻辑/权限与访问控制.md) 第 13–19、43–50、64–79、122–128 行。

## 已确认的实现边界

1. **身份先于范围**：非在职账号、角色字段冲突、缺少可信角色时，统一身份解析返回空，不继续放行。见 [`src/lib/current-permission-context.ts`](../../src/lib/current-permission-context.ts) 第 37–59 行。
2. **范围只来自可信归属**：组长、所有者和组员的公司/团队范围来自服务端 `profiles.team_id`；请求参数不能替换可信归属。见 [`src/lib/data-access-scope.ts`](../../src/lib/data-access-scope.ts) 第 160–180 行。
3. **组员只读放宽有边界**：数据管理、视频复盘、发布管理三页可放宽到本公司历史与在职成员，结果不得传入写路径。见 [`src/lib/data-access-scope.ts`](../../src/lib/data-access-scope.ts) 第 230–275 行。
4. **历史归档不丢失**：本公司范围包含在职成员与归档前属于本公司的历史成员；当前操作另用 `activeVisibleUserIds` 限制在职成员。
5. **页面隐藏不是安全边界**：接口还需要统一鉴权和范围过滤；service role 查询必须有等价鉴权与 `visibleUserIds` 限制。见权限文档第 134–160 行。
6. **账号选择与团队归属是两条链路**：顶部工作账号选择器只切换工作账号；成员与团队架构入口只对有 `manage_members` 的账号呈现，不能改变服务端可信公司归属。

## 集团模式下线结论

产品口径已确认：集团模式按已取消处理。当前代码不再有可点击入口、状态 API、进入/退出 API、集团权限上下文或集团令牌消费分支。

已完成的施工范围：

- 删除设置弹窗、导航壳层和成员管理入口中的跨公司切换 UI 与状态传递。
- 删除 `/api/group-mode/status`、`/api/group-mode/enter`、`/api/group-mode/exit`、共享鉴权、服务端库及对应测试。
- 删除权限上下文、数据范围、导出、审批、成员生命周期、视频生命周期和管理 AI 中的跨公司分支；公司所有者继续按当前公司范围工作。
- 新增 `supabase/migrations/20261016090000_remove_group_mode.sql`：删除集团会话/资格表，撤销旧令牌函数和权限重载，重建当前公司范围函数与豁免原子 RPC，并把旧 `profiles.data_scope = 'all'` 收口为 `team`。
- 历史 migration 与历史归档文档保持只读，不能作为当前 API、权限或数据库状态的证明。

迁移的生产执行仍未发生。该 migration 含 `drop table ... cascade` 和生产数据归一化，必须在单独的生产变更记录中确认回滚边界与“范围收窄、既有集团会话失效”可接受后执行。
