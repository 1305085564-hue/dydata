## 产品边界基线

| 身份/模式 | 应看到 | 应看到的历史 | 明确不能做 |
|---|---|---|---|
| 组员 `member` | 个人数据；数据管理、视频复盘、发布管理三页为本公司只读 | 本公司允许查询的历史记录 | 审批、成员管理、作品/发布写入、跨公司读取 |
| 组长 `admin` | 当前公司在职成员 | 当前公司历史记录 | 跨公司审批，管理组长/所有者/自己，升组员为组长 |
| 公司所有者 `company_owner` | 默认当前公司全部成员 | 当前公司含归档历史 | 未开启集团模式时跨公司读取或写入 |
| 集团模式 | 集团内所有公司在职成员 | 仅按权限查询历史 | 由 URL 参数或普通客户端自称集团模式 |
| 归档账号 | 无当前操作范围；由有权人员查历史 | 保留历史记录 | 登录、提交、审批、指派、提醒、上传、修改、恢复 |

依据：[`docs/业务逻辑/权限与访问控制.md`](../业务逻辑/权限与访问控制.md) 第 13–19、43–50、64–79、122–128 行。

## 已确认的实现边界

1. **身份先于范围**：非在职账号、角色字段冲突、缺少可信角色时，统一身份解析返回空，不继续放行。见 [`src/lib/current-permission-context.ts`](../../src/lib/current-permission-context.ts) 第 42–67、70–110 行。
2. **集团模式不是前端参数**：服务端读取 `profiles` 的角色与在职状态，签发哈希令牌；退出会撤销会话，cookie 为 HttpOnly + SameSite Strict。见 [`src/app/api/group-mode/_shared.ts`](../../src/app/api/group-mode/_shared.ts) 第 21–35、38–64、67–99、102–108 行。
3. **范围由可信成员归属生成**：组长/所有者当前公司范围来自服务端 `team_id`；集团模式才为全公司；调用方传入的 `teamId` 不会替换可信归属。见 [`src/lib/data-access-scope.ts`](../../src/lib/data-access-scope.ts) 第 54–75 行及其团队加载逻辑。
4. **历史归档不丢失**：本公司范围包含在职成员与归档前属于本公司的历史成员；当前操作另用 `activeVisibleUserIds` 限制在职成员。见同文件第 106–120 行及定向测试。
5. **页面隐藏不是安全边界**：接口还需要统一鉴权和范围过滤；项目规则明确 service role 使用后必须有等价鉴权与 `visibleUserIds` 限制。见权限文档第 134–160 行。
6. **账号切换与团队切换是两条不同链路**：顶部工作账号选择器只调用 `selectDashboardAccount(account.id)`；成员与团队架构入口只对有 `manage_members` 的账号呈现。见 [`src/components/user-workspace-popover.tsx`](../../src/components/user-workspace-popover.tsx) 第 195–215、277–294 行。它不能替代集团模式验收。

## 必须补做的真实验收

拿到两个真实登录态（公司所有者 + 普通组员）并恢复可用本地隔离环境或线上登录后，按下面顺序继续：

1. 所有者：当前公司 → 进入集团模式 → 观察成员、数据管理、视频复盘、发布管理、导出；退出/刷新/过期后确认立即回到当前公司。
2. 组员：工作台、选题库、视频复盘只读、数据管理只读、发布管理只读；确认只能看到本人或本公司规定的只读范围，所有写入口与直链均得到清晰 403/重定向。
3. 团队切换：所有者集团模式下切换团队、搜索、归档筛选、批量选择；确认已选对象不会跨团队残留，历史归档按原归属团队展示。
4. 第二用户：组员打开所有者曾访问的深链，验证页面、API、导出和对象详情均不扩大范围。
5. 最后再做 1440/1024/768/375 宽度、键盘 Tab/Escape、刷新与中断恢复；这些属于真实浏览器验收，不能由本轮静态测试替代。

## 审计判定

本轮交付为：**权限边界静态盘点 + 公司所有者浏览器入口观察 + 阻塞证据**。  
不是“全站权限通过”，也不是“发现越权漏洞”。继续审计所需外部条件只有两项：

- Chrome 中保持 DYData 公司所有者登录态；
- 提供可切换的普通组员登录态，或安排一个可安全使用的组员测试账号。
