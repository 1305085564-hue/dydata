## Summary

表单信息架构清晰（截图→指标→共创伙伴→内容→提交），OCR 失败降级明确、缺项列表具体可点、草稿自动保存可用。但提交主链路存在一个 Critical 死角：发布时间只能来自 OCR 识别且输入框永久禁用，dev 环境 OCR 通道不可用（AI_CHANNEL_UNAVAILABLE）导致新建＋补交全部无法提交，界面只给「重新上传」一条路、没有任何兜底出口。其余高严重度问题集中在「按钮禁用时不告诉用户缺什么」「日历绿点与历史数据矛盾」「草稿切日期回来不自动恢复」。

**未覆盖项与原因**：
- **通知铃铛/通知中心**：精确定位失败（header 按钮无 aria-label，svg 选择器未命中），归属行动中枢分片，未在本分片强测。
- **Thread 2「编辑已提交日报」**：测试账号历史手稿为空（0 条），今日提交又被 OCR 通道阻断无法自造已提交数据 → 无法进入编辑模式。编辑相关源码走查确认 `dataSource==="manual"` 时回填话术、`resolveCompleteEditPayload` 组装编辑包，但 UI 行为未实测。
- **Thread 5「从历史进入编辑→取消回摘要」**：同上，历史列表空，只验证了空态文案质量。
- **多选上传/拖拽上传/重新识别按钮**：多选与拖拽需要系统级文件对话框/拖拽事件，headless 下仅验证点击无报错；「重新识别」未单独触发（手输路径已覆盖槽位恢复）。
- **Heavy Data 多态（100+ 行列表）**：按数据纪律不灌库；dashboard 主要列表（历史手稿）实测为 0 条空态，1 条/多条形态未覆盖。
- **提交成功的服务端校验与提交后行动项（submitted-view）**：被 C1 阻断，未触达。
- **一键粘贴**：headless 无剪贴板权限，点击无反应未定性。
- **豁免「特殊豁免（不该交不交）」模式**：只验证「请假」模式全程；特殊豁免的多日期模式未走。

## Findings

### Critical（任务无法完成）

- **C1. 发布时间硬依赖 OCR 且无手动兜底，OCR 通道不可用时新建＋补交全部无法提交**
  今日新建（create）与历史补交（实测 backfill 同样卡此门槛）的提交按钮都以「发布时间已确认」为必要条件；发布时间只能来自完播截图 OCR（`PublishedAtPicker` 硬编码 disabled，界面明示「不能手动修改」），源码注释确认服务端对未确认发布时间一律 409、「用户连『申请补交』都拿不到」。dev 环境 OCR 对 4 个不同会话、2 种图片全部返回 `AI_CHANNEL_UNAVAILABLE`（500）。用户卡死时唯一提示是「请重新上传能看清"发布"时间的完播截图」——若手头截图无法识别（拍糊、通道故障），永远交不了日报，且无「稍后重试/联系谁/跳过」的出路指引。
  - *Where*: /dashboard `form-v2/left-column.tsx`（发布时间 disabled）、`提交状态机.ts`（publishedAtUnconfirmed 阻塞 create）、`/api/ocr-screenshot`（500）
  - *Screenshot*: `t1f-02-gate-check.png`、`t3c-02-still-disabled.png`
  - *Thread*: ①③
  - *备注*: 「发布时间服务端保底不可改」是已知设计决定；本条报的是 **OCR 通道故障时无兜底出路**，不是要求放开手动编辑。建议至少补「今日确实无法识别时申请人工登记」的出口。

### High（困惑、摩擦、信任损伤）

- **H1. 提交按钮禁用态零指引**：表单未齐备时「确认提交立卷」灰色 disabled，底部左侧除「⌘/Ctrl+Enter 提交」外无任何缺项提示；「待补全：缺少互动截图…」列表只在 `hasAttemptedSubmit=true` 后渲染，而按钮 disabled 用户根本点不了 → 该列表永远无法自然触达。小周填了标题文案后按钮还是灰的，不知道还差两张截图。
  - *Where*: `form-v2/submit-footer.tsx`
  - *Screenshot*: `01-dashboard-initial.png`、`t1d-02-filled.png`
  - *Fix*: 禁用时常驻显示缺项摘要（`issueSummary` 已能算出缺什么）。
- **H2. 必填项「题材标签」无必填标记**：题材标签（干货/复盘）是提交必要条件（计入 totalIssueCount），但无红星、无「必填」字样，与视频标题*/文案*的标记标准不一致；不选时按钮静默变灰。
  - *Where*: `form-v2/left-column.tsx` 题材标签分段控件
  - *Screenshot*: `t3c-02-still-disabled.png`
- **H3. 草稿切日期回来不自动恢复，恢复入口弱**：今日填草稿（标题+播放量）→ 切到历史日期 → 切回今日，表单是**空的**；唯一线索是卡片右上角一行小字「未交草稿 · 恢复 · 丢弃 +2」。怕丢数据的小周会以为刚才填的全没了。实测点击「恢复」后内容完整回来（标题+指标），说明存储可靠、只是恢复交互缺失。
  - *Where*: `video-submit-panel-v2.tsx` + 草稿条
  - *Screenshot*: `t3-03-back-to-today.png`、`t6-02-after-restore.png`
  - *正向结果*: 草稿 key 按模式隔离验证通过——今日草稿未串进补交表单（`t3.log`），未出现「切模式草稿互串」的 Critical 情形。
- **H4. 日历绿点（已交）与历史数据矛盾，已交日期可再进补交表单**：日历上 10-04、10-05 显示绿点（图例=已交），但「历史手稿」弹窗为空态、豁免弹窗里这两天也无豁免/请假标记；点击 10-05 后 21 秒内始终显示「创作纪事补录 (2026-10-05)」补交表单而非已提交摘要。用户可以对「已交」日期再次填写提交（重复立卷风险），且无法解释绿点来源——三处数据源（loader 的 monthSubmittedDates / activity 历史 / 豁免状态）相互矛盾。
  - *Where*: 日历（`SubmissionCalendar`）× `resolveSubmitPanelMode` × 历史弹窗数据源
  - *Screenshot*: `t3b-02-picked-5-final.png`、`t5-01-history-dialog.png`、`t3-01-calendar-open.png`
- **H5. 豁免申请提交后无任何可见成功反馈，且同会话内状态不同步**：提交请假申请后弹窗直接关闭，无成功 toast/横幅（截图 t4b-03 无任何反馈痕迹）；同会话内立即重开弹窗，10-03 仍显示可申请状态（`t4b-05-dialog-reopen.png`），可以重复提交同一天；重新加载页面后才显示「申请审批中」并锁定（`t10-cleanup-reopen.png`）。
  - *Where*: `redesign/exemption-dialog-v2.tsx`（提交成功处理）+ `localPendingExemptionDates` 同步
  - *Fix*: 提交成功 toast＋同会话内立即更新 pendingDates。

### Medium

- **M1. OCR 识别等待 12–75 秒无进度预期**（dev-mode 观察）：识别中槽位显示「AI 正在分析图片指标...」，无预计时长、无取消/重试入口；两次实测 12s 与 75s，波动大，小周会以为卡死而重复上传。（`t1b-01-after-upload-2s.png`）
- **M2.「2s跳出率」可输入 200 无即时校验**：>100% 的非法值无字段级报错、无警告色（`t1d-01-bounce-200.png`）；提交服务端校验因 C1 未触达，存在脏数据入库风险。
- **M3. OCR 失败返回 500 而非业务码**：`POST /api/ocr-screenshot` 对无法识别的合法图片返回 500（`AI_PARSE_FAILED`/通道类错误都落 500）。前端已优雅降级，但 500 会污染错误监控、误导排障方向。
- **M4. Base UI DialogTrigger 无障碍警告**：console 报 `nativeButton` 语义警告（`dialog.tsx` ← `截图槽位区.tsx:475`），槽位触发器非原生 button，影响表单语义与键盘行为。
- **M5. 发布时间自相矛盾展示**：更多设置里发布时间框显示「2026-10-02 19:00」（静默回退默认值），紧跟「未识别到发布时间，请重新上传…」。用户看到"有值却说没识别"，无从判断该信哪个。（`t3c-02-still-disabled.png`）
- **M6. 丢弃草稿无确认且表单不清空**：点「丢弃」→ 无确认弹窗、无撤销；草稿条消失但表单内容仍完整显示（`t6-03-discard-clicked.png`），用户不知道屏幕上的内容还作不作数（随后编辑还会重新存草稿）。
- **M7. 移动端触控目标不足 44px**：375px 下 11 个可点元素高度 <30px（日期按钮 28px、请假/报备 28px、正常发布/作品异常 tab 21–24px、+1 23px）。
- **M8. 异常模式提交门槛同样不明**：「作品异常」模式截图变为选填（提示「异常提交可不带截图」，设计合理），平台通知/申诉进展字段出现；但填齐标题文案后提交按钮仍 disabled 且无缺项提示，缺什么无从得知（`t8a-02-abnormal-filled.png`）。

### Low

- **L1. 账号切换浮层显示「方向: 未分类」**：内容方向为空时直接显示「未分类」，小周不知道该找谁设置。（`t1-01-account-switcher-open.png`）
- **L2. 移动端槽位标题截断**：375px 下「互动数据截图」显示为「互动...」，另一槽位「完播截图」完整，同屏不一致。（`t7-mobile-375.png`）
- **L3. 移动端仍显示「⌘/Ctrl+Enter 提交」**：触屏设备无此快捷键，提示无效。
- **L4. 移动端桌面导航可聚焦但不可见**：375px 下工作台/选题库/视频复盘/数据管理链接视觉隐藏但仍进入 Tab 序列，键盘焦点会"消失"。
- **L5. 审批中的豁免申请无自助撤回**：「可回收」仅针对已驳回申请；手滑选错日期只能找组长驳回。（`t10-after-recycle.png`）

## Per-thread

### Thread 1: 提交今日日报（选账号→三岗位指派→OCR 一次→提交）
- **Completable end-to-end**: **No** —— 卡在发布时间门槛（C1）；截图上传/OCR 降级/手输确认/指标填写全部正常。
- **Click count**: 登录后 0 点击即达表单；填表约 15 次交互＋上传 2 张＋手输 2 次 ≈ 20 次交互（预估合理值 ~15，多出在等 OCR 无反馈的重复确认）。
- **Decision points**: 4 —— 「立卷」是什么（术语）、「为什么按钮灰」（无指引）、OCR 失败后选手输、发布时间缺失后无路可走。
- **Dead ends**: 1 —— 发布时间死锁（C1）。
- **OCR 实录**: 假图 2 种 ×4 会话全部 `AI_CHANNEL_UNAVAILABLE`；降级 UI 明确（截图保留＋手输入口＋顶部核对横幅）——降级设计好，但出口没有。
- **Did it end clearly?**: 未走到提交，无法评价提交后行动项（未覆盖）。
- **One thing**: 给发布时间一个「识别失败时的兜底出路」，或至少在提示里写明「通道恢复前可先保存草稿」。

### Thread 2: 编辑已提交日报并保存
- **Completable**: **未覆盖** —— 测试账号无任何已提交日报（历史手稿空态），今日提交被 C1 阻断无法自造数据。

### Thread 3: 补交历史日期
- **Completable**: **No** —— 补交表单可正常进入（badge「正在补交历史数据」＋标题「创作纪事补录 (日期)」＋归属显示），截图选填语义与今日一致、题材标签补上后除发布时间外全齐，最终卡 C1。补交表单有「取消」按钮可退出（wrong-turn 可恢复）。
- **Decision points**: 3 —— 选哪个日期、补交与已提交摘要的区分（H4）、发布时间。
- **正向**: 补交模式不串今日草稿（隔离验证通过）。

### Thread 4: 无数据日豁免申请＋跟踪反馈
- **Completable**: **Yes** —— 请假/报备弹窗 → 选 10-03 → 填原因（64/100 字数器实时）→ 提交 → 弹窗关闭；重载后日历 title=「申请审批中」＋锁定、弹窗内 disabled、主横幅出现「豁免申请审批中」。反馈链路完整但见 H5（成功即时反馈缺失＋同会话不同步）。
- **正向**: 弹窗顶部防误用提示（限流/违规请走「作品异常」）＋申请类型红星＋未来日期禁用＋100 字上限＋实时字数器，表单质量高。

### Thread 5: 历史手稿弹窗→编辑→取消回摘要
- **Completable**: **部分** —— 弹窗打开正常，空态文案「历史手稿静待立卷 / 完成立卷或补交后，这里将收录最近 30 份纪事手稿」清晰（0 条空态合格）；编辑路径因列表为空未覆盖。

## What works

- OCR 失败降级诚实：槽位明示「识别通道暂不可用，请手动填写或稍后重试，截图已保留」，顶部核对横幅计数准确；不伪造成功。
- 草稿体系：自动保存带时间戳、跨刷新可靠、按模式隔离（新建/补交不互串——本轮重点盯缝正向通过）。
- 缺项列表（一旦触达）每项可点击滚动定位到对应区块。
- 豁免弹窗表单质量：防误用提示、类型红星、未来日期禁用、100 字上限＋实时字数器、审批中锁定（重载后）。
- 「更多设置」在发布时间成为唯一阻塞项时自动展开（`shouldRevealPublishedAtHint`）——好设计，只是救不了 C1。
- 账号/角色数据隔离正确（组员/组长 Second User 验证）。
- 移动端 TabBar 与提交按钮避让、无横向溢出。

## Recommendations（按影响排序）

1. **给发布时间一个兜底出路（C1）**——OCR 通道故障/截图模糊时用户走投无路。最小改法：识别失败 N 次后提供「人工登记」申请入口（组长补确认），或至少在提示中写明恢复路径。Est. M。
2. **禁用提交按钮常驻缺项摘要（H1/H2/M8）**——`issueSummary` 现成，一行判断渲染；同时给题材标签补必填标记。Est. S。
3. **切回日期自动恢复草稿或在原位显眼提示（H3）**——恢复入口从角落小字升级为表单内提示条。Est. S。
4. **对齐日历绿点/历史/豁免三处数据源（H4）**——先统一「已交」定义（是否含豁免），再决定已交日期是否允许进入补交表单。Est. M。
5. **豁免提交成功 toast＋同会话 pendingDates 即时刷新（H5）**。Est. S。
6. **移动端触控目标 ≥44px（M7）＋槽位标题不截断（L2）**。Est. S。
7. **OCR 接口改业务码（M3）＋跳出率即时校验（M2）**。Est. S。
