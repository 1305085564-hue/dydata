## 牵一发动全身（连累关系）

> 新对话读到这里就够了：下面是最容易踩的跨模块依赖，动之前必须想清楚。

### 核心数据连累

- **daily_reports 是全站命根子表**：dashboard、growth、admin/analytics、admin/fulfillment（通过 `get_fulfillment_range` RPC）、指挥台告警（cockpit/queue-overview）、admin/collaboration（限 `report_date >= 2026-07-27`）、export、remind、smart-alert、video-submit 全依赖它。18 个源码文件直接查询。动它的结构/口径 = 动全站。
- **videos 表跨模块共享**：admin/content（仅 active）、admin/videos（active/trashed/purged）、video-submit、violations（`source_video_id`）、cockpit/queue-overview 都查它。改 lifecycle_state 过滤逻辑会影响多个模块。

### 接口复用连累

- `/api/exemptions/*` 豁免链路被 `/dashboard` 的 `quick-exemption-button` 和 `video-submit-panel` 复用；video-review 已归档只读，但 exemptions 不能随它一并禁用。
- 选题库 topics 的 **recommendations**（推荐）复用 content-tools 链路；**suggest**（建议）是纯本地排序不走 AI，两者别混。

### 配置连累

- `content_rewrite` 走 `rewrite_model_*` 专用路由；`ai_feature_config` 只为文案改写提示词+旧接口兼容保留，不是新业务入口；首页截图识别仍在用。
- `feature-catalog.ts` 是唯一业务功能名单（包括首页截图识别、视频复盘、成长页面、智能预警、飞书催交），后台只管状态与模型策略。

### 权限连累

- `visibleUserIds`（`src/lib/data-access-scope.ts`）是"谁能看谁"的唯一入口，30+ 文件引用。已知架构债务：`/api/video-submit` 被指派者校验与 `/api/dashboard/operator-members` 各有一套独立实现，下次动这两处时顺手收口。

### 性能连累

- 首屏 RPC：admin/content 走 `admin_content_first_screen`，admin/analytics 走 `admin_analytics_first_screen`。改 RPC 签名 = 改两个核心页面的加载。
- 4 个 60 秒内存缓存接口：`content/list`、`dashboard-alerts`、`sidebar-badges`、`cockpit/queue-overview`。改了数据但页面没变 → 先查它们。

### 连累决策速查

| 你要改的东西 | 先想清楚 |
|---|---|
| daily_reports 表结构/口径 | 全站 6+ 模块受影响 |
| /api/exemptions/* | dashboard 豁免按钮会挂 |
| visibleUserIds 逻辑 | 所有人的数据范围变 |
| ai_feature_config / feature-catalog | 多个 AI 功能受影响 |
| 首屏 RPC | admin/content 或 analytics 加载崩 |
| 60 秒缓存接口的上游数据 | 改了但页面没变 → 缓存未过期 |

## 二、员工层模块明细

核心表 = 这个模块坏了/慢了，先查这几张表。全量接口见底稿。

### 数据看板 dashboard（核心）
- 加载器：`loaders/dashboard-page`
- 核心表：daily_reports、accounts、profiles、exemption_request/exemption_grant
- 接口目录：`app/api/video-submit/` + `app/api/dashboard/`
- 坑与连累：`/api/video-submit` 异常视频自动生成待审核避坑案例；三岗位责任人字段 `script_author_user_id`/`video_editor_user_id`/`operator_user_id` 写入 daily_reports；被指派者校验有独立实现（不走 `visibleUserIds`，已知架构债务）

### 成长分析 growth（核心）
- 加载器：`loaders/growth-page`（`loadGrowthPageContract`，服务端一次返回真实指标、可信度、规则诊断、最小实名对标、`ownScriptSnippet` 和三态字段 `stage`）
- 核心表：daily_reports、accounts、profiles、content_item、script_document/script_segment；`ai_insight_result` 只留给后续 AI V2
- 接口目录：`app/api/dashboard/trend` + `app/api/dashboard/leaderboard` + `app/api/growth/`
- 三态判定来源：`daily_reports` 全历史 exact count + `profiles` 团队 active count

| 三态 | 门槛 | 展示形态 |
|---|---|---|
| 累积期 | <10 份日报 | 成长进度卡+教练卡+体征数据条+锁定雷达+追赶条 |
| 观察期 | 10–30 份 | VERDICT 回归、比例指标逐个点亮、双人对比 |
| 成熟期 | >30 份且团队 ≥5 人 | 榜单形态 |

- 断流 >3 天不降级，只出琥珀横幅；近 30 天窗口算不出数的模块显示冻结/锁定占位
- 文案对照：嵌入「该学谁」和「教练卡」，取 `ownScriptSnippet` 截断 80 字做并排对照
- 降级：脚本表缺数据/缺表/缺列时自动回退用日报文案原文，不拖垮其余体检数据
- 趋势图：`result-trend`/`interaction-trend`（实线=已知、虚线=缺数、灰斜纹=停更；团队不足 5 人隐藏 P70 对比线）

### 视频审核 video-review（归档，只读）
- 加载器：无（页面已全部清除）
- 核心表：publish_drafts、work_submissions、exemption_request、profiles、teams、groups
- 接口目录：`app/api/work-submissions/` + `app/api/publish-drafts/` + `app/api/exemptions/` + `app/api/submission-screenshots/`
- 坑与连累：`/api/exemptions/apply` 被 `/dashboard` 工作台复用，不能随 video-review 一并禁用（详见连累关系图）

### 避坑案例 violations
- 加载器：无（页面内直接查，待收口到 loaders）
- 核心表：violation_cases、knowledge_cases、videos、violation_events、violation_reason_tags、violation_case_visual_tags、visual_tags、script_usage_records；管理视角走 `case_library_*` RPC
- 接口目录：`app/api/violations/` + `app/api/case-library/` + `app/api/conversion-hub/`
- 坑与连累：异常视频以 `source_video_id` 幂等写入 `violation_cases`（`status=submitted`，保留来源元数据和管理员违规段落标注）；员工视角只读 `status=verified`；PATCH/DELETE 需 `manage_violations` 权限

### 文案工具 content-tools
- 加载器：`content-tools-page`；渲染组件 `RewriteWorkbenchV3`
- 核心表：rewrite_documents/conversations/messages/skills/workflows + ai_* 配置表
- 接口目录：`app/api/content-tools/` + `app/api/rewrite/`（`/api/rewrite/generate` 是核心生成链路）
- 坑与连累：两套 API 并存（content-tools + rewrite），减法待重新沟通；2026-07-16 撤回前端减法，现状完整保留；`src/lib/rewrite/` 不是可删的旧层，当前仍承载主链路

### 选题库 topics
- 加载器：无（V1 页面内直接查）；V2 页面入口为 `/topics-v2`，由 `TopicHubV2` 按区块并行补充数据
- 核心表：topics、topic_groups、sub_topics、sub_topic_claims、videos.topic_id
- 接口目录：`app/api/topics/`
- V2 组件：`src/components/topics-v2/`（今日聚焦、选题池、我的认领、横向对比、创建、详情抽屉、替换弹窗）；完整编辑/删除继续复用 `/topics/[id]`
- V2 首屏读取：`/api/topics/active`、`/api/topics/options`、`/api/topics/pool`（全量筛选页与我的认领页）、`/api/topics/comparison`；详情打开后再读取 detail/works/claims
- 坑与连累：`/api/topics/sub-topics/suggest` 是纯本地排序（查 sub_topics 表 + `rankSuggestedSubTopics`），不走 AI；`/api/topics/recommendations` 复用 content-tools 链路。两者别混。V2 不替换 V1、不删除 recommendations 后端；算法只用现有播放量与发布时间，不做 AI 评分/外部热点/超时释放

## 五、接口存活判断（⚠️ 不要凭本文件删接口）

判断一个接口能否删，必须逐个查：route 定义、前端调用、被其他接口内部调用、测试、外部/手动触发。少查一项都不能判死。静态 grep 搜不到前端调用 ≠ 闲置。真要清理走"代码治理"专项，逐个验证，禁止批量删。

已证实被误判为闲置但真实在用的反例：`/api/ai/insight/period`、`/api/admin/first-screen-monitor`、`/api/admin/cockpit/summary`、`/api/publish-drafts/approved`、`/api/publish-drafts/queue`、`/api/fulfillment/appeal/submit`——这些都是有前端调用或正式 route 的，禁止当废接口删。
