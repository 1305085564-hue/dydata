## 牵一发动全身（连累关系）

> 新对话读到这里就够了：下面是最容易踩的跨模块依赖，动之前必须想清楚。

### 核心数据连累

- **daily_reports 是全站命根子表**：dashboard、growth、admin/fulfillment（通过 `get_fulfillment_range` RPC）、admin/collaboration（限 `report_date >= 2026-07-27`）、export、remind、video-submit 全依赖它。18 个源码文件直接查询。动它的结构/口径 = 动全站。
- **videos 表跨模块共享**：admin/content（仅 active）、admin/videos（active/trashed/purged）、video-submit 都查它。改 lifecycle_state 过滤逻辑会影响多个模块。

### 接口复用连累

- `/api/exemptions/*` 豁免链路被 `/dashboard` 的 `quick-exemption-button` 和 `video-submit-panel` 复用；video-review 已归档只读，但 exemptions 不能随它一并禁用。
- 选题库 topics 的 **suggest**（建议）是纯本地排序不走 AI。旧 recommendations 链路（复用 content-tools）已随旧版文案工具下线一并删除，别再引用。
- `lib/conversion-hub` 和 `lib/case-library` 虽属已下线的避坑案例生态，但被 `/api/video-submit`（替换重报 usage record）依赖，**不能删**；对应的 `api/conversion-hub`、`api/case-library` 页面级路由已下线。

### 配置连累

- `content_rewrite` 走 `rewrite_model_*` 专用路由；`ai_feature_config` 只为文案改写提示词+旧接口兼容保留，不是新业务入口；首页截图识别仍在用。
- `feature-catalog.ts` 是唯一业务功能名单（包括首页截图识别、视频复盘、成长页面、智能预警、飞书催交），后台只管状态与模型策略。
- 旧指挥台 `queue-overview` RPC 已随 2026-08-25 死代码清理删除 API 调用方，RPC 本体仍会读 `violation_cases`（表已无写入方），留待后续 migration 清理。

### 权限连累

- `visibleUserIds`（`src/lib/data-access-scope.ts`）是"谁能看谁"的唯一入口，30+ 文件引用。新增 `activeVisibleUserIds` 用于当前操作候选（不含 archived），`visibleUserIds` 保留历史数据查询（含 archived）。已知架构债务：`/api/video-submit` 被指派者校验与 `/api/dashboard/operator-members` 各有一套独立实现，下次动这两处时顺手收口。

### 性能连累

- 首屏 RPC：admin/content 走 `admin_content_first_screen`。改 RPC 签名 = 改核心页面的加载。（`admin_analytics_first_screen` 已无调用方，待 migration 清理）
- 2 个 60 秒内存缓存接口之一 `sidebar-badges` 已于 2026-08-26 随死代码清理删除（五个计数无任何 UI 消费）；现存缓存接口仅 `content/list`

### 连累决策速查

| 你要改的东西 | 先想清楚 |
|---|---|
| daily_reports 表结构/口径 | 全站 6+ 模块受影响 |
| /api/exemptions/* | dashboard 豁免按钮会挂 |
| visibleUserIds 逻辑 | 所有人的数据范围变 |
| ai_feature_config / feature-catalog | 多个 AI 功能受影响 |
| 首屏 RPC | admin/content 加载崩 |
| 60 秒缓存接口的上游数据 | 改了但页面没变 → 缓存未过期 |

## 二、员工层模块明细

核心表 = 这个模块坏了/慢了，先查这几张表。全量接口见底稿。

### 数据看板 dashboard（核心）
- 加载器：`loaders/dashboard-page`（今日提交 + 本月已提交日报与日期，供首屏日期状态和顶部日历红点；活动查询失败保留错误态）

- 性能（2026-08-30）：岗位成员列表已改首次打开选择器时加载并复用（挂载 0 请求）

- 历史修改（2026-08-31）：历史手稿与历史已提交日期统一进入 `VideoSubmitFormV2` 完整编辑链路，可修改文案、剪辑、运营责任人；详情未完整加载时禁止保存，取消后回到该日期摘要态

### 成长分析 growth（核心·🔁 待重做）

| 三态 | 门槛 | 展示形态 |

- 接口目录：`app/api/topics/`

- 口径明示（2026-09-04）：选题池 `claimCount`（认领数）走 scope 过滤（`buildTopicPoolItem`），但 `recent7dParticipants`（7 天参与人数）来自 `loadRecent7dHeat`，**按全量成员统计，不受 scope 过滤**——即普通成员看到的"X 人在写(受限)"与"Y 人参与(全量)"是两个不同口径。这是有意设计（作品热度反映选题本身的全员吸引力，身份信息仍受 scope 控制在认领明细里），见 `src/lib/topics/service.ts:loadRecent7dHeat` 顶部注释。前端展示这两个数字时不要混用语义。

## 五、接口存活判断（⚠️ 不要凭本文件删接口）

判断一个接口能否删，必须逐个查：route 定义、前端调用、被其他接口内部调用、测试、外部/手动触发。少查一项都不能判死。静态 grep 搜不到前端调用 ≠ 闲置。真要清理时按 `docs/工程运行事实.md` 的项目边界逐个验证，禁止批量删。

已证实被误判为闲置但真实在用的反例（历史教训，判断时仍须逐项核查）：`/api/admin/first-screen-monitor`、`/api/publish-drafts/approved`、`/api/publish-drafts/queue`、`/api/fulfillment/appeal/submit`——这些是有前端调用或正式 route 的，禁止当废接口删。（`/api/ai/insight/period`、`/api/admin/cockpit/summary` 曾在列；前者 2026-08-22 随经营分析下线删除，后者随旧指挥台于 2026-08-25 经全链路核实后删除）
