# 效率美学

> **界面上真正的美，就是用户心里的问题和屏幕上的答案之间，没有多余的东西。**
>
> 注意力是用户带进来的预算，交互链路是他要走的路。好的界面花掉的注意力最少，让人走的路最短。字体、墨色、留白这些质感，是在这两件事做对之后才轮到的东西。

**本手册是设计系统的主卷**，回答「做什么、为什么做、按什么顺序做」。数值查《美学宝典》。

**读法**：拿到任务 → 判型（§4）→ 走决策树（§1/§2）→ 查数值（→ 手册）→ 验收（→ 手册）。

---

## 0. 内核

### 设计分三层

| 层 | 回答的问题 | 没做对的后果 |
|---|---|---|
| **第一层：对** | 用户要办什么事？机器该干什么、人该干什么？最少几步？ | 链路绕、步数多、空框多 |
| **第二层：秩序** | 答案在首屏吗？焦点在哪？视线顺序对吗？ | 找不到、看不懂、不知道下一步 |
| **第三层：质感** | 用什么字号、墨色、留白画出来？ | 不够精致、不耐看 |

**铁律：上一层没过，不准动下一层。** 第一层没想清楚就调视觉 = 把错的东西画精致。

### 三条元定律

这三条定律跨越三层，是判断一切设计决策的元规则：

#### 定律 1: Every Element Earns Its Place（每个元素都挣得其位置）

```
IF 删掉这个元素，用户理解变慢或完成任务变难（认知功能）
  OR 删掉它，"被善待、安心、愿意停留"的感觉随之减弱（关系功能）
THEN 保留
ELSE 删除
```

空输入框是最贵的注意力：每个空框都在告诉用户「这是你的活」。机器能填的，不摆成空框。

**定位锚是认知功能，不是装饰**（阿禅 2026-11-19 纠正）。效率不只是「元素少」，还包括「扫一眼就定位」的精度。下面这些删掉后找东西变慢，按定律 1 必须保留：

- **人名前的头像首字圆**：在几十人的名单里，眼睛先找形状再读字。
- **功能行前的语义图标**：团队用楼、小队用人、设置用齿轮、密码用钥匙、归档用箱子。图标先于文字被认出来。
- **类别色**：身份（老板 / 组长 / 组员）、工种这类「分是哪一种」的颜色。它和「异常红、正常绿」是两回事，不受配色规则①限制。

真正该删的是没有指向的装饰：没有含义的彩色色块、重复同一信息的第二个标签、只为显得丰富的图标。判断方法：盖住文字，这个图标或颜色还能告诉你「这是什么 / 这是谁」吗？能，就是定位锚。

**温度不是附加项**：克制不等于简陋。头像、图标、柔和的类别色，属于「被善待、愿意停留」的关系功能。整页只剩文字和发丝线，就是删过头了。

#### 定律 2: Systematic but Expressive（系统化但有表现力）

有严格的系统（字号档位、颜色系统、留白级数），但不僵化。打破条件：

```
IF 打破规则能显著提升功能性
  AND (连续 3+ 场景需要同一例外 OR 一次性特殊场景)
THEN 允许打破（封闭系统须经阿禅确认，并在纠错索引留档）
ELSE 遵循系统
```

#### 定律 3: Load-Bearing in the Worst Environment（承重信号须在最差环境里成立）

层级由哪种手段承担，取决于它在**目标用户最差的渲染环境**里是否仍然看得出来。

本产品的基线环境是 **Windows**（约 95% 用户）：微软雅黑 UI（只有 400 / 700 两档字重）、中易宋体、显示缩放 100%–125%。

- **承重信号**（层级靠它们立住）：字号、字体族（衬线/无衬线）、位置、留白
- **辅助信号**（锦上添花，剥掉后层级仍须成立）：墨度里相邻两阶的细微差
- **不入系统**（基线环境里不存在）：字重 500 / 600

## 1. 第一层检查：链路

**目标：确定要不要这个改动，机器和人各干什么，最少几步。**

### 决策树

拿到任务后，按顺序问自己这 5 个问题：

#### 1.1 一页一问：这一页回答的那个问题是什么？

**写不出 = 页面没想清楚，停，别动手。**

- 工作台的问题：「今天交了没？」标题就是答案：「今天还没交」/「今天已交」
- 选题库的问题：「明天发什么？」首屏就是待选的选题列表
- 数据复盘的问题：「这条表现怎么样？」首屏就是核心指标卡片

**判断方法**：闭着眼想，用户打开这一页，脑子里只有一个疑问句。写下来。如果写出来的是两个问题，或者是一段话而不是一个问句，说明页面职责不清，先拆页面或重新定位，再谈 UI。

**常见失败模式**：
- 标题是装饰（「创作立卷 · 表达纪事」），不是答案
- 首屏是导航、说明、装饰，答案要往下翻才看到
- 同一页既要看数据、又要填表单、还要审批，用户不知道先干什么

#### 1.2 机器该干的不摆成人的活

**IF 机器能从已有数据里算出来、认出来、带出来 THEN 直接显示结果，不要空框**

- 截图能识别出 11 个指标 → 直接显示数字，只有没认准的才是输入框
- 上次选的角色、题材、形式九成不变 → 收成一行摘要，要改才展开
- 发布时间能从截图里认出来 → 直接显示，异常时才需要人改

**判断方法**：
1. 列出页面上所有输入框、下拉、切换
2. 逐个问：这个值能不能从数据库、URL 参数、上次记录、OCR 结果里拿到？
3. 能拿到 → 改成「显示 + 点击可改」，不要常驻空框

**常见失败模式**：
- 表单里每个字段都是空框，其实上次填的、系统已知的都能预填
- 让用户手抄截图上的 11 个数字
- 每次都要重新选角色、选题材，明明上次的选择还在数据库里

#### 1.3 步数就是成本

**数清用户从进来到办完事，最少点几次、输入几次。** 多一步 = 多一次放弃的机会。

- 工作台：粘贴截图 1 次 + 核对存疑数字 1 次 + 粘贴文案 1 次 + 提交 1 次 = 4 步
- 豁免申请：选日期 1 次 + 选类型 1 次 + 填原因 1 次 + 提交 1 次 = 4 步

**判断方法**：
1. 写下理想路径：从进入页面到任务完成，每一步用户的动作
2. 数清点击次数、输入次数、跳页次数
3. 问：哪一步能省？哪一步能合并？哪一步能让机器替人做？

**常见失败模式**：
- 提交后发现质量问题，要再点「修改」回去改了再交 → 应该提交前就检查
- 选完选题要跳回工作台，URL 参数才能带过来 → 应该选完直接打开预填表单
- 分三页填：基础信息 → 责任人 → 数据指标，其实一页能填完

#### 1.4 视线顺序 = 决策顺序

**用户心里想的顺序，和页面从上到下的顺序，必须一致。**

工作台的决策顺序：今天交了没？→（没交）现在要干什么？→（粘贴截图）还差什么？→（文案）好了，交
页面从上到下：标题「今天还没交」→ 粘贴区 → 识别结果 → 文案框 → 提交按钮

**判断方法**：
1. 闭着眼，从用户视角走一遍：我进来想知道什么 → 知道之后要判断什么 → 判断完要做什么
2. 睁眼看页面从上到下：是不是按这个顺序排的
3. 不一致 → 记下哪里反了

**常见失败模式**：
- 最重要的状态（今天交了没）藏在页面中部，顶部是装饰性标题
- 要先往下翻找到数据，再回到顶部看筛选器，才知道现在看的是什么数据
- 用户要先选日期（在顶部），但只有往下翻才能看到这一天的状态

#### 1.5 同一个状态只在一处说

**IF 两处都在告诉用户「你现在什么状态」AND 口径不一样 THEN 删掉一处，或者合并**

- 工作台原来有四处讲「今天要不要交」：标题、月历、胶囊、底部提示 → 合并成标题一句话
- 提交按钮上写「还差：文案」，底部又有一行灰字「待补全：文案」→ 删掉灰字

**判断方法**：
1. 列出页面上所有在讲「状态」的地方：标题、提示条、角标、按钮文案
2. 问：它们在回答同一个问题吗？答案一样吗？
3. 一样 → 只留最显眼的那一处；不一样 → 搞清楚哪个是对的，删掉错的

**常见失败模式**：
- 页头说「今日待履约」，同一行又说「今日免交」
- 按钮上写「提交」，旁边提示「还差 2 项」，用户不知道能不能点
- 五周前的请假通知还挂在右上角

## 2. 第二层检查:焦点

**目标：确定这个元素放哪、多显眼，让用户一眼找到下一步。**

### 决策树

第一层过了，确定要加这个元素，按顺序问自己这 5 个问题：

#### 2.1 标题是答案，不是装饰

**标题要直接回答「一页一问」里那个问题，而且答案会随任务进度变化。**

- ❌ 固定标题「创作立卷 · 表达纪事」→ 没回答「今天交了没」
- ✅ 动态标题「今天还没交」→「还差一步：粘贴文案」→「今天已交」

**判断方法**：
1. 看标题，不看内容，能不能回答§1.1 里那个问题
2. 任务做到一半时，标题还是原来那句话吗？
3. 如果标题不变 → 它是装饰，不是答案，改成会变的

#### 2.2 焦点唯一且会走

**同一时刻，全页只有一个主角（陶土橙实底、大字、重墨）。任务进行中，主角会跟着走。**

- 刚进工作台：粘贴区是主角（陶土橙按钮 +虚线框）
- 截图识别完：存疑的数字是主角（标黄输入框）
- 核对完：文案框是主角（唯一的空框）
- 填完：提交按钮是主角（陶土橙实底）

**判断方法**：
1. 眯眼看页面，最跳的是哪一个？
2. 任务做到下一步时，最跳的还是它吗？
3. 如果同时有 2 个以上同样跳 → 削弱次要的，不要加强主要的

**常见失败模式**：
- 状态色（成功/异常/待处理）用饱和实底，跟主 CTA 抢焦点
- 同层两个主按钮都是陶土橙实底
- 识别完 11 个数字全用大字重墨显示，用户不知道先看哪个

#### 2.3 焦点的注意力价格

**想强调一个元素时，从免费档开始花，够用就停。**

| 档 | 手段 | 什么时候用 |
|---|---|---|
| **免费档** | 位置（独占一行、固定槽位）、留白（头顶 > 脚下）、墨度四阶、出现顺序 | 默认优先用 |
| **中等档** | 字号升一档、字体族（衬线 = 宣告，≥20px）、淡底与下沉、发丝线与微投影 | 免费档确实不够用 |
| **昂贵档** | 主色饱和实底、动效、插画与装帧 | 同屏省着花：实底至多一处、动效只报真实变化、装帧只在关键心理节点 |

**判断方法**：
1. 想强调某个元素时，先试免费档（给它独占一行、加留白、用重墨）
2. 还不够 → 试中等档（升字号、加淡底）
3. 还不够 → 查是不是别处滥用把这一档的区分度削弱了（削弱别人，而不是继续升档）
4. 仍然不够 → 才用昂贵档

**常见失败模式**：
- 一上来就用陶土橙实底，其实加个淡底就够了
- 想突出表格某一列，给它加粗，其实只要用重墨就能区分
- 同屏三个按钮都是陶土橙实底，用户不知道先点哪个

#### 2.4 承重信号优先

**层级靠「字号、字体族、位置、留白」立住，不靠字重。**

Windows 雅黑只有 400 / 700，中间档不存在。所以：
- ✅ 页面定名 28px + 衬线 + 头顶 20px 留白 → 一眼看出是标题
- ❌ 条目名 14px + 字重 500 + 留白 12px → Windows 上看不出跟正文有什么区别

**判断方法**：
1. 列出页面上的层级：页面定名、区块标题、条目名、正文、元数据
2. 每一层用什么手段区分：字号？位置？留白？字重？
3. 如果靠字重 → 换成字号、位置或留白

**承重手段优先级**（按在 Windows 上的可靠性排序）：
1. 字号（5 档）
2. 字体族（衬线 / 无衬线，≥20px 才能用衬线）
3. 位置（独占一行、固定槽位、头顶留白 > 脚下留白）
4. 墨度（4 阶，相邻两阶只能辅助，不能独立承重）

#### 2.5 布局零跳动

**用户做一个动作（点击、输入、悬停），页面上其他元素的位置不能跳。**

- ✅ 核对完数字，警告文字变成灰色「已核对」留在原位 → 下方的「一键粘贴」按钮不动
- ❌ 核对完数字,警告文字消失 → 页面往上跳 20px，「一键粘贴」按钮跑到鼠标上方，点空了

**判断方法**：
1. 列出页面上所有会引起内容变化的交互：输入、点击、悬停、加载
2. 逐个问：这个变化会不会让其他元素的位置跳动？
3. 会跳 → 要么给消失的元素留空位，要么改成渐变透明度而不是直接删除

**常见失败模式**：
- 表单校验失败，错误提示突然出现，把下面的提交按钮挤下去
- 加载完成，骨架屏消失，内容高度跟骨架屏不一样，整页重排
- 悬停表格行，行高变化，下面的行都往下挪

## 3. 第三层执行：质感

**前两层过了，确定要这个元素、放这里、这么显眼。现在定数值。**

### 3.1 查数值

所有具体数值（字号、墨色、留白、圆角、色值）查《美学宝典》，不自造。

| 要什么 | 去哪查 |
|---|---|
| 字号 / 墨度 / 留白 / 圆角 | 手册 §1 |
| 色值 / 状态色 / 边框 / 阴影 | 手册 §2 |
| 按钮 / 表格 / 表单 / 卡片 | 手册 §3 |
| 页头 / 布局 / 宽度 | 手册 §4 |
| 动效 / 微交互 | 手册 §5 |

### 3.2 封闭系统

每个设计维度（字号 / 墨度 / 留白）都是封闭的白名单，不是开放的连续值。

**遇到「现有档位不够用」时**：
1. 先问：能不能用现有档位组合代替（如用墨度 + 位置代替字号变化）
2. 仍然不够 → 走定律 2：连续 3+ 场景需要同一例外 → 加入白名单；一次性场景 → 允许例外但不入常规系统，代码注释说明缘由

**白名单由门禁强制**：`npm run gate:design` 会拦截所有不在白名单里的值。

### 3.3 组件优先

**涉及的组件是否已有契约？有就照抄，不自造。**

查《美学宝典》§3，看这个场景有没有已定契约：
- 表格：行高、悬停、选中、操作按钮
- 表单：输入框、下拉、切换、校验
- 按钮：主次、禁用、加载
- 卡片:圆角、阴影、内边距

有契约 → 复制粘贴；没有 → 按前两层决策树走一遍,定完数值后补进契约手册。

## 4. 任务型路由

**判定顺序**：先看影响范围，按型 5 → 型 4 → 型 3 → 型 2 → 型 1 依次判定，命中即停。

| 型 | 机械判据 | 走哪条链 |
|---|---|---|
| **型 5 全站改版** | ≥3 个页面同改（配色/页头/壳/模式） | 链 E |
| **型 4 共享组件/令牌** | 改动 `src/components/ui/` 或 `design-tokens.css` 的实际表现 | 链 D |
| **型 3 从零建页** | 新建 `page.tsx` 或新模块目录 | 链 C |
| **型 2 改已有页** | 单页内改结构：加区块、重排、改容器与层级 | 链 B |
| **型 1 微调** | 改动 ≤3 个文件，只调数值（间距/字号/色值），不动结构 | 链 A |

---

### 链 A：微调（型 1）

**适用**：改动 ≤3 个文件，只调数值，不动结构，影响限于当前页面。

**步骤**：
1. **过第一层** → §1 决策树（5 个问题），确认这个改动是在解决链路问题，还是只在调视觉
2. **过第二层** → §2 决策树（5 个问题），确认焦点、主次、位置
3. **查数值** → 手册 §1–§2
4. **门禁** → `npm run gate:design`
5. **验收** → 手册 §6 页面验收快检（5 秒测试）

---

### 链 B：改已有页（型 2）

**适用**：单页内改结构（加区块、重排、改容器与层级）。

**决策树**：
1. 这一页回答的那个问题是什么？答案在首屏吗？→ 不在 = 停，先调结构
2. 用户做这件事最少几步？现在的页面是几步？→ 多了 = 记下多在哪
3. 页面从上到下的顺序，是不是用户心里想的顺序？→ 不是 = 记下哪里反了
4. 同屏有几个主角（陶土橙实底、大字、重墨）？→ >1 = 记下谁在抢
5. 以上都过了 → 查数值 → 门禁 → 验收

**步骤**：
1. **过第一层 + 第二层** → 上面 5 个问题
2. **定结构** → 这块归哪一层？统领它的是什么？按感知分组建立亲密度与组间距离
3. **定表现** → 查手册 §1–§2
4. **查契约** → 手册 §3，涉及的组件是否已有契约
5. **门禁 + 验收** → `npm run gate:design` + 手册 §6

---

### 链 C：从零建页（型 3）

**适用**：新建 `page.tsx` 或新模块目录。

**决策树**：
1. 这一页回答的那个问题是什么？→ 写不出 = 停，先想清楚页面职责
2. 用户从进来到办完事，最少几步？→ 列出理想路径
3. 每一步机器能干什么、人必须干什么？→ 机器能做的不摆成空框
4. 有没有现成的样板页（职责类似、结构可复用）？→ 有 = 优先复用
5. 以上都过了 → 走链 B

**步骤**：
1. **明任务、选型** → 上面 4 个问题
2. **参照样板** → 手册 §7 样板页索引，默认复用真实样板
3. **走链 B** → 定结构、定表现、查契约
4. **页头走壳** → 不自建页头（手册 §4）
5. **空态走统一组件** → 不自绘空态（手册 §3.7）
6. **收尾** → 门禁 + 页面验收（含任务闭环、状态真实性）

---

### 链 D：共享组件/令牌变更（型 4）

**适用**：改动 `src/components/ui/` 或 `design-tokens.css` 的实际表现。

**步骤**：
1. **影响面盘点** → 谁引用了它？列出来（grep），不许凭印象
2. **该不该改** → 现有档位组合能否替代？确需打破走定律 2
3. **定新契约** → 改组件契约，并同步手册对应小节
4. **全站自检** → 跑一遍所有受影响页面，不只看一个
5. **门禁与基线** → 基线只降不升；下调须阿禅确认 + 纠错索引留档
6. **令牌同步** → 令牌与 CSS 变量同步，不留两套
7. **收尾** → 门禁 + 全站页面验收

---

### 链 E：全站改版（型 5）

**适用**：≥3 个页面同改（配色 / 页头 / 壳 / 模式）。

**步骤**：
1. **盘点** → 列全受影响页面与组件（含动态拼装的 class 名）
2. **令牌层先改** → 改 `design-tokens.css` 让页面批量跟随，而不是逐页改 class
3. **逐页走型 2** → 每页单独走链 B，不批量套模板
4. **统一验收** → 逐页过页面验收清单，不抽查
5. **门禁 + 基线只降不升**
6. **留档** → 执行清单与上线核对报告各留一份

## 5. 常见失败模式速查

| 症状 | 根因 | 查哪里 |
|---|---|---|
| 焦点失控 | 同层双主 CTA、状态色实底抢主行动 | §2.2 焦点唯一 |
| 层级失真 | 靠字重突出条目名、小字用衬线 | §2.4 承重信号优先 |
| 空间噪音 | 表单白底套白框，常规数据区塞装帧元素 | §2.3 注意力价格 |
| 交互误伤 | 表格行悬停位移/缩放，导致数字错位或点击脱靶 | §2.5 布局零跳动 |
| 链路绕弯 | 机器能填的摆成空框、提交后才检查质量 | §1.2 机器该干的 |
| 答案藏起来 | 标题是装饰、首屏是说明、要往下翻才看到答案 | §1.1 一页一问 + §2.1 标题是答案 |
| 删过头、显简陋 | 把头像、语义图标、类别色当冗余删掉，名单找不到人、设置行认不出 | §0 定律 1「定位锚」 |
| 内容散、没主体 | 数据表直接铺在页面底色上，没有托盘收拢 | 《美学宝典》§2.5 托盘 `shadow-card-ring` |
| 选中看不清 | 选中行用浅砂 `#F1F1F0` 或悬停色，和悬停分不开 | 《美学宝典》§3.9 选中三档 |
