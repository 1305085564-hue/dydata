## 1. 读法与地位

- 本文件只写**暗色与亮色的差异**。每条注明覆盖亮色版哪一节、改成什么、为什么；未提到的一律沿用亮色三卷。
- 触发后的冲突裁决：本补丁覆盖条目优先于亮色三卷的对应小节；其余仍按亮色三卷的裁决顺序。
- **当前状态：建议稿，未入系统。** §3 全部色值为推测，未经 Windows 实机目检，不得直接写进 `design-tokens.css`。入系统须走主卷步骤链 D（令牌、门禁名单、基线同批提交）。

## 2. 主卷覆盖条目

### 2.1 空间层次：越近越亮（覆盖主卷 §4.2、数值手册 §2.1 与 §2.4）

**改什么**：
- 亮色"上浮 = 纯白 + 微投影"改为"**上浮 = 更亮的面**"。离用户越近的层越亮：桌面（Canvas）< 托盘与输入框（Card）< 下拉与气泡（Float）< 弹窗与抽屉（Dialog）。
- 亮色"下沉 = 浅砂气垫"改为"**下沉 = 比桌面更暗**"。适用范围不变：只读区确需下沉分区时才用，不因只读自动铺底。
- 亮色"纯白触点物理凸出律"（必须配发丝边与微投影）改为"**亮面靠发丝线与亮度差立边界**"。阴影只保留给 Float 与 Dialog 两层，并以极淡白色内描边代替投影外环。
- "严禁同色套同色"不变。

**为什么**：深底上的投影几乎看不见，无法承担 Z 轴层次；靠阴影分层在暗色里是失效手段（定律3）。纯白放进暗色界面会成为全屏最亮的块，直接抢走主行动的焦点（原则4）。

### 2.2 聚光灯与主色（覆盖主卷 §2.2）

**改什么**：
- "极净暖白专属 L1 背景"改为"**温润暖炭专属 L1 背景**"。禁纯黑 `#000`，禁偏蓝冷黑（如 slate / zinc 的深档）。
- 暖陶土橙继续只给同一活跃层唯一的主行动，规则一字不改。色值见 §3.3：本体沿用，悬停改为"变亮"而非"变暗"。
- 状态色不占实底，规则不变；但淡底配方须换暗色专用值（§3.4），亮色的 8% alpha 在深底上几乎不可见。

**为什么**：温润是本质，不是配色策略。暗色的"灯"是一盏台灯，冷黑等于把书房换成机房。深底上饱和色的视觉音量会放大，主色不提饱和度已足够成为唯一焦点。

### 2.3 墨度四阶（覆盖主卷 §2.1"沉稳墨度"、数值手册 §1.2）

**改什么**：
- "炭黑油墨落在暖白纸上"改为"**暖米白落字于炭色底上**"。定名墨不用纯白 `#FFF`。
- 四阶的职责（定名 / 正文 / 元数据 / 信号）与"信号墨只承载'这里没有内容'"判据不变，色值整体反转（§3.1）。
- 定名墨与正文墨在暗色下更难分辨，仍只作辅助信号，不得单独承担层级或激活态。

**为什么**：纯白字在深底上会产生光晕感（笔画发虚、长看刺眼），与"长时间注视亦不疲倦"相悖。

### 2.4 心智模型（覆盖主卷 §2 标题与首段）

**改什么**："一间光线充足的工作室"改为"**夜里一盏台灯下的书房**"：四周沉静，灯下的工作区最亮，工具仍摆在原处、触手可及。§2 其余心智（先看整页、再看局部）不变。

**为什么**：§2.1 越近越亮、§2.2 暖炭大底都从这个心智推出。

### 2.5 定律3 暗色补充检查（补充主卷定律3）

**加什么**：暗色版入系统前，须在 Windows 实机（100% / 125% / 150% 缩放，普通 sRGB 显示器）目检两项：
1. **背景相邻层能否分清**：Canvas / Card / Float / Sand 四个深色相邻档，低端屏上容易糊成一片。分不清的层不得承担层次，改用发丝线承重。
2. **中易宋体衬线标题是否发虚**：宋体细笔画落在深底上易断笔。若发虚，衬线标题墨色取定名墨，不得取更浅档。

**为什么**：深灰阶的相邻差在 Mac 屏上清楚，在 95% 用户的 Windows 屏上未必存在。

### 2.6 小项

| 亮色条目 | 暗色改法 |
|---|---|
| 数据指标涨跌着色（饱和色字） | 涨跌两色各提亮一档（§3.4 主色），保证深底上可读；涨跌与颜色的对应沿用亮色版，不改 |
| 暖墨线描插图、有机微印记、`✦` | 改为浅暖米色线条（取元数据墨），不反相处理位图 |
| 弱圆点 `#D6D3D1`（正常状态锚点） | 换暗色值（§3.5），仍不可删除 |
| 计数徽章降级（灰底灰字） | 底取 Hover 面，字取元数据墨 |
| 聚焦态"深炭墨色微光晕" | 改为"暖米白微光晕"（定名墨 30% 左右），仍不得借用主色 |

## 4. 不改的部分

以下全部沿用亮色三卷，暗色版不得另立规则：三条定律本身、执行主链（§1 全章）、三问自检、六条判断原则的定义与判据、字号五档、字重一档、留白四级、圆角三档、衬线白名单与字体栈、位置恒定（§4.1）、组件契约与动效、文案语气。

## 5. 落地前提（本补丁之外的工程）

- 代码中写死的色值类（如 `bg-[#D97757]`）约 4500 处（2026-11-06 实测：`grep -rhoE "(bg|text|border)-\[#[0-9A-Fa-f]{6}\]" src | wc -l`）。这些不随令牌切换，必须先改为令牌引用，暗色版才能整体生效。
- `src/app/globals.css` 目前只有 `@custom-variant dark` 一行声明，无任何暗色令牌。
- 门禁 `npm run gate:design` 目前只认亮色色值白名单，暗色入系统时须同批扩展。
