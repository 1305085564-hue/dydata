# 决策 0004：小队上限维持 20，前端刻意不禁选

**状态**：有效（保留既有决策；本次仅修复证据入口，不代表重新验收运行状态）

**背景**：实际一次分配最多约 10 人；逐人写入仍需服务端护栏，但把几乎不会发生的场景做成前端禁选和计数器会增加交互复杂度。
**决定**：服务端去重后最多 20 人，超限在任何写入前拒绝；维持上限 20，前端不做禁选和人数计数器，只展示真实拒绝原因。
**后果**：安全边界在服务端，正常选择流程保持简洁；超限测试需证明零写入。
