## 二、核心数据表关系

```
profiles (用户)
  ├→ daily_reports (日报)
  ├→ videos (视频)
  ├→ douyin_account_bindings (抖音授权绑定)
  ├→ exemption_request (豁免申请)
  │    ├→ exemption_request_date (逐日审批)
  │    └→ exemption_grant (批准生效投影)
  ├→ fulfillment_appeals (补交申请)
  ├→ topic_child_claims (选题认领)
  └→ notifications (待办)

videos (视频)
  ├→ video_metrics_snapshots (快照)
  ├→ douyin_external_videos (抖音作品暂存与精确关联)
  ├→ video_tags (标签)
  ├→ video_topic_claims (选题绑定)
  └→ video_screenshot_replacement_history (截图替换)

teams (团队)
  ├→ profiles (成员)
  ├→ work_groups (小队)
  └→ fulfillment_records (履约记录)

topic_parent_items (母题)
  └→ topic_child_items (子题)
       ├→ topic_child_claims (认领)
       └→ video_topic_claims (作品绑定)
```

## 四、牵一发动全身

### 命根子表

- **daily_reports 是全站命根子表**：dashboard、admin/fulfillment、admin/collaboration、export、remind、video-submit 全依赖它。动它的结构/口径 = 动全站。
- **videos 表跨模块共享**：admin/content（active/trashed）、video-submit 都查它。改 lifecycle_state 过滤逻辑会影响多个模块。
- **profiles**：所有用户相关操作都依赖它；`membership_status` 及归档快照影响 `visibleUserIds` 的算法。

### 接口复用连累

- 旧 `/video-review` 页面已删除；仍在用的豁免双入口见上表，不随旧页面清理。
- 选题库 topics 的 **suggest**（建议）是纯本地排序不走 AI。旧 recommendations 链路（复用 content-tools）已随旧版文案工具下线一并删除。
- `lib/case-library` 虽属已下线的避坑案例生态，但被 `/api/video-submit` 依赖，**不能删**。`lib/conversion-hub` 已于 2026-10-27 随导粉话术并入文案删除，video-submit 不再依赖话术表（表与历史数据保留）。

## 六、接口存活判断（⚠️ 不要凭本文件删接口）

判死必须逐个查 route 定义、前端调用、被其他接口内部调用、测试和外部触发；静态 grep 无前端调用 ≠ 闲置。清理按[工程运行事实](工程运行事实.md)的边界逐个验证，禁止批量删。反例：`/api/admin/first-screen-monitor`（2026-09-27 核对仍在）。
