# 数据口径

> 最后核对代码日期：2026-11-09（本次核对岗位个人作品评级：达人与文案共用内容标准、按岗位归属选作品；其余日期/统计规则保留此前核验范围）。

## 1. 7个核心指标

| 指标 | 定义 | 公式/口径 | 来源 |
|------|------|-----------|------|
| 24h播放量 | 视频发布满 24 小时后的播放量 | 原始值，无二次计算 | `play_count`，作为各比率分母与爆款系数分子 |
| 互动率 | 点赞、评论、收藏、分享总和占播放的比例 | `(点赞 + 评论 + 收藏 + 分享) / 播放` | `interactionRate()` |
| 点赞率 | 点赞占播放的比例 | `点赞 / 播放` | `likeRate()` |
| 收藏率 | 收藏占播放的比例 | `收藏 / 播放` | `favoriteRate()` |
| 转粉率 | 涨粉量占播放的比例 | `涨粉量 / 播放` | `followerConversionRate()` |
| 导粉率 | 导粉量占播放的比例 | `导粉量 / 播放` | `fanConversionRate()` |
| 爆款系数 | 当前视频 24h 播放相对账号基线的倍数 | `本视频24h播放 / 基线中位数` | `breakoutCoefficient()` |

说明：
- 以上 7 项里，6 个计算公式来自 [src/lib/video-metrics.ts](../../src/lib/video-metrics.ts)。
- `24h播放量` 是原始观测值，不在该文件里做函数计算，但它是所有比率指标的分母，也是爆款系数的分子。
- 比率统一称「互动率」「转粉率」，原始计数仍称「涨粉数/涨粉量」；现役互动率只使用 `interactionRate()`，已下线成长页的加权互动率不作为当前规则。
- 主页访问率（`主页访问 / 播放`）已于 2026-09-21 撤下：`homepage_visits` 无任何采集来源，写入端恒为 0，展示只会误导。字段与历史数据仍保留在 `video_metrics_snapshots`。
- 复盘抽屉大盘第 4 格按视频「话题」标签切换：**干货显示收藏率，复盘及其他显示点赞率**。判定见 `classifyVideoTopicKind()`（`src/lib/topics/library.ts`），标签来源为 `video_tags` 的「话题」维度。

## 3. 爆款判定标准

> ⚠️ **当前无代码消费者（2026-09-27 核对）**：`breakoutCoefficient()`、`median()`、`getAccountBaseline()` 在生产代码里已无任何调用方，本节口径**没有在任何页面生效**。复盘抽屉播放卡片用的是另一套硬编码显示规则（`play_count ≥ 100000` 时标「🔥 爆款层级」，见 `src/app/(app)/admin/content/detail/content-detail-metrics.tsx`），**与本节不是同一个判定**。两套并存属预存问题，已挂待办，未拍板前不得据本节实现新功能，也不得擅自统一数字。

爆款判定口径：
- `24h播放 ≥ 账号近30条中位数 × 2`

等价表达：
- `爆款系数 ≥ 2`

说明：
- 账号基线优先取近 30 条视频的播放样本中位数。
- 若样本不足，按下文“爆款系数冷启动规则”处理。

> 本节是**流量口径**（能不能爆）。下面 3.1 是**内容质量口径**（单条内容达没达标），两者独立，不要混用。

### 3.1 内容质量达成率与留存分（2026-11-13）

单条作品的内容质量由互动达成率和留存达成率共同计算。互动达成率沿用互动数据标准线，留存达成率就是五项留存数据合成的留存分，两个数据均为百分数达成率且允许超过 100%。

留存达成率统一按好标准计算：高值指标为 `实际值 ÷ 好标准 × 100%`，低值指标为 `好标准 ÷ 实际值 × 100%`。2 秒跳出率实际值为 0 时按 200% 计。差线只负责页面不合格提示，不改变达成率、留存档位或综合评级。

默认留存标准为 2 秒跳出率好 25%、差线 >35%；5 秒完播率好 60%、差线 ≤50%；均播时长好 50 秒、差线 ≤30 秒；平均播放占比好 25%、差线 <20%；整体完播率好 10%、差线 ≤5%。快照中的平均播放占比按 0–1 小数保存，展示和评价转换为百分数。

均播时长与平均播放占比先分别计算达成率，再取平均作为 `avgPlayBundle`，该组合项占留存分 20%。五项留存权重为 35%、30%、20%、15%。任一留存值缺失或不是有限数值时，不生成留存分。

### 3.2 综合评级

综合评级取互动达成率与留存达成率（留存分）的平均值，保留弱项最多被强项拉升一档的限制，再叠加播放量门槛。播放低于 2,000 直接判劣，2,000 至不足 15,000 最高为普，达到 15,000 不限档。任一输入缺失时不生成综合评级。评级档位仍为优 ≥100%、良 ≥80%、普 ≥60%、劣 <60%。

详情徽章消费统一内容质量结果中的 `overallGrade`，不在详情层按互动达成率与话题核心指标重新计算。转粉率和话题原核心指标继续展示单项表现，但不参与新的综合评级。

视频复盘列表及详情的指标表现颜色仍按公司评价标准显示。默认标准为 2 秒跳出率 ≤25% 为好、>35% 为差；5 秒完播率 ≥60% 为好、≤50% 为差；均播时长 ≥50 秒为好、≤30 秒为差；平均播放占比 ≥25% 为好、<20% 为差；整体完播率 ≥10% 为好、≤5% 为差。默认颜色样本下限为 3,000，保存后的 `minPlayCount` 可由公司调整。复盘队列的异常提醒固定使用播放 5,000、2 秒跳出 30%、5 秒完播 50%、均播时长 30 秒和整体完播 5%，不随公司评价配置变化。综合评级的播放门槛固定使用 2,000 / 15,000，也不受 `minPlayCount` 覆盖。列表核心指标继续保留自身表现，不替代互动与留存考核。

计算来源：[src/lib/content-quality.ts](../../src/lib/content-quality.ts) 的留存计分和综合质量构造、[src/lib/breakout-rating.ts](../../src/lib/breakout-rating.ts) 的档位与播放门槛；展示位置为详情指标「爆款数据核心大盘」标题旁。

## 4. 下滑判定标准

> ⚠️ **当前无代码实现（2026-09-27 核对）**：全仓（含 `src/`、`supabase/migrations/`、`scripts/`）搜不到任何下滑/近7条中位数比较的实现，本节只是业务口径备查，**没有在任何页面生效**。

下滑判定口径：
- `近7条中位数较前7条下降30%`

公式：
- `(近7条中位数 - 前7条中位数) / 前7条中位数 ≤ -30%`

判定前提：
- 两个窗口都必须有足够样本。
- 若前7条中位数为 0 或为空，不判定下滑。

## 5. 异常状态枚举

| 状态 | 含义 |
|------|------|
| normal / 正常 | 数据处于正常波动区间，无明显异常信号 |
| abnormal / 异常 | 新提交统一异常标记；异常详情下沉到 `punish_type`、`platform_notice`、`appeal` |
| 限流 | 旧数据兼容状态，读模型映射为异常，处罚类型为 `limited` |
| 删稿 | 旧数据兼容状态，读模型映射为异常，处罚类型为 `deleted` |
| 投流 | **已下线（2026-09-26）**：不再接受新写入；旧行读模型仍映射为异常，中文标签照常显示，唯一兼容入口见 `src/lib/video-anomaly.ts` |
| 活动干预 | **已下线（2026-09-26）**：不再接受新写入；旧行读模型仍映射为异常，中文标签照常显示，唯一兼容入口见 `src/lib/video-anomaly.ts` |
| 未满24h | 视频尚未到 24h 观察点，暂不进入 24h 口径比较（自动写入避坑案例库的钩子已于 2026-08-22 移除） |

说明：
- 新写入只使用 `normal / abnormal` 两档。异常录入下拉只剩「限流」「删稿」；「投流」「活动干预」2026-09-26 起不再接受新写，`/api/video-submit` 校验明确拒绝，旧行只做读兼容（进「异常」桶显示原中文标签，不改写）。
- 视频提交链路的异常状态仍以 `videos.anomaly_status` 为准，用于视频复盘与历史异常详情兼容；避坑案例模块已于 2026-08-22 下线，`violation_cases` / `knowledge_cases` 不再有新写入，仅保留历史数据供查询。
- 历史数据口径：高转化话术曾写入 `knowledge_cases(status=submitted)`，违规话术曾写入 `violation_cases`；两条写入链路均已随避坑案例下线停止。

## 6. 业务日期、上传时点与观察窗口

本系统对外展示作品时统一看真实发布日；实际业务通常在发布日之后上传数据。上传日只用于补交、审批、审计和核实先后：

| 名称 | 实际含义 | 使用方式与边界 |
|------|----------|----------------|
| 发布日（D） | 视频在平台实际发布的上海自然日，对应 `videos.published_at` | 全站作品展示、筛选、排序和统计默认按此日期 |
| 上传日 | 员工把数据提交到系统的实际时间，对应 `uploaded_at` | 只在补交、审批、审计和核实先后时显示，并同时说明对应发布日 |
| 日报归属日 | 历史日报的内部编辑和追溯日期，对应 `daily_reports.report_date` | 不作为普通作品日期展示；没有发布日的历史记录才作为回退日期 |
| 24h 观察数据 | 播放、点赞、评论、分享、收藏、涨粉，以及由这些数据计算的核心比率 | 未满 24h 的即时数据不参与统一比较 |

统一规则：
- `videos.published_at` 的上海自然日是全站作品主日期；`uploaded_at` 只记录实际上传时间，不改变作品发布日。
- 新建普通上传和历史手稿时，只要有有效 `published_at`，`daily_reports.report_date` 自动取其上海自然日；没有发布日期的历史记录才使用手填日期。历史编辑沿用原日报归属日，不因编辑表单重新改日。
- 数据库约束 `report_date_must_match_published_at` 拒绝有发布日期但归属日不一致的日报；`published_at` 为空的历史日报保留兼容回退。
- 2026-10-13 的历史修复按正确的 `Asia/Shanghai` 转换执行；旧版 `20261013120000` 迁移只保留作历史记录，已由后续修复迁移覆盖，禁止单独重放旧版 SQL。
- 正常流程按 D+1 上传 D 的数据。基础信息与 24h 数据可以在同一次补录中提交，不因分阶段观察而产生两条日报。
- 历史补录必须选择合法的历史业务日期；验收或补录不需要等待真实 24 小时，但数据仍归属于所选业务日。
- 同一账号同一业务日可以有多条日报，但每条必须绑定不同作品（`video_id`）；同一作品重复提交返回 `409`，编辑必须按原 `video_id` 或日报 `id` 精确更新，不能复用同账号同业务日的其他日报。
- 文档或页面中的 T+0/T+1 仅用于描述观察阶段：T+0 指业务日，T+1 指次日观察/上传阶段；不表示员工必须在当天提交，也不表示管理侧按日检查是否上传。
- `daily_reports.report_date` 继续作为历史编辑、补交申请和记录追溯键，不直接覆盖作品主日期。
- 周、月管理视图、发布管理和员工工作台按发布日聚合；没有发布日的历史记录才回退日报归属日。

补交门禁（2026-09-30 起）：

- `videos.published_at` 表示平台真实发布时间；现有历史值不回填、不按新规则重算。
- 首次创建按提交时刻与真实发布时间计算自然小时差；同月且不超过 72 小时允许直接提交。
- 上传月份与 `report_date` 所在月份不同，或首次提交超过 72 小时，必须先提交补交申请并经管理人员审批。
- `edit` 历史编辑不重新计算首次提交时限；审批通过只取得补交资格，实际日报成功写入后才恢复对应业务日履约状态。
- 补交申请按“成员 + 账号 + 业务日期”去重；趋势图横轴日期不作为业务日期依据。

## 7. 爆款系数冷启动规则

> ⚠️ 同第 3 节：`getAccountBaseline()` 当前无代码消费者，本规则**未在页面生效**，仅作口径备查。

账号基线由 `getAccountBaseline()` 计算，规则如下：

| 样本量 | 口径 | strategy |
|--------|------|----------|
| ≥10条 | 直接取账号自身播放中位数 | `self` |
| 3-9条 | 账号自身中位数 × 50% + 团队中位数 × 50% | `mixed` |
| <3条 | 不给基线，不计算爆款系数 | `insufficient` |

补充：
- 中位数函数为 `video-metrics.ts` 的 `median()`，基线策略为同文件的 `getAccountBaseline()`（行号见第 2 节说明，不写死）。

## 8. 内容吸引力指标优先级

内容吸引力优先看“先吸引点击，再承接停留，再放大互动与转化”。建议优先级如下：

| 优先级 | 指标 | 作用 |
|--------|------|------|
| P1 | 24h播放量 | 最终结果指标，先看是否拿到分发 |
| P2 | 爆款系数 | 判断是否显著跑赢账号常态基线 |
| P3 | 互动率 | 判断内容是否激发反馈与参与 |
| P4 | 转粉率 | 判断内容是否带来直接涨粉 |
| P5 | 导粉率 | 判断内容是否完成更深层转化 |

使用建议：
- 看单条是否“爆”时，先看 `24h播放量 + 爆款系数`。
- 看内容本身是否“有吸引力”时，先看 `互动率`，再看 `转粉率 / 导粉率`。
- 若播放高但转化弱，优先排查内容承接问题；若播放低但转化高，优先排查分发与选题问题。

## 10. 发布管理月度作品口径

- 实发作品数：页面统计范围内 `get_fulfillment_range.published_count` 求和；一天发布多条按真实条数累计，不能拿“发布天数”代替作品数。
- 应发目标：统计范围内自然日数，扣除状态为 `leave`、`waived`、`exempted` 的已批准请假/豁免日，并由成员入职日期裁剪。
- 还差作品数：`max(应发目标 - 实发作品数, 0)`；超发不显示负数。
- 达成率：`实发作品数 / 应发目标`；应发为 0 时记 0。
- `pending` 豁免申请只在月历显示为待审批黄色，不提前扣减应发目标；审批通过后由授权记录进入批准请假/豁免口径。

## 11. 岗位管理月度口径

- 作品按有效 `videos.published_at` 的上海自然日进入所选月份，缺有效发布日的历史记录回退 `daily_reports.report_date`。候选日报仍受 `report_date >= 2026-07-27` 的历史起点限制。
- 达人按 `accounts.profile_id` 认定账号归属，并汇总名下账号当月作品。
- 文案按 `script_author_user_id` 归属，采用「先认定岗位、再统计全量」：管理员认证后进入文案岗；进入后统计本人当月署名的全部文案，包括给自己账号写的。是否给别人写过不再作为入场条件；已认证零作品显示0。认证不推断运营身份。
- 剪辑按 `video_editor_user_id` 归属，只统计给别人账号剪辑的日报；给自己账号剪辑的记录不进入剪辑岗列表和指标。
- 运营按 `operator_user_id` 归属，只统计为别人孵化、负责账号的日报；本人孵化本人账号属于达人工作，不进入运营岗列表和指标。
- 账号主人统一按 `accounts.profile_id` 判断；账号未绑定主人时按别人的账号计入，避免漏掉真实协作。只服务一个别人的账号、只干过一两条也照常展示，不设最低条数。
- 运营、文案、剪辑是服务岗位，不要求本人拥有达人账号；没有自有账号不影响按真实协作归属进入对应岗位，也不能作为异常账号或待清理依据。
- 按团队查看（2026-09-22 起改版）：按工种小队编制（文案/达人/运营）展示，指标与视频复盘抽屉同源——每作品取 `video_metrics_snapshots` 最新 24h 快照，先加总再相除。列 = 作品数（当月署名作品总数，与按岗位口径一致）、总播放（快照播放合计）、条均播放（floor(总播放/快照作品数)，不用未同步作品稀释）、转粉率（Σ涨粉/Σ播放）、互动率（Σ(赞+评+藏+转)/Σ播放）、点赞率（Σ赞/Σ播放）、收藏率（Σ藏/Σ播放）；播放合计为 0 时比率显示 —。署名归属与按岗位口径一致（文案=script_author 署名含本人账号、达人=账号归属、运营=只算他人账号）；一人兼多岗各算各的。每组第一行为「组综合」（组内全部署名作品一次聚合，比率按合计重算，不是成员比率平均）；组内名单含零产出在职成员（数值 0、比率 —）；未同步视频复盘的作品只计入作品数，不参与播放与比率；历史月份按当前编制回看。按岗位四个 Tab 维持原日报口径不变。
- 作品数按岗位责任人对应的日报条数累计；总播放为这些日报 `play_count` 之和；条均播放为 `总播放 / 作品数`，向下取整。个人档案的 `records`、`currentMonth` 仍展示该成员全部日报记录（含给自己账号干的），仅 `operatorSummary` 与服务岗 tab 同口径。
- 个人档案「近 30 天作品质量增长曲线」（2026-09-28 起，替代原「近 6 个月协同产量趋势」堆叠柱状图，旧 `trend` 字段已删除）：窗口固定为上海时区含今天往前数 30 个自然日，**不跟随页面顶部的历史月份**。作品归属与四个岗位榜单同源（达人=本人名下账号的作品；文案=本人署名，含自有账号；运营/剪辑=本人署名且非本人账号；账号未绑主人按他人账号计），抽屉从哪个岗位 Tab 打开就只取该岗位的作品，小队详情里按小队工种换算（文案/达人/运营）。三率取每作品最新 24h 快照、走 `video-metrics` 单条视频口径：未采快照、播放为 0 或指标缺值时互动率/点赞率/收藏率为 `null`（折线在此断开，**不折算成 0%**），该作品只在图底线挂一颗中性虚环灰点，行情带提示「数据待采集（未满 24 小时）」；真实 0% 返回 0 并正常连线。行情带的「近30天均值」= `buildPerformanceMetrics` 加权口径（分子合计 ÷ 播放合计，只计已同步快照的作品），与岗位榜单、小队详情同一个数，**不是单条比率的算术平均**；未采快照的作品只计入作品数、不稀释均值。计算来源：`src/lib/collaboration/domain/report-rules.ts#selectGrowthReports` 与 `src/lib/collaboration/domain/person-rules.ts#buildPersonGrowth`。
- 文案与达人作品评价（文案自 2026-09-30 接通；达人自 2026-11-09 统一）：文案岗位表、文案个人抽屉 30 日曲线、文案本月明细及达人个人档案本月作品共用 `content-quality-contract.ts` 的单篇算法。文案按署名归属；达人按账号主人归属。考核数据统一为互动数据和留存数据。互动数据为（赞+评+藏+转）/播放，按互动好标准计算达成率。留存数据包含 2 秒跳出率、5 秒完播率、均播时长、平均播放占比和整体完播率，按公司可编辑权重合成留存分，默认权重为 35% / 30% / 20% / 15%，其中均播时长与平均播放占比各占组合项的一半。高值指标按实际值 ÷ 好标准 × 100%，低值指标按好标准 ÷ 实际值 × 100%，低值实际值为 0 时按 200% 计。差线只在页面显示不合格警告，不改变达成率、留存档位或综合评级。五项留存值缺一项时不生成留存分；互动数据或留存分缺失时不生成综合评级。综合评级取互动达成率和留存分的平均值，保留弱项最多被强项拉升一档的限制。留存档位为优 ≥100%、良 ≥80%、普 ≥60%、劣 <60%。`overallGrade` 受播放量门槛限制：播放低于 2,000 判劣，2,000 至不足 15,000 最高为普，达到 15,000 后不封顶。留存良优率 = `overallGrade` 为优/良的作品数 / `overallGrade` 非空的署名日报数；留存分均值只纳入五项留存数据完整作品。作品数量按署名日报计数，video_id 去重只用于批量读取。状态使用 `rated`、`unlinked`、`pending_snapshot`、`invalid_play`、`missing_metrics`、`topic_unavailable`；标签查询成功但无标签按 `other`，读取失败时留存分仍可独立计算，但综合评级还需要互动数据。评价标准页面支持负责人修改留存好线、差线与四项权重，权重合计必须为 100%。达人个人明细的转粉率/涨粉评级退出；岗位汇总里的转粉率等业绩读数和个人 30 日原始率曲线继续保留，不参与评级。
- 岗位管理里的“爆款数”是管理页参考指标：当前作品播放至少 30,000；当前作品之前至少有 3 条同账号样本；当前播放达到此前最多 5 条样本平均播放的 3 倍。运营和剪辑只基于给别人账号产出的作品；文案基于已入选文案岗成员当月署名的全部文案（含本人账号）。它不替代第 3 节用于内容分析的全站爆款系数口径。

### 岗位质量与文案计费（2026-09-07）

- 有效作品：播放 >500；优秀作品：播放 ≥30,000 简单计数。各岗位只对自身现有统计范围计数，原有爆款口径不变。
- 文案绩效条数：播放≥500的署名作品数 + 优秀作品数×2（2026-09-08 起不再扣月度基准25，见提交 45e3162f）。优秀每条合计3条；500播放不计有效但可参与计费，两个边界按需求分别执行。
- 例：50条中10条<500、10条优秀，计费60条（基数40 + 优秀10×2）。缺失播放不计有效、优秀或计费基础；不把缺失当作达标。
- 日报来源：`data_source = manual` 显示“手工”；`ai` 不额外标记；`douyin` 表示来自抖音官方接口的自动归集；历史 `null` 显示“来源未知”，不能宣称历史均为 AI。只有 24 小时数据指标被人工录入或修改才标为手工（播放、点赞、评论、分享、收藏、涨粉、导粉、均播时长、2 秒跳出率、5 秒完播率、整体完播率）；首次没有 OCR、直接手填指标也算手工。标题、文案、题材标签、视频形式、内容标签、发布时间、异常信息和运营/文案/剪辑责任人不改变来源标记；一条日报已有手工标记后不降级。历史已有手工标记保留，不凭当前字段倒推清理。
- 导粉话术（2026-10-27 起下线）：话术并入文案，不再有独立话术字段，服务端也不再要求「导粉 > 0 必填话术」；提交接口与编辑详情都不再读写 `script_usage_records` / `violation_cases`（`lib/conversion-hub` 已删除），两张表与历史数据原地保留、不再增长，编辑老记录既不清空也不重建。
- **导粉文案的口径**：不单独存表、不单独打标——`daily_reports` 里 `follower_convert > 0` 的那条记录，其文案就是导粉文案。要筛"哪些文案带来导粉"，直接按日报的文案 + 导粉数取，无需任何关联表。导粉数本身照常采集（选填，留空即 null，不折算成 0）。

## 12. 作者作品画像（视频复盘）

- 作者身份按 `accounts.profile_id ?? videos.user_id` 认定：优先账号归属人，账号未绑定归属人时回退作品提交人，不把提交人当作已绑定账号的作者。
- 周期支持近 30 天（默认，上海自然日）、本月、上月、全部历史；作品总数与画像摘要按所选周期的全部作品计算，不受列表分页影响，所选周期超过 10,000 篇或取数期间列表变化时明确报错，不返回截断统计。作品日期遵循第 6 节。
- 每篇作品取最新 24h 快照；发布未满 24 小时、缺快照、播放缺失或无效的作品不计入有效样本。有限非负播放量有效，0 播放计入样本；作品总数仍包含无效样本作品。
- 条均播放 = `floor(有效样本播放合计 / 有效样本数)`；没有有效样本时为空，不伪装成 0。
- 完播达标数只统计有效样本中整体完播率有效且按当前公司 `completionRate.good` 与 `minPlayCount` 达到“优质”的作品；两个标准来自公司评价设置，不复制固定阈值。
- 优质作品数只统计有效样本中 `overallGrade === "优"` 的作品，随公司评价基准计算；它不同于第 11 节岗位管理里的“爆款数”。实现：`src/lib/content/author-works-domain.ts`、`src/lib/loaders/author-content-works.ts`。
