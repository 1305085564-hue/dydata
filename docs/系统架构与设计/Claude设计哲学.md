# Claude 设计哲学

> **功能性秩序成就惊艳体验**
>
> 我们追求极其强烈的惊艳感。但这惊艳不是花里胡哨的视觉表演，而是来自**功能性的秩序**——每个元素都有明确的目的，所有元素按其功能组织成可预测的系统。
>
> 当用户发现"想做的事情，界面早就准备好了"，当复杂的数据在清晰的秩序中一目了然，当每个交互都丝滑且符合直觉——这种**流畅与确定感**，就是我们要的惊艳。

**本卷是设计系统的主卷**，承担三件事：立场与原理（何以如此）、判断判据（怎么判）、执行主链（按什么顺序做）。两本辅卷是字典：《视觉与数值手册》定数值（是多少），《组件与场景契约》定组件（怎么做）。

**读法**：先读本卷第 0–1 章；按需查《视觉与数值手册》和《组件与场景契约》；判据不明时回查第 2–4 章。

**冲突裁决顺序**：本卷（为什么）→《视觉与数值手册》（是什么）→《组件与场景契约》（怎么做）。

**单一详写律**：原则与"为什么"归本卷，数值归数值手册，组件契约归契约手册；同一规则不两处详写，其余位置只留一行引用，改规则时只改详写处。

## 0. 美学内核

**立场：尊重注意力是目的，功能性秩序是方法，惊艳是秩序的自然结果。**

**可停留检验**：用户停在页面上什么都不做，是否被打扰——自动轮播、脉冲红点、自动刷新跳动、抢焦点，都算打扰。惊艳不只是"用得顺"，还要"看着也舒服"。

### 三条基本定律

#### 定律1: Every Element Earns Its Place (每个元素都挣得其位置)

不是"能不能加装饰"，而是"这个装饰是否帮助用户更快理解或完成任务"。

- 该强调时用颜色 → 因为需要引导注意力（功能性）
- 留白处用图画 → 因为需要视觉引导或情绪缓冲（功能性）
- 不是"克制所以不用"，而是"不需要所以不用"

**判断公式**：
```
IF 删掉这个元素，用户理解变慢或完成任务变难？（认知功能）
  OR 删掉它，"被善待、安心、愿意停留"的感觉随之减弱？（关系功能）
THEN 保留
ELSE 删除
```

#### 定律2: Systematic but Expressive (系统化但有表现力)

有严格的系统（字号档位、颜色系统、留白级数），但不僵化，该打破时就打破。

**打破条件**：
```
IF 打破规则能显著提升功能性
  AND (连续3+场景需要同一例外 OR 一次性特殊场景)
THEN 允许打破
ELSE 遵循系统
```

**治理要求**：打破封闭系统须经阿禅确认，并在 `docs/通用管理/纠错索引.md` 或当日日志留档，注明场景与理由；未留档的"例外"视为违规。

#### 定律3: Load-Bearing in the Worst Environment (承重信号须在最差环境里成立)

层级由哪种手段承担，取决于它在**目标用户最差的渲染环境**里是否仍然看得出来，而不是在设计者自己的屏幕上。

本产品的基线环境是 **Windows**（约 95% 用户）：Segoe UI 与微软雅黑 UI（雅黑只有 400 与 700 两档字重）、中文衬线为钉死的中易宋体（防逐机漂移，见《视觉与数值手册》§1.6）、显示缩放 100%–125%。macOS 是增强环境，不是基线。

- **承重信号**（层级靠它们立住）：字号、字体族（衬线/无衬线）、位置、留白。
- **辅助信号**（锦上添花，剥掉后层级仍须成立）：墨度里相邻两阶的细微差，例如定名墨与正文墨。
- **不入系统**（基线环境里不存在）：字重 500 / 600。一个在 95% 用户屏幕上不存在的手段，不是手段。

**判断公式**：
```
IF 在基线环境里，这个手段的相邻两档肉眼能分清
THEN 它可以承重
ELSE IF 剥掉它之后层级仍然成立
  THEN 它只能做辅助信号
ELSE 它不得进入系统，换一个承重手段
```

新手段入系统前须在 Windows 实机（100% / 125% / 150% 缩放）目检相邻档位；既有字体实测记录见 `docs/通用管理/纠错索引.md`。

### 功能性秩序的双重含义

| 维度 | 含义 |
|---|---|
| **秩序 (Order)** | 如何组织：有章法、可预测、舒适 |
| **功能性 (Utility)** | 为什么这样组织：为了好用、高效、达成目标 |

秩序不是目的，功能性才是。秩序是让功能性持续可靠的手段。

## 1. 执行主链（动手之前先走这一章）

本章是主卷的**常驻核心**。它回答的不是"这个值是多少"，而是"面对一个前端任务，我按什么顺序想、按什么顺序查"。

### 1.0 三条使用纪律

1. **先判型，再走链。** 按任务型选一条链，不通读三卷。
2. **步骤不可跳，展开按需。** 各步均须覆盖，引用章节按需查阅。
3. **判据是硬条件，不是建议。** 不满足就回上一步，不许绕过。

### 1.1 任务型路由（机械判定，不靠感觉）

判定顺序：先看影响范围，按型5 → 型4 → 型3 → 型2 → 型1 依次判定，命中即停；仅修改注释或文档不因路径升型。

| 型 | 机械判据 | 步骤链 | 典型量级 |
|---|---|---|---|
| **型5 全站改版** | ≥3 个页面同改（配色/页头/壳/模式） | E（6 步） | 30+ 文件 |
| **型4 共享组件/令牌** | 改动 `src/components/ui/` 或 `src/styles/design-tokens.css` 的实际表现 | D（7 步） | 影响多页 |
| **型3 从零建页** | 新建 `page.tsx` 或新模块目录 | C（6 步） | 10+ 文件 |
| **型2 改已有页** | 单页内改结构：加区块、重排、改容器与层级 | B（6 步） | 4–20 文件 |
| **型1 微调** | 改动 ≤3 个文件，只调数值（间距/字号/色值/圆角/墨度/对齐），不动结构，影响限于当前页面 | A（3 步） | 1–3 文件 |

**边界模糊**：取影响范围更大的型；跨型任务补做必要专项检查，不重复执行整条流程。

### 1.2 步骤链 A：微调（轻量路径）

- **A0 过三问自检**（§1.7）—— 尤其第 2 问：这处改动会不会让页面自己动起来？
- **A1 会不会抢焦点？** 改前改后，一屏里最响的元素是谁？答案变了就降级（原则4、注意力价格表）。
- **A2 查数值** —— 按《视觉与数值手册》§1–§2 查既定档位；原写法仅在符合现行规范时沿用（详见数值手册 §0），不借微调扩大整改。
- **A3 收尾** —— `npm run gate:design` + 页面验收快检（5 秒测试见原则4，清单见《组件与场景契约》§7.2）。

### 1.3 步骤链 B：改已有页

- **B0 过三问自检**（§1.7）。
- **B1 明任务、看房间** —— 明确用户目标，审视整页布局及现有结构是否妨碍任务完成；本次范围内修正，超范围则指出并提出建议（§2）。
- **B2 定结构** —— 这块归哪一层？统领它的是什么？按感知分组建立亲密度与组间距离（§4、原则5）。
- **B3 定主次** —— 按任务重要性排列核心内容、关键行动与辅助信息，对照整页实际视觉重量检查：主声部是否唯一、相邻两个是否有可见落差？主体不足时先查配角是否过重，再决定是否加强主体（原则4）。
- **B4 定表现** —— 字体族（宣告 / 过程）、墨度、留白档位（§2.1、原则2 价格表；《视觉与数值手册》§1）。
- **B5 查契约** —— 涉及的组件是否已有已定契约？有就照抄，不自造（《组件与场景契约》§3）。
- **B6 收尾** —— 门禁 + 页面验收（含任务闭环、状态真实性及层级，见《组件与场景契约》§7）。

### 1.4 步骤链 C：从零建页

- **C0 过三问自检**（§1.7）。
- **C1 明任务、选型** —— 根据用户目标确定核心操作及完成反馈，再选页面类型；需求与用户任务冲突时提出修正建议，不擅改业务规则（《组件与场景契约》§6）。
- **C2 参照样板** —— 默认复用真实样板；若其结构妨碍当前任务，作最小必要偏离并说明理由（样板页索引见 §1.10）。
- **C3 走 B3–B5** —— 主次 → 表现 → 契约。
- **C4 页头走壳** —— 不自建页头（《组件与场景契约》§4.1）。
- **C5 空态走统一组件** —— 不自绘空态（《组件与场景契约》§3.7）。
- **C6 收尾** —— 门禁 + 页面验收（含任务闭环、状态真实性，见《组件与场景契约》§7）。

### 1.5 步骤链 D：共享组件 / 令牌变更

- **D0 过三问自检**（§1.7）—— 组件改动影响全站，第 2 问尤其要过。
- **D1 影响面盘点** —— 谁引用了它？列出来（grep），不许凭印象。
- **D2 该不该改** —— 现有档位组合能否替代？确需打破走定律2：连续 3+ 场景同一例外 → 加白名单并同步令牌文件；一次性场景 → 允许例外但不入常规系统。
- **D3 定新契约** —— 改组件契约，并同步契约手册对应小节（单一详写律：只改一处）。
- **D4 全站自检** —— 跑一遍所有受影响页面，不只看一个。
- **D5 门禁与基线** —— 基线只降不升；下调须阿禅确认 + 纠错索引留档。
- **D6 令牌同步** —— 令牌与 CSS 变量同步，不留两套；涉及色值/令牌的三卷修订，须与代码令牌、门禁名单、基线同批提交，文档不得先行。
- **D7 收尾** —— 门禁 + 全站页面验收（逐页过《组件与场景契约》§7.2）。

### 1.6 步骤链 E：全站改版

- **E0 过三问自检**（§1.7）。
- **E1 盘点** —— 列全受影响页面与组件（含动态拼装的 class 名——门禁扫不到）。
- **E2 令牌层先改** —— 改 `design-tokens.css` 让页面批量跟随，而不是逐页改 class。
- **E3 逐页走型2** —— 每页单独走 B 链，不批量套模板。
- **E4 统一验收** —— 逐页过页面验收清单（《组件与场景契约》§7.2），不抽查。
- **E5 门禁 + 基线只降不升**。
- **E6 留档** —— 执行清单与上线核对报告各留一份（照 2026-10-28 视觉与 28 色那次的做法）。

### 1.7 三问自检（所有步骤链的公共前置）

动手改任何 UI 前先过一遍，答不上来就先别动：

1. **这是在服务用户理解，还是在争夺用户注意？**
2. **页面静止不动时看着舒服吗？**（静止为默认：无用户动作、无数据真实变化，界面不自行运动）
3. **有没有更便宜的手段达到同样强调效果？**（价格表：从免费档开始花）

### 1.8 谁验证什么

| 自动门禁（`npm run gate:design`） | AI 主动页面自检（《组件与场景契约》§7.2） |
|---|---|
| 字号、墨度、间距、字重、衬线、圆角与阴影等机械项 | 视觉主次、装饰必要性、容器层级、任务闭环、失败反馈与实际交互 |

**门禁全绿 ≠ 验收完成。** AI 未能实际检查的页面或 Windows 实机项目须标记「未验证」，交由具备条件者复验；不得伪称通过。

### 1.9 常见失败模式速查

- **焦点失控**：同层双主 CTA、状态色实底抢主行动（原则4）。
- **层级失真**：靠字重突出条目名、把条目名放大成章节标题、小字用衬线（《视觉与数值手册》§1）。
- **空间噪音**：表单白底套白框，或常规数据区塞装帧元素（原则3、§4）。
- **交互误伤**：表格行悬停位移/缩放，导致数字错位或点击脱靶（《组件与场景契约》§5）。

## 2. 心智模型：一间光线充足的工作室

界面应当像一间光线充足的设计工作室——工具齐全、摆放有序、触手可及。想拿笔，笔在手上；想喝水，杯子在左手边。一切都自然，本该就在那里，以极低心智即可取用。

调整局部前，先审视整页，再判断组件在其中的位置，最后修改具体元素，**避免局部优化破坏整体**。

### 2.1 人文出版物感 (Editorial Warmth)

界面是一本装帧考究的思想读本，不是冷冰冰的软件控制台。层次靠**字阶对比 + 墨度梯次 + 位置恒定**建立，不靠边框、色块与图标堆砌。

- **双字协同，看时刻不看位置**：过程中的内容——正文、表单、控件、写作途中的草稿——坚守 **Sans 清爽黑体**；被郑重宣告为结论的内容——页面定名、空间定名（弹窗标题除外）、AI 结论、归档寄语——才启用 **Serif 衬线体**。小字不逞强，大字不因写得大就理所当然庄重。衬线只落在 **20px 及以上**（缘由见定律3，锁死值见《视觉与数值手册》§1.5）；20px 以下的郑重感，交给 ✦ 微符与左侧竖线承担，不靠衬线。

- **沉稳墨度，去灰入纸**：摒弃偏冷发青的默认灰阶（如 `slate` / `zinc`），墨色师承高档书刊的温润炭黑油墨，落字沉着，与极净暖白大底互为呼应，长时间注视亦不疲倦。墨色梯次严格锁定四阶暖石色值，靠极黑定名与温润浅灰的贴身反差立住锋芒。定名墨与正文墨相差极微，是**辅助信号**：它给细心的读者多一分余味，但不独立承担层级（见定律3）。

- **装帧细节**：卷首寄语 (Epigraph)、学者边注 (Marginalia)、完卷微符 (✦) 赋予精装书般的阅读仪式感。装帧回应内容的郑重程度：关键节点（页面定名、AI 结论、空状态与归档）配得上被精心对待，日常操作区（表格、表单、列表）保持克制，让装帧的出现更有仪式感。

- **暖墨线描意象**：仅在迎宾入场、深度洞察、空态与安心归档等关键心理节点，采用极简暖墨单线手稿插图或微符，拒绝花哨营销插画与冷冰控制台色块。

**场景应用**：数据密集页（表格/图表/监控）极少用衬线，只在页面定名；工作台页（卡片/表单/详情）衬线可用于空间区块标题；引导页可适度增加衬线占比营造氛围，但正文仍用 Sans。

### 2.2 温润与单点聚光灯 (Warm Neutrals & Single Focal Point)

**温润是本质，不是策略**。深度思考需要一盏令人愿意久坐的灯，不是一间审讯室——极净暖白与暖陶土橙回应的是这个，基于高档无酸出版物与人眼长期阅读的物理光学，不因流行调色板而动摇。

- **极净暖白专属 L1 背景**：极净温润暖白只用于全站大背景，承托全屏通透视窗，去除老旧发黄感。

- **单点聚光灯**：全屏 95% 保持克制的水墨中性，**同一活跃交互层级（Z 轴）内应只有一个饱和色焦点**。暖陶土橙（色值见《视觉与数值手册》§2.2）只赋予当前活跃层唯一的主行动（当抽屉或弹窗打开成为当前焦点时，其内部主提交按钮可承接聚光灯）；同层若确需两个主行动，次要行动用 outline 样式。聚焦环、选中勾、引用线等非行动场景一律不得借用主色（聚焦态统一采用深炭墨色微光晕）。主 CTA 的落位随场景而定（页头右侧、表单底部、Hero 区），同层唯一光的约束不变。静音区是默认；有声区可多，但主声部唯一，其余按使用重要性递减，相邻两个之间须有可见落差。

- **状态色不占实底**：成功、异常、待处理、进行中都是**信息**，不是行动。它们以极淡透明底承载同色文字即可被认出，一旦铺成饱和实底就跟主行动争夺唯一的那束光。自造色值同样受此约束——换个 hex 不改变它是一块饱和实底的事实。

### 2.3 安静搭档 (Quiet Partnership)

安静，管的是界面机关，不管内容立场。界面不争宠、不聒噪：操作成功若结果直接可见，原地乐观更新，省略打扰性弹窗与全屏阻塞等待；加载采用等高骨架呼吸，完成立即撤出，布局零跳动。

但克制不等于失语：Claude 的判断、提醒、不同意见值得被听见——不必靠弹窗，走学者边注与卷首寄语这套"发声"语言即可。

**语气**：像一位谨慎的编辑对读者说话，不是系统通知。禁命令口吻与假兴奋：

- ❌ "操作成功！" → ✅ "已记下，可在下方列表看到"
- ❌ "立即填写" → ✅ "先填这一项，其余稍后补也行"
- ❌ "错误，请检查网络后重试"（非网络故障时） → ✅ "这一步没走通，已填的内容没有丢，可以再提交一次"

不确定就承认：推测出的结论用边注标明"这是推测，依据是…"，不假装全知。

## 3. 判断原则 (Design Principles)

从价值观到具体规范的桥梁。这6条原则可以推导出所有具体设计决策。

### 原则1: Closed Systems (封闭系统)

**定义**：每个设计维度（字号/墨度/留白等）都是封闭的白名单，不是开放的连续值。

**为什么**：开放系统会失控。今天加 15px，明天加 16px，最终导致"每个场景都有点不一样"的四不像。

**遇到"现有档位不够用"时**：先重新审视能否用现有档位组合代替（如用墨度+位置代替字号变化）；确需打破，条件与治理见定律2——连续 3+ 场景需要同一例外值 → 加入白名单（改《视觉与数值手册》档位表并同步 globals.css）；一次性场景（落地页 Hero、品牌物料）→ 允许例外但不入常规系统，代码注释说明缘由。常规产品页面、后台、数据密集页不得例外。字号与墨度等机械规则由门禁 `npm run gate:design` 强制，不靠记忆。

---

### 原则2: Single Responsibility (单一职责)

**定义**：每个设计手段只回答一个问题，不许代劳。

| 手段 | 它回答的问题 | 它不回答的问题 |
|---|---|---|
| **字号** | 这是哪一层？（结构位置） | 这重不重要 |
| **字体族** | 这是宣告，还是过程？（宣告性） | 这是第几层 |
| **墨度** | 这是内容，还是元数据？（信息性质） | 这要不要被注意 |
| **位置** | 这东西在哪？（恒定性） | 这有多大、这在第几层 |

**为什么**：一个手段被滥用，其余三个会一起失效。这是可观察的物理过程：

手段会因滥用而失效；手段在目标环境里根本不存在，则从一开始就不是手段（字重退出即其例，见定律3）。同理，若辅助墨被用在大量有内容的文字上，墨度就不再意味着"这是元数据"。手段一个个废掉之后，唯一还在工作的字号被迫承担全部强调，于是列表里一个条目的名称被推到章节标题的字号——它并没有变成一个章节，只是别的手段都用光了。

**注意力价格表**（本卷强调手段的唯一详写；想强调时从免费档起花）：

| 档 | 手段 | 花法 |
|---|---|---|
| **免费档** | 位置（固定槽位、独占一行）、留白（梯次、头顶>脚下）、墨度四阶（相邻两阶只作辅助，见定律3）、出现顺序（渐进揭示） | 便宜够用就停在便宜 |
| **中等档** | 字号升一档、字体族（衬线=宣告，≥20px；条目定名不升字号，用"独占一行+邻居紧跟元数据"的免费档配方）、淡底与下沉、发丝线与微投影 | 下面一档确实不够用，才升这一档 |
| **昂贵档** | 主色饱和实底、动效、插画与装帧符号（✦/边注/寄语） | 同屏省着花：实底同层至多一处（原则4）、动效只报真实变化（《组件与场景契约》§5）、装帧只在关键心理节点（§2.1） |

两条推论（由"为什么"段落的失效机制直接得出）：

- 升到某档仍觉得不够突出：**先查这一档是否被别处滥用，削弱别人，而不是继续升档**。
- 允许组合（如字号+字体族），但三档同时变化=过度花费，退回免费档重新排布。

**验证方法**：
- 看到 `font-medium` 等字重类时：违规，换成对应的承重手段（写法见《视觉与数值手册》§1.1、《组件与场景契约》§3.9）
- 看到浅墨度时，问：这是元数据吗？如果是内容，改为正文墨
- 看到大字号时，问：这是更高层级吗？如果只是想强调，改用墨度或位置

**同档内分层**（多套信号系统共存时的优先级拉开）：

当同一区域有两套或以上信号系统（如表格里数据指标 vs 状态标签 vs 计数徽章），用**色彩降档**拉开注意力层次，而非都用饱和色竞争：

| 层级 | 视觉配方 | 典型场景 |
|---|---|---|
| **主信号** | 饱和色字，无底或微淡底 | 数据指标红绿着色（决定内容质量） |
| **次信号** | 淡底+正文墨字+饱和色圆点 | 状态标签（异常/删稿/限流，需被看到但不抢主角） |
| **背景信号** | 无底+淡灰字+淡灰圆点 | 正常状态（"没问题"的静默确认） |

**判据**：主信号是用户的核心决策依据，次信号是需要被注意但不能抢焦点，背景信号是静默的基线确认。圆点的双重作用：① 吸引注意（饱和色）；② 视觉定位锚点（即使正常状态也保留淡灰圆点，帮助眼睛对齐表格行）。

### 状态色决策树（执行用，唯一详写）

状态色有 4 个语义 × 3 个角色，不需要记 12 个类名，只需要判断：

**STEP 1: 这是什么语义？**
- 成功 / 涨 / 达标 / 正常增长 → `success`
- 异常 / 跌 / 错误 / 删稿 → `danger`
- 待处理 / 警告 / 待审 → `warning`
- 进行中 / 位置 / 信息提示 → `info`

**STEP 2: 这是什么角色？**
- 圆点 / 图表 / 大标记 → 主色（无后缀）
- 文字 → `-text`
- 淡底 → `-bg`

**STEP 3: 拼出类名**
```
text-status-{语义}{角色}
bg-status-{语义}{角色}
```

**示例：**
- "播放量上涨文字" → 成功 + 文字 → `text-status-success-text`
- "删稿状态圆点" → 异常 + 圆点 → `before:bg-status-danger`
- "待审标签淡底" → 待处理 + 淡底 → `bg-status-warning-bg`

**约束（由其他原则推出，此处不重复详写）：**
- 状态色不上实底（见原则4"单点聚光灯"）
- 异常文字统一用正文墨 `text-status-danger-text`（即 `#1F1E1D`）
- 状态淡底用独立 hex，不用透明度（见原则1"封闭系统"）
- 弱圆点 `#D6D3D1` 用于正常状态的视觉定位锚点，不可删除

---

### 原则3: Relationships First, Boundaries as Needed (关系先行，边界补位)

**定义**：先让内容之间的关系成立，再用必要且低干扰的视觉信号表达。归属与强调分别判断：归属回答“哪些是一组”，强调回答“应该先看谁”。需要被分清，不等于需要被突出。

**为什么**：没有结构，内容会散落；结构表达过重，又会与内容争夺注意。目标不是边框最少，而是关系清楚、包装退后。不增加辨识能力的边界是噪音；能够减少归属或操作歧义的边界是结构。

**判断（沿用原则2价格表，不另设手段体系）**：
1. 先用亲密度、对齐、排列节奏及标题归属建立分组。
2. 仍有歧义时，再补局部分隔、连续底色或完整边界；选择足以解决问题、干扰更少的手段，不预设阴影比边框安静。
3. 同一关系若已被可靠表达，不再重复围合。多种信号可以协作，但须带来额外辨识收益。
4. 移除边界前，确认它承担的内容归属或操作范围；移除后，该职责必须仍然成立。不能只删样式而不调整布局。
5. 输入、焦点、拖放及浮层等必要的交互边界，不因降噪而牺牲可发现性。

**配方引用**：边界与底色沿用《视觉与数值手册》§2，组件表现沿用《组件与场景契约》§3，不自造。装帧元素（✦、边注、寄语、暖墨线描插图）仍属昂贵档：只出现在既定关键心理节点（§2.1），常规数据展示永不用图标装饰。

---

### 原则4: Single Focal Point (单点聚光灯)

**定义**：一屏分静音区与有声区。静音区是默认；有声区可含任意数量元素，但同一活跃交互层（Z 轴）内主声部只有一个，其余有声元素按使用重要性递减，相邻两个之间须有可见落差。颜色只是音量的一种，位置、字号、留白、墨度同样计入。

**为什么**：人的注意力是单线程的；多个同级焦点 = 没有焦点。有声元素多不是病，同级才是病。

**判断（价格表昂贵档的预算规则，Z 层定义见 §4.2）**：在整页及当前活跃层中，按任务重要性排列核心内容、关键行动与辅助信息，再检查实际视觉顺序是否一致。视觉重量应综合位置、面积、围合、对比和重复密度判断，不因颜色浅、线条细或单个组件克制，就视为整体安静。

主体不够突出时，先检查辅助内容是否占据过多面积、优先位置或包装，再决定是否加强主体；不得以降低必要信息的可读性代替降噪。

主声部唯一，通常由当前关键行动或核心内容承担，不机械等同于某个按钮；其余依次减弱，轻提醒只和静音区拉开可辨的一档。状态与辅助信息可清楚辨认，但不因分组需要而自动升级为展示重点。弹窗/抽屉打开即成为当前活跃层，其内部主提交可承接主声部；同层主行动之间的实底预算与次要行动配方不变。状态色（成功/异常/待处理）是信息不是行动，永不占饱和实底（见 §2.2）。

**验证方法**：无可靠静态命令；对照《组件与场景契约》§7.2，逐活跃层列出全部有声元素并排序，检查主声部是否唯一、相邻两个是否有可见落差，再做眯眼/灰度/5 秒测试。检查用户是否能先找到当前任务，再辨认辅助信息；不能只统计饱和实底数量，也不能只逐个检查组件（主色色值见《视觉与数值手册》§2.2）。

---

### 原则5: Nested Hierarchy (嵌套层级)

**定义**：整体应能统领局部。空间关系按用户感知的分组建立，不按代码嵌套层数机械推导；具体维度分别遵循下列约束。

**为什么**：局部不能反过来支配整体；代码里的容器层数，也不能替代用户对任务与内容归属的理解。

**具体体现**：
- **留白梯次**：同组内容应比异组内容更亲近，距离须结合对齐、方向与内容密度判断。仅当父子容器确实对应感知分组时，才使用 `gap(父) > gap(子)`，不要求所有代码嵌套逐层扩大间距。
- **标题亲密度**：标题头顶间距 > 标题到内容间距（标题贴近其统领的内容）
- **容器嵌套**：外容器圆角 ≥ 内容器圆角
- **容器阻尼**：容器缩小，内部可用的字号档位也跟着收窄——控件级浮层（Popover / 下拉）里没有"标题"这个身份（档位与判据见《组件与场景契约》§3.6 容器阻尼律、§3.3 浮层内部层级）

**判断流程**：
1. 识别任务分组与标题统领范围，不按 DOM 层数直接决定视觉层级。
2. 按既有档位安排组内亲密度和组间距离，间距映射见《视觉与数值手册》§1.3。
3. 结合对齐、方向与内容密度检查：组内是否相连、组间是否可分、标题是否归属于下方内容。

**验证方法**：目视检查，必要时用开发者工具测量。标题应贴近它统领的内容；移除围合时检查整组范围是否仍清楚，而非只测某一个 gap。

---

### 原则6: Progressive Disclosure (渐进式揭示)

**定义**：默认最简，按需唤醒。用户此刻不看它，不会做出不同的下一步，就不该出现。

**为什么**：界面不争宠，信息密度 ≠ 信息噪音。

**判断决策树**：
```
决定一个元素是否该显示时：

STEP 1: 必要性判断
IF 用户此刻不看它，会做出错误的下一步？
  THEN 必须显示
ELSE 进入 STEP 2

STEP 2: 时机判断
IF 这是次要操作（删除、复制、更多选项）
  THEN 常态隐藏，hover/focus 时浮现
    → opacity-0 group-hover:opacity-100
ELSE IF 这是辅助信息（统计、说明、提示）
  THEN 降级呈现（更小字号、更浅墨度）
ELSE IF 这是高级选项
  THEN 收起到"更多"或折叠区

STEP 3: 视觉重量检查
IF 显示后，页面是否感觉"太挤"或"太吵"？
  THEN 重新评估必要性，或改为渐进式揭示
```

**具体应用**：
- 表格行内操作：常态隐藏、hover/focus 浮现（组件契约见《组件与场景契约》§3.1）
- 筛选器默认值：不在 UI 上写"全部"，因为未筛选时这是废话
- 空值单元格：用 `—` 而不是 "无数据" 或 "N/A"

## 4. 位置与空间（XY 与 Z）

### 4.1 位置即秩序 (Constancy of Place)

眼睛记住的是坐标而非长相：同一件东西在每个页面落在同一处，视线落下即命中；位置一旦随页面漂移，每次进来都得先找一遍，秩序便从舒适转为负担。

- **一屏之内**：正文以统一的主对齐轴贯通成视觉脊梁。确需用缩进表达从属时，同组内容统一服从该轴，不因容器嵌套各自逐层缩进（关系判据见原则5）。
- **同类页面之间**：页面级元素落在恒定槽位（页头槽位表见《组件与场景契约》§4.1），翻页如翻同一本书的下一页。
- **网格之内**：各卡的定名、数据与脚注落在同一水平线，内容长短不改变重心。

秩序来自恒定，不来自对齐得多复杂。放置一件东西要同时回答两问：**它在哪一格（XY，本节），它在第几层（Z 轴，见 §4.2）。**

### 4.2 空间：桌子 - 纸 - 排版三层

位置管平面坐标（XY，见 §4.1），本节管深度层次（Z 轴）。

#### 4.2.1 三层的职责

| 层级 | 物理心智 | 色值 | 使用场景 |
|---|---|---|---|
| **L1 背景层** | 现代书案 | 见《视觉与数值手册》§2.1 | 全站统一视窗底层 |
| **L2 容器层** | 气垫与触点 | 见《视觉与数值手册》§2.1 | 只读区下沉，触点上浮 |
| **L3 内容层** | 纸上排版 | 透明 | 依靠留白与发丝线建立秩序 |

**为什么是三层**：物理世界的桌面就是桌板+纸张+墨迹，人类几千年的书桌心智模型。

#### 4.2.2 双向深度法则

- **展示下沉,交互上浮**：
  - 下沉（只读）：只读汇总区、背景槽确需下沉分区时使用浅砂气垫，不因只读或辅助身份自动铺底（适用范围与色值见《视觉与数值手册》§2.1）
  - 上浮（可交互）：输入框、按钮用纯白 + 微投影（见《视觉与数值手册》§2.4）

#### 4.2.3 全局容器律

- **主角端庄落座**：核心数据大表格配独立纯白托盘；表单直接裸铺或下沉浅砂槽
- **配角直接裸铺**：筛选器（时间/成员 Select）、导航、分页器等配角工具背景透明、无边框。纯白上浮只给文本输入框与承载状态色的特殊按钮——**能下拉不等于要边框，看它是表单字段还是视图工具**。契约见《视觉与数值手册》§2.1。
- **克制嵌套**：只在看板/瀑布流/网格项用多卡片，常规页面用留白+发丝线+字阶建立层次
- **高密度降噪**：次要操作常态 `opacity-0`，hover/focus 时 `opacity-100`
