# Claude 设计哲学

> **功能性秩序成就惊艳体验**
>
> 我们追求极其强烈的惊艳感。但这惊艳不是花里胡哨的视觉表演，而是来自**功能性的秩序**——每个元素都有明确的目的，所有元素按其功能组织成可预测的系统。
>
> 当用户发现"想做的事情，界面早就准备好了"，当复杂的数据在清晰的秩序中一目了然，当每个交互都丝滑且符合直觉——这种**流畅与确定感**，就是我们要的惊艳。

本卷述其物理本义与心智因由（何以如此），《Claude 设计规范》定其尺度与节拍（如何落地）。**两卷冲突时以本卷为准。** **单一详写律**：原则与判断详写于本卷，数值与契约详写于《规范》，同一规则不两处详写。

## 0. 美学内核

这套美学源自现代主义设计的核心原则：

**Form Follows Function** (形式服从功能)  
+  
**Systematic Design** (系统化设计)

### 三条基本定律

#### 定律1: Every Element Earns Its Place (每个元素都挣得其位置)

不是"能不能加装饰"，而是"这个装饰是否帮助用户更快理解或完成任务"。

- 该强调时用颜色 → 因为需要引导注意力（功能性）
- 留白处用图画 → 因为需要视觉引导或情绪缓冲（功能性）
- 不是"克制所以不用"，而是"不需要所以不用"

**判断公式**：
```
IF 删掉这个元素，用户理解速度是否变慢？
  OR 删掉这个元素，用户完成任务是否变难？
THEN 保留
ELSE 删除
```

#### 定律2: Systematic but Expressive (系统化但有表现力)

有严格的系统（字号档位、颜色系统、留白级数），但不僵化，该打破时就打破。

**打破条件**：
```
IF 打破规则能显著提升功能性
  AND (连续3+场景需要同一例外 OR 一次性特殊场景)
THEN 允许打破
ELSE 遵循系统
```

**治理要求**：打破封闭系统须经阿禅确认，并在 `docs/通用管理/纠错索引.md` 或当日日志留档，注明场景与理由；未留档的"例外"视为违规。

#### 定律3: Load-Bearing in the Worst Environment (承重信号须在最差环境里成立)

层级由哪种手段承担，取决于它在**目标用户最差的渲染环境**里是否仍然看得出来，而不是在设计者自己的屏幕上。

本产品的基线环境是 **Windows**（约 95% 用户）：Segoe UI 与微软雅黑 UI（雅黑只有 400 与 700 两档字重）、中文衬线回退为宋体、显示缩放 100%–125%。macOS 是增强环境，不是基线。

- **承重信号**（层级靠它们立住）：字号、字体族（衬线/无衬线）、位置、留白。
- **辅助信号**（锦上添花，剥掉后层级仍须成立）：墨度里相邻两阶的细微差，例如定名墨与正文墨。
- **不入系统**（基线环境里不存在）：字重 500 / 600。一个在 95% 用户屏幕上不存在的手段，不是手段。

**判断公式**：
```
IF 在基线环境里，这个手段的相邻两档肉眼能分清
THEN 它可以承重
ELSE IF 剥掉它之后层级仍然成立
  THEN 它只能做辅助信号
ELSE 它不得进入系统，换一个承重手段
```

任何新手段入系统之前，须在 Windows 实机（100% / 125% / 150% 缩放）目检相邻档位确实可分。字体族承重的前提——Windows 宋体标题实机观感可接受——见《规范》§9 闸门。

### 功能性秩序的双重含义

| 维度 | 含义 |
|---|---|
| **秩序 (Order)** | 如何组织：有章法、可预测、舒适 |
| **功能性 (Utility)** | 为什么这样组织：为了好用、高效、达成目标 |

秩序不是目的，功能性才是。秩序是让功能性持续可靠的手段。

## 1. 心智模型：一间光线充足的工作室

界面应当像一间光线充足的设计工作室——工具齐全、摆放有序、触手可及。想拿笔，笔在手上；想喝水，杯子在左手边。一切都自然，本该就在那里，以极低心智即可取用。

秩序带来的舒适是这么来的，它源于**全局高于局部的绝对原则**。

工作室是一个整体，每个物件都有其从属的定位。**你不能为了凸显某一个水杯或工具，就非要单独给它垫一个碟子或造一个外框（局部最优），从而破坏了整个桌面的清爽（全局最优）。**

因此，动手改动任何 UI 之前，必须严格执行三步视野缩放：

1. **先审视整个页面的宏观风格与布局**（看房间）
2. **再评估当前组件在全局中的定位**（看家具）
3. **最后才聚焦修改具体的元素**（动工具）

**绝对禁止为了追求局部的丰富，而破坏页面整体的秩序与协调。**

### 1.1 人文出版物感 (Editorial Warmth)

界面是一本装帧考究的思想读本，不是冷冰冰的软件控制台。层次靠**字阶对比 + 墨度梯次 + 位置恒定**建立，不靠边框、色块与图标堆砌。

- **双字协同，看时刻不看位置**：过程中的内容——正文、表单、控件、写作途中的草稿——坚守 **Sans 清爽黑体**；被郑重宣告为结论的内容——页面定名、空间定名（弹窗标题除外）、AI 结论、归档寄语——才启用 **Serif 衬线体**。小字不逞强，大字不因写得大就理所当然庄重。衬线只落在 **18px 及以上**：基线环境（Windows）的中文衬线是宋体，小字下横笔发虚，18px 起才站得住；18px 以下的郑重感，交给 ✦ 微符与左侧竖线承担，不靠衬线。

- **沉稳墨度，去灰入纸**：摒弃偏冷发青的默认灰阶（如 `slate` / `zinc`），墨色师承高档书刊的温润炭黑油墨，落字沉着，与极净暖白大底互为呼应，长时间注视亦不疲倦。墨色梯次严格锁定四阶暖石色值，靠极黑定名与温润浅灰的贴身反差立住锋芒。定名墨与正文墨相差极微，是**辅助信号**：它给细心的读者多一分余味，但不独立承担层级（见定律3）。

- **装帧细节**：卷首寄语 (Epigraph)、学者边注 (Marginalia)、完卷微符 (✦) 赋予精装书般的阅读仪式感。装帧回应内容的郑重程度：关键节点（页面定名、AI 结论、空状态与归档）配得上被精心对待，日常操作区（表格、表单、列表）保持克制，让装帧的出现更有仪式感。

- **暖墨线描意象**：仅在迎宾入场、深度洞察、空态与安心归档等关键心理节点，采用极简暖墨单线手稿插图或微符，拒绝花哨营销插画与冷冰控制台色块。

**场景应用**：数据密集页（表格/图表/监控）极少用衬线，只在页面定名；工作台页（卡片/表单/详情）衬线可用于空间区块标题；引导页可适度增加衬线占比营造氛围，但正文仍用 Sans。

### 1.2 温润与单点聚光灯 (Warm Neutrals & Single Focal Point)

**温润是本质，不是策略**。深度思考需要一盏令人愿意久坐的灯，不是一间审讯室——极净暖白与暖陶土橙回应的是这个，基于高档无酸出版物与人眼长期阅读的物理光学，不因流行调色板而动摇。

- **极净暖白专属 L1 背景**：极净温润暖白只用于全站大背景，承托全屏通透视窗，去除老旧发黄感。

- **单点聚光灯**：全屏 95% 保持克制的水墨中性，**同一活跃交互层级（Z 轴）内应只有一个饱和色焦点**。暖陶土橙（色值见《规范》§2.2）只赋予当前活跃层唯一的主行动（当抽屉或弹窗打开成为当前焦点时，其内部主提交按钮可承接聚光灯）；同层若确需两个主行动，次要行动用 outline 样式。聚焦环、选中勾、引用线等非行动场景一律不得借用主色（聚焦态统一采用深炭墨色微光晕）。

- **状态色不占实底**：成功、异常、待处理、进行中都是**信息**，不是行动。它们以极淡透明底承载同色文字即可被认出，一旦铺成饱和实底就跟主行动争夺唯一的那束光。自造色值同样受此约束——换个 hex 不改变它是一块饱和实底的事实。

**场景应用**：数据密集页主 CTA 常在页头右侧（"导出报表"/"新建分析"）；工作台页主 CTA 可能在表单底部或卡片内；引导页 Hero 区可有一个主 CTA。状态色（成功/异常/待处理）在所有场景都只能用淡底 + 同色文字，绝不上实底。

### 1.3 安静搭档 (Quiet Partnership)

安静，管的是界面机关，不管内容立场。界面不争宠、不聒噪：操作成功若结果直接可见，原地乐观更新，省略打扰性弹窗与全屏阻塞等待；加载采用等高骨架呼吸，完成立即撤出，布局零跳动。

但克制不等于失语：Claude 的判断、提醒、不同意见值得被听见——不必靠弹窗，走学者边注与卷首寄语这套"发声"语言即可。

**场景应用**：表格行编辑、状态切换完成后原地直接生效，不弹 Toast；表单提交成功后直接流转，不停留弹窗；数据加载用浅砂骨架屏（色值见《规范》§2.1），完成即刻原地淡入。AI 洞察、系统提醒用边注或寄语，不用模态弹窗打断。

## 2. 判断原则 (Design Principles)

从价值观到具体规范的桥梁。这6条原则可以推导出所有具体设计决策。

### 原则1: Closed Systems (封闭系统)

**定义**：每个设计维度（字号/墨度/留白等）都是封闭的白名单，不是开放的连续值。

**为什么**：开放系统会失控。今天加 15px，明天加 16px，最终导致"每个场景都有点不一样"的四不像。

**判断决策树**：
```
遇到"现有档位不够用"时：

IF 打破规则能显著提升功能性
  AND 近期连续3+个场景都需要同一个"例外值"
  THEN 档位有缺口，考虑加入白名单
  → 修改设计规范的档位表，同步更新 globals.css
  
ELSE IF 打破规则能显著提升功能性
  AND 只是一次性场景（落地页 Hero、品牌物料）
  THEN 允许例外，但不入常规系统
  → 在代码中注释说明为什么例外
  
ELSE 
  THEN 重新审视：是否可以用现有档位组合解决？
  → 比如用墨度+位置代替字号变化
```

**何时可以打破**：
- ✓ 一次性落地页、品牌物料、特殊营销页面
- ✗ 常规产品页面、后台管理、数据密集页

**验证方法**：运行《规范》§7.1 的字号与墨度检查命令（检查命令的唯一详写处在《规范》§7.1）。

---

### 原则2: Single Responsibility (单一职责)

**定义**：每个设计手段只回答一个问题，不许代劳。

| 手段 | 它回答的问题 | 它不回答的问题 |
|---|---|---|
| **字号** | 这是哪一层？（结构位置） | 这重不重要 |
| **字体族** | 这是宣告，还是过程？（宣告性） | 这是第几层 |
| **墨度** | 这是内容，还是元数据？（信息性质） | 这要不要被注意 |
| **位置** | 这东西在哪？（恒定性） | 这有多大、这在第几层 |

**为什么**：一个手段被滥用，其余三个会一起失效。这是可观察的物理过程：

手段会因滥用而失效；手段在目标环境里根本不存在，则从一开始就不是手段。字重曾被设计为第四个手段，但基线环境里 500 渲染成 400，"定名"与"过程"在 95% 用户眼里字形完全相同——它从未回答过任何问题，所以退出系统，它原本回答的"宣告性"由字体族接管（缘由见定律3）。同理，若辅助墨被用在大量有内容的文字上，墨度就不再意味着"这是元数据"。手段一个个废掉之后，唯一还在工作的字号被迫承担全部强调，于是列表里一个条目的名称被推到章节标题的字号——它并没有变成一个章节，只是别的手段都用光了。

**判断决策树**：
```
遇到"想强调某个元素"时：

STEP 1: 确定它是什么
IF 这是一个层级标题（章节、区块、条目）
  THEN 用字号体现层级
ELSE IF 这是一个定名（宣告一个实体）
  THEN 页面级、空间级：用衬线（≥18px，字体族）
       条目级：独占一行 + 定名墨 + 下方紧跟元数据（位置与邻居反差）
       不靠字重
ELSE IF 这是元数据或辅助信息
  THEN 用浅墨度
ELSE IF 这是位置恒定的交互入口
  THEN 用位置（固定槽位）

STEP 2: 检查是否已经用对了手段
IF 已经用对手段，但还觉得不够明显
  THEN 检查其他元素是否滥用了同一手段（导致对比度丢失）
  → 削弱其他元素，而不是再加强这个元素

STEP 3: 多手段组合
IF 单一手段不足以建立层级
  THEN 允许组合（如字号+字体族，或字号+墨度）
  BUT 不允许三手段同时变化（过度强调）
```

**验证方法**：
- 看到 `font-medium` / `font-semibold` / `font-bold` 时：违规。字重全站只有 400，换成对应的承重手段（条目名与激活态的写法见《规范》§1.1、§3.9）
- 看到浅墨度时，问：这是元数据吗？如果是内容，改为正文墨
- 看到大字号时，问：这是更高层级吗？如果只是想强调，改用墨度或位置

### 原则3: Hierarchy Without Ornament (无装饰层级)

**定义**：层次只用字号、字体族、墨度、位置建立，不靠边框、色块、图标堆砌。

**为什么**：装饰是视觉噪音。每多一个边框，用户理解数据的速度就慢一分。

**判断决策树**：
```
遇到"想加边框/底色/图标"时：

STEP 1: 功能性检查
IF 删掉这个装饰，内容是否仍然清晰？
  THEN 删除（它是垃圾）
ELSE 进入 STEP 2

STEP 2: 替代手段检查
IF 可以用留白、发丝线、字阶替代
  THEN 用替代手段
ELSE 进入 STEP 3

STEP 3: 必要装饰判断
IF 这是交互触点（输入框、按钮）需要物理凸出感
  OR 这是容器需要明确边界（卡片、弹窗）
  OR 这是状态需要视觉信号（成功、异常、激活/选中）
  THEN 允许装饰，但：
    - 输入框：发丝边 + 微投影
    - 容器：圆角 + 轻阴影（不用粗边框）
    - 状态：淡底 + 同色文字（不用饱和实底）
    - 激活/选中：墨度升至定名墨 + 浅砂底或上浮白底（不靠字重，配方见《规范》§3.9）
ELSE 删除
```

**特殊场景例外**：
- ✓ 空状态可用暖墨线描插图（引导功能）
- ✓ AI 结论可用左侧竖线或 ✦ 微符（装帧仪式感）
- ✓ 关键节点可用装帧元素（卷首寄语、边注）
- ✗ 常规数据展示不用图标装饰

---

### 原则4: Single Focal Point (单点聚光灯)

**定义**：同一活跃交互层（Z 轴）内只有一个饱和色焦点。

**为什么**：人的注意力是单线程的。多个焦点 = 没有焦点。

**判断决策树**：
```
遇到"想加一个主 CTA 按钮"时：

STEP 1: 确定当前活跃层
IF 有打开的弹窗/抽屉
  THEN 活跃层 = 弹窗/抽屉内部
ELSE 
  THEN 活跃层 = 页面主体

STEP 2: 检查是否已有聚光灯
IF 当前活跃层已有饱和色实底的主 CTA
  THEN 新按钮不能用饱和色实底
    → 选项1: 改用 outline 样式
    → 选项2: 判断哪个更重要，把聚光灯移过去
ELSE
  THEN 可以用饱和色实底

STEP 3: 状态色检查
IF 想用饱和色实底表示状态（成功/异常/待处理）
  THEN 不允许
  → 改用淡底 + 同色文字
  → 原因：状态是信息，不是行动
```

**验证方法**：无可靠静态命令，禁止以"写了脚本数过"宣称合规——对照《规范》§7.2 目视清单，逐活跃层数饱和色实底，同一层 >1 即违规（主色色值见《规范》§2.2）。

---

### 原则5: Nested Hierarchy (嵌套层级)

**定义**：任何维度的层级都遵循"外层 > 内层"规则。

**为什么**：违反这条，秩序就会倒置，看起来像"儿子管爹"。

**具体体现**：
- **留白梯次**：`gap(父容器) > gap(子模块)`
- **标题亲密度**：标题头顶间距 > 标题到内容间距（标题贴近其统领的内容）
- **容器嵌套**：外容器圆角 ≥ 内容器圆角

**判断决策树**：
```
设置容器间距时：

STEP 1: 识别层级关系
确定当前容器在哪一层：
- 页面级大章节（最外层）
- 区块/卡片（中层）
- 组件内部（最内层）

STEP 2: 应用梯次规则
IF 页面级章节之间
  THEN 用断层 (gap-5，见《规范》§1.3)
ELSE IF 区块标题到内容
  THEN 用呼吸 (gap-3，见《规范》§1.3)
ELSE IF 同级元素之间
  THEN 用紧凑 (gap-2，见《规范》§1.3)
ELSE IF 强关联元素（大数+单位）
  THEN 用亲密 (gap-1，见《规范》§1.3)

STEP 3: 验证梯次
检查：gap(当前容器) 是否 > gap(子模块)
IF 不是
  THEN 调整，直到满足梯次
```

**验证方法**：
目视检查或用开发者工具测量：
- 外层容器的 `gap` 值必须大于内层
- 标题到下方内容的距离必须小于标题到上方的距离

---

### 原则6: Progressive Disclosure (渐进式揭示)

**定义**：默认最简，按需唤醒。用户此刻不看它，不会做出不同的下一步，就不该出现。

**为什么**：界面不争宠，信息密度 ≠ 信息噪音。

**判断决策树**：
```
决定一个元素是否该显示时：

STEP 1: 必要性判断
IF 用户此刻不看它，会做出错误的下一步？
  THEN 必须显示
ELSE 进入 STEP 2

STEP 2: 时机判断
IF 这是次要操作（删除、复制、更多选项）
  THEN 常态隐藏，hover/focus 时浮现
    → opacity-0 group-hover:opacity-100
ELSE IF 这是辅助信息（统计、说明、提示）
  THEN 降级呈现（更小字号、更浅墨度）
ELSE IF 这是高级选项
  THEN 收起到"更多"或折叠区

STEP 3: 视觉重量检查
IF 显示后，页面是否感觉"太挤"或"太吵"？
  THEN 重新评估必要性，或改为渐进式揭示
```

**具体应用**：
- 表格行内操作：常态隐藏、hover/focus 浮现（组件契约见《规范》§3.1）
- 筛选器默认值：不在 UI 上写"全部"，因为未筛选时这是废话
- 空值单元格：用 `—` 而不是 "无数据" 或 "N/A"
- 成功反馈：结果可见时不弹 Toast，直接原地更新

## 3. 设计维度的完备性

界面设计本质是**信息的视觉编码**。用户看到一个元素时，大脑同时解码6个问题：

1. **层级？** → 字号（四档，见《规范》§1.1）
2. **宣告还是过程？** → 字体族（衬线/无衬线，见《规范》§1.5）
3. **内容还是元数据？** → 墨度（四阶，见《规范》§1.2）
4. **在哪？** → 位置（恒定槽位，见 §3.2）
5. **跟谁一伙？** → 留白（四级,见《规范》§1.3）
6. **属于哪个容器？** → 圆角+阴影（三档+全圆/四档，见《规范》§1.4/§2.4）

这6个维度**各司其职、互不代劳**：覆盖所有静态元素的视觉编码，互不干扰。

**范围限定**：以上六维指**静态元素**的解码清单。动效管时间维度、语义色管状态维度，由《规范》§5、§2 另行约束，不属于本清单的"冗余"判定范围。

### 3.1 为什么是这些档位？

| 维度 | 档位数 | 原因 |
|---|---|---|
| 字号 | 4档 | 页面→空间→正文→元数据；条目名并入正文档，靠位置与邻居反差区分 |
| 字体族 | 2类 | 衬线（宣告，≥18px）vs 无衬线（过程），二分足够 |
| 墨度 | 4阶 | 定名→正文→元数据→信号；前两阶相差极微，只作辅助，承重的是后三层，再多难分辨 |
| 留白 | 4级 | 断层→呼吸→紧凑→亲密，覆盖所有场景 |
| 圆角 | 3档+全圆 | 控件→容器→浮层，对应Z轴层级 |

具体数值见《Claude 设计规范》。

### 3.2 位置即秩序 (Constancy of Place)

眼睛记住的是坐标而非长相：同一件东西在每个页面落在同一处，视线落下即命中；位置一旦随页面漂移，每次进来都得先找一遍，秩序便从舒适转为负担。

- **一屏之内**：正文有唯一一条左对齐轴，容器不各自缩进，贯通成视觉脊梁。
- **同类页面之间**：页面级元素落在恒定槽位（页头槽位表见《规范》§4.1），翻页如翻同一本书的下一页。
- **网格之内**：各卡的定名、数据与脚注落在同一水平线，内容长短不改变重心。

秩序来自恒定，不来自对齐得多复杂。放置一件东西要同时回答两问：**它在哪一格（XY，本节），它在第几层（Z 轴，见 §4）。**

## 4. 空间：桌子 - 纸 - 排版三层

位置管平面坐标（XY，见 §3.2），本章管深度层次（Z 轴）。

### 4.1 三层的职责

| 层级 | 物理心智 | 色值 | 使用场景 |
|---|---|---|---|
| **L1 背景层** | 现代书案 | 见《规范》§2.1 | 全站统一视窗底层 |
| **L2 容器层** | 气垫与触点 | 见《规范》§2.1 | 只读区下沉，触点上浮 |
| **L3 内容层** | 纸上排版 | 透明 | 依靠留白与发丝线建立秩序 |

**为什么是三层**：物理世界的桌面就是桌板+纸张+墨迹，人类几千年的书桌心智模型。

### 4.2 双向深度法则

**展示下沉,交互上浮**：
- 下沉（只读）：只读汇总区、背景槽用浅砂气垫（色值见《规范》§2.1）
- 上浮（可交互）：输入框、按钮用纯白 + 微投影（见《规范》§2.4）

### 4.3 全局容器律

- **主角端庄落座**：核心数据大表格配独立纯白托盘；表单直接裸铺或下沉浅砂槽
- **配角直接裸铺**：筛选栏、分页器、统计汇总等外围工具背景透明、无边框
- **克制嵌套**：只在看板/瀑布流/网格项用多卡片，常规页面用留白+发丝线+字阶建立层次
- **高密度降噪**：次要操作常态 `opacity-0`，hover/focus 时 `opacity-100`
