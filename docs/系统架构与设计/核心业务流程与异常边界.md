# 核心业务流程与异常边界

> 本文件回答两件事：DYData 的主要业务链路怎么流转；遇到限流、删稿、补交、豁免、数据缺失时怎么办。
> 正常路径看第一节到第五节，走不通时看第六节"异常与边界"。
> 最后核对：2026-11-18（豁免审批、成员归档/恢复按代码核对）

## 1. 视频数据上传

### 1.1 普通上传（72小时内且同月）

```
员工填表 → 提交 → daily_reports + videos →
→ fulfillment_records 更新 → 通知（可选）
```

**检查点**：
- 新建判重按[数据口径与计算规则 §6](数据口径与计算规则.md#6-业务日期上传时点与观察窗口)：仅同一作品重复提交返回 409；同账号同日可提交不同作品
- published_at 必填，report_date 自动匹配
- ≤72小时 且 同月 → 直接通过

### 1.1.1 截图上传：按顺序归位（2026-11-15 起）

截图类型由位置决定，不由内容猜：第一张是互动截图，第二张是留存截图，各自只按本类提示词识别一次。

```
空态「把互动截图粘贴或拖进来」（小字：一次传两张时，请按互动、留存的顺序上传）
→ 第一张进互动槽（按互动识别）→ 粘贴区改为「请再上传留存截图」（小字：互动截图已收到），不等识别
→ 第二张进留存槽（按留存识别）→ 截图区换成两张卡片、下方表单展开，识别在后台继续
```

**规则**：
- 一次多选或拖入多张：按列表顺序填空槽，放不下的不收，提示「截图只收两张，多出的 N 张没上传」。
- 两槽都有图时直接粘贴：不顶掉任何一张，提示「要点开想替换的那张卡片再选图」。换图只能点卡片空白处，点哪张换哪张，新图立即替换旧图；点卡片里的小图是看大图。
- 表单展开时机：两槽都有图过（展开后删掉一张也不收回）、点「没有截图，直接手填」、编辑已交记录、作品异常不要求截图。只填了标题文案（如从选题库带入）不会提前展开。
- 识别失败沿用卡片上的「没认出，请手填/重传」，截图照样保留。
- 识别接口 `/api/ocr-screenshot` 必须显式带 `screenshot_type`（`data` / `retention`），不带直接 400。工作台按槽位带；管理端「补 24 小时数据」弹窗固定带 `data`（只回填互动截图上的六个数字）。

### 1.2 补交申请（超72小时或手填发布时间）

```
填表 → 补交申请 → pending →
→ 管理员审批 →
  → 通过：批准补交并尝试自动续交；续交成功才写日报并恢复履约
          续交失败保留资格，员工可「去完成填报」
  → 驳回：关闭申请，通知员工
```

**检查点**：
- 按"成员+账号+业务日"去重
- 新建提交和补交申请都先按作品判重，命中直接提示“这条已经上传过,无需重复提交”，不创建申请
- 发布时间识别失败时允许手填。手填或修改识别值都按手工来源进入补交审批，审批卡片保留并展示 OCR 原值
- 审批写 audit_logs
- 批量关闭待办（source_type=fulfillment_appeal）

### 1.3 抖音自动归集（转正后启用）

```text
账号授权 → Cron 拉取作品/账号趋势 → 外部作品暂存
→ 按「业务账号 + 抖音 item_id」精确关联
→ 自动创建或补齐 videos → 24h/72h 快照按年龄写入
→ 无法确认的作品进入待关联，不自动改履约
```

边界：官方列表当前没有时间过滤且最多返回 4 页；视频数据按最多 10 个 item_id 分批读取；Token 只在服务端加密保存。模糊标题/时间只能生成候选，不能自动绑定。抖音接口失败、授权过期或作品不可见时，员工仍可走原手工填报和补交申请。

## 2. 豁免申请与审批

### 2.1 员工申请

```
申请豁免 → 填原因 → 提交 →
→ exemption_request (pending) →
→ 通知管理员（导航角标）
```

### 2.2 管理员审批

```
豁免抽屉 → 查看 →
→ 按日期处理通过或驳回，已批准日期投影至 exemption_grant
→ 管理员待办随申请状态自动消失；员工只在工作台横幅看到最近一条申请的结果（不写通知中心）
```

**检查点**：
- 一个业务日一条生效豁免
- 批准日期按生效豁免计入履约。逐日明细与旧区间兼容见[模块地图](全站模块与数据关系.md)。

## 3. 视频复盘

### 3.1 列表展示

```
进 /admin/content → 加载器 →
→ videos (active) + snapshots + tags →
→ 列表（筛选/排序/分页）
```

### 3.2 详情抽屉

```
点视频 → 抽屉 →
→ 爆款大盘（互动率/转粉率/播放/第四格）
→ 选题库状态
→ 双截图（可替换）
```

**连累**：
- 选题库 POST `/api/topics/library-status` 批量
- 截图替换走 video_screenshot_replacement_history
- 回收站 (trashed) 不在主列表

### 3.3 作者作品与人效回看

作品复盘可从责任人进入作者作品档案，再查看该作者在数据管理中的岗位人效；来源作品仍可读时可返回原复盘。作者归属和画像口径见[数据口径与计算规则](数据口径与计算规则.md#12-作者作品画像视频复盘)，入口范围与验证见[模块地图](全站模块与数据关系.md#三高频高风险模块地图)。导航参数和返回行为原由旧《组件与场景契约》§3.11 约定；该节在 2026-11-13 美学文档重构后未保留，2026-11-16 确认不回写，现无文档出处。

## 4. 发布管理

### 4.1 履约状态

```
查 fulfillment_records → 按团队/日期聚合 →
→ 已提交 / 已豁免 / 缺失 →
→ 团队×日期矩阵
```

### 4.2 申诉处理

```
点"处理申诉" → 详情 →
→ 批准/驳回 → 审批与审计 → 后置处理各自记录结果
  → 批准：尝试自动续交，失败保留已批准资格（见 §1.2）
  → 驳回：关闭申诉，通知员工
```

## 5. 选题库与成员生命周期

### 5.1 选题库

```
母题 topics → 分组 topic_groups → 子题 sub_topics
开始写作 → sub_topic_claims 记录在写/取消/完成 → 作品 videos.topic_id 关联子题
多人同时在写时展示真实写作动态
```

### 5.2 成员生命周期

| 动作 | 链路 |
|---|---|
| 入职 | 添加成员 → profiles (active) → 关联 team_id → 分配 work_group_id（可选） |
| 归档 | profiles.membership_status = archived，先封禁登录；团队写入归档快照 → 历史保留（visibleUserIds）→ 候选排除（activeVisibleUserIds） |
| 恢复 | membership_status = active，但团队、角色、权限清空，归档快照删除 → 成员需重新申请入团；原团队管理员在成员列表里看不到他 |

## 6. 异常与边界

### 6.1 异常状态枚举

| 状态 | 含义 | 接受新写入 |
|------|------|-----------|
| normal | 正常 | ✅ |
| abnormal | 异常（限流/删稿） | ✅ |
| 限流 | 旧兼容 | ❌ 只读 |
| 删稿 | 旧兼容 | ❌ 只读 |
| 投流 | 已下线 | ❌ 只读 |
| 活动干预 | 已下线 | ❌ 只读 |
| 未满24h | 未到观察点 | ✅ 自动 |

**规则**：
- 新写入只用 normal / abnormal
- 旧行保留原状态，只读兼容
- 投流/活动干预 2026-09-26 起拒绝

异常状态的含义与判定归 [数据口径与计算规则](数据口径与计算规则.md) §5。

### 6.2 补交门禁

- **直接提交**：首次提交 − published_at ≤ 72h（跨月不额外要求补交）
- **必须补交申请**：超 72 小时，或发布时间为手工来源
- **历史编辑**：不重算时限，沿用原 report_date

### 6.3 豁免规则

- 审批只写逐日明细与生效授权（exemption_grant），不写 fulfillment_records；发布履约查询时现场按生效授权判定请假(leave)/豁免(exempted)
- 打回会让该申请的授权失效（保留为历史行），再次批准重新生效
- 只拦同一申请人、同一分类的待审批日期重叠。不同日期可继续申请。

### 6.4 数据缺失处理

| 缺什么 | 怎么显示 |
|---|---|
| 播放量 | 爆款评级不显示徽章；列表显示 "—" |
| 互动率/转粉率 | 单项评级不显示；综合评级不显示徽章 |
| 话题标签 | 按"复盘及其他"处理；第四格显示点赞率 |

### 6.5 边界场景

- **重复提交**：新建判重规则见[数据口径与计算规则 §6](数据口径与计算规则.md#6-业务日期上传时点与观察窗口)；编辑无法按原作品唯一绑定日报时拒绝编辑。
- **回收站视频**：`lifecycle_state = trashed`，不在主列表，可通过"回收站"入口查看
- **归档成员**：`profiles.membership_status = archived`，历史保留（visibleUserIds），候选排除（activeVisibleUserIds）
- **跨团队访问**：按[权限与访问控制「数据范围」](权限与访问控制.md#数据范围)判断；视频复盘成员有专用只读特例，不复制到其他页面或写操作。
