# 核心业务流程

> 本文件回答：DYData 的主要业务链路怎么流转。
> 行数上限：300行 | 最后核对：2026-10-14

## 1. 视频数据上传

### 1.1 普通上传（72小时内且同月）
```
员工填表 → 提交 → daily_reports + videos → 
→ fulfillment_records 更新 → 通知（可选）
```

**检查点**：
- 同账号同业务日去重（409）
- published_at 必填，report_date 自动匹配
- ≤72小时 且 同月 → 直接通过

### 1.2 补交申请（超72小时或跨月）
```
填表 → 补交申请 → pending →
→ 管理员审批 →
  → 通过：写 daily_reports，恢复履约
  → 驳回：关闭申请，通知员工
```

**检查点**：
- 按"成员+账号+业务日"去重
- 审批写 audit_logs
- 批量关闭待办（source_type=fulfillment_appeal）

## 2. 豁免申请与审批

### 2.1 员工申请
```
申请豁免 → 填原因 → 提交 →
→ exemption_requests (pending) →
→ 通知管理员（导航角标）
```

### 2.2 管理员审批
```
豁免抽屉 → 查看 →
→ 通过：写 exemptions，关闭申请和待办
→ 驳回：状态改 rejected，关闭待办
```

**检查点**：
- 一个业务日一条生效豁免
- 授予后自动更新 fulfillment_records

## 3. 视频复盘

### 3.1 列表展示
```
进 /admin/content → 加载器 →
→ videos (active) + snapshots + tags →
→ 列表（筛选/排序/分页）
```

### 3.2 详情抽屉
```
点视频 → 抽屉 →
→ 爆款大盘（互动率/转粉率/播放/第四格）
→ 选题库状态
→ 双截图（可替换）
```

**连累**：
- 选题库 POST `/api/topics/library-status` 批量
- 截图替换走 video_screenshot_replacement_history
- 回收站 (trashed) 不在主列表

## 4. 发布管理

### 4.1 履约状态
```
查 fulfillment_records → 按团队/日期聚合 →
→ 已提交 / 已豁免 / 缺失 →
→ 团队×日期矩阵
```

### 4.2 申诉处理
```
点"处理申诉" → 详情 →
→ 批准/驳回 → 审计 + 关闭待办 →
  → 批准：恢复履约
  → 驳回：关闭申诉，通知员工
```

## 5. 选题库

### 5.1 母题/子题
```
创建母题 → topic_parent_items →
→ 添加子题 → topic_child_items →
→ 关联视频 → video_topic_claims
```

### 5.2 认领与撞车
```
认领子题 → topic_child_claims →
→ 提交视频绑定 video_id →
→ 撞车检测：同子题多人 → 撞车动态
```

## 6. 成员生命周期

### 6.1 入职
```
添加成员 → profiles (active) →
→ 关联 team_id →
→ 分配 work_group_id（可选）
```

### 6.2 归档
```
归档 → lifecycle_state = archived →
→ 历史保留（visibleUserIds）
→ 候选排除（activeVisibleUserIds）
```

### 6.3 恢复
```
恢复 → lifecycle_state = active →
→ 重回候选
→ 历史自动关联
```
