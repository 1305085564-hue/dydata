# 异常与边界处理

> 本文件回答：遇到限流、删稿、补交、豁免、数据缺失时怎么处理。
> 行数上限：200行 | 最后核对：2026-10-14

## 1. 异常状态枚举

| 状态 | 含义 | 接受新写入 |
|------|------|-----------|
| normal | 正常 | ✅ |
| abnormal | 异常（限流/删稿） | ✅ |
| 限流 | 旧兼容 | ❌ 只读 |
| 删稿 | 旧兼容 | ❌ 只读 |
| 投流 | 已下线 | ❌ 只读 |
| 活动干预 | 已下线 | ❌ 只读 |
| 未满24h | 未到观察点 | ✅ 自动 |

**规则**：
- 新写入只用 normal / abnormal
- 旧行保留原状态，只读兼容
- 投流/活动干预 2026-09-26 起拒绝

## 2. 补交门禁

### 2.1 直接提交
- 上传月 = report_date 月
- 首次提交 - published_at ≤ 72h

### 2.2 必须补交申请
- 跨月
- 超72小时

### 2.3 历史编辑
- 不重算时限
- 沿用原 report_date

## 3. 豁免规则

### 3.1 生效条件
- 一个业务日一条生效豁免
- 授予后自动更新 fulfillment_records

### 3.2 申请去重
- 按"成员+账号+业务日"去重
- 已有 pending 不能重复

## 4. 数据缺失处理

### 4.1 播放量缺失
- 爆款评级 → 不显示徽章
- 列表 → 显示 "—"

### 4.2 互动率/转粉率缺失
- 单项评级 → 不显示
- 综合评级 → 不显示徽章

### 4.3 话题标签缺失
- 按"复盘及其他"处理
- 第四格显示点赞率

## 5. 边界场景

### 5.1 重复提交
- 同账号同业务日 → 409
- 提示"已存在"

### 5.2 回收站视频
- lifecycle_state = trashed
- 不在主列表
- 可通过"回收站"入口查看

### 5.3 归档成员
- lifecycle_state = archived
- 历史保留（visibleUserIds）
- 候选排除（activeVisibleUserIds）

### 5.4 跨团队访问
- 组员：只看本公司
- 组长：只看本团队成员
- 公司所有者：看本公司全部
