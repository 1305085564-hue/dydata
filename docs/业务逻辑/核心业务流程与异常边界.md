# 核心业务流程与异常边界

> 本文件回答两件事：DYData 的主要业务链路怎么流转；遇到限流、删稿、补交、豁免、数据缺失时怎么办。
> 正常路径看第一节到第五节，走不通时看第六节"异常与边界"。
> 最后核对：2026-10-14

## 1. 视频数据上传

### 1.1 普通上传（72小时内且同月）

```
员工填表 → 提交 → daily_reports + videos →
→ fulfillment_records 更新 → 通知（可选）
```

**检查点**：
- 同账号同业务日去重（409）
- published_at 必填，report_date 自动匹配
- ≤72小时 且 同月 → 直接通过

### 1.2 补交申请（超72小时或跨月）

```
填表 → 补交申请 → pending →
→ 管理员审批 →
  → 通过：写 daily_reports，恢复履约
  → 驳回：关闭申请，通知员工
```

**检查点**：
- 按"成员+账号+业务日"去重
- 审批写 audit_logs
- 批量关闭待办（source_type=fulfillment_appeal）

### 1.3 抖音自动归集（转正后启用）

```text
账号授权 → Cron 拉取作品/账号趋势 → 外部作品暂存
→ 按「业务账号 + 抖音 item_id」精确关联
→ 自动创建或补齐 videos → 24h/72h 快照按年龄写入
→ 无法确认的作品进入待关联，不自动改履约
```

边界：官方列表当前没有时间过滤且最多返回 4 页；视频数据按最多 10 个 item_id 分批读取；Token 只在服务端加密保存。模糊标题/时间只能生成候选，不能自动绑定。抖音接口失败、授权过期或作品不可见时，员工仍可走原手工填报和补交申请。

## 2. 豁免申请与审批

### 2.1 员工申请

```
申请豁免 → 填原因 → 提交 →
→ exemption_requests (pending) →
→ 通知管理员（导航角标）
```

### 2.2 管理员审批

```
豁免抽屉 → 查看 →
→ 通过：写 exemptions，关闭申请和待办
→ 驳回：状态改 rejected，关闭待办
```

**检查点**：
- 一个业务日一条生效豁免
- 授予后自动更新 fulfillment_records

## 3. 视频复盘

### 3.1 列表展示

```
进 /admin/content → 加载器 →
→ videos (active) + snapshots + tags →
→ 列表（筛选/排序/分页）
```

### 3.2 详情抽屉

```
点视频 → 抽屉 →
→ 爆款大盘（互动率/转粉率/播放/第四格）
→ 选题库状态
→ 双截图（可替换）
```

**连累**：
- 选题库 POST `/api/topics/library-status` 批量
- 截图替换走 video_screenshot_replacement_history
- 回收站 (trashed) 不在主列表

## 4. 发布管理

### 4.1 履约状态

```
查 fulfillment_records → 按团队/日期聚合 →
→ 已提交 / 已豁免 / 缺失 →
→ 团队×日期矩阵
```

### 4.2 申诉处理

```
点"处理申诉" → 详情 →
→ 批准/驳回 → 审计 + 关闭待办 →
  → 批准：恢复履约
  → 驳回：关闭申诉，通知员工
```

## 5. 选题库与成员生命周期

### 5.1 选题库

```
创建母题 → topic_parent_items →
→ 添加子题 → topic_child_items →
→ 关联视频 → video_topic_claims
```

```
认领子题 → topic_child_claims →
→ 提交视频绑定 video_id →
→ 撞车检测：同子题多人 → 撞车动态
```

### 5.2 成员生命周期

| 动作 | 链路 |
|---|---|
| 入职 | 添加成员 → profiles (active) → 关联 team_id → 分配 work_group_id（可选） |
| 归档 | lifecycle_state = archived → 历史保留（visibleUserIds）→ 候选排除（activeVisibleUserIds） |
| 恢复 | lifecycle_state = active → 重回候选 → 历史自动关联 |

## 6. 异常与边界

### 6.1 异常状态枚举

| 状态 | 含义 | 接受新写入 |
|------|------|-----------|
| normal | 正常 | ✅ |
| abnormal | 异常（限流/删稿） | ✅ |
| 限流 | 旧兼容 | ❌ 只读 |
| 删稿 | 旧兼容 | ❌ 只读 |
| 投流 | 已下线 | ❌ 只读 |
| 活动干预 | 已下线 | ❌ 只读 |
| 未满24h | 未到观察点 | ✅ 自动 |

**规则**：
- 新写入只用 normal / abnormal
- 旧行保留原状态，只读兼容
- 投流/活动干预 2026-09-26 起拒绝

异常状态的含义与判定归 [数据口径与计算规则](数据口径与计算规则.md) §5。

### 6.2 补交门禁

- **直接提交**：上传月 = report_date 月，且首次提交 − published_at ≤ 72h
- **必须补交申请**：跨月，或超 72 小时
- **历史编辑**：不重算时限，沿用原 report_date

### 6.3 豁免规则

- 一个业务日一条生效豁免；授予后自动更新 fulfillment_records
- 申请按"成员+账号+业务日"去重；已有 pending 不能重复

### 6.4 数据缺失处理

| 缺什么 | 怎么显示 |
|---|---|
| 播放量 | 爆款评级不显示徽章；列表显示 "—" |
| 互动率/转粉率 | 单项评级不显示；综合评级不显示徽章 |
| 话题标签 | 按"复盘及其他"处理；第四格显示点赞率 |

### 6.5 边界场景

- **重复提交**：同账号同业务日 → 409，提示"已存在"
- **回收站视频**：`lifecycle_state = trashed`，不在主列表，可通过"回收站"入口查看
- **归档成员**：`lifecycle_state = archived`，历史保留（visibleUserIds），候选排除（activeVisibleUserIds）
- **跨团队访问**：按[权限与访问控制「数据范围」](权限与访问控制.md#数据范围)判断；视频复盘成员有专用只读特例，不复制到其他页面或写操作。
