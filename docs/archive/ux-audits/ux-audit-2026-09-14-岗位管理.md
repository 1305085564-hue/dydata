## Findings

### P1｜当前月份缺少“截至日/进度”语义，月度比较容易误判

- 证据：本轮在 2026-09-14 审查时，2026-9 显示 267 条作品、达人 27 人，状态为“岗位归属完整”；切到 2026-8 后显示 542 条作品、岗位完整度 99%（5 条待补）。页面只显示 `2026-9` / `2026-8`，没有在首屏标明当前月已统计到哪一天或当前月是否未完结。
- 影响：负责人可能把未完结的当月产量与完整月份直接比较，误判产出、排名或岗位表现。当前月的“完整”也只代表岗位归属完整，不代表月度数据已经结算。
- 建议：首屏同时展示“数据截至 YYYY-MM-DD”“当前月进行中/已结算”及与上月比较的口径提示；对未完结月份的环比、排名和绩效数字加明确标识。

### P1｜切换岗位页签存在短暂的 URL、页签和内容不同步

- 证据：从运营切到文案、从文案切到剪辑时，点击后的即时可访问性状态曾短暂保留上一页内容或显示“暂无文案岗位记录”，随后才更新为目标页签及真实数据表；最终等待后四个页签均正常加载。
- 影响：这是管理核对页，短暂的空态/旧数据态可能被误读为“没有记录”或让用户在错误表格上继续操作，尤其在网络较慢时会损害信任。
- 建议：路由参数、选中页签和表格数据完成同一轮更新后再展示空态；加载期间保留目标页签高亮并显示骨架/加载提示，禁止旧表格和“暂无记录”同时作为可操作内容出现。

### P2｜排序方向对辅助技术的表达不足

- 证据：桌面视觉上能看到“总播放”等列的排序箭头，点击后数据确实在升序/降序间切换；Chrome 原生可访问性状态只暴露为“按钮 总播放”，没有读出当前排序方向或 `aria-sort` 语义。
- 影响：键盘或屏幕阅读器用户无法确认当前列表是按升序还是降序，复核排名时容易把列表方向看反。
- 建议：为可排序列暴露当前方向、下一次动作和排序优先级；排序后将焦点和状态播报保持在同一列。

### P2｜写操作与只读核对入口同层，关键防误操作护栏未能在只读轮次验证

- 证据：文案页每行直接出现“阿禅认证/未认证”切换入口；视频诊断面板在分析内容旁出现“移入回收站”；归属缺口抽屉中的“补录文案/剪辑/运营”组合框会实时重算月报。按用户约束，本轮没有点击这些会改业务数据的控件，因此没有把确认、权限拒绝、撤销和审计记录当作通过证据。
- 影响：负责人从核对指标进入分析时，写操作与查看操作距离近；若确认层级、影响范围和可撤销性不足，会增加误认证、误归档或误改岗位归属的风险。
- 建议：将写操作统一收进“操作”入口，点击前明确影响范围和月报重算后果；对认证、归属补录、回收站分别提供确认、撤销/恢复和操作记录。下一轮应在专用测试账号上验证完整护栏。

## Scenario Results

### First Contact

通过。既有 DYData 标签页导航到目标页，首屏显示岗位标题、月份、四个页签、岗位完整度、当前角色“阿禅 / 公司所有者”和真实表格数据。

### Interrupted Workflow

通过。打开人员档案、岗位归属缺口抽屉、视频诊断后均可用关闭按钮或 Esc 返回上一级；刷新目标页后仍保留 `year=2026&month=9&tab=talents`、真实达人表和角色信息。

### Wrong Turn

通过。跨页签、月份往返和从作品进入诊断后均能回到岗位管理上下文；没有因为关闭抽屉而丢失月份或页签。

### Returning User

通过（同一已登录角色）。直接刷新带有月份/页签参数的 URL 后，数据表、月份和角色恢复；未测试退出后重新登录。

### Keyboard Only

部分覆盖。Esc 可关闭抽屉/诊断；Tab 能在页面导航和岗位控件间移动，实际观察到从排序按钮继续 Tab 会回到页面主导航，尚未完成整页仅键盘走完“排序 → 档案 → 作品 → 诊断”的任务。

### Heavy Data

部分覆盖。8 月抽屉显示 542 条作品总量并列出 5 条缺口，9 月人员档案最多展示 31 条左右明细；未用 500+ 人员或更大列表数据完成滚动、筛选和长列表性能审查。

### Second User

未覆盖。本轮只有当前已登录的公司所有者角色，没有切换或创建受限角色账号。

### Destructive Confidence

按用户明确的只读约束跳过所有保存、删除、认证、提交、上传和外部发送动作；不以未执行伪装成通过。
已确认的写入口包括文案认证/反认证、归属缺口中的责任人补录和诊断面板“移入回收站”；它们只记录为未验证的护栏风险，没有产生业务写入。

## Responsive / Dark Mode

本轮仅验证当前 Google Chrome 桌面窗口；Cua 原生通道没有在不改变用户窗口布局的前提下完成视口缩放与暗色模式切换，因此响应式、移动端和暗色模式未覆盖。

## What Works Well

- 月份、页签和 URL 参数形成稳定上下文，前进边界（未来月份）有禁用态。
- 岗位完整度不是只给百分比：缺口能下钻到具体日期、账号、作品和缺失岗位；完整月份也能明确提示所有作品已关联责任人。
- 岗位表既支持聚合排序，也支持运营按账号展开、文案/剪辑按作品展开，适合从总量追到明细。
- 人员档案统一承载岗位计数、趋势和作品列表，作品标题能继续进入视频诊断，形成从岗位到作品病因的闭环。
- 关键指标有解释性帮助文本，例如有效作品“播放大于 500”、优秀作品“播放至少 30,000”；文案页还暴露绩效结算规则。

## Priority Recommendations

1. 先补“数据截至日 + 当前月进行中/已结算”语义，避免把 9 月未完结数据与 8 月完整数据直接比较。
2. 修正页签切换的加载状态机：URL、选中页签、数据请求和空态必须原子对齐；请求期间显示目标页签加载态，不渲染上一页或误导性空表。
3. 统一写操作护栏：认证、岗位补录、回收站动作显示影响范围，提供确认、撤销/恢复与操作记录，并在 UI 层与只读核对动作分组。
4. 补充排序控件的可访问语义（当前方向、下一动作、排序结果播报），再用专用测试账号完成键盘全链路与受限角色验收。
