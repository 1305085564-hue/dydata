# UX 体验全链路审计：审批工作台

**日期**：2026-10-12
**审计对象**：导航栏「行动中枢」弹窗 —— 审批工作台（`UnifiedCommandHub`），组长/管理员处理请假、特殊豁免、补交申诉、团队待办
**环境**：本地隔离库（`.env.ai-test.local` → 本地 Supabase），`next dev :3100`，Playwright Chromium，视口 1440×900 + 375/768/1024 响应式扫描
**人设**：一位忙碌的团队组长，中等技术熟练度，日常在 MacBook 上批量处理团队审批，偶尔在手机上处理
**方式**：真实浏览器点击驱动（非读代码），逐状态截图 + 控制台/网络监听；截图见 `screenshots-qw/`
**说明**：本报告为独立复跑，与 Codex 同日审计（`ux-audit-2026-10-12.md`）分开留档，未改任何生产代码

---

## 总评

审批工作台的**核心闭环是扎实的**：同意/驳回都有 5 秒可撤回、驳回原因必填且提示会通知成员、逐日批注能落到具体某一天、权限边界正确（组员看不到审批）。**但有三处会真正伤到日常使用**：① 手机上「同意/驳回/批注」这些按钮只在鼠标悬停时才出现，触屏没有悬停，等于组长在手机上只能"一键全部同意"或干瞪眼，没法单独处理一条；② 同一条补交申诉在"补交申诉"卡片和"团队待办"里各出现一次，勾掉待办并不等于批准了申诉，容易"以为处理了其实没处理"；③ 顶部三个数字（角标 8 / 共 6 份明细 / 一键全部同意 4）互相不解释，组长扫一眼数不清到底还有几条要办。

## 问题清单（按严重度）

### Critical（阻断任务）

- **C1 · 手机上无法单独处理任何一条审批**
  - 现象：卡片级「同意全部/拒绝全部」、逐日「仅准许/仅驳回/批注」、补交的「同意补交/驳回」全部是 `opacity-0 group-hover:opacity-100`（悬停才现）。触屏没有 hover，375px 下这些按钮**看不见也基本点不到**，唯一稳定可用的是右上角「一键全部同意」。
  - 后果：组长在手机上要么整批同意、要么没法逐条驳回/批注，核心任务做不了。
  - 位置：`exemption-approval-card.tsx:87`、`fulfillment-appeal-card.tsx:129`
  - 截图：`screenshots-qw/05-resp-375.png`
  - 建议：触屏/窄屏改为**常显**操作（去掉 hover-only，或点击卡片即展开操作行），别把主操作藏在 hover 里。

### High（困惑、摩擦、信任受损）

- **H1 · 同一条补交申诉"一物两现"，勾待办≠批准申诉**
  - 现象：一条补交既作为「补交申诉」审批卡（同意补交/驳回），又作为「团队待办」里的一条（左侧圆圈=完成待办）。代码 `canMarkDone = todo.source !== 'exemption'` 允许把补交待办直接勾完成，但勾完成**不会批准申诉**；反过来批准申诉才会顺带关掉同源待办。
  - 后果：组长勾掉待办、以为处理完，申诉其实还挂在待审里 → 假闭环、两本账。
  - 位置：`todo-item-card.tsx:31`、`unified-command-hub.tsx`（todo 与 appeal 分列）
  - 截图：`screenshots-qw/02-01-hub-open-default.png`、`22-17-todo-tab.png`
  - 建议：补交待办不给"完成"圆圈，改成"去处理"跳转到审批卡；或勾完成时二次确认"这不等于批准"。

- **H2 · 桌面端也存在隐藏操作，静态看卡片像"不能动"**
  - 现象：不悬停时，补交卡、豁免卡上没有任何可见按钮（见 `06-02-filter-appeal.png` 整屏无操作入口）。第一次用的人不知道能逐日分别处理。
  - 建议：至少把卡片级"同意/拒绝"做成常显弱样式，hover 再增强；逐日操作加一个可见的展开提示。

- **H3 · 顶部三个数字互相不解释**
  - 现象：角标/标题「8」= 审批卡数 + 待办数；「共 6 份明细」= 底层申请单数；「一键全部同意 (4)」= 可批的审批卡数。同一屏三个数，没有一处说明各自口径。
  - 后果：组长数不清"到底还有几条要我办"。
  - 位置：`workbench-header.tsx:33`、`approvals-tab.tsx:200`
  - 截图：`02-01`、`22-17`、`28-29`
  - 建议：统一为一个"待处理 N"口径，"份明细"若无实际意义就删；批量按钮数量与"全部"角标对齐。

- **H4 · 375px 下中文竖排断行，读不了**
  - 现象：申请人「测试组员」被压成一字一行竖排；页签断成"补交/申诉""团队待办与权/限""已处理/记录"。
  - 位置：`exemption-approval-card.tsx:57`（头部 flex 未给名字留最小宽）
  - 截图：`05-resp-375.png`
  - 建议：窄屏给名字 `min-w`/`whitespace-nowrap` + 溢出省略，页签横向滚动而非折行。

- **H5 · 「一键全部同意」无二次确认**
  - 现象：一次点击把当前可见的**所有**申请排入同意队列，只有 5 秒撤回兜底，无确认框。
  - 后果：手滑一次 = 整批放行，5 秒后不可逆。
  - 建议：批量前弹确认（列出"将同意 N 条：…"），或把撤回窗口对批量单独延长。

### Medium（可用但别扭）

- **M1 · 历史里"打回待处理"对豁免是零确认、对补交却要确认**
  - 豁免卡点"打回待处理"直接执行（`02-reopen-confirm.png` 显示"打回中…"），补交卡反而有"确认打回"。误点一下豁免打回 = 悄悄撤销已批准的决定并重发全员待办，且**没有撤回窗口**。建议：豁免打回也加确认，或纳入 5 秒撤回。
- **M2 · 历史审阅时间比上海业务日早一天（UTC/本地错位）**
  - 实测：当前上海时间 10-12 凌晨，历史卡显示"由 测试组长 审阅 · **10月11日**"。审阅时间按 UTC 渲染，与全站"业务日=上海"口径冲突，日志读起来"不可信"。建议：`reviewed_at` 按上海日展示。（注：卡上"业务日期 11月2日"是本次种子造的**未来日期**，非缺陷，勿据此判 bug。）
- **M3 · "半天"被当成整天**
  - 事由写"牙医复诊，请半天"，却归入"请假4天"、10月20日按整天出片。系统无半天粒度，组长"同意"即多给半天。建议：至少支持半天或在卡片上把"半天"显式标出。
- **M4 · 非连续日期被标成区间**
  - "10月18日 至 10月23日（共 3 天）"实际是 18、22、23 三个不连续日，"至"字误导成连续段。建议：非连续时改为"18、22、23（共3天）"。
- **M5 · 两个"全部同意"口径不同、名字几乎一样**
  - 卡内"同意全部"（这一单的所有天）vs 顶部"一键全部同意"（所有单）。易点错。建议：卡内改"同意整单"。
- **M6 · 待办的完成入口是个像单选框的空心圆**
  - `22-17-todo-tab.png` 里待办只有一枚圆圈，没有"完成/去处理"字样，看不出可点。建议：加文字标签或 hover 提示。
- **M7 · 历史卡丢了关键信息**
  - 已批准的"免交"只显示"免交"+ 单个日期，事由被截断（丢了"外部项目连日；"），批准了几天看不出来。建议：保留"共 N 天/日期列表"。
- **M8 · 撤回窗口 5 秒且会堆叠**
  - 多条待撤回会各占一行把列表往下顶；5 秒一到没有别的反悔入口。建议：合并为一条"已处理 N 项 · 全部撤回"，或窗口内可续。

### Low（打磨）

- **L1** 新建项一律"申请于 0 小时前"，应为"刚刚"（`02-01`）。
- **L2** 顶部撤回条与底部"已撤回…"提示会同时出现，反馈自相矛盾（`13-08`）。
- **L3** 底部快捷键图例（J/K/A/R/Z/1-3/Esc）本身是 `opacity-0 hover:opacity-100`，新用户根本发现不了有快捷键（`unified-command-hub.tsx:1009`）。
- **L4** 组员弹窗标题"通知与待办"，实际只有待办、没有通知，也看不到自己提交的申请进度（`30-member-hub.png`）。
- **L5** 申请人与分组同名时显示"测试组员 · 测试组员"，冗余（`06-02`）。

## 线程走查

**线程一 · 批准一条请假（含撤回）**：可完整走完。开弹窗→悬停卡→同意全部→顶部"已同意…撤回(5s)"→点撤回→卡片回来了（`06-after-undo`）。判定清晰、有反悔。约 4 次点击。**一处可让它更顺手**：把"同意全部"常显，省掉"先找按钮"的犹豫。

**线程二 · 驳回一条补交并填原因**：可走完。驳回→原因框（必填、0/1000 计数、"将通知成员"提示、未填时"确认驳回"置灰）→确认。反馈到位。**风险**：同一条又以待办形式出现（H1）。

**线程三 · 逐日批准 + 单日批注**：可走完。多日卡上对某一天点✓→卡片实时从"免交3天"变"免交2天"；点✎→就地批注框（⌘Enter 发送、"仅记录在该单日明细中"）→"确认同意并附批注"。体验是这版里最顺的。**风险**：✓✗✎ 三个图标约 12px 无文字（M 级误点）。

**线程四 · 历史与打回**：历史记录、审阅人、驳回原因都能回看；"打回待处理"可把已批项退回待审（`03-after-reopen` 后回到待处理）。**风险**：豁免打回零确认（M1）、审阅日期差一天（M2）。

## 场景电池

- **首次接触**：入口（铃铛+标题）自解释，能上手；但快捷键图例藏进 hover（L3）、卡片操作藏进 hover（H2），首次会漏。
- **中断恢复**：5 秒撤回、Esc/点遮罩/关闭都能退出（`21-after-esc`、backdrop 实测关闭）。关标签页中途撤回未真机验证。
- **走错回退**：切错筛选→点"全部"即回；进错历史→"返回待处理"。恢复成本低。
- **老用户**：计数实时更新、历史留痕，回来能看出变化。
- **纯键盘**：1/2/3 切视图、J/K 选卡、A/R 同意/驳回、Z 撤回、Esc 关闭均生效；但**这些能力对不读 hover 图例的人不可见**（L3）。
- **二次用户（组员）**：正确看到"通知与待办"、无审批/无历史入口，权限边界 OK。
- **破坏性动作**：驳回=必填原因（好）；一键全部同意/豁免打回=无确认（H5/M1，弱）。
- **大数据量**：未测（见覆盖度）。

## 网络 / 控制台

- 本地 localhost 全程：**0 个 4xx/5xx 接口错误、0 个控制台报错**（`manifest*.json`）。

- 冷启动出现过一次 Next 水合告警（`Date.now()`/`Math.random()`），热运行未复现，判为 dev 冷编译产物、非稳定缺陷。

## 值得保留的好设计

- 撤回是**非阻断顶部条** + 文案"已同意 X 的特殊豁免" + 倒计时 + 底部确认 toast，误操作可救。
- 驳回原因**必填、未填置灰、明示"将通知成员"**，防呆到位。
- 逐日批注**就地落到某一天**、⌘Enter、卡片实时重算天数，颗粒度和反馈都对。
- 权限边界干净：组员看不到审批与历史。
- 空态有引导文案（"当前筛选下无匹配记录 / 可切换筛选条件…"）。

## 优先建议（按影响排序）

1. **修 C1（触屏无法逐条处理）** —— 把卡片/逐日/补交操作在窄屏与触屏下常显。这是"手机上根本没法审批"的阻断级问题。工作量 M。
2. **修 H1（补交待办与审批卡假闭环）** —— 补交待办去掉"完成"圆圈、改"去处理"跳转，或勾完成时确认"这不等于批准"。工作量 S–M。
3. **统一 H3 计数口径 + 修 M2 时区** —— 顶部只留一个"待处理 N"；历史审阅时间按上海日展示。工作量 S。
4. **补 H5/M1 破坏性确认** —— 一键全部同意、豁免打回各加一次确认（或纳入撤回）。工作量 S。
5. **H4 移动端断行 + M3/M4 请假语义** —— 名字最小宽防竖排；半天/非连续日期的展示说清楚。工作量 S–M。
