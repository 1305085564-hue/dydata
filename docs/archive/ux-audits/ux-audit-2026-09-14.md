## 审计主线

1. 首次进入：理解页面、团队动态、母题和题库范围。
2. 发现与筛选：搜索、排序、时间、母题、更多筛选、清空/返回。
3. 判断与继续：打开详情、读 Hook/作品/在写状态、从详情继续写作或回到列表。
4. 开始创作：卡片/详情触发“去飞书创作”，验证复制提纲 → 标记在写 → 跳转的闭环；不实际向飞书提交内容。

## 发现记录

### F-01｜P1｜已在写的题目仍显示“去飞书创作”，没有“继续创作”语义

- 复现：在 `/topics` 以当前公司所有者登录态展开“动态”；打开“学会游资选股技巧，轻松抓龙头”详情。
- 当前页面证据：动态明确显示“阿禅 正在写《学会游资选股技巧，轻松抓龙头》 09-01”；对应卡片显示“1 人在写”；详情抽屉也显示“阿禅 正在写”，但卡片按钮仍是“去飞书创作此题”，抽屉底部仍是“去飞书创作”。
- 业务影响：用户已经有进行中的写作记录，却被告知要“去创作”，无法从题库判断这是恢复原任务还是重新开始；在选题撞车和继续创作的主路径上会造成重复创作/误操作担忧，削弱题库作为工作中枢的可信度。
- 建议：按当前用户是否已有进行中记录切换为“继续创作”；若多人同时在写，文案应同时说明“继续我的创作”与“查看正在写的人”，不要让同一按钮承担开始和恢复两种语义。
- 边界：本轮未点击飞书入口，未验证外部页面是否真的会新建或恢复；因此结论针对当前状态文案与继续路径可理解性，不臆测外部动作实现。

### F-02｜P2｜异步刷新期间旧列表仍与新筛选条件并存

- 复现：任意切换排序、时间范围或更多筛选；例如从“全部时间”切换到“近 7 天”，或从“最新”切换到“7天热度”。
- 当前页面证据：控件已显示新条件，同时页面出现“选题库加载中...”，旧的数量和旧卡片仍短暂保留；等待约 1–数秒后才稳定为目标结果（“近 7 天”最终为 3 条，“7天热度”首条为量比选题）。
- 业务影响：用户可能在加载窗口点击旧卡片、误读数量或以为筛选未生效；对“这个列表就是当前条件的结果”产生短暂不信任。
- 建议：刷新期间对旧列表加遮罩/禁用卡片点击，或先清空结果并只保留明确的加载骨架；条件标签、数量和结果应作为一个状态原子更新。

### F-03｜P3｜生产页面有重复 CSS preload 警告

- 复现：打开 `/topics`，在 DevTools Console 查看。
- 当前页面证据：5 条警告均指向 `/_next/static/immutable/chunks/0lhax8_svjqz_.css`，提示 preload 后未在 load 后数秒内使用；Network 采样请求均为 200。
- 业务影响：当前未观察到功能失败；它会增加首屏资源诊断噪音，并可能掩盖真正的资源加载问题。
- 建议：确认该 CSS 是否确实需要首屏 preload；若不是，移除或修正 preload 的 `as`/加载时机。作为性能卫生项处理，不阻断本轮业务验收。
