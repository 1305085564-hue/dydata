## 1. 交叉裁定：哪些结论站得住

第三轮把两份报告里**互相矛盾**和**只有一份抓到**的条目，逐条回代码与生产库复算。

| 断言 | 来源 | 裁定 |
|------|------|------|
| 5s 完播率显示 4773% 且被排到榜首 | 仅第二遍 | **成立（生产库实锤）**：`video_metrics_snapshots` 全表 1813 行中唯一一条 `completion_rate_5s = 4773`、`play_count = 14700`（2026-08-18 发布）；`formatPercent` 只做 `toFixed(1)`，无区间校验 |
| 提醒条「68」与明细相加「69」对不上 | 仅第二遍 | **成立（代码实锤）**：删稿/限流/投流/异常走 `else if` 互斥链，「腰斩」在链外单独 `if`，一条既限流又腰斩的稿子被算两次 |
| 抽屉初始焦点落在「移入回收站」 | 仅第二遍 | **成立（API 层面）**：Sheet 基于 Base UI Dialog，其默认落焦为「弹层内第一个可聚焦元素」，而破坏性按钮在 DOM 上先于正文 |
| 归因能力「已删」，文案仍卖「原因」 | 第一遍 | **方向需修正**：`/api/admin/content-attribution/[videoId]` 完整存在（`self/team/top/user` 四参照 + `computeAttribution`），`src/app/(app)/admin/content/` 对这两个模块**零引用**。不是「能力已删」，是「后端在、前端没接」——修复含义从「改文案或重做」变成「接一根线」 |
| 换列排序方向写死降序 | 仅第二遍 | **成立（代码实锤）**：`handleSort` 换列时 `setSortDir("desc")` |
| 两页「互动率」是两套算法，属缺陷 | 仅第二遍 | **误判**：这是 09-21 口径定稿——`互动率`（加总）与 `加权互动率`（成长页加权）本来就是两个指标，**禁止同名**。第二遍「统一成加权口径」的建议与定稿冲突，不采纳；但「用户会困惑」的观察成立，靠显示名与 tooltip 消歧 |
| 列表刷新失败静默 | 两遍 | **成立（代码实锤）**：`loadData` catch 里只留注释，页面继续显示上一次的数 |
| Hydration #418 深链偶发 | 第一遍 | **严重度上调**：第二遍在**不带参数的普通加载**上稳定复现 |

**第二遍独有、第一遍完全没抓到的命门**：4773%（数据可信）与 68/69（口径自洽）。这两条决定了「你早上第一眼看的数是不是真的」。
