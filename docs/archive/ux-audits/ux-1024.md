# 视频复盘全链路审计

审计时间：2026-10-24 至 2026-10-25，北京时间。对象：[线上视频复盘](https://dydata.cc/admin/content)。角色：负责人为主，补真实成员只读视角。负责人日常任务是查团队作品、发现问题、看证据、连续复盘；不假设用户懂统计或系统实现。

本轮审计和授权的功能修复已完成本地验证，尚未发布。发现的七类功能问题已形成修复；其中发布日期、评级筛选、特殊字符搜索仍需执行数据库迁移才能在线生效。手机布局、键盘预览和成员引导仍有残项，详见交接部分，不能称为全链路全部通过。

## 一、范围与证据边界

- 主路径：工作台 → 视频复盘 → 日期/成员/搜索/筛选 → 作品详情 → 截图证据 → 连续查看 → 返回；补归档列表、危险操作取消及成员越权拒绝。
- 浏览器：用户现有已登录 Chrome；主窗口实际操作。扩展标签读取连续两次超时后改为原生 Chrome 操作，没有用未登录页面替代。成员使用既有测试账号的独立无痕窗口，验后关闭，未修改账号。
- 线上负责发现和确认现状；本地 `localhost:3000` 负责应用修复复验。该本地站连接生产数据，只做读取。数据库回归单独在本地 `supabase_db_dydata` 容器事务内执行并回滚。
- 没有生产测试写入，没有提交归档、恢复、彻底删除或选题状态变更，没有通知员工；没有 push。
- 线上响应式基准使用设备工具 1440×900，并检查 1280、1024、768、375。本地修复截图为关闭设备工具后的正常浏览器窗口，不混作同视口的前后对照。
- 截图位于 [截图目录](ux-1024-视频复盘截图/)。图片已压到最大边 1440。截图是状态证据，键盘焦点和数据库结论同时以操作记录/查询结果为准。

## 三、问题与修复

### 高：影响数据判断或核心连续复盘

**F01 发布日分组与显示时间不一致。状态：本地应用修复＋数据库回归通过，线上待执行迁移。**

复现：负责人选10月15日，作品“3步选出横盘么股”在该日列表显示05:49；生产只读核对其时间是 `2026-10-15 21:49+00`，上海自然日应为10月16日05:49。在线分页函数用会话UTC日期截取，页面时间却按上海显示。2490条 active 作品中1362条储存时间存在UTC/上海归日差异；这是归日影响范围，不是对外部平台发布时间真实性的逐条核验。

处理：数据库日期筛选、默认最近一天、每日条数统一用上海自然日；本地筛选、异常计数、兼容加载器同步复用既有发布日期工具。不改原始时间、不改上传日或日报绑定键。证据：[01](ux-1024-视频复盘截图/01-线上旧页-1015.png)、SQL午夜15:59Z/16:00Z边界回归。根因：页面＋在线函数定义＋生产样本实测。

**F02 选“普”却出现“劣”。状态：数据库修复已回归，线上待执行。**

复现：10月15日 → 筛选 → 评级 → 普，共10条，4条显示劣：唐震4032播放、曾文聪3499播放两条、袁懿2592播放。在线函数仍用2000门槛，列表已用5000。处理：SQL统一小于5000判劣；回归覆盖0、1999、2000、4999、5000，保留5000以上分档规则。证据：[08](ux-1024-视频复盘截图/08-普筛选出现劣.png)。根因：真实筛选结果＋在线函数实测。

**F03 同一指标在列表和详情给出相反颜色。状态：经用户确认，本地修复并页面复验，线上未发布。**

复现：10月23日林继成作品，22.2%跳出率列表绿、详情红；39.6%的5秒完播在详情反而绿。详情原有阈值方向与现行列表相反。用户确认：详情沿用“优质绿／正常原色／预警红”，不足5000播放降灰。

处理：2秒跳出、5秒完播、整体完播、平均播放时长均读取现有双线标准；异常比率优先红色，0与缺值分开。综合评级四色和计算方式没有改。真实本地复验22.2%绿、39.6%原色，截图 [32](ux-1024-视频复盘截图/32-本地详情颜色统一.png)；旧状态见 [04](ux-1024-视频复盘截图/04-详情加载.png)。另以唐震4032播放作品实测四项降灰，见[34](ux-1024-视频复盘截图/34-本地低样本详情降灰.png)。5000上下界、缺值、脏值由定向测试覆盖，不用单测冒充全部页面证据。

**F04 列表第一条打开后变“7/10”。状态：本地修复并页面复验，线上未发布。**

复现：10月15日评级普，按默认播放量排序首条胡航15000，打开详情显示7/10；前后篇与眼前列表顺序不一致。原因是客户端单日默认播放量、接口仍默认发布时间。

处理：未指定排序的单日查询统一按播放量降序，保留多日和显式发布时间排序。实测同一首条已为1/10、上一条禁用，下一条为猎龙学神“如何区分新周期”。证据：[旧15](ux-1024-视频复盘截图/15-375详情.png)、[新24](ux-1024-视频复盘截图/24-本地首条序号修复.png)、[下一条31](ux-1024-视频复盘截图/31-本地连续查看第二条.png)。

**F05 百分号被当通配符，搜索范围放大。状态：数据库修复已回归，线上待执行。**

复现：生产只读调用同范围关键词 `%`，返回10条，逐条字面比对仅1条含百分号。截图 [09](ux-1024-视频复盘截图/09-百分号搜索.png)只证明输入状态，错误结论来自真实RPC结果对照。原因是SQL用LIKE而客户端用文字包含。

处理：服务端改成不区分大小写的字面包含，标题与文案范围不变。百分号、下划线、反斜杠分别有数据库断言；不改变用户输入为高级查询语法。

### 中：状态保持、兼容和操作效率

**F06 手动发布时间排序刷新后丢失。状态：本地修复并刷新复验，线上未发布。**

复现：单日点击发布时间降序，地址不保留sort；刷新后又回默认播放量。处理：所有手动排序显式写入地址，前进/后退恢复是否手动排序。已验证地址含 `sort=published_at&dir=desc` 且刷新仍为发布时间降序。[证据25](ux-1024-视频复盘截图/25-本地排序刷新保持.png)。

**F07 表格提示组件使用已失效接口。状态：本地兼容修复，类型检查通过。**

全仓类型检查实测11处 `TooltipTrigger asChild` 与已安装Base UI接口不兼容。改为当前render接口，保留原提示内容、数值与样式，没有修改共享组件。类型检查从退出2变为退出0；实际低样本提示的全部鼠标/键盘路径未逐个覆盖，不宣称提示交互全部验收。

## 五、逐线程结果

| 线程 | 起点到终点/成本 | 结果、犹豫和中断 |
|---|---|---|
| 1 团队巡检 | 工作台主导航→视频复盘1次，作品→详情再1次 | 可到达证据；“全部时间”含义需解释，颜色原先相反会误导。第一次和再次进入均可复用地址，没有计时，不编造熟练度提升 |
| 2 找人找日找问题 | 日历定位→成员搜索/选择→高级评级→结果 | 能缩小范围，但F01/F02/F05影响可信度；不能把筛完后的行数当当天总数。清除筛选/返回保留日期，排序刷新问题见F06 |
| 3 连续复盘 | 点作品→大图（2次），左右方向换图、Esc返回，详情上下篇 | 可看原图；旧顺序错位F04已修本地。大图键盘焦点仍有U02，不标完整键盘通过 |
| 4 处理与恢复 | 全部/归档切换1次；详情→移入确认再1次 | 归档56条可读；移入提示作品隐藏和关联绩效日报作废；取消与换篇丢弃旧确认已实测。最终写入未执行，恢复/销毁未验收，线程只读部分完成 |
| 5 成员查看 | 既有成员登录→视频复盘→同公司他人作品详情 | 实测成员可公司内读，未见归档/移入/恢复/销毁管理按钮。引导与可用能力不一致U04；跨公司未验证 |

两分钟使用说明（审计理解结果，不是新增产品文案）：负责人从工作台进视频复盘，先确定日期，再按成员或评级缩小范围；打开作品对照指标和截图，用上下篇继续，关闭回同一列表。处理前看清回收站对日报的影响，有疑问取消。成员只负责查看同公司作品与证据，无需寻找归档或选题写入口。以上说明仍需明确“最近一天”和筛选命中数，不能掩盖待决策项。
