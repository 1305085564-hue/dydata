**Persona**：公司内负责日常内容审核与数据维护的管理员；中等技术熟练度、时间紧，需要快速定位异常作品、看证据并完成后续处理。

## Summary

本轮结论：内容管理的核心浏览、搜索、筛选、排序、分页、详情和证据查看链路可走通，但当前不适合作为“直接据此做业务判断”的安全审阅工具。共确认 1 个 Critical、3 个 High、3 个 Medium 问题；最严重的是详情把明显不可能的比例继续渲染成正常评级和达成率。

主任务能完成，但会在三个地方失真：异常入口打开后状态可能变成“正常”；375px 下作品行不可读；键盘用户无法进入作品详情。归档详情中的“恢复作品/永久删除”已看到，但未执行写入动作；受限角色未取得，均不冒充通过。

## Findings

### Critical

- **作品详情仍把不可能的比例当成正常大盘展示**：作品《3.19盘前》（播放量 2）在详情首屏显示转粉率 `5450.0%`、互动率 `31250.0%`、点赞率 `20700.0%`，并进一步显示 `优545000% / 优976563% / 优1035000%` 的达成率。列表对其中一个 `31250.0%` 有“上游数据异常”的标题提示，但详情核心卡片没有同等醒目的异常标识，且综合评级仍可被正常阅读为业务结论。管理者会把脏数据当成有效证据，无法安全判断内容表现。
  - *位置*：作品诊断抽屉 → “爆款数据核心大盘”和三项达成率。
  - *复现*：列表找到《3.19盘前》→打开详情；视频 ID `95ff6090`，播放量 `2`。
  - *证据*：S06（详情首屏直接显示上述越界比例）。
  - *建议*：详情与列表共用同一套比率边界校验；越界值显示“数据异常/不参与评级”而不是直接给出达成率和“优”；综合评级在关键输入无效时应降为“数据异常/待核”，并说明需要重新抓取或人工核对。

### High

- **“去盘”打开的作品状态与列表状态不一致**：从基线点击“去盘 →”，抽屉打开《内外盘的重要性，你现在知道了吗》，抽屉头部显示“正常”；关闭抽屉后用标题搜索同一作品，列表状态显示“腰斩”。用户无法判断到底是需要处理的异常，还是普通作品，入口的优先级信号因此失真。
  - *位置*：顶部“去盘 →”入口、列表状态徽标、作品诊断抽屉。
  - *复现*：重置筛选 → 点击“去盘 →” → 记下视频 ID `ee56127e` 与标题 → 关闭抽屉 → 搜索标题。
  - *证据*：S04（抽屉显示“正常”）；同一视频列表文本为“腰斩 … 内外盘的重要性，你现在知道了吗”。
  - *建议*：详情抽屉与列表共用同一状态映射，并把“为什么被去盘选中”的异常原因写在抽屉首屏；若“腰斩”是入口依据，抽屉不能显示“正常”。

- **375px 移动端列表不可读**：表格宽度仍为约 `686px`，在 `332px` 可视容器中横向截断；“视频标题 / 账号”表头被压成竖排，标题、负责人和指标在行内互相挤压，底部固定导航还覆盖列表内容。页面虽然没有整体横向滚动，但用户必须猜测横向滚动才能看到剩余指标，且关键标题不可连续阅读。
  - *位置*：375×812 内容管理列表。
  - *证据*：S07（移动端首屏）；实测表格 `686px`、可视容器 `332px`，页面只有内部横向滚动。
  - *建议*：移动端改为卡片/两层信息结构，至少固定状态+标题两列；扩大触控目标（当前多个工具按钮高度 23–28px），避免底部导航覆盖正在查看的行。

- **键盘无法进入作品行，主任务不能键盘完成**：从筛选按钮继续按 Tab，只会依次进入搜索框、10 个排序按钮、页大小和页码；表格行没有焦点入口，也没有跳过导航的 Skip link。键盘用户无法打开任意作品详情，只能停留在列表控制层。
  - *位置*：内容管理列表全页。
  - *复现*：刷新页面 → 只按 Tab → 经过“筛选/搜索/列排序/分页”后观察，没有任何作品行获得焦点。
  - *证据*：S08（键盘路径记录）；首批作品行均无 `tabindex`/`role`，焦点序列未出现作品标题。
  - *建议*：把作品行或标题做成可聚焦、可 Enter 打开的控件；补 Skip link、`aria-current` 和详情抽屉内的焦点回收路径。

### Medium

- **排序方向只靠视觉箭头，未提供 `aria-sort`**：当前表头按钮显示 `↕/▲`，但表头和按钮都没有 `aria-sort` 或等价的可访问状态；键盘/读屏用户不知道当前按哪一列、升序还是降序。
  - *位置*：列表表头 10 个排序按钮。
  - *建议*：当前排序列标注 `aria-sort="ascending|descending"`，按钮名称包含“按播放量升序排序”等可理解状态。

- **“复制文案”点击后没有可见成功反馈**：详情抽屉中的“复制文案”按钮可点击，但点击后没有 Toast/提示；Codex 内置浏览器的剪贴板读取为空，无法证明复制成功。即使浏览器最终复制成功，用户也没有“已复制”的确认信号。
  - *位置*：作品诊断抽屉 → 视频文案内容库。
  - *边界*：当前 IAB 会话中 `navigator.clipboard` 不可用，故不能单凭这一次把“复制失败”定为业务根因；但页面没有可见的成功/失败反馈仍是体验风险。
  - *建议*：复制成功与失败都显示短暂、可读的反馈；剪贴板 API 不可用时给出可执行的降级提示。

- **账号下拉存在同名选项，且没有搜索或唯一标识**：账号菜单需要在较长名单中人工扫描；本轮看到“罗礼杰”“小芸姐”等同名选项。用户不能确认选择的是哪一个账号，筛选结果也难以复核。
  - *位置*：人员筛选 → 账号下拉。
  - *建议*：账号选项增加头像/账号 ID/团队等可辨识信息，并支持名称搜索；同名时必须显示区分字段。

## Thread Results

### 线程 1：发现异常 → 定位优先级作品

- **目标**：管理员从全量内容中找到需要优先处理的作品。
- **实测路径**：进入页面 → 查看异常数量 → 点击“去盘” → 打开详情 → 返回列表 → 用标题搜索核对。
- **结果**：列表、异常入口、搜索和详情均能打开；但“去盘”作品的详情状态与列表状态冲突，主任务的判断环节不能安全闭环（High）。
- **主要决策点**：全部/归档/异常、完整/宽松、时间、人员、筛选、10 列排序、去盘入口。

### 线程 2：详情诊断 → 查看证据 → 复制文案

- **目标**：管理员判断内容问题、查看截图证据并带走文案。
- **实测路径**：搜索作品 → 打开详情抽屉 → 查看核心数据 → 切换单图/双图 → 全屏查看截图 → 尝试复制文案 → 关闭抽屉。
- **结果**：证据图可切换、可放大；但《3.19盘前》的不可能比例仍被当成评级依据展示（Critical），复制动作缺少可见反馈（Medium/环境耦合待复核）。

### 线程 3：归档 → 查看归档作品 → 后续处理

- **目标**：管理员查看已归档内容，并决定恢复或永久删除。
- **实测路径**：进入“归档” → 查看 16 条记录 → 打开归档详情 → 观察“恢复作品/永久删除”。
- **结果**：归档列表和详情可达；写入型按钮已确认存在，但本轮没有执行恢复或永久删除，因为这会改变真实数据，必须另行明确授权（BLOCKED）。

## Verified Not Findings

- 自定义日期不是本轮产品问题：使用 Codex IAB 的原生日期字段（开始 `2026-10-01`、结束 `2026-10-09`）后，URL 写入 `startDate/endDate`，结果为 121 条。
- 分页“下一页”可用：页面滚动到分页区域后用真实指针点击，能从 1-20 进入 21-40；此前的定位失败是浏览器自动化定位问题，不列为产品缺陷。
- 快捷时间范围、人员/账号、主题状态、播放量区间、质量等级、排序和页大小均能改变 URL 与列表结果；本轮未发现静默回到全量的同类问题。
- 搜索特殊字符（包括 `O'Brien café <script>`）未见页面执行或结构破坏；空结果有明确提示。

- 通过 Codex 内置浏览器 CDP 扫描本轮 123 个事件：未发现非 2xx/3xx 请求、`loadingFailed`、Runtime exception 或 Console error。

## Priority Recommendations

1. **P0 / Critical**：在详情层阻断越界比例进入评级和达成率，统一列表/详情异常标识，并显示“数据异常/待核”原因。
2. **P1 / High**：统一“去盘”入口、列表徽标和详情状态映射，首屏说明被选中的异常原因。
3. **P1 / High**：移动端改为可读的卡片或两层结构；同时让作品标题/行成为可聚焦、可 Enter 打开的控件，补 Skip link 和焦点回收。
4. **P2 / Medium**：补 `aria-sort`、账号唯一标识/搜索和复制成功/失败反馈；复制能力需在产品支持的真实浏览器再做一次确认。

## Fix-and-Verify

本轮按“只审计、不施工”收口，未修改业务代码，也未执行恢复/永久删除。若进入修复轮，建议按 P0 → P1 → P2 顺序，每项都用同一条真实页面链路复验，并保留本报告中的 S06/S04/S07/S08 对照证据；第二角色和破坏性动作仍需单独授权与账号条件。
