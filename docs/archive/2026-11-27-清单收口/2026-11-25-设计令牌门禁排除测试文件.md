# 设计令牌门禁排除测试文件

> 可直接派单。范围：一个门禁脚本 + 一处测试写法。不涉及页面、接口、数据、线上行为。

## 一、给阿禅看

- **诉求**：让设计规范门禁只检查"真正会上线的前端代码"，不再因为测试文件里提到被禁的样式名就报违规。
- **现在的问题**：门禁是靠文本搜索扫 `src/` 全目录的，测试文件也在 `src/` 里。今天为了通过一条"断言不该出现小圆角"的测试，施工方只能把 `rounded-lg` 拆成几段字符串拼起来躲开扫描（提交 `a4c32a28`）。这属于让检查看不见，不是问题不存在——后面每个写测试的人都会撞上，迟早有人干脆把规则注释掉。
- **完成定义**：门禁照样拦得住源码里的违规（用反证实验证明），同时测试文件里可以正常写样式名字面量；那处字符串拼接改回正常写法。
- **要你拍板**：无，可直接开工（不改判定口径、不动基线、不影响页面）。

## 二、现状事实（施工依据，已核）

`scripts/design-token-gate.mjs` 共 8 条规则，全部用 `rg` 扫 `src/` 文本：

| 规则 id | 是否排除测试文件 |
|---|---|
| font-size | 否（只排 `app/page.tsx`） |
| ink | 否 |
| gap-half | 否 |
| font-weight | 否（只排 `opengraph-image.tsx`） |
| serif-floor | 否 |
| rounded | 否 |
| shadow | 否 |
| 调色板（`checkPalette`，第 120 行） | **是**，已带 `-g "!**/*.test.*"` |

结论：8 条里只有调色板排了测试文件。所以色值写进测试不报错，圆角、阴影、墨度、字号、间距写进测试就报违规。判定函数多为 `violation: () => true`（命中即算违规），走基线棘轮。

基线 `scripts/design-token-baseline.json` 内无任何 `*.test.*` 条目（已核），因此加排除不会让现有基线项失效，也不会触发"基线只降不升"的争议。

## 三、要改什么

1. 给上表 7 条文本规则统一补 `-g "!**/*.test.*"`，位置与调色板规则一致（放在 `"src/"` 之后）。建议顺手把这条排除抽成一个常量（如 `TEST_EXCLUDE = ["-g", "!**/*.test.*"]`）拼进每条规则的 `args`，避免以后再漏。
2. 把 `src/components/screenshot/screenshot-placeholder.test.tsx` 里的写法还原成正常字面量：
   - 现在：`new RegExp("rounded-(?:l" + "g|m" + "d)")`
   - 改成：`/rounded-(?:lg|md)/`
3. 脚本顶部注释补一句口径：门禁对象是会被打包进前端的代码，测试文件不参与构建，故排除；新增规则默认带这条排除。

## 四、不要动

- 不改任何规则的判定口径、档位、合规白名单，不新增/删除规则。
- 不动基线数字，**不跑** `--update-baseline`。
- 不放宽成目录级排除（`!**/test/**`、`!**/__tests__/**` 之类），只排 `*.test.*`，避免顺手排掉真实页面目录。将来引入 `*.spec.*` 时再补一条。
- 不碰 `src/` 下的业务代码与页面。

## 五、验收清单

- [ ] 反证 B：把同一处违规改写进某个 `*.test.tsx`，`npm run gate:design` 必须绿灯。

- [ ] `npm run gate:design` 绿灯；`git status` 中 `scripts/design-token-baseline.json` 未出现改动。

- [ ] `npm run doc:links`、`npm run doc:size` 仍绿（本单文档会被这两项扫到）。

## 六、风险与回退

- 风险：排除后，若有人把"应该上线的组件"错放进 `*.test.tsx`，其设计违规不再被拦。本项目无此用法，影响面仅限测试文件，可接受。
- 回退：删掉 7 处 `-g` 参数即恢复原状；不涉及数据、配置与线上。
