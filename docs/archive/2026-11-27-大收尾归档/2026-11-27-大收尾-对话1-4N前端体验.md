## 三、分关卡施工规格

### 关卡 1（C6-9）：视频复盘右侧不遮挡抽屉 + 跨行无缝切换
1. **现状核查**：先读 `src/app/(app)/admin/content/content-detail-dialog.tsx`、`content-page-client.tsx`、`content-list-table.tsx`、`content-video-navigation.ts` 与 `src/components/ui/sheet.tsx`。
2. **核心改造**：
   - 将桌面端居中遮罩详情弹窗改为**右侧非模态抽屉**（符合 `美学宝典.md` §3.3 规格，不引入「弹窗/抽屉模式切换开关」）。
   - 抽屉展开时：无阻挡点击的全屏遮罩，左侧表格不发生宽度挤压跳动；当前选中行在表格中有清晰持久高亮态。
   - 抽屉打开期间，直接点击左侧表格任意其他行，抽屉保持展开状态、原地切换加载该作品详情（无需关闭重开）；保留抽屉顶部「上一条 / 下一条」、键盘上下切换与全屏放大看图能力。
   - 抽屉滚轮隔离：滚动抽屉内容不连带滚动主表；按 `Esc` 或点关闭按钮关闭抽屉，关闭后焦点体验自然。
   - 手机端（375px 视口）：保持合理全宽抽屉/弹层可读可用，不裁切、不溢出。
   - 旧行为保持：详情内仍以两张原截图为主（无图/失败兜底展开 12 项明细）、第 4 格按话题切换收藏率/点赞率、换截图/回收站/作者档案往返、URL 深链 `?videoId=` 全部保持。
3. **测试与提交**：补充/更新组件单测，跑 `npm run gate:static` 全绿后本地 commit：`feat(content): 视频复盘改为右侧不遮挡抽屉并支持跨行无缝切换`。

### 关卡 2（C9）：视频复盘桌面翻页器移底栏 + 筛选命中数展示
1. **现状核查**：读 `date-pagination.tsx`、`content-list.tsx`、`content-page-client.tsx` 及 `src/app/api/admin/content/list/route.ts` / `src/lib/loaders/admin-content-page.ts`，核实当前多日跨页筛选是否已返回真实总基数（未筛选总数）与真实命中数。
2. **核心改造**：
   - **桌面端（≥1024px）**：将日期翻页器从顶部整行移至列表底栏，释放顶部一行垂直空间：
     - 单日模式：左「共 Y 条」（有筛选时「命中 X / 共 Y 条」）、右「◀ 日期 ▶」；点击日期打开的日历弹层改为**向上展开**（避免被屏幕底边裁切）。
     - 多日模式：左「共 Y 条」（有筛选时「命中 X / 共 Y 条」）、中间区间平移控件、右侧页码控件。
   - **手机端（<768px）**：日期翻页器留在顶部原位不动（2026-10-23 阿禅拍板铁律）。
   - **数据口径**：前后端对账——若多日筛选下接口未返回未筛选总基数，则在列表接口规范补充该只读统计字段，确保单日/多日筛选均准确显示「命中 X / 共 Y 条」，严禁拿当前页条数冒充总数。
3. **测试与提交**：补齐 `date-pagination.test.tsx` 与列表计数测试，跑 `npm run gate:static` 全绿后本地 commit：`feat(content): 桌面端日期翻页器移至底栏并展示筛选命中数与总基数`。

### 关卡 3（D3）：设计令牌基线消化（白名单范围）+ 多行 Input 检查范围复核
1. **白名单消化**：对照 `scripts/design-token-baseline.json`，**仅清理白名单内文件**（`admin/content/*`、`admin/collaboration/*`、`people/*`、`privacy/*`、`terms/*`、`components/screenshot/*`、`components/rating-rules/*`、`components/modules/*`、`design-system-README.md`）中的违规项（`font-size`、`gap-half`、`font-weight`、`rounded` 等），按 `美学宝典.md` 标准令牌替换，并同步下调 `scripts/design-token-baseline.json` 中对应文件的基线数（绝对不动对话 2 归属文件的条目！）。
2. **规则复核**：阅读 `scripts/design-token-gate.mjs`，核实多行 JSX 的业务层 `<Input ... className=...>` 覆盖是否已有检查或存在漏检；产出核查结论写入本分支交付说明（若确认无漏检则不改脚本；若发现明确漏检且零误报、不引入新基线膨胀则可补测试修复，否则记清结论供架构师拍板）。
3. **测试与提交**：确认 `npm run gate:design` 与 `npm run gate:static` 全绿且基线净下降，本地 commit：`chore(design): 消化白名单文件设计令牌存量并下调基线`。
