## 一、要解决什么

复盘抽屉「爆款数据核心大盘」现在只有三个独立的达成率标签（互动率 / 第四格 / 转粉率各说各话），没有「这条作品整体算几档」的结论。本方案新增一个 **综合 X（优/良/普/劣）** 徽章，**一个作品一个总评**，与三个标签并存：标签解释「每项达到多少」，总评回答「整体几档」。

## 二、评级口径（原 3.2 正文，逐字保留）

复盘抽屉「爆款数据核心大盘」标题旁新增一个 **综合 X（优/良/普/劣）** 总评徽章——**一个作品一个总评**。这是阿禅定的团队 KPI 评价标准接入线上的结果，与 3.1 的三个独立达成率标签并存：三个标签解释「每项各达到多少」，综合评级给出「这条作品整体算几档」。

计算口径（`overallBreakoutGrade()`）：

1. **流量是硬门槛**：`播放 < 5,000` → 直接判**劣**，不看指标。
2. **指标用短板原则**：`播放 ≥ 5,000` 时，取「互动率 / 第四格 / 转粉率」三项各自评级（复用 3.1 的达成率档位）里**最低的一档**——全部达成才算达标，一良则良、一劣则劣。
3. **优需要流量达标**：仅当 `播放 ≥ 12,000` 且三项全达优线才评**优**；`5,000–12,000` 区间即使三项全优也封顶**良**。
4. **缺数据不臆造**：播放未采集，或播放已过门槛但任一指标缺值无法评级 → 综合评级为空（不显示徽章），下方「话题未识别，暂不评级」文案照旧。

流量门槛常量：`KPI_PLAY_FLOOR = 5000`、`KPI_PLAY_EXCELLENT = 12000`。第四格仍按话题取收藏率/点赞率。

## 四、验收

- 静态：定向单测覆盖上面四组边界；`npx tsc --noEmit` 与 `npm run lint` 零 error。
- 真实浏览器：`npm run gate:roles` 里补一条——同一条作品在复盘抽屉看到徽章，缺指标的作品**不出现**徽章（不是显示「劣」）。
- 数字对账：抽 3 条线上作品，手算档位与徽章一致；与 3.1 三个标签并存不冲突。

## 五、待阿禅确认的关键点

1. **5,000 播放直接判「劣」会不会太狠**：按当前口径，播放 4,900 但三项指标全优的作品会被判劣，而三个标签全是「优」——同一张卡片上会出现「三个优 + 综合劣」。要不要给这种「流量不达标但质量优」单独一档（例如「优·未起量」）。
2. **转粉率缺值比例高**：缺值即不评级（徽章消失）。若线上多数作品缺转粉率，徽章会出现大面积不显示，先只读统计再决定要不要降权。
3. **是否影响岗位管理的「爆款数」**：不影响。第 11 节的爆款门槛与本评级是两套，不合并、不互相引用。
