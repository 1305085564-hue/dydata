## 二、问题清单

### P0

#### P0-1 矩阵格内数字使用 10px，突破全站字号底线

- **位置**：`src/app/(app)/admin/fulfillment/components/monthly-matrix.tsx:417`  
  （`mx-auto flex h-5 min-w-5 items-center justify-center rounded-[4px] border px-0.5 text-[10px] font-medium tabular-nums`）
- **当前表现**：格子从 17px 方块（`size-[17px]`）改为 20px 方块并塞入发布条数，数字字号 10px、字重 500。
- **违反规范**：
  - 设计规范 §2.3「常规正文字号不得小于 13px；`11px~12px` 仅限用于微印章与辅助元数据」——10px 低于豁免下限；
  - 设计规范 §2.2 字阶表无 10px 档位；
  - 设计规范 §7.2「正文字号小于 13px」属字体禁区；
  - 直接违背 Codex 自述文档 `三大管理模块职责收敛设计.md` 中「正文不小于 13px」的验收条款。
- **实际影响**：这是全站最小字号，且承载的是**核心数据值**（当日发布条数）。在 Windows 低密度屏（DPR<1.5）上中文混排的数字会发虚糊化，而履约页恰恰是管理员每天长时间扫读 31 列的界面。21 个成员 × 31 天 = 651 个 10px 数字，视觉噪音极大。
- **建议**：**重新设计**——不要靠缩小字号换取密度。推荐两条路：
  1. 保留色块语义，数字只在 hover/抽屉中呈现（保持 17px 方块的清爽扫读）；
  2. 若必须常显数字，格子需放大到 24px 以上、数字不低于 12px，并接受横向滚动增加。
- **浏览器验证**：未完成（见第五节）。

#### P0-2 待审批琥珀描边过重，黄标反客为主

- **位置**：`monthly-matrix.tsx:101`（`bg-[#B98A54]/20 border-[#B98A54]/60 text-[#8A6A2F]`）、同文件 `:484`（图例色块同款）
- **当前表现**：待审批格 = 20% 琥珀底 + **60% 琥珀描边** + 深色琥珀字；而同期其他状态的描边只有 `/20`~`/40`（已发布 `/40`、请假 `/35`、缺勤 `/35`、待确认 `/80` 但为中性砂色）。
- **违反规范**：
  - §6.3 状态色降饱和：警示/待处理应为 `text-[#B98A54]` + `bg-[#B98A54]/10`；
  - §1.2 单点聚光灯：「同一视野内绝不允许出现两个以上饱和色焦点」；
  - §1.2 视觉杠杆不叠加原则：「单个元素禁止同时叠加：超大字号 + 重字重 + 鲜艳色 + 有色背景」；
  - §7.1「把暖橙散布到所有次级按钮」同理适用于把警示色做重。
- **实际影响**：待审批是**新增**状态，却被做成了矩阵里描边最重的一种。一行里只要有 2–3 个待审批格，视觉重心就从"谁没发"漂移到了"谁在请假"，而后者是次要信息。若该日同时有申诉，还会叠加 `:426` 的 `ring-1.5 ring-[#D99E55]`，形成「描边 + 外环」双重强调，属于典型的视觉杠杆叠加。
- **建议**：**调整视觉**——底色降到 `bg-[#B98A54]/10`、描边降到 `border-[#B98A54]/30`、文字回到 token 内的 `text-[#B98A54]`；与已有 `ring-[#D99E55]` 申诉环二选一，不要同时出现。功能（待审批进月历）必须保留。
- **浏览器验证**：未完成。
