### 1. 数据库定义与权限收口（修正 3、修正 5、修正 6）

#### 迁移脚本：`supabase/migrations/20261107140000_ocr_recognition_logs.sql`
```sql
-- 1. 创建测速台账表
create table if not exists public.ocr_recognition_logs (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz not null default now(),
  duration_ms integer not null,           -- 接口完整总耗时（毫秒）
  ocr_ms integer,                         -- AI 模型看图/提字识别耗时（毫秒，含百度提字映射）
  download_ms integer,                    -- 截图存储读取耗时（毫秒）
  channel_name text,                      -- 真实渠道名（可空，超时/全挂时为空，如 "api9 claude (max)"）
  model_id text,                          -- 真实模型名（可空）
  screenshot_type text,                   -- "data" | "retention"
  is_success boolean not null default true, -- 直接复用 businessSucceeded
  error_code text,                        -- 失败错误码（如 AI_TIMEOUT）
  user_id uuid                            -- 操作员工 ID
);

-- 2. 索引：查询最近 1000 条与清理 90 天
create index if not exists idx_ocr_recognition_logs_created_at
  on public.ocr_recognition_logs (created_at desc);

-- 3. 开启行级安全 RLS，不配置前台策略（浏览器端密钥不可读写）
alter table public.ocr_recognition_logs enable row level security;
revoke all on public.ocr_recognition_logs from anon, authenticated;
grant select, insert, update, delete on public.ocr_recognition_logs to service_role;

-- 4. 90 天自动清理函数（供每天北京时间 02:00 定时任务调用）
create or replace function public.cleanup_ocr_recognition_logs()
returns integer
language plpgsql
security definer
as $$
declare
  deleted_count integer;
begin
  delete from public.ocr_recognition_logs
  where created_at < now() - interval '90 days';
  get diagnostics deleted_count = row_count;
  return deleted_count;
end;
$$;

revoke all on function public.cleanup_ocr_recognition_logs() from public, anon, authenticated;
grant execute on function public.cleanup_ocr_recognition_logs() to service_role;
```

### 2. 真实渠道名透传与 await 写入（修正 2、修正 4、修正 6、修正 7）

#### 改动文件：`src/app/api/ocr-screenshot/route.ts` 与 `src/app/api/ocr-screenshot/baidu-channel.ts`
1. **透传真实渠道名**：
   - `runVisionOcrAttempt`：`aiResult = await callAi(...)` 中包含 `aiResult.channelName`（如 `"api9 claude (max)"`）与 `aiResult.model`。透传至返回对象 `{ parsed, channelName: aiResult.channelName, model: aiResult.model }`。
   - `baidu-channel.ts`：`callStructureModelViaAi` 同理透传 `aiResult.channelName`。
   - `logContext.aiChannel` 取真实渠道名。
2. **耗时映射**：
   - 百度渠道的纯识别耗时为 `timings.baidu_ms`，写入时统一存入 `ocr_ms: timings.ocr_ms ?? timings.baidu_ms ?? null`。
3. **写入机制（等完再返回，无裸异步）**：
   - 在 `finish()` 中使用 `createAdminClient`（service_role）直接 `await` 插入：
     ```ts
     const logEntry = {
       duration_ms: timings.total_ms ?? (Date.now() - startTime),
       ocr_ms: timings.ocr_ms ?? timings.baidu_ms ?? null,
       download_ms: timings.download_ms ?? null,
       channel_name: logContext.aiChannel ?? null,
       model_id: logContext.aiModel ?? null,
       screenshot_type: logContext.screenshotType ?? null,
       is_success: businessSucceeded, // 修正7：严格复用现成判定（recognized_failed 算失败）
       error_code: errorCode ?? null,
       user_id: userId ?? null,
     };
     try {
       const adminSupabase = createAdminClient();
       await adminSupabase.from("ocr_recognition_logs").insert(logEntry);
     } catch {
       // 异常彻底吞并，零影响员工填报回执
     }
     ```

## 二、验收标准（严格核对）

1. **真实渠道名核验**：实测一条真实识别调用后，台账中 `channel_name` 准确显示真实配置渠道名称（如 `api9 claude (max)`），不再出现 "vision/baidu" 泛称；
2. **RLS 行级安全核验**：使用浏览器端匿名公钥（anon key）直接 SELECT `ocr_recognition_logs`，必须被数据库 RLS 拒绝访问；
3. **异常零阻断核验**：人为模拟插入失败场景，截图识别主流程依然返回 HTTP 200 与完整识别结果，员工页面不受影响；
4. **口径统一核验**：抽屉顶部五项摘要指标全部清晰标注"最近 1000 次"口径，出参字段名完全对齐契约。
