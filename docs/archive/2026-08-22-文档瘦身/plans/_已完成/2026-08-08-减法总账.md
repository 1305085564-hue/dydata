## 一、减法总纲

### 两层减法，分开做

这次减法是两件事，判断标准完全不同，混着做会被淹没：

- **代码垃圾层**：用户根本看不见，AI 早年堆的死代码。不需要产品判断，列清单→核实→清掉。**本轮已完成，见第三节。**
- **用户心智层**：用户能看见、能点的功能。"有人用"不等于"该留"，需要阿禅逐项拍板。**待施工，见第四节。**

### 三分类标准

- **A 保留强化**：核心命脉或战略功能，不但留，还要投入打磨。
- **B 默认保留**：有用但非核心，留着，除非明确无价值。
- **C 默认删/降级**：低频或零转化，默认砍，除非有说不出口的刚需。

### 数据的边界

埋点只记"页面被看了多少次"，记不到页面内每个按钮。所以页面级有硬数据，页面里的功能点靠产品判断。选题库路径未纳入埋点范围，零数据 ≠ 没人用。

## 四、用户心智层 · 待施工清单

### 1. 避坑案例降级为只读案例库（阿禅已拍板，可出规格）

定位从"话术协作平台"降为"只读案例库"：能查阅旧案例，不再往里加新料。分前后端两份活。

**保留（强化查阅体验）**
- 案例列表 + 行（case-list / case-row）、案例详情（detail-container）
- 高转化 / 高风险话术排行榜（rank-board 两块）
- 筛选栏、图片灯箱、j/k 快捷键翻案例、Hero 团队指标条、统计卡

**砍掉（整条上传/审核链路）**
- 员工端："上传新话术"入口 + 整个上传话术页（/violations/submit + step-wizard 全套）
- 管理端："审核工作台"入口 + 三桶审核台（task-inbox-v2：批量通过/驳回、驳回弹窗、5 秒撤销）
- 详情页："审核决策面板"（review-decision-panel：采纳/驳回/风险等级/踩雷点标签）
- "代上传话术"按钮

**灰色地带（待阿禅拍板，见第五节）**
- 详情页"记录使用效果"（test-record-form）：算"往库里加料"该砍，还是算"只读库的用法沉淀"该留

**后端配合（Codex）**
- 停用/下线上传与审核接口：/api/violations（POST 提交）、/api/violations/upload、/api/violations/[id]/review、/api/violations/batch-review
- 保留只读接口：/api/violations（GET 列表）、/api/violations/[id]、/api/violations/screenshot/[...path]、/api/violations/review/restore（若涉及只读恢复则评估）

**分工**：Codex 管后端拆接口 + 逻辑；Antigravity 管前端删 UI（**必须先给阿禅确认再 push**）。

### 2. AI 文案改写埋点 bug（可先修，不影响功能）

`rewrite_generate` 事件有调用点（useRewriteV3Logic.ts:596）但 4 周内 0 次触发。功能有人用（7 人进入），说明埋点埋在了错误位置——大概率没挂到"生成成功"的路径上。

**要做**：排查 trackUsageEvent 是否真的在生成成功后被触发，修正埋点位置。否则这页永远显示"没人用"，以后再做数据减法会被误导。属诊断+小修，交 Codex 或 Luna。

### 3. 复盘台批改/反馈链路（待阿禅拍板拆不拆，见第五节）

视频复盘页本身高频（145 次），保留。但阿禅反馈其内部"批改→反馈卡下发→员工读"链路没人用。埋点测不到页面内动作，需阿禅从实际使用确认。若拆，涉及反馈卡编辑、批量生成反馈草稿、下发通知等模块，待定后再出规格。

### 4. 内容工具台（待阿禅拍板砍不砍，见第五节）

独立员工页（/content-tools），三个 tab：选题建议 / 模板库 / 发布时间，全是 AI 辅助生成类。近 4 周仅 5 次访问 / 4 人。与"AI 文案改写"是两回事（一个给选题、一个改文案）。
