### 关于「type / action」

> 任务描述里提到 `type` 和 `action` 两个字段——**实际表里并不存在**这两个独立字段。表只有 `event_type`（事件类型）和 `path`（页面路径）两个业务维度。因此下文「功能」粒度 = **`event_type` + `path` 的组合**（等价于「type + action」的意图）。

### 埋点写入链路

1. 前端 `trackUsageEvent({ path, eventType })`（`client.ts`）→ 优先 `navigator.sendBeacon`，失败兜底 `fetch`。
2. POST `/api/usage-events`（`route.ts`）→ `parseUsageEventPayload` 校验（路径归一化 + 必须命中 `TRACKED_PAGE_PREFIXES` + `event_type` 必须在枚举内）→ `supabase.auth.getUser()` 取登录用户 → **未登录直接 202 跳过（不写）** → `insert({ user_id, path, event_type })`。
3. 受追踪路径前缀：`/dashboard`、`/growth`、`/violations`、`/content-tools`、`/admin`（`shared.ts` `TRACKED_PAGE_PREFIXES`）。

## 二、统计 SQL（标准原文）

```sql
-- ① 按 event_type + path 汇总最近 4 周热度
SELECT
    event_type,
    path,
    COUNT(*)              AS total_calls,
    COUNT(DISTINCT user_id) AS distinct_users,
    MAX(created_at)       AS last_used_at
FROM public.usage_events
WHERE created_at >= now() - interval '4 weeks'
GROUP BY event_type, path
ORDER BY total_calls ASC, event_type ASC, path ASC;

-- ② 找出「定义了但 4 周内 0 次」的 event_type（对照代码里的 9 个枚举）
SELECT v.event_type
FROM (VALUES
    ('page_view'),
    ('submit_daily_report'),
    ('apply_exemption'),
    ('submit_work_submission'),
    ('submit_review_draft'),
    ('submit_violation_case'),
    ('review_violation_case'),
    ('rewrite_generate'),
    ('mark_fulfillment_status')
) AS v(event_type)
LEFT JOIN (
    SELECT DISTINCT event_type
    FROM public.usage_events
    WHERE created_at >= now() - interval '4 weeks'
) recent USING (event_type)
WHERE recent.event_type IS NULL
ORDER BY v.event_type;
```

## 六、结论与减法建议（基于硬证据）

1. **可直接删的死配置**（3 个）：`apply_exemption`、`submit_work_submission`、`submit_review_draft`——代码里压根没调用点，枚举值可从 `USAGE_EVENT_TYPES` 与表 CHECK 约束里移除。
2. **有入口无转化的功能**（3 个，重点核查）：`rewrite_generate`、`submit_violation_case`、`review_violation_case`——埋点调用点存在但 4 周内 0 次触发。要么功能没人用（可砍），要么调用点埋错了位置/时机（需排查 `trackUsageEvent` 是否真的在成功路径上被触发）。
3. **个位数使用的页面**：`/video-review/*` 系列（已停止追踪的历史残留）、`/violations/[id]` 详情页、`/admin` 根页——访问量极低，可考虑合并或下线入口。
4. **真正高频在用的**：`/dashboard`（651 次）、`/growth`（206 次）、`submit_daily_report`（134 次）、`/admin/content`（145 次）、`/admin/fulfillment`（83 次）——这些是核心，不能动。
