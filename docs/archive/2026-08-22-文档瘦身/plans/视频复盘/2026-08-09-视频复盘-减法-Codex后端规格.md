# 视频复盘 减法 · Codex 后端规格（较难）

> 任务复杂度：**较难**（涉及双入口裁决、状态机隐藏、多处联动，误删会炸 build 或砍掉复测数据源）。
> 你只做逻辑 / 数据 / 链路裁决 + 一次性简陋前端走通。美学交给 Antigravity，你的简陋前端他会删掉重写，别在样式上花功夫。
> 背景见同目录《…-减法定稿》，产品内核见《2026-07-18-视频复盘重构-产品设计总纲》，字段契约见《2026-07-18-视频复盘重构-接口约定》。

## 0. 一句话目标

把视频复盘从「大宽表 + 站内下发」瘦成「诊断队列 + 归因舱 + 建议可复制」。**删重复、止损死功能、保住归因与复测两条命根子**，不新增业务能力。

## 1. 本批范围（务必只做这些）

1. **裁决双复盘入口**：下线右侧抽屉 `content-detail-dialog`，统一走全屏归因舱 `content-diagnosis-workbench`。
2. **删复盘台首屏大宽表**：`content-list` 的资产大表 + 与素材库重复的筛选维度下线，改为「今日待盘队列」数据源。
3. **下发闭环止损**：隐藏站内下发 / 已读 / 采纳申诉 / 催办的**入口与写操作**，但保留表、接口、历史数据。
4. **走势下拉下线**：推流峰值 / 走势 / 流量承接相关调用从归因舱移除（后端接口可留，前端不再调）。
5. **建议可复制**：提供「把归因结论 + 建议拼成一段纯文本」的 helper，供前端一键复制。
6. **素材库降二级**：导航层把 `/admin/videos` 降为二级入口（配合前端）。
7. 走通链路的简陋前端（队列→归因舱，能调通即可）。

**不做**：AI 归因（AI 仍只在 content-analysis 辅助按钮）；删 `content_feedback_cards` 表 / 接口 / 历史；碰履约状态；碰 8-8 死接口清理线。

## 2. 双入口裁决（第一优先，最易出错）

- 现状：`content-page-client.tsx` 里 `selectedVideoId` 有值就整页替换为 `ContentDiagnosisWorkbench`；而 `content-list.tsx` 内部又挂了约 1600 行的 `ContentDetailDialog`。两套并存。
- **裁决**：保留 `ContentDiagnosisWorkbench`（全屏归因舱），下线 `ContentDetailDialog` 抽屉。
- **要求**：
  1. 先 grep `ContentDetailDialog` 的所有引用点，列出受影响文件清单再动手。
  2. 确认 `ContentDetailDialog` 里有没有归因舱缺失、但产品要留的能力（如某个对比 / 沉淀入口）；有则先迁移到归因舱，再删抽屉，**不能直接砍掉功能**。
  3. 抽屉删除后，列表点「复盘」只走归因舱一条路。

## 3. 首屏大宽表 → 今日待盘队列

- 删 `content-list.tsx` 的资产大宽表（12 列）与和素材库重复的筛选（人员 / 账号 / 状态 / 日期这套资产检索维度）。
- 首屏数据源改为「今天该盘哪几条」：默认按异常严重度 / 待复盘排序，复用现有异常雷达打分与 `admin_content_first_screen`。
- 保留：按最差 / 按人 / 按时间的排序切换（这是「主动挑主角」，不是资产检索）。
- **资产检索能力整体让给素材库**，复盘台不再承担「翻全量视频」职责。

## 4. 下发闭环止损（保数据、隐入口）

- **隐藏**：确认并下发按钮、`sent/viewed` 状态流转触发、员工已读追踪展示、采纳 / 申诉回传入口、站内催办、顶栏「已下发 / 员工已读」工作流计数。
- **保留不动**：
  - `content_feedback_cards` 表结构与全部历史数据。
  - `PATCH /api/admin/content-feedback-cards/:videoId` 的**存草稿**能力（建议仍要落库，供复测读取）。
  - `GET …/previous` 复测接口（命根子，见 §6）。
- **止损方式**：走前端隐藏 + 后端写操作短路即可，**不删表、不删接口**，留待飞书能力起来后决定去留。用一个开关常量控制，方便回滚。
- 交付报告必须写清：哪些是「入口隐藏」、哪些是「写操作短路」、哪些「完全没动」。

## 5. 建议可复制 helper

- 新增一个纯函数：输入归因 `findings` + 已填的主要问题 / 建议草稿，输出一段可粘飞书的纯文本（标题 + 归因要点 + 建议）。
- **死规则 + 模板**产出，不调 AI。AI 只在用户点「AI 参考」时可选润色。
- 放在 `src/lib/` 下单独文件，附单测。

## 6. 命根子：复测接口保住

- `GET /api/admin/content-feedback-cards/:videoId/previous`（7-18 已定）**必须继续可用**：取同账号上一条已存草稿 / 已下发的卡 + 那条 24h 关键指标，供前后对比。
- 止损隐藏下发入口后，复测依据从「上次已下发卡」放宽到「上次已存草稿卡」，避免因不再下发而永远取不到上一条。**这条口径改动要在返回里注明来源（草稿 / 已下发）。**

## 7. 归因 / 对比 / 走势（沿用 + 微调）

- 归因结论带、四参照系对比：沿用 7-18 已落地逻辑，本轮不改算法。
- 走势下拉：`content-observations` 相关接口可留，但归因舱不再调；确认前端下线后无残留 fetch。

## 8. 交付物

- 双入口裁决（删抽屉）+ 首屏队列改造 + 下发止损开关 + 建议文本 helper + 复测口径放宽。
- 简陋前端跑通：队列→点进归因舱→归因出数→切 ref→生成建议文本→复制。
