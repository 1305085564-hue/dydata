## 一、已经拍板的产品取舍

### 放弃或后置

1. **放弃 V2 独立「近期高热」视图。** 近期信号并入顶部「今日聚焦」；旧接口的 `trending` 能力暂不删除，避免影响 V1。
2. **放弃 V2 的 AI 推荐前台入口。** 不展示生成、采纳、忽略等 AI 操作；`/api/topics/recommendations` 和 `from-recommendation` 不得删除，因为文案工具仍复用相关能力。
3. **后置母题折叠和复杂显示偏好。** 不迁移折叠记忆、分组折叠等设置；保留网格/表格切换即可。

### 必须保留

- 今日聚焦、团队最新认领、最新成片。
- 全部、我的认领、我录入、高潜待挖、从未做过。
- 搜索、母题筛选、排序、真实分页总数。
- 创建、查重、认领、满额替换、开始写稿、放回。
- 横向对比及账号维度的母题筛选。
- 详情深链、创建者编辑/删除、作品分页/排序、相近作品参考。
- 前台零 AI 干扰。

## 二、任务目标与完成定义

本轮目标不是功能等价迁移，而是让 `/topics-v2` 的核心操作结果真实、状态判断可信、失败可见，并通过现有 `/topics/[id]` 深链复用完整详情能力。

同时满足以下条件才算完成：

1. 创建、查重、横向对比、详情、作品、撞车动态均按真实接口结构展示。
2. 当前用户的认领状态由后端明确返回，前端不再从团队认领数组猜测。
3. 候选上限和替换列表只计算当前用户的 `candidate`；`scripting` 不占候选位，也不可被替换。
4. 详情动作只显示当前状态允许的命令；未认领时不能直接开始写脚本。
5. 所有 GET 失败均有错误状态和重试入口，不得伪装成空数据。
6. 母题筛选、搜索、排序和分页在服务端作用于完整结果集；「全部」默认代表全部历史。
7. 顶部聚焦包含真实近期信号，且与下方默认排序不再只是同一份历史均播榜重复展示。
8. V1 路由、AI 后端、数据库结构和现有视觉风格不受破坏。

## 四、推荐架构

### 1. 统一前端契约层

新增一个可单测的 V2 契约模块，例如：

`src/lib/topics/v2-client-contract.ts`

职责只包括：

- `fetchTopicJson`：先检查真实 `Response.ok`，失败时读取 `{ error }` 并抛出明确错误，成功后只返回 JSON。
- 解析创建、建议、选题池、详情、作品、撞车和横向对比的真实响应。
- 将可空字段标准化，不使用 `any` 掩盖结构差异。
- 将作品中的 `video_metrics_snapshots[0].play_count` 标准化为前端 `playCount`。

不要改变全站 topics API 的成功包装方式。现状成功响应就是业务 JSON 本体，V2 应适配现有契约，不再读取不存在的 `res.ok`、`res.value`。

### 2. 后端明确返回当前用户状态

选题池每一项新增：

```ts
myClaim: {
  id: string;
  subTopicId: string;
  status: "candidate" | "scripting";
  claimedAt: string | null;
} | null
```

详情返回的 `subTopic` 同样带 `myClaim`。该字段只能按接口当前登录用户 ID 生成，不能从可见团队成员中挑第一条。

`sub_topic_claims` 仍可保留给撞车统计，但不得再承担“哪个是我”的判断。

### 3. 详情职责分层

- V2 抽屉：快速看标题、Hook、撞车、摘要、少量作品和当前可执行动作。
- `/topics/[id]`：完整详情，继续承载编辑、删除、作品分页/排序和相近作品参考。
- V2 抽屉增加「查看完整详情」深链，不复制第二套编辑/删除实现。

## 五、分批施工

### 批次 A：P0 契约与认领真值

#### A1. 修复响应解析

涉及：

- `TopicCreateModal.tsx`
- `TopicComparisonMatrix.tsx`
- `TopicWorkBreakdownDrawer.tsx`
- V2 契约模块及测试

要求：

- 创建：`POST /api/topics/sub-topics` 成功返回新建记录本体。
- 查重：`GET /api/topics/sub-topics/suggest` 成功返回数组本体。
- 对比：读取 `{ dimension, windowDays, rows, sampleTotal }` 的 `rows`。
- 对比字段统一使用后端真实命名：`qualifiedRate / avgPlayCount / bestPlayCount`。
- 详情：从 `{ subTopic, works }` 中读取 `subTopic`。
- 撞车：使用 `displayName / userId / claimedAt`。
- 作品：从 `video_metrics_snapshots` 读取播放量，空快照才显示未拉取。

#### A2. 修复当前用户认领状态

涉及：

- `src/lib/topics/service.ts`
- pool、detail route
- `TopicHubV2.tsx`
- `types.ts`

要求：

- pool 和 detail 返回 `myClaim`。
- V2 删除 `sub_topic_claims[0]` 兜底逻辑。
- 我的认领列表只由 `myClaim` 构造。
- `hook` 类型改为 `string | null`，所有搜索和显示均为空安全。
- 删除能掩盖错误结构的关键 `any`，至少覆盖 pool、detail、comparison、claims、works。

#### A3. 候选上限与替换规则统一

要求：

- 前端候选数只统计 `myClaim.status === "candidate"`。
- `SmartReplaceModal` 只列 `candidate`。
- 后端 `replaceSubTopicClaim` 只允许原认领是 `candidate`；对 `scripting` 返回业务错误，不修改任何记录。
- 替换失败时弹窗保持打开并显示错误；成功后才关闭。
- 顺手修正 V1 详情页和主页面中“脚本中占候选位”的同一条预存规则，但不改变 V1 其他交互。

#### 批次 A 验收

- 候选 3 条、脚本中 3 条时，仍可直接认领第 4 条候选。
- 候选 5 条时才弹替换；替换列表恰好 5 条且没有脚本中项目。
- 模拟替换接口 409，弹窗不关闭，原状态不变。
- 创建成功不再提示失败；查重能展示；横向对比不再空白。

### 批次 B：详情动作闭环与错误恢复

#### B1. 三态动作

| 当前用户状态 | 抽屉主操作 | 不得显示 |
|---|---|---|
| 未认领 | 认领到候选 | 直接开始写脚本、放回 |
| `candidate` | 开始写脚本、放回 | 再次认领 |
| `scripting` | 显示「脚本中」、允许放回、查看完整详情 | 再次认领、再次开始 |

操作成功后只刷新受影响的 pool、我的认领、详情状态；失败保留当前界面并显示后端错误。

#### B2. 详情和作品

- 抽屉正确显示标题、母题、分组、可空 Hook。
- 作品预览读取真实播放量。
- 增加 `/topics/[id]` 的「查看完整详情」入口。
- 完整详情页继续负责编辑、删除、作品分页/排序、相近参考。
- 修复抽屉每次打开时的旧数据残留：切换 ID 后先清空上一次详情，再显示新加载状态。

#### B3. 明确错误状态

以下区域分别维护 `loading / error / empty / success`，禁止共用一个模糊空态：

- 今日聚焦
- 选题池
- 我的认领
- 横向对比
- 详情
- 作品
- 撞车动态

401 继续走登录提示；其他失败显示「加载失败」和重试。只有接口成功且数组为空时才显示「暂无数据」。

#### 批次 B 验收

- 未认领详情只有认领按钮，不能制造 404。
- `candidate` 开始写稿后立即切为 `scripting` 状态。
- 任一 GET 模拟 500 时显示错误而不是「暂无数据」。
- `/topics-v2` 可打开 `/topics/[id]`，刷新深链不丢失详情。

### 批次 C：完整结果集筛选、排序和分页

#### C1. 稳定母题选项

新增受登录保护的只读接口 `GET /api/topics/options`，按 `sort_order` 返回完整母题列表。创建弹窗、母题筛选和账号维度对比共用它；不得再从当前 50 条 pool 数据反推选项。

#### C2. pool 查询契约

扩展 `GET /api/topics/pool`：

- `topic_id`：可重复传递，服务端多选过滤。
- `q`：服务端搜索标题和 Hook；空 Hook 安全。
- `sort`：`latest / avg_play / claim_count`，必须在完整结果集排序后分页。
- `time_range`：新增 `all`；V2 默认 `all`，使「全部」等于全部历史。
- 返回并使用 `pagination.page / pageSize / totalItems`。

前端切换视图、时间、母题、搜索或排序时重置到第 1 页。搜索增加短防抖，避免每次按键立刻请求。

#### C3. 补齐保留视图

V2 展示：

- 全部
- 我的认领
- 我录入
- 高潜待挖
- 从未做过

不展示独立近期高热，不展示 AI 推荐。保留网格/表格切换，不增加母题折叠和复杂偏好。

#### C4. 横向对比账号维度

- `dimension=account` 时必须选择母题，并传 `topicId`。
- 母题列表来自 options 接口。
- 样本少继续明确标记；失败与零样本分开。

#### 批次 C 验收

- 选中某母题后，翻页仍只出现该母题。
- 均播、认领数、最新录入排序跨页正确，不是只排当前 50 条。
- 页面展示的总数与 `pagination.totalItems` 一致。
- 「全部 + 全部时间」能看到 3 个月前的数据。
- 账号对比切换母题后请求参数和表格结果同步变化。

### 批次 D：今日聚焦去重与真实近期信号

#### D1. 新的聚焦数据

`GET /api/topics/active` 增加 `focusTopics`，由两类非 AI 结果组成，最多各 3 条并去重：

1. **近期有成绩**：近 30 天有 24h 播放快照且播放量达到 1000 的子题，按近 30 天合格作品平均播放排序，附最近成片时间。
2. **历史高均播、久未重做**：全历史有合格作品，但近 30 天没有合格成片，按历史合格作品均播排序，附距上次成片天数。

每项返回明确的 `reasonType`、`reasonText`、`latestWorkedAt` 和 `summary`。不得使用 AI、外部热点或伪造分数。

现有 `worthRedoing` 可先兼容保留，确认 V1 无调用后再另开清理任务；本轮不删除字段。

#### D2. 前端呈现

- 区块标题改为「今日聚焦」，不声称实时热点或智能推荐。
- 卡片直接展示后端理由，例如「近 30 天 2 条合格作品，均播 3.2 万」或「历史均播 5.1 万，42 天未重做」。
- 团队最新认领、最新成片保留为紧凑动态区。
- 下方 pool 默认不再用同一份历史均播逻辑制造重复首屏；默认使用最新录入或上次用户选择，均播仍可手动切换。
- 不新增独立近期高热 Tab。

#### 批次 D 验收

- 聚焦卡片每条都有可核对的非 AI 理由。
- 近期有成绩和久未重做不重复同一子题。
- 数据不足时诚实空态，不补假推荐。
- 首屏聚焦与下方默认列表不再是相同顺序的重复榜单。

### 批次 E：测试、文档与双路由回归

#### E1. 必须新增的测试

1. 契约解析：创建、查重、对比、详情、作品、撞车。
2. `hook=null`：搜索、卡片和详情不崩。
3. `myClaim`：团队有多人认领时只返回当前用户记录。
4. 候选规则：`candidate=5` 阻断；`candidate=3 + scripting=3` 不阻断。
5. 替换：脚本中不可替换；失败回滚后新认领不残留。
6. pool：母题多选、搜索、三种排序、`all` 时间和分页总数。
7. focusTopics：近期与久未重做规则、去重、空数据。
8. 详情动作：未认领、candidate、scripting 三态。

优先测试纯函数和契约层，不依赖真实业务数据。禁止为测试创建账号、重置账号或写入生产数据。
