# 达人考核统一文案标准

状态：已完成（2026-11-09）。

## 目标与边界

达人个人档案作品明细和文案使用同一套内容质量评级：按话题选互动率＋收藏率或互动率＋点赞率，沿用现有公司标准、达成率、播放门槛和缺数状态。达人岗位汇总仍保留转粉率等业绩数据，个人档案现有 30 日原始曲线不变。不改数据库，不新增团队质量汇总。

## 已核实链路

`GET /api/admin/collaboration/person?role=talents` → `loadPersonData()` 按账号主人筛选达人作品并加载快照 → `buildPersonPayload()` 当前对每条 `record` 单独计算转粉评级 → `PersonalCardWorks` 展示「转粉·涨粉」；文案路径已通过 `loadVideoTopicTags()` 和 `buildWorkContentQuality()` 生成同源质量结构。话题标准、缺值状态和综合评级的唯一计算已在 `src/lib/content-quality.ts`，由 `quality-rules.ts` 暴露给个人数据装配。

## 实施方案

复用现有 `WorkContentQuality` 作为 `PersonRecordItem.contentQuality`，移除达人专属 `followerAchievement` / `followerGrade` 评级字段；保持 `hasSnapshot` 供既有记录状态和数据行为使用。数据层对达人作品一并加载话题标签，并通过相同 `buildWorkContentQuality()` 计算。页面沿用文案明细的标签、两项达成率、指标档位、综合评级及 `ContentQualityStatus` 状态文案。该方案不另造达人评级算法，也不改变作品归属或其他岗位记录。

## 文件与顺序

1. `src/lib/collaboration/data/person-loader.ts`：达人和文案岗位均加载质量话题，标签读取覆盖已筛出的达人明细作品。
2. `src/lib/collaboration/domain/person-rules.ts`、`src/app/(app)/admin/collaboration/types.ts`：记录项统一生成和声明 `contentQuality`；清除旧达人评级字段和算法依赖，不改业绩汇总。
3. `src/app/(app)/admin/collaboration/personal-card-works.tsx`：达人表格展示话题、互动/核心达成率和综合评级；复用现有缺数据状态文案。
4. `src/app/(app)/admin/collaboration/person-data.test.ts`、`src/app/api/admin/collaboration/content-quality.test.ts`：覆盖达人账号归属、两类话题选择、公司标准覆盖、评级门槛、快照/指标缺失，以及业绩字段仍独立。
5. `docs/系统架构与设计/数据口径与计算规则.md`、`docs/reference/协作管理接口文档.md`：记录岗位评级统一和 `records[].contentQuality` 返回契约。
6. `日志/2026-11-09.md`：验收后记录结果、提交状态和未覆盖边界。

## 边界行为与兼容

- 达人作品仍按现行账号主人归属和上海发布日窗口筛选；无快照、播放无效、指标缺失、话题读取失败时沿用文案的空值/错误状态，不回落到转粉评级。
- 标签读取成功但没有分类，按现有 `other` 规则选择复盘类指标；话题读取失败保持错误状态。
- `records[].contentQuality` 是个人接口内部新增统一字段，原 `records` 的达人评级字段移除；数据库和其他公开接口不变。
- 转粉率、互动率汇总和达人原始 30 日曲线继续按现有口径展示。
