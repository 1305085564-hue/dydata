## 二、必须补充的设计细节

### 1. 除零处理

**问题**：2 秒跳出率为 0 时，公式 `好标准 ÷ 实际值 × 100` = `25 ÷ 0`，会得到无穷大。

**解决方案**：定义达成率上限为 **200%**。

**理由**：
- 0% 跳出率意味着"没有人 2 秒内离开"，确实是极好表现，但无穷大没有业务含义
- 200% 既能体现"远超标准"，又不会在汇总时过度扭曲平均值
- 其他"低值更好"的指标（如 2 秒跳出率）出现 0 时，同样按此逻辑处理

**实施**：在新的达成率计算函数中加特判：
```typescript
// 低值更好的指标
if (lowerIsBetter) {
  if (actual === 0) return 200; // 达成率上限
  return (good / actual) * 100;
}
// 高值更好的指标
return (actual / good) * 100;
```

### 2. 差线语义与展示（已确认：选项 B）

**问题**：方案说"差线只判定不合格"，但"不合格"状态具体怎么用，方案未明确。

**已确认的处理方式**：
- **差线不影响档位**，只在展示层显示警告标签
- 达成率按好标准正常计算，综合评级按平均达成率正常评级
- 页面读取五项留存指标原始值，判断是否低于差线，显示"⚠️ [指标名]不合格"警告

**业务语义**：
- 差线标准相对较高，低于差线不代表"很差"，而是"不够好"
- 普通标准（好线）是"正常偏好"
- 好线以上是"极好"

**实施影响**：
- `WorkContentQuality` 无需新增 `retentionBelowPoor` 字段
- 前端页面需读取五项留存指标原始值和差线配置，自行判断并显示警告标签
- 综合评级逻辑只读取达成率，不读取差线状态

### 3. 综合评级的弱项拉升限制

**问题**：方案说"候选计算沿用现有综合评级的结构"，但没有明确说明弱项拉升限制是否保留。

**现有逻辑**（来自 `overallBreakoutGrade`）：
- 两项（互动、第四格）达成率取平均
- 较弱项最多被强项拉高 **1 个档位**（`MAX_PULL_GRADES = 1`）
- 即：要拿优（≥100%），两项都不能低于良（≥80%）；要拿良，两项都不能低于普（≥60%）

**建议**：**保留这个机制**，直接应用到互动+留存。

**理由**：
- 防止"一项 200%、一项 50%"被平均成 125% 评优
- 这是阿禅 2026-10-12 定稿的规则（见 `breakout-rating.ts` 注释）
- 互动和留存是两个维度的质量，都重要，不能互相抹平

**实施**：
- 综合评级改为处理"互动达成率 + 留存分"
- 保留弱项拉升限制逻辑
- 保留播放量门槛逻辑（见第三节）

## 四、方案中七个待确认问题的答复

### 1. "好标准"是否就是达成率 100% 的基准，超过后继续累计

**答**：**是**。好标准就是 100% 基准，超过后继续累计，不封顶。

### 2. "差线"是否只改变档位状态，不改变达成率计算

**答**：**差线不改变档位状态，也不改变达成率计算**。差线只在展示层显示警告标签。（见第二节第 2 条）

### 3. 2 秒跳出率为 0 时的有限值处理

**答**：达成率上限 **200%**。（见第二节第 1 条）

### 4. 留存三档的具体边界和名称

**答**：留存分按达成率评级，沿用现有档位：
- 优：≥100%
- 良：≥80%
- 普：≥60%
- 劣：<60%

差线不影响这个档位，只在展示层显示警告。

### 5. 综合评级是否沿用播放门槛、弱项拉升限制和四档结果

**答**：**全部保留**。
- 播放门槛调整为 2000/15000（见第三节）
- 弱项拉升限制保留（见第二节第 3 条）
- 四档结果（优/良/普/劣）保留

### 6. `avgContentAchievement` 是否继续作为接口字段名

**答**：**是**。保留字段名，在文档中更新语义为"留存分均值"。避免影响视频复盘、选题库和旧客户端。

### 7. 小队页面主列显示留存分均值，还是同时显示留存良优率和评级分布

**答**：建议显示 **留存分均值** 和 **综合良优率**，与互动均值并列。评级分布可在详情页或悬浮提示中显示。具体由前端实现时根据页面宽度调整。

### 2. 当前 scoreRetentionMetric（待替换）

```typescript
function scoreRetentionMetric(
  actual: number | null | undefined,
  band: { good: number; poor: number },
  lowerIsBetter = false,
): number | null {
  if (actual == null || !Number.isFinite(actual)) return null;
  const score = lowerIsBetter
    ? ((band.poor - actual) / (band.poor - band.good)) * 100
    : ((actual - band.poor) / (band.good - band.poor)) * 100;
  return Math.max(0, Math.min(100, score));
}
```

**改动点**：改为按 `band.good` 计算达成率，删除 0-100 限制，加除零保护。

### 3. 综合评级（content-quality.ts:159-169）

```typescript
function overallRetentionGrade(
  playCount: number | null,
  achievement: number | null,
): BreakoutGrade | null {
  if (playCount === null || !Number.isFinite(playCount)) return null;
  if (achievement === null) return null;
  if (playCount < KPI_PLAY_FLOOR) return "劣";
  const grade = breakoutGrade(achievement);
  if (!grade || playCount >= KPI_PLAY_GOOD) return grade;
  return grade === "优" || grade === "良" ? "普" : grade;
}
```

**改动点**：改为处理互动+留存双输入，参考 `overallBreakoutGrade` 的结构（见下）。

### 4. 参考：现有双输入综合评级（breakout-rating.ts:169-191）

```typescript
export function overallBreakoutGrade(
  playCount: number | null | undefined,
  items: readonly [BreakoutRating | null, BreakoutRating | null],
): BreakoutGrade | null {
  if (playCount === null || playCount === undefined || !Number.isFinite(playCount)) {
    return null;
  }
  if (playCount < KPI_PLAY_FLOOR) return "劣";
  const [interaction, fourth] = items;
  if (!interaction || !fourth) return null;
  const averageAchievement = (interaction.achievement + fourth.achievement) / 2;
  const metricGrade = breakoutGrade(averageAchievement);
  if (metricGrade === null) return null;
  const weakerGrade = lowerGrade(interaction.grade, fourth.grade);
  const pullCap = GRADE_ORDER[
    Math.min(GRADE_ORDER.indexOf(weakerGrade) + MAX_PULL_GRADES, GRADE_ORDER.length - 1)
  ];
  const cappedMetricGrade = lowerGrade(metricGrade, pullCap);
  const playGrade: BreakoutGrade = playCount >= KPI_PLAY_EXCELLENT
    ? "优"
    : playCount >= KPI_PLAY_GOOD ? "良" : "普";
  return lowerGrade(cappedMetricGrade, playGrade);
}
```

**改动点**：复用这个结构，把 `fourth` 改为 `retention`，把 `interaction.achievement + fourth.achievement` 改为 `interaction.achievement + retentionAchievement`。
