# 管理中心系统设置清理实施方案

## 1. 交付目标

退役 `/admin/settings` 导航入口与旧配置 API；将旧地址转到仍在使用的发布履约页。保留视频复盘正在使用的异常优先级和样本提示规则为代码内默认规则，但撤销过时的管理员编辑入口。

本方案已于 2026-09-26 执行完成；本文保留原冻结范围、实施步骤和验收口径，末尾补充当前工作树的独立复核结果。本次后续批次新增清理 migration，删除已无应用消费者的数据库残留。

## 2. 当前核查结论

### 2.1 页面范围

当前管理中心系统设置只有两个区块：

- `ThresholdsConfigPanel`：五项视频复盘阈值。
- `QuotaConfigPanel`：每日发片目标与历史规则。

入口与页面：

- `src/app/(app)/admin/settings/page.tsx:21-85`
- `src/app/(app)/admin/settings/components/thresholds-config-panel.tsx:18-262`
- `src/app/(app)/admin/settings/components/quota-config-panel.tsx:31-290`

没有发现第三个管理中心系统设置面板。头像弹窗的“系统参数配置”不属于本方案范围。

### 2.2 产量目标管理是现行页面残留

设置页读取 `get_daily_quota` 和 `daily_quota_config`，写入 `/api/daily-quota-config`：

- `src/app/(app)/admin/settings/page.tsx:39-57`
- `src/app/(app)/admin/settings/components/quota-config-panel.tsx:46-101`
- `src/app/api/daily-quota-config/route.ts:40-103`

当前发布履约统计没有读取目标配置。`get_fulfillment_range` 生成每日记录，前端按符合条件的日期数量累计 `requiredCount`：

- `supabase/migrations/20260806090000_fix_fulfillment_drop_group_refs.sql:106-140`
- `src/lib/loaders/fulfillment-page.ts:182-203`
- `src/lib/loaders/fulfillment-page.ts:300-331`

全仓库现行代码中，`daily_quota_config` / `get_daily_quota` 只被系统设置页和 `/api/daily-quota-config` 使用；没有发现发布履约、数据管理或员工端消费目标值的调用方。该功能当前是“能配置、没有业务结果”的孤立配置，建议退役，不接入新的统计口径。

### 2.3 异常阈值属于旧版视频复盘遗留，当前作用不完整

阈值接口和数据结构仍然存在：

- `src/app/api/admin/settings/thresholds/route.ts:50-117`
- `src/lib/video-review-thresholds.ts:1-84`
- `system_settings.key = 'video_review_thresholds'`

当前新版 `/admin/content`（视频复盘）实际使用情况：

1. `play_count` 只用于列表中“样本不足”灰显和提示：
   - `src/app/(app)/admin/content/content-list.tsx:258-265`
   - `src/app/(app)/admin/content/content-list.tsx:290-327`
   - `src/app/(app)/admin/content/content-list.tsx:100-130`
2. 五项阈值会进入 `buildReviewQueue` 的内部优先级分数，但调用链不统一且列表结果会再次排序：
   - 列表组件将设置值传入 `buildReviewQueue`：`content-list.tsx:269-277`
   - 紧接着列表按默认 `published_at` 或用户选中的表头字段重新排序，覆盖 `buildReviewQueue` 返回顺序：`content-list.tsx:215-216`、`content-list.tsx:343-407`
   - 顶部“异常提醒 / 最需关注 / 直接去盘”在 `content-page-client.tsx` 直接调用 `getPriorityScore`，未传入设置值，使用默认值：`src/app/(app)/admin/content/content-page-client.tsx:226-242`
3. 新版页面的异常提醒主要按 `anomaly_status`、`play_change_signal` 和数据完备度分桶：
   - `src/app/(app)/admin/content/content-page-client.tsx:230-242`
   - `src/app/(app)/admin/content/content-page-client.tsx:547-560`
4. 设置页文案仍写“视频复盘与素材库”，且承诺“触及警戒线时以浅红框亮起”，但素材库已合并/下线，现有列表只对样本不足降灰、对脏比例标红，没有对应的五项阈值红框闭环：
   - `src/app/(app)/admin/settings/components/thresholds-config-panel.tsx:77-80`
   - `src/app/(app)/admin/content/content-list.tsx:101-130`

结论：这不是一个可以继续扩展的稳定配置契约。阈值名义上能保存，实际只部分影响排序/样本提示，而且新版顶部异常提醒不跟随管理员配置。建议撤销管理员编辑入口，保留当前代码默认值带来的运行行为，不继续修补“素材库”旧口径。

### 2.4 `system_settings` 表不能整体删除

表仍被现行功能使用：

- 飞书履约开关：`src/app/api/admin/system/settings/route.ts:9-117`
- 选题库飞书工作区链接：`src/lib/topics/feishu-workspace.ts:78`
- 选题库飞书链接写入：`src/app/api/admin/topics-library/feishu-url/route.ts:36`

应用侧只清理旧 API 和旧页面依赖；保留表、RLS、飞书开关和选题库链接。本批数据库旧 key 与目标表数据也留存，不做破坏性清理。

## 3. 推荐方案

### 方案 A：退役系统设置入口，保留视频复盘的代码内规则（推荐）

- 从管理中心导航移除“系统设置”项；旧路径保留登录与 `manage_system` 闸机，并重定向到 `/admin/fulfillment`，旧书签仍可到达现在实际管理催交的页面。
- 删除产量目标页面区块、接口和 loader 查询；不接入新的统计口径。
- 删除旧版阈值设置面板、阈值 API 和 `video_review_thresholds` 的读写；在新版视频复盘继续使用代码内默认阈值，维持当前异常优先级和样本不足提示行为。
- 保留发布履约页现有飞书开关，不把它重复搬回系统设置。

优点：导航和接口不再承诺已经失效的配置；视频复盘当前使用者维持原规则；不重新定义异常口径。风险是管理员不再能通过页面调整这几个阈值，未来需要变更时走代码发布。

### 方案 B：保留阈值设置，但重做成新版视频复盘配置

把异常分类、优先级、样本不足和列表警示全部统一到同一份配置，并让顶部提醒、直接去盘、列表排序都消费同一份阈值。

不推荐本批执行：这会重新定义新版视频复盘的异常判定口径，涉及产品规则、真实数据抽查和较大的回归范围；用户当前意图是清理失效设置，不是恢复旧版参数中心。

- 不恢复或重做“每日发布”业务；发布履约和数据管理继续按当前口径运行。
- 不把飞书催交开关重复搬入系统设置；它继续由发布履约页管理。
- 不删除 `system_settings` 整张表。
- 不物理删除每日目标配置表、RPC、历史记录或阈值 key；本批只断开应用入口，数据库清理另行审批。

- 不顺手处理头像弹窗里的伪设置和矩阵账号“解绑”文案；那是另一个范围。
- 若线上对象、代码引用和 migration 记录冲突，标记 `BLOCKED`，先补事实核查，不以本地测试替代线上证据。

## 8. 最终接受标准

1. 管理中心不再展示系统设置导航项；旧路径受原 `manage_system` 权限保护并重定向到发布履约。
