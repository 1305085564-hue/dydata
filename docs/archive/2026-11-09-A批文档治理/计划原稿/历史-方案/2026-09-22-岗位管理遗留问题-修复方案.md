## 批次 1：批量分配正确性 + 替换提示 + 回滚机制

### 1.1 现状（问题）

**A1｜部分成功被当整体失败**

批量 Action 串行调用单人分配，第 N 个失败就整体返回 `ok: false`。但前 N-1 个**已写库、已写审计**。客户端收到失败后回滚**整个**名单。

> 勾 5 人加入、第 3 人失败 → 界面显示"一个都没加进去"，库里实际已加 2 个。要等下次整页刷新才对齐。

**A2｜自动换组的提示回退**

旧实现（已被删除）用 `describeAssignSuccess` 提示「已从「达人一组」移入「文案二组」」。新批量路径只说"已将【甲、乙】加入【X】"，被静默换组的人操作人看不到。服务端已返回 `replacedGroupName`，客户端算了不用。

**B2｜回滚靠渲染期快照，不是机制保证**

`prevRoster` / `prevGroups` 是渲染时捕获的数组引用。两次操作重叠时，后一次失败的回滚会覆盖前一次已成功的本地状态。目前靠 `isPending` 禁用按钮挡住重叠窗口 —— 隐式约束，不是机制保证。

### 1.3 修法

#### A1｜批量 Action 如实返回部分结果

不再「遇错即整体失败」，改为**收集成功与失败，如实返回**：

```ts
// work-group-actions.ts
export type BatchAssignOutcome = {
  groupId: string;
  assignedCount: number;          // 实际发生变更的人数
  skippedCount: number;           // 幂等跳过（changed=false）
  failures: Array<{ userId: string; message: string }>;
  details: Array<{ userId: string; changed: boolean; replacedGroupName: string | null }>;
};

// run 内：
//   逐个调用 assignWorkGroupMember
//   ok  → details.push(res.value)，失败不中断，failures.push({ userId, message })
//   循环结束后：
//     failures.length === input.userIds.length  → 全失败，返回 ok:false（保留原语义）
//     否则 → 返回 ok:true + 上述 outcome（部分成功也算成功）
```

**判定规则（必须严格照做）**：
- 全失败（每个人都失败）→ `ok: false`，与现在行为一致
- 只要有 1 人成功 → `ok: true`，`failures` 如实带出
- 空数组入参 → 维持现状（返回成功、0 人）

#### A2｜消费 `replacedGroupName`，恢复替换提示

客户端按 `details` 分组生成提示：

```ts
// 替换的人 → describeAssignSuccess({ groupName, replacedGroupName })
//            "已从「达人一组」移入「文案二组」"
// 新增的人 → "已分配至「文案二组」"
// 多条时合并为一句，最多列 2 个名字 + "等N人"
```

**必须复用** `work-group-membership-copy.tsx` 的 `describeAssignSuccess`，不得另写文案。理由：该文件注释写明「两个入口共用同一句话」，`modules-content-v3.tsx` 已在用。

失败的人单独提示，**不得静默**。

#### B2｜回滚改为按 userId 逆操作

废弃整表快照回滚，改为函数式、按 id 定位：

```ts
// 分配失败回滚：只把失败的人还原（不是整表）
setLocalRoster((prev) =>
  prev.map((m) => (failedIds.has(m.id) ? restoreSlot(m, snapshotOf(m.id)) : m)),
);

// 移出失败回滚：只把该成员还原
setLocalRoster((prev) =>
  prev.map((m) => (m.id === userId ? { ...m, peerGroupId, operatorGroupId } : m)),
);
```

要点：
- 每个成员的回滚快照**按 id 单独存**，不再用整表引用
- 用函数式 `setState(prev => ...)`，不读渲染期闭包里的数组
- 回滚只影响本次操作涉及的人，不碰其他人

#### C2｜补无障碍

- 触发器：`aria-expanded={isOpen}`、`aria-haspopup="listbox"`、`aria-controls={panelId}`

- 全选 = 把当前过滤结果的 id 并入已选

> 若认为「清空全部」更符合直觉，则反过来把全选也改成全量。**两者必须一致**，不得再不对称。改动后更新按钮文案（如「清空」→「清空所选」/「清除筛选结果」）以免歧义。
