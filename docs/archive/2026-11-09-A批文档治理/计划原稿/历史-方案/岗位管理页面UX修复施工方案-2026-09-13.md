## Codex 任务清单

### Codex-1：健康度加载失败状态逻辑（P0）

**文件**：`src/app/(app)/admin/collaboration/health-bar.tsx`

**当前问题**：
- 接口失败时只弹 Toast，`reports` 状态仍为空数组
- 空数组被渲染为"已完备"状态，误导管理者

**需求**：
1. 增加状态：`const [loadError, setLoadError] = useState<string | null>(null)`
2. 修改 `fetchUnattributedList`：
   - 失败时设置 `setLoadError(错误信息)`
   - 不再只弹 Toast（删除 `feedbackToast.error` 调用）
3. 提供状态判断逻辑给 UI 层：
   ```typescript
   // 四种状态：
   // 1. isLoading === true：加载中
   // 2. loadError !== null：加载失败
   // 3. !loadError && reports.length === 0：成功且无待补
   // 4. !loadError && reports.length > 0：成功且有待补
   ```
4. 暴露重试函数：`fetchUnattributedList` 已是 useCallback，可直接给 UI 调用

**交付标准**：
- `loadError` 状态正确存储失败信息
- 不再用空数组伪装失败状态
- UI 层可根据状态渲染不同视图

**验证方法**：
- 手动断网或修改 API URL 触发失败
- 检查 `loadError` 是否有值
- 检查 UI 是否显示错误态而非"已完备"

### Codex-2：补录归属改为本地乐观更新（P0）

**文件**：`src/app/(app)/admin/collaboration/health-bar.tsx`

**当前问题**：
- 每次保存调用 `router.refresh()` 全页重算
- 补齐 3 个角色 = 3 次全量服务端查询
- 补齐的行瞬间消失，造成视觉跳动

**需求**：

1. **删除立即刷新**：
   ```typescript
   // handleAssignRole 成功后删除这行：
   // router.refresh();
   ```

2. **本地乐观更新状态**：
   ```typescript
   // 保存成功后更新本地 reports 状态
   setReports(prev => prev.map(r => {
     if (r.reportId !== report.reportId) return r;

     const updated = { ...r };
     if (role === "scriptAuthor") {
       updated.scriptAuthorUserId = targetUserId;
       updated.scriptAuthorName = targetMemberName;
     }
     if (role === "videoEditor") {
       updated.videoEditorUserId = targetUserId;
       updated.videoEditorName = targetMemberName;
     }
     if (role === "operator") {
       updated.operatorUserId = targetUserId;
       updated.operatorName = targetMemberName;
     }

     return updated;
   }));
   ```

3. **增加"待移除"标识**：
   ```typescript
   // 在 UnattributedReport 类型中增加可选字段（或用 Map 存储）
   // 判断逻辑：
   const isComplete = report.scriptAuthorUserId &&
                     report.videoEditorUserId &&
                     report.operatorUserId;

   if (isComplete) {
     // 标记为待移除，150ms 后真正过滤
     // 方案 A：在 report 对象上加 pendingRemoval 标记
     // 方案 B：用独立的 Set<string> 存储 reportId

     setTimeout(() => {
       setReports(prev => prev.filter(r => r.reportId !== report.reportId));
     }, 150);
   }
   ```

4. **抽屉关闭时统一刷新**：
   ```typescript
   // 增加状态跟踪是否有保存操作
   const [hasSaved, setHasSaved] = useState(false);

   // handleAssignRole 成功时设置
   setHasSaved(true);

   // Sheet 的 onOpenChange
   onOpenChange={(open) => {
     if (!open && hasSaved) {
       router.refresh();
       setHasSaved(false);
     }
     setIsOpen(open);
   }}
   ```

**交付标准**：
- 单条保存不触发全页刷新
- 本地状态正确更新
- 提供"待移除"标识给 UI 层（字段名或 getter 函数）
- 关闭抽屉时统一刷新一次

**验证方法**：
- 补录一条作品的 3 个角色
- Network 面板应只在关闭抽屉时看到一次页面数据请求
- UI 应立即更新，不等待服务器响应

### Codex-4：个人档案卡缓存失效逻辑（P1）

**文件**：`src/app/(app)/admin/collaboration/person-data.ts`

**当前问题**：
- 缓存永不失效
- 补录归属/认证后重开同一人档案，看到的是旧数据

**需求**：

**方案 A（推荐）**：显式清除缓存

1. 暴露清除函数：
   ```typescript
   export function clearPersonDataCache(userId: string) {
     // 清除该用户相关的所有缓存 key
     // 格式：`${userId}-${year}-${month}`
     // 需要遍历或记录当前缓存的 key
   }
   ```

2. 在保存成功后调用清除：
   - `health-bar.tsx` 的 `handleAssignRole` 成功后：
     ```typescript
     clearPersonDataCache(report.creatorUserId);
     if (report.scriptAuthorUserId) clearPersonDataCache(report.scriptAuthorUserId);
     if (report.videoEditorUserId) clearPersonDataCache(report.videoEditorUserId);
     if (report.operatorUserId) clearPersonDataCache(report.operatorUserId);
     ```

   - `writer-certification-button.tsx` 的 `handleToggle` 成功后：
     ```typescript
     clearPersonDataCache(userId);
     ```

**方案 B（备选）**：TTL 机制

```typescript
interface CacheEntry {
  data: PersonDetailData;
  expireAt: number;
}

const cache = new Map<string, CacheEntry>();

export function readPersonDataCache(key: string): PersonDetailData | null {
  const entry = cache.get(key);
  if (!entry || Date.now() > entry.expireAt) {
    cache.delete(key);
    return null;
  }
  return entry.data;
}

export function writePersonDataCache(key: string, data: PersonDetailData) {
  cache.set(key, {
    data,
    expireAt: Date.now() + 5 * 60 * 1000, // 5 分钟
  });
}
```

**交付标准**：
- 选择一个方案实现
- 方案 A：暴露 `clearPersonDataCache` 函数并在相关操作后调用
- 方案 B：缓存 5 分钟后自动失效

**验证方法**：
- 补录归属后立即重开涉及人员的档案，数据应已更新
- 或等待 5 分钟后重开档案，数据应已更新

### Codex-5：Tab 切换改为 replace（P1）

**文件**：`src/app/(app)/admin/collaboration/collaboration-workbench.tsx:229`

**当前问题**：
- 使用 `router.push` 导致每次 Tab 切换都进入浏览器历史栈
- 点 4 个 Tab，后退键会在 Tab 间倒退而非返回上一页面

**需求**：
将 `router.push` 改为 `router.replace`

```typescript
const handleTabChange = (nextTab: TabKey) => {
  setTab(nextTab);
  router.replace(
    `/admin/collaboration?year=${year}&month=${month}&tab=${nextTab}`,
    { scroll: false }
  );
};
```

**交付标准**：
- 一行代码修改：`push` → `replace`

**验证方法**：
- 进入岗位管理页面
- 依次点击 4 个 Tab
- 点击浏览器后退按钮，应返回上一个页面（如工作台），而非返回上一个 Tab

3. 视觉风格：
   - 符合整体出版物气质
   - 错误图标和文字用暖色系警示色（不是刺眼的红色）

### Antigravity-2：补录归属的完成态过渡动效（P0）

**文件**：`src/app/(app)/admin/collaboration/health-bar.tsx`

**设计需求**：

Codex 会提供"待移除"状态标识（可能是字段 `pendingRemoval` 或独立的 Set），你需要根据这个标识加过渡效果。

**视觉反馈设计**：

1. **完成态标识**（三项填齐后立即显示）：
   - 该行出现淡绿色微光晕（左侧边框或整行背景）
   - 右侧增加小对勾图标
   - 颜色参考：`#6FAA7D`（矿石绿）

2. **退场动效**（150ms 延迟后）：
   - 高度平滑收缩（不是瞬间消失）
   - 使用 CSS transition 或动画库
   - 符合"物理缓冲"设计原则

**设计约束**：
- 不能用瞬间消失（会导致下方行猛地上弹，造成误点击）
- 过渡时长与 Codex 的 150ms 定时器协调
- 退场动效要流畅自然，像纸片轻轻滑走

**交付物**：
- 完成态视觉反馈（绿色微光 + 对勾）
- 平滑退场动效
