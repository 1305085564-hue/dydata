# 岗位管理优化方案（2026-09-07 修订）

本轮依据阿禅五项最终需求补全并实施。原稿已完整备份到 `/tmp/岗位管理优化方案-2026-09-07-原稿.md`。沿用现有界面，不做视觉重设计。

## 一、冻结业务口径

- 四个岗位新增有效作品（播放 >500）、优秀作品（播放 ≥30000，简单计数）。原有爆款字段及历史样本算法保持不变，不给原本没有爆款列的表格额外扩张爆款功能。
- 有效作品与计费分别按原话执行：恰好 500 不算有效作品，但参与计费。优秀作品只计一次。
- 文案绩效 = max(0, 播放≥500的作品数 + 优秀作品数×2 −25)。25 按人按所选自然月扣一次；播放缺失不计有效、优秀或计费基础条数。50条、10条<500、10条优秀得到35条。不能引用原有复杂爆款数计费。
- 月份沿用 daily_reports.report_date，统计起点及各岗位归属不变。文案认证只替换原“至少为别人账号写过一篇”的入场判断，入场后计本人当月全部署名文案，含自己账号。
- 达人、文案、运营身份分别按现有责任字段认定，可兼任；写文案不能推断为运营。剪辑、运营原统计范围不变。

## 二、文案认证闭环

- 使用独立 writer_certifications 表保存每个成员的当前状态、操作人、操作人姓名快照、操作时间。与个人可编辑资料隔离；认证人由服务端当前身份写入。
- 文案 tab 内提供“已认证 / 待认证”入口；管理员可在同一表格对当前可管理在职成员认证、取消及重新认证。零作品成员也能认证，已认证零作品显示0。普通成员不可操作。
- POST /api/admin/collaboration/writer-certification 严格校验登录、管理员权限、activeVisibleUserIds 和目标状态；认证/取消状态与署名原子保存。独立表仅服务端授权路径可写，客户端不能直接自行认证。
- 已认证显示“某某认证”；取消后可重新认证，再认证显示本次操作人。界面刷新后仍一致。认证按当前资格控制所选月份的入场，不做历史结算锁定或追溯版本系统。
- 查询必须加载认证状态和署名，并独立加载当前候选，不能只从当月已有作品反推候选。失败明确报错，不将认证查询失败解释为无人认证。

## 三、具体作品打开视频复盘

- 文案/剪辑作品摘要、展开作品及个人岗位明细里的具体作品均可打开复盘。达人/运营已有账号汇总保持账号语义，通过人员明细查看具体作品，不把账号行当成单个作品。
- 以 reportId 在后端校验日报可见范围，再按既有业务日期配对规则定位视频。无匹配返回404，多匹配返回409，不任取第一条；无复盘权限返回403。
- 跳转 /admin/content?videoId=...，目标页按ID补齐指定作品与24小时数据，不依赖其是否在当前待盘队列。打开后可查看数据、截图、文案；缺失明确显示。
- 不扩大 review_content 权限，不自动触发AI分析。复盘页关闭详情清除定位参数，刷新/前进后退行为一致。

## 四、手工标记

- daily_reports.data_source 使用 ai/manual/null；null为历史来源未知，历史不回填成AI。界面只为manual显示“手工”，提示“该数据由人工填写或修改”。
- AI识别未人工改动不标；手工录入或实际改动后标手工。只打开编辑或原样保存不新增标记。
- 用户实际修改行为经前端提交到服务端保存；草稿恢复与历史编辑保留来源。手工一旦成立不被再次OCR、重传、刷新或后续原样保存降回AI。
- 覆盖主提交、历史编辑及管理端改动日报字段的入口。字段默认值、预填不能直接等同人工改动。
- 读取字段、返回类型、作品摘要/明细展示必须同步。数据库保证已manual不能降级；提交事务失败不能留下假成功状态。

- 定向测试先证明边界：499/500/501/29999/30000/null、35条示例及归零；认证首次/取消/再认证/零作品/跨公司/普通成员；定位零/一/多结果；AI不动/手改/恢复/再次OCR/原样保存。
