**判定口径**（与需求一致）：

| 维度 | 口径 |
| --- | --- |
| 是否写入路由 | route.ts 导出了 GET 以外的任一方法（POST/PUT/PATCH/DELETE）即为**是**；纯 GET 为**否** |
| 观测接入 | 区分**旧签名** `observeMutation(route, handler)` 与**新签名** `observeMutationRequest(route, request, handler)` |
| 分层字段齐全 | 三选一命中即算齐全：① `import` 并**实际调用** `appendObservedMutationResult`；② 路由内自造 `appendMutationLayers` / `mutationFields` 之类构造器并应用到响应；③ 响应体里 6 个字段名齐全 |
| 缺口 | 「是写入路由但未接观测」**或**「已接观测但分层字段不齐」 |

**两条关键事实**（本表重点）：

1. **不存在「旧签名且没造分层字段」的写入路由** —— 21 个仍用旧签名 `observeMutation` 的写入路由，全部通过 `appendObservedMutationResult`（10 个）或路由自造构造器（11 个）补齐了分层字段。

## 五、待确认问题

1. **`/api/feishu/event` 是否纳入统一写入契约？**
   它是飞书事件回调，无权限模型、无审计/通知/待办分层语义，但导出了 POST。三种处理：① 纳入契约，补 `observeMutation` + 分层字段（会产生语义空洞的 `skipped` 分层）；② 显式登记为**契约例外**（推荐——在契约文档里列出「外部回调不适用」，并让对账脚本排除它）；③ 改成 `dynamic = "force-static"` 之外的形态或调整口径，把「回调类 POST」从写入路由定义中剔除。**推荐 ②**：改动最小、语义最诚实、避免为通过检查而伪造分层字段。

2. **21 个旧签名 `observeMutation` 路由是否统一迁移到 `observeMutationRequest`？**
   现状分层字段都齐全，差别只在 requestId：新签名 `observeMutationRequest` 会读请求头 `x-dydata-request-id`。旧签名 21 个里，10 个用 `resolveObservedMutationRequestId` 手工补了解析；另外 11 个自造构造器路由中，只有 `/api/admin/fulfillment/appeal/handle` 自己解析了请求头（`route.ts:482 const supplied = request.headers.get("x-dydata-request-id")`），**其余 10 个未解析**（实测证据：`for f in ...; do echo $(grep -c "resolveObservedMutationRequestId" $f) $f; done` → 这 10 个均为 `0`，且 `grep -n "x-dydata-request-id"` 无命中），端到端 requestId 串联会断。属于技术债，不是功能缺口。

3. **纯 GET 但有数据变更的路由是否要观测？**
   - `/api/notifications/cleanup`：`admin.rpc("cleanup_expired_notifications")` —— 真删除，走 cron 鉴权。
   - `/api/remind/count`：`supabase.rpc("count_remind_logs_for_user")` —— 名字是 count，但 `remind_logs` 语义上可能落记录，**需确认这个 RPC 是否只读**。
   按本次口径它们是读路由、标「不适用」，但实际有变更副作用。

4. **8 个 GET + 写入方法共存的路由，其 GET 分支不接观测**，是否确认符合预期？（写入方法均已接入；其中 `/api/feishu/event` 例外——它两个方法都没接，即第四节唯一缺口。）

5. **契约测试的形态在核对期间变了，当前已不存在「逐路由登记」的兜底测试。**
   核对开始时存在 `src/app/api/admin/observed-mutation-contract.test.ts`（内部登记 24 条 `routeContracts` + 2 条 `sampleRoutes`，只覆盖 26 条路由，断言 `businessSucceeded|mutationFields|appendObservedMutationResult`，且两类路由断言强度不同）。核对期间该文件与 `src/app/api/user-mutation-contract.test.ts` 被**删除**，改为新增 `src/app/api/mutation-contract.behavior.test.ts`（10 个纯行为用例：成功/403/401/500/400、路由自报分层优先、非 JSON 放行、request id 换发等）与 `src/app/api/exemptions/layering.behavior.test.ts`。实测新文件 `grep -c "route.ts"` = **0**，即**不再逐路由枚举**。
   影响：现在**没有任何测试能保证「新增写入路由必须接入契约」**——漏接一个路由不会有测试报警，本次唯一缺口 `/api/feishu/event` 就是靠人工对账才发现的。建议补一个"扫描 `src/app/api/**/route.ts`、凡含非 GET 方法者必须命中 `observeMutation(Request)?` 且必须命中分层字段来源"的守卫测试。当前状态：`git status` 显示两个旧测试为未提交删除（`D`），新测试为未跟踪文件（`??`），**尚未提交**。

6. **`src/app/auth/callback/route.ts`、`src/app/auth/logout/route.ts` 不在本表口径内**（不在 `src/app/api/` 下，且都是 GET）。若「全部写入类 API 路由」应覆盖整个 `src/app/`，需扩大扫描范围。

7. **`POST` 但语义只读的路由是否算写入路由？** 例：`/api/admin/ai-config/check-dependencies`（依赖体检）、`/api/dashboard/sample-quality-check`（抽样质检计算）。按口径算写入路由且都已达标，仅确认口径。

8. **统一出口新增了「非 JSON 响应原样放行」规则，写入路由若返回非 JSON 会静默拿不到 6 个分层字段。**
   核对期间 `src/lib/observed-mutation-result.ts` 新增（`route.ts:48-57`）：

   ```ts
   const contentType = response.headers.get("content-type") ?? "";
   const isJson = contentType.includes("application/json") || contentType.includes("+json");
   // 非 JSON 响应（二进制图片、CSV 导出、纯文本）…原样放行，不做分层字段附加。
   if (response.body !== null && !isJson) {
     observation?.setDetail?.({ businessSucceeded: response.ok });
     return response;
   }
   ```

   实测影响面：**当前 45 个写入路由中没有任何一个返回非 JSON 响应**（`grep -E 'text/csv|text/plain|application/octet-stream|image/png|NextResponse.redirect'` 只在 `/api/ocr-screenshot`、`/api/submission-screenshots` 命中请求侧类型白名单，非响应体）。所以**当前不构成缺口**，但这是一条**潜在契约漏洞**：将来某个写入路由改成返回 CSV/二进制/纯文本时，它会通过「已 import appendObservedMutationResult」的静态检查，却在运行时丢掉全部分层字段。建议要么在守卫测试里加运行时断言，要么让非 JSON 分支显式报错而非静默放行。

9. **`observeMutationRequest` 新增了第 4 个可选参数 `deps`**（`route.ts:32`，`deps: ObserveMutationDeps = {}`，用于测试注入 `createRequestId`）。本表 23 个新签名路由均未传 `deps`，不影响判定，仅记录接口扩展。

## 六、复现脚本

```bash
cd /Users/mac/Projects/dydata

# 路由总数
find src/app/api -name route.ts | wc -l

# 每个路由：方法 / 是否用新签名 / 是否用旧签名 / 是否用统一分层出口 / 是否自造分层构造器 / 字段名命中数
for f in $(find src/app/api -name route.ts | sort); do
  m=$(grep -o "^export async function \(GET\|POST\|PUT\|PATCH\|DELETE\)" "$f" | sed 's/export async function //' | paste -sd/ -)
  req=$(grep -c "observeMutationRequest(" "$f")
  old=$(grep -c "observeMutation(" "$f")
  app=$(grep -c "appendObservedMutationResult(" "$f")
  mb=$(grep -c "appendMutationLayers(\|function mutationFields" "$f")
  n=0
  for x in businessSucceeded permissionChecked auditStatus employeeNotificationStatus todoStatus compensationRequired; do
    grep -q "$x" "$f" && n=$((n+1))
  done
  printf "%-60s %-20s new=%s old=%s append=%s own=%s fields=%s\n" "$f" "$m" "$req" "$old" "$app" "$mb" "$n"
done
```
