# 全站"整页刷新感"排查 — 后台管理页与全局壳

> 只读排查，产出分档清单。范围：`/admin/content`（视频复盘）、`/admin/videos`、`/admin/modules`（成员管理，含团队管理）、`/admin/fulfillment`（发布管理）、`/admin/ai-config`、`/admin/settings`、全局壳 `src/components`（导航栏/布局）与 `src/app` 鉴权登录。
> 未覆盖：`/admin/teams` 作为独立路由在 `src` 中不存在——团队管理并入 `/admin/modules`（团队筛选 + `TeamManagementDialog`）。`/admin/videos` 已收敛为 `permanentRedirect → /admin/content`。
> 方法：先以高信号 grep 建候选，再逐个读 page/container/client 源码证实/证伪。判据以"本应就地完成的用户动作是否触发 (a) 整块重挂露骨架/(b) 整条路由服务端重取/(c) 跳回顶部"为准。
> 扫描基线：本地工作树 `main`（注意与 origin 可能分叉，本文全部以工作树当前文件为准）。

## 对齐参照（协作管理范本，本模块刚收口，只作标尺不扫不改）

`collaboration/page.tsx`：`<Suspense key={`${year}-${month}`}>` —— key 只随**真·改变服务器取数的维度（年月）**；`view/tab/groupId` 由服务器读但仅作默认打开项。
`collaboration-data-container.tsx`：首屏一次备齐全部页签/视图/小队数据。
`collaboration-workbench.tsx`：`tab/view/groupId` 用 `useState`，切换只 `router.replace(..., {scroll:false})` 同步地址栏，不触发重挂。
`health-bar.tsx`：写操作乐观更新 + 关抽屉后 `startRefresh(() => router.refresh())` 包进 `useTransition` 后台静默校正。
→ 判缺陷的核心尺子：**切换类小操作的数据客户端是否已全有？URL 同步是否走 `history.replaceState`（零服务端导航）而非 `router.replace`（触发 RSC 重取）？写后 revalidate 是否包了 transition？**

## 一、一定要做（高频小操作触发全量服务端重取/整块重挂）

### M-1 成员管理 · 搜索框逐字符、团队筛选、在职/已归档页签切换 → 每次全量服务端重取 + 客户端列表被重置

- **路由/入口 + 触发操作**：`/admin/modules` 顶部搜索框每敲一个字符；团队下拉换一个团队；"在职 ↔ 已归档"页签点一下。
- **定位**：`modules-content-v3.tsx`（`"use client"`）
  - 搜索：`ContentList` 区搜索输入 `onChange` → `setSearchQuery(next)` + `replaceWorkspaceUrl({ query })`
  - 团队筛选下拉 `onValueChange` → `setSelectedTeamId(val)` + `replaceWorkspaceUrl({ team })`
  - 页签按钮 `onClick` → `setMemberView(...)` + `replaceWorkspaceUrl({ view, memberId:null })`
  - `replaceWorkspaceUrl` = `router.replace(buildMemberWorkspaceHref({...}), { scroll:false })`
- **现象**：(b) 整条路由服务端重取。`router.replace` 触发 App Router 服务端导航 → `page.tsx` 的 `AdminModulesPage` → `ModulesDataContainer` 重新 `await`：`loadAdminModulesData` + `listPendingRequestsForAdmin`（整份成员 + 团队 + 小队 + 待审批数据集）。同时返回的新 props 命中"Sync props → state"系列 `useEffect`（`setLocalProfiles(allProfiles)` / `setLocalTeams(visibleTeamOptions)` / `setLocalWorkGroups` / `setLocalWorkGroupRoster`），把客户端本地列表整体重置一遍（数组身份全变 → 大表格重渲染）。Suspense 无 key，所以多半**不闪骨架**，但表现为逐字符打网络、列表每次重新灌数据/可能瞬时抖一下。
- **根因归类**：高信号 #3（用 `router.replace` 只为镜像页内状态）+ #7（客户端靠 props 变化重置本地态）。
- **关键证据（判它非"真·重取"）**：`ModulesDataContainer` 服务端查询**只依赖 `params.date`（`searchDate`）**，`q/team/view/memberId` 都不进服务器取数——`loadAdminModulesData({supabase, searchDate})`。所以这几路的重取返回的是**同一份数据**，纯属空转。
- **分档**：**一定要做**。搜索/筛选/页签是成员管理最高频动作，逐字符打全量接口代价最高。
- **建议修法（对齐范本，最小方案）**：这三处只做**客户端过滤**（数据客户端本就全有），URL 镜像改用 `window.history.replaceState` 而非 `router.replace`——**同仓 `content/content-list.tsx` 的 `updateFilter`/`handleResetFilters` 已是现成正确写法**（`history.replaceState` + 容器内 `scrollTo`，零服务端导航）。把 `replaceWorkspaceUrl` 内实现从 `router.replace` 换成 `history.replaceState` 即可，三个调用点不用动。
- **涉及层**：仅客户端组件。
- **风险**：改动本身不碰权限/口径（服务器不依赖这几个参数）。但**首屏深链 `?member=`/`?view=archived` 依赖服务端把 `focusMemberId/initialMemberView` 传进来**——改成 `replaceState` 只影响"页内切换时的再取"，不影响首屏 SSR 读 URL，需保留首屏这条链。别顺手把 `date` 相关逻辑一起改。
- **复杂度**：F2（路径明确，照抄现成写法）。

### M-2 成员管理 · 点击成员行开抽屉 → 每次 `router.push` 全量重取

- **路由/入口 + 触发操作**：成员列表点某一行/某个"查看"打开右侧成员抽屉；点"逐个浏览不同成员"。
- **定位**：`modules-content-v3.tsx` `openMemberDrawer(member, syncUrl=true)` → `router.push(buildMemberWorkspaceHref({... memberId}), {scroll:false})`；`closeMemberDrawer` → `replaceWorkspaceUrl({memberId:null})`（同 M-1 的 `router.replace`）。
- **现象**：(b) 服务端重取。开抽屉本是纯客户端动作——`activeMemberId` 用 `setActiveMemberId(member.id)` 已即时打开，抽屉内容来自已加载的 `localProfiles`。但 `openMemberDrawer` 额外 `router.push` 写 `?member=`，同样触发整份数据集服务端重取 + props→state 重置。逐个翻成员 = 逐个全量重取。
- **根因归类**：高信号 #3。
- **分档**：**一定要做**（翻人是成员管理主循环动作，频率与 M-1 同级）。
- **建议修法**：`?member=` 仅作**首屏深链**用（SSR 读一次即可）；页内开/关抽屉用 `history.pushState/replaceState` 镜像 URL，不走 `router.push/replace`。
- **涉及层**：仅客户端组件。
- **风险**：`appliedFocusMemberId` 那段 `useEffect`（监听 `focusMemberId` prop）承担"URL→开抽屉"。若页内不再经服务端导航，`focusMemberId` prop 不更新，但抽屉已由 `setActiveMemberId` 打开，行为一致；需回归验证浏览器"前进/后退"对抽屉开合仍可用（当前代码未见 popstate→抽屉 的监听，改成 pushState 后前进后退对 `?member` 的响应会变化，**存疑：需产品确认是否要保留历史栈驱动抽屉**，或只 `replaceState` 不入栈）。
- **复杂度**：F2。

## 二、尽量做（中频，或代价明确但频率一般）

### C-1 视频复盘 · 切换"全部↔回收站""公司↔团队视角"→ 整块重挂露 TableSkeleton + 与客户端取数重复的服务端重取

- **路由/入口 + 触发操作**：`/admin/content` 顶部"全部/回收站"页签；右侧"全公司/各团队"范围下拉切换。
- **定位**：
  - `content/page.tsx`：`<Suspense key={`${view}-${requestedPerspective}-${params.teamId ?? ""}-${directVideoId ?? ""}`} fallback={<TableSkeleton columnCount={10} rowCount={8}/>}>`
  - `content/content-page-client.tsx`：`loadData()` 已**在客户端 `fetch('/api/admin/content/list')` 并 `startTransition(()=>setData(...))`**（就地换数据），随后 `if (!options.background) router.replace(buildContentPageUrl({view,perspective,teamId, videoId:null,...}), {scroll:false})`。
- **现象**：切页签/切视角时，`view`/`perspective`/`teamId` 变化 → (a) `router.replace` 触发服务端重渲染 `ContentDataContainer` → Suspense **key 变了 → 整块卸载重装，露 `TableSkeleton` 骨架**；且 `ContentDataContainer` 又 `loadAdminContentInitialData` **再取一次服务器数据**，与刚发生的客户端 `loadData` **重复**。
- **根因归类**：高信号 #4（Suspense key 混进纯客户端态维度）+ #3（`router.replace` 只为镜像状态）。
- **对照范本**：协作管理正是把 `view/tab` 移出 key、只留 `年月`，才做到"切页签/视图不重挂"。此处 key 反而把页内切换维度全塞进去。
- **分档**：**尽量做**。翻视角/回收站对管理者是日常但非逐字符级高频（低于 M-1）；且此模块客户端已备好就地取数能力，收益主要是"去掉重复重取 + 去掉骨架闪"。
- **诚实边界（别误判成真·重取缺陷）**：`view=all|trash`、`perspective=company|team`、`teamId` 确实决定服务器查询范围，**首屏/深链/硬刷新时服务器必须按这些取数**——所以"要重取"这件事本身不是 bug，bug 是"**客户端已经取过了，router.replace 又让 keyed Suspense 重挂再取一次并闪骨架**"。
- **建议修法（对齐范本）**：让页内切换只走既有的客户端 `loadData`（数据已在 `data` state），URL 同步用 `history.replaceState`（`selectVideo/closeVideo` 已经用 `window.history.pushState` 镜像 `?videoId`，照此扩展即可），**不要**在 `loadData` 里用会改 key 的 `router.replace`；`<Suspense key>` 只保留"确实改变服务器首屏取数、且需要露骨架"的维度（可退化为不带页内态的 key，甚至在首屏恒定时移除动态 key）。`directVideoId` 同理：页内开抽屉走 pushState 已不重挂，把它留在 key 里是"深链首屏"与"页内态"混淆的隐患。
- **涉及层**：客户端组件 + `page.tsx` 的 Suspense key（服务器渲染边界）。
- **风险（重点，沾数据范围/权限）**：`requestedPerspective`/`teamId` 驱动 `resolveAdminDataPerspective` + `scope`（**决定可见数据范围，涉 RLS/集团模式**）；`view=trash` 有 `manage_videos` 权限守卫（`page.tsx` 里 `view==="trash" && manage_videos!==true → redirect`）。**改前先核对线上真实字段/范围，勿先动数据库；"去掉重挂"≠"去掉服务器按范围取数"，深链与硬刷新首屏仍须服务器正确取数**；别把"UI 隐藏"当安全边界。
- **复杂度**：F3（要同时保证页内就地、深链首屏、权限跳转、前进后退 `popstate` 处理四条链一致）。

### S-1 全局壳 · 设置弹窗切换"集团模式"→ 裸 `router.refresh()` 使底层当前页重挂露骨架

- **路由/入口 + 触发操作**：任意页面右上角头像 → 设置弹窗 → 切换"进入/退出集团模式"。
- **定位**：`src/components/premium-settings-modal.tsx` `handleGroupModeChange`：`fetch('/api/group-mode/enter|exit')` 成功后 `setIsGroupModeActive(...)` 然后 **`router.refresh()`**（未包 `startTransition`）。对比：同文件 `handleSaveProfile` 已用 `startTransition(async()=>{...})`（第 240 行附近）——说明作者知道要包，唯独这处漏了。
- **现象**：(a)/(b) `router.refresh()` 重跑当前路由服务端组件；弹窗正关闭时，底下页面（若含数据 `Suspense`）会重新挂起露骨架/闪一下。
- **根因归类**：高信号 #1（裸 refresh 未包 transition）。
- **分档**：**尽量做**（集团模式切换是 owner 级低频操作，但一旦发生是明显的全页闪）。
- **建议修法**：`const [, startRefresh] = useTransition(); ... startRefresh(() => router.refresh())`（完全对齐 `health-bar.tsx`）。
- **涉及层**：客户端组件。
- **风险（沾数据范围）**：切换集团模式改变 server 可见 scope，**refresh 必须做**（要按新模式重取数据），只是别裸跑导致闪；不要为"消除闪烁"而省掉这次 revalidate。
- **复杂度**：F1。

### M-3 成员管理 · "Sync props → state" 副作用是 M-1/M-2 的放大器（伴随修复）

- **定位**：`modules-content-v3.tsx` 第 412–437 行一组 `useEffect`，把 `allProfiles/visibleTeamOptions/initialPendingRequests/initialWorkGroups/initialWorkGroupRoster` 无差别回灌进各自 `local*` state。
- **现象/根因**：任何一次服务端导航（M-1/M-2 的 `router.replace`、以及写操作后的 `router.refresh`）返回**新数组身份**即整体重置本地列表；乐观写操作与"URL 镜像导航"叠加时，理论上存在"刚乐观改完、镜像导航返回的旧一致数据把乐观态刷回去/列表重渲染"的抖动窗口。
- **分档**：**尽量做**（随 M-1 修完，触发频率骤降，这里只需把"无差别回灌"收窄为"确有新数据时回灌"）。
- **建议修法**：M-1 改用 `replaceState`（不再触发服务端导航）后，这组 `useEffect` 仅在**真·写操作 `router.refresh`** 时触发，属预期；如需更稳，可比较关键 id 集合再决定是否 setState。
- **风险**：别把写后 revalidate 需要的同步也一并去掉（写操作乐观态最终仍要靠服务器真相收敛）。
- **复杂度**：F2。

## 三、可做可不做（低频 / 代价可控 / 需产品权衡）

### A-1 AI 配置 · 页签切换 `<Link ?tab>` + 三 tab `dynamic()` 条件渲染 → 切走再切回丢本地态、首次露占位骨架

- **定位**：`admin/ai-config/ai-config-shell.tsx`：Tab 用 `<Link href="/admin/ai-config?tab=...">`（软导航，重跑 `page.tsx` → `getUserPermissions`，服务器页无重数据）；内容 `{activeTab==="models" && <ModelsClient/>}` 等三分支，`ModelsClient/BindingsClient/ProvidersClient` 各自 `dynamic()` 带 `LoadingPlaceholder` 小骨架。
- **现象**：切页签时目标 tab 组件首次下载 chunk → 露 `LoadingPlaceholder`（h-48 居中小骨架，非整页）；三个 tab 条件渲染互斥，切走再回来会丢该 tab 的本地未保存态并重新 `fetch` 自身数据。
- **根因归类**：高信号 #5（动态组件挂载点）+ #7 轻度。
- **分档**：**可做可不做**。AI 配置是 owner 低频设置页；各 tab 本就取不同数据、首访露一次骨架可接受；`<Link>` 是软导航非整页刷新。收益低。
- **建议修法（若做）**：保留三 tab 挂载、用 CSS 显隐替代条件卸载以保住本地态；或首访预取三个 chunk。
- **风险**：低。
- **复杂度**：F2。

## 五、存疑项（结论未闭环，需补充信息/实测）

1. **C-1 是否"真"闪骨架**：本排查纯静态、未跑浏览器。代码上 `view/perspective/teamId` 进 Suspense key + `loadData` 的 `router.replace` 会改变 key → 理论会整块重挂露 `TableSkeleton`；但 App Router 在 key 变化时的 `popstate`/transition 细节可能影响观感。**需要**：`gate:browser` 或本地 dev 连真实库，实测"切页签/切视角"时 TableSkeleton 是否再现、是否两次 `/api/admin/content/list`。
2. **M-1 逐字符 refetch 的实际耗时与 Next Router Cache 去重**：代码确认每次 `onChange` 都发 `router.replace`；**需要**：Network 面板看是否每字符一发全量接口、是否被 Next 短时客户端缓存吸收（即便吸收，props→state 重置仍每次触发）。
3. **M-2 改 `history.pushState` 后浏览器前进/后退对成员抽屉的开合**：当前无 `popstate→抽屉` 监听，改法可能弱化历史栈行为。**需要**：产品确认是否保留"后退换上一个成员"这一动线（若不需要，退化为 `replaceState` 不入栈即可）。

## 六、TOP 行动项（本范围，性价比排序，最多 5 条）

## 结论摘要（业务语言）

- 最痛、最该改的是**成员管理**：每敲一个字、每换团队、每点在职/归档、每点一个成员，系统都悄悄把整份成员名单重新拉一遍——纯浪费，改法有现成模板，属"能就地小改"。
- **视频复盘**切"全部/回收站""公司/团队"会整块闪一下重载，原因是页面把"只影响显示"的参数也当成了"要重新取数"的信号；能修，但它关联"谁能看哪些数据"的权限，**修前要先核对线上权限口径，别急着上线**。
- **全局设置里切集团模式**会闪一下，一个小改动（包一层过渡）就能治好。
- 其余大部分后台页（发布管理、AI 配置、系统设置、回收站/删除/补录、写操作）**已经是正确的"就地更新"或本就该整页**，不用动。
- 建议先做"成员管理止住逐字符重取"这一件——收益最大、风险最低。
