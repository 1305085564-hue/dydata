### 1.5 真实业务链路

#### 登录与页面保护

```text
浏览器请求
  -> src/middleware.ts
  -> 登录 cookie / session 校验
  -> profiles.membership_status 生命周期校验
  -> 页面或 API 自己的权限、对象归属、数据范围校验
  -> 页面 loader / Server Component / route handler
```

`src/middleware.ts` 负责登录、生命周期、限流和清缓存，不负责所有细粒度角色权限。页面能否显示和 API 能否写入是两层判断，不能只看导航。

#### Dashboard 提交链路

```text
/dashboard
  -> DashboardDataContainer / 页面 loader
  -> DashboardContent
  -> VideoSubmitPanelV2
  -> VideoSubmitFormV2
  -> POST /api/video-submit
  -> daily_reports / videos / screenshots / 责任人绑定
```

编辑链路另外经过：

```text
/api/video-submit/edit-detail
  -> 原视频、日期、日报、截图绑定核对
  -> 历史责任人和不可编辑指标保留
  -> POST /api/video-submit 编辑写入
```

`src/lib/conversion-hub` 与 `src/lib/case-library` 虽然属于已下线的案例生态，但仍被视频提交链路使用，不能按目录名删除。

  -> TopicHubV2
  -> pool / detail / claims / works / claim / return 等动态接口

`/topics/[id]` 只是深链兼容入口，服务端重定向到 `/topics?topic_id=...`，详情抽屉继续由 `/topics` 页面处理。
