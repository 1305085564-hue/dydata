# 颜色替换任务提示词（需要语义判断，禁止机械替换）

> 目标：将存量的"漂移色"与"近白底色"替换为28色系统的语义类名
> 要求：**必须判断使用场景，不得机械替换**
> 执行模型：Haiku / Sonnet（轻量快速）
> 验证：每批次替换后必须 `npm run build` + 目视检查

---

## 一、核心原则（必读3遍）

### ❌ 错误做法：机械替换
```bash
# 这是错的！不要这样做！
sed -i 's/#57534E/text-ink-body/g' **/*.tsx
```

**为什么错：**
- `#57534E` 在当前仓库里只作为异常文字使用，正确映射只有一种：`text-ink-body`（`#1F1E1D`）
- 但全局 sed 会把 `style={{ color: '#57534E' }}`、注释、字符串和其他语境一起改掉
- 如果未来出现 `bg-[#57534E]`，它不是文字色，不能替换成 `text-*`，必须停下并报告

### ✅ 正确做法：判断语境后替换
```tsx
// 读取文件，找到每个颜色的使用位置
// 判断：这个颜色用在哪里？
// - 用在 className="text-[#57534E]" → 统一替换成 text-ink-body
// - 用在 style={{color: '#57534E'}} → 替换成 style={{color: 'var(--ink-body)'}}
// - 用在 className="bg-[#57534E]" → 停下报告，不要替换（当前仓库不应存在这种用法）
// - 禁止把 #57534E 替换成 text-ink-muted；淡红底上只有 4.09:1，不达标
```

## 二、替换清单（按优先级排序）

### 阶段1：替换"文字色漂移"（影响最广）

这些颜色**只出现在文字上**，可以安全替换。

| 原色值 | 语义判断 | 替换目标 | 出现次数 | 验证点 |
|---|---|---|---|---|
| `#57534E` | 异常文字漂移色,统一用正文墨 | `text-ink-body` | 约7次 | 淡红底上`#1F1E1D`对比度14.20:1 |
| `#9A4D32` | 深橙文字(今日待办专用) | `text-ink-body` + `border-action` | 约2次 | 今日待办标签,保留橙边 |
| `#A55246` | 深橙文字(孤儿) | `text-ink-body` 或 `text-action-hover` | 约1次 | 先查用途,再决定 |

**判断规则:**
```
IF 这个颜色用在 className="text-[#hex]"
  THEN 判断:
    IF 它是#57534E(历史异常文字色)
      → 统一替换成 text-ink-body(正文墨#1F1E1D)
      → 理由:异常文字必须用正文墨(淡红底上14.20:1),不用元数据墨(淡红底上4.09:1不达标)
    ELSE IF 它修饰的内容是"表头/字段名/单位/次要说明"
      → 替换成 text-ink-muted
    ELSE IF 它修饰的内容是"主要文字/数据/正文"
      → 替换成 text-ink-body
    ELSE
      → 询问阿禅或跳过
ELSE IF 用在 style={{color: '#hex'}}
  → 替换成 style={{color: 'var(--ink-body)'}}
ELSE IF 用在 className="bg-[#hex]" 或 border-[#hex]
  → 暂不替换,记录位置,留待阶段2
```

---

### 阶段2：替换"状态色漂移"（需要语义判断）

这些颜色的替换**取决于使用场景的语义**。

| 原色值 | 可能语义 | 判断依据 | 替换目标 |
|---|---|---|---|
| `#B05B5B` | 异常主色（圆点） | 用在圆点、图标、图表 | `bg-status-danger` |
| `#C75D5D` | 异常主色漂移 | 同上 | `bg-status-danger` |
| `#2E7D32` | 成功主色/淡底 | 看上下文：圆点用主色，底色用淡底 | `bg-status-success` 或 `bg-status-success-bg` |
| `#B45309` | 待处理淡底 | 用在标签背景 | `bg-status-warning-bg` |
| `#F2E1E1` | 异常淡底悬停 | 异常标签的 hover 态 | `bg-status-danger-bg` |

#### 阶段2b：`#A15C5C`（旧异常红，AI 配置页 102 处）

不能一刀切换成文字色。按用法分流：

| 用法 | 预期数量 | 替换目标 |
|---|---:|---|
| `text-[#A15C5C]` 纯文本 | 26 | `text-status-danger-text`（`#1F1E1D`） |
| `text-[#A15C5C]` 图标 | 5 | `text-status-danger`（`#C0685C`） |
| 图标+文字共用父级 `text-[#A15C5C]` | 7 | 父级 `text-status-danger-text`，子图标补 `text-status-danger` |
| `border-[#A15C5C]/xx` | 23 | `border-status-danger/原透明度` |
| `bg-[#A15C5C]/5、/8、/10` 淡底 | 16 | `bg-status-danger/[0.05]`、`/[0.08]`、`/[0.10]`，保留原强度 |
| `bg-[#A15C5C]` 圆点/破坏性实心按钮 | 6 | `bg-status-danger`（允许实底，仅限圆点和破坏性动作） |
| `ring-[#A15C5C]/40` | 4 | `ring-status-danger/40` |
| `hover:text-[#A15C5C]` 删除图标 | 4 | `hover:text-status-danger` |
| `hover:bg-[#A15C5C]/90` 实心按钮 | 2 | `hover:bg-status-danger/90` |
| `hover:bg-[#A15C5C]/10、/15` 淡底 | 8 | `hover:bg-status-danger/[0.10]`、`/[0.15]` |
| `divide-[#A15C5C]/15` | 1 | `divide-status-danger/15` |

规则：
- 文字一律用 `text-status-danger-text`，图标一律用 `text-status-danger`；父级同时含图标和文字时，父级用文字色，子图标单独补主色。
- 多档淡底保留原透明度，不要全部压成 `#F7EAEA`；这不新增 hex。
- 已经是 `bg-[#F7EAEA]` 的地方，换成 `bg-status-danger-bg`，观感不变。

**判断规则：**
```
STEP 1: 读取该颜色所在的组件代码
STEP 2: 判断用途
  IF 这是一个圆点 (className 包含 "rounded-full" 且尺寸 w-1.5 h-1.5)
    → 用主色：bg-status-{语义}
  ELSE IF 这是一个标签背景 (有文字在内部)
    → 用淡底：bg-status-{语义}-bg
  ELSE IF 这是图表/图标
    → 用主色：text-status-{语义} 或 bg-status-{语义}
  ELSE
    → 跳过，记录位置

STEP 3: 判断语义
  IF 代码里有 "error" "删稿" "限流" "异常" 等关键词
    → 异常语义：status-danger
  ELSE IF 有 "success" "达标" "上涨" "完成" 等关键词
    → 成功语义：status-success
  ELSE IF 有 "warning" "待审" "待处理" 等关键词
    → 待处理语义：status-warning
  ELSE IF 有 "info" "进行中" "位置" 等关键词
    → 进行中语义：status-info
  ELSE
    → 跳过，询问阿禅
```

**示例：**
```tsx
// 原代码
<div className="flex items-center gap-1">
  <span className="w-1.5 h-1.5 rounded-full bg-[#B05B5B]" />
  删稿
</div>

// 判断过程：
// 1. 这是圆点（rounded-full + w-1.5）
// 2. 旁边文字是"删稿" → 异常语义
// 3. 替换目标：bg-status-danger

// 替换后
<div className="flex items-center gap-1">
  <span className="w-1.5 h-1.5 rounded-full bg-status-danger" />
  删稿
</div>
```

### 阶段3：合并"近白底色"（需要判断层级）

这些颜色的替换**取决于它在哪个层级**。

| 原色值群 | 判断依据 | 替换目标 |
|---|---|---|
| `#FAF9F7` `#FAF9F8` `#FAF9F6` `#FAF8F5` `#FAFAFA` | 看层级：页面底 / 行悬停 / 浅砂底 | 见下方决策树 |
| `#F7F7F5` | 行悬停 | `bg-surface-row-hover` |
| `#F4F4F2` `#EFEFEC` `#F0F0ED` | 浅砂底 | `bg-surface-sand` |
| `#E5E5E0` | 边框 | `border-[var(--border)]` |

**判断规则：**
```
STEP 1: 读取该颜色所在的元素标签
STEP 2: 判断层级
  IF className 包含 "min-h-screen" 或这是 <body> 或最外层容器
    → 页面底：bg-surface-canvas
  ELSE IF className 包含 "hover:" 或父级有 group-hover
    → 行悬停：bg-surface-row-hover
  ELSE IF 这是卡片内部的分组底色
    → 浅砂底：bg-surface-sand
  ELSE IF 这是表格行的背景（与 hover 交替）
    → 行悬停：bg-surface-row-hover
  ELSE
    → 跳过，询问阿禅

STEP 3: 检查语境
  IF 替换后，父子层级的背景色会冲突（同色套同色）
    → 跳过，记录位置，留待人工处理
  ELSE
    → 执行替换
```

**示例：**
```tsx
// 原代码
<div className="min-h-screen bg-[#FAF9F7]">
  <div className="bg-white rounded-xl p-4">
    <Table>
      <TableRow className="hover:bg-[#F7F7F5]">
        ...
      </TableRow>
    </Table>
  </div>
</div>

// 判断过程：
// 1. #FAF9F7 在 min-h-screen → 页面底 → bg-surface-canvas
// 2. #F7F7F5 在 hover: → 行悬停 → bg-surface-row-hover

// 替换后
<div className="min-h-screen bg-surface-canvas">
  <div className="bg-white rounded-xl p-4">
    <Table>
      <TableRow className="hover:bg-surface-row-hover">
        ...
      </TableRow>
    </Table>
  </div>
</div>
```

## 三、执行流程（逐个文件处理）

### 步骤1：查找该颜色的所有出现位置
```bash
grep -rn "#57534E" src/ --include="*.tsx" --include="*.ts"
```

### 步骤2：逐个位置判断语境

**必须回答的3个问题：**
1. 这个颜色用在什么属性上？(`text-*` / `bg-*` / `border-*` / `style`)
2. 这个颜色修饰的内容是什么？（表头 / 正文 / 圆点 / 标签背景 / 页面底）
3. 这个内容的语义是什么？（元数据 / 异常 / 成功 / 页面级 / 行级）

### 步骤3：根据决策树替换

**不要一次性替换所有文件！**
- 每次只替换 5-10 个文件
- 替换后立即 `npm run build`
- 如果构建失败，立即回滚，检查哪里替换错了

### 步骤4：目视验证

**必须检查的点：**
- [ ] 文字颜色没有变成背景色（`text-*` 没有写成 `bg-*`）
- [ ] 背景色没有变成文字色（`bg-*` 没有写成 `text-*`）
- [ ] 异常/成功/待处理的语义没有搞混
- [ ] 页面底/行悬停/浅砂底的层级没有搞混
- [ ] 没有出现"同色套同色"（父子都是 `bg-surface-sand`）

## 四、特殊案例处理

### 案例1：今日待办的橙色（`#9A4D32`）

**原代码：**
```tsx
<Badge className="text-[#9A4D32] border-[#D97757]">今日待办</Badge>
```

**判断：**
- 这是一个强调标签，但不是主 CTA
- 橙边保留（`border-action`），橙字改成深墨（可读性）

**替换后：**
```tsx
<Badge className="text-ink-body border-action">今日待办</Badge>
```

**原因：**
- 橙字 `#9A4D32` 在白底上对比度不足（违反 WCAG）
- 改用深墨 `text-ink-body`，保留橙边 `border-action` 即可传达"强调"

---

### 案例2：AI配置页的"健康点与文字双轨"

**原代码：**
```tsx
<div className="flex items-center gap-2">
  <span className="w-2 h-2 rounded-full bg-[#6FAA7D]" />
  <span className="text-[#4B6B4E]">健康</span>
</div>
```

**问题：**
- 圆点用规范绿 `#6FAA7D`（主色）
- 文字用降档绿 `#4B6B4E`（文字色）
- 这是隐式的"双轨"，应该显式统一

**替换后：**
```tsx
<div className="flex items-center gap-2">
  <span className="w-2 h-2 rounded-full bg-status-success" />
  <span className="text-status-success-text">健康</span>
</div>
```

**原因：**
- 圆点 → 主色角色 → `bg-status-success`
- 文字 → 文字角色 → `text-status-success-text`
- 显式统一：都属于"成功语义"，只是角色不同

---

### 案例3：表格行悬停的近白底

**原代码：**
```tsx
<TableRow className="hover:bg-[#FAF9F7]">
  <TableCell className="text-[#78716C]">...</TableCell>
</TableRow>
```

**判断：**
- `#FAF9F7` 用在 `hover:` → 行悬停
- 但要检查：有没有与其他层级冲突？

**检查：**
```tsx
// 如果外层是这样
<div className="bg-[#F7F7F6]"> // 这也是近白
  <Table>
    <TableRow className="hover:bg-[#FAF9F7]"> // 这也是近白
      ...
    </TableRow>
  </Table>
</div>
```

**判断：**
- 外层 `#F7F7F6` 应该是"页面级浅底" → `bg-surface-canvas` 或 `bg-surface-sand`
- 内层 `#FAF9F7` 应该是"行悬停" → `bg-surface-row-hover`
- 两者不同，不冲突 ✅

**替换后：**
```tsx
<div className="bg-surface-sand">
  <Table>
    <TableRow className="hover:bg-surface-row-hover">
      <TableCell className="text-ink-muted">...</TableCell>
    </TableRow>
  </Table>
</div>
```

## 五、禁止事项（红线）

### ❌ 禁止1：全局搜索替换
```bash
# 这是错的！不要做！
find . -name "*.tsx" -exec sed -i 's/#57534E/text-ink-body/g' {} \;
# 即使目标 token 正确，也不能全局 sed：会误改 style、注释、字符串和非文字用法
```

### ❌ 禁止2：不看语境直接替换
```tsx
// 错误示例
// 原代码
<div className="bg-[#57534E]">背景</div>
// 机械替换成
<div className="text-ink-body">背景</div>
// ❌ bg-* 变成了 text-*，样式错乱；正确做法是停下报告，当前仓库不应有 #57534E 作背景
```

### ❌ 禁止3：跨阶段一次性替换
```bash
# 错误：一次性替换所有颜色
# 应该：先做阶段1，验证通过，再做阶段2
```

### ❌ 禁止4：替换后不验证构建
```bash
# 错误：替换 50 个文件后才运行 npm run build
# 正确：每 5-10 个文件就验证一次
```

## 六、验收标准（每批次）

### 技术验收
- [ ] `npm run build` 通过
- [ ] `npm run lint` 无新增错误
- [ ] `npm run gate:design` 通过（如已更新门禁）

### 视觉验收
- [ ] 打开受影响的页面，目视检查颜色正确
- [ ] 表头、字段名、辅助说明仍然是元数据墨（浅灰）
- [ ] 正文、数据仍然是正文墨（深灰）
- [ ] 状态标签的圆点、淡底、文字三者协调
- [ ] 表格行悬停时背景色正确

### 语义验收
- [ ] 异常用红、成功用绿、待处理用琥珀，没有搞混
- [ ] 页面底、行悬停、浅砂底的层级清晰，没有"同色套同色"
- [ ] 主 CTA 仍然是唯一的饱和实底（橙色），没有被状态色抢光

## 七、执行建议（给轻量模型的提示）

**你是一个谨慎的颜色替换助手，你的职责是：**
1. 逐个文件读取代码
2. 找到每个待替换颜色的使用位置
3. 判断它的用途（文字 / 背景 / 边框 / 圆点）
4. 判断它的语义（元数据 / 异常 / 成功 / 页面底 / 行悬停）
5. 根据决策树选择替换目标
6. 执行替换
7. 验证构建

**当你不确定时，不要替换，记录位置，留给人工处理。**

**你每次替换后，都要说明：**
- 替换了哪个文件的第几行
- 原色值是什么
- 替换成什么
- 为什么这样替换（判断依据）

**示例输出：**
```
替换 src/components/VideoTable.tsx:42
原: className="text-[#57534E]"
替换: className="text-ink-body"
依据: #57534E 是历史异常文字色，统一用正文墨 #1F1E1D；不能按表头语义改成元数据墨
```
