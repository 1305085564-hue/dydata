## 一、接口契约（前端后端共同遵守，双方不得擅自变更）

### 1.1 `sync_key_models` 返回结构变更（本次唯一破坏性变更）

**现状问题**：返回 `syncResult.models` = `newModels`（仅本次新入库），导致前端弹窗显示「已启用 2 / 0 个型号」自相矛盾。

**契约要求**：`syncResult` 必须改为返回该渠道**全部**模型，并带分类标记。

```ts
type SyncKeyModelsResult = {
  keyId: string;
  allModels: Array<{
    modelId: string;
    displayName: string | null;   // 有则用，无则前端兜底
    isEnabled: boolean;           // 本渠道 ai_provider_key_models.is_enabled
    isGlobalActive: boolean;      // 该 model_id 是否全站现役（任一渠道 is_enabled=true）
    isNewlyDiscovered: boolean;   // 本次同步是否新入库
  }>;
  // 兼容保留：本次新入库的数量，仅供日志
  newCount: number;
};
```

**禁止**：继续把 `newModels` 作为弹窗数据源；禁止只返回增量。

### 1.2 `test_key_all_models` 范围扩展

**现状问题**：`route.ts:731-732` 有 `.eq("is_enabled", true)` 过滤，只测已勾选模型。

**契约要求**：去掉该过滤，测该渠道 `ai_provider_key_models` 中**全部**挂载模型（含 `is_enabled=false`）。

返回结构：

```ts
type TestKeyAllModelsResult = {
  keyId: string;
  results: Array<{
    modelId: string;
    ok: boolean;
    latencyMs: number | null;
    error: string | null;         // 失败必须给出可读原因
  }>;
  total: number;      // 测了几个
  successCount: number;
  failureCount: number;
  failedModelIds: string[];
};
```

### 1.3 `test_all_keys_all_models` 范围扩展

同 1.2 去掉 `is_enabled` 过滤，测全部渠道 × 各渠道全部挂载模型。

返回结构：

```ts
type TestAllKeysAllModelsResult = {
  totalKeys: number;
  totalModels: number;
  successCount: number;
  failureCount: number;
  failures: Array<{ keyId: string; keyLabel: string; modelId: string; error: string | null }>;
};
```

### 1.4 `create` entity=key 的隔离要求

见任务 3，本次必须修复。修复后契约：**新建渠道的模型勾选只影响该 key_id 的行**，不得触碰其他渠道。

## 二、后端施工任务

### 任务 3（最高优先级）：修复跨渠道数据污染 bug

**文件**：`src/lib/ai-config/batch-actions.ts:193-198`

```ts
.update({ is_enabled: true }).in("model_id", selectedModelIds)   // 缺 key_id 过滤
```

**问题**：接入新渠道并勾选模型时，会把**所有渠道**的同名模型行强制启用。

**修法**：补 `key_id` 限定，仅作用于本次新建的 key。

**必须带回归测试**：新建渠道勾选模型 → 断言其他渠道同名模型的 `is_enabled` 未被改动。

### 任务 1（后端部分）：同步接口返回全量

按 1.1 契约改造 `src/app/api/admin/ai-config/sync-models/route.ts` 与 `src/lib/ai-config/batch-actions.ts`。

- 同步逻辑仍先请求上游 `/models` 并入库（保留现有 6 秒超时与失败抛错行为）。
- 返回时改为查该 key 的全部 `ai_provider_key_models` 行，组装 `allModels`。
- `isNewlyDiscovered` 取本次 insertedModelIds 集合。
- `isGlobalActive` 由该 model_id 是否存在任一 `is_enabled=true` 行判定。

### 任务 2（后端部分）：检测范围扩展

按 1.2 / 1.3 契约改造 `route.ts` 的 `test_key_all_models`（726-740）与 `test_all_keys_all_models`。

- 去掉 `is_enabled` 过滤。
- 失败必须回传可读原因，不得吞掉。
- 结果回写健康状态的逻辑保持不变。
