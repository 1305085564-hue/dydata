## 真实代码基线

改造前的算力池已经通过 PoolViewSwitcher 提供“模型视角”“分组视角”“渠道视角”三种入口。此次改造只升级渠道视角，把其中的渠道内容改成左右分栏；模型视角、分组视角和业务功能绑定面板继续复用原实现。

GET /api/admin/ai-config 返回的 AiConfigBundle 字段是：

- providers
- keys
- models
- featureBindings
- featureControls

密钥前端类型只接收 api_key_masked（脱敏值，显示为 *** 后四位）；前端不接收也不展示明文密钥。

渠道和模型健康状态统一复用 src/lib/ai/provider-routing.ts 的：

- getProviderKeyHealthStatus
- getProviderKeyModelHealthStatus

文档不自行复制健康判定阈值，避免和路由实现产生分叉。

## 实现内容

### 1. 渠道列表

文件：src/app/(app)/admin/ai-config/components/channel-list.tsx

- 按 priority 升序展示 bundle.keys。
- 显示渠道标签、服务商名称和健康指示器。
- 支持当前渠道选择、键盘访问和超过五个渠道时的搜索。
- 状态点复用真实健康判定：健康、熔断/待测、禁用。

### 2. 模型卡片

文件：src/app/(app)/admin/ai-config/components/model-cards.tsx

- 按显示名称排序，以响应式网格展示模型。
- 显示模型名称、状态、全局启用开关和单模型检测按钮。
- 开关的 checked 由同一 model_id 在所有渠道记录中是否存在 is_enabled 为真来判断。
- 开关复用 compute-pool-panel.tsx 已有的 handleShelfChange，调用全局上下架 action；服务端返回 409 时原样显示失败原因。
- 单模型检测继续调用真实的 test_key_model。

### 3. 渠道详情

文件：src/app/(app)/admin/ai-config/components/channel-pool-view.tsx

- 左侧为固定宽度渠道列表，右侧为当前渠道详情。
- 右侧显示脱敏密钥、服务商地址、渠道状态和模型卡片。
- “检测渠道”“同步模型”“编辑”按钮使用已有回调。
- 同步弹窗仍按渠道保存模型选择；渠道级选择和全局模型上下架保持不同职责。

### 4. 数据调用

文件：src/app/(app)/admin/ai-config/hooks/use-ai-config.ts

- 复用已有渠道测试、模型同步、渠道模型选择和全局上下架调用。
- 增加单模型检测的前端回调，使用 test_key_model 并回写最新 bundle。

## 真实接口表

| 功能 | 请求 | action | data |
|---|---|---|---|
| 拉取配置 | GET /api/admin/ai-config | — | 返回 providers / keys / models / featureBindings / featureControls |
| 同步单渠道模型 | POST /api/admin/ai-config | sync_key_models | { key_id } |
| 保存单渠道模型选择 | POST /api/admin/ai-config | set_key_model_selection | { key_id, model_ids } |
| 全局模型上架/下架 | POST /api/admin/ai-config | set_global_model_shelf_state | { modelId, is_enabled } |
| 检测渠道 | POST /api/admin/ai-config | test_key | { key_id, model_id?, test_mode? } |
| 检测单个模型 | POST /api/admin/ai-config | test_key_model | { key_id, model_id } |
| 检测全部渠道 | POST /api/admin/ai-config | test_all_keys | 无 |

全局模型上下架由既有处理逻辑保护独占使用中的模型；前端只展示返回结果，不复制保护规则。

## 验收清单

- 进入 /admin/ai-config 可见三视角切换，默认进入渠道视角。
- 选择渠道后，右侧显示该渠道的脱敏密钥、地址和模型卡片。
- 模型开关显示全局状态，并通过全局上下架调用保存。
- 独占使用中的模型下架收到 409 时开关不伪造成功，并显示失败原因。
- 单模型检测回写健康状态并显示结果。
- 同步模型打开原有勾选弹窗，保存仍使用渠道模型选择接口。
- 运行 npm test、npx tsc --noEmit --pretty false、定向 ESLint、npm run build。
- 浏览器验收需使用测试账号完成选渠道、全局开关、409 拦截、单模型检测和同步弹窗保存。
