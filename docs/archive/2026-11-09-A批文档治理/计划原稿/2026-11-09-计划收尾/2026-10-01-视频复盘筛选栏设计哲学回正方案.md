## 三、专项汇报：SelectTrigger 与 Input 在 size="sm" 下的字号不一致

在 `src/components/ui/` 基础组件库中发现以下事实：
1. **Input 组件**（`ui/input.tsx`）：
   ```tsx
   size === "sm" && "h-7 px-2.5 py-1 text-[12px]"
   ```
   其小号尺寸明确绑定了 **12px**。
2. **SelectTrigger 组件**（`ui/select.tsx`）：
   ```tsx
   data-[size=sm]:h-7
   ```
   其高度虽然是 28px（`h-7`），但文字字号**继承了基础类的 `text-[13px]`**，并未显式下调到 12px。

**潜在问题**：
如果直接在业务侧移除手写覆盖、完全交给 `size="sm"`，页面上的下拉框会显示 13px，而输入框会显示 12px，造成同一行工具栏内的文字大小轻微参差。

**当前处置**：
本次改动**严格遵照阿禅指示**，业务文件中的字号暂不改动，维持当前两者的平齐视觉。

**建议后续拍板方案**：
在 `src/components/ui/select.tsx` 的 `SelectTrigger` 中，将 `data-[size=sm]:text-[12px]` 补齐（遵循《设计规范》§1.1 元数据/次级控件 12px 契约），届时全站所有 `size="sm"` 的 Select 与 Input 便能完全统一，再顺理成章移除业务代码的覆盖。
