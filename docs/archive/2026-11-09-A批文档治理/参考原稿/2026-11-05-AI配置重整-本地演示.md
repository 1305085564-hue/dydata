# AI 配置重整 · 本地演示

脚本会在本地 Supabase 写入固定前缀 `codex-local-demo-ai-config-` 的演示渠道，并启动只绑定 `127.0.0.1` 的进程内假上游。数据库地址和上游地址都必须是 `http://127.0.0.1:<端口>`；`localhost`、局域网地址、域名、IPv6 和公网地址都会被拒绝。

先启动本地 DYData 页面。脚本读取 `.env.ai-test.local`；该文件不存在时读取 `.env.local`，只使用 `NEXT_PUBLIC_SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY`，不显示凭据。

## 演示

```bash
node --import tsx scripts/ai-config-local-demo.ts --run
```

保持运行脚本的终端打开，再访问本地 AI 配置页。使用上面的直接启动命令可确保 Ctrl+C 交给脚本处理并完成清理。启动状态会显示正常业务、默认顶班，以及能用、暂时歇着、需要处理、已停用的渠道；唯一前缀模型用于演示“只剩 1 条”。同一个找渠道模型会出现两条候选：一条假 token 测通，另一条返回 404 并保持关闭。上游模型清单也包含 `claude-haiku-5-5` 和 `claude-haiku-5.5` 两种写法。

另开终端可切换业务场景：

```bash
node --import tsx scripts/ai-config-local-demo.ts --scenario normal
node --import tsx scripts/ai-config-local-demo.ts --scenario outage
node --import tsx scripts/ai-config-local-demo.ts --scenario retrying
```

正常场景同时展示正常与默认顶班。停摆和仍在自动重试的停摆需要让全局默认模型不可用，因此不能与默认可用时的顶班状态同时出现。

## 清理

正常结束时在演示终端按 `Ctrl+C`，脚本会还原演示前的业务绑定并删除演示地址组、渠道和模型。若进程异常退出，先确认没有演示进程仍在运行，再执行：

```bash
node --import tsx scripts/ai-config-local-demo.ts --cleanup
```

脚本只删除状态文件记录的演示地址组及其自有子记录。发现额外记录或业务绑定已被改动时会保留冲突数据并报告，不覆盖当前值。一次性实测可运行 `--verify`，它会检查本地 Supabase、假上游 HTTP 成功/失败、状态场景和地址拒绝，并在结束时自动清理。
