# 导粉话术提交失败修复 + 界面对齐，上线核对（2026-10-27）

## 1. 现象

数据上传（`/dashboard` 今日提交）填了「导粉数 > 0」并写话术，点提交后右下角弹「替换话术使用记录失败」，整笔提交没有落库。

## 2. 根因（实测）

保存话术要向数据库提交 12 项参数，但代码只发了 11 项：`replaceDailyReportUsageRecord` 的 payload 未包含 `result_flag`，`p_result_flag` 为 `undefined`，而 `postgrest-js` 用 `JSON.stringify(body)` 组包会把 `undefined` 键**整体丢弃**（源码 `dist/index.mjs:299`、`:3849`），PostgREST 因此匹配不到 12 参函数。

生产只读探针（用故意非法的 uuid 触发参数绑定失败，不产生任何写入）：

| 调用 | 结果 |
|---|---|
| 12 参（含 `p_result_flag`） | HTTP 400 / `22P02` invalid input syntax for uuid → 函数存在且参数匹配成功 |
| 11 参（＝线上代码实发） | HTTP 404 / `PGRST202` Could not find the function …(11 参)，hint 明确应带 `p_result_flag` |

## 3. 影响窗口

- `script_usage_records` 中 `source='daily_report'` 的最后一条写入：**2026-06-05**。
- `daily_reports.follower_convert > 0` 的最近日期：**2026-06-05**。
- 2026-07-18 `d18eeffc` 把「先删后插」换成单 RPC 起，这条分支即成为死路（推测，与上述两条实测自洽）：凡是「导粉 > 0 且填了话术」的提交必然整单回滚。因 4 个多月无人走到该分支（导粉数长期填 0），直到 10-26 首次触发才暴露。
- 数据影响：撞上弹窗的提交整单回滚、未入库；不存在历史脏数据。6 月以来无漏录。
