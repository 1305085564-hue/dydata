# DYData 全量缓存总账

更新时间：2026-10-24  
覆盖范围：公开页面、静态资源、89 个 API 路由、浏览器缓存、页面内缓存、服务端短缓存、截图文件读取。

## 先看结论

缓存分成三种，不能混为一谈：

1. **公共缓存**：所有人拿到同一份内容，例如版本固定的脚本文件。Cloudflare 可以直接复用。
2. **私有缓存**：只给当前用户、当前公司或当前团队复用，例如视频复盘列表。它能减少重复查询，但不能给所有人共用。
3. **不缓存**：每次都要重新确认权限、状态或执行写入，例如登录、审批、同步、健康检查。

当前线上真正确认命中 Cloudflare 公共缓存的，只有 Next.js 的静态脚本、样式和其他带版本指纹的静态文件。线上动态页面和 API 仍显示 `CF-Cache-Status: DYNAMIC`，这是现在的安全规则。

本轮之前已经存在的缓存，主要是私有缓存和静态资源缓存；我上一轮错误地提前做的“新缓存”只有注册页团队列表这一项，而且**代码已提交但尚未 push、尚未上线、尚未在 Cloudflare 打开例外规则**，所以现在不能说它已经产生线上收益。

| `/` 首页 | 不进公共缓存 | Cloudflare 当前规则将首页视为动态路径；页面公开但以后仍需单独评估是否接受内容延迟 |

| `/dashboard`、`/admin/*`、`/topics/*`、`/people/*`、`/douyin/*` | 不进公共缓存 | 登录后页面包含权限和业务数据 |
| `/privacy`、`/terms` | 当前没有确认线上缓存收益 | 本地有页面文件，但生产域名当前曾返回 404；部署后可另设 1 小时公共缓存 |
| `/_next/static/*` | 公共缓存已生效 | 当前唯一确认的 Cloudflare 公共缓存主体 |
| 广州 COS 中的截图对象 | 文件存储，不等于 CDN 缓存 | 已解决截图跨区域读取问题；当前业务接口仍做权限校验 |

## 六、Cloudflare 当前实际状态

已有规则把首页、后台、登录、API、主题和其他动态业务路径放在绕过缓存范围内，只缓存 `/_next/static/`。线上观测与这个规则一致：

- 静态 JS/CSS：`CF-Cache-Status: HIT`。
- 首页：`CF-Cache-Status: DYNAMIC`。
- 健康检查 API：`CF-Cache-Status: DYNAMIC`。

Cache Reserve 是否开启，单靠公开响应无法确认；而且 Cache Reserve 只会延长“本来就允许缓存”的内容保存时间，不会把带登录权限的数据库接口变成安全的公共缓存。

## 七、对“尽可能全走缓存”的准确结论

目前能安全放进 Cloudflare 公共缓存的业务数据非常少：

- **已经生效**：静态脚本、样式、字体等版本固定文件。
- **可以增加**：注册页团队下拉列表；公开协议页部署后也可以增加。
- **不能增加**：视频复盘、数据库列表、看板、选题、人员、履约、审批、抖音账号、AI 配置、导出和所有写入接口。

真正能改善视频复盘速度的方向不是把这些权限数据塞进公共缓存，而是继续扩大“按用户/团队隔离的服务端缓存”，或者为明确的只读派生数据做带版本和权限边界的广州副本。此前测速已经证明广州静态快照的读取阶段更快，但那不能直接替代数据库的权限过滤、排序和实时计算。
