## 3. 步骤

### F0 · 切换前补迁（必做，约 5 分钟）


### F1 · 切换前留基线（1 分钟）

### F2 · 切换（约 3 分钟）

1. Vercel → 项目 `dydata` → Settings → Environment Variables → Production → `SCREENSHOT_STORAGE` 设为 `cos`。
2. Deployments → 最近一次 Production → **Redeploy**（改变量不会自动生效）。
3. 等状态 `Ready`。

### F3 · 切换后立即自检（5 分钟内）

用**真实登录态**取 2 张真实图（一张 10 月新图、一张 6 月老图），确认：

| 检查项 | 期望 |
|---|---|
| HTTP | `200` |
| `X-Screenshot-Backend` | `cos` |
| `X-Screenshot-Fallback` | `0` |
| `Cache-Control` | 新图 `max-age=1800`；老图 `max-age=2592000` |

**任一项不符 → 进第 5 节回退。**

### F4 · 盯 2 小时（这是重点，不是走过场）

| 指标 | 采集方式 | 红线 |
|---|---|---|
| 回退率 | 日志里 `read_fallback` 条数 / `read` 总条数 | >5% 回退 |
| `write_failed` | 日志计数 | **出现任何一条就回退** |
| 5xx 率 | 截图接口状态码分布 | 明显抬头 |
| 抽样耗时 | 随机 5 张取 `total_ms` | 持续 >3s |

## 4. 回退后的真实语义（别写错）

如果回退到 `supabase`：

- **历史 3,264 张**：走 Supabase 主读，快。
- **切换期间新上传的图**：Supabase 没有副本，但读逻辑会**自动回退到 COS**（`fallback_reason=supabase_primary_failed`），**仍然能看到，只是慢**。
- **真正救不回的只有一种**：COS 写失败的那些图——接口当时返回 500，用户重传即可，回滚变不出来。

所以「回退后新图全丢」是错的，别这么写。
