## 三、问题根源分析

### 3.1 关键发现

1. **`content_items` 表的存在性存疑**
   - 在整个代码库中，`content_items` 只在一处被引用（发布履约RPC）
   - 没有找到 `content_items` 表的 CREATE TABLE 或 CREATE VIEW 语句
   - 只找到 `content_item` 表（单数形式，用于新架构但未启用）

2. **两个数据源的分离**
   - 发布履约：查询 `content_items`（存在性存疑）
   - 历史手稿：查询 `daily_reports`
   - 如果两个表数据不同步，就会出现"一边能看到，一边看不到"的症状

### 3.2 可能的原因

#### 假设 A：`content_items` 是 `videos` 表的别名或视图

**如果成立**：
- 发布履约查询的是 `videos` 表（通过 `content_items` 别名）
- 历史手稿查询的是 `daily_reports` 表
- **问题**：`daily_reports` 记录创建失败，但 `videos` 记录创建成功

**验证方法**：
```sql
-- 检查 content_items 是否存在
SELECT table_name, table_type 
FROM information_schema.tables 
WHERE table_name = 'content_items';

-- 检查是否是视图
SELECT definition 
FROM pg_views 
WHERE viewname = 'content_items';
```

#### 假设 B：`content_items` 是错误的表名（BUG）

**如果成立**：
- 20260806的修复引入了错误的表名
- 发布履约 RPC 实际上在查询一个不存在的表
- **问题**：RPC 应该报错，但如果没报错，说明 PostgreSQL 有某种容错机制

**验证方法**：
```sql
-- 直接执行发布履约 RPC，看是否报错
SELECT * FROM get_fulfillment_range(
  '2026-10-01'::date, 
  '2026-10-13'::date, 
  NULL, 
  NULL, 
  NULL
);
```

#### 假设 C：`daily_reports` 记录被标记为无效

**如果成立**：
- `daily_reports` 记录存在，但 `is_void = true`
- 历史手稿查询时过滤掉了 `is_void = true` 的记录
- **问题**：为什么何静和张超的记录会被标记为无效？

**验证方法**：
```sql

  id,
  user_id,
  report_date,
  title,
  is_void,
  uploaded_at,
  created_at
FROM daily_reports
WHERE user_id IN (
  SELECT id FROM profiles WHERE name IN ('何静', '张超')
)
ORDER BY report_date DESC
LIMIT 20;
```

**方案**：

   - 修改所有查询逻辑统一使用 `content_item`
   - 废弃 `daily_reports` 表（或改为视图）
3. **长期**：建立数据一致性监控，定期检查不同表之间的数据同步状态

### 5.2 增强数据完整性约束

```sql
-- 1. 确保 videos 和 daily_reports 的关联完整性
-- 添加触发器：创建 video 后自动创建 daily_report
CREATE OR REPLACE FUNCTION auto_create_daily_report()
RETURNS TRIGGER AS $$
BEGIN
  -- 只有当 published_at 有值时才创建 daily_report
  IF NEW.published_at IS NOT NULL THEN
    INSERT INTO daily_reports (
      user_id,
      account_id,
      report_date,
      video_id,
      title,
      content,
      uploaded_at,
      is_void,
      data_source
    ) VALUES (
      NEW.user_id,
      NEW.account_id,
      NEW.published_at::date,
      NEW.id,
      NEW.video_title,
      NEW.content,
      NEW.uploaded_at,
      false,
      'auto'
    )
    ON CONFLICT (video_id, report_date) DO NOTHING;  -- 避免重复创建
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_auto_create_daily_report
AFTER INSERT OR UPDATE ON videos
FOR EACH ROW
EXECUTE FUNCTION auto_create_daily_report();

-- 2. 定期检查数据一致性
CREATE OR REPLACE FUNCTION check_data_consistency()
RETURNS TABLE (
  issue_type text,
  video_id uuid,
  user_id uuid,
  published_date date,
  details text
) AS $$
BEGIN
  -- 检查：videos 有记录但 daily_reports 没有
  RETURN QUERY
  SELECT 
    'missing_daily_report'::text,
    v.id,
    v.user_id,
    v.published_at::date,
    format('Video %s (user %s, date %s) missing daily_report', 
           v.id, v.user_id, v.published_at::date)
  FROM videos v
  LEFT JOIN daily_reports dr 
    ON dr.video_id = v.id 
    AND dr.report_date = v.published_at::date
  WHERE v.lifecycle_state = 'active'
    AND v.published_at IS NOT NULL
    AND dr.id IS NULL;

  -- 检查：daily_reports 有记录但 videos 没有
  RETURN QUERY
  SELECT 
    'missing_video'::text,
    dr.video_id,
    dr.user_id,
    dr.report_date,
    format('Daily report %s (user %s, date %s) missing video', 
           dr.id, dr.user_id, dr.report_date)
  FROM daily_reports dr
  LEFT JOIN videos v ON v.id = dr.video_id
  WHERE dr.is_void = false
    AND v.id IS NULL;
END;
$$ LANGUAGE plpgsql;
```
