## 唯一规则与边界

- `src/lib/ai/channel-governance.ts` 是五类身份的唯一判断来源。运行候选、汇总、删除依赖检查共同引用；旧四态字段仅作现有视图兼容。
- 身份互斥：`active` 正常在岗、`retest` 待复测、`sleeping` 休眠、`invalid` 失效、`disabled` 停用。仅前两类参与调度。
- 关闭供应商、Key、渠道模型或全站模型时优先判停用。凭据明确无效、模型明确不存在/不支持，或连续失败满 24 小时判失效。普通 403、额度和上游拦截不会直接判永久失效；明确的模型错误只影响该模型。
- 失效优先于休眠。手动、Key 自动、模型自动三个休眠截止时间取最晚值，表示实际可重回队列的时间；原始 `manual_sleep_until` 供独立展示手动倒计时。
- 自动冷却结束后为待复测；满 24 小时的失效不会因时间过去或“恢复调度”而解除，必须成功复测。
- 成功会清除对应自动失败周期，不清手动休眠。失败手测不改变自动健康；“仅记录”沿用当前测试反馈，不需要额外健康写入。
- 顶部按 Key 去重：多模型的 Key 取其最佳供给身份；没有挂载模型的启用 Key 计失效，不计可调度。模型卡按当前模型渠道计数，五类合计等于该层总数。不能把全池 Key 冗余代替某个模型的冗余。
- 冗余为 `max(可调度数 - 1, 0)`；`singlePointRisk` 在可调度数 ≤ 1 时为真。0 条表示没有供给，1 条表示单点，视图须据数量区分文案。
- 全量兜底保持原有跨模型位置；同一模型占用的位置按它自己的独立顺位填充。没有引入新的跨模型优先级产品规则。
- 同一次请求内某个 Key 失败后，后续若再次遇到该 Key 的另一个模型，会重读可调度状态，避免使用已经冻结的旧候选。
- 业务绑定、供应商密钥、收费和普通提交必须有识别发布时间的现行规则均未调整。全渠道失效后可以保图和手填指标，不代表普通新作品在没有可信发布时间时能直接提交。

## 给 Antigravity 的接口契约

`GET /api/admin/ai-config` 及休眠、恢复、交换成功响应都返回完整配置，并新增 `availability`。前端通过现有 `useAiConfig()` 使用；不要在组件重写五态或冗余判断。

| 数据 | 使用位置 |
| --- | --- |
| `availability.identityCounts`、`totalKeyCount`、`schedulableKeyCount`、`redundancyCount`、`singlePointRisk` | 顶部 Key 汇总；五类计数只用 `identityCounts`，不要与旧四态计数相加 |
| `availability.keys[]` | 按 `keyId` 找五态、`sleepSource`、`sleepUntil`、`persistentFailure` |
| `availability.modelFamilies[]` | 按 `modelId` 找当前模型的五类计数、冗余和单点风险；`channels[]` 含 `keyModelId`、`keyId`、`sortOrder` 和五态 |
| Key 的 `manual_sleep_until` | 手动休眠的独立倒计时；不要用它覆盖自动休眠 |
| Key、模型、单次测试、批量模型结果的 `failureDiagnostic` | `category` 为 provider/model_access/credentials/quota/unknown；`owner` 为 provider/configuration/unknown；`technical` 含脱敏 message、status、requestId；历史没有请求号时为 null |

管理动作仍需 `manage_system`：

```json
{"action":"sleep_key","data":{"key_id":"..."}}
{"action":"resume_key","data":{"key_id":"..."}}
{"action":"swap_model_channel_order","data":{"model_id":"...","key_model_id":"...","target_key_model_id":"..."}}
```

- `useAiConfig().setKeySleep(keyId, true/false)` 已提供；休眠从服务端当前时间起 30 分钟，恢复只清手动期限。
- `swapModelChannelOrder(modelId, keyModelId, targetKeyModelId)` 已提供；现有上下移动作已接入并经真实页面验证。只接受同模型的相邻两条，非相邻拒绝为 409。
- 原全局 `swap_key_priority` 与对应旧实现已删除；Key 更新 `priority` 明确拒绝。旧渠道视角的全局数值编辑和 P 数字需要在视觉接入时移除，不能继续调用它作为排序入口。
- 故障详情字段已补齐前端类型。实际展示文案、展开区、休眠按钮、倒计时、持续失效置底/折叠、模型顶部预警都留给 Antigravity。
- 现有页面尚保留旧四态视图兼容入口；视觉完成前，不把当前页面宣称为“五态展示已验收”。

上传入口每个 `SlotViewState` 已增加 `startedAt`、`phaseStartedAt`、`finishedAt`、`batchStartedAt`（毫秒）。`getUploadProgress(slots, now)` 提供两图各自状态、阶段与总耗时、当前处理槽位、整批长等待标志。视图负责定时刷新 `now`，按 `status` 呈现上传、识别、已完成、需核对、失败；计时逻辑不要复制到组件。串行两图的第二张仍引用整批开始时间，新批次不会继承旧图的等待时间。失败保图及手填提示沿用现有入口。

## 数据迁移与发布顺序

新增 `supabase/migrations/20261104120000_ai_channel_availability_governance.sql`，仅在隔离本地库执行：

1. 为 Key 和模型增加连续失败窗口、失效标记，Key 单独增加手动休眠截止时间。
2. 按旧的 Key＋供应商顺位及稳定 ID 初始化每个模型顺位；历史首败时间只从最后已知失败推算，不捏造更早历史。
3. 新增插入追加顺位、成功结束失败周期的触发器；失败 RPC 保留旧参数的默认调用兼容，额外接收永久失效标志。
4. 相邻交换 RPC 仅 `service_role` 可执行。管理接口先鉴权，再使用服务端管理客户端调用；真实页面曾发现用户客户端没有该 RPC 执行权，已修复并重验成功。

新应用依赖新列，必须先迁移，再发布应用；不提供吞掉迁移缺失错误的旧字段降级。发布时检查目标库函数权限、实际顺序与 schema cache，再做真实角色请求。本轮不证明生产迁移已生效，也不把本地库验证当作 CloudBase 平台验收。
