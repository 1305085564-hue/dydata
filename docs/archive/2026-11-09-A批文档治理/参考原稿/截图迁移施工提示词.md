## 3. 任务清单

### 阶段 A —— 缓存分档（代码 + 单测）

**改哪里**：`src/app/api/submission-screenshots/file/route.ts` 第 73 行，现为固定 `Cache-Control: private, max-age=1800`。

**改成两档**：

| 图龄 | 响应头 |
|---|---|
| ≤ 3 天 | `Cache-Control: private, max-age=1800`（30 分钟） |
| > 3 天 | `Cache-Control: private, max-age=2592000`（30 天） |

**图龄判定规则（必须严格照此实现）**：

- 取 **path 最后一段文件名**里的时间戳，形如 `2026-05-18T06-52-59-583Z-xxxx.jpg`，转为 UTC 时间。
- **禁止使用 `storage.objects.created_at`**：迁移过来的 5 月老图会被当成新图，直接判错。
- **禁止使用文件系统 mtime、上传时间、当前时间做近似**。
- 正在写第一张图（`path` 解析不出时间戳）时，**保守取 30 分钟**，不要取 30 天。
- 时间戳在未来（时钟漂移）时按「≤3 天」处理。

**缓存语义必须写进注释**：这是**私有缓存**，只存浏览器本地，不跨用户共享；不得在文档里把它描述成「首次加载优化」。

**完成定义**：

- [ ] 单测覆盖 4 种路径：3 天内的图 → 1800；4 天前的图 → 2592000；5 月老图 → 2592000；解析失败 → 1800。
- [ ] 现有单测 `route.test.ts:54` 里断言 `private, no-store` 的用例同步更新，不得为了让测试通过而放宽断言。
- [ ] `npm test` 全绿。
- [ ] 在方案文档 3.5 节写明：这是对 REQ-06「7 天 immutable」的**有意偏离**，理由与分档依据，不许写成「等价满足」。

### 阶段 C —— S4 写入失败负向验收

**为什么要做**：切到 COS 后新图**只写 COS，不写 Supabase**。写失败时若能「静默成功」，用户以为传上去了，实际丢了，且**回滚也救不回**。

**现有行为**（`src/lib/screenshot-storage.ts:163` + `src/app/api/submission-screenshots/route.ts:126`）：COS 写失败 → 返回 `{ok:false}` → 路由返回 `500 {"error":"截图上传失败，请稍后重试"}`，并打 `write_failed` 日志。**代码层面是对的，但没有测试证明它不会退化成静默成功。**

**要做**：写一条集成测试，注入 COS 写失败（mock `cosPutObject` 返回失败，或用错误密钥），断言三件事：

1. HTTP 状态码 **不是 200/201**（应为 500）。
2. 响应体 **不含** `path` / `url`（不能给出「已完成」的假象）。
3. 日志里出现 `write_failed`，且 `backend=cos`。

**完成定义**：

- [ ] 测试在 CI 里能跑，不依赖真实 COS。
- [ ] 测试名直白（如 `COS 写失败时上传接口必须报错，不得伪成功`）。
- [ ] 在方案文档写明：**该对象在 Supabase 无副本，回滚无法恢复**。
