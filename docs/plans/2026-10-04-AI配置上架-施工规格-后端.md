## 逻辑规格（六项）

### B1 根治"同步复活"地雷（D2）
`sync-models/route.ts`：现状对已存在记录无条件 `update is_enabled:true`（约 L114-121）——**删除该覆盖**。新规则：
- 仅对库中从未出现的新 model_id 做 insert，且 `is_enabled: false`
- 已存在记录（无论启用/停用）**一律不碰 is_enabled**
- 删除 `DEFAULT_RECOMMENDED_MODELS` 兜底猜热门逻辑（约 L75-81）：探测失败返回明确失败，禁止静默用猜单
- 测试：先手动下架某模型 → 触发同步 → 断言其仍为停用

### B2 全局联动上架/下架（D1/D3）
`route.ts` 新增 action `set_global_model_shelf_state`，入参 `{ modelId, is_enabled }`：
- **单事务**批量更新全库所有 Key 下该 model_id 的 is_enabled（要么全成要么全不动，禁止半亮半灭）
- 下架时前置依赖扫描：若某启用业务绑定的模型**仅剩该 model 且无其他健康渠道**→ 返回 409，body 含受影响业务名（照抄 `key-dependencies.ts` 密钥删除拦截模式）
- 有备用渠道则放行，不静默改业务绑定
- 测试三档：独占拦截 409 / 有备用放行 / 部分渠道失败时事务整体回滚（断言 DB 状态与操作前一致）

### B3 取消勾选改停用（D6）
`set_key_model_selection` 分支：现状取消勾选＝物理 delete——改为 `update is_enabled:false`；物理删除只保留在 `action=delete entity=model` 入口。存量数据零迁移。
- 测试：取消勾选后记录仍在库且 is_enabled=false；重新勾选恢复 true

### B4 服务商停用/删除（D4/D5-S5）
- 停用：`update entity provider is_enabled` 已有，无需新逻辑（运行时 `toConfig()` 已过滤）；补一条行为测试断言停用后调度器选不到其 Key
- 删除：`action=delete entity=provider` 增加前置扫描——名下密钥被核心业务独占→409 阻断；否则返回将级联移除的密钥数/模型关联数供前端弹窗展示，删除在单事务内级联完成

### B5 模型改名同步（S6）
`update entity=model` 的 `display_name` 需同步写入该 model_id 在所有 Key 上的记录（当前只改单行）。

### B6 接入即联动（D1）
新增 Key 的接口接收可选 `selectedModelIds: string[]`：保存 Key → 勾选的模型走 B2 全局上架 → 探测到的其余新模型按 B1 规则入库不上架。全程单事务。
