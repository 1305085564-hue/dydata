# 发布履约工作台体验精进实施方案（基于《设计心理学》）

> **实施目标**：针对发布管理工作台（`/admin/fulfillment`）在《设计心理学》走查中发现的 3 项微体验瑕疵（评估鸿沟、自然映射、宽容失误恢复），落实纯前端与轻量交互闭环改造，将页面可用性评分从 **9.0 / 10** 推进至 **9.8~10.0（极致顺畅·零困惑）**。  
> **制定日期**：2026-10-01  
> **负责人**：[An] Antigravity  
> **状态**：待评审（Plan-only）

## 一、需求与背景

在 2026-10-01 对 `/admin/fulfillment` 进行唐·诺曼（Don Norman）五维可用性走查后，整体评分 9.0 分（高段位），但识别出以下 3 项直接影响主管操作体感的微小断层：

1. **单格改判缺少即时微反馈（评估鸿沟）**：在全员战况月历中点击任意小方格弹出快捷菜单改判时，弹窗立即关闭，但因缺少本地即时反馈，方格需等待 200~400ms 后台刷新后才变色，主管在此瞬间容易产生“我点上了吗”的悬空迟疑。
2. **时间筛选与全月矩阵缺少联动聚焦（自然映射）**：顶部微气垫切换到“今天”或“最近7天”时，下方的全月矩阵依然展开 1~31 天全部列，表头未对所选范围形成视觉呼应，导致“选了今天，却在看全月大表”的心智轻微脱节。
3. **改判失误缺少一键撤销通道（宽容设计 / Undo）**：主管快捷打标时若手抖按错（如把请假误点为缺勤），目前需重新点击小格或打开侧滑抽屉去改判/删除标记，恢复成本偏高，未充分落实诺曼推崇的“不可摧毁的操作宽容度”（Forgiving Design）。

## 二、架构决策与方案对比

| 决策点 | 备选方案 A（过度设计） | 备选方案 B（推荐：最小改动精进） | 备选方案 C（简陋敷衍） |
|:---|:---|:---|:---|
| **改判微反馈** | 全局加全屏遮罩 Loading 菊花 | **本地乐观更新变色 + 右下角 Toast 明确提示**（已将 张三 10月1日 标为「请假」） | 仅在控制台打印日志，界面不给任何提示 |
| **时间筛选映射** | 动态把 31 天表格切割为 1 列或 7 列（破坏表头对齐与月度连续性） | **保持 31 天完整表格结构，表头与列身施加温润轻聚光灯底色（H=60° 暖灰微高亮）** | 不做任何处理，全凭主管肉眼辨认 |
| **撤销操作机制** | 前端自建复杂 Redo/Undo 内存栈与全局快捷键拦截 | **复用既有 `/api/admin/fulfillment/remove` 接口，在 Toast 中提供 5 秒非阻塞 `[撤销]` 动作** | 告诉用户“自己进抽屉手动清除” |

**推荐理由**：方案 B 严格遵循《Claude设计哲学》的“极净暖白（H=60°）、单点聚光灯、安静搭档”与《设计规范》的最小改动原则。零新增接口、零数据库变更、零破裂风险。

## 四、分阶段实施任务清单

### 阶段 1：单格改判乐观更新与 Toast 微反馈 (Feedback & Gulf of Evaluation)
- [ ] **1.1 状态映射与动作标签抽离**：在 `fulfillment-workbench.tsx` 中建立统一的 `ACTION_DISPLAY_NAMES: Record<MarkAction, string>`（`confirmed_published: "已确认", leave: "请假", waived: "豁免", absent: "缺勤"`）。
- [ ] **1.2 增强 `handleQuickMarkCell`**：
  - 改判前记录目标成员原本的 `prevStatus` 与姓名。
  - 前端执行乐观更新（Optimistic UI），立即将 `calendarData.members` 中该单元格的状态变为目标状态，使表格小格子毫秒级变色。
  - 静默发起 `POST /api/admin/fulfillment/mark`。
  - 成功时调用 `toast.success(`已将 ${userName} ${dateStr} 标记为「${actionLabel}」`, { action: { label: "撤销", onClick: ... } })`。
  - 失败时将状态自动回滚为 `originalMembers` 并提示错误。

### 阶段 2：改判支持一键撤销 (Forgiving Design & Undo)
- [ ] **2.1 实现 `handleUndoMark(userId, date, prevStatus)`**：
  - 判断原状态 `prevStatus`：
    - 若原状态存在且为人工状态（`isManualFulfillmentMarkStatus(prevStatus)`），调用 `/api/admin/fulfillment/mark` 恢复至原状态；
    - 若原状态为系统判定/未确认（`unconfirmed` 或无标记），调用 `/api/admin/fulfillment/remove` 清除人工标记。
  - 撤销期间前端乐观还原状态，后台静默刷新日历。
  - 提示 `toast.success("已撤销刚才的改判")`。
- [ ] **2.2 行动港与月历改判统一复用**：将 `handleQuickMark`（行动港待办列表快捷改判）与 `handleQuickMarkCell`（月历方格快捷改判）统一接入相同的撤销反馈。

### 阶段 3：时间筛选与全月矩阵联动聚焦 (Natural Mapping)
- [ ] **3.1 传递 `range` 属性**：在 `fulfillment-workbench.tsx` 中向 `<FulfillmentMatrixRoster range={range} ... />` 传递当前时间范围。
- [ ] **3.2 表头与列身自然聚焦**：
  - 在 `fulfillment-matrix-roster.tsx` 中增加聚焦判定逻辑：
    - 当 `range === "today"` 时，计算当天的日期。该列表头增加温润暖灰底色（`bg-[#D97757]/10 text-[#D97757]`）并在日期数字旁微显 `今日` 徽符；该列所有格子所在的 `td` 施加极淡暖底（`bg-[#FAF9F7]/80`），与整行 hover 优雅叠加。
    - 当 `range === "last7days"` 时，计算 7 天范围区间，为该 7 列的表头施加微弱的分组上边框与底色指示。
    - 当 `range === "thisMonth"` / `"lastMonth"` / `"custom"` 时，保持原有默认均等展示。

## 六、风险、兼容性与回滚策略

- **风险评估**：极低（F1/F2 级）。不触碰底层数据库表结构、RLS 权限策略、中间件与 API 契约；纯前端状态管理与展示增强。
- **向后兼容**：`range` 在 `FulfillmentMatrixRoster` 中声明为可选参数（`range?: TimeRangePreset`），缺省时降级为既有默认全月视图。
- **回滚方案**：纯前端组件文件改动，若有异常直接 `git revert` 即可瞬间回退至上一个稳态版本。
