本目录放「还没做的事」。做完的**往下挪一层**，不离开本目录——归档动作只有一个，不需要在多个归档地之间做选择。

## 目录结构

| 位置 | 放什么 |
| --- | --- |
| 本目录根 | 在办的计划，单文件命名 `YYYY-MM-DD-主题.md` |
| `<任务名>/` | 在办的多文件任务：同一任务已有 ≥3 份文件时，建任务文件夹装在一起 |
| `历史-方案/` | 已办：方案、规格书、需求书、实施计划 |
| `历史-报告/` | 已办：审查、盲审、排查、验证报告、进度台账、决策报告 |
| `历史-任务/` | 已办：整个任务包（`历史-任务/<任务名>/`，不拆散） |
| `上下文交接/` | 会话交接，常驻（模板见 `docs/上下文交接.md`） |

## 什么时候归档（触发点）

1. **交付即归档**——派单/提示词类文件，任务交付的同一轮就归入 `历史-*`，不留在根目录。
2. **收尾即归档**——任何任务收尾时，若本轮写过 plan 且已执行完，归档是本轮收尾清单的一项，不是可选项。
3. **多文件打包**——同一任务在本目录下累计 ≥3 份文件时，建任务文件夹装在一起；办完整包挪进 `历史-任务/<任务名>/`。
4. **阶段批量**——每完成一个阶段扫一遍本目录根，列出可归档候选交阿禅确认。不按日期或「已完成」字样自动搬迁，只列候选。

## 归到哪一类（判断顺序）

1. 先看是不是同一任务 ≥3 份 → 是则整体打包进 `历史-任务/`（在办期就先建 `<任务名>/`）。
2. 剩下的单份文件，一句话判据：
   - **给人照着干活用的**（方案、规格、需求书、实施计划、派单提示词）→ `历史-方案/`
   - **给人看结论和证据用的**（审查、盲审、排查、验证报告、进度台账、决策报告）→ `历史-报告/`
3. 只有 1 份、执行完不再有参考价值的一次性提示词 → 直接删（git 历史可查），不进归档。

**不要按业务主题分类**（治理 / UI / 架构 / 性能）。主题会互相重叠，每次归档都要犹豫「这份到底算哪类」——而犹豫就是当初忘记归档的原因。

## 给 AI 的提示

- 写新方案：命名 `YYYY-MM-DD-主题.md` 放本目录根；同一任务要拆多份（规格书 / Codex 提示词 / Antigravity 提示词 / 续派令）时，**直接建任务文件夹**，别散在根目录。
- **任务做完的同一轮，把对应 plan 归入 `历史-*`**。收尾报告里要说明归档了哪些文件。
- 一次性施工产物（.sql / .json 快照、回滚脚本）不提交，用完即删。
- 归档是移动不是复制：同一结论只保留一份原文，历史文件里已有的路径引用要跟着改。
