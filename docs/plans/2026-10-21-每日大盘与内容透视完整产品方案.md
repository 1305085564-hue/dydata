# 每日大盘与内容透视完整产品方案

> **状态**：已评审修订，可直接交付开发团队实施
> **版本**：V1.1（瘦身版，基于 V1.0 与视频复盘页边界对齐结论）
> **基线**：阿禅 2026-10-21 晨间复盘痛点 + GDD/UX 审查 + 与现有"视频复盘/数据管理/工作台"三页职责核对
> **目标**：新建"以天为单位的晨间决策大盘"页，3 分钟看清大盘涨跌、穿透全员产出、抓出昨日红黑两头、闭环派发复盘。
> **修订要点**：V1.0 的模块③（红黑榜自建标准）与模块④（自建诊断抽屉）与视频复盘页高度重复，本版删除自建部分、改为复用；红黑判定废掉"前15%/后15%排位制"，统一走全站爆款评级真值。全站新建的只有三块：晴雨表、人员日战报、派发复盘闭环。

---

## 〇、设计决策确认

以下决策已由阿禅在 2026-10-21 评审确认：

1. **页面定位** → 独立新做"每日大盘"页，**不**并入视频复盘页；MVP 阶段**不改**管理层默认落地页，新增独立入口（跑稳后再评估提级）。
2. **红黑判定标准** → **复用全站统一的爆款评级（优/良/普/劣）与现有异常标记**，废除 V1.0 的"当天前15%/后15%动态排位"。理由：全站只能有一把尺子；排位制还会衍生"全员都好时黑榜为空""样本极少时失效"等补丁逻辑（原边界场景 2、3），一并作废。
3. **单条视频下钻** → **复用视频复盘页现有详情弹窗**（系统已支持用链接直接打开指定视频的详情），**不新建诊断抽屉**。理由：复盘详情已有留存、完播、异常证据，重复建设会产生第二套详情界面与口径漂移。
4. **"入库样板"** → 复用现有**"入选题库"**动作，不新建入库流程。
5. **派发复盘待办** → 全站唯一需要从零新建的机制（现在没有任何"上级给下级派任务"的通道）；接收侧 = 创作者**工作台的今日待办区**。
6. **日期切换** → 任意日期可自由切换；默认锁定"昨日"（跑满 24 小时的完整战报）；"今日"可看但顶部黄字提示数据回流中，不参与涨跌对比结论。
7. **排序** → 人员日战报支持按发片数/播放量/留存排序；作品列表排序沿用复盘页现有能力（播放、互动、完播等任一列），不另建排序体系。

## 一、核心功能模块（3 新建 + 2 复用）

| 模块 | 性质 | 核心能力 | 解决的痛点 |
|------|------|---------|-----------|
| **① 顶层大盘晴雨表** | **新建** | 昨日总播放量、日环比涨跌幅、昨日发片总数、近 30 天每日走势折线。 | 全站没有任何页面有"汇总数字"视角，解决"不知道昨天整体是好是坏"的全局盲区。 |
| **② 团队日度战报表** | **新建** | 按选定日 × 成员聚合：发布条数、合计播放量、平均 2s 留存、平均 5s 完播，可排序、可展开名下作品。 | 数据管理只按月聚合，没有"天"粒度；解决"昨天谁发了片、谁贡献主力流量"。 |
| **③ 内容红黑榜** | 展示新建 / **口径复用** | `[全部]`、`[🔥 昨日爆款]`、`[⚠️ 昨日异常]`、`[未评级]` 四胶囊。爆款 = 昨日 + 综合评级"优"；异常 = 昨日 + 现有待处理异常标记。 | 大海捞针。**胶囊命中结果必须与复盘页同条件筛选结果 100% 一致。** |
| **④ 作品详情下钻** | **纯复用** | 点击列表行 → 打开视频复盘页现有详情（留存、完播、异常证据齐全），返回时大盘日期与筛选上下文不丢。 | 无需新开发。 |
| **⑤ 派发复盘闭环** | **新建** | 列表/详情一键"派发复盘"→ 注入创作者工作台今日待办 → 创作者勾选改进确认 → 自动闭环归档；带 5 秒撤回。 | 群里截图私聊、没人跟踪改没改的断环问题。 |

**口径铁律（开发必须遵守）**：红黑判定必须从全站评级真值源派生（与复盘页评级筛选同一数据源），禁止在本页新定义任何阈值或排位算法。

### 旅程 A：公司负责人（阿禅）晨间 3 分钟复盘

| **2. 查验人员** | 看"团队日度战报" | 张小明昨日 3 条（82 万播放）、王大力 1 条（8200 播放），默认按播放降序，可点列重排 | 人员×天聚合展示 | 🟢 掌控感 |
| **3. 抓取两头** | 点击 `[⚠️ 昨日异常 (4)]` 胶囊 | 列表原地收缩为 4 条异常作品（与复盘页异常筛选同源同数） | 本地秒级过滤 | 💡 聚焦高效 |
| **4. 下钻诊断** | 点击王大力扑街视频行 | 打开复盘页现有详情：前 2 秒流失、完播、异常证据齐全；关闭后回到大盘原位，日期与胶囊状态保留 | 单条详情查阅 | 🔍 查明病因 |

**关键计数**：管理者全程在**一页**完成，共约 4 次点击；查详情是一次跳转且返回可恢复上下文。

### 旅程 B：内容创作者（王大力）接收与改进

| 步骤 | 操作 (触点) | 界面反馈 | 状态/数据变化 | 用户情感 |
|---|---|---|---|---|
| **1. 看到待办** | 登录工作台（/dashboard） | 今日待办区置顶：`【待复盘】昨日视频《新人避坑》前2秒流失偏高` | 工单状态：`待复盘` | ⚠️ 明确具体，非无端批评 |
| **2. 快速查验** | 点击待办卡片 | 展开诊断卡片：管理者标记 + 关键指标，可跳详情看完整证据 | 记录查阅时间 | 💡 知道错在哪里 |
| **3. 提交改进** | 勾选改进措施标签（如：调整前3秒黄金Hook）并确认 | 待办自动勾销，归档至历史改进记录 | 工单状态：`已闭环` | 🟢 动作清晰，无心理负担 |

## 三、状态流转与状态机设计

### 3.1 红黑身份 = 只读派生，不新建状态

- "爆款亮点" = 该作品综合评级 = 优（现有真值）
- "异常预警" = 现有待处理异常标记（限流 / 删稿 / 数据异常）
- 大盘与复盘页显示**永远同步**，本页不提供任何手工修改入口。

### 3.2 复盘工单状态机（唯一新增的状态链）

```
[ 异常作品 ]
     │ 管理者点击"派发复盘"
     ▼
[ 📬 已派发待复盘 ]（责任人：视频创作者，SLA 24h）
     │                        │
     │ 创作者勾选改进并确认     │ 管理者撤回（5s 内气垫 / 5s 后工单内撤回）
     ▼                        ▼
[ ✅ 已复盘闭环 ]        [ 已撤回 ]（通知创作者，待办消失）
```

### 3.3 状态机硬规则（开发团队必须严格遵守）

1. **状态只能由真实动作驱动**：禁止提供手工改状态的下拉框；每次变更绑定操作人与时间戳。
2. **派发动作原子化**：单事务内创建工单 + 更新作品复盘状态；前端 5 秒 Undo 气垫。
3. **撤回保护**：5 秒内撤回 = 回滚工单、创作者端不留任何废弃通知；5 秒后由管理者在工单内撤回，工单关闭并通知对方"已撤回"。
4. **同源待办唯一性**：同一作品同一自然日内禁止重复派发；已有在办工单时按钮置灰并显示"已于 XX:XX 派发，等待作者确认"。
5. **红黑判定唯一真值**：只从全站评级真值源派生，本页不得自定标准（见第一章口径铁律）。

## 四、核心交互设计

1. **预计算与预排序**：大盘与人员聚合由快照预生成，首屏直出，前端 0 计算。
2. **零筛选默认聚焦**：进入即锁定昨日；人员表默认按合计播放量降序，直奔主题。
3. **一键胶囊秒级过滤**：红黑胶囊本地内存过滤；胶囊计数与复盘页同条件筛选结果对账一致。
4. **日期自由切换**：日历选任意历史日；切到"今日"时顶部黄字提示"今日数据回流中，仅供预览"。
5. **排序复用**：作品列表排序列与复盘页完全相同，不另建一套。
6. **确定性与安全感**：5 秒撤回气垫；空状态温和降级（"该日无发布作品，可切换上方日历查看其他日期"）；派发成功后明确告知"已注入对方今日待办，24 小时内未处理会自动标黄催办"。

## 五、边界问题与解决方案（修订后 8 场景）

| # | 边界场景 | 解决方案 |
|---|---------|---------|
| 1 | 早晨昨日数据尚未完全回流 | 顶栏黄色提示条："昨日部分数据回流中（已同步 85%），预计 08:30 跑满"，不隐藏已同步数据。 |
| 2 | 作品无平台快照 / 未评级 | **不进红黑榜**，单独 `[未评级 (N)]` 胶囊收纳，点击可跳复盘页"未评级"筛选核实，避免"没数据"被误读为"表现差"。 |
| 3 | 视频已被平台下架或删除 | 该行灰显 + "平台已下架"标签，不参与当日大盘与人均计算，详情保留最后快照。 |
| 4 | 同一成员一天发布多条视频 | 人员表聚合"发布条数 + 合计播放 + 加权平均留存"，点击该行展开名下全部子作品。 |
| 5 | 创作者离职或被禁用 | 历史归属日数据保留并标注"已离职"，派发按钮自动置灰。 |
| 6 | 选定日期全员无发片 | 温和空状态插画 + 引导切换日期，不报空白或红字错误。 |
| 7 | 详情加载失败 | 详情内部提供重试，大盘主列表不受影响。 |
| 8 | 管理者误派发复盘待办 | 5 秒浮动撤回；超时后在工单内"撤回"，工单关闭并通知对方"已撤回"。 |

> V1.0 的边界场景 2（全员都好时黑榜置空）与场景 3（样本极少时排位失效）是为"15% 排位制"打的补丁；排位制废除后两场景随之作废，不再需要。

## 六、数据与权限设计

### 6.1 核心数据实体

**新建 3 张表：**

| 实体 / 表 | 关键字段 | 业务说明 |
|---|---|---|
| **日度大盘快照 (daily_pulse_snapshots)** | `report_date`, `team_id`, `total_play_count`, `day_over_day_rate`, `works_count`, `avg_retention_2s`, `avg_completion_5s` | 每日跑满后预生成的宏观战报，支撑首屏秒开。 |
| **日度人员聚合 (daily_member_performances)** | `report_date`, `user_id`, `team_id`, `published_count`, `total_play_count`, `avg_retention_2s`, `avg_completion_5s` | 按天×成员预聚合，支撑"团队日度战报"秒开。 |
| **复盘工单 (video_review_tickets)** | `id`, `video_id`, `reporter_id`, `assignee_id`, `issue_tag`, `status`（`pending`/`resolved`/`withdrawn`）, `created_at`, `resolved_at` | 派发-确认闭环的管理痕迹，不可篡改。 |

**复用（不新建）**：作品综合评级（全站真值源）、异常标记、选题库入库、作品详情弹窗、作品列表排序。工作台"今日待办区"为新建展示位，数据来自 `video_review_tickets`。

### 6.2 权限矩阵

页面数据范围遵循全站三级权限运行时推导（组员仅自己 / 组长本公司团队 / 老板全部），不新增权限层级。

| 资源 / 动作 | 老板 / 集团 | 团队主管 (Leader) | 普通创作者 (Creator) |
|---|---|---|---|
| **进入大盘页** | ✅ 全公司数据 | ✅ 本团队数据 | ❌ MVP 不开放入口（V2 评估是否开放脱敏大盘） |
| **切换任意历史日期** | ✅ | ✅ 本团队 | — |
| **派发复盘建议** | ✅ 可向任意成员 | ✅ 仅本组组员 | ❌ |
| **入选题库（原"设为样板"）** | ✅ 沿用现有选题库权限 | ✅ 沿用 | ✅ 沿用现有权限，不改动 |
| **接收并确认复盘待办** | ❌ | 仅当自己产出作品时 | ✅ 在工作台接收并确认 |

## 七、产品优先级判断（MVP 取舍）

### MVP 必做（新建的只有三块）

- **晴雨表 + 30 天极简曲线**（纯 SVG Sparkline，悬停显示单日数字）。
- **人员日战报**（选定日 × 成员聚合、排序、展开子作品）。
- **红黑胶囊**（复用评级与异常真值 + 未评级胶囊）。
- **派发复盘闭环**（工单创建/撤回/确认 + 工作台今日待办区注入）。

### 明确复用、不新建

- 作品详情弹窗、入选题库、作品排序、评级与异常判定——全部走视频复盘页现有能力。

### V1 简化做

- 复盘原因标签：内置 5 个高频系统标签（`前2秒流失高`、`封面与内容不符`、`开头缺乏悬念` 等），暂不做自定义标签管理。

### V2 再考虑

- 平台观众画像标签自动抓取；样板库联动拆解脚本；周/月"进步最快"徽章；是否向创作者开放脱敏大盘视图。

### 明确不做（红线）

- ❌ 复杂的自定义 SQL 报表生成器（背离晨间 3 分钟初衷）。
- ❌ 强制签字确认的考核罚款功能（协作工具不变监控工具）。
- ❌ **第二套作品详情界面、第二套好坏评级标准**（本次修订核心红线：所有判定与详情一律复用现有真值）。
- ❌ 改变底层视频数据存储架构（聚合只做只读快照）。

## 八、成功判据（量化验收标准）

| 判据维度 | 成功标准 (通过) | 失败标准 (不合格) | 验收验证方式 |
|---|---|---|---|
| **晨间决策耗时** | 进入页面到看完涨跌、翻完红黑榜 ≤ **3 分钟** | 需翻多页或自己算百分比 > 5 分钟 | 现场计时实测。 |
| **首屏加载响应** | 选定日期后大盘与人员表 **800ms 内**渲染 | 白屏转圈 > 2 秒 | 浏览器性能监测。 |
| **上下文不丢** | 查详情为一次跳转且返回后日期/胶囊状态自动恢复；派发操作 0 次离开本页 | 返回后筛选丢失需重设 | 交互链路走查。 |
| **口径一致性** | 大盘红黑胶囊命中数与复盘页同条件筛选结果 **100% 一致** | 出现"复盘页是优、大盘进黑榜"的矛盾 | 对账测试（同一日期跑两边筛选比对）。 |
| **管理动作闭环率** | 派发后创作者 24h 内确认改进率 ≥ **85%** | 派发后无人处理沦为死记录 | 工单状态统计。 |
