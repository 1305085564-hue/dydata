## 一、唯一命名依据：裁决④冻结词表（禁止另造口径词）

| 词 | 唯一含义 | 用在哪 |
| --- | --- | --- |
| 现役 | 模型在全站层面已启用上架 | 模型/渠道工作台的启用态 |
| 渠道就绪 | 这条渠道线供得上（不代表业务能用上） | 渠道层描述（渠道池等处） |
| 可用 | 合成口径：业务最终能不能用上（现役＋渠道就绪＋健康未冻结） | 业务功能面板的支撑计数 |
| 健康 / 故障 / 待命中 / 已停用 | 检测明细四态（最近检测通过 / 未通过 / 尚未检测 / 已停用） | 冗余列等检测明细展示 |

两条铁律：

1. 「就绪 / 未就绪」**禁止**用于描述检测态——这正是本轮要消灭的同词反义。
2. 同屏同一个词只允许一个含义：「可用」只表达合成口径；检测明细只用四态词。

## 二、需求清单

### R-1 调度模型系列下拉：计数口径与文案归一

- **现状**（`src/app/(app)/admin/ai-config/components/model-family-select.tsx`，约 L56-59、L91-93；行号以最新代码为准）：选中项显示 `模型名 (N 个渠道就绪)`，N＝可调度渠道数（调度口径）；绑定不可调度时显示 `(不可调度 · 0 个渠道就绪)`。
- **目标**：计数逻辑与 0 可用项置灰规则（约 L99 `disabled={f.schedulableCount === 0}`）**一律不动**，只改文案：
  - `N 个渠道就绪` → `N 个渠道可用`
  - `不可调度 · 0 个渠道就绪` → 基准句式 `0 个渠道可用 · 当前不可用`（可按设计规范微调措辞，但不得出现「就绪」）
- **验收**：下拉各态文案与词表一致；`rg -n "个渠道就绪" "src/app/(app)/admin/ai-config/"` 0 命中。

### R-2 冗余列：四态明细＋聚合展示＋悬停明细（ChannelRedundancyCell 文案层重写）

- **现状**（`business-functions-panel.tsx` 约 L55-155）：按检测口径渲染；healthy=0 时顶部硬标「全部未就绪」，并把「待命中」也计入；渠道全名长串平铺。
- **目标**（同一组件内完成三件事）：
  1. 废弃「就绪 / 全部未就绪」：检测态一律四态词（健康/故障/待命中/已停用），配色沿用现状（绿/红/灰/灰）；
  2. 聚合替代平铺：行内显示 `共 X 渠道：a 健康 · b 故障 · c 待命中`（有已停用才追加 `· d 已停用`，零值态省略）；无健康时 `0 健康` 前置并保留红色警示点；
  3. 悬停 tooltip 列逐渠道明细（渠道名＋四态），替代现在的全名平铺；tooltip 实现方式按设计哲学/规范选。
- **不碰**：运行状态列（约 L188-195）口径与词（运行中/回落/已停用）不动；下拉计数逻辑不动。
- **验收**：
  - 同一行同屏三处（下拉计数 / 冗余列 / 运行状态）口径可各自解释、无同词反义；
  - healthy=0 且待命中>0 的场景不再出现「全部未就绪」类字样；
  - `rg -n "全部未就绪" "src/app/(app)/admin/ai-config/"` 0 命中；
  - 「共 X 渠道」的 X 与真实渠道数一致（当前生产实测：全局默认模型 gpt-6-sol 恰为 5 渠道）。

### R-3 四词表扫词：ai-config 目录内误用逐一处置

- `rg -n "就绪|未就绪|可用|健康|现役" "src/app/(app)/admin/ai-config/"` 逐处判定：
  - 误用检测态的「就绪/未就绪」→ 按词表改；
  - 合法的「渠道就绪」（渠道层「供得上」义）→ 保留；
  - 「可用/健康/现役」与词表含义冲突处 → 按词表改。
- **验收**：交付处置清单（文件：行 → 改/留＋理由）；检测态「就绪」清零。

### R-4 停用功能：确认即写库，撤回＝恢复

- **现状**（`business-functions-panel.tsx` 约 L650-672）：确认弹窗点「确认停止」后只弹 toast，`setTimeout` 5 秒后才真正调 `archiveFeature` 写库；5 秒内刷新/关页＝库里仍是启用，但界面已宣称停用（状态不可信窗口，且窗口内界面本身分裂：行仍显示启用、提示却说已停用）。
- **目标**：
  - 保留现有确认弹窗（危险动作先确认的既有裁决不变）；
  - 点「确认停止」→ **立即**调 `archiveFeature` 写库，成功后刷新数据，再弹「已停用『X』」toast，5 秒内带「撤回」按钮；
  - 撤回＝调用现有「恢复启用」同一接口（自定位，恢复按钮在约 L630 附近），成功后同样刷新＋toast；
  - 失败处理：写库失败→错误 toast＋如实刷新；撤回失败→错误 toast＋如实刷新；
  - 唯一不变式：**任何时刻刷新页面，界面状态＝库状态**。禁止任何「先改界面后补写库」的延迟提交。
- **安全阀（生产写，谨慎）**：验收需一次真实「停用→撤回」往返（该功能前台阻断窗口预计秒级）。选低峰时段＋影响最小的功能，开工时先在日志声明所选功能；若判断风险不可接受，降级为代码走查＋网络面板证据（不实际提交），并在报告明确标注「未实测」。
- **验收**：确认后网络面板可见立即发出写请求（不再等 5 秒）；5 秒内点撤回→库恢复启用；5 秒内刷新页面→功能确为已停用（这是修复的关键差异点）。

### R-5 行内改模型下拉：加「改选即生效」提示
