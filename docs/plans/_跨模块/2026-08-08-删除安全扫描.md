# 死代码删除安全扫描

- **调查日期**: 2026-08-09
- **项目**: /Users/mac/Projects/dydata
- **调查性质**: 只读，未改任何源文件
- **调查范围**: 51 个疑似死接口 + 4 个疑似死组件 + 3 个死埋点配置
- **输入清单**: `docs/plans/2026-08-08-死接口清单.md`（第四节 51 个）、`docs/plans/2026-08-08-死组件清单.md`（4 个）、`docs/plans/2026-08-08-埋点功能热度表.md`（3 个死配置）
- **调查方法**: 对每个删除目标做连带依赖检查——grep route.ts 自定义 export 在存活代码的 import、检查同名 test、检查同目录/父目录 `_shared.ts` 是否被存活生产代码复用、扫描动态字符串拼接路径与外部触发迹象。两轮独立调查 + 合并互补。

---

## 判定标准

| 归类 | 含义 |
|------|------|
| **A** | 可直接删：route.ts/组件自身 export 无人 import（仅自身 .test 引用），同目录无被存活代码复用的 helper。删 route.ts 不影响 build。 |
| **B** | 删 handler 保 helper：route.ts 可删，但同目录 `_shared.ts` / `lib` 里的函数被"存活代码"import。删 route.ts 时必须保留 helper，否则 build 崩。 |
| **D** | 待人工确认：疑似被飞书/cron/外部监控触发，或动态字符串拼路径。 |

**关键说明**：
- 删除目标指的是 `route.ts`（HTTP 端点），但同目录 `_shared.ts`、`_errors.ts`、`lib` 函数可能被别处复用，本扫描已逐个 grep 区分。
- 每个 B 类都实际 grep 了 `_shared.ts` export 的符号被谁 import，不只看文件名。
- 对 A 类，若 route.ts 依赖的 `@/lib/*` 公共函数**只**被该死接口引用，会注明"可连带清理"，但不影响归类（公共 lib 删除属后续清理，非本次必须）。
