> 状态：前端表现层与4项返工已全面完成，真实浏览器用例覆盖三入口并完成改错变红负向防伪验证；门禁 16/16 全绿，全仓单测 1,813/1,813 全绿；待阿禅对小队列表 11 列对齐现状拍板后提交收口。
>
> 当前基线：2026-10-01，经过两轮实施与返工，三大入口（/admin/content 视频复盘列表、/admin/collaboration?view=teams 小队看板、/topics 选题抽屉）已全部连通。
>
> 施工顺序：契约冻结 → Codex 后端接通并验收 → Antigravity 前端落地 → 审查返工（补3条真实用例+负向验证、去点赞兜底、统一短文案契约、降级标注组员卡片未验证）→ 最终全绿收工。

## 1. 目标与范围

继续把文案质量落到三个入口：

| 入口 | 本批结果 | 主要用途 |
|---|---|---|
| 视频复盘·作品列表 | 综合评级列、对应核心指标、按综合评级筛选 | 批量找优秀案例和需要改进的作品 |
| 文案小队·汇总与成员表 | 文案小队评级分布、良＋优作品占比；成员点击进入现有个人档案抽屉 | 看团队质量是否改善，避免只比较产量和播放 |
| 选题库·关联作品 | 每篇内容达成率、综合评级、互动率与对应核心指标；点击进入视频复盘 | 选题时判断哪些题能稳定产出好内容 |

前三个已经完成的入口不重做，只作为本批数据契约和计算结果的对账基准。

## 2. 明确决策与非目标

### 已确认决策

1. 小队“展开作品”采用现有成员行 → 文案岗位个人档案 → 本月文案作品明细 → 视频复盘的链路，不在小队表内另做一套内嵌作品列表。
2. 良＋优占比的分母是 `overallGrade` 非空的作品；综合评级为空的作品不进入分母，低播放判劣的作品仍进入分母。
3. 同题达标占比属于后续增强项，本批先完成每篇作品质量展示，不把它混进第一轮验收。
4. 不新增数据库表、migration、质量配置后台或新权限键；沿用现有 `review_content` 对视频复盘的访问边界。
5. 选题库作品点击复盘采用权限复用：有 `review_content` 时进入现有 `/admin/content?videoId=...`，无权限时保留质量数据但不显示复盘入口；不新增写权限。
6. 三处入口继续使用各自现有 60 秒缓存边界；短时间跨入口不同步属于已知权衡，写操作后按现有失效函数刷新，不做跨模块统一缓存。

### 明确排除

- 不修改 3.1 单项评级、旧绩效条数、优秀作品计费口径、认证和提成。
- 不把内容达成率替换成综合评级；两者继续并列展示。
- 不在三个页面各自复制评级算法。
- 不做小队内嵌全量作品展开，不新增第三套人员档案抽屉。
- 不改变选题库原有作品排序；“同题达标占比”和按质量排序另立任务。

### 3.2 视频复盘列表现状

调用链：

```text
admin/content/page
  → src/lib/loaders/admin-content-page.ts
  → AdminContentPageData(videos + snapshots + reviewReadiness)
  → src/app/(app)/admin/content/content-page-client.tsx
  → src/app/(app)/admin/content/content-list.tsx
```

当前 `content-list.tsx` 在客户端计算原始互动率，并通过 `topic-library-status` 异步加载话题分类和入库状态。列表 loader 已批量读取快照，但缺少 `video_tags(tag_dimension='话题')`，因此还没有统一的 `WorkContentQuality` 字段，也没有评级筛选 URL 契约。本批必须在 loader 内补齐标签批量读取，不能让组件等待另一套异步状态后自行算评级。

风险：如果直接在组件里用异步话题状态临时算评级，会出现首屏先显示空值、批次失败后混入错误评级、列表与复盘抽屉口径不一致的问题。

### 3.3 文案小队现状

调用链：

```text
collaboration-data-container
  → buildWorkGroupViews(dataset)
  → WorkGroupListTab / WorkGroupDetailView
  → onSelectPerson(userId)
  → personal-card(role="writers")
```

`buildWorkGroupViews()` 已经按小队成员和当月日报聚合，并使用最新 24h 快照；`WorkGroupSummaryRow`、`WorkGroupMemberRow` 当前只有作品数、播放和四率。成员行已经能打开个人档案，因此本批只需补文案质量汇总列，不再传输每篇作品到小队首屏。

### 3.4 选题库关联作品现状

调用链：

```text
/topics
  → TopicHubV2
  → TopicWorkBreakdownDrawer
  → /api/topics/sub-topics/[id]/works
  → src/lib/topics/service.ts#loadSubTopicWorks
```

`loadSubTopicWorks()` 已有分页和“最高播放/最新发布”排序，但当前作品项只返回播放、标题、作者和日期。现有查询未过滤 `snapshot_type`，并通过 `maxSnapshotPlayCount()` 取最大播放值；质量评级必须改为 `snapshot_type='24h'` 下按 `captured_at` 取最新一条，不能用历史最大播放污染复盘口径。旧客户端仍可回退到原有 `playCount` 字段。

## 4. 推荐架构

采用“纯计算共享、各模块保留自己的读链”的平衡方案。

### 4.1 新增纯计算模块

创建 `src/lib/content-quality.ts`，承载跨页面复用的纯函数：

- `contentQualityRules()`：从 `breakout-rating.ts` 生成当前标准线、分档线和播放门槛。
- `buildContentQualityFromMetrics()`：输入话题类型、最新 24h 快照和原始比率，输出 `WorkContentQuality`。
- `buildContentQualitySummary()`：按 `achievementSampleCount` 与 `ratedCount` 两套分母汇总。
- `buildContentQualityGradeFilter()`：只负责把 `优/良/普/劣/未评级` 映射为筛选结果，不改变评级算法。

现有 `_shared.ts` 保留兼容包装或改为导入该模块；不让 `topics/service.ts`、`admin-content-page.ts` 反向依赖协作 API 的内部文件。

### 4.2 新增质量数据读取模块

创建 `src/lib/content-quality-data.ts`，只做批量读取和快照归一化：

- 批量读取 `video_tags` 的 `tag_dimension = "话题"`；
- 批量读取 `video_metrics_snapshots` 的 `snapshot_type = "24h"`；
- 每个视频按 `captured_at` 取最新一条；
- 标签查询失败返回明确 `error` 状态，不把失败当作 `other`；
- 成功但无标签按现有规则归为 `other`，即复盘口径。

模块不做权限判断、不改变 `visibleUserIds`，调用方先完成自己的范围过滤再传入 video id。

## 5. 前后端拆分建议

推荐采用组合方案，理由是三个入口的前端改动已经超过单个组件级别，而且后端需要统一改造数据链。文件所有权如下：

| 角色 | 负责 | 禁止触碰 |
|---|---|---|
| CC/主代理 | 冻结契约、审查口径、合并冲突、最终验收 | 不替代 An 写视觉，不替代 CX 写数据查询 |
| Antigravity | `content-list.tsx`、`content-list-filters.ts`、小队两个表格、`TopicWorkBreakdownDrawer`、对应展示测试和角色测试 | 不改 `_shared.ts`、loader、topics service、数据库查询、评级计算 |
| Codex | `content-quality.ts`、`content-quality-data.ts`、`admin-content-page.ts`、`_shared.ts`、`topics/service.ts`、契约解析、单元测试和真实数据联调 | 不顺手改视觉体系、旧绩效或其他岗位列 |

### 前端工作量判断标准

Claude Code 审查时必须重新核对当前源码，并按以下标准判断：

- 本批实际包含列表筛选 URL、未评级状态、表格横向空间和选题库复盘权限入口，前端属于中等偏大，推荐 An/Codex 分工；
- 若要求小队内嵌作品展开或选题库同题统计，前端和数据链都会明显增大，应拆成后续任务，不与本批混做。

本方案推荐的最小拆分是：**本轮 CX 先做共享计算和真实数据接线，An 在后续轮次只做三个页面的表现层；不拆独立前端接口代理，也不让两人同时改同一个组件。**

## 7. 失败、空值与兼容行为

| 状态 | 视频复盘列表 | 小队汇总 | 选题关联作品 |
|---|---|---|---|
| `rated` | 显示综合评级、内容达成率和核心指标 | 计入评级分布和良优率 | 显示质量数据，可打开复盘 |
| `unlinked` | 显示未关联，不参与评级筛选命中 | 署名作品仍计入作品数，质量为空 | 显示未关联 |
| `pending_snapshot` | 显示待采集，不进入良优率分母 | 不进入质量分母 | 显示待采集 |
| `invalid_play` | 播放缺失显示不可计算；播放0沿用既有综合劣语义 | 只按已有综合结果计数 | 同上 |
| `missing_metrics` | 显示缺指标，不把缺失当0 | 不进达成率样本；若综合已判劣仍进入评级分母 | 同上 |
| `topic_unavailable` | 不猜复盘口径，不显示质量评级 | 质量列显示不可用 | 不显示伪造评级 |

权限失败、接口失败和空数据必须进入明确错误/空态；不得回退到前端样例、旧的最大播放值或“默认复盘”。

## 10. 风险、待审查点与停止条件

- 风险：统一质量字段加入 admin/content 首屏后会增加批量标签和快照读取；必须复用分页、批量和 60 秒缓存边界，不按作品逐条查询。列表缓存与个人缓存独立，最多允许 60 秒显示差异。
- 风险：选题库当前作品接口用最大播放展示；本批必须切到最新 24h 快照，否则会和复盘抽屉不一致。
- 风险：小队良优率不能平均成员良优率，必须重新汇总作品级评级。
- 风险：`review_content` 既控制复盘入口又控制选题库管理动作；只读复盘入口必须沿用页面权限，不新增或扩大写权限。
- 已按 Claude Code 结论冻结：前端属于中等偏大，采用 An/CX 分工；本轮只验收 CX 后端，An 不在本轮启动。
- 停止条件：发现评级口径、权限范围、最新快照选择或分母定义无法从现有事实确认时停止施工，只回报阻塞，不用猜测补齐。

### 本轮后端停止点

- 只允许修改共享质量计算、质量批量读取、admin/content loader、文案小队数据装配、选题库 service/契约解析和对应后端测试/文档。
- 不修改任何三个入口的 `.tsx` 表现层，不增加前端筛选控件，不做浏览器视觉验收。
- 代理完成后由主代理独立复跑约定命令；若出现评级、权限、分母或快照口径阻断，停止在后端，不顺手补前端。
