## 二、需求（唯一可靠来源，不得自行扩张）

1. **目标**：`/admin/collaboration`（岗位管理）页面对「组员」（`company_role = member`）放开可见范围 —— 从"只有自己"改为**本公司全体成员**。放开面包含该页面的全部子视图：四个页签（达人 / 运营 / 文案 / 剪辑）、首屏汇总、个人档案卡、作品明细、待补归属弹窗、「按团队」视图。
2. **明确不做**：
   - 不改全站数据范围（组员在数据分析 / 导出 / 工作台等处仍只看自己）。
   - 不给组员任何写权限。
   - 不改视频复盘（`/admin/content`）的权限。
   - 不改集团模式（`kind === "all"`）行为。
3. **硬约束**（项目纪律，违反即方案不成立）：
   - **成员可见性 / 协作者范围判断的唯一入口是 `src/lib/data-access-scope.ts`，禁止在任何接口 / 页面内联实现 `team_id` / `data_scope` 范围逻辑**（`docs/权限与安全说明.md` B.5，约第 318 行）。请特别核对：方案是否把范围判断（例如页面里仍比较 `scope.kind`）留在了模块内。
   - 权限规则集中记录在 `docs/权限与安全说明.md`，代码 / migration / RLS / API / 前端入口必须同步，不能只改一层。
   - 高风险改动（权限 / RLS / Auth）动手前必须先列受影响文件清单（`AGENTS.md`）。
   - 禁止数据库先行发布；本次预期**无 migration**（若方案引入了 migration，请重点质疑）。
4. **已知业务边界**：生产 45 名在职组员中 **2 人没有 `team_id`**；归档组员 17 人 `team_id` 全为空。
