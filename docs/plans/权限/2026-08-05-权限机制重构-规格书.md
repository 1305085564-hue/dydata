> 决策人：阿禅 | 架构：Antigravity | 执行：Codex

## 一、设计目标

**核心变化：** 权限不再跟角色绑定，任何人（包括 member）都可以被授予具体权限。

**附带清理：**
- 去掉 `groups` 表和 `group_id` 字段（组织结构只保留 team）
- 去掉 `BusinessRole`（team_admin / group_leader）整套推导逻辑
- 权限键重命名 + 新增，按模块分 4 类
- 数据范围从 `view_all_data` 权限键迁出，变为独立字段 `data_scope`

## 二、新权限模型

### 2.1 角色（3 个，仅做默认模板）

| 角色 | 含义 | 默认 data_scope |
|------|------|-----------------|
| owner | 最高管理员 | all |
| admin | 管理员 | team |
| member | 普通成员 | self |

角色只决定「新人加入时默认给什么权限」，实际能力全看 `permissions` + `data_scope`。

### 2.2 数据范围（profiles 新增字段）

```sql
-- profiles 表新增
data_scope text not null default 'self' check (data_scope in ('self', 'team', 'all'))
```

| 值 | 含义 |
|----|------|
| self | 只能看自己的数据 |
| team | 能看同 team 的数据 |
| all | 能看全公司数据 |

## 四、数据库迁移

### 4.1 新 migration 文件

文件名：`20260805120000_permission_v2.sql`

```sql
-- ============================================================
-- 权限机制 V2：解耦权限与角色
-- ============================================================

-- 1. profiles 新增 data_scope 字段
ALTER TABLE public.profiles
  ADD COLUMN IF NOT EXISTS data_scope text NOT NULL DEFAULT 'self'
  CHECK (data_scope IN ('self', 'team', 'all'));

-- 2. 根据现有数据填充 data_scope
UPDATE public.profiles SET data_scope = 'all' WHERE role = 'owner';
UPDATE public.profiles SET data_scope = 'all'
  WHERE role = 'admin' AND (permissions->>'view_all_data')::boolean = true;
UPDATE public.profiles SET data_scope = 'team'
  WHERE role = 'admin' AND data_scope = 'self';

-- 3. 迁移权限键名（在 JSONB 中重命名）
UPDATE public.profiles SET permissions = permissions
  - 'manage_violations' || jsonb_build_object('review_violations', permissions->'manage_violations')
  WHERE permissions ? 'manage_violations';

UPDATE public.profiles SET permissions = permissions
  - 'view_conversion_hub' || jsonb_build_object('view_conversion', permissions->'view_conversion_hub')
  WHERE permissions ? 'view_conversion_hub';

UPDATE public.profiles SET permissions = permissions
  - 'view_content_review' || jsonb_build_object('review_content', permissions->'view_content_review')
  WHERE permissions ? 'view_content_review';

UPDATE public.profiles SET permissions = permissions
  - 'manage_video_assets' || jsonb_build_object('manage_videos', permissions->'manage_video_assets')
  WHERE permissions ? 'manage_video_assets';

UPDATE public.profiles SET permissions = permissions
  - 'use_ai_copywriting' || jsonb_build_object('use_ai_copy', permissions->'use_ai_copywriting')
  WHERE permissions ? 'use_ai_copywriting';

UPDATE public.profiles SET permissions = permissions
  - 'use_ai_management' || jsonb_build_object('use_ai_assist', permissions->'use_ai_management')
  WHERE permissions ? 'use_ai_management';

-- 4. 删除旧权限键
UPDATE public.profiles SET permissions = permissions - 'view_all_data' - 'edit_data';

-- 5. 给原 admin 补 manage_fulfillment（之前靠角色判断）
UPDATE public.profiles SET permissions = permissions || '{"manage_fulfillment": true}'::jsonb
  WHERE role IN ('admin', 'owner') AND NOT (permissions ? 'manage_fulfillment');

-- 6. 给 owner 补 manage_system
UPDATE public.profiles SET permissions = permissions || '{"manage_system": true}'::jsonb
  WHERE role = 'owner';

-- 7. 修改 has_permission() 函数 — 不再限制 role
CREATE OR REPLACE FUNCTION public.has_permission(perm text)
RETURNS boolean
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1
    FROM public.profiles
    WHERE id = auth.uid()
      AND (
        role = 'owner'
        OR (permissions->>perm)::boolean = true
      )
  );
$$;

-- 8. 新增 get_data_scope() 函数
CREATE OR REPLACE FUNCTION public.get_data_scope()
RETURNS text
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT COALESCE(
    (SELECT data_scope FROM public.profiles WHERE id = auth.uid()),
    'self'
  );
$$;

-- 9. 删除 profiles.group_id 列
ALTER TABLE public.profiles DROP COLUMN IF EXISTS group_id;

-- 10. 删除 profiles.access_level 列（如果存在）
ALTER TABLE public.profiles DROP COLUMN IF EXISTS access_level;

-- 11. 删除 groups 表（先删引用）
DROP TABLE IF EXISTS public.groups CASCADE;
```

### 4.2 RLS 策略更新

需要单独一个 migration 更新现有 RLS 策略中的 `is_admin()` 调用。对于读操作改用 `has_permission()`，写操作保留 `is_admin()`。

### 5.2 权限判断 (`src/lib/permission-utils.ts`)

```typescript
import type { PermissionKey, Permissions, UserRole } from "@/types";

export function hasPermission(
  role: UserRole,
  permissions: Permissions,
  key: PermissionKey,
): boolean {
  if (role === "owner") return true;
  return permissions[key] === true;
}

export function hasAnyPermission(
  role: UserRole,
  permissions: Permissions,
): boolean {
  if (role === "owner") return true;
  return Object.values(permissions).some(v => v === true);
}
```

export function canAccessAdminPath(pathname: string, role: UserRole, permissions: Permissions = {}) {
  if (role === 'owner') return true;

  if (pathname === '/admin/settings' || pathname.startsWith('/admin/settings/'))
    return hasPermission(role, permissions, 'manage_system');
  if (pathname === '/admin/ai-config' || pathname.startsWith('/admin/ai-config/'))
    return hasPermission(role, permissions, 'manage_system');
  if (pathname === '/admin/modules' || pathname.startsWith('/admin/modules/'))
    return hasPermission(role, permissions, 'manage_members');
  if (pathname === '/admin/analytics' || pathname.startsWith('/admin/analytics/'))
    return hasPermission(role, permissions, 'view_analytics');
  if (pathname === '/admin/collaboration' || pathname.startsWith('/admin/collaboration/'))
    return hasPermission(role, permissions, 'view_analytics');
  if (pathname === '/admin/content' || pathname.startsWith('/admin/content/'))
    return hasPermission(role, permissions, 'review_content');
  if (pathname === '/admin/fulfillment' || pathname.startsWith('/admin/fulfillment/'))
    return hasPermission(role, permissions, 'manage_fulfillment');
  if (pathname === '/admin/videos' || pathname.startsWith('/admin/videos/'))

### 5.5 API 鉴权 (`src/app/api/admin/auth-helper.ts`)

```typescript
// hasAnyAdminPermission → hasAnyPermission
// 不再判断 businessRole

export async function requireAdminActor(options: { requiredPermission?: PermissionKey } = {}) {
  // ...获取 user 和 profile...

  const role = profile.role as UserRole;
  const permissions = (profile.permissions ?? {}) as Permissions;

  const allowed = options.requiredPermission
    ? hasPermission(role, permissions, options.requiredPermission)
    : hasAnyPermission(role, permissions);

  if (!allowed) return { error: "无权限", status: 403 };

  return {
    supabase,
    actor: {
      userId: profile.id,
      role,
      permissions,
      dataScope: profile.data_scope as DataScope,
      name: profile.name ?? null,
      teamId: profile.team_id ?? null,
    },
  };
}
```

## 八、迁移注意事项

1. **先跑 migration 再部署代码** — migration 是向后兼容的（旧代码读新字段会忽略）
2. **data_scope 的 owner 回填** — migration 里已处理，owner 自动填 'all'
3. **权限键重命名是原子操作** — migration 内 JSONB 操作，一条 SQL 搞定
4. **groups 表删除是不可逆的** — 确保不需要历史分组数据后再执行（或先 `ALTER TABLE groups RENAME TO groups_archived`）
