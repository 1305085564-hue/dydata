## 批次一：数据库迁移（最高优先级）

### 目标
创建新 migration，完成 schema 变更 + 数据迁移。

### Codex 提示词

```
读取 docs/plans/2026-08-05-权限机制重构-规格书.md 的「四、数据库迁移」章节。

任务：创建 supabase/migrations/20260805120000_permission_v2.sql

内容：
1. profiles 新增 data_scope 字段（text, default 'self', check in self/team/all）
2. 根据现有 role + permissions 回填 data_scope（owner→all, admin+view_all_data→all, admin→team, member→self）
3. 重命名 permissions JSONB 中的旧 key（manage_violations→review_violations, view_conversion_hub→view_conversion, view_content_review→review_content, manage_video_assets→manage_videos, use_ai_copywriting→use_ai_copy, use_ai_management→use_ai_assist）
4. 删除旧 key（view_all_data, edit_data）
5. 给原 admin 补 manage_fulfillment=true, 给 owner 补 manage_system=true
6. 重写 has_permission(perm) 函数：不再限制 role='admin'，改为 role='owner' OR (permissions->>perm)::boolean = true
7. 新增 get_data_scope() 函数
8. 删除 profiles.group_id 列
9. 删除 profiles.access_level 列
10. 删除 groups 表（CASCADE）

注意：
- 参考现有 migration 风格（看 supabase/migrations/007_owner_role_and_permissions.sql）
- 每步加注释说明
- groups 表删除前先 DROP 依赖的 index 和 policy
- 确保 topic_groups 表不受影响（那是选题分组，和团队分组无关）
- leader_daily_reports 表有 group_id 引用，需要先 DROP 该列或整表（该表已废弃）

验证：migration 文件语法正确，可以 dry-run。
```

## 批次四：权限分配 UI 重设计（Antigravity 执行）

### 目标
在成员管理页面重新设计权限编辑区域，按 4 类分组展示权限 + 新增数据范围选择。

### 执行者：Antigravity（前端设计+实现）

### Antigravity 提示词

```
## 背景

权限机制已重构完成（批次一~三由 Codex 完成）。核心变化：
- 权限不再跟角色绑定，member 也可以被授予权限
- 11 个权限键按 4 类分组：经营(3)、内容(3)、管理(3)、AI(2)
- 新增 data_scope 字段（self/team/all）决定数据可见范围
- 旧的"分组"UI 已删除

## 任务

重新设计并实现「成员权限编辑」UI。位置：成员管理页面中，点击某个成员后展开的权限编辑区域。

## 数据契约

类型定义在 src/types/index.ts：
```ts
export const PERMISSION_CATEGORIES = {
  business: ['view_analytics', 'export_data', 'view_conversion'],
  content: ['review_content', 'manage_fulfillment', 'manage_videos'],

  ai: ['use_ai_copy', 'use_ai_assist'],

  business: '经营', content: '内容', admin: '管理', ai: 'AI',

  view_analytics: '经营分析', export_data: '导出数据', view_conversion: '转化中心',
  review_content: '视频复盘', manage_fulfillment: '发布管理', manage_videos: '素材库',
  manage_members: '成员管理', review_violations: '违规复核', manage_system: '系统设置',
  use_ai_copy: 'AI 文案助手', use_ai_assist: 'AI 管理助手',
};

export type DataScope = 'self' | 'team' | 'all';
```

## 设计要求

1. 权限编辑区分两个板块：
   - 「功能权限」— 按 4 类分组，每类一个 section，每个 section 有类别标题 + 该类下的 checkbox
   - 「数据范围」— 三个选项（仅自己/同团队/全公司），用 radio 或 segmented control

2. 视觉层级要清晰：类别之间有明确分隔，同类权限在一组内紧凑排列

3. 交互：
   - 编辑后实时标记为"未保存"
   - 保存按钮同时写入 permissions + data_scope
   - owner 的权限区域显示为全选且不可编辑（灰色状态）

4. 组件位置：src/app/(app)/admin/permission-manager.tsx 或新建权限编辑组件

5. server action：更新 权限管理.ts 中的 updatePermissions 支持写入 data_scope

## 美学约束
- 遵循项目 docs/美学规范.md
- 不参考 Codex 写的任何前端代码，从零设计
- 保持和成员管理页面其他区域的视觉一致性

## 验证
- npm run build 零错误
- owner 进入成员管理 → 点击某成员 → 看到按 4 类分组的权限编辑 UI
- 给 member 勾选 view_analytics + data_scope=team → 保存 → 该 member 能看到经营分析页面
