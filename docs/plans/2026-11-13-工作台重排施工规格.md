## 一、施工原则（先读这节再动手）

### 1. 换皮换顺序，不换骨头

示意稿只是验收样本，**不得把示意稿 HTML 直接搬进项目**。现有页面的「骨头」已经过真实数据和线上考验，原样保留；只重写「皮」和「排列顺序」。

| 保留不动（骨头） | 重写（皮与顺序） |
|---|---|
| `video-submit-form-v2/` 下全部控制器：上传与识别 `upload-controller.ts`、草稿 `draft-controller.ts`、提交 `submit-controller.ts`、质检 `quality-check-controller.ts`、署名 `assignee-controller.ts` | `video-submit-panel-toolbar.tsx` 页头（去掉「创作立卷 · 表达纪事」那一层）——第一批已做 |
| 状态机与缺项汇总：`components/submission/提交状态机.ts`、`填报表单状态.ts`（`summarizeSubmissionIssues`） | 本月履约条与「今日待履约/今日免交」并存的状态行——第一批已撤（`MonthlyFulfillmentStrip` 已删） |
| 服务端提交、超 72 小时补交审批、编辑历史、权限判断 | `form-v2/workspace.tsx` 两栏布局 → 单栏自上而下 |
| 识别后自动对调截图槽位、识别失败保留截图转手填 | `form-v2/left-column.tsx`、`right-column.tsx` 的区块顺序与展示方式 |
| 互动数据超过播放量的确认弹窗、删除截图确认、补交申请弹窗（`form-v2/dialogs.tsx`） | `form-v2/submit-footer.tsx` 提交区 |
| 署名选择弹窗 `form-v2/role-picker.tsx` 的选人逻辑 | `form-v2/submitted-view.tsx` 交完后的样子 |

判据：**改一个文件前先问「它算数据还是摆数据」**。算数据的不动，摆数据的才改。页面上显示的统计数字（如「漏 y 天」）也算「算数据」，必须引用口径文档里的唯一来源，不在界面层另写一套算法。

### 2. 页面只回答一个问题

这页只回答「今天交了没有，没交还差什么」。任何元素若不帮助回答这个问题，降级到折叠区或移出本页。

### 3. 六条新原则（本次验收的硬判据）

1. **一页一问**：同一时刻只有一个主声部，即当前该做的那一步。
2. **步数即成本**：理想路径为 拖入两张截图 → 粘贴文案 → 提交，共 3 步。每多一步须写出理由。
3. **视线顺序 = 做事顺序**：从上到下依次为：状态 → 截图 → 识别结果 → 文案 → 提交。
4. **空输入框是最贵的注意力**：识别出来的值以文字呈现，不画输入框；只有「请核对」的那一项变成输入框。
5. **同一状态只在一处说**：今日状态只在页头说一次，其他地方不重复，也不互相矛盾。
6. **布局零跳动**：任何状态切换都不许让下方元素位移。示意稿已经踩过这个坑：核对完后行高变化，导致「一键粘贴」点空。

## 二、分状态施工说明

### 1. 页头：一句状态 + 一行本月的账

- **左侧大标题是状态句。** 最终取值依次为「今天还没交」→「还差一步：粘贴文案」→「可以交了」→「今天已交」（已交时前面加成功色圆点）；免交、修改、补交分别为「今天免交」「修改 · 日期」「补交 · 日期」。
  - 第一批的实现：状态句只接了当天的日期状态（`activeDateStatus` / `primaryMode`，派生函数在 `src/lib/dashboard-panel-header.ts`），所以还没有「还差一步」和「可以交了」。
  - 第四批：改成和提交按钮的「还差」用同一个来源（`summarizeSubmissionIssues`），**不另写一套判断**。
- **标题下面一行**：按示意稿写「日期 · 本月已交 x 天，漏 y 天」，点「本月已交…」展开月历；当天请假时，请假事由并入这一行。月历不常驻。
  - 「漏 y 天」必须和《数据口径与计算规则》的应交口径一致（自然日、扣除已批准的请假/豁免、按入职日裁剪、待审批不提前扣），见〇节第一批的核实项。
- **右侧**只保留「请假/报备」和「历史记录」两个入口。修改、补交时的日期写进标题（「修改 · 日期」），不在右侧另放日期标签。
- 过期的请假提示（例如 10-05 的旧请假仍在显示）**不得再出现**：在取数时过滤，涉及日期全部早于今天就不返回，前端不各自判断。
- 作品异常的切换（`VideoStatusSegmented` + 限流/删稿）移到「更多」折叠区，默认收起（第二批做）。

### 2. 截图区：唯一的大入口

- 两个槽位改为一个合并的拖放区，沿用现有 `handleUnifiedUpload`，系统按识别类型自动归位（现有逻辑已支持）。
- 拖放区下面一行把整条路摊开：「粘贴截图 → 核对识别结果 → 粘贴文案 → 提交」，当前一步高亮（见示意稿）。
- **等待态必须真实设计**（示意稿零延迟，真实环境会有上传与识别耗时，这是丝滑感能否落地的关键）：
  - 每张图单独显示「上传中 / 识别中 / 已识别 / 需手填」，占位高度固定，状态切换不改变高度。
  - 识别进行时，下方文案区**可以先填**，不锁页面。
  - 识别失败：截图保留，文字提示「这张没认出来，数字请手填」，对应指标直接变为输入框。
- 删除、重传为次要操作，常态隐藏，悬停或聚焦时浮现。

### 3. 识别结果区：文字为主，只有存疑项是输入框

- 11 项指标 + 标题 + 发布时间，按「已认出」「请核对」两类呈现：
  - 已认出：以文字展示数值（20px 数字），点击可改，改后标记「已改」。
  - 请核对：对应 `EditableMetricField.confidenceLevel` 为 `low` / `medium` 的字段，以及 `issueSummary.publishedAtUnconfirmed`。默认就是输入框，旁边显示「请核对」（警示色文字，不铺实底）。
  - 核对完成后保留一行「已核对」（正文墨色），**行高不变**。
- 小标题一行汇总：「13 项认出 12 项，1 项请核对」→「13 项已全部核对」。
- 「恢复识别值」沿用现有 `restoreOcrValue`。
- 缺失的必填指标（`missingRequiredMetrics`）与「请核对」同样处理。

### 4. 文案区：一键粘贴是主动作

- 文案框上方仅放一个「一键粘贴」按钮，沿用现有 `handlePasteContent` / `isPastedFeedback`。
- 标题：识别到后以文字显示（可点改）；没识别到时才显示输入框。
- 选题标签、署名（脚本 / 剪辑 / 运营）收进「更多」折叠区。折叠标题行直接写出当前值（例如「选题：干货 · 署名：本人」），一眼就能确认，无需展开。
- 选题标签为必填项：若缺失，「更多」自动展开，并在提交按钮的「还差」中列出（`topicTagMissing`）。

### 5. 提交区：按钮自己说还差什么

- 吸底在**行容器**上（示意稿 `.foot-row`，`position: sticky; bottom: 0`），不得吸在按钮本身上，否则在首屏看不见。
- 按钮不可用时，按钮旁写明「还差：核对收藏数、文案」，文字从 `issueSummary` 拼出，点击后跳到第一处缺项（沿用 `scrollToIssueAnchor`）。
- 按钮文案统一为「提交」；补交与修改沿用现有分支，分别为「补交」和「保存修改」。现有的「确认提交立卷」等文案需替换。
- 超过 72 小时需要审批时，按钮位置换成「申请补交」，流程沿用 `requestLateSubmission`。
- 草稿保存时间降为辅助墨色小字，放在按钮左侧。
- 底部灰色「待补全」那一行撤掉，「还差什么」只在按钮上说。

### 6. 交完之后

- 页头变为「今天已交」。下方显示本次提交的摘要（截图缩略图 + 关键数字），提供「修改」和「看历史」两个次要入口；下一步（去选题库、看复盘）退成文字链接，不再有主按钮。
- AI 质检入口保持现状（交完后再触发），不前移（已拍板，见三-1）。

### 7. 不得丢的边缘状态（每条都要在验收里点到）

| 状态 | 要求 |
|---|---|
| 免交日 / 请假日 | 页头说明「今天免交」，表单仍可交（现有永久豁免逻辑保留） |
| 修改今日 / 修改历史 | 页头显示「修改 · 日期」，按钮为「保存修改」 |
| 补录（`isBackfillMode`） | 页头显示「补交 · 日期」 |
| 超 72 小时补交审批 | 见二-5 |
| 作品异常（限流 / 删稿） | 截图可不必交（`areSubmissionScreenshotsRequired`），「还差」随之变化 |
| 手机宽度 | 单栏天然适配；吸底提交区不得遮挡输入框 |
| 识别全部失败 | 全部转为输入框，页头提示「这次没认出来，数字请手填」 |
