## 一、用户心智与痛点对账 (GDD 心智模型)

### 1.1 核心痛点与心流断裂
当前算力池区仅提供**「模型视角」**（一个模型一张卡，渠道作为阶梯附属于模型）。  
当阿禅需要评估某家服务商（如 Anthropic、DeepSeek、火山引擎）的全局水位时：
- **旧路径（认知装配 Excise）**：必须在 11 个模型卡片中逐个点开手风琴折叠，肉眼检索属于该服务商的密钥行与在线状态，心智成本极高；
- **旧局限（无法就地排障）**：无法针对“单一渠道”批量做连通探测，只能全池体检（触发全局结果条）或逐个模型翻找点击。

### 1.2 呈现模型与三模型对齐 (GDD 目标)
- **用户心智模型**：以“服务商/渠道”为实体，一眼看清：挂了多少把密钥？在线几把？供了多少在册模型？一键测试这路渠道通不通。
- **系统实现模型**：数据已在前端单次下发的 `bundle` 中全部就绪（`providers`、`keys`、`key_models`、`models`），零新增后端 API。
- **呈现模型 (UI)**：通过平滑视角切换，原地投射为以 `ProviderChannelCard` 为单元的高密度阅读看板。

## 二、架构设计与组件拆分（严格保护维护性棘轮）

主面板 `compute-pool-panel.tsx` 当前 527 行，棘轮上限为 532 行（余量仅 5 行，**禁止上调 baseline**）。  
为彻底消除行数风险，除 `viewMode` 状态外，**所有渠道视角的实现细节（筛选栏、分段切换器、并发调度、渠道卡列表）全部下沉至独立组件**，主面板只做三元条件分支；若主面板仍有行数压力，整段上提既有子逻辑至独立模块，确保棘轮只降不升：

## 三、视觉规范与交互细节 (Claude 设计系统对齐)

严格遵循《Claude 设计哲学》与《Claude 设计规范（高密度版）》：

### 3.1 视角切换分段控件 (R1，无障碍对齐 T17)
- **位置**：置于池区区段标题右侧；
- **排版结构**：
  - 左侧：区段定名 `text-[14px] font-medium text-[#1F1E1D]`；
  - 右侧：双选项 Segmented Control；
- **视觉 Token**：
  - 容器外框：`inline-flex p-0.5 rounded-lg bg-[#F1F1F0] border border-[#E2E2DF]/60`
  - 激活项：`bg-white text-[#141413] shadow-sm font-medium text-[12px] px-2.5 py-1 rounded-md transition-all`
  - 未激活项：`text-[#78716C] hover:text-[#141413] font-normal text-[12px] px-2.5 py-1 rounded-md transition-colors`
- **无障碍规范（对齐 T17）**：
  - 采用全站已落地的 `aria-pressed` 按钮组模式，不另造 `tablist/tab` 语言；
  - 各按钮设置 `aria-pressed={viewMode === "..."}` 与清晰语义 `aria-label="切换至模型视角 / 切换至渠道视角"`。

### 3.2 筛选栏语义适配与防假承诺 (R1 附带，修正项 3)
- **搜索输入框**：
  - 统一契约：`h-8 text-[13px] border-[#E2E2DF] bg-white shadow-input focus:border-[#78716C]`；
  - Placeholder 智能自适应：“搜索渠道、密钥或模型”；
- **状态筛选下拉框（消除假承诺）**：
  - 剔除与模型视角绑定的「仅无可用渠道」；
  - 针对底层 health 三态（`healthy` 在线 / `fault` 故障 / `untested` 待命中），如实提供明确选项：
    - `全部状态`
    - `仅含故障密钥`（`fault`：存在失败或健康冻结）
    - `仅含待测密钥`（`untested`：已启用但尚未进行过健康检测）
  - 语义清晰诚实，绝不将待测密钥模糊归入“不在线”。

### 3.3 渠道卡头与卡身视觉规范 (R2，修正项 1 掩码不平铺)
- **卡片容器**：`rounded-xl border border-[#E2E2DF] bg-white overflow-hidden shadow-input transition-all`；
- **卡头 (14px Sans 条目定名)**：
  - 服务商名称：`text-[14px] font-medium text-[#141413]`（如 `Anthropic (官方直连)`）；
  - 汇总徽标组（元数据 12px / 400 字重 / 中性灰底）：
    - 密钥总览：`bg-[#F1F1F0] text-[#78716C] px-2 py-0.5 rounded-full`（例：`2 个密钥`）；
    - 在册模型总览：`bg-[#F1F1F0] text-[#78716C] px-2 py-0.5 rounded-full`（例：`4 个在册模型`）；
    - 健康状态圆点：
      - 全健康：`text-[#6FAA7D] inline-flex items-center gap-1`（绿点 + `全部在线`）；
      - 存在故障：`text-[#C0685C] bg-[#C0685C]/10 px-2 py-0.5 rounded-full`（红点 + `1 处故障`）；
      - 待检测：`text-[#78716C]`（灰点 + `待命中`）；
  - 卡头主操作：
    - 「测试本渠道」次级按钮：`Button variant="outline" size="s"`，高度 28px (`h-7`)，12px 墨度，`hover:bg-[#EBEBE9]`，阻止点击冒泡；
- **卡身展开明细 (两段式白纸版式，外留白 > 内留白)**：
  1. **第一段：密钥与连通性列表 (Keys，严守 T25 契约)**

       - 状态微符：`Zap` (启用) / `Pause` (停用)；
       - **标签与掩码（T25 落地形态）**：主行只显示 `{key.label}` (13px font-medium #1F1E1D)；掩码**严禁在主行平铺显示**，仅通过标签的 `title={key.api_key_masked ? `密钥：${key.api_key_masked}` : undefined}` 悬停与 `<span className="sr-only">密钥 {key.api_key_masked}</span>` 呈现；
       - 同源健康状态：调用 `getProviderKeyHealthStatus`，绝对禁止第三种口径；

## 四、数据流与业务闭环

### 4.1 数据同源推导 (Zero Extra Requests)
```ts
// 纯前端派生，无任何新增网络请求
interface ProviderChannelGroup {
  provider: AiProvider;
  keys: AiProviderKey[];
  models: Array<{
    modelId: string;
    displayName: string;
    isShelved: boolean; // 是否全站上架
    keyModelId: string;
  }>;
  stats: {
    totalKeys: number;
    activeKeys: number;
    healthyKeyCount: number;
    faultKeyCount: number;
    untestedKeyCount: number;
  };
}
```
- **数据来源**：100% 取自 `useAiConfig()` 的 `bundle`；
- **健康判断**：直接复用 `@/lib/ai/provider-routing` 的 `getProviderKeyHealthStatus`，确保双视角数据 100% 对齐。

### 4.2 一键连通测试调度 (R3 闭环与防刷屏)
- **并发控制**：单个渠道包含的密钥通常在 1~5 个之间，采用并发受控队列（并发度 ≤ 5），单个密钥报错捕获后记录错误，不阻断整批；
- **请求轻量**：仅发送 `{ action: "test_key", data: { key_id } }`，不携带 `model_id`，走连通级轻量检测；
- **防 Toast 风暴 (验收标准 2)**：
  - 渠道卡一键测试**不触发单密钥的 toast**，测试结果直接以内联状态反映在对应行右侧；
  - 整批完成后，仅触发**唯一一条**总结性 toast：“【{服务商名}】测试完成：X/Y 个密钥在线”；
  - 彻底规避一屏弹出 5-6 条 toast 的噪声违规。

### 4.3 同步模型弹窗复用 (R4 闭环)
- 点击渠道卡内任一密钥行的「同步模型」按钮：
  - 直接调用上层已有的 `handleSyncKeyModels(key)`；
  - 呼出全站唯一的 `SyncModelsDialog`；
  - 保存后通过 `setKeyModelSelection` 更新全局缓存并刷新 bundle；
  - 弹窗关闭后，两视角所有卡片与数字自动完成响应式同步。

## 五、验收标准与统一验收命令

### 统一门禁命令
**`npm run gate:static` 必须退出码 0**（涵盖 lint、build、maintainability-gate 全绿）。

### 行为级验收清单
1. **渠道汇总准确**：渠道卡数 = 服务商数；每卡密钥数/模型数/在线数与模型视角同源一致；
2. **真实一键测试**：点击「测试本渠道」，密钥行就地呈现 `✓ 耗时` 或 `✗ 错误摘要`；Toast 仅 1 条；
3. **弹窗同源互通**：点击「同步模型」呼出同一弹窗；保存后双视角即时同步更新；
4. **键盘走查可访问**：`aria-pressed` 分段按钮组、卡头折叠、操作按钮均支持键盘 Tab 聚焦与 Enter/Space 操作；
5. **筛选器无假承诺**：渠道视角下拉提供「全部状态 / 仅含故障密钥 / 仅含待测密钥」，真实对应 health 三态；
6. **静态门禁全通**：`npx tsc --noEmit`、`npm test`、`npm run gate:static` 全绿退出码 0；
7. **纯前端零污染**：Git diff 零后端接口修改，零数据库变动。
