# 截图识别切换百度 OCR · 项目规划书

> 创建：2026-08-25 · 状态：进行中
> 决策人：阿禅 · 目标：首页截图识别从视觉大模型切换为百度「网络图片文字识别」，提升速度和稳定性，成本不设限

## 一、目标与成功判据

### 业务目标

组员上传日报截图后，识别更快、更少失败，提交链路不因 AI 通道抖动而中断。

### 成功判据（上线验收按此逐条打勾）

| # | 判据 | 现状基线 | 目标 |
|---|---|---|---|
| 1 | 单张数据图识别耗时 | 视觉模型约 5-20 秒 | **p95 ≤ 5 秒**（timings 拆分 download_ms / ocr_ms(兼容保留) / baidu_ms / structure_ms / total_ms，看分布不看单张最好成绩） |
| 2 | 识别成功率 | 无精确统计，偶发通道不可用 | 连续 20 张真实截图 ≥ 19 张成功 |
| 3 | 提交链路功能 | 8 项必测清单全过 | 全过且无新增失败项 |
| 4 | 数据口径 | 留存 4 数字 + 互动 6 指标正常入库 | 不变，一个不少 |
| 5 | 可回滚 | — | 出问题可在后台一键切回旧通道 |

## 二、范围边界（做什么 / 不做什么）

**做：**

- 两槽截图识别全部改为：百度 OCR 提字 → 文字模型结构化字段映射
- 接口对外返回结构不变，前端三个调用点零改动
- 后台增加独立开关，支持切回旧视觉模型通道（回滚保命符）

**不做（已明确砍掉）：**

- 曲线形态判断、留存分段分析、跳出/回放峰值识别（第 0 步已清理）
- 不动留存 4 个数字指标（均播时长、2秒跳出率、5秒完播率、整体完播率）的提取和入库
- 不动批改台的截图展示和历史数据
- 不出删除数据库死列的 migration（后续独立任务）

### 第 1 步 · 百度 OCR 客户端模块

新建独立服务模块（建议 `src/lib/baidu-ocr.ts`）：

- access_token 获取 + 缓存（30 天有效，内存缓存 + 过期前刷新；Serverless 环境接受冷启动重新换取）
- **入参前置校验按百度限制执行**（评审补充）：剥掉 `data:image/...;base64,` 头、urlencode、校验编码后大小 ≤4M 及图片边长限制；超限不进百度请求，直接返回可手填的降级结果
- 错误码映射到现有 `OcrErrorCode` 体系（**评审修正后的分类**）：
  - `110/111` token 无效/过期 → 自动刷新 token 重试一次（不是限流）
  - `18` QPS 超限 → RATE_LIMITED
  - `17/19/216604` 额度类 → CHANNEL_UNAVAILABLE + 管理员告警语义
  - `216201/216202/216205/282100` 图片/请求体问题 → 用户需重传
  - `282000` 服务内部错误 → AI_TIMEOUT 语义
- 超时 8 秒 + 失败抛出可识别错误类型
- Key 从环境变量读取：`BAIDU_OCR_API_KEY` / `BAIDU_OCR_SECRET_KEY`
- 同步更新 `.env.example` 和 `docs/reference/项目事实.md` 的环境变量清单（评审第 7 条）

已实测可用凭证：本地 `.env.local` 已配置并验证通过（token 换取 ✅ / webimage 接口权限 ✅ / 识别准确 ✅ / 约 1.3 秒 ✅）

### 第 2 步 · 识别接口改造

改造 `/api/ocr-screenshot/route.ts`：

1. 图片下载逻辑不动（storage 校验、格式校验、大小校验全保留）
2. 识别主链路替换为：百度 OCR 提取文字行 → callAi 文字模型把文字行映射为结构化字段（prompt 按槽位区分：screenshot_1 要 6 指标，screenshot_2 要留存 4 数字）
3. 返回 JSON **输出契约与现通道完全等价**（评审第 5 条）：`request_id` / `slot_status` / `screenshot_type` / `screenshot_type_source` / `recognized_fields` / `confidence_score` / `confidence`（互动图为 6 字段 high/medium/low，留存图为 nested numeric）/ `error_code` / `timings`；复用现有 parseOcrResponse / parseRetentionContent 输出契约或补全等价测试
4. confidence 由文字模型按字段给出，沿用现有 high/medium/low → 0.7 阈值机制
5. 旧视觉模型链路保留为函数，由后台开关控制走哪条通道，默认百度
6. `[perf]` 埋点补齐：baidu_ms / structure_ms 分开计时

### 第 3 步 · 后台开关与可观测性

- **通道开关的存储位置必须先定案再施工**（评审第 1 条，不能笼统写 ai_feature_config——该表是旧兼容定位，不是新业务入口）：
  - 需明确 `ocr_screenshot_channel = baidu | vision` 的真实存储位置、是否需要 migration、后台 UI/API 的读写路径
  - 候选方案：feature-catalog 扩展枚举配置项，或独立 settings 行；施工批次里二选一并写明理由
- 开关切换不需要发版
- api_log 的 detail 里记录 channel: baidu / vision，方便线上排查

**回退可用性验收（评审第 2 条，强制卡点）：** 上线前必须真实把开关切到 vision，确认 vision 通道仍绑定支持图片输入的模型（后台绑定不被文本模型占用），上传两张图完整跑通，才算"可一键回退"成立。
