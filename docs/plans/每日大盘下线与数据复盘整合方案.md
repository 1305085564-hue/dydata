# 每日大盘下线与数据复盘整合方案

> **决策背景**：每日大盘与数据复盘功能重叠，数据源相同，维护成本高，性能问题突出（首次加载11-16秒）。本方案将每日大盘的管理层诉求整合进数据复盘，统一入口和口径，降低维护成本。
> 
> **交付物**：产品设计方案（不涉及技术实现）

---

## 一、现状问题

### 1.1 功能重叠

| 页面 | 核心功能 | 权限 | 数据源 |
|---|---|---|---|
| **数据复盘** (`/admin/content`) | 作品列表 + 详情 + 作者画像 | 全员可看 | `loadAdminContentPageData` |
| **每日大盘** (`/admin/pulse`) | 总播放量 + 人员战报 + 作品列表 | 仅管理层 | 同上（二次汇总） |

**问题**：
- 每日大盘的"作品列表"与数据复盘完全重叠（只是默认筛选昨天）
- 每日大盘的"人员战报"本质是对数据复盘按负责人分组统计
- 数据复盘已有"作者作品画像"功能，能看单个作者的统计

### 1.2 性能问题

- 每日大盘首次加载耗时 11.6-16.9 秒
- 一个"快速看昨天"的页面如此慢，违背设计初衷
- 优化投入产出比低（使用频率不高）

### 1.3 维护成本

- 两套页面长期要保持：数据口径一致、筛选逻辑一致、权限规则一致
- 历史决策已明确"不做第二套评级标准"，说明已经意识到口径风险
- 每次改数据逻辑（如评级规则）需要同时验证两个页面

---

## 二、解决方案

### 2.1 核心改动

**下线每日大盘页面（`/admin/pulse`），将管理层诉求整合进数据复盘（`/admin/content`）**

具体做法：
1. 数据复盘顶部增加**"视图切换"**：普通视图 / 管理视图
2. 管理视图只对管理层可见（负责人、组长）
3. 管理视图提供每日大盘的核心功能：昨日概览 + 人员战报
4. 保留数据复盘的所有现有功能（作品列表、详情、筛选器）

---

## 三、管理视图详细设计

### 3.1 入口与权限

**位置**：`/admin/content` 顶部，筛选器上方

**显示规则**：
- 负责人、组长：显示"视图"切换器（普通 / 管理）
- 组员：不显示切换器，只能用普通视图

**交互**：
- 切换视图时保留当前筛选条件（日期、负责人等）
- URL 参数：`?view=management`，刷新后保持视图选择

### 3.2 管理视图布局

从上到下依次：

#### ① 昨日概览卡片（新增）

**样式**：4个数字卡片横排，桌面端一行，移动端两行

| 卡片 | 内容 | 颜色 | 说明 |
|---|---|---|---|
| 总播放量 | 数字 + "总��放" | 中性（元数据墨） | 昨天所有作品的播放量合计 |
| 总发片数 | 数字 + "发片数" | 中性 | 昨天发布的作品总数 |
| 优质作品 | 数字 + "优质" | 绿色（成功色） | 综合评级为"优"的作品数 |
| 异常作品 | 数字 + "异常" | 橙色（警示色） | 触发异常线的作品数 |

**默认行为**：
- 进入管理视图时，自动筛选昨天的数据
- 用户可以手动改日期，卡片数字跟着变

**点击行为**：
- 点"优质作品"：筛选器自动设为"综合评级=优"
- 点"异常作品"：筛选器自动设为"异常作品"
- 卡片数字变成可点击的链接样式（蓝色 + 下划线）

#### ② 人员战报表格（新增）

**表头**：

| 列名 | 宽度 | 说明 |
|---|---|---|
| 负责人 | 100px | 显示头像 + 姓名，可点击 |
| 发片数 | 80px | 该负责人昨天发布的作品数 |
| 总播放量 | 120px | 该负责人作品的播放量合计 |
| 优质作品 | 100px | 综合评级为"优"的作品数 |
| 完播达标 | 100px | 完播率达标的作品数 |
| 条均播放 | 120px | 总播放量 / 发片数 |

**默认排序**：按"总播放量"降序（复用每日大盘现有规则）

**可选排序**：点击表头可改按"发片数"、"条均播放"、"完播达标"排序

**点击行为**：
- 点击"负责人"：跳转到该负责人的作者作品画像（复用现有功能）
- 点击其他数字：筛选器自动设为"负责人=该人员"，表格下方的作品列表立即筛选

**空态**：
- 昨天没有数据：显示"昨天没有发布作品"
- 切换到其他日期，该日期无数据：显示"{日期} 没有发布作品"

#### ③ 作品列表（复用现有）

**显示规则**：
- 管理视图下，作品列表默认筛选昨天
- 用户可以手动改筛选条件（日期、负责人、评级等）
- 保留所有现有功能：排序、分页、详情抽屉、作者画像

**与人员战报的联动**：
- 点人员战报的某个负责人 → 作品列表自动筛选该负责人
- 筛选器显示当前筛选条件（高亮显示）

### 3.3 普通视图（现状保持）

**不改动任何现有功能**：
- 默认显示"全部"作品
- 筛选器、排序、分页、详情、作者画像保持原样
- 权限规则不变（全员可看）

## 四、每日大盘下线清单

### 4.1 页面与路由

**下线项目**：
- 页面：`/admin/pulse`（整个目录）
- 组件：`pulse-barometer.tsx`、`pulse-member-table.tsx`、`pulse-video-list.tsx` 等
- 路由：删除导航栏的"每日大盘"入口

**保留逻辑**（移植到数据复盘）：
- `computePulseSummary()`：计算总播放量、发片数、优质/异常作品数
- `computePulseMembers()`：计算人员战报
- `pulse-filters.ts` 的日期处理逻辑

### 4.2 导航与入口

**现有导航栏**（假设）：
- 工作台
- 数据复盘 ← 保留
- 发布管理 ← 保留
- ~~每日大盘~~ ← 删除
- AI配置
- 团队协作

**管理层的默认落地页**：
- 保持现状（不改）
- 如果之前是每日大盘，改为数据复盘（管理视图）

## 五、体验优化

### 5.1 快捷入口

**场景**：管理层早上打开系统，想快速看"昨天怎么样"

**方案**：
- 负责人、组长进入 `/admin/content` 时：
  - 自动切换到管理视图
  - 自动筛选昨天
  - URL 变为 `/admin/content?view=management&date=昨天`

**退出机制**：
- 用户手动切回"普通视图"，系统记住选择（localStorage）
- 下次进入时尊重用户选择，不再自动切管理视图

### 5.2 移动端适配

**昨日概览卡片**：
- 桌面端：4个卡片横排
- 移动端：2×2 网格

**人员战报表格**：
- 桌面端：显示所有列
- 移动端：只显示"负责人"、"发片数"、"总播放量"，其他列收进点击展开

**作品列表**：
- 保持现有的移动端适配（已有）

## 六、权限规则

| 角色 | 普通视图 | 管理视图 |
|---|---|---|
| 负责人 | ✅ 可看全公司 | ✅ 可看全公司 |
| 组长 | ✅ 可看本团队 | ✅ 可看本团队 |
| 组员 | ✅ 可看本人 | ❌ 不显示入口 |

**说明**：
- 完全复用现有的权限规则
- 管理视图只是在数据复盘基础上增加汇总展示
- 不新增权限判断，只在UI层控制"视图切换器"是否显示

## 七、数据口径一致性

### 7.1 评级规则

**统一来源**：
- 公司标准：`src/lib/evaluation-standards-store.ts`
- 默认值：`src/lib/evaluation-standards.ts`
- 异常线：`src/lib/video-review-thresholds.ts`
- 综合评级：`src/lib/breakout-rating.ts`

**保证**：管理视图的"优质作品"、"异常作品"与作品列表的评级徽章完全一致

### 7.2 作者认定

**统一规则**：
- 作者按 `accounts.profile_id ?? videos.user_id` 认定
- 人员战报的"负责人"与作品列表的"负责人"是同一个字段

### 7.3 日期口径

**统一规则**：
- 按上海发布日（`published_at` 转上海时区的日期）
- "昨天"：上海时区的昨天自然日

## 八、迁移与沟通

### 8.1 用户沟通

**目标用户**：管理层（负责人、组长）

**沟通话术**（给阿禅确认后发给团队）：

> **系统优化通知**
> 
> 为了提升数据查看效率，我们把"每日大盘"的功能整合进了"数据复盘"。
> 
> **变化**：
> - 进入"数据复盘"后，顶部有"视图"切换：普通 / 管理
> - 切换到"管理视图"，就能看到之前每日大盘的内容（昨日概览 + 人员战报）
> - 所有筛选、排序、详情查看功能保持不变
> 
> **好处**：
> - 一个页面搞定所有数据查看需求，不用在两个页面跳转
> - 数据口径统一，不会出现"两个页面数字不一样"的困惑
> - 加载速度更快（统一优化）

### 8.2 旧链接处理

**处理方案**：
- `/admin/pulse` 自动跳转到 `/admin/content?view=management&date=昨天`
- 保留 30 天，之后返回 404

## 九、验收标准

### 9.1 功能验收

| 项目 | 验收标准 |
|---|---|
| 视图切换 | 负责人、组长能看到切换器；组员看不到 |
| 昨日概览 | 4个卡片数字正确，点击能正确筛选 |
| 人员战报 | 表格数字与每日大盘完全一致，排序正确 |
| 作品列表 | 筛选、排序、详情保持原有功能 |
| 权限 | 组员看不到管理视图，负责人/组长能看 |
| 移动端 | 昨日概览2×2网格，人员战报折叠次要列 |

### 9.2 数据一致性验收

**对比验证**（下线前）：
1. 同一天的数据，每日大盘的数字 vs 新管理视图的数字
2. 总播放量、发片数、优质/异常作品数必须完全一致
3. 人员战报的每个负责人的数字必须完全一致

**工具**：
- 用测试脚本导出每日大盘的数据
- 新管理视图跑同样的查询
- 逐字段对比，100% 一致才能上线

### 9.3 性能验收

**目标**：
- 首次加载 < 5 秒（比每日大盘的 11-16 秒快）
- 切换视图 < 1 秒

**说明**：统一数据源后，优化一次即可，不需要分别优化两个页面

## 十、风险与预案

### 10.1 管理层反对

**风险**：管理层习惯了独立的每日大盘页面，不想整合

**预案**：
- 保留旧页面 30 天，同时新页面上线
- 30 天后根据使用数据决定是否完全下线
- 如果管理层坚持要独立页面，考虑极简版（只保留4个数字 + top3/bottom3）

### 10.2 数据不一致

**风险**：整合后发现某些边界场景的数字对不上

**预案**：
- 上线前必须做详细的数据对比验证
- 发现不一致，优先修复数据复盘的逻辑（作为统一真源）
- 记录差异原因，写进设计文档

### 10.3 性能仍然慢

**风险**：整合后性能没有明显改善

**预案**：
- 昨日概览和人员战报做独立的缓存（1小时）
- 作品列表保持现有的分页加载
- 管理视图的默认"昨天"筛选做预加载

## 十一、要你拍板

### 11.1 下线确认

**问题**：是否确认下线每日大盘页面（`/admin/pulse`），将功能整合进数据复盘？

**建议**：✅ 确认下线

**理由**：
- 功能重叠 80%，维护成本高
- 数据源相同，整合后口径天然一致
- 性能问题集中优化，投入产出比高

### 11.2 管理视图默认行为

**问题**：管理层（负责人、组长）进入数据复盘时，是否自动切换到管理视图并筛选昨天？

**建议**：✅ 第一次自动切换，之后记住用户选择

**理由**：
- 符合管理层的高频场景（早上看昨天）
- 尊重用户习惯（记住选择，不强制）

### 11.3 旧链接保留期

**问题**：`/admin/pulse` 的跳转保留多久？

**建议**：30 天

**理由**：
- 管理层使用频率不高，30 天足够适应
- 避免收藏夹的旧链接失效

### 11.4 沟通话术

**问题**：上面第八节的沟通话术是否需要修改？

**建议**：由阿禅确认或改写

**理由**：管理层是公司高层，沟通话术需要阿禅把关

## 十二、后续优化方向

**整合完成后，可以考虑的进一步优化**：

1. **智能提醒**：昨天有异常作品时，管理视图顶部显示橙色提示条
2. **趋势对比**：昨日概览卡片增加"vs前天"的涨跌箭头
3. **快速筛选**：人员战报表格增加"只看异常"、"只看优质"的快捷按钮
4. **导出功能**：人员战报支持导出为 Excel

**说明**：这些都是锦上添花，不影响本次整合方案，可以后续迭代时再评估。
