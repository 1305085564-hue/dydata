# B2 数据库与维护性欠账实施方案（2026-09-26）

> 交付给独立代理执行。范围：P1 数据库库存/RPC 清理、A-21/B-16 到期观察复核、可维护性剩余项。
> 删除型工作必须先完成生产只读盘点与回滚准备；本方案不等于生产删除授权。
> 观察期未到的事项只准备查询，不提前判定可删。

## 开工三问

1. **交付物**：数据库候选对象清理方案与安全 migration 候选、A-21/B-16 观察结果（到期后）、维护性缺陷和拆分分批结果。
2. **验收命令**：各子项定向测试/数据库演练、`npx tsc --noEmit --pretty false`（涉及 TS 时）、`git diff --check`；生产状态以真实只读查询为准。
3. **边界**：不得生产 DROP/DELETE，不得删除观察期内对象，不得改变生产数据。未获明确保留期或数据/权限证据时停在只读方案；不同领域分开提交。

## 共用纪律

- 先读实际迁移、当前维护入口、代码调用点和生产只读证据。日志、历史方案和 grep 结果不能单独证明生产对象可删。
- `violation_cases` 明确在 conversion-hub 话术链路使用，禁止删除。
- migration 只能新增；上线必须应用代码先具备部署条件，并经过本地/隔离库重放和权限核验。
- 不运行 `git add -A`、`git add -u`；不自动 push/deploy。
- 本 B2 包含不同时间触发项。每个子项独立开始、验收、停止，弱模型不得自动从一个子项续做下一个。

## B2-1 P1 清理库存 DB/RPC

### 目标对象与前置判断

按 [历史清理库存草案](../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-09-08-P1库存DB清理草案.md) 复核 `knowledge_cases` 家族 5 表、`violation_test_records`、`smart_alert_claims` 与孤儿 RPC。`violation_cases` 及 conversion-hub 依赖必须保留。同步复核 middleware `/violations/:path*` 与 `review_violations` 权限键，现有结论为保留。

### 阶段 0：只读盘点（现在可做）

1. 逐表核对生产 `to_regclass`、行数、最近写入时间、RLS/ACL、触发器、外键、视图、函数依赖。
2. 查询生产 `pg_proc`、`pg_depend` 和当前迁移账本；逐 RPC 记录 owner、security definer、grant、调用日志/统计证据。
3. 复核现行代码调用者、外部/手动触发入口；静态无引用不等于可删。
4. 产出对象矩阵：保留/可删候选/证据不足；每个可删候选列出依赖解除顺序和回滚方式。
5. 只有数据保留期已获阿禅确认，才进入阶段 1。

### 阶段 1：候选 migration 与隔离库验证

- 仅新增 migration；不直接执行生产 SQL。
- `DROP` 前处理外键、策略、视图和函数依赖；禁止用未解释的 `CASCADE`。
- 对可能含业务数据的表先导出加密/受控快照，确认恢复路径和责任人。
- 空库重放与“模拟生产对象存在且有数据”的升级路径都必须验证；migration 重复执行行为按 Supabase 正常一次性迁移语义处理，不靠伪造空表吞错误。
- 验证 `violation_cases`、conversion-hub、`review_violations` 权限和 middleware 结果未变。

### 停止条件

- 保留期未确认。
- 生产存在活跃写入、外部触发或未解释数据。
- `violation_cases` / 现役权限链路受到影响。
- 生产只读连接不可用，无法形成基线。

### 验收命令

```bash
npx supabase db reset --local
npx tsx --test <本批新增或受影响的migration测试> <本批受影响代码测试>
git diff --check
```

若本地 Docker/Supabase 不可用，记录具体错误并 `BLOCKED`；隔离 PostgreSQL 可提供补充证据但不能冒充命令通过。生产删除需另有明确授权，不在该命令内执行。

## B2-2 A-21 / B-16 观察期复核

### 时间门槛

- 待办规定 2026-10-18 复核。该日期前禁止删除、改写对象或改变调用路径。
- 到期后再查：A-21 `audit_logs.action = 'cleanup_observation_a21_claim'`；B-16 的 7 个 RPC 在 `pg_stat_user_functions` 的观察结果。
- Postgres 函数统计可能受重启、track_functions 配置、统计重置影响。先核对统计口径和观察窗口；单一计数为 0 不足以证明长期无调用。

### 交付

1. 记录观察开始/结束时间、数据库启动/统计重置证据、track_functions 设置。
2. 对 A-21 与 7 个 RPC 分别记录调用数、时间范围、可见性限制和统计可信度。
3. 若全为 0 且观察证据完整，只产出逐个删除建议和依赖矩阵；任何一个非 0 或证据不完整则保留。
4. 删除需另立迁移施工单，不能在观察复核单里顺手清理。

### 停止条件

- 2026-10-18 前执行。
- 数据库统计已 reset 或 track_functions 不覆盖目标。
- RPC 在系统视图里不可观测或未核外部调用入口。

## B2-3 已知维护性缺陷

待办记录的三处历史缺陷：历史编辑态缺“取消”按钮；无候选兜底路径无法由真实 UI 到达；受控触发后 effect 依赖 `comparisonMembersLoading` 导致请求自中止。证据在 `output/maintenance/04-验收.md` 和 `docs/archive/2026-11-09-A批文档治理/计划原稿/历史-项目/2026-09-16-可维护性实施方案/04-复杂组件职责拆分.md`。

### 施工顺序

1. 重新检查现代码和既有验收证据，判断是否已经被后续提交修复；确认前不重复开工。
2. 历史编辑取消：先明确 editToday/历史编辑/新建三种模式下取消的目标状态，优先复用当前 panel `onCancel` 和确认保护；不改保存逻辑。
3. 无候选兜底：先向产品确认“无候选时是否仍需让用户选择指定成员”；如果无需该路径，删除不可达死逻辑需单独记录产品决定；如果仍需，则设计最小可达 UI 后才施工。不得只修 effect 却保留不可达入口。
4. effect 自中止：若路径仍有效，修正请求生命周期依赖并覆盖 loading→success/error→retry/unmount；使用真实组件/hook 测试，不以源码正则替代。
5. 每个缺陷独立提交。依赖产品决定的缺陷标记 `BLOCKED`。

### 验收

- 受影响历史编辑表单和 content comparison 定向测试。
- 真实浏览器只验证对应入口/状态，记录截图、请求和 console；不跑全站浏览器门禁。
- `npx tsc --noEmit --pretty false`、目标 ESLint 文件、`git diff --check`。
