## 〇、总纲

本次改造只做两件事：

1. **单指标双线颜色标注**：每个数据格只做「优质=绿 / 正常=默认色 / 预警=红」标注，不做评级；
2. **原方案批次 1 的三处小改**：分段容器改独立按钮、「去盘→」改「详情」、小数值去千分位。

原方案批次 2（阈值配置系统、数据库迁移、配置弹窗、API）**整体作废**，留给第二期视情况再立项。

## 一、最终定稿的方向与结论（阿禅已裁决，照做即可）

| # | 结论 | 内容 |
|---|------|------|
| 1 | **播放门槛 5,000，已定稿** | 播放 5,000 以下（不含 5,000）的作品**不套这套阈值判定**：不标色、比率降灰（现有样本不足降灰保留）、不参与爆款/优秀作品评选。实测该门槛会排除约半数（53.6%）作品，阿禅 10-24 终裁「半数就半数」，**不再复核，此数定稿** |
| 2 | 阈值全站统一 | 阈值是全公司一套标准，**不做按用户的个人配置**，每个人看到的颜色必须一致 |
| 3 | 三档颜色 | 正常档 = 默认色（完全不着色，注意不是灰色）；优质 = 绿色强调；预警 = 红色警示（文字红，可加极浅红底）。绿色是强调色，与"正常无颜色"是两种东西 |
| 4 | 命名：优质 / 正常 / 预警 | **不用「异常」**：页面上「异常」已固定指限流/删稿/异常的平台处罚状态（异常按钮、异常计数、详情入口都是它），数据标注再叫「异常」无法干净区分，且历史状态词不许改。第三档一律叫「预警」 |
| 5 | 只标注、不评级 | 对单个数据只把**明显异常**的标出来（红）和**明显好**的强调出来（绿）。没有"数据评级"逻辑、**不新增**评级列、没有优秀/正常之类的评级标签；现有作品「评级」列（优良普劣，评价内容的）保留不动，两者同屏不一致属正常 |
| 6 | 不做整条数据总评 | 不给整条视频判"数据优秀/正常/异常"。整条作品的评价只保留现有「评级」列（优良普劣 4 档，未来阿禅会改成 3 档——那是对整条内容的定性，与本次单指标标注是两回事，本次不动） |
| 7 | 不做一键筛选 | 第一期不做"只看数据差的"筛选；顶部「异常」按钮语义与位置保持原样，不改。两个筛选日后怎么融合，后期再看 |
| 8 | **阈值第一期固定写死，后期再考虑手工配置** | 第一期阈值直接写在 `video-review-thresholds.ts` 里，改值走代码发布，全站同步。**"手工选择阈值"的配置入口放到后面**：颜色标注跑一段时间后，若确有必要再立项做配置界面。原方案批次 2 的配置表、弹窗、API 本期全部不做 |
| 9 | 阈值数值先用建议值上线 | 本单第四节的优质线/预警线数值为按真实数据分布定的建议值，**先拿着正常用**；日后觉得不合适再调整（改常量走发布） |
| 10 | 批次 1 三处小改照做 | 原方案说的独立按钮、「详情」改名、千分位修正属正常修改，照做（细节见第三节） |

## 四、阈值常量规格（施工用，数值已定稿先用）

全部数值集中 `src/lib/video-review-thresholds.ts`，禁止在任何页面硬编码数值（爆款评级侧从 `src/lib/breakout-rating.ts` 派生，页面文案用常量插值）。

**改法是"新增"，不是"替换"**：现有常量对象里的告警线（2秒跳出 30 / 5秒完播 50 / 完播 5 / 均播 30）正在驱动复盘队列优先级（`review-queue.ts`），**原样保留一个字都不动**；`play_count: 5000` 也已改好，不要重改。只在对象上**新增** `excellent` 与 `poor` 两组子对象，与现有键并存。下图为结构示意：

```typescript
export const VIDEO_REVIEW_RULE_THRESHOLDS = {
  // 播放门槛：低于 5000 不套用本表任何判定（2026-10-24 阿禅定稿，已改）
  play_count: 5000,
  // 优质线（亮绿）——2026-10-24 定稿先用，后续调整走发布
  excellent: {
    bounce_rate_2s: 25,      // ≤25% 亮绿（约 19% 作品达到）
    completion_rate_5s: 55,  // ≥55% 亮绿（约 15%）
    completion_rate: 8,      // ≥8% 亮绿（约 22%）
    avg_play_duration: 40,   // ≥40s 亮绿（约 33%）
  },
  // 预警线（亮红）——取数据最差约一成，2026-10-24 定稿先用
  poor: {
    bounce_rate_2s: 36,      // ≥36% 亮红
    completion_rate_5s: 32,  // ≤32% 亮红
    completion_rate: 2.2,    // ≤2.2% 亮红
    avg_play_duration: 16,   // ≤16s 亮红
  },
};
```

- 现行复盘告警线（2秒跳出 30 / 5秒完播 50 / 完播 5 / 均播 30）继续驱动复盘队列优先级，**不动**；
- 备注：若日后把预警线改成现行告警线，须知悉 5秒完播 <50% 会红 63% 的格子（数据实测报告 §7），不建议。

## 五、着色逻辑规格（伪代码）

```
对每个比率/时长格（2秒跳出率、5秒完播率、完播率、均播时长）：
  若比率越界（脏值）        → 保持现有标红+虚线+tooltip，不参与本次分档
  否则若播放 < 5000          → 保持现有降灰 + tooltip「播放不足 5,000，样本不足，仅供参考」，不着色
  否则若命中优质线            → 绿色文字（text-status-success，无背景）
  否则若命中预警线            → 红色文字（text-status-danger）+ 极浅红底（bg-status-danger/5）
  否则                        → 默认文字色，完全不着色
2秒跳出率方向相反：≤优质线 绿、≥预警线 红；其余三项 ≥优质线 绿、≤预警线 红。
每个着色格带悬浮提示，大白话解释「这个数字算好/算差的依据」（数值用常量插值，禁止写死）。
```
