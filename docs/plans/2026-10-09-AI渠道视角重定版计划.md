# AI 渠道视角重定版计划

## 1. 目标

把“算力储备”从当前的“供应商 + 分组标签”展示，改成真正的“渠道 + 模型”产品视角：

- 渠道是用户唯一看到的接入名称，由“供应商名称 + 分组名称”组成，例如 `api9 Claude`。
- 模型仍然作为渠道下的第二层能力展示，所有模型使用完整、可读名称。
- 供应商和分组只在“接入渠道”这个配置动作中出现，用于完成接入；其他页面不再把它们当作独立业务对象展示。
- 分组标签最终只保留 4 个：`Claude`、`Gemini`、`ChatGPT`、`其他`。原来的 `default` 归入 `其他`；`gpt`、`gemin` 等旧简称统一规范化。

## 2. 已确认的现状

### 现有链路

`/admin/ai-config` → `AIConfigShell` → `ComputePoolPanel` → `ChannelPoolView` / `ModelFamilyCard` → `/api/admin/ai-config` → `ai_providers`、`ai_provider_keys`、`ai_provider_key_models`。

运行时仍需要供应商、密钥和模型三层数据来做地址、密钥健康、优先级和故障切换；这部分属于内部接入实现，不等于产品展示概念。

### 当前造成混淆的地方

- `channel-list.tsx:30-40, 89-93`：把 `key.label` 当主名称，再把 `providerName` 当副名称；实际仍是分组视角。
- `channel-pool-view.tsx:82-98, 174-228`：详情中显示供应商、分组名称、所属供应商、是否启用分组。
- `add-key-dialog.tsx:251-312`：接入时的标签仍是 `claude / gemini / gpt / default`，允许旧标签继续进入系统。
- `model-family-card.tsx:286-288`：模型视角里把 `供应商 · 分组`直接展示给用户。
- `compute-pool-panel.tsx:70-97`：模型分组记录中继续以 providerName 组织展示。
- `providers-dialogs.tsx` 与多个按钮仍混用“渠道服务商 / 供应商 / 渠道”，产品名称不统一。
- `model-families.ts:2-33`：模型名称映射不完整，部分 GPT 仍显示简称或原始 ID。

## 3. 推荐方案

采用“展示层建立渠道口径，底层接入结构暂不拆库”的方案。

### 为什么这样做

- 能立即把所有页面的用户心智统一成“渠道 + 模型”。
- 不破坏现有密钥健康、供应商地址、优先级和自动切换能力。
- 避免为了改名而重写 AI 调度链，回归范围更小。
- 后续如果真的要把供应商表从底层删除，可以另立数据库重构任务；本轮不扩大范围。

### 不采用的方案

- **直接把供应商表改名或删除**：会牵动密钥、模型、健康状态、路由和历史绑定，当前需求不需要，风险过大。
- **只改文字不清洗数据**：页面看似改好，但旧的 `api9-claude`、`gpt`、`default` 等值仍会继续生成脏渠道，下一次接入还会复发。

## 4. 产品规则

### 渠道命名

- 渠道展示名统一由 `供应商名称 + 分组标签全称`组成，例如：`api9 Claude`、`api7 Gemini`。
- 分组标签只用于接入表单的选择/录入；保存后所有列表、详情、模型卡、业务绑定、健康状态、测试结果、错误提示都使用渠道名。
- 优先级属于渠道排序属性，展示为“渠道优先级”，不再暗示“分组优先级”。
- 供应商名称、API 地址、API Key 只在接入/编辑接入资料时出现；普通渠道浏览页只显示渠道名、优先级、状态和模型。

### 分组标签清洗

- `gpt` 统一改为 `ChatGPT`。
- `gemin` 统一改为 `Gemini`。
- 其他旧值（包括人工加上的 `api数字-` 前缀、`default`、无法归入白名单的值）先列清单，再按这 4 个标签做一次性映射；无法归类的值不自动猜测。
- 不对未知值静默猜测；无法映射的记录进入阻断清单，避免把真实渠道改错。

### 模型名称

- 模型 ID 仍保留给系统调用和审计。
- 用户界面统一使用完整模型名称；GPT 系列补齐全称映射，未命中的模型使用稳定的可读兜底，不直接把内部 ID 当标题。

## 5. 施工阶段

### 阶段 A：只读盘点与口径冻结

- 导出当前供应商、分组标签、渠道数量、模型 ID、业务绑定和健康状态的只读清单。
- 统计所有非白名单标签，特别标出带供应商前缀、`gpt`、`gemin`、`default` 和无法识别的值。
- 确认 4 个合法分组标签的最终大小写和显示规则。
- 产出映射表：旧值 → 新分组标签 → 新渠道展示名。

完成条件：每条现有接入记录都有明确的归属；未知项明确列为 BLOCKED，不进入自动更新。

### 阶段 B：建立统一渠道展示口径

- 在 AI 配置数据转换层集中生成 `channelName`，禁止各组件自行拼接 `providerName + label`。
- 让渠道列表、渠道详情、模型卡、模型管理、同步模型、检测结果、可用性报告、业务绑定弹窗全部读取 `channelName`。
- 统一状态文案为“渠道健康 / 渠道待测 / 渠道熔断 / 渠道已停用”。
- 将“供应商”保留为接入资料字段，不再作为普通页面的展示维度。

完成条件：全站 AI 配置相关页面只出现“渠道 + 模型”；供应商/分组只在接入或编辑接入资料时出现。

### 阶段 C：先收口页面动作，再改接入流程

当前页面同时存在“添加供应商、接入渠道、管理供应商、检测渠道、测试全部渠道、探测并同步模型、同步模型、全池体检”，实际是三类动作被重复命名：接入资料管理、连通性检查、模型发现/上架。

- **接入资料**只保留一个主入口：`接入渠道`。供应商选择、API 地址、API Key、合法分组标签都在这个流程内完成；“添加供应商”和普通浏览态的“管理供应商”不再作为并列主按钮。
- **连通性检查**合并为两个清晰层级：当前渠道的`检测渠道`，全部渠道的`检测全部渠道`。顶栏“全池体检”不再另设一套同义入口，改为全局状态摘要或并入“检测全部渠道”。
- **模型发现/上架**只保留一个动作名：`同步模型`。单渠道从渠道详情触发；全部渠道从算力储备工具栏触发；删除“探测并同步模型”这个容易误解的重复名称，并在结果中明确“发现了多少、上架了多少、失败了多少”。
- 按以上三类动作重新安排按钮位置：工具栏只放“检测全部渠道 / 同步全部渠道模型 / 接入渠道”；渠道详情只放“检测当前渠道 / 同步当前渠道模型”；供应商资料编辑只作为接入流程中的次级操作。
- 所有按钮补充结果反馈，明确动作对象（当前渠道/全部渠道）和结果（连通、发现、上架、失败），不再用“体检、测试、探测”混称同一件事。

完成条件：用户看到按钮名称就能判断“是在接入、检查连通，还是同步模型”，且每个动作只有一个入口。

### 阶段 D：接入流程改成最终口径

- 接入渠道表单保留两步资料：选择供应商接入点、选择合法分组标签。
- 表单实时展示最终渠道名预览，例如 `api9 + Claude = api9 Claude`。
- 禁止输入未在白名单内的标签；旧简称不再作为快捷按钮。
- 新建和编辑保存时，保证渠道名可唯一识别；同一供应商下同一分组不重复创建。
- “管理供应商”从普通算力浏览区移入接入资料入口，避免它继续成为主导航概念。

完成条件：新接入记录不会再产生 `gpt`、`gemin`、`default` 或供应商前缀分组；`default` 只能以“其他”保存。

### 阶段 E：清洗现有数据

- 先执行阶段 A 的映射预览和数量核对。
- 用一条可回滚、可审计的迁移或受控脚本，把 `ai_provider_keys.label` 清洗为白名单标签；去除人工添加的供应商前缀。
- 清洗后重新生成渠道展示名，不改 API Key、地址、优先级、模型关联和健康状态。
- 对无法映射的记录保持原值并标记阻断，不强行修改。

完成条件：线上现有渠道全部能按最终规则显示，关键绑定和调用链未断。

### 阶段 F：模型名称和“算力储备”收口

- 完善 `model-families.ts` 的完整名称映射，覆盖当前真实模型清单，尤其是 GPT 系列。
- 模型视角按“模型名称 → 可用渠道列表”展示，渠道列表只显示渠道名和优先级。
- 渠道视角按“渠道名称 → 模型列表”展示，移除“供应商 · 分组”的重复组合。
- 删除或改名所有“分组名称、是否启用分组、所属供应商”这类普通浏览态字段；接入表单中的配置字段保留但限定在接入场景。
- 清理页面标题、说明、空状态、按钮、弹窗、错误提示中“供应商/分组/服务商/渠道”混用的旧文案。

完成条件：用户在算力储备页能直接回答“有哪些渠道、每个渠道有哪些模型、优先级和健康状态如何”。

## 6. 需要修改的文件范围

### 预计修改

- `src/app/(app)/admin/ai-config/components/channel-list.tsx`：只显示统一渠道名和渠道优先级。
- `src/app/(app)/admin/ai-config/components/channel-pool-view.tsx`：移除普通浏览态的供应商/分组展示，保留接入资料编辑能力。
- `src/app/(app)/admin/ai-config/components/add-key-dialog.tsx`：改为白名单分组标签和渠道名预览。
- `src/app/(app)/admin/ai-config/components/model-family-card.tsx`：用渠道名替代供应商 + 分组。
- `src/app/(app)/admin/ai-config/components/model-manager-dialog.tsx`、`sync-models-dialog.tsx`：统一渠道展示。
- `src/app/(app)/admin/ai-config/components/providers-dialogs.tsx`：只作为接入资料管理入口，统一文案。
- `src/app/(app)/admin/ai-config/components/compute-pool-panel.tsx`：复用统一渠道转换结果，合并重复动作入口，清理旧视角文案。
- `src/app/(app)/admin/ai-config/hooks/use-ai-config.ts`、`src/lib/ai-config/availability.ts`：补充/复用统一渠道展示字段。
- `src/lib/ai/model-families.ts`：补齐真实模型的完整显示名。
- `src/app/api/admin/ai-config/route.ts` 及相关 action：接入标签白名单、重复校验和错误文案。
- `src/app/(app)/admin/ai-config/hooks/use-ai-config.ts`：把单渠道检测、全渠道检测、单渠道同步、全渠道同步四类动作的命名和反馈统一。

### 需要新增或更新

- 一个集中维护分组白名单、规范化和渠道名生成的纯函数模块及单元测试。
- 一份数据清洗 migration 或受控数据脚本（仅在阶段 A 映射表确认后创建）。
- AI 配置页面的行为测试：新建、旧值拦截、渠道名展示、模型名展示、绑定不丢失。

### 明确不改

- 不删除 `ai_providers`、`ai_provider_keys`、`ai_provider_key_models` 表。
- 不改 AI 调度的优先级算法、健康熔断、故障切换和业务功能绑定语义。
- 不扩展到其他业务模块的普通“分组”概念；这里只处理 AI 配置中的分组。

## 7. 验收方式

1. 静态与行为测试：
   - `npm test -- --runInBand`（或仓库当前可用的定向测试命令）
   - AI 配置相关 route/component/lib 测试必须覆盖白名单、规范化、渠道名和模型名。
   - AI 配置页面测试必须覆盖四类动作：当前渠道检测、全部渠道检测、当前渠道同步模型、全部渠道同步模型；并确认旧按钮文案不再出现。
2. 真实页面验收：
   - 进入 `/admin/ai-config`，分别检查模型视角和渠道视角。
   - 新建一条接入：供应商和分组只在接入表单出现，保存后列表只显示渠道名。
   - 检查渠道详情、模型卡、同步模型、检测结果、业务绑定弹窗，不再出现旧的“供应商 · 分组”展示。
3. 数据对账：
   - 清洗前后逐条核对渠道数量、模型关联、业务绑定、优先级、启用状态和健康状态。
   - 对未知标签和无法映射记录输出 BLOCKED 清单，不以页面显示正常代替数据闭环。

## 8. 风险与待确认

- 分组标签已确认只有 4 个：`Claude`、`Gemini`、`ChatGPT`、`其他`。
- 如果供应商名称后续允许改名，渠道展示名应实时跟随；如果渠道名必须永久不变，则需把渠道名单独持久化，这属于另一项数据模型决策。本计划推荐实时组合展示，避免名称漂移和重复存储。
- 带供应商前缀的历史分组值不能仅靠字符串替换处理，必须先做只读映射预览并逐项核对。

## 9. 最终验收标准

- 算力储备页的两个视角统一为“渠道 + 模型”。
- 新旧渠道都能按统一渠道名识别；旧简称和供应商前缀分组不再产生。
- 接入流程仍能配置供应商、地址、密钥和合法分组标签。
- 模型、优先级、健康状态、业务绑定和故障切换行为保持不变。
- 无法确认的历史数据单独标记，不被伪装成已完成。
