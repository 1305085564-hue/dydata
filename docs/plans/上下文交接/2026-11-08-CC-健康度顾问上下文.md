## 为架构讨论准备的关键事实
- 规模：约 18 万行、1225 个文件、93 个接口；最近 30 天 695 次提交，约 135 次是修复或返工（约 1/5）。
- 多 Agent 分工：CC 统筹，An 前端视觉，CX 逻辑，QW 审查；push main 就是上线（Vercel），没有 CI，没有预览环境把关。
- 已有机制：
  - AGENTS.md 开工卡和收尾卡（134 行）；
  - 产品全书是文档路由；
  - 工程运行事实、纠错索引、ADR；
  - gate:static / roles / browser / design / maintainability；
  - preflight:release。
- 典型事故：
  - 11-07 为压行数删掉导入，截图识别全挂（规则反噬加检查失真）；
  - AI 自报 tsc 通过，实际 58 个错误；
  - 并行会话把未授权的改动推上线；
  - 本地 3000 端口的开发服务连的是生产库（只靠规则禁止）。
- 我倾向的架构思路（待讨论，还没跟他说透）：
  - 约束放在离 AI 最近、且不靠自觉的位置：自动检查优先于文档规则；
  - 少而硬的关口：上线前、改数据库前、改权限前；
  - 唯一来源加统一入口：日期、口径、权限各只有一处；
  - 产品经理只验证据，不验代码；
  - 每月体检看分数趋势；
  - 规则也要有"删除机制"，防止只增不减。
