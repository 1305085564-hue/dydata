## 一、改造背景与核心痛点

1. **层级倒错与猜谜（P0）**：
   在现有的【渠道视角】下，供应商卡片把名下的所有 Key 堆在上面，把所有模型去重平铺在最底部。导致用户看到“3 个 Key（2 绿 1 红），2 个模型，可用 0”时，**根本看不出底部的模型到底属于哪个 Key，谁把谁弄死的一无所知**。
2. **缺乏专线大盘视角（P1）**：
   大部分中转站都按系列配置了相同的分组（如 `claude` 专线、`gemin` 专线、`default` 专线）。目前缺乏一个能横向纵览“全网 Claude 专线分布在哪些供应商、整体健康度如何”的【分组视角】。
3. **故障颗粒度一刀切（P1）**：
   现状下 Key 只要有一条失败记录，整行甚至整个渠道都被打成故障红灯。然而真实业务中，经常出现**中转站是通的，但上游某一个特定模型下架/限流**；需要实现“坏哪个模型红哪个模型，渠道仅提示部分异常；全部模型坏或渠道断连才亮大红灯”。
4. **假概念误导（P2）**：
   弹窗标题使用“新建/编辑 API 密钥分组”，造成认知混乱。

## 二、目标架构：算力底座三维矩阵

数据层**零新增表、零后端改造**，完全基于当前下发的 `bundle` 数据，在纯前端进行三维切面派生：

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        算力底座三重视角全景                            │
├───────────────────┬───────────────────┬────────────────────────────────┤
│ 视角              │ 聚合第一层        │ 展开层级                       │
├───────────────────┼───────────────────┼────────────────────────────────┤
│ 1. 分组视角 (新)  │ 密钥专线分组      │ 分组 (如 claude)               │
│    (全网专线大盘) │ (如 claude/gemini)│   ↳ 分布在各供应商 (api1, api7)│
│                   │                   │     ↳ 包含模型与状态           │
├───────────────────┼───────────────────┼────────────────────────────────┤
│ 2. 渠道视角 (改)  │ 供应商 / 渠道     │ 供应商 (如 api7)               │
│    (各中转站清单) │ (如 api7)         │   ↳ 名下专线分组 (default,gemin)│
│                   │                   │     ↳ 该分组专属模型与状态     │
├───────────────────┼───────────────────┼────────────────────────────────┤
│ 3. 模型视角 (存)  │ 具体模型          │ 模型 (如 gemini-2.5-flash)     │
│    (业务容灾顺位) │ (如 DeepSeek-V3)  │   ↳ 供货来源: [供应商] 分组名  │
│                   │                   │   ↳ 容灾顺位 (P1/P2/P3)        │
└───────────────────┴───────────────────┴────────────────────────────────┘
```

## 三、双层故障诊断与红绿灯级联逻辑

严格遵循阿禅的补充规则，实行**从模型到渠道的向上级联计算**：

| 节点 | 判定条件 | 视觉反馈 | 提示文案示范 |
| :--- | :--- | :--- | :--- |
| **单个模型** | • 连通探测正常且无该模型失败记录<br>• 上游该模型调用报错 / 探测失败 | 🟢 正常<br>🔴 故障 | ✓ 310ms<br>✗ 上游报错: model_not_found |
| **密钥分组** | • 名下所有模型正常<br>• 名下**部分模型故障**，但仍有模型可用<br>• 分组自身网络断连/401/欠费，或名下**所有模型全军覆没** | 🟢 就绪<br>🟡 局部受阻<br>🔴 全线故障 | 全部正常<br>部分模型异常 (1/2 可用)<br>专线断连 / 所有模型不可用 |
| **供应商卡片** | • 名下所有分组全绿<br>• 有部分分组处于受阻或故障状态<br>• 名下**所有分组全部故障**或服务商停用 | 🟢 全线健康<br>🟡 部分受阻<br>🔴 渠道瘫痪 | 3/3 专线就绪<br>2/3 专线就绪 · 部分异常<br>全线故障 (0/3 就绪) |

## 四、具体实施任务拆解 (Tasks)

### Phase 1：渠道视角彻底重构（立即消灭截图盲区）
> 目标：将 `api7` 内部的模型平铺改成树状从属，模型紧跟分组，彻底解决“谁属于谁”的猜谜问题。

- [ ] **T1.1 重构 `provider-channel-card.tsx` 内部骨架**：
  - 取消卡身底部的独立 `<div className="p-3.5 bg-white">` 模型平铺区；
  - 在每个密钥行（分组行）内部下方，直接渲染属于该密钥的 **挂载模型子清单**；
  - 若该分组未勾选模型，显示温和弱化占位：`未开启上架模型 · 点击「同步模型」添加`。
- [ ] **T1.2 模型卡片归属与状态呈现**：
  - 每个模型子项包含：模型显示名称、`model_id`、独立健康圆点（🟢/🔴）、错误原因摘要；
  - 明确展现因果关系：若当前分组故障，其子模型直接标注 `🔴 不可用 (依赖此分组)`。
- [ ] **T1.3 级联状态计算优化**：
  - 更新卡头与分组状态徽标，实施“部分受阻（黄灯）”与“全线故障（红灯）”的分级逻辑。

### Phase 2：构建全新的【分组视角】(Group Pool View)
> 目标：让管理员一屏看清全站专线大盘（如全网所有 Claude、Gemini 分组分布）。

- [ ] **T2.1 新建 `group-pool-view.tsx` 组件**：
  - 纯前端聚合逻辑：遍历 `bundle.keys`，按 `key.label`（标准化小写 trim 后）分组，聚合各分组在不同 `provider` 下的分布与绑定的 `models`；
  - 识别常见专线系列（如 `claude`、`gemini`、`gpt`、`deepseek`、`default`）；
- [ ] **T2.2 分组专线卡片渲染**：
  - 卡头：分组名称（如 `🏷️ gemin 专线`）+ 接入供应商数（如 `分布在 2 家供应商`）+ 专线整体健康度；
  - 卡身展开：按供应商平铺展开（如 `[api7] 供应商`、`[api2] 供应商`），列出各自的连通性、延迟与下属模型。
- [ ] **T2.3 快捷连通测试集成**：
  - 支持针对特定专线分组做一键测试（例如只测全网所有 `claude` 专线）。

### Phase 3：切换控件升级与模型视角对齐
> 目标：打通三重视角切换，统一词汇与弹窗。

- [ ] **T3.1 扩展 `PoolViewSwitcher`**：
  - 将双段切换器升级为三段分段控件：`[ 渠道视角 | 分组视角 | 模型视角 ]`；
  - 适配移动端/窄屏下的发丝边界与无障碍 `aria-pressed` 属性。
- [ ] **T3.2 模型视角来源强化 (`model-family-card.tsx`)**：
  - 在展开的渠道密钥明细行中，来源标题由 `providerName · key.label` 强化为清晰的：
    **`[供应商] 渠道名 · 分组标签`**，让模型供货来源一目了然。
- [ ] **T3.3 弹窗假概念清理 (`providers-dialogs.tsx`)**：
  - 弹窗标题统一：“编辑 API 密钥分组” → **“新建 / 编辑专线密钥”**；
  - 输入框“分组 / Key 名称”改为 **“专线分组名称”**；
  - 提供快捷常用分组药丸：`[default]` `[claude]` `[gemini]` `[gpt]` `[deepseek]`，点选直接填入，杜绝拼写错误。

## 六、验收判据与成功标准

1. **直观性验证（截图复测）**：
   - 打开 `api7` 渠道卡，1 和 2 两个模型必须紧贴在 `gemin` 分组下方，完全消除“猜谜”；
   - 3 和 5 两个分组下方显示无模型，不会与 4 发生混淆。
2. **故障级联验证**：
   - 当 `gemin` 分组故障但 `default` 和 `claude` 正常时：
     - `gemin` 分组与 1、2 模型亮红灯 🔴；
     - `api7` 卡头显示**黄灯 🟡（部分受阻，2/3 分组健康）**，严禁亮大红灯；
     - 只有当 3 个分组全挂或渠道断网时，`api7` 才亮大红灯 🔴。
3. **三重视角切换验证**：
   - 点击 `[分组视角]`：一屏列出全网所有固定分组大盘，点击展开各供应商分布；
   - 点击 `[渠道视角]`：按中转站供应商列出名下所有专线及模型；
   - 点击 `[模型视角]`：按具体模型排容灾顺位。
4. **门禁与零衰退**：
   - `npx tsc --noEmit` 退出码 0；
   - `npm test` 保持现有 2073+ 单测全绿；
   - 界面无任何控制台报错。
