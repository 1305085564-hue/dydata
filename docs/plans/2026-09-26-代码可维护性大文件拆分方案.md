**总原则（顺序固定）**：先抽**无 React 依赖的纯函数与类型** → 再抽**不共享父 state 的稳定子组件** → 最后才考虑抽 hook。**禁止**把一个大文件平均切成多个同样耦合的文件（下面每个文件都点名了"平均切"会踩什么）。

## 2. 三个前置事实（影响执行方式）

1. **源码断言测试是拆分的第一阻力，不是代码本身**。四个文件里除 `service.ts` 外，其余三个都被"读源码文本 + 正则断言"的测试按**文件路径**钉住（清单见 `docs/plans/2026-09-26-测试方式治理分批清单.md` 的 A/C 类）。搬 JSX/函数会让断言集体变红——不是行为回归，但测试必须同步改读取路径。**因此拆分批次必须与"测试路径同步"同批完成。**
2. **页面级 state 切不干净的地方要保留**：三个组件文件里真正跨区块的 state（`meta`/`fields`/`slots`；`localProfiles`/`localTeams`/`memberView`；`activeUndoList`+`undoQueueRef`）不适合作拆分切口。
3. **`service.ts` 是纯服务层，没有 UI 耦合**，不适用"抽子组件降低重渲染"的收益模型；本文明确给出不拆结论与替代方案。

## 3. 执行纪律（每步都必须满足）

- 每步**只新增文件 + 改本文件 import/调用**，不顺手改其它调用点；每步独立 commit。
- 每步的完成条件与定向验收命令写在对应文件小节的"迁移顺序"里；改完必须跑 `npx tsc --noEmit`。
- 涉及测试路径变更的步骤（`video-submit-form-v2` 步骤 C、`modules-content-v3` 步骤 B 之后）**单独成 commit**，便于只回滚测试改动。
- 每一步都要能回答："这一步把哪几行搬走、哪些接口没变、怎么退回"。

#### 4.4 结论：**不拆**（并给替代建议）

**理由（证据）**：
1. 它是**单一领域服务层**：一个 `SupabaseClient` 依赖 + 一个 topic 领域，14 个消费方按 20 个导出名使用；拆文件必然要在 `service.ts` 做 re-export 门面，等于加一层无价值间接层。
2. **纯计算与 DB loader 交错**（4.2），不是可整块搬运的独立区块；强行归类要动 ≈35 个符号的 import 与 re-export，回归面大而收益仅"文件变小"。
3. **测试面**：943 行 `service.test.ts` 按 20 个符号名从 `./service` import，且 :170-189 直接**读 service.ts 源码**。拆分要么改测试 import（违背"只读、不改测试"前提），要么堆 re-export 使得结构更绕。
4. **无 React/UI 耦合**：它不是"巨型组件"，没有"拆成子组件降低重渲染"的收益；1942 行对纯服务层属可接受量级。

**替代建议（若确有"降体量"诉求，且单独排期）**：
- 只抽**明确独立、无 loader 贴身依赖**的纯计算簇到 `src/lib/topics/pool-scoring.ts`：`calcFlowScore`@802、`calcTimeScore`@811、`calcTopicScore`@822、`buildTopicPoolItem`@826、`sortTopicPoolItems`@773、`matchesTopicPoolQuery`@792（≈120 行），并在 `service.ts` 保留 `export ... from "./pool-scoring"`。
- 或抽"纯校验/查询串"簇到 `src/lib/topics/service-validators.ts`：`isUuidLike@171`、`validateTopicText@150`、`validateSubTopicInput@440`、`validateRecommendationSubTopicInput@411`、`buildPoolQueryOptions@212`、`buildWorksQueryOptions@321`、`matchesPostFilters@299`。
- **无论哪种，都必须保留 `service.ts` 的同名 re-export**，且**至少留一处 `TOPIC_LIBRARY_QUALIFY_PLAY_COUNT` 引用在 service.ts 内**（否则 service.test.ts:170-189 红）。
- 但这些都**不是当前该做的事**：它不解决任何实际痛点，只增加门面。**建议：本轮不拆 service.ts。**

#### 4.5 不得改变的接口

- 全部 44 个导出名与签名（`TopicPoolView/TopicTimeRange/...` 类型、`TOPIC_*` 常量、20+ 函数）。
- 14 个非测试消费方按名 import：**任何改名/移动都必须有 `service.ts` 的 re-export 兜底**。

- `service.test.ts` 从 `./service` import 的 20 个符号名（见 4.3）与 `matchTopicGroup` 的 re-export（@18）。
