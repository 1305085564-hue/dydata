## 一、最终产品口径

### 1.1 概念模型：全站只剩两个概念

| 概念 | 数据实体 | 稳定身份 | 显示规则 |
|---|---|---|---|
| **渠道** | `ai_provider_keys` 一行 | `key.id`（永不改变） | `key.label` 作为显示名，一次定好不再改 |
| **模型** | `model_id` | `model_id`（永不改变） | 完整可读名称 |
| ~~分组~~ | — | — | **概念删除，不再存在** |
| 供应商 | `ai_providers` | `provider.id` | **仅接入/编辑接入资料时出现**，其余页面零显示 |

「渠道 × 模型」= `ai_provider_key_models` 一行，是供给的最小单元（一条渠道供某个模型）。

### 1.2 渠道显示名规则

- 渠道显示名 = 自由文本备注，例：`api9 chatgpt 特惠`、`api9 claude 主`、`api9 claude 备`。
- **不做任何自动清洗、不做白名单、不做规范化映射。**
- 接入表单提供三个快捷词按钮：`Claude` / `Gemini` / `ChatGPT`（仅输入便利，非约束）。
- 表单提供显示名建议值 = `供应商名 + 空格 + 模型族词`，可改可覆盖。
- 存量渠道名**由阿禅在界面上逐条定名**，不跑 migration、不猜、不映射。

### 1.3 两个视角（页面只有这两层）

**视角一 · 业务保障（默认打开）** —— 看需求侧

回答：网站在用什么模型、还安全吗、不安全还剩几条线。
组织：`业务功能 → 使用的模型 → 可调度渠道数 / 故障渠道数`。
断供时（某业务功能解析到的模型 `schedulableChannelCount === 0`）：该行标红告警 + 提供「去换模型」按钮，点击跳到视角二并定位到该模型。

**视角二 · 供给管理** —— 看供给侧

回答：某个模型挂了能换谁、换过去下面有哪几条渠道。
组织：`模型 → 渠道明细列表`。
渠道明细字段：显示名、渠道优先级、健康状态、最后成功时间、最后失败时间、该渠道启用的模型数。

**渠道不再是并列视角，是模型下面的一层明细。** 旧「模型视角 / 渠道视角 / 分组视角」三视角全部取消，合并为上述两视角。

### 1.4 勾选与上架合并为一个动作

- **模型上架**：全局唯一开关（`set_global_model_shelf_state`），界面上是模型行的主开关。
- **渠道勾选**：降级为渠道明细里的小勾（`set_key_model_selection`），标注「这条渠道供不供这个模型」，不再是独立的主操作。
- 文案不得再出现「分组」「上架到分组」等表述。

## 二、现状事实（已核查，Codex 不得推翻）

### 2.1 分组标签的真实职能

| 标签是否影响 | 结论 |
|---|---|
| AI 调用路由 | 否 |
| 故障切换顺序 | 否 |
| 业务功能绑定 | 否 |
| 成本计费 | 否 |
| 唯一作用 | 人工识别线路 |

依据：`src/lib/ai/provider-routing.ts` 的候选排序只读 `key.priority` 与 `provider.priority`，全程未读取 `label`；业务绑定表 `ai_feature_bindings` 绑定 `feature_key + model_id`，与标签无关。

**因此「分组白名单 / 数据清洗 migration / 旧值映射表 / BLOCKED 阻断清单」整块工作全部取消。**

### 2.2 优先级的真实算法

`src/lib/ai/provider-routing.ts:327` ：

```
score = key.priority + provider.priority   // 升序，小者优先
```

供应商优先级是界面上看不见的隐形权重，本次必须消除。

### 2.3 按钮 → 接口真实映射

| 现有按钮 | 实际 action | 处置 |
|---|---|---|
| 全池体检 | `test_all_keys` | **删除**（与「测试全部渠道」同一接口） |
| 测试全部渠道 | `test_all_keys` | 改名「全部检测」保留 |
| 检测渠道 | `test_key` | 保留，改名「检测连通」 |
| （无） | `test_key_model` | 升级为三级测试 L1 |
| 同步模型 | `sync_key_models` | 保留 |
| 探测并同步模型 | 同步链路 | **删除**（纯文案重复） |
| 同步全部 | `sync_all_keys` | 保留，改名「全部同步模型」 |
| 添加供应商 / 管理供应商 | — | **收进「接入渠道」流程**，不再作为并列主按钮 |

顶部「全池算力健康状态」摘要条**整块删除**。

### 2.4 视角数据引擎已存在，不需要新接口

`src/lib/ai-config/availability.ts` 的 `computeAvailability()` 已返回 `AvailabilityReport`：

| 字段 | 用途 |
|---|---|
| `modelFamilies[]`（含 `channels[]`、`schedulableChannelCount`、`faultChannelCount`） | 视角二 |
| `affectedBusinessFeatures[]`、`affectedBusinessCount` | 视角一的断供告警 |
| `keys[]`（含 `label`、`health`、`isSchedulable`、`enabledModelCount`） | 渠道明细 |
| `noChannelModelFamilyCount` | 零供给模型 |

**两个视角全部复用此函数，不新增聚合接口。**

## 三、施工批次

按风险从低到高分五批，**每批独立验收、独立提交，不得跨批混提交**。

### 批次一：概念收口与文案统一（纯前端，零数据风险）

**改动文件**

- `src/app/(app)/admin/ai-config/ai-config-shell.tsx`：删除「全池体检」按钮与顶部健康摘要条。
- `src/app/(app)/admin/ai-config/components/channel-list.tsx`：主名称改为 `key.label`，删除 `providerName` 副标题；优先级改称「渠道优先级」。
- `src/app/(app)/admin/ai-config/components/channel-pool-view.tsx`：删除「分组名称 / 是否启用分组 / 所属供应商」字段；接入资料编辑能力保留。
- `src/app/(app)/admin/ai-config/components/model-family-card.tsx`：删除「供应商 · 分组」组合展示，改用渠道显示名。
- `src/app/(app)/admin/ai-config/components/compute-pool-panel.tsx`：按 2.3 表删除/改名按钮。
- `src/lib/ai/model-families.ts`：补齐模型完整显示名，GPT 系列补全称；未命中模型用稳定可读兜底，不得直接展示内部 ID。

**规则**

- 全站 AI 配置相关文案只允许出现「渠道 / 模型」两个业务名词。
- 「供应商」「服务商」仅允许出现在接入与编辑接入资料的表单内。
- 「分组」一词全站清零。

**完成条件**：`grep -rn "分组" src/app/\(app\)/admin/ai-config/` 零命中（代码注释除外）。

### 批次二：两视角重构（前端，复用现有数据）

**改动文件**

- `src/app/(app)/admin/ai-config/components/compute-pool-panel.tsx`：改为两视角切换结构，视角一为默认。
- 新增视角一组件（业务保障行：业务功能 → 模型 → 健康渠道数）。
- 视角二组件：模型 → 渠道明细列表（展开式）。
- `src/lib/ai-config/availability.ts`：**不改逻辑**，仅在需要时补充输出字段（如缺少渠道显示名则补 `label` 透传）。

**规则**

- 视角一断供行（`schedulableChannelCount === 0`）：红色告警样式 +「去换模型」按钮，点击切到视角二并滚动定位到该模型。
- 视角二默认折叠渠道明细，展开后按渠道优先级升序排列。
- 空状态文案明确说明「此模型当前没有任何可用渠道」。

**完成条件**：视角一能直接回答「网站在用什么模型、还安全吗」；视角二能直接回答「挂了能换谁、下面有哪几条线」。

### 批次三：动作收口与三级测试（前后端）

**按钮最终态（唯一清单，不得增删）**

| 位置 | 按钮 | 动作 |
|---|---|---|
| 顶栏 | `接入渠道` | 接入流程 |
| 顶栏 | `全部检测` | `test_all_keys` |
| 顶栏 | `全部同步模型` | `sync_all_keys` |
| 渠道详情 | `检测连通` | `test_key` |
| 渠道详情 | `同步模型` | `sync_key_models` |
| 渠道明细行 | `检测此模型` | `test_key_model` |
| 模型行 | 上架开关 | `set_global_model_shelf_state` |
| 渠道明细 | 小勾 | `set_key_model_selection` |

**三级测试补齐**

| 级别 | 语义 | 实现 |
|---|---|---|
| L1 | 测某一个模型 | `test_key_model`（已有） |
| L2 | 测当前渠道全部模型 | **新增** action `test_key_all_models`，参数 `{ key_id }` |
| L3 | 测全部渠道全部模型 | **新增** action `test_all_keys_all_models`，重量级操作，需二次确认弹窗 |

`test_key` / `test_all_keys` 语义限定为**连通性快速检测**，文案不得写成「体检」。

**结果反馈规则**：每次检测/同步必须显示「测了谁、发现多少、成功多少、失败多少」，失败项可展开看原因。

**完成条件**：三级测试全部可执行且结果可追溯；旧按钮文案零残留。

### 批次四：优先级摊平（数据迁移，最高风险，单独验收）

**目标**：界面上只剩一个「渠道优先级」，且**切换顺序零变化**。

**迁移规则**

```
新 key.priority = 旧 key.priority + 旧 provider.priority
新 provider.priority = 0
```

因为排序用的正是两者之和，此迁移**在数学上保证排序结果完全不变**。

**强制要求**

1. 迁移前导出全量对账清单：每个 `model_id` 下的候选渠道排序快照。
2. 迁移后重算同一快照，**逐模型逐位次比对，必须完全一致**，不一致即回滚。
3. 提供可回滚 SQL，回滚脚本单独成文件。
4. 迁移脚本不得改 `api_key`、`base_url`、健康状态、模型关联、业务绑定。

**完成条件**：对账清单比对通过 + 回滚脚本验证可用 + 界面只显示一个优先级数字。

### 批次五：接入流程与存量定名

**改动文件**

- `src/app/(app)/admin/ai-config/components/add-key-dialog.tsx`：
  - 分组标签下拉**删除**，改为「渠道显示名」自由输入框 + 三个快捷词按钮（`Claude` / `Gemini` / `ChatGPT`）。
  - 表单内实时预览最终显示名。
  - 供应商选择、API 地址、API Key 保留在此流程内，标注为「接入资料」。
  - 「下一步：探测并配置模型」改为「下一步：同步并选择模型」。
- `src/app/api/admin/ai-config/route.ts`：新增校验「渠道显示名不得为空、同供应商下不得完全重名」，错误文案中文说明。
- 存量渠道改名：在渠道列表提供**就地编辑**显示名能力（不做批量 migration）。

**完成条件**：新接入记录不再需要理解「分组」概念；存量渠道可逐条定名且改名即时生效。

## 四、验收标准

1. **概念**：全站只出现「渠道 / 模型」两个业务名词；「分组」零残留。
2. **两视角**：视角一默认打开并可完成「模型安全性」判断；视角二可完成「换模型」决策。
3. **断供告警**：业务功能所用模型零可调度渠道时，视角一红色告警并可一键跳转视角二。
4. **动作**：按钮总数 ≤ 8，且每个按钮名称能自解释属于「接入 / 检测 / 同步」哪一类。
5. **三级测试**：L1 / L2 / L3 全部可执行，结果含成功与失败计数。
6. **优先级**：迁移前后每个模型的候选排序逐位次一致。
7. **兼容**：业务绑定、故障切换、健康熔断、模型上下架行为无变化。
8. **工程**：`npm test`、TypeScript、lint、build 全绿；使用测试账号完成真实页面验收。

## 五、边界与回滚

### 明确不改

- 不删除 `ai_providers`、`ai_provider_keys`、`ai_provider_key_models` 表。
- 不改 AI 调度算法、健康熔断、故障切换语义。
- 不改业务功能绑定语义（`ai_feature_bindings` 仍绑 `model_id`）。
- 不扩展到其他业务模块的「分组」概念。
- **不写数据清洗 migration**（原计划阶段 A / E 整块取消）。

### 视觉与交互落地要求

Codex 只负责逻辑、接口、数据迁移与文案；**视觉与交互的最终形态必须符合**：

- `docs/Claude设计哲学.md`
- `docs/Claude设计规范.md` §0 五条核心约束

前端实现不得自创样式体系；若 Codex 产出简陋前端，由 Antigravity 从零重写，**禁止参考 Codex 的前端代码**。

### 逐批回滚

| 批次 | 回滚方式 |
|---|---|
| 一 / 二 / 三 / 五 | `git revert <commit>` 单批提交，可独立回退 |
| 四 | 执行随批次提供的回滚 SQL，恢复 `priority` 原值 |

每批完成后必须报告状态：**本地已改 / 已推送 / 线上已生效**（三者不可混称）。
