## 三、P0 施工方案

### 批次 A（逻辑，[CX]，建议一次改完再复测）

**A1 成功后草稿不再复活（#2）**
- 链路：提交成功 → `clearDraft()` → 表单状态仍有值 → `useFormDraft` 防抖/`pagehide` 重存 → 刷新后显示"未交草稿"。
- 改动点：`src/hooks/use-form-draft.ts` 加一个"暂停保存"开关（提交成功后置位）；`draft-controller.ts` 把 `isSubmitted` 传入。唯一来源在这个 hook，不在调用方各处补。
- 同样的问题还在：`history-report-edit-form.tsx:480-505` 也用 `useFormDraft`，需确认历史编辑成功后同样不复活。
- 验收：先写复现测试（成功 → 触发 `pagehide` → 断言 localStorage 无该键）；再手测成功后刷新无"未交草稿"。

**A2 "再交一条"（#3）**
- 改动点：`form-v2/submitted-view.tsx` 加主按钮"再交一条"，调用表单重置（清 workflow、截图槽位、`isSubmitted`、`submittedViewActive`），回到上传框；与 A1 共用"已提交"状态，同批做。
- 注意：重置必须同时解除 A1 的暂停开关，否则新一条不会自动保存。
- 验收：成功 → 点"再交一条" → 回到空上传框 → 传图后草稿正常自动保存。

**A3 补交结果回到本页（#32 + #33，可并入 §10.2 C）**
- 链路：提交 409 → 申请补交 → 管理员通过 → 服务端自动续交写库（失败才发"去完成填报"）→ **页面不知道**。
- 改动点（先看拍板 2 的查库结果再定）：
  1. `submit-controller.ts:202` 申请成功后不再 `setAppealRequired(false)` 回到普通"提交"，改为常驻"补交申请已提交，等待审批"状态，写进 `submit-footer.tsx` 与 `ui-state.ts`；
  2. 页面聚焦及每 30 秒查一次本账号该日期的补交状态（只读接口，复用现有 appeals 查询，不新建口径）；
  3. 状态变为已通过：若数据已自动写入 → 本页切到成功态并清草稿（复用 A1/A2 的成功分支，避免再点提交撞 409）；若自动续交失败 → 本页出现"去完成填报"，调用 `/appeals/resume`，不再依赖 `?resumeAppeal=`；已驳回 → 显示驳回原因（`2026-10-15-审批链结果可见闭环` 已定的口径）。
- 不改：审批裁决规则、`resolveVideoSubmitDeadline`、`route-core.ts` 的 72 小时判定。
- 同样的问题还在：`video-submit-panel-v2.tsx:70` 的 `?resumeAppeal=` 入口保留（通知链接仍在用）。
- 验收：审批通过后不刷新、不点通知，页面自己变成成功态或"去完成填报"；驳回时自己显示原因。

**A4 发布时间有路可走（#1，等拍板 1）**
- 选 A 时的改动点：`results-section.tsx:109-127` 发布时间行在"未识别"时给日期时间输入，值标记为手填；`提交状态机.ts` 的 `publishedAtUnconfirmed` 对手填值放行到"需审批"而不是"可提交"；`route-core.ts` 在 `requires_confirmation` 分支对"手填"来源转入补交流程，`_resume-submission.ts` 续交时放行同一手填值；补交申请内容带上"发布时间为手填"。
- 链路：识别失败 → 手填 → 强制补交申请 → 审批 → 自动续交写库。
- 必须保持的旧行为：OCR 识别出的时间仍按 72 小时规则；`edit`、`abnormal` 模式仍跳过该门禁；错误码 `PUBLISH_TIME_CONFIRM_REQUIRED` 不改名。

## 七、拍板结果（2026-11-16，阿禅）

**统一规则：需要审批 = 超过 72 小时 或 发布时间被手填/手改。两种原因共用同一条补交申请路径，不为手填另开流程。**

1. **A4 定为方案 A 的简化版**：识别不出发布时间允许手填；手填或改过 OCR 值，一律走补交申请。不做自由手填，不维持锁死。
2. **并入提前判断**（原审计 §10.2 C）：发布时间一确定（识别或手填），页面立刻判断是否需要审批，按钮直接变"提交审批"并写明原因，不再等点提交后被 409 拦回。
3. **并入申请前判重**：申请补交之前先判重。实测原因：11-16 那条申请批准后自动入库失败，报"该作品已录入"，因为同账号同标题同发布日的作品 10-13 已入库（申请 `e2b7d50a`，暂存数据仍在，无法续交）。组员白等了审批。
4. **A3 补充**：申请提交后页面常驻"已提交审批"；聚焦和每 30 秒查状态；通过且已自动入库→切成功态并清草稿；通过但自动入库失败→显示失败原因，可重试的给"重试"，重复作品这类不可重试的说明原因；驳回→显示原因。"是否已自动入库"以申请的暂存数据是否已清空判断（`_resume-submission.ts` 成功后清空）。
5. **审批卡片**写明触发原因；手填的同时显示截图识别出的原值。
6. 不改：72 小时阈值、审批裁决规则、`edit`/`abnormal` 跳过门禁、错误码 `PUBLISH_TIME_CONFIRM_REQUIRED` 名称。
7. 回写：`docs/reference/架构决策.md` 记一条取代 2026-10-01"发布时间锁死"的决定。
8. 分工：逻辑（A 批）由 [CX] 施工中；本章为对 [CX] 的补充指令。
