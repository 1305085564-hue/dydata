## 1. 目标与第一批范围

让文案在日常页面上看见自己的内容目标：互动有没有达标，干货的收藏／复盘的点赞有没有达标，哪些作品值得学习或需要改进。

第一批只做三个位置：

| 位置 | 用户能完成什么 | 时间范围 |
|---|---|---|
| 个人抽屉·30日曲线 | 看两项达成率与内容平均达成率，知道是否进步、离目标多远 | 上海时区含今天的近30个自然日 |
| 数据管理·文案岗位表 | 比较成员互动达成率、核心指标达成率、综合良优率 | 页面选定月份 |
| 个人抽屉·本月文案明细 | 查看每篇原始比率、达成率、综合评级，并直接打开复盘 | 页面选定月份，仅本人文案署名 |

新增展示仅在 `writers` 岗位视角生效。文案小队打开成员档案时，现有工种转换得到 `writers`，可复用同一档案展示；小队汇总和成员表本轮不加列。

明确排除：视频复盘总列表的评级筛选、文案小队汇总、选题库质量排序、其他岗位曲线改版、认证规则、薪酬与提成、原绩效条数、数据库结构／RLS、独立配置后台。后三个展示入口作为第二批候选，不自动续做。六处是最初的展示建议，并非六处都已开工；本批三处也尚未正式施工。

## 3. 已确认展示口径：达成率看指标，良优率含播放兜底

### 3.1 单篇内容目标

1. 干货：互动率＋收藏率；复盘及其他：互动率＋点赞率。
2. 每项达成率 = 原始比率 ÷ 当前对应标准线 × 100%，不封顶、不提前取整。
3. 内容达成率 = 两项达成率平均值。
4. 内容档位沿用现有达成率分档：当前为≥100%优、≥80%良、≥60%普、低于60%劣。
5. **内容达成率不加播放门槛**，用于表达文案内容目标。单篇另显示现有「综合评级」，继续受播放5千／1万／1.5万限制。

参数只消费 `src/lib/breakout-rating.ts` 的现行定义。前端不再复制标准线、播放门槛或分档条件。后端会下发画线所需规则；参数调整后，在新请求中同步体现。历史月份按当前标准回看，页面注明「按当前标准」，不生成工资历史结算凭证。

### 3.2 月度与近30日摘要（审查后阿禅已确认）

- 先按每篇自己的话题标准换算，再汇总；干货收藏与复盘点赞的原始百分比不混在一起平均。
- 达成率摘要只纳入两项均可计算的作品。三项均值使用同一批作品：互动达成率均值、核心指标达成率均值、内容达成率均值；每篇等权，不按播放量加权。该样本数量为 `achievementSampleCount`。
- **综合良优率 = 综合评级为良或优的署名日报篇数 ÷ 综合评级非空的署名日报篇数**。使用现有 `overallBreakoutGrade()`，播放兜底参与：不足5,000为劣；5,000/10,000/15,000分别允许最高普/良/优，最终仍与两项平均达成率档位取低。不能按不含播放的内容档位统计良优率。
- 综合评级非空的数量为 `ratedCount`；显示「综合已评级 X / 署名作品 Y」。达成率均值另注明「指标完整 N 篇」，不要让两个样本数量混用。低播放但指标缺失时，既有函数仍可综合判劣：计入综合分母，不计入达成率均值；播放0同理。
- 无综合可评级作品时综合良优率为 `null`；无指标完整作品时三项均值为 `null`，各自显示「—」。有综合已评级作品但没有良优时显示真实0%，不足5,000的作品不能从分母删除以抬高良优率。未评级原因计数只统计综合评级为空的作品；内容不可计算原因由单篇status另行说明。
- 既有原始比率加权均值不改公式，不改成新达成率均值。文案新视图若保留它，单独标「原始比率（按播放加权）」；其他岗位照旧。
- 作品归属和数量沿用当前文案署名日报口径，包括本人账号。查询 video_id 去重只是避免重复读取，不自行改成按视频去重的绩效／作品数量。重复绑定风险在真实抽样中记录，不顺手清理数据。

阿禅已确认保留播放兜底、按署名日报计数；本轮修订不改变认证或计费。达成率只用于说明指标表现，综合良优率才表达同时满足指标和播放要求的比例。

| 展示／字段 | 是否看播放 | 作用 |
|---|---|---|
| 内容达成率／contentAchievement | 不加播放门槛（比率本身需可计算） | 曲线与指标均值 |
| 指标档位／contentGrade | 不加播放门槛 | 解释两项平均达成率，单篇明确标「指标档位」 |
| 综合评级／overallGrade | 播放兜底，取较低档 | 单篇总评、综合优良普劣计数 |
| 综合良优率／goodExcellentRate | 按overallGrade统计 | 月度和30日摘要，分母为综合已评级篇数 |

### 3.3 空值与错误

| 情况 | 内容展示 | 单篇综合评级 |
|---|---|---|
| 无 video_id | 未关联视频，内容值为空 | 为空，不按日报播放猜评级 |
| 没有24h快照 | 数据待采集，图中保留中性待采集点，不连成0% | 为空 |
| 有快照，播放为0或缺失 | 内容值为空，原因明确 | 播放为0时沿用既有函数得到劣；缺播放则为空 |
| 任一内容输入缺失 | 保留可显示的原始数据；平均达成率、内容档位为空，曲线断开 | 直接复用现有函数；低播放可直接为劣，过门槛缺参与项则为空 |
| 原始计数确为0、播放正数 | 真实0%正常计算，可评内容劣 | 正常计算 |
| 标签读取成功，无标签／非已知标签 | `other`，按复盘的点赞标准 | 正常计算 |
| 标签读取失败或分类状态未拿到 | 质量模块明确失败／未就绪 | 不把失败当作 `other` 生成评级 |

状态不得统一写成「未满24小时」：没有快照并不能证明视频年龄；缺关联、缺字段、播放不可计算、读取失败应给准确原因。保留 `hasKnownTopicKind` 和现有话题未识别说明，不重写现有抽屉评级行为。

## 4. 选用架构与前后端契约

推荐「现有读链补字段＋共用纯计算」：后台按已有数据范围加载日报、最新24h快照、话题标签，计算统一结构；前端只展示、排序、交互。

未选：①各页面自行算评级，会形成三套口径；②新增质量数据库表／配置后台，本轮没有落库或管理配置需求，增加发布与历史一致性成本。

### 4.1 拟新增的共用类型文件

`src/lib/collaboration/content-quality-contract.ts`（**待创建**，纯类型，Antigravity 第一阶段建立；Codex 按此实现）。下列字段都是计划字段，不是已上线字段。

| 类型／字段 | 契约 |
|---|---|
| `ContentQualityRules` | 当前两种话题标准线、分档线、播放门槛；由后端从同一算法常量生成，前端画60/80/100等当前参考线 |
| `WorkContentQuality.topicKind` | `dry_goods`／`review`／`other`／`null`；成功无标签与失败未识别分开 |

### 4.2 拟扩展现役结构

- `PersonGrowthWorkItem.contentQuality?`：为已有近30日作品增加统一质量结果；保留标题、账号、日期、reportId、三项原始比率。
- `StaffRow.writerQuality?`：An兼容阶段可选；CX接通后文案生产者必须返回明确状态和月度 `summary`，在writer分支收窄，不能强迫共享剪辑类型增加文案数据；剪辑行不改变行为。`writer-tab.tsx` 的零作品补齐行也返回明确未接入或后端就绪的零作品状态。
- `WriterCandidateRow.writerQuality?`：首屏在月度数据成功加载后，为确实没有署名作品的候选成员附带正式零作品summary；writer-tab补齐行消费该字段。不能从别人的行猜模块就绪，也不能让后端接通后的零作品候选一直显示未接入。
- `PersonDetailData.writerQuality?`：新增 `state`、`rules`、`monthSummary`、`monthWorks`、`growthSummary`。`monthWorks` 采用带真实快照比率及 `contentQuality` 的作品结构，只包含本人文案署名。
- `state` 为 `ready`／`error`；对象尚未返回时，前端明确显示「质量数据尚未接入」。`ready`下0作品是零作品，不是错误；`error`不能变成0作品。加载失败沿用明确错误态，质量附加查询失败不伪造标签分类；在可保留原数据时仅质量块报错。
- 后端阶段先保证所有 writer 行都有明确状态，再收窄临时可选契约；其他岗位和旧调用不强制增加文案块。清理前端预览样例、临时兜底与重复类型，只保留正式兼容边界。

### 7.1 必须覆盖的计算与数据场景

| 场景 | 预期 |

| 真实计数0、播放正数 | 内容达成0%，内容劣；不是缺数据 |

| 成功无话题标签与标签请求失败 | 前者other；后者明确错误或未就绪，不能默认为复盘出评级 |
