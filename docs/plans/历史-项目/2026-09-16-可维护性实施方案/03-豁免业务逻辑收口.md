# 第 3 批：豁免申请共享预检

前置：第 2 批通过；第 1 批 observation 已接入 REST。先读 `00-执行基线与交接.md`、权限与数据口径。

目标：两条申请入口使用一份“同申请人、同分类、待审批日期重叠”查询与判定。保留不同写入流程，不合并申请、授予、审批，不改数据库。

## 真实调用链

- Dashboard `submitExemptionRequest` → `submitExemptionRequestWithClient`（`src/app/(app)/dashboard/actions.ts:272`）→ `buildRequestDraft(s)ForDates`（`src/lib/豁免流程.ts`）→ 重复查询两张表 → `collectOverlappingPendingDates` → 一次批量插入 drafts → `revalidatePath('/dashboard')`。
- REST `POST /api/exemptions/apply` → `buildApplyExemptionResponse`（`src/app/api/exemptions/apply/route.ts`）→ 输入校验、连续日期分段 → 相同两表预检 → 逐段插入主表、插入逐日明细 → 失败清理已建 pending 行 → 201。
- 二者已共用 `src/lib/豁免.ts:getPendingExemptionDatesFromRequests`，尚未共用查询和重叠计算。
- Dashboard 逐日 drafts 与 REST 连续段不是同一个写入契约；永久申请当前预检 end=null 按开始日处理，本批原样保留，不能顺手“修正”为无限范围。

## 确定实现

**新增** `src/lib/exemption-application-precheck.ts`，导出：

- `checkPendingExemptionOverlap(client, { applicantUserId, category, ranges })`。client 使用 `Pick<SupabaseClient, 'from'>`；category 复用 `ExemptionCategory`；ranges 是 `{ start_date: string; end_date: string | null }[]`。
- 返回判别联合：`{ ok: true; overlappingDates: string[] } | { ok: false; stage: 'requests' | 'dates'; error: unknown }`。不要在共享层返回 NextResponse 或中文入口文案。
- 查询严格保留：`exemption_request.select('id, start_date, end_date').eq('applicant_user_id', ...).eq('request_status','pending').eq('exemption_category', ...).limit(500)`；仅有 requestIds 时查询 `exemption_request_date.select('request_id, request_date, status').in('request_id', ids)`。
- 复用 `getPendingExemptionDatesFromRequests`；请求 ranges 逐日展开，null 末日=开始日，去重后排序返回真正交集。可沿用 Dashboard `shiftDateOnly`，不引入新的日期库。
- 任一查询失败立即返回对应 stage，不能把错误当空数据继续写入。共享层不另写日志，以免入口重复上报；保留入口现有日志与文案映射。

修改仅两入口：Dashboard 直接传 drafts；REST 将 segments 映射 snake_case range。删除入口重复预检查询和只服务预检的函数/import。REST `expandDates` 仍用于输入解析，必须保留。Dashboard `shiftDateOnly` 若仍有其他用途则保留，按引用决定。

## 实际验收矩阵与恢复

| 场景 | 断言 |
|---|---|
| 同人同分类重叠、无重叠、不同分类 | 原阻拦/允许行为一致；不能把“有任何 pending”改成全部禁止 |
| 非连续日跨月 | Dashboard 逐日 drafts、REST 连续段+逐日表形状各自保持，不按另一入口格式重写 |
| 主表或逐日查询失败 | 两入口都零插入，错误非成功；日志和用户文案仍由入口决定 |
| 日期明细写失败/主表并发冲突 | REST 原清理及 409 保留；Dashboard Set 在成功/失败后都释放 |
| 刷新与对象回收 | 成功页面可见与只读数据一致；只回收本轮明确登记的专用测试对象，不新增公开清理接口 |

单测模拟查询/写入失败；真实页面验证允许/拒绝/刷新，不能在生产故意断表制造故障。无可用测试对象时停在本地通过。
