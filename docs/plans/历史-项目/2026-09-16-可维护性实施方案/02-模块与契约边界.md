# 第 2 批：解除三组非权限反向依赖

前置：第 1 批本地通过，先读 `00-执行基线与交接.md`。

目标：三个可复用工具不再由 src/lib 反向导入 src/app，原业务结果保持不变。不要把全站依赖重构塞进本批。

## 已确认事实及冻结方案

1. `src/lib/ai-config/key-patch.ts` 与 `swap-key-priority.ts` 从 `src/app/api/admin/ai-channels/_shared.ts` 引入纯转换函数；后者同时导入鉴权、AI 客户端与网络安全代码，造成不必要耦合。只将 `toPriority` 原样移动到 **新增** `src/lib/ai-config/priority.ts`；`toBoolean`、`toTrimmedString` 改为直接导入已有 `src/lib/type-guards.ts`。路由 `_shared.ts` 为现有路由调用方保留 `toPriority` 的具名再导出（这是兼容入口，不保留第二份实现）。不搬网络请求与鉴权。
2. `src/lib/content-comparison-reference.ts` 只需上海日期，却导入 `src/app/api/production/_shared.ts:getShanghaiDate`。已有 `src/lib/loaders/shared.ts:formatShanghaiDateOnly(date = new Date())` 实现完全相同日期格式。将 production 的 `getShanghaiDate()` 函数体改为调用已有函数；content-comparison-reference 直接调用已有函数。保持 daily-quota-config 和 admin/settings 现有入口不变，不创建第三个日期工具库。
3. `src/lib/loaders/dashboard-{activity,page}.ts` 导入页面内 `video-submit-panel-state.ts` 的类型和运行时函数。该文件整份为纯类型/纯计算，无 React 和浏览器依赖。将它及测试完整移动至 **新增** `src/lib/dashboard-submission-state.ts`、`src/lib/dashboard-submission-state.test.ts`。不拆它的内部算法，不改返回值；所有调用方直接改新路径，删除原文件与原测试，不留转发壳。
