目标：三个大组件各分离一个能独立理解、验证的职责，不以行数为验收。仅结构调整，不改变页面外观、接口、权限和业务规则。本方案来自 2026-09-16 当前源码；行号仅供定位，以符号为准。

前置：第 3 批本地通过，先读 `00-执行基线与交接.md` 及两份设计文档；第 2 批仅把 `video-submit-panel-state.ts` 移至 `src/lib/dashboard-submission-state.ts`；面板类型沿新路径引用。4A 的 `buildVideoSubmissionEditRefill/getDefaultPublishedAtForBizDate` 仍从原 `./video-submit-form-state` 导入，两组 helper 不可混淆。

执行顺序：4A → 验收 → 4B → 验收 → 4C → 验收。上一子项通过才继续；每个子项独立提交。权限改造未结束、同文件仍由其他执行者修改时，先等待交接，不抢改。

## 4A：提交表单的初始值与编辑回填

现状：`src/app/(app)/dashboard/video-submit-form-v2.tsx` 的 `FormMetaState`（279）、`SlotViewState`（300）、`createInitialMeta`（333）、`createFieldState`（374）、`buildOcrSummary`（385）、`createEditableFields`（433）、`createEditableSlots`（449）、`createMetaFromEditDetail/createEditableFieldsFromEditDetail/createEditableSlotsFromEditDetail`（457/495/512）是无 React 状态的表单模型逻辑。目前必须进入巨大页面文件才能核对“旧数据如何回填”。已有 `video-submit-form-state.ts` 提供 `buildVideoSubmissionEditRefill` 等业务规则，不能再复制它。

选择：新增同目录 `video-submit-form-model.ts`，只承接以上类型和纯函数。沿用 `video-submit-form-state.ts` 现有规则。拒绝抽整个 OCR hook 或整个表单 reducer：它们牵涉对象 URL 生命周期、异步上传、手工覆盖和草稿，成本与本批不匹配。

文件清单：
- 新增 `src/app/(app)/dashboard/video-submit-form-model.ts`：上述类型和纯函数；将 `VISIBLE_SCREENSHOT_UPLOAD_SLOT_ORDER` 一并移动并导出，父组件改 import；`OVERVIEW_FIELDS`、`SLOT_LABELS` 留父组件。禁止模型从 TSX 反向 import。
- 修改 `src/app/(app)/dashboard/video-submit-form-v2.tsx`：删除旧定义并 import，保持调用位置、参数、初始化时机不变。`SLOT_LABELS` 留原文件，不改截图标签与顺序。
- 新增 `src/app/(app)/dashboard/video-submit-form-model.test.ts`：对公共模型函数直接断言。
- `video-submit-form-state.ts` 原则不改，只复用；原有 layout/state 测试保留。

明确状态归属：`meta/fields/slots` 与所有 setter、ref、effect 继续归表单；模型不拥有状态、不发请求、不读存储、不读当前时间。`today/userId/bizDate/detail` 全部由参数输入。输出保留 `FormMetaState`、`SubmissionState['fields']`、`Record<SubmissionSlotRole, SlotViewState>` 类型。

步骤：
1. 新增模型，将纯函数原样移动并保持现有参数；不要合并三个回填函数或优化重复调用。
2. 新增测试：非法日期回退 today；本人/他人岗位回填；指标 0 不变空串；编辑指标 confirmed/manual 标识不变；旧截图 assetUrl/previewUrl 相同、file=null，待确认截图不变已确认；空 assets 保持初始空槽。
3. 表单改为 import；检查移动符号只有一个定义，删除失效 import，不动提交 DTO/OCR/草稿。
4. 实页 `/dashboard` 普通成员：新建初始化、打开已有视频完整编辑（检查零指标、岗位、截图）；更改字段后取消，不保存共享线上业务数据。本步验证页面集成，模型测试验证值转换。

## 4B：成员页 AI 对话框呈现

现状：`src/app/(app)/admin/modules/modules-content-v3.tsx` 内 AI 类型（187）、显示名/预览转换（195、218、222）、AI 诊断 JSX（1829-1934）、执行确认 JSX（2224-2292）与成员管理主流程混排。请求处理（971、1011）涉及敏感工具与 409 二次确认，本批不移动请求和状态，避免扩大权限链路风险。

选择：新增一个受控展示组件 `member-ai-dialogs.tsx`，同时呈现两个相关对话框；父组件仍掌握网络与业务状态。拒绝新建 AI 通用服务或修改工具协议。

文件清单：
- 新增 `src/app/(app)/admin/modules/member-ai-dialogs.tsx`：两个弹窗原样 JSX；export `AiSuggestionItem`、`MemberAiSuggestionState`、`ToolConfirmationState` 类型。
- 新增同目录 `member-ai-preview.ts`：原 `AI_TOOL_DISPLAY_NAMES/getAiToolDisplayName/formatAiToolPreview`；profiles 参数只需 `Array<{id:string;name:string|null}>`，不要 import 父 TSX。
- 新增同目录 `member-ai-preview.test.ts`：归档保留历史、角色显示、未知工具原始预览、空预览。
- 修改父文件：保留四项 AI 状态、`handleFetchAiSuggestion/handleExecuteAiSuggestion`、路由、startTransition、所有打开/关闭时重置；调用新展示组件。移除旧 JSX 和旧 helper。

受控 props 固定为：
- `open:boolean; onOpenChange:(open:boolean)=>void; suggestion:MemberAiSuggestionState|null; executingKey:string|null; pending:boolean`。
- `confirmation:ToolConfirmationState|null; profiles:Array<{id:string;name:string|null}>`。

- `onConfirm` 的 fakeSuggestion 和 token 组装仍在父层；子组件仅调用 callback。子组件不得 fetch、router.push、创建第二套 state。诊断 JSX 的直接导航改为 `onNavigate(s.action.href)`，父层传入原 `router.push` 包装；不得改走 `onExecute`，因为它的 executingAiKey 防重检查会改变导航行为。

步骤：先提取预览 helper 并测试，再原样移 JSX，最后替换父渲染。检查打开成员、关闭抽屉、URL focus 清空三条路径中的 `setAiSuggestion(null)` 全部保留。

实页 `/admin/modules`：company_owner 打开成员 → AI 诊断 → 加载/错误/成功显示；拦截建议与执行接口并使用合成响应，不触发真实收费 AI；对网络请求使用浏览器拦截构造 409，检查确认框预览、取消不重发、确认原 token 重发、pending 防重按钮；拦截工具调用，不实际执行归档/权限变更。另核对成员筛选和详情抽屉照常工作。该证据只证明客户端重构，不声称通过后台权限验收。

## 4C：诊断工作台对比数据生命周期

现状：`src/app/(app)/admin/content/content-diagnosis-workbench.tsx` 的 refs/指定成员/候选/归因状态（412-431）、候选派生（474-504）、切换参照与两类请求/effect（527-675）形成完整职责；当前已有 AbortController、可选成员补查、视频切换清理，不得在拆分中丢掉。展示指标排序（434）、诊断汇总（678）、截图与复盘操作不属于它。

选择：新增同目录 `use-content-comparison.ts`，仅封装以上对比选择及请求；不新建全局缓存或统一数据加载框架。

改前先核对第 0 批“无候选加载”真实基线：当前 effect 依赖 `comparisonMembersLoading`，可能在置 true 后因 cleanup 中止自身请求；这是源码推断，尚未实证。若基线确认失败，4C 记预存阻塞，不以删除依赖/静默修 bug 来完成结构重构；可继续独立的 4A/4B，但不能将 4C 或全批勾完成。

输入固定：`{video:VideoRow|null; videos:VideoRow[]; profiles:Array<{id:string;name:string}>}`。复用 `@/lib/review-queue` 的 VideoRow、`@/lib/content-comparison-members` 和 `@/lib/content-attribution` 类型。

返回固定：`selectedRefs,toggleRef,selectedRefUserId,setSelectedRefUserId,availableComparisonMembers,validSelectedRefUserId,selectedMemberName,comparisonMembersLoading,comparisonMembersError,multiAttribution,attributionLoading,attributionError`；同时返回 `comparisonMembers`，不再由父层重复计算。`RefKey` 定义随 hook 移动；原 TSX 若被外部 import 此类型，保留 type re-export 兼容。

状态归属：上述对比状态只在 hook 中存在；`showAllMetrics/cardCols/primaryMetrics/primaryDiagnosis/analysisResult/mobileScreenshotIndex` 留父组件。视频切换 effect 拆为两个：hook 清空成员/归因状态；父组件继续清空 analysisResult 和 mobileScreenshotIndex。两个 effect 均依赖 video?.id，保留空 id 条件和既有顺序，不新增行为。

步骤：

2. 逐项核对：至少保留一个参照；user 无候选时排除 user 不影响其余参照；选中当前作者被排除；切换视频 abort 旧请求；失败清理归因；取消请求不得覆盖新结果。
3. 修改 `content-diagnosis-workbench-structure.test.ts`：对候选/请求/重置的断言读取新 hook 文件；复盘人/生成时间继续读取父组件。不得删除断言或用拼接全目录源码掩盖接线错误；额外断言父组件实际调用 hook。
4. 真实 `/admin/content`：有候选/无候选、切换指定成员、快速切换两条视频、请求失败后切换其他视频恢复。用浏览器延迟拦截旧响应证明不会覆盖新视频，截图、复制话术和前后条导航保持原行为。仅加载，不标复盘、不移除选题、不删视频。

## 完整类型与交接补充

`MemberAiSuggestionState` 从父层原内联状态原样提取：`{status: "normal" | "warning" | "critical"; summary: string; suggestions: AiSuggestionItem[]; loading: boolean; error?: string | null}`。`ToolConfirmationState` 为 `{toolName:string; toolArgs:Record<string,unknown>; confirmationToken:string; preview?:Record<string,unknown>|null}`。两者的 null 仍在 state/props 联合类型，不另造默认成功状态。

4C 保留原有 fallback 候选缓存与 selectedRefs 生命周期：原切视频 effect 没有清空它们，提取后不能新增清空。先在 hook 中声明对比重置 effect，再声明发起归因请求 effect；父层的 analysisResult/mobileScreenshotIndex 重置保持原依赖。不要把混合 effect 整段移入 hook 丢掉父层 reset。
