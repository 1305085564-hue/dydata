# 发布与协作性能优化

目标：翻月请求小于 2 秒；协作页先出当前岗位/小队，重复切换 60 秒内复用。数据、人工标记、请假优先级和权限范围保持一致。本轮不发版、不推送、不修改正式数据。

## 当前链路与选择

- 发布页 `fulfillment-workbench-state.ts:131` → `api/admin/fulfillment/calendar/route.ts:34` → `loaders/fulfillment-page.ts:428` → CloudBase PG `get_fulfillment_range`。本地迁移保留函数输入输出契约；没有取得当前正式 CloudBase 函数定义的可读备份，不能把仓库里的 Supabase 历史迁移当作现网定义。
- 所选月明细拆成有发布时间/无发布时间两路；连续未发天数仍保留截至今天的历史定义，改成一次分组聚合。仅截月会改变旧结果，舍弃。
- 缓存复用 `BoundedTtlCache`，60 秒/32 项，环境、公司、完整可见成员、月份、日期范围隔离。空权限范围不下放为全量。写入成功主动失效；历史连续未发字段有跨月依赖，保守清空履约缓存。失败不缓存，失效期间在途结果不得回填。
- 协作页现无 `/data` API；服务端容器同时计算四岗位与小队。实际四页签是达人/运营/文案/剪辑。保持这些现有功能，新增按当前岗位或小队取数的入口，不新增年度页签。
