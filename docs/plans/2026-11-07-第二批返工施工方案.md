```ts
export function findMoveTarget(
  channels: AvailabilityChannel[],
  keyModelId: string,
  direction: -1 | 1,
): AvailabilityChannel | null {
  const idx = channels.findIndex((c) => c.keyModelId === keyModelId);
  if (idx === -1 || !channels[idx].isSchedulable) return null;
  for (let i = idx + direction; i >= 0 && i < channels.length; i += direction) {
    if (channels[i].isSchedulable) return channels[i];
  }
  return null;
}
```

**C1 · 月份契约与按钮判定**

月份对外统一1基，保留内部滚动不回写父级的语义：父级记录最后一次显式导航目标，内部 `visibleMonthKey` 记录正在看的月份；两者允许不同，但翻月只按后者计算。

```ts
onMonthShift?: (target: { year: number; month: number }) => void;
canShiftNext?: (target: { year: number; month: number }) => boolean;
```

- `canShiftNext` 从旧的预先算好的布尔值改为目标月判断函数；未传表示沿用不设上限的行为。下一月按钮与其处理函数使用同一个目标和判断结果。
- `canShiftPrev` 保留既有布尔语义和默认值；现有调用方未提供动态下界，不新增下界判断，不改 minDate。
- 导出 `resolveStepMonthTarget(visibleMonthKey, direction)` 供实际按钮和测试共用：年月解析后转总月份，加方向，再转回1基年月，跨年正确。输入来自组件内部有效月份键，不新增重复格式校验。
- 仅替换翻月按钮使用的月份基准。日期禁用、选日回调、区间、长卷生成范围、最大日期和“本月”快捷入口的既有业务语义均保持。

**C2 · 保留点击的实际跳转，不再只依赖父级数值变化**

1. `handleStepMonth` 从 `visibleMonthKey` 算出目标月，通过对应按钮边界后，把这个**明确目标**传给父级，父级不得再按旧月份自行加减。
2. 目标月份已渲染时，保留组件内部按这个目标执行滚动及可见月份更新；即使目标等于父级现有年月、或没有传父级回调，也不能让已有目标的点击失效。
3. 目标尚未在长卷中渲染时，由父级更新锚点后沿用既有月份效果定位；不能只依赖旧 `months[index±1]` 在边缘找不到就不处理。
4. 父级年月变化的既有效果仍保留外部定位职责，并使用同一目标年月；不执行原方案“删除内部滚动、只依赖父级效果”的做法。此次只纠正两个入口的目标基准，不扩展为滚动去重、取消、导航序号或状态机改造。
