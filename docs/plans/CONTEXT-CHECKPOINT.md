# CONTEXT CHECKPOINT HANDOFF 生成标准

> 所有 AI 共用此模板。会话结束或任务阶段性交接时，按下方字段结构生成交接文档。

---

## 核心原则

1. 给下一个 AI 用的，不是给人看的——它读完就能直接接手干活
2. 关键信息**直接引用原文**（文件路径、变量名、错误信息、代码片段），禁止转述或概括
3. 用户原话约束（"不要""禁止""必须""优先"）逐字保留，禁止归纳后丢失细节
4. 无内容的字段写 `N/A`，禁止省略字段

## 字段结构（按顺序输出，不可增删）

```
# CONTEXT CHECKPOINT HANDOFF

## Current Objective
- 用户最初的核心任务是什么
- 当前进展到哪个阶段（探索 / 实现 / 验证 / 修复）

## User Constraints & Preferences
直接引用用户原话，禁止转述：
- 所有"不要…""必须…""优先…"类指令
- 代码风格偏好、技术栈限制
- 被用户否决过的方案及用户原话

## Key Decisions & Rationale
已做出的决策，每个写清楚：
- 决策内容（what）
- 原因（why）
- 被放弃的替代方案 + 放弃原因（防下个 AI 重复尝试）

## Active Files & Symbols
精确到行号/函数名：
- 已修改的文件：路径 + 改了什么（一句话）
- 已查看但未修改的关键文件
- 当前正在编辑的位置（文件:行号）

## Critical Data
直接引用，禁止概括：
- 关键错误信息（保留完整信息）
- 关键变量名、配置项、API 端点
- 测试失败的具体断言

## Tool Call Trail
- 已执行的关键工具调用及结果（成功/失败/输出摘要）
- 已归档的旧结果：记"曾执行过 xxx，结果已归档"

## Pending Tasks（优先级降序）
- 未完成的子任务 + 当前状态
- 阻塞点（blockers）及等待什么解除
- 下一步推荐动作

## Do Not Redo
- 已尝试失败的方法（含失败现象）
- 已验证不可行的路径
- 用户明确拒绝过的方案（引用原话）

## Historical Thread
- 如果存在前序交接的 Historical Thread，原样保留并追加本次 3-5 句关键进展
- 如果是首次交接，写本次进展的关键节点
```

## 书写纪律

- **总长度**：3000 tokens 以内；信息量大时优先保留精确引用，砍掉概括性叙述
- **代码/路径/错误信息**：用代码块包裹，不裸写在正文里
- **文件路径**：相对于项目根目录（如 `src/app/page.tsx`），不写绝对路径
- **用户约束**：用引用块（`>`）逐字记录用户原话，禁止改成第三人称转述
- **Historical Thread**：如果有前序交接摘要，必须**原样复制**它的 Historical Thread 段落，只在末尾追加本次进展，不允许重新概括旧内容

## 输出格式

生成时直接输出完整 Markdown，不写前言后语，不加"以下是交接文档"之类的套话。
文件名约定：`CONTEXT-CHECKPOINT-{YYYY-MM-DD}-{简短关键词}.md`
存放在 `docs/plans/` 目录下。
