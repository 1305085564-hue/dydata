## 演练记录

故障注入只在本地隔离 Supabase 上执行。入口 `src/lib/fault-injection.ts` 只允许非 Vercel 本地运行时直接注入；Vercel Preview 必须提供密钥请求头，生产环境即使设置本地标记也不会注入。生产保护回归在 `src/app/api/health/route.test.ts`。

| 步骤 | 预期 | 实际退出码/状态 | 回滚点 |
|---|---|---|---|
| 本地 inject | health 返回 503，`checks.supabase=down` | 脚本 0 / HTTP 503 | 终止注入进程 |
| 本地 recover | 同一 health 返回 200，`checks.supabase=up` | 脚本 0 / HTTP 200 | 无数据写入，终止本地进程 |
| 生产 capture-before | 记录 Ready、SHA、健康检查 | 未执行，`BLOCKED` | 保留原部署 URL/SHA |
| 生产 promote-rollback | 单步回滚到目标部署 | 未执行，`BLOCKED` | 原部署可再次 Promote |
| 生产 verify-after | 健康、数据库、release SHA 与目标一致 | 未执行，`BLOCKED` | 按原部署 URL/SHA 恢复 |

回滚脚本强制一次只接收一个 `--step`；`promote-rollback` 还要求 `[QW]` 审核、阿禅确认和目标部署变量。当前只完成 dry-run，不能把它写成真实生产回滚通过。
