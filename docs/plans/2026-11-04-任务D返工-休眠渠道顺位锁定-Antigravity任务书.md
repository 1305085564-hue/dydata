# 任务 D 返工 · 休眠渠道顺位锁定（Antigravity 任务书，2026-11-04）

> 来源：CC 对 4a65a2b0 的页面复验。收纳本体全部通过（折叠条、过滤、跳过失效交换、空态自动展开、徽章、交互保留），但实测抓到一个契约缺口：**休眠渠道留在主列表，而后端交换要求两端可调度**，导致所有与休眠行相邻的移动必然 409。

## 实测证据（本地页面）

| 场景 | 结果 |
|---|---|
| 休眠行（自动休眠中）点下移 | 409「渠道不存在、不属于同一模型或当前不可调度，请刷新后重试」 |
| 成功交换后，反向点上移还原（目标恰为休眠行） | 409，**移动出去后回不来** |
| 两端均为在岗/待复测、中间隔失效渠道 | 200，正常互换 ✅ |

## 逻辑规格（主列表移动目标重算）

主列表行 = active / retest / sleeping。移动规则：

1. **sleeping 行**：上移、下移按钮**禁用**，title 改为「休眠期间顺位锁定，恢复后可调整」。点击不发请求。
2. **active/retest 行**：移动目标 = 沿移动方向**最近的 active/retest 行**（跳过中间的 sleeping 行）；方向上不存在 active/retest 行时按钮禁用。
3. 边界判定由「index 是否为 0/末位」改为「是否存在合法目标」。
4. 后端无需改动：交换校验已允许中间隔不可调度渠道（「可调度相邻」），两端都是 active/retest 必然放行；反向点击目标回到原相邻行，可逆性恢复。
5. # 序号保持按主列表位置显示（含休眠行占位），不改。

示例：`[#1 休眠中, #2 待复测, #3 正常在岗]`
- #1 两个按钮禁用；
- #2 上移禁用（上方无可用目标），下移与 #3 互换；
- #3 上移与 #2 互换，下移禁用。
- #2↔#3 互换后反向点击必然成功还原。
