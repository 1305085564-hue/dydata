# Topics V3 目标与关联施工进度

> 用途：上下文压缩后，以本文件恢复目标、施工边界和完成状态。原始需求曾按五批讨论，正式施工改为三个关联施工包，不机械保留“第五批”。完成一项就更新状态，不另建重复计划。

## 总目标

选题库只沉淀被数据验证过的干货选题，帮助员工快速选题并去飞书创作。允许多人重复写同一好题，持续累积成绩。

固定边界：保留现有八大母题；不做站内编辑器、飞书嵌入、原视频图片/播放/链接；内部和外部成绩不能混成一个平均值；视觉不能代替真实接口和数据。

## 施工包 B：多人写作、七天热度、日报闭环与飞书

状态：`代码完成（2026-08-29，Codex）；生产 migration 尚未执行`

- 废除撞车阻止、认领名额、候选位和替换认领。
- 同一选题允许多人同时写。
- 热度统一为近 7 天参与人数；详情可拆分已写完与仍在写，同一人去重。
- 员工提交作品时关联所选选题，成绩继续累积；提交后结束“正在写”，也可手动取消。
- 主行动复制选题内容并打开团队固定飞书空间；不自动创建个人文档。
- 失败时不标记成功；飞书打开与写作状态要有明确顺序和可恢复错误。

- B 包要点：migration `20260829091000_topics_v3_writing_states.sql` —— sub_topic_claims 状态迁移为 writing/cancelled/completed（旧值仅作历史兼容保留在 check 中），新增 ended_at/completed_video_id，一人一题唯一约束改为仅限 writing，删除 5 条候选上限触发器；废除 replaceSubTopicClaim、replace-claim 路由、SmartReplaceModal、候选位组件（MyClaimDrawer/MyClaimSlotBar，经全量调用点核查后删除）；startWritingClaim 幂等（唯一索引兜底并发）且拒绝已移出选题。七天热度唯一口径 computeRecent7dHeat（近7天提交过关联作品的成员 + 近7天开始写且仍在写的成员，并集去重），服务端在 pool/claims 接口返回三值，排序新增 recent_heat 并在完整结果集上分页前执行；ai_recommended 排序已删除、best_play 实装真实排序。日报提交改为校验选题存在且在库（不要求先认领），提交成功后幂等结束正在写（提交失败不会走到该步骤）。飞书地址存 system_settings `topics_feishu_workspace_url`（仅 https），管理端 /api/admin/topics-library/feishu-url（manage_system 鉴权）读写；FeishuCreationModal 收真实 isWriting 与地址，标记失败明确报错不关闭、等待结果后才打开飞书，复制内容新增数据证明摘要。全量 npm test 1236/1236、lint 0 error、tsc、build 通过。
