## 一、要不要让 Codex 跑上线？

**结论：跑 migration 让 Codex 跑；前端部署基本是自动的，你确认一下就行。**

大白话分两块：

- **数据库改动（跑 migration）**：这是把改好的数据库脚本推到线上库执行。命令有先后、要连对库、跑错顺序会出事——这种活交给 Codex，比你手敲稳。让它跑，并要求它把**每条命令的执行结果原文**贴回来，别只说"成功了"。
- **前端部署**：你们是 push 到仓库后 Vercel 自动部署。所以 Codex（或你）把代码 push 上去，Vercel 就自己构建上线了，你不用手动操作。只需在 Vercel 后台确认这次部署**状态是绿的（Ready）**。

> 一句话：migration 交给 Codex 跑，前端 push 后等 Vercel 自动部署，你只负责看结果。
