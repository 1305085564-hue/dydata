## 〇、一句话目标

现在同一个意思有好几个界面、好几套名字，最危险的是**一个写着「是否启用渠道」的开关，停的是整个接入点**。你把界面收成"一个意思一个地方、一个名字一件事"，并让人在危险动作点下去**之前**就看到该看的东西。

**你不判定任何业务事实**：哪些模型该收走、下架后某条线算不算供、可用数怎么算——全归 Codex 与口径。你只负责让人**看懂、敢点、点不错**。

**批次**：B-2（执行前确认界面）最先，B-1 / B-3 / B-4 / B-6 可并行；**B-5 与 B-4 里的「现役」一行必须等 C-2 定稿**。

## B-1 · 接入点管理：只留两处写入口

**现状（已核验）**：管理接入点的入口有**三处**，其中两处文案自称"渠道"。

| 位置 | 实际操作的层 | 界面自称 |
|---|---|---|
| 齿轮 →「渠道管理」弹窗 | 接入点 | 标题「渠道管理」、按钮「新建渠道」、开关「是否启用渠道」、按钮「保存渠道」 |
| 渠道工作台 · 接入资料区 | 接入点（改 API 地址） | 「已更新接入点 API 地址」（这处说对了） |
| 渠道工作台 · 下拉 | 渠道（改所属接入点） | 「所属接入点」（说对了） |

**最危险的一条**：在那个弹窗里点「是否启用渠道」，停的是**整个接入点**——该服务商下所有线路一起停，全站相关业务瞬间没有可用算力，且没有任何提示说明按错了。删除同理：删的是接入点，反馈写的是「已删除渠道「X」，5 秒内可撤回」。

**口径已定（冻结裁决②，不许自行改判）**
- **允许两处**：① 渠道工作台**只读展示归属**，并提供改所属接入点 / 改接入资料；② 接入点管理弹窗做停 / 启 / 改名 / 改接入资料。
- **不允许第三个写入口。**
- 两层用词分层到底：弹窗只讲接入点、工作台与卡片只讲渠道。
- **必须保留接入点的改名能力**——存量有个脏名 `api2 gemin` 等人逐条定名。收口过程把改名能力弄丢了，就是本条未完成。

**判据**：想改接入点名字，全页只有一条清晰路径；想停一条线，界面上不存在"看起来像停这一条、实际停了全部"的开关。

## B-2 · 危险动作的执行前确认界面（**最先交付**）

五类动作要在**点击之后、真正改东西之前**给出一屏确认：停接入点、删接入点、收走模型供应、全站下架、跨渠道批量启用。名单内容由 Codex C-1 供给你，**你负责这一屏怎么排**。

**必须有什么（冻结裁决③）**
1. **被牵连对象的真实名称，逐条列出**——具体渠道名、具体业务功能名。只有"共 3 条"这种数字算不合格。
2. **一个更窄的替代动作**：例如"只想停这一条线？"。不能只给"确定 / 取消"。
3. 信息不全时**默认不可执行**，界面显示"无法确定，因为……"。**禁止用空白、0、"暂无"冒充"很干净"。**

**明确禁止的省事做法**
- 不得把名单折叠成"展开查看"。
- 不得把确认塞进 toast。
- 不得因为后端字段还没到，就先上一个只有数字的版本等后续补——那会被当成已完成。

**判据**：五类动作逐一实操，每类都能看到名单＋替代动作。必测样本 `api1 default`（21 个死模型）、`api tang ChatGPT`。

## B-3 · 同一个动作只留两个入口

「检测此渠道全部模型」今天在**工具栏两处、模型卡渠道行、渠道工作台、同步弹窗**共四处调用同一个后端动作。名字收口不等于入口收口。

**要求**：**入口数 ≤ 2**，且留下哪两处要能说出理由（为什么是这两处、用户从哪进最顺手）。**不得靠"改同名"交差**——那是把四个重复按钮并排摆出来。

## B-4 · 术语收口

| 现在混用 | 统一为 |
|---|---|
| 供应商 / 服务商 / 上游接入点 / 接入点 | **接入点**（仅"接入 / 编辑接入资料"处可出现服务商语义） |
| 渠道 / 专线 / 密钥 | **渠道** |
| 模型 / 型号 | **模型** |
| 储备 / 储备中 / 储备待开启 / 收回储备仓库 | **储备** |
| 「仓库」（仍是生产在用的类型名 + 界面文案） | **概念清零**，全站不再出现 |
| **现役 / 现役在册 / 在册** | **暂缓，等 C-2 定稿**（见下） |
| **可用 / 可调度 / 就绪 / 在线** | **暂缓，等两态归一方案**（硬卡） |

**现在就做的**：「仓库」——它已在界面上以"存入仓库""储备待开启"露出，且是一个仍在用的类型名，改名不涉及口径争议。

**同类必须一起扫干净的**：全站多处仍把一条渠道叫「密钥」——删除反馈「已删除密钥，5 秒内可撤回」、依赖提示「此密钥正在被…使用」、就绪提示「N 个密钥就绪」、工作台「绑定新接入点与专线密钥」、业务页「未命名密钥」。**这些说的都是渠道。**

**为什么「现役」「可用」两行要卡住**：今天"现役"的含义是"任一渠道开着就叫现役"，而本轮要把"全站用不用"和"这条线供不供"拆成两级；"可用"更敏感——**上一轮刚为可用性口径倒挂修过一次**，先定词会把歧义重新埋回去。这两行归统筹侧定，你不要自己判。

**判据**：全站搜索"密钥 / 专线 / 仓库 / 供应商 / 服务商"，在 AI 配置中心内命中为 0（纯代码注释除外）。

## B-5 · 「本渠道启用」分类（**等 C-2，不许提前删**）

它今天确实永远不可能出现（本渠道开着必然全站现役），但拆级之后会**第一次获得合法含义**（全站关、这条线记着"我供"）。提前删等于拆完再补。

**要求**：等 C-2 定稿后随其结论一并处理；在此之前**保持原样不动**。

## B-6 · 名不符实按钮的文案半边

**事实**：模型视角渠道行的按钮文案「测试连通」、tooltip「只测通不通，最快」，实际做的是**测"这条线供这个模型"**，还会给那个模型记一次失败。

**口径已定（冻结裁决①）：改名字，不改行为。**
- 你：把名字和提示语改成说清"测这条线供这个模型"。
- **不得**自行把它改成真的渠道级连通测试（行为归 Codex C-7）。
- **不得**为它新造第二个同义按钮，也不得自行换一套别的措辞。

---

## B-7 · 删除与撤回的反馈预期要能自洽

今天同类动作混着两种模型：一处"不可撤销 + 二次确认"，一处"5 秒可撤回"（还带倒计时）。用户对"删除"建立不起稳定预期。

**边界**：本条只做**同类动作反馈形式的一致化**（同一类动作用同一种确认与反馈），**"哪一类动作该可撤回"是口径判断，等确认后再改，不要自己判**。判据：同类动作在全站的反馈形式只有一种。

## B-8 · 三态显示语义（依赖 Codex 供字段）

| 状态 | 必须能读出什么 |
|---|---|
| **未知** | 未成功同步过或清单为空 → 显示「未知 · 尚未成功同步」，**禁止显示 0** |
| **待收走** | 清单没有 **且** 实测不通（两个信号同时成立）→ 才给收走入口；仅凭清单依据的写「疑似，未验证」，不给一键收走 |
| **已就绪，但全站未启用** | 这条线供、但全站级没开 → 必须明写这一句，**不许静默**，也不许在可用数里被计成可用 |

后端字段没到位前，宁可标"未接入"，**不许前端硬编码或造兜底值顶上**。
