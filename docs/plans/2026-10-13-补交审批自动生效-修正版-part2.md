# 补交审批自动生效 - Part 2：审批自动续交对接（可执行版 V3）

> 前置条件：Part 1 已上线（`buildVideoSubmitResponse` 支持 `actor` 参数）
> 预计工作量：**半天到一天**
> 本版基于对真实代码的逐行核对，替换 V2 中与现状不符的设计

---

## 与 V2 的差异（本版修正了什么）

| V2 的设计 | 真实情况 | 本版处理 |
|---|---|---|
| 选方案 A（先写数据、后审批） | `route-core.ts:314` 明确要求：超过 72 小时的提交必须存在 `status='approved'` 的申请，否则 409。先写时申请还是 pending → **必然被拒** | 改为**方案 B**（先审批、后续交） |
| 续交成功后立刻清空 `submission_payload` | 之后 RPC/通知失败 → 暂存已清、申请未通过 → 用户无法重试，死锁 | 清空挪到最后，失败只告警 |
| 给 `HandleFulfillmentAppealDeps` 加**必需**字段 | `route.test.ts:32` 是完整字面量 `const deps: HandleFulfillmentAppealDeps = {...}`，缺字段 → **TS 编译错误**，13+ 处调用受影响 | 设为**可选** + 默认兜底 |
| `mark("auto-resume")` | 不在 `MutationStage` 联合类型（`observed-mutation.ts:8-22`） | 先往枚举里加，再使用 |
| `route.config.ts` 配 `maxDuration` | 不是 Next.js 约定，不生效。项目里已有正确写法：`export const maxDuration = 60`（`ocr-screenshot/route.ts:56`） | 写在 `route.ts` 内 |
| 测试用 `appealId: "test-appeal-id"` | `parseHandleFulfillmentAppealPayload` 校验必须是 uuid → 直接返回 400 | 用真实格式 uuid |
| 删掉"去上传数据"按钮 | `resume.test.ts:45` 按源码文本断言 `resumeAppeal=...`，删了必红 | **不删按钮**：失败分支保留它 |

## 方案选择：只能用方案 B

**方案 A 不可行的证据**（`src/app/api/video-submit/route-core.ts:314`）：

```typescript
if (deadline.decision === "requires_appeal") {
  const { data: approvedAppeal } = await supabase
    .from("fulfillment_appeals")
    .select("id")
    .eq("user_id", user.id)
    .eq("account_id", normalized.account_id)
    .eq("record_date", normalized.biz_date)
    .eq("status", "approved")          // ← 必须是 approved
    .maybeSingle();
  if (!approvedAppeal) {
    return NextResponse.json({ error: "该提交已超过 72 小时，请先申请补交", ... }, { status: 409 });
  }
}
```

补交场景本来就是因为**超时**才申请的，必然走 `requires_appeal` 分支。
先写数据时申请还是 `pending` → 409 → 整个审批失败。**所以只能先审批、后续交。**

**方案 B 的代价（必须接受，且要有兜底）**：
审批 RPC 会同时把 `fulfillment_records` 标成 `confirmed_published`，
所以续交失败时"审批已通过、统计已算发布、数据没写入"。

兜底就是：**保留 `submission_payload` + 保留通知里的"去上传数据"按钮**。
用户点按钮仍能走原来的 resume 链路完成提交。这是本方案能接受方案 B 的前提。

## 步骤 2：抽取续交函数（1.5 小时）

**新建**：`src/app/api/admin/fulfillment/appeal/_resume-submission.ts`

```typescript
import { NextRequest } from "next/server";
import type { SupabaseClient } from "@supabase/supabase-js";
import { buildVideoSubmitResponse, defaultVideoSubmitDeps } from "@/app/api/video-submit/route-core";

export type ResumeSubmissionResult =
  | { success: true; videoId: string | null; cleared: boolean }
  | { success: false; error: string };

export type ResumeSubmissionDeps = {
  getBaseUrl: () => string;
};

export async function resumeAppealSubmission(
  appealId: string,
  supabase: SupabaseClient,
  deps: ResumeSubmissionDeps,
): Promise<ResumeSubmissionResult> {
  // 1. 读暂存数据
  const { data: appeal, error: readError } = await supabase
    .from("fulfillment_appeals")
    .select("id, user_id, submission_payload")
    .eq("id", appealId)
    .maybeSingle();

  if (readError) return { success: false, error: "读取补交申请失败" };
  if (!appeal) return { success: false, error: "补交申请不存在" };
  if (!appeal.submission_payload || typeof appeal.submission_payload !== "object") {
    return { success: false, error: "没有找到待续交的数据" };
  }

  // 2. 直接调用提交链路（不走 HTTP，无网络往返、无超时风险）
  //    actor 参数只有服务端能传，外部请求不可达
  const request = new NextRequest(new URL("/api/video-submit", deps.getBaseUrl()), {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(appeal.submission_payload),
  });

  const response = await buildVideoSubmitResponse(
    request,
    defaultVideoSubmitDeps,
    undefined,
    { userId: appeal.user_id },
  );

  if (!response.ok) {
    const body = await response.json().catch(() => ({ error: "未知错误" }));
    return { success: false, error: body?.error ?? "数据写入失败" };
  }

  const result = await response.json().catch(() => ({}));
  const videoId = (result?.id ?? result?.video_id ?? null) as string | null;

  // 3. 清空暂存（放在最后；失败只告警，不阻断 —— 提交接口自身有查重兜底）
  const { error: clearError } = await supabase
    .from("fulfillment_appeals")
    .update({ submission_payload: null })
    .eq("id", appealId);

  if (clearError) {
    console.warn(`[appeal ${appealId}] 数据已写入，但清空暂存失败`, clearError);
  }

  return { success: true, videoId, cleared: !clearError };
}

export function defaultResumeSubmissionDeps(): ResumeSubmissionDeps {
  return {
    getBaseUrl: () => {
      if (process.env.VERCEL_URL) return `https://${process.env.VERCEL_URL}`;
      return process.env.APP_BASE_URL ?? "http://localhost:3000";
    },
  };
}
```

**注意**：
- `new NextRequest(...)` 必须用**绝对 URL**，相对路径会抛 `URL is malformed`
- 提交链路内部会读 `request.nextUrl.origin`（route-core.ts:414 / 639），所以 base URL 必须真实可达语义
- 本地开发请在 `.env.local` 配 `APP_BASE_URL=http://localhost:3000`

## 步骤 3：接入审批接口（1.5 小时）

**文件**：`src/app/api/admin/fulfillment/appeal/handle/route.ts`

### 3.1 依赖设为**可选**

```typescript
export type HandleFulfillmentAppealDeps = {
  // ... 现有 10 个字段保持不变
  resumeSubmission?: (appealId: string, supabase: SupabaseClient) => Promise<ResumeSubmissionResult>;
};
```

**必须是可选**。现有测试是 `const deps: HandleFulfillmentAppealDeps = { ...10 个字段 }`（route.test.ts:32），
加必需字段会让 13+ 处调用全部编译失败。

### 3.2 在 RPC 之后插入续交

现状顺序（约 340 行起）：`mark("review-rpc")` → RPC → 通知 → 标记待办。
改为：RPC → **续交** → 通知（按续交结果选文案）→ 标记待办。

```typescript
mark("review-rpc");
const rpcResult = await deps.handleAppealRpc(auth, payload.data);

// RPC 失败：保持现状的错误处理，不要动
if (!rpcResult || rpcResult.error) {
  setFulfillmentAppealObservationResult(observation, {
    businessSucceeded: false,
    auditStatus: "skipped",
    employeeNotificationStatus: "skipped",
    todoStatus: "skipped",
    autoResumeStatus: "skipped",
  });
  return failureResponse(new AppError({ code: "RPC_FAILED", message: errorText(rpcResult?.error) ?? "rpc failed" }), {
    businessSucceeded: false,
    auditStatus: "skipped",
    employeeNotificationStatus: "skipped",
    todoStatus: "skipped",
    notificationMarked: null,
  });
}

// 审批成功后，尝试自动续交（失败不阻断审批，走兜底）
let autoResume: ResumeSubmissionResult | null = null;
if (payload.data.decision === "approve" && !("response" in auth)) {
  mark("auto-resume");
  autoResume = await (deps.resumeSubmission ?? defaultResumeSubmission)(
    payload.data.appealId,
    auth.supabase,
  );
}
```

**关键**：续交失败**不要** `return failureResponse`。
审批已经落库了，返回失败只会让管理员以为没通过，而库里其实已经变了 —— 这是 V2 最大的语义错误。

### 3.3 通知按结果分支（**保留按钮**）

```typescript
const status = payload.data.decision === "approve" ? "approved" : "rejected";
const autoResumeOk = autoResume?.success === true;

const notification = await deps.emit({
  recipients: [appealOwnerResult.data.user_id],
  type: "fulfillment.appeal.result",
  category: "feed",
  severity: status === "approved" ? (autoResumeOk ? "success" : "warning") : "warning",
  title: status === "approved" ? "补交申请已通过" : "补交申请已驳回",
  body: status === "approved"
    ? (autoResumeOk
        ? `${appealOwnerResult.data.record_date} 的补交申请已通过，数据已自动提交。`
        : `${appealOwnerResult.data.record_date} 的补交申请已通过，但数据写入未成功：${autoResume?.error ?? "未知原因"}。请点击按钮重试。`)
    : buildFulfillmentAppealRejectionNotification(appealOwnerResult.data.record_date, payload.data.reason ?? ""),
  // 只在续交未成功时保留按钮；成功则不显示
  actionLabel: status === "approved" && !autoResumeOk ? "去上传数据" : null,
  actionUrl: status === "approved" && !autoResumeOk
    ? `/dashboard?resumeAppeal=${encodeURIComponent(payload.data.appealId)}`
    : null,
  sourceType: "fulfillment_appeal_result",
  sourceId: payload.data.appealId,
  payload: {
    appealId: payload.data.appealId,
    accountId: appealOwnerResult.data.account_id,
    status,
    autoResumeStatus: autoResume ? (autoResume.success ? "succeeded" : "failed") : "skipped",
    ...(autoResumeOk && autoResume && "videoId" in autoResume && autoResume.videoId ? { videoId: autoResume.videoId } : {}),
    ...(status === "rejected" ? { reason: payload.data.reason ?? "" } : {}),
  },
});
```

`resumeAppeal=${encodeURIComponent(payload.data.appealId)}` 这个字符串。
