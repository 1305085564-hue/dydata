# P3 视觉 UI 修复与审查提示词

> 2026-09-08 由 CX 从 `docs/待办清单.md` 的 P3 库存中单独拎出。本文是独立派发入口，相关条目已从待办清单移除；修复完成后只写日志和交付结论，不把条目加回待办。本文不包含后端、数据库、接口或数据口径任务。

## 本批范围

- 员工端触控热区规范补齐：V2 填报表单关键交互仅 36px/30px，未达 >=44px 规范。
- 后台消除黑底旋转菊花：`collaboration-workbench.tsx` L21-25 异步加载个人档案卡弹窗改用浅砂骨架屏（`bg-[#F5F3EE]` 2.5s 呼吸）。
- 后台抽屉人名去衬线：`member-drawer.tsx` L299 的 SheetTitle 用户名去掉 `font-serif`，保留 L437 的学者边注衬线设计。
- 后台空状态接入真实暖墨手稿插图：`talent-tab.tsx` 等次级 Tab 使用真实组件（`DeskStudyIllustration`、`CompassConstellationIllustration`、`ZenFinishedIllustration`、`DraftRecalibrateIllustration`），替代冷灰 Lucide 图标。
- 灰框换微环：仅改不承载错误态的容器；文案卡等兼任校验红框的容器需先设计好错误态替代方案再动。
- Toast 降噪：仅移除“操作结果已经就地可见”的成功 Toast；批量操作部分失败、后台异步失败、不可见结果仍必须保留明确反馈。

## 暂不纳入

- `/admin` 路由解耦：这是权限与路由架构工程。
- `/growth` 与 `/content-tools/rewrite` 整体重做：已冻结，重做前只修明确故障。
- 文案助手历史会话完整交互：偏业务闭环与状态机。
- OCR ↺ 恢复识别值：偏数据留存与提交状态机。

## 修复 Agent 提示词

```text
你是 DYData 项目的前端视觉/UI 修复 agent，本轮只处理 P3 视觉 UI 库存，不碰后端、数据库、接口、权限、业务口径和发布。

目标：
把 P3 中偏视觉/UI 的库存单独修复收口，范围只包括：
1. 员工端 V2 填报表单触控热区补到 >=44px。
2. 后台个人档案卡异步加载从黑底旋转菊花改为浅砂骨架屏：bg-[#F5F3EE]，2.5s 呼吸。
3. 后台成员抽屉人名去掉错误衬线：member-drawer.tsx 的 SheetTitle 用户名去掉 font-serif；保留学者边注位置的衬线设计。
4. 后台次级 Tab 空状态接入已有暖墨手稿插图组件，替代冷灰 Lucide 空图标。
5. 灰框换微环：只改不承担错误态/校验态的容器；任何兼任红框校验的容器先不改，记录原因。
6. Toast 降噪：只移除结果已经就地可见的成功 Toast；失败、部分失败、后台异步不可见结果必须保留。

必须先读：
- AGENTS.md
- docs/待办清单.md
- docs/Claude设计哲学.md
- docs/Claude设计规范.md

施工边界：
- 禁止改 API route、server action、Supabase 查询、migration、权限判断、统计口径。
- 如果发现某项需要后端或数据状态机配合，停止该项，只记录为“超出本批”。
- 不处理 `/growth` 与 `/content-tools/rewrite` 整体重做，不处理 OCR 恢复识别值，不处理文案助手历史会话。
- 不做全站大扫荡，只改待办点名路径及其必要邻近组件。
- 保留已有用户/其他 agent 未提交改动，不要重排无关代码。

设计标准：
- 遵守三层空间：L1 `#FBF9F5`，L2 `#FFFFFF`，L3 透明排版。
- 主容器优先用 `shadow-card-ring`，避免厚灰框；但错误态/校验态容器不得直接去掉红框反馈。
- 小字、表格、表单、抽屉标题默认 Sans；衬线只用于设计规范允许的四类场景。
- 骨架屏用浅砂 `#F5F3EE`，2.5s 呼吸，加载完成快速退场。
- 空状态避免“暂无数据”系统语，使用业务化短句和已有暖墨手稿插图。
- 每屏最多一个暖橙主行动。

建议先定位这些文件和调用链：
- `src/app/(app)/admin/collaboration/collaboration-workbench.tsx`
- `src/app/(app)/admin/collaboration/member-drawer.tsx`
- `src/app/(app)/admin/collaboration/talent-tab.tsx`
- `src/app/(app)/dashboard/video-submit-form-v2.tsx`

验收：
- 改动后跑定向测试；如果没有现成测试，至少跑 `npx tsc --noEmit`、`npm run lint`、`git diff --check`。
- 对可见 UI 改动，必须用真实浏览器或 Playwright 截图检查对应页面/抽屉/空状态，覆盖桌面和窄屏关键宽度。
```

```text

审查对象：
- 修复 agent 的交付说明
- 当前 git diff
- docs/待办清单.md（只确认本批没有被重新挂回待办）
- 日志/YYYY-MM-DD.md
- 实际相关页面/组件截图或浏览器证据

必须先读：
- AGENTS.md
- docs/待办清单.md
- docs/Claude设计哲学.md
- docs/Claude设计规范.md

重点审查：
1. 是否误改后端、数据库、接口、权限、统计口径或被冻结页面整体重做范围。
2. 触控热区是否真的达到 >=44px，且没有挤压文字或破坏布局。
3. 个人档案卡加载态是否消除了黑底旋转菊花，是否为浅砂骨架屏并能在加载后退场。

10. 日志是否把“已修复”“暂缓”“超出本批”写清楚；`docs/待办清单.md` 是否没有把本批视觉/UI 条目重新挂回库存。

输出格式：
- 先列阻断问题：必须修，否则不能算完成。
- 再列非阻断问题：可以后续优化。
- 最后给结论：通过 / 不通过 / 需要补证据。
- 每个问题必须带文件路径和行号，或明确说明缺少哪类截图/命令证据。
```
