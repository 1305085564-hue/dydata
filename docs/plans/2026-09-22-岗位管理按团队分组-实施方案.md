# 岗位管理按团队分组 · 实施方案与执行计划

> 日期：2026-09-22（定稿修订：权限/审计/零产出 + RLS、人数口径）  
> 范围：数据中心 `/admin/collaboration` 新增「按团队（工种小队）」排列  
> 本文只做方案与派工，**不含已实现代码**。实现按本计划分批执行。  
> 已与阿禅确认三处修改与两条补充，按本版定稿执行。

---

## 一、给阿禅的结论

**要做什么**：在岗位管理里，除了现在的「按岗位」（达人/运营/文案/剪辑），再加一种「按团队」——按你们的工种小队（文案一组、达人一组、运营组…）看完成情况。

**怎么看**：点进某个小队后，**第一行是整组综合数据**，下面**每位组员一行**，列和现在岗位表一致，不另起一套报表。

**要动什么**：

1. 给成员增加「所属工种小队」（挂在一部/二部下面，只是编组，**不动权限、不动公司**）。
2. 小队可以：起名、改名、新建、删除、分配/取消组员。
3. 规则：**文案 / 达人二选一**；**运营可以兼任**（在文案或达人之外再进一个运营组）。**剪辑本轮不独立分组**。

**不做什么**：不改一部/二部（teams）公司模型；不改爆款/有效/优秀/文案计费等口径；不做编制历史快照；不做剪辑小队。

## 二、已确认决策（冻结）

| # | 决策 | 结论 |
|---|------|------|
| 1 | 「团队」指什么 | **工种小队**（文案一组等），挂在一部/二部（现有 `teams`）下 |
| 2 | 岗位管理看哪一层 | 只看工种小队，不做一部 vs 二部对比 |
| 3 | 数据指标 | **沿用各岗位原有指标**（文案/达人/运营各用自己那套列） |
| 4 | 展示形态 | 组详情：**第一行组综合 + 下面组员个体行**，尽量延续现有个体表 |
| 5 | 入口 | 顶部 **按岗位 \| 按团队** 双模式，默认按岗位 |
| 6 | 兼任规则 | 文案/达人互斥（一人最多一个 peer 小队）；运营可兼一个运营小队。**同槽位换组 = 就地自动替换原归属**（2026-09-22 A 案裁定），不要求操作人先取消 |
| 7 | 剪辑 | 本轮无独立剪辑分组；剪辑只在「按岗位」出现 |
| 8 | 编制来源 | 可自定义组名、增减小组、分配成员；历史月份按**当前编制**回看 |
| 9 | 管小队权限 | **`manage_members` + 限本公司**：有成员管理权的公司所有者、组长管本公司小队；建组挂本公司，分配仅本公司成员，禁止跨公司 |
| 10 | 操作留痕 | 统一 `writeAuditLog` → **`audit_logs`**（不用 `admin_actions`） |
| 11 | 零产出组员 | **必须出人行**（含文案未认证 0 篇），数值 0/—，不与有产出者混用「有数才显示」 |
| 12 | 按团队人数 | 一人兼文案组+运营组时，**各岗位人数各算各的**，不跨岗位去重合计 |
| 13 | 换组语义（2026-09-22 追加） | 两个入口（管理小队抽屉 / 成员抽屉）**统一为一次原子替换**：界面既已写「加入将替换原归属」，服务端就必须真的替换，不得回 409「请先取消原分配」 |

组织关系：

```text
teams（一部/二部，已有，管权限与数据范围）
├── work_groups kind=writer   文案一组、文案二组…
├── work_groups kind=talent   达人一组、达人二组…
└── work_groups kind=operator 运营一组…
      ↑ 仅用于岗位管理分组展示与编制，不参与权限
```

## 三、实施方案

### 3.1 数据模型

**新表 `work_groups`**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid PK | |
| team_id | uuid NOT NULL → teams(id) ON DELETE CASCADE | 所属一部/二部 |
| name | text NOT NULL | 组名，同一 team 内唯一 |
| kind | text NOT NULL CHECK (`writer` \| `talent` \| `operator`) | 工种 |
| created_at | timestamptz | |
| created_by | uuid NULL | 操作人，便于审计 |

唯一约束：`unique (team_id, name)`。

**`profiles` 增加两列（可空）**

| 字段 | 指向 | 规则 |
|------|------|------|
| work_peer_group_id | work_groups，kind ∈ {writer, talent} | 文案/达人二选一（单列天然互斥） |
| work_operator_group_id | work_groups，kind = operator | 可兼任，至多一个 |

外键：`ON DELETE SET NULL`（删组不删人）。

**约束执行**

- DB：类型 CHECK、外键、组名唯一；`work_groups` **启用行级安全**，不给 authenticated 任何直连读写通道。
- 应用层：分配时校验 kind 匹配、**同 team（本公司）**、peer 互斥、operator 可兼；**同槽位换组就地替换**（覆盖原归属，审计记 `previous_group_id`/`previous_group_name`），跨公司小队、跨公司成员、无团队归属成员一律 403。
- 写路径：统一 **Server Action**，门禁 **`manage_members` + 限本公司**（公司所有者、有成员管理权的组长可管本公司小队）；**禁止** authenticated 直写 work_groups / 改归属。读写全部走服务端（service role）。

**Migration 文件**：`supabase/migrations/<timestamp>_work_groups_for_collab.sql`  
执行纪律：**应用代码具备部署条件后再跑 migration**（见项目规则「禁止数据库先行发布」）。

### 3.2 服务端模块

| 模块 | 职责 |
|------|------|
| `src/lib/work-groups.ts` | 列出/新建/改名/删除小队；分配/取消组员；互斥与同 team 校验 |
| `src/app/api/admin/collaboration/_shared.ts` | `CollaborationProfile` 带上归属；新增 `buildWorkGroupViews(dataset)` |
| Server Action | **唯一写入口**，门禁 `manage_members` + 限本公司（**不要**照搬 `canManageTeamStructure` / createTeam：那是集团模式 `groupMode` 下 `company_owner` 专属，普通公司 admin 进不去，与业务冲突） |

每个写操作成功后调用 `writeAuditLog` → `audit_logs`，`action` 建议：`create_work_group` / `rename_work_group` / `delete_work_group` / `assign_work_group` / `unassign_work_group`。

**`buildWorkGroupViews` 输出**

```ts
type WorkGroupSummaryRow = {
  id: string;
  name: string;
  kind: "writer" | "talent" | "operator";
  teamId: string;
  memberCount: number;
  // kind 对应的组综合（与该岗位列一致的合计字段）
  aggregate: WriterAgg | TalentAgg | OperatorAgg;
};

type WorkGroupDetailView = {
  summary: WorkGroupSummaryRow;
  // 组员行 = 现有 StaffRow | TalentRow | OperatorRow，不改字段口径
  // 必须覆盖小队当前编制名单（零产出也出人行），再叠统计
  members: StaffRow[] | TalentRow[] | OperatorRow[];
};
```

**组综合合计规则**（只加总，不改个人口径）

| 指标 | 规则 |
|------|------|
| 作品数/篇数、有效、优秀、计费、导粉、爆款、独立完成、账号数（去重） | 组内求和（账号数为组内去重并集） |
| 条均播放 | `floor(组总播放 / 组作品数)`，0 件为 0 |
| 环比（仅运营组） | `（组本月总播放 - 组上月总播放） / 组上月总播放`，上月为 0 则 null |
| 文案计费 | 仅已认证成员计入；未认证个人为 null，合计只加已认证 |

范围仍走现有 `visibleUserIds`；组员只读本人。

**零产出组员**：组详情 `members` **先按小队当前成员名单全部生成（一个不能少）**，再叠加 `buildStaff` / `buildTalents` / `buildOperators` 的统计数据；当月无产出则数值填 **0 或 —**（含文案**未认证** 0 篇，不能只显示已认证）。数值口径仍复用上述三个 builder，不另写一套。

### 3.3 前端页面

**URL**

| 模式 | URL |
|------|-----|
| 按岗位（默认） | `?year&month&tab=talents\|operators\|writers\|editors`（现状不变） |
| 按团队·列表 | `?year&month&view=teams` |
| 按团队·组详情 | `?year&month&view=teams&groupId=<uuid>` |

- 模式/进组：`router.replace`（与现 Tab 一致，不污染历史）。
- 月份：`router.push`（保留月份浏览历史）。

**布局**

1. 顶部控制舱下增加双模式：`按岗位 | 按团队`。
2. 按团队列表：组名、kind 徽章（文案/达人/运营）、人数、本月作品、总播放、条均，+ 1 个 kind 关键预览列。  
   **人数口径**：一人既在文案组又在运营组时，**各岗位人数各算各的**，不跨岗位去重合计。
3. 组详情：
   - 第一行：`组综合`（浅砂微气垫底，与数据行区分）。
   - 下面：组员行**复用** `StaffTab` / `TalentTab` / `OperatorTab` 的行组件与列（按 kind 选择），仅数据收窄为该组。
   - 点击人 → 现有个人档案卡；点击作品 → 现有视频诊断抽屉。
4. 视觉：遵守《Claude设计哲学》《Claude设计规范》（暖白底、浅砂 Tab、发丝线、tabular-nums），不新增色板。

**小队编制 UI（写）**

- 岗位管理「按团队」：有 `manage_members` 时显示「管理小队」抽屉（建/改/删组、分配成员）。
- 成员管理：成员详情抽屉增加「工种小队 / 运营小队」两处归属（与上同一套服务端动作，禁止两套逻辑）。

### 3.4 权限与安全

| 角色 | 按团队查看 | 管理小队 |
|------|------------|----------|
| 组员 member | 只读自己 | 否 |
| 组长 admin | 本公司可见 | 有 `manage_members` 可管**本公司**小队与**本公司**成员 |
| 公司所有者 company_owner | 本公司可见（集团模式按 `visibleUserIds`） | 同上，限本公司编制写入 |
| 集团模式查看 | 按 `visibleUserIds` | 写入仍不跨公司建组/分配 |

- 门禁口径：**`manage_members` + 限本公司**。不使用 `canManageTeamStructure`（集团模式 company_owner 专属）。
- 不改 RLS 信任模型；`work_groups` **启用 RLS 且无直连通道**，读写全部 service role + 服务端门禁。
- 建组必须挂在操作者本公司 `team_id` 下；分配成员仅限本公司 `team_id`；**普通组长不能跨公司建组或分配别公司的成员**。
- 禁止伪接：无权限或失败必须明确提示，不假成功。

### 3.5 口径与文档同步

- 个人/岗位指标口径**不变**，不改 `docs/数据口径.md` 数字定义。
- 需在 `docs/数据口径.md` §11 或 `docs/全站模块地图.md` 岗位管理节**补一句**：按团队=工种小队编制展示，综合行=组员合计，历史按当前编制回看。
- 更新 `docs/reference/协作管理接口文档.md`：增加 work group 读写契约。

## 五、风险与边界

| 风险 | 影响 | 处理 |
|------|------|------|
| 历史月份按当前编制回看 | 换组后旧月归属变化 | 文档写明；本轮不做编制考古 |
| 删组/换人后综合变化 | 管理误操作 | 删组二次确认；操作落 **`audit_logs`**（`writeAuditLog`；`admin_actions` 仅 AI 工具执行专用，本功能不写） |
| 与旧「小组」概念混淆 | 误以为恢复 group_id | 不建 groups 表；文案统一叫「工种小队」 |
| Migration 先行 | 权限/契约风险 | 严格「代码可部署再跑库」 |
| 组员 0 产出被隐藏 | 以为漏人 | 0/— 仍展示 |
| 双入口两套赋值逻辑 | 数据不一致 | 强制共用 `work-groups.ts` |

**明确不做（Out of Scope）**

- 不改 teams 公司/权限/RLS/集团模式  
- 不恢复旧 `groups` / `profiles.group_id`  
- 不做编制变更历史  
- 不做剪辑小队、不改岗位指标口径  
- 不做按小队导出、小队考核分、一部/二部对比视图
