# AI 配置中心 · 模型上架闸门与资产管理 · 方案设计简报

> 交 Antigravity 出**方案**（不写代码）。产出后交 [审计] 复验真实性、阿禅拍板决策点，再出施工规格书。
> 高密度重塑已完成，本单只解决两个功能缺口，禁止顺手重构无关代码。

## 一、目标（阿禅原话转译）

1. **上架闸门**：接入密钥时模型"全部发现、全部入库"可以，但**默认不上架**；只有管理员手动放出来的模型，才进网站顺位、才能被业务选到。
2. **资产可管理**：模型（上架/下架/改名/删除）与服务商（编辑/停用/删除）必须能在页面上管起来。现状是：密钥能删/调顺位/测试，但单模型零操作入口，服务商只有新增/编辑——旧页面的管理能力在重构中丢了。

## 二、真实体验场景（方案必须逐条走通）

- S1 接入火山方舟新密钥，只想放出 doubao-seed 两个模型，其余 20 个发现但不露出
- S2 某模型渠道质量差，下架它 → 正在用它跑的业务功能会发生什么？必须明确定义（拦截提示 or 自动降级到备用并告知）
- S3 下架后想恢复上架，一步完成
- S4 再次点"同步模型"，**已手动下架的模型不得被自动复活**（现状会复活，见三.2 地雷）
- S5 删除服务商：下面挂着密钥/模型/业务绑定时的行为（拦截/级联/转归档），必须定义且不可静默
- S6 模型改名（display_name）后，业务调度台与算力池两处显示同步

## 三、现状事实（已核实，方案基于这些，不许猜）

1. `add-key-dialog.tsx` L107：勾选自动同步 → `syncKeyModelsAuto(newKeyId)` 不带 modelIds → 后端**全部 insert `is_enabled:true`**
2. `sync-models/route.ts` L114-121：对已存在模型执行 `update is_enabled:true`——**再同步会复活手动下架的模型**（地雷，方案必须收口）
3. `set_key_model_selection`（route.ts L355 附近）：取消勾选 = **物理 delete**，不是停用；需改为停用语义并保留真删除入口
4. 运行时可发现性后端已天然支持：`listRankedProviderKeyModels` 过滤 `is_enabled=true`；`model-family-select` 只列启用模型——**下架=自动退出调度与下拉，无需新后端字段**
5. 密钥删除已有服务端强阻断（409，`key-dependencies.ts`）；模型下架若被启用绑定独占引用，需要同款口径，方案要定义
6. `display_name`、provider `is_enabled/priority` 字段库里都有，后端 update 已支持，缺的是前端入口
7. 变更后 `aiClientInternal.resetCache()` 已在 mutation 路径统一调用

## 四、交付物要求

一份方案文档（放 `docs/plans/`），包含：

1. **交互规格**：每个操作（上架/下架/改名/删除/同步/服务商停用）的入口位置、控件形态、确认流程、反馈文案——按已上线的高密度表格版 UI 落位，禁止新增大卡片
2. **状态与语义表**：发现未上架 / 已上架 / 已下架 / 已删除 四态的定义、迁移条件、对顺位与业务可见性的影响
3. **边界 case 表**：S2/S4/S5 及"下架正被业务独占的模型""删除最后一个服务商"等，逐条给推荐+理由（阿禅拍板）
4. **决策点清单**：所有需要阿禅定的语义（默认全未上架？下架=停用？同步复活策略？）单独列表
5. **改动范围预估**：前端文件清单；需要 Codex 配合的后端点（如三.2 复活收口、独占下架 409）标注"待 Codex"，不许自己改 `src/app/api/`
