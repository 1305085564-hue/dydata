# 报警通道建设（支线任务，2026-11-18 [CC] 立项）

> 状态：**未开工**，阿禅排期后做。支线，不挡主线（架构治理、国内数据库迁移）。
> 待办登记：`docs/通用管理/待办清单.md`「业务待办」。
> 分两段：第一段给阿禅（要你亲手点的部分），第二段给接手的 AI（技术施工）。

## 一、给阿禅看

**要办成的事**：网站打不开、或者夜里的自动任务失败时，你在几分钟内就知道——手机上有推送、飞书报警群里有消息，不用等员工来反映。

**现在的情况（11-18 实测）**
- 没有任何外部监测：网站挂了只能靠人发现。
- 网站自带一个"体检地址"，能同时检查网站和数据库是否正常，监测服务直接用它就行。
- 飞书里已有「dydata」应用，凭证有效。还有一个群机器人在往员工群推"日报提交通知"，它还连着，但**报警不能发进员工群**。
- 今晚 Codex 做的架构治理批10b 会让"夜间自动任务失败"自动上报：已经接了错误记录平台，同时预留了飞书报警群的接口——**只差一个报警群机器人地址**。

**你要做的两件事（共约 15 分钟）**

1. 建飞书报警群和机器人
   1. 飞书新建群，名字如「DYData 报警」，只放你自己（或再加一位技术负责人）。
   2. 群设置 → 群机器人 → 添加机器人 → 选「自定义机器人」，名字「DYData 报警」。
   3. 安全设置选「自定义关键词」，关键词填 `DYData`（只有带这个词的消息才能发进来，防止地址泄露后被人乱发）。
   4. 复制它给出的 webhook 地址（以 `https://open.feishu.cn/open-apis/bot/v2/hook/` 开头），**私聊发给 AI，不要发到任何群里**。
2. 注册网站监测（UptimeRobot，免费）
   1. 打开 uptimerobot.com 注册（建议用公司邮箱）。
   2. 点「New Monitor」，类型选 HTTP(s)，名称填「DYData 线上」，网址填 `https://dydata.cc/api/health?check=cloudbase`，间隔 5 分钟。
   3. 报警联系人勾上你的邮箱；手机装 UptimeRobot App 并登录，就能收到推送。
   4. 建好后把账号邮箱告诉 AI（不用给密码），记进交接文档，方便以后换人维护。

**做完会怎样**：网站挂了 5 分钟内手机收到推送；夜里自动任务失败，第二天一早飞书报警群里有消息，写明哪个任务、什么错。

**要注意**：本周迁到国内数据库/换服务器后，监测地址如果变了，要回来改一下监测网址（AI 迁移时会提醒）。

## 二、给接手的 AI（施工）

**前置**
- 阿禅已完成第一段 1、2，并在对话里给出报警群 webhook 地址。
- 核对批10b 是否已上线：`git grep -n FEISHU_ALERT_WEBHOOK_URL origin/main -- src` 有命中，且 `reportCronFailure` 在该变量存在时发飞书。**没上线就先停**，回报阿禅等架构治理发布；不要自己另写一套发送逻辑（报警发送只有一个入口）。

**事实（11-18 实测，开工时只读复核）**
- 体检地址：`https://dydata.cc/api/health?check=cloudbase` 返回 HTTP 200 及 `{"status":"ok","checks":{"server":"up","cloudbase":{"backend":"cloudbase","status":"up","table":"profiles","rowCount":1,"checkedAt":"..."}}}`（`rowCount` 为抽查行数 0 或 1，失败或未配置返回 HTTP 503 `status:"degraded"`）。
- `FEISHU_WEBHOOK_URL` 是员工群"日报提交通知"（`src/app/(app)/dashboard/actions.ts` `notifyFeishu`、`src/app/api/admin/first-screen-monitor/route.ts` 在用），空请求探测返回 `19002 params error`（地址有效）。**禁止用它发报警，也禁止往里发测试消息。**
- `FEISHU_APP_ID/SECRET`（「dydata」应用）有效，但缺 `im:chat` 类权限、不在报警群里；报警走群机器人 webhook，不用应用身份。
- 本机 Vercel CLI 未 link 项目、`vercel ls` 曾报 `fetch failed`；配环境变量可能要 `vercel link` 或请阿禅在 Vercel 后台操作。

**步骤**
1. 发一条测试消息到报警群（消息正文必须含关键词 `DYData`）：
   `{"msg_type":"text","content":{"text":"DYData 报警通道测试：收到即表示报警群已接通。"}}`
   返回 `code: 0` 且阿禅确认群里看到，才算通。返回 `19024 Key Words Not Found` 说明关键词不对。
2. 核对批10b 发出的报警正文以 `DYData` 开头（架构方案已这样要求并有单测）；不满足就在 `reportCronFailure` 的消息模板里补前缀（只改这一处，补单测断言）。
3. 在 Vercel 的 Production 环境加 `FEISHU_ALERT_WEBHOOK_URL`（**生产配置变更，先跟阿禅确认再做**），之后需重新部署一次才生效。**不写进 `.env.local`**：本机连的是生产库，本地跑定时任务会误报。
4. 上线后验证：确认线上部署包含该变量（重新部署后的提交号）；不为验证故意制造失败。如批10b 带有安全的自检方式，用它；没有就以第 1 步测试消息 + 单测为准，并在收尾卡写明"真实失败报警未实测"。
5. 在 `docs/reference/` 记一份《报警通道上线核对》：报警群名称、机器人安全设置、UptimeRobot 监测项与账号邮箱（不写密码、不写 webhook 地址）、测试结果。

**禁区**
- webhook 地址等同密码：不打印到日志，不提交仓库，不写进文档。
- 不碰员工群机器人。
- 不新增第二套报警发送逻辑。

**验收**
- 阿禅手机收到 UptimeRobot 的测试推送（UptimeRobot 后台可对监测项发测试通知）。
- 飞书报警群收到测试消息。
- Vercel Production 有 `FEISHU_ALERT_WEBHOOK_URL`，且已重新部署。
