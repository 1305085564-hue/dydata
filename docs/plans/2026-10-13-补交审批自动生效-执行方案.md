# 补交审批自动生效 - 执行方案

> 创建日期：2026-10-13  
> 问题：补交审批通过后，用户还要点"去上传数据"按钮，数据才能生效  
> 目标：审批通过后，数据自动生效，不需要用户操作  
> 预计工作量：1小时

---

## 问题分析

### 当前流程
1. 用户上传历史数据 → 超过3天 → 系统拒绝："需要申请补交"
2. 用户填写补交申请 → 数据暂存在 `fulfillment_appeals.submission_payload`
3. 管理员审批通过 → 发送通知："去上传数据"（带 `resumeAppeal` 链接）
4. **用户点击通知按钮** → 调用 `/api/admin/fulfillment/appeals/resume`
5. 自动续交 → 读取 `submission_payload` → 调用 `video-submit` API → 数据写入
6. 清空暂存 → `submission_payload` 设为 `null`

### 问题
**步骤4需要用户额外操作，体验不好。**

用户期望：审批通过 → 数据立即生效（跳过步骤4）

---

## 解决方案

**在管理员审批通过时（步骤3），直接执行步骤5的自动续交逻辑。**

### 技术方案

#### 方案A：在审批接口中直接调用续交逻辑（推荐）

**优点**：
- ✅ 用户体验最好：审批通过即刻生效
- ✅ 代码改动最小：只改一个文件
- ✅ 逻辑集中：审批和续交在同一个事务中

**缺点**：
- ⚠️ 审批接口变慢（多了一次数据写入）
- ⚠️ 审批失败可能是因为数据写入失败（需要明确错误提示）

#### 方案B：审批通过后发送后台任务，异步续交

**优点**：
- ✅ 审批接口不变慢
- ✅ 数据写入失败不影响审批流程

**缺点**：
- ❌ 代码改动大（需要引入后台任务队列）
- ❌ 用户不知道数据何时生效（可能有延迟）
- ❌ 异步失败难以处理（用户已经收到"审批通过"的通知）

### 推荐：方案A

**原因**：
1. 补交申请本来就是"先上传数据，等审批通过后生效"
2. 数据已经暂存了，审批通过时直接写入是最自然的流程
3. 如果数据写入失败，应该拒绝审批（让管理员知道有问题）

## 执行步骤

### 步骤1：抽取续交逻辑为独立函数（30分钟）

#### 1.1 创建共享函数

**创建文件**：`src/app/api/admin/fulfillment/appeals/_resume-logic.ts`

```typescript
import { createAdminClient } from "@/lib/supabase/admin";
import { POST as submitVideo } from "@/app/api/video-submit/route";
import { NextRequest } from "next/server";

/**
 * 自动续交补交申请中暂存的数据
 * 
 * @param appealId - 补交申请 ID
 * @param userId - 用户 ID
 * @param requestUrl - 当前请求的 URL（用于构造 submitVideo 请求）
 * @param requestHeaders - 当前请求的 headers（用于构造 submitVideo 请求）
 * @returns { success: boolean; error?: string; videoId?: string }
 */
export async function resumeAppealSubmission({
  appealId,
  userId,
  requestUrl,
  requestHeaders,
}: {
  appealId: string;
  userId: string;
  requestUrl: string;
  requestHeaders: Headers;
}): Promise<{ success: boolean; error?: string; videoId?: string }> {
  const admin = createAdminClient();

  // 1. 读取补交申请和暂存的数据
  const { data: appeal, error: appealError } = await admin
    .from("fulfillment_appeals")
    .select("id, user_id, status, submission_payload")
    .eq("id", appealId)
    .eq("user_id", userId)
    .maybeSingle();

  if (appealError) {
    return { success: false, error: "读取补交申请失败" };
  }
  if (!appeal) {
    return { success: false, error: "补交申请不存在" };
  }
  if (appeal.status !== "approved") {
    return { success: false, error: "补交申请尚未通过" };
  }
  if (!appeal.submission_payload || typeof appeal.submission_payload !== "object") {
    return { success: false, error: "没有找到待续交的数据" };
  }

  // 2. 调用 video-submit API 写入数据
  const forwardedHeaders = new Headers(requestHeaders);
  forwardedHeaders.set("content-type", "application/json");
  const submitRequest = new NextRequest(requestUrl, {
    method: "POST",
    headers: forwardedHeaders,
    body: JSON.stringify(appeal.submission_payload),
  });

  const response = await submitVideo(submitRequest);
  if (!response.ok) {
    const errorPayload = await response.json().catch(() => ({ error: "未知错误" }));
    return { 
      success: false, 
      error: `数据写入失败：${errorPayload.error || "未知错误"}` 
    };
  }

  // 3. 清空暂存数据
  const { error: clearError } = await admin
    .from("fulfillment_appeals")
    .update({ submission_payload: null })
    .eq("id", appealId)
    .eq("user_id", userId)
    .eq("status", "approved");

  if (clearError) {
    // 数据已经写入了，清空失败不算致命错误
    console.warn(`补交申请 ${appealId} 数据已写入，但清空暂存失败:`, clearError);
  }

  // 4. 提取 video_id（可选，用于返回给调用方）
  const resultPayload = await response.json().catch(() => ({}));
  const videoId = resultPayload.id || resultPayload.video_id;

  return { success: true, videoId };
}
```

#### 1.2 修改现有的 resume 接口使用这个函数

**文件**：`src/app/api/admin/fulfillment/appeals/resume/route.ts`

**修改前**：
```typescript
// 整个 handlePost 函数里都是续交逻辑
```

**修改后**：
```typescript
import { resumeAppealSubmission } from "../_resume-logic";

async function handlePost(request: NextRequest, observation: MutationObservation, layers: MutationLayers) {
  observation.mark("auth");
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return NextResponse.json({ error: "未登录" }, { status: 401 });

  observation.mark("validate");
  let body: { appealId?: unknown };
  try {
    body = (await request.json()) as { appealId?: unknown };
  } catch {
    return NextResponse.json({ error: "请求格式错误" }, { status: 400 });
  }
  const appealId = typeof body.appealId === "string" ? body.appealId.trim() : "";
  if (!appealId) return NextResponse.json({ error: "缺少补交申请编号" }, { status: 400 });

  observation.mark("write-video");
  const result = await resumeAppealSubmission({
    appealId,
    userId: user.id,
    requestUrl: request.url,
    requestHeaders: request.headers,
  });

  if (!result.success) {
    return NextResponse.json({ error: result.error }, { status: 500 });
  }

  layers.businessSucceeded = true;
  observation.mark("finalize");
  return NextResponse.json({ ok: true, resumed: true, videoId: result.videoId });
}
```

import { resumeAppealSubmission } from "../appeals/_resume-logic";

// ... 在发送通知之前

let autoResumeResult: { success: boolean; error?: string; videoId?: string } | null = null;

  autoResumeResult = await resumeAppealSubmission({
    appealId: payload.data.appealId,
    userId: appealOwnerResult.data.user_id,
    requestUrl: context.requestUrl || "/api/admin/fulfillment/appeal/handle", // 需要一个合法的 URL

#### 3.1 单元测试

   - 审批接口返回错误："审批已通过，但数据写入失败"

## 注意事项

### 1. 错误提示要明确
- ❌ 不好："审批失败"（管理员不知道是审批本身失败还是数据写入失败）
- ✅ 好："审批已通过，但数据写入失败：xxx。请联系用户重新上传。"

### 2. 事务一致性
- 审批通过 + 数据写入应该在同一个事务中
- 如果数据写入失败，审批状态不应该改变

### 3. 向后兼容
- 保留 resume 接口，以防有旧的通知链接
- resume 接口检测到 `submission_payload` 为空时，返回友好提示
