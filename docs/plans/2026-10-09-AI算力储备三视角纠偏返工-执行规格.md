## 一、实测证据（真实页面走查，2026-10-09）

以下问题全部在真实环境复现，施工方不得以「未能复现」推诿。

### 1.1 同步模型弹窗自相矛盾（最高优先级）

点渠道 `api9 gemin` 的「重新探测并同步模型」，弹窗同时显示三句互斥文案：

- 「已从渠道获取 **0** 个可用型号」
- 「已启用 **2** / **0** 个型号」
- 「**还没有可启用的型号**」

**根因**：弹窗数据源是 `syncResult.models`，而服务端返回的 `newModels` **只含本次新入库的 model_id**（`src/lib/ai-config/batch-actions.ts:38-42`、`src/app/api/admin/ai-config/sync-models/route.ts:147-156`），不含该渠道已入库的模型。第二次点同步永远为 0。

**正确语义**（阿禅定）：弹窗显示**该渠道全部模型**，勾选的进模型列表，没勾的不显示。不是「新发现」。

### 1.2 弹窗标题泄漏供应商

弹窗标题为「`api9 · api9 gemin`」，违反「全站只显示渠道 + 模型」口径。

### 1.3 接入点下拉两项缺陷

- **收起时显示 UUID**（`12f92599-faa9-...`），展开才显示名称（api1 / api7 / api2 gemin / api tang / api9）。
- **无「新增接入点」选项**。新增入口藏在渠道视角左上齿轮 →「渠道管理」→「新建接入点」，默认视角下完全找不到。

### 1.4 「全部检测」名不符实

工具栏「全部检测」实际只对每个渠道**抽测一条**模型（`src/lib/ai-config/batch-actions.ts:264-268`、`route.ts:435-445` 的 `limit(1)`）。

### 1.5 存量名称脏数据

渠道名：`api9 gemin`、`api 7 gemin`、`api2 default`、`api1 default`、`api7 default`、`claude`。
接入点名：`api2 gemin`。
模型名：`claude-haiku-4-5-20251001` 仍是内部 ID。

### 1.6 一条渠道跨模型族，名字撒谎

渠道 `api tang Gemini` 同时为 gemini、claude、gpt 三族模型供力。渠道名自称 Gemini，实测供力范围远超。

### 1.7 按钮过载

单条渠道行常驻 6 个按钮（上移 / 下移 / 测全模型 / 重新探测并同步模型 / 删除此渠道 / 测试连通），加工具栏与视角内按钮，全页入口 11 个。

### 1.8 已做对的（不要返工）

- 优先级已摊平，界面上只有一个数字（P1/P5/P50…），migration `20261009120000_flatten_ai_provider_priority.sql` 已执行。
- 健康口径已修：健康 / 故障 / 待命中 三态分开，上下一致。
- 业务表「专线冗余」列已显示具体渠道名与不可用原因。
- 渠道名支持就地改名。

## 二、目标架构：三视角正位

### 2.1 三个视角，各司其职

| 位置 | 视角名（固定文案） | 组织方式 | 回答什么 |
|---|---|---|---|
| 页面上半部 | **业务功能调度** | 业务功能 → 模型 → 专线冗余 | 网站在用什么模型，还安全吗 |
| 下半部 · 药丸一 | **模型视角** | 模型 → 渠道明细 | 挂了能换谁，下面有哪几条线 |
| 下半部 · 药丸二 | **渠道视角** | 渠道 → 模型明细 | 这条线路配了什么，状态如何 |

**药丸文案必须改成「模型视角」「渠道视角」**，删除「供给管理」这个功能名（`pool-view-switcher.tsx:26`）。

### 2.2 检测范围与「你能看到哪些模型」绑定（核心规则）

| 你在哪 | 能看到什么模型 | 就测什么 | 调用 |
|---|---|---|---|
| 渠道视角工作台 | 已挂载全部（含未上架） | 测该渠道全部模型 | `test_key_all_models` 扩展 |
| 同步模型弹窗 | 全部（含未上架） | 测该渠道全部模型 | 同上 |
| 模型视角 · 模型卡 | 该模型的供给渠道 | 测该模型在各渠道的连通 | `test_key_model` |
| 工具栏 | — | 全部渠道全部模型 | `test_all_keys_all_models` 扩展 |

**`test_key_all_models` 与 `test_all_keys_all_models` 当前只测 `is_enabled=true` 的模型（`route.ts:731-732`），必须改为测该渠道全部挂载模型，含未勾选/停用的。**

### 2.3 同步模型弹窗的新口径

弹窗 = **该渠道全部模型清单**，四类都要出现并区分标识：

| 分类 | 默认勾选 | 文案 |
|---|---|---|
| 已上架（全站现役） | ✅ | 现役 |
| 本渠道已勾选但未上架 | ✅ | 本渠道启用 |
| 已入库未勾选 | ❌ | 储备中 |
| 本次新发现 | ❌ | 新增 |

- 勾选 = 这个模型在这个渠道可不可用；取消 = 不进模型列表。
- 保存调 `set_key_model_selection`（只影响本渠道）。
- 顶部计数改为「已勾选 X / 共 Y 个」，Y 必须等于该渠道全部模型数。
- **禁止出现「获取 N 个可用型号」这种增量口径文案**，一律用存量口径。

## 四、使用流验收（本轮起改用此验收方式）

**验收标准不再是「功能存在」，而是「阿禅能独立走完」。** 每条流程必须由施工方自己先走通，中途不得出现看不懂的状态。

1. **接入一条新线**：点「接入渠道」→ 下拉能看到名字并能就地新增接入点 → 填显示名（可用快捷词）→ 填 Key → 下一步看到该渠道全部模型并勾选 → 确认后回到页面，新渠道出现且只在它身上生效。
2. **复看已接入的线**：点同一条渠道的「同步模型」→ 看到**全部**模型（不是 0 个）→ 能分辨哪些现役、哪些储备 → 取消勾选某个 → 保存后模型列表里消失。
3. **测一条线**：在同步弹窗里点「检测此渠道全部模型」→ 结果告诉我测了几个、几个通、几个不通、哪个不通。
4. **换模型**：在模型视角看到某模型 `0/N 渠道可用` → 展开看清谁故障、谁待命中 → 能判断该换哪个模型。
5. **巡检**：点工具栏按钮 → 明确知道它测的是「每渠道一条」还是「全部模型」。

**五条走不通任意一条，即为验收不通过。**

## 五、边界与回滚

**明确不改**：表结构、调度算法、健康熔断语义、业务绑定语义、已摊平的优先级 migration、已修好的健康三态口径。

**分批提交**：任务 1 / 2 / 3 / 4 / 5 / 6 各自独立 commit，不得混提交。任务 5（数据污染）必须带回归测试。

**回滚**：每任务一个 commit，可单独 `git revert`。

**状态报告**：每批完成后报「本地已改 / 已推送 / 线上已生效」，三者不可混称。
