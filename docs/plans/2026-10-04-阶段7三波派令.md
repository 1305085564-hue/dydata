## 全局执行纪律（五份派令共用，粘贴时随派令一起给）

1. **不理解需求不自行发挥**：目标、验收命令、禁区照抄执行；拿不准就停下在交付报告里标注疑点，禁止猜。
2. **行为红线**：契约接入只允许"补分层结果记录＋统一错误出口"，**禁止改业务判断、权限范围、数据口径**；改行为＝判不通过。
3. **禁止伪接**：不许用假数据、空 catch、`console.log` 冒充接入；接不动就明确失败或在报告登记"未接入＋原因"。
4. **每批收尾自查**：`git diff --cached --stat` 全量核对暂存区，发现非本任务文件先 `git restore --staged`；只 commit 本任务点名文件。
5. **验收命令组**（交付报告必须带真实退出码）：`npx tsc --noEmit --pretty false`；`npm test`；`npm run gate:static`；`git diff --check`。
6. 交付报告格式：改了什么（文件清单＋每文件一句话）／验收命令退出码／未接入项与原因／疑点。**读数不实＝该批直接打回。**

> **⚠️ 2026-10-05 施工前必读：[QW] 实测发现第 3、4 件事都缺前置条件，不得直接动工**
>
> **第 3 件（运行时指标）缺底座。** 实测 `src/lib/observability.ts` 仅 76 行，导出 `observeOperation` 与 `observeRequest`，**这两个函数当前全仓零调用点**；`queryCount` 只在该文件的类型定义里出现过一次。**全站没有任何一处计算 P95 或 5xx。** 派令写"经观测底座上报，禁止自造第二套指标"——但底座本身还没有入口。**执行前必须先由 [QW]/阿禅拍板：P95、5xx、查询次数这三个指标落在哪（复用 `observeOperation` 还是别的存储），拍完再写代码。** 在此之前禁止开工该项，否则必然自造第二套底座，正好违反本条自己的禁令。
>
> **第 4 件（页面性能预算进门禁）同样缺前置。** `scripts/architecture-baseline.mjs` 里确有一张 `pageBudgets` 静态表（来源 `docs/工程运行事实.md`），但同文件第 85 行自注：`"运行时 P95、查询数、缓存命中率和连接池数据由 observeOperation 接入点追加；本次静态基线不伪造线上数字。"` —— 也就是说**预算表存在、运行时数字为空**，而运行时数字正是第 3 件事的产出。**第 4 件依赖第 3 件**，顺序不能颠倒。
>
> **口径澄清（避免施工方卡壳）：** 禁区写"不改任何 SQL 语义/数据口径"，目标却要"N+1 改批量"，字面看像矛盾。实际口径是：**允许改查询的执行方式（批量化），不允许改结果集**；判定标准就是验收标准第 1 条的结果集等价测试。据此，超时补齐与错误分支收口不受该禁区限制。

**禁区**：

- 不改任何 SQL 语义/数据口径——批量化必须结果集等价，用行为测试证明
