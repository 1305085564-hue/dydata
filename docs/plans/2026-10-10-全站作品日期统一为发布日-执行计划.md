# 全站作品日期统一为发布日（执行计划）

## 目标
全站作品的对外日期统一为「发布日期」（`videos.published_at` 上海自然日），上传日仅用于核实场景，日报归属日不再冒充作品日期。参照 detached 提交 `a964d320`（Antigravity）逐文件手工重打，禁止 merge / cherry-pick（其基线 `81bb9f4a` 与 main 分叉，协作侧同主题改动已在 main）。

## 业务口径（阿禅已确认 7 条）
1. 作品页面/日历/统计/选题库/排行榜/导出主日期 → 真实发布日期（无发布日回退日报归属日，绝不回退上传日）
2. 发布履约「实发/应发、4号是否完成」→ 按发布日；8 号只保留补交/审批事件
3. 跨月作品统计跟发布月；填报/审批记录保留实际发生日
4. 补交案例双层展示：4号已补交 + 8号补交事件
5. 无发布日历史 → `report_date` 兼容
6. 表单日期命名简化为「发布日 / 上传日」
7. 同日多条按数量显示

## 线上真机核对结论（2026-10-10，psql 直连只读实测）
| 函数 | 签名 | 用 published_at | 用 report_date | 用 uploaded_at | 结论 |
|---|---|---|---|---|---|
| `get_fulfillment_range` | (date,date,uuid[],uuid,uuid) | 否 | 是 | — | 迁移未执行 |
| `get_leaderboard_rows` | (date) | 否 | 是 | — | 迁移未执行 |
| `topics_pool_aggregates` | (uuid) | 否 | — | 是 | 旧版，返回 `latestUploadedAt` |

每个函数线上仅 1 个重载，无调用歧义。

- 执行前两处必要修正（数据库先行的向后兼容）：
  1. **topics RPC 保留旧字段名**：新函数原本只返回 `latestPublishedAt`，而线上仍在运行的旧版应用只读 `latestUploadedAt`；两者错位会让选题库「趋势」列表瞬间变空（`daysSinceLastWork` 落到 999 → `>30` 全被过滤）。现两个键都给同一新口径值，过渡期兼容，应用上线后可另行迁移移除。
  2. **leaderboard 迁移补 `notify pgrst, 'reload schema'`**：该函数是 DROP 后重建，oid 变化，不重载缓存会让 PostgREST 继续引用旧 oid。
