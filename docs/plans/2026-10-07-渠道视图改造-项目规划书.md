# 渠道视图改造 — 项目规划书

**日期：** 2026-10-07
**目标：** 把 AI 配置后台算力池的渠道视角升级为 Cherry Studio 风格的左右分栏管理视图。
**范围：** 只改前端组件与本项目两份计划文档；后端 route、src/lib/ai/、数据库保持不变。

## 一、现状与问题

API 配置页面原本已经通过 PoolViewSwitcher 提供“模型视角”“分组视角”“渠道视角”三种视角。此次工作不重做页面入口，也不把现状描述成单一表格或弹窗页面，而是把渠道视角升级为更直接的左右分栏：

- 左侧选择渠道并查看健康状态。
- 右侧查看当前渠道的脱敏配置和模型卡片。
- 模型卡片提供全局上下架开关和单模型检测。
- 同步模型仍打开原有渠道模型勾选弹窗。

## 二、三种视角的职责

### 模型视角

按 model_id 汇总所有供给渠道，处理模型现役状态、渠道供给和业务路由关系。继续使用现有模型管理逻辑，本次不改其业务职责。

### 分组视角

按渠道标签分组展示渠道实例和已启用模型，继续使用现有分组视角。

### 渠道视角

本次升级的目标。管理员可以选择一个渠道，直接查看：

- 渠道名称、服务商、健康状态。
- 脱敏 API 密钥 api_key_masked（*** 后四位）。
- 服务商 base_url。
- 该渠道关联的模型卡片。
- 渠道检测、同步模型和编辑入口。

## 三、交互设计

### 左右分栏

桌面端左侧约 240px，右侧自适应；移动端上下排列。左侧渠道按 priority 升序排列，当前项高亮。健康指示器复用：

- getProviderKeyHealthStatus
- getProviderKeyModelHealthStatus

状态判定以 src/lib/ai/provider-routing.ts 为唯一来源，文档不写独立失败次数阈值。

### 模型卡片

模型卡片按显示名称排序，响应式采用单列、双列和三列布局。每张卡片包含：

- 模型显示名称和 model_id。
- 健康状态。
- 全局启用开关。
- “检测连接”按钮。

模型开关的显示状态是全局判据：同一 model_id 在任意渠道的 models 记录中只要有一条 is_enabled 为真，就显示为启用。开关调用 set_global_model_shelf_state，因此沿用现有“独占使用中禁止下架”的 409 保护。

### 同步模型

右侧“同步模型”按钮调用单渠道同步，随后打开原有同步弹窗。弹窗勾选保存使用 set_key_model_selection，这个动作只维护当前渠道的模型选择，不承担全局模型上下架。

## 四、真实数据结构

GET /api/admin/ai-config 返回：

    type AiConfigBundle = {
      providers: AiProvider[];
      keys: AiProviderKey[];
      models: AiProviderKeyModel[];
      featureBindings: AiFeatureBinding[];
      featureControls: AiFeatureControl[];
    };

    type AiProviderKey = {
      id: string;
      provider_id: string;
      label: string;
      priority: number;
      is_enabled: boolean;
      api_key_masked?: string;
      unhealthy_until: string | null;
      last_failure_at: string | null;
      last_success_at: string | null;
    };

前端只使用 api_key_masked，不依赖明文密钥字段。

## 五、真实接口表

| 功能 | action | data |
|---|---|---|
| 同步单渠道模型 | sync_key_models | { key_id } |
| 保存单渠道模型选择 | set_key_model_selection | { key_id, model_ids } |
| 全局模型上架/下架 | set_global_model_shelf_state | { modelId, is_enabled } |
| 检测渠道 | test_key | { key_id, model_id?, test_mode? } |
| 检测单个模型 | test_key_model | { key_id, model_id } |
| 检测全部渠道 | test_all_keys | 无 |

配置读取使用 GET /api/admin/ai-config；上述 action 均通过 POST /api/admin/ai-config 调用。

## 七、验收标准

1. 进入 /admin/ai-config 后默认看到渠道视角和左右分栏。
2. 选择渠道，右侧显示脱敏密钥、地址、渠道状态和模型。
3. 模型开关显示全局状态，并通过全局上下架 action 保存。
4. 独占使用中的模型下架被后端 409 拦截，前端显示失败原因。
5. 单模型检测可执行并回写结果。
6. 同步弹窗可打开、勾选并保存当前渠道的模型选择。
7. 模型视角、分组视角和业务功能绑定保持可用。
8. 完成 npm test、TypeScript、lint、build，并使用测试账号完成真实页面验收。
