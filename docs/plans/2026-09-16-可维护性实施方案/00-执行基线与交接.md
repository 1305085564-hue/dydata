# 第 0 批：执行基线与交接

目标：让后续执行者直接按第 1–5 批施工，不再选择架构。完成本批不代表任何功能已改造。

## A. 全套执行约定（各批共同遵守）

1. 顺序为 0→1→2→3→4→5；同一工作区只允许一个写入者。获整套执行授权后，通过本批就更新总进度并继续，不逐批请求批准。仅授权单批时，完成该批即停。
2. 每份方案中的文件、符号、接口、场景就是冻结范围；新增文件已显式标注。行号仅为规划时定位提示，按符号识别。符号已迁移时沿引用查找，不复制第二份实现。
3. 不变更业务/权限口径，不执行 SQL migration，不安装新框架、不改环境密钥、不清理无关代码。新问题记入验收记录“范围外”，不擅自修。
4. 每小步先运行相关旧测试，再修改、补有意义的回归、定向复验。失败只做一次最小修复；同路径再次失败停下，保留现场。不得删除有效断言或放宽安全规则求绿。
5. 每批独立提交，逐个 `git add -- <文件>`；不带入其他任务内容。共用文档只精确暂存本批段落；无法可靠区分则不提交该共用文件并说明。默认不部署中间批次，第 5 批统一发布本专项已验收提交序列。
6. 单元测试、模拟数据库、首屏门禁、真实写入验收分别记录。代码检查通过可以交接下一本地批次；缺生产证据记“本地通过”，整体不得写“完成”。
7. 改 Next.js 入口先读对应 `node_modules/next/dist/docs/` 指南；可见交互拆分读两份设计文档并使用浏览器验收技能，但本专项不改视觉。
