- 签字状态：待权限负责人 + DBA 对本快照与四份 permission-*.txt 对账签字。

[BLK-3 get_daily_quota]
- 线上函数存在，定义与计划书中的历史定义逐字一致（p_date、coalesce 4、SECURITY DEFINER、search_path=public、effective_date<=p_date desc limit 1）。
- 表 daily_quota_config 线上列结构与历史定义一致（6 列）。
- 线上 policy 两条：成员读取 SELECT using(true)、仅管理员写入 ALL using/check is_admin()——注意线上是 ALL 而计划书草案是 INSERT，对账时以线上为准。
- grant：authenticated 仅 SELECT+INSERT（无 UPDATE/DELETE），anon 无 EXECUTE，authenticated/service_role 有 EXECUTE → 与 20260919030217 收紧口径一致。
- 结论：线上对象完整且权限正确；缺口仅是"repo 迁移链无来源"，补正式 migration 时按线上真实定义逐字回放即可，不扩大权限。
- 待办：backend/DBA 写新 migration（仅建 get_daily_quota + daily_quota_config + 上述 policy/grant，勿复活整份 20260707090000）。

[B-16 orphan RPC 候选 14 个]

- ⚠️ 调用热度不可判：生产 track_functions=none，pg_stat_user_functions 无数据；repo 零引用 ≠ 线上零调用（可能有外部直连 REST RPC）。
