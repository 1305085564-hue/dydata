## 1C · 可靠数据读取体系

目标：统一处理查询 error、分页、排序和 1000 行上限，核心查询失败不能静默变空数据。

包含问题：P1-04、P1-05。

优先范围：

- growth
- admin/content
- topics
- remind
- AI 分析
- admin tools
- rewrite
- team join
- 其他在总清单中明确属于核心统计、核心列表或数据安全链路的读取点

执行方式：

1. 先用 `rg` 找核心 Supabase 查询，不要依赖已删除的白名单/测试计划文件。
2. 区分三类读取：
   - 核心业务结果读取：必须显式处理 `error`，不能静默当空数据。
   - 列表/统计读取：必须有稳定排序、分页或明确受控上限。
   - 低频展示读取：可保留局部处理，但不能吞掉影响判断的错误。
3. 只修会造成核心统计错误、列表缺数据或静默失败的路径。
4. 不要把全站所有查询一次性翻新。
5. 改完后运行相关单测/类型检查；有真实页面影响时做定向浏览器验收。

完成标准：

- P1-04：核心查询失败可观察，不能伪装为空数据或成功结果。
- P1-05：高风险列表有分页、稳定排序或明确受控上限，避免 Supabase 1000 行默认上限造成缺数据。
- 在 `1-P0与系统根因.md` 记录实际修改文件、测试结果、未覆盖边界。
