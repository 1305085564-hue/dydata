# 视频复盘列表页：筛选栏「数据高亮」功能方案（v3）

> 演进：v1 误做成列头小图标 → v2 改为筛选栏独立"数据高亮"项（四字段平铺）→ v3 阿禅确认字段要覆盖全部数值列（播放、涨粉、互动率、核心指标、点赞、评论、分享、收藏、2s跳出、5s完播、均播、完播，共 12 项），平铺放不下，改为**规则列表式**交互。

## 一、要解决什么问题

扫列表时想快速锁定符合自己数据标准的作品（如"播放过万""互动率 3.5~6%""跳出率超 60% 的问题稿"），现在只有筛选一条路，但筛选会把其他作品**藏掉**，没法横向对比。

**数据高亮：条件设在筛选栏里，所有作品都还在，命中的数字自己发光。** 配「只看命中行」开关（默认关），需要时一键切换成纯筛选视角——同一条件，两种用法。

## 二、用户怎么用

入口：筛选下拉（现放「播放量档位」「评级」处）新增一项**「数据高亮」**，展开后是规则列表：

1. 下方一行添加区：**选字段（12 项下拉）+ 填「不低于 / 低于」+ 点「添加」**
   - 只填一边 = 单边条件；两边都填 = 区间；单位自动提示（次 / % / 秒）
   - 同一字段重复添加 = 覆盖旧规则（一个字段最多一条）
2. 已设规则显示为小标签（如「播放 ≥1万 ×」「互动率 3.5~6% ×」），点 × 删除
3. 生效表现：
   - 命中单元格淡琥珀底 + 数字加粗（规范：淡底不上实底；琥珀与红/绿/灰状态色区分）
   - 多条规则同时生效，各亮各列，互不干扰
   - 「数据高亮」菜单项右侧显示已设条数，计入筛选按钮角标
4. 勾选「只看命中高亮的行」→ 列表只剩命中作品；取消恢复全量

12 个字段与单位：
| 按"次" | 按"%" | 按"秒" |
|---|---|---|
| 播放、涨粉、点赞、评论、分享、收藏 | 互动率、核心指标、2s跳出、5s完播、完播 | 均播 |

## 三、五条防误判规则

1. 数字为空（无快照显示 `—`）→ 永不点亮、"只看命中"时不出现
2. 脏值（比率越界，复用现有 `isImpossibleRatio`）→ 不点亮，不把问题数据发光成"重点"
3. 区间口径与现有播放档位筛选一致：**含下限、不含上限**
4. 输入非法（非数字、负数）→ 红边提示、不生效（拒绝而非静默截断）
5. 多条规则并存时，"只看命中"的口径 = **同时满足所有规则**（与叠加筛选的直觉一致）

## 四、与现有体系的关系

- **并入现有筛选状态**：规则列表 + 开关作为新字段加进 `ContentListFilterValue`，自动走现成的 URL 读写、`applyFilterPatch`、「重置」一键清除、摘要计数——刷新/后退/分享链接都保持；不做 localStorage（状态真值源统一在 URL）
- **与现有筛选叠加**：先筛选出范围，再在范围内高亮，互不干扰
- **列可见性**：宽松模式隐藏点赞/评论/分享/收藏列；移动端卡片只有播放/涨粉/完播/互动率/点赞 5 项——规则设了但当前模式看不到该列时，无格子可亮属正常，v1 不改列结构与卡片布局（"只看命中"不依赖列可见，任何模式都可用）

## 五、施工边界（一句话）

列表筛选本来就是纯前端执行、12 个字段数值现成可用：**不动数据库、不动接口、不动服务端**，只改列表页前端。

| 步骤 | 位置 | 内容 |
|---|---|---|
| 1 | 新建 `src/lib/content/domain/content-list-highlight.ts` | 真值源：12 字段定义（键名/标签/单位/取数路径）、规则类型、URL 读写（紧凑编码）、命中判断纯函数、高亮色值 |
| 2 | `content-list-filters.ts` | `ContentListFilterValue` 加 `highlightRules` + `highlightOnly`；parse/write URL；摘要追加「高亮 N 条」 |
| 3 | `content-list-state.ts` | 初值从 URL 读、popstate 恢复、并入 `handleResetFilters` / `handleClearSecondaryFilters` / `hasActiveFilters` |
| 4 | `content-list-secondary-filters.tsx` | 新增「数据高亮」子菜单：规则标签列表 + 添加区（字段下拉/双输入/添加钮）+ 只看命中开关（复用现有输入框与 DropdownMenu 模式） |
| 5 | `content-list.ts`（过滤逻辑） | `highlightOnly` 开启时过滤未命中行（多规则取交集） |
| 6 | `content-list-table.tsx` | 桌面 12 列 + 移动卡片 5 项：命中套高亮 class |
| 7 | 新建测试 | URL 读写往返、单边/双边/空值/脏值/非法输入、同字段覆盖、只看命中交集、多规则并行 |

## 六、验收标准

1. 添加「播放 ≥1万」→ 所有播放 ≥1 万的行播放格发光，其余不动
2. 再添加「互动率 3.5~6」与「跳出率 ≥60」→ 三条规则三列独立发光互不影响
3. 同字段再添加新规则 → 覆盖旧规则，标签不重复
4. 点标签 × → 该列高亮立即消失；清空全部 → 无高亮
5. 勾「只看命中行」→ 只剩同时满足全部规则的作品；取消恢复
6. 高亮 + 现有筛选（时间/成员/播放档位/评级）叠加 → 先筛选后高亮，结果正确
7. 刷新、后退、分享链接 → 规则列表与开关状态完整保持
8. 空值、脏值单元格永不高亮；非法输入被拒有提示
9. 「重置」清除全部高亮；菜单项与筛选角标显示条数
10. 宽松模式/移动端：不可见列不报错，可见处正常生效
11. 定向测试全过 + `tsc --noEmit` 退出码 0 + 浏览器完整走查（复杂交互级）

## 七、待阿禅拍板（推荐已标注）

1. **「只看命中」开关**：推荐做（默认关），同一条件两种用法，成本低
2. **同字段唯一规则**：推荐"新规则覆盖旧规则"，不做同字段多条（避免标签爆炸）
3. **区间口径**：含下限不含上限，与现有档位筛选一致
4. **均播单位是秒**：字段下拉里会显示"均播（秒）"，避免和百分比混淆
