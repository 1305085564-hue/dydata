# 渠道视图融合清理方案

**日期：** 2026-10-08  
**目标：** 清理新老架构的冗余,确保产品逻辑顺畅,交互合理  
**原则：** 能看到的地方就应该能直接改,不要有无意义的跳转

---

## 一、当前架构问题诊断

### 问题 1：三个视角并存,但"分组视角"无存在意义

**现状：**
- 顶部有三个视角切换：`模型视角` / `分组视角` / `渠道视角`
- 分组视角的实现逻辑：按 `key.label` 分组（比如多个渠道都叫 "api9" 就归为一组）

**问题：**
- **新架构下只有"渠道"和"模型"两个维度**,不存在"分组"这个概念
- 分组视角的分组规则是按名字匹配,这完全是人为制造的混乱
- 用户的真实需求：
  - 想看某个模型 → 用**模型视角**
  - 想管理渠道配置 → 用**渠道视角**
  - 想按标签分类？→ 这不是核心需求,可以用搜索/筛选实现

**结论：** ❌ **删除"分组视角"**

---

### 问题 2：顶部有"模型"和"渠道"两个按钮,但功能重复

**现状：**
```
[模型视角] [分组视角] [渠道视角]  [同步] [测试] [模型] [渠道] [接入渠道]
                                                   ↑      ↑
                                              这两个按钮
```

**两个按钮的功能：**
- **[模型]** 按钮 → 打开 `ModelManagerDialog` → 显示所有模型,可以启用/禁用/删除
- **[渠道]** 按钮 → 打开 `ProvidersManagerDialog` → 显示所有供应商,可以编辑供应商信息

**问题：**
- 这两个按钮的功能**和左侧的视角切换完全重复**
- 用户要看模型,为什么不直接点"模型视角",而是要点一个弹窗？
- 用户要看渠道,为什么不直接点"渠道视角",而是要点一个弹窗？

**更大的问题：**
- 渠道视角已经是 Cherry Studio 风格（左侧渠道列表 + 右侧详情）
- 但右侧只能看密钥和模型,**不能编辑密钥和 API 地址**
- 这违反了"能看到就应该能改"的原则

**结论：** 
- ❌ **删除顶部的 [模型] 和 [渠道] 按钮**
- ✅ **在渠道视角的右侧,直接支持编辑密钥和 API 地址**

---

### 问题 3：渠道视角右侧信息是只读的,不合理

**现状：**
渠道视角的右侧显示：
```
┌─────────────────────────────────┐
│ gemin                            │
│ API 密钥: ****telu              │
│ API 地址: https://api.xxx/v1    │
└─────────────────────────────────┘

模型列表                    [同步模型]
┌────────────┐ ┌────────────┐
│ Gemini 2.5 │ │ Gemini 3.6 │
│  ✓ 启用    │ │  ✗ 禁用    │
│ [检测]     │ │ [检测]     │
└────────────┘ └────────────┘
```

**问题：**
- 密钥和 API 地址是**只读展示**,不能直接修改
- 如果要改,必须：点顶部 [渠道] → 弹窗 → 找到这个渠道 → 点编辑 → 改完保存
- 这是**典型的心智负担增加**

**正确的做法（参考你的截图）：**
- 密钥旁边有个"编辑"图标,点了直接改
- API 地址旁边也有"编辑"图标,点了直接改
- 改完自动保存,不需要跳转

**结论：** ✅ **右侧的密钥和 API 地址要支持原地编辑**

---

### 问题 4：模型视角和渠道视角的模型管理重复

**现状：**
- **模型视角**：显示所有模型,按模型分组,每个模型下显示所有渠道
- **渠道视角**：显示所有渠道,选中一个渠道后,右侧显示该渠道的模型

**两者的功能重叠：**
| 功能 | 模型视角 | 渠道视角 |
|------|---------|---------|
| 启用/禁用模型 | ✅ | ✅ |
| 检测模型 | ✅ | ✅ |
| 同步模型 | ✅ | ✅ |

**问题：**
- 两个视角都能做同样的事,用户会困惑"我应该用哪个？"
- 这不是"提供灵活性",而是"制造冗余"

**正确的定位：**
- **渠道视角**：管理员规划算力池,关注"我有哪些渠道,每个渠道有哪些模型,优先级如何"
  - 核心操作：添加/删除渠道、同步模型、检测连通性、配置优先级
- **模型视角**：管理员从业务角度看"某个模型在哪些渠道可用,如果主渠道挂了,备用渠道是什么"
  - 核心操作：查看模型的多渠道分布、快速切换优先级、一键禁用某个模型

**结论：** ✅ **保留两个视角,但明确各自的职责边界**

## 二、清理方案

### 清理项 1：删除"分组视角"

**要删除的代码：**
1. `src/app/(app)/admin/ai-config/components/channel-pool-view.tsx`
   - 删除 `GroupPoolView` 组件
   - 删除 `PoolViewSwitcher` 中的"分组视角"按钮

2. `src/app/(app)/admin/ai-config/components/compute-pool-panel.tsx`
   - 删除 `viewMode === "group"` 的分支
   - 将 `viewMode` 类型从 `"group" | "model" | "channel"` 改为 `"model" | "channel"`

**预计删除代码量：** ~150 行

---

### 清理项 2：删除顶部的 [模型] 和 [渠道] 按钮

**要删除的代码：**
1. `src/app/(app)/admin/ai-config/components/compute-pool-panel.tsx`
   - 删除工具栏中的这两个按钮：
     ```tsx
     <Button onClick={() => setModelManagerOpen(true)}>
       <Boxes /> 模型
     </Button>
     <Button onClick={() => setProvidersManagerOpen(true)}>
       <Server /> 渠道
     </Button>
     ```
   - 删除对应的 state 和弹窗组件

**要删除的组件和弹窗：**
- `ModelManagerDialog` — 模型集中管理弹窗（可能还有其他地方在用,先确认）
- `ProvidersManagerDialog` — 供应商管理弹窗

**替代方案：**
- 想看模型 → 切换到"模型视角"
- 想看供应商 → 切换到"渠道视角"（供应商信息在渠道详情里显示）

**预计删除代码量：** ~300 行（包括弹窗组件）

### 清理项 3：渠道视角右侧支持原地编辑

**要新增的功能：**

#### 3.1 密钥原地编辑

**现在：**
```tsx
<div>
  <span>API 密钥: </span>
  <code>{key.slice(0, 8)}****{key.slice(-4)}</code>
</div>
```

**改成：**
```tsx
<div className="flex items-center gap-2">
  <span>API 密钥: </span>
  {isEditingKey ? (
    <input
      value={editingKeyValue}
      onChange={(e) => setEditingKeyValue(e.target.value)}
      onBlur={handleSaveKey}
      className="..."
    />
  ) : (
    <code>{key.slice(0, 8)}****{key.slice(-4)}</code>
  )}
  <button onClick={() => setIsEditingKey(true)}>
    <Pencil className="size-3" />
  </button>
</div>
```

#### 3.2 API 地址原地编辑

同理,支持点击编辑图标 → 变成输入框 → 失焦自动保存。

#### 3.3 后端接口复用

直接调用现有的 `/api/admin/ai-config` 接口：
```typescript
await fetch('/api/admin/ai-config', {
  method: 'POST',
  body: JSON.stringify({
    action: 'update_key',
    data: { id: keyId, api_key: newKey }
  })
})
```

**预计新增代码量：** ~100 行

### 清理项 4：明确两个视角的职责边界

**改进点：**

#### 4.1 渠道视角：聚焦算力池管理

**保留的功能：**
- ✅ 左侧渠道列表（状态指示器）
- ✅ 右侧显示密钥、API 地址（**支持原地编辑**）
- ✅ 右侧模型列表（启用/禁用、检测）
- ✅ 同步模型按钮
- ✅ 添加渠道按钮

- ❌ 不显示模型的跨渠道分布（那是模型视角的事）

#### 4.2 模型视角：聚焦业务可用性

**保留的功能：**
- ✅ 显示所有已启用的模型
- ✅ 每个模型下显示所有渠道（按优先级排序）
- ✅ 支持拖拽调整渠道优先级
- ✅ 一键禁用某个模型（跨所有渠道）

**新增的功能：**
- ✅ 显示"该模型在几个渠道可用"的统计
- ✅ 高亮显示"无可用渠道"的模型

## 五、风险点

### 风险 1：删除 ModelManagerDialog 可能影响其他功能

**检查方法：**
```bash
grep -r "ModelManagerDialog\|setModelManagerOpen" src/app --include="*.tsx"
```

如果有其他地方在用,暂时保留,但改名为 `ModelQuickActionsDialog`,定位为"快捷操作面板",而不是"主要入口"。

### 风险 2：原地编辑可能和现有的编辑弹窗冲突

**解决方案：**
- 删除 `KeyDialog`（编辑密钥弹窗）
- 保留 `AddKeyDialog`（新增密钥弹窗）
