## 一、接口契约（由后端提供，前端按此对接，不得自行假设）

本次后端会交付三个接口的新结构，前端一律按此消费：

| 接口 | 变更 | 前端拿到什么 |
|---|---|---|
| `sync_key_models` | 返回改为全量 | `syncResult.allModels[]`：`modelId` / `displayName` / `isEnabled` / `isGlobalActive` / `isNewlyDiscovered` |
| `test_key_all_models` | 范围扩到含未勾选 | `results[]` + `total` / `successCount` / `failureCount` / `failedModelIds` |
| `test_all_keys_all_models` | 同上 | `totalKeys` / `totalModels` / `successCount` / `failureCount` / `failures[]` |

**禁止**：继续使用 `syncResult.models`（旧增量结构）。后端会同时保留 `newCount` 仅供日志，前端不得用它做展示。

## 二、视角结构（任务 3）

### 2.1 三个视角，两个药丸对等

| 位置 | 药丸文案（固定，不得改） | 分组方式 |
|---|---|---|
| 页面上半部 | 业务功能调度 | 按业务功能分组 |
| 下半部 · 药丸一 | **模型视角** | 按模型分组：每个模型下展开看它的所有渠道 |
| 下半部 · 药丸二 | **渠道视角** | 按渠道分组：每个渠道下展开看它的所有模型 |

**硬规则**：模型视角与渠道视角是同一份供给侧数据的两种分组方式，**地位完全对等、互不从属**。不是主从，不是二合一，也不是只保留一个。任一视角都要能完成全部管理动作。

### 2.2 具体改动

- `pool-view-switcher.tsx:26`：「供给管理」→「模型视角」。
- 「渠道视角」文案保持不变（`pool-view-switcher.tsx:41`）。
- 视角选择写入 URL query（`?view=model|channel`），刷新不丢、可分享链接。
- 回归确认：下半部两个视角内**不得出现任何业务功能调度内容**（业务表只在上半部）。

## 三、同步模型弹窗（任务 1 前端）

### 3.1 列表四类分区（数据源 `allModels`）

| 分类 | 判定 | 默认勾选 | 标识文案 |
|---|---|---|---|
| 现役 | `isGlobalActive` 为真 | ✅ | 现役 |
| 本渠道启用 | `isEnabled` 为真但非全站现役 | ✅ | 本渠道启用 |
| 储备中 | 已入库、未勾选、非新增 | ❌ | 储备中 |
| 新增 | `isNewlyDiscovered` 为真 | ❌ | 新增 |

- 保留现有搜索、按住划选、批量全选能力。
- 保存调 `set_key_model_selection`（只影响本渠道）。

### 3.2 计数与空态必须用存量口径

- 顶部计数：**「已勾选 X / 共 Y 个」**，Y = `allModels.length`。
- **禁止出现**「已从渠道获取 N 个可用型号」这类增量文案。
- 空态三态，禁止混用：
  - **拉取中**：显示进度提示。
  - **拉取失败**：显示失败原因 + 「重试」按钮。**禁止显示成「还没有可启用的型号」。**
  - **真的 0 个**：才显示「此渠道尚未返回任何模型」。

### 3.3 弹窗内新增检测入口

弹窗底部提供 **「检测此渠道全部模型」**，调 `test_key_all_models`，结果显示「测了几个 / 通过几个 / 失败几个」，失败项可展开看原因。

### 3.4 标题

弹窗标题「`api9 · api9 gemin`」→「`api9 gemin`」，**去掉供应商名**。

## 七、使用流验收（本轮起按此验收，不看功能清单）

**验收 = 阿禅能独立走完这 5 条，中途不需要问任何人。** 施工方必须自己先走通再交。

1. **接入一条新线**：点「接入渠道」→ 下拉显示名字且能就地新增接入点 → 填显示名（可用快捷词）→ 填 Key → 下一步看到该渠道全部模型并勾选 → 确认后新渠道出现，且**其他渠道的同名模型没有被点亮**。
2. **复看已接入的线**：点「同步模型」→ 看到**全部**模型（不是 0 个）→ 能分辨现役 / 本渠道启用 / 储备中 / 新增 → 取消勾选某个 → 保存后模型列表里消失。
3. **测一条线**：在同步弹窗点「检测此渠道全部模型」→ 明确看到测了几个、通几个、不通几个、哪个不通。
4. **换模型**：在模型视角看到某模型 `0/N 渠道可用` → 展开看清谁故障、谁待命中 → 能判断该换哪个模型。
5. **巡检**：点工具栏按钮 → 不看 tooltip 也知道它测的是「每渠道一条」还是「全部模型」。

**走不通任意一条即验收不通过。**
