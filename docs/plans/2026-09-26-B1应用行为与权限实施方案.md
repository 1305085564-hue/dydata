## B1-1 OCR 恢复识别值

### 目标与现状

截图 OCR 成功后，用户编辑指标再触发重新识别时，现有状态需要保留每个字段的 OCR 原始值，并与手工编辑、置信度、槽位确认及日报提交状态一致。当前已存在 OCR 响应 `confidence`、字段编辑模型、草稿、`data_source`（`ai/manual/null`）和低置信度确认状态；不得另造第二套来源规则。

### 先核实

- `src/app/(app)/dashboard/video-submit-form-v2.tsx`
- `src/app/(app)/dashboard/video-submit-form-state.ts` 及对应测试
- `src/app/(app)/dashboard/video-submit-form-model.ts` 及对应测试
- `src/lib/dashboard-logic/use-ocr-upload.ts`
- `src/app/api/ocr-screenshot/ocr-contract.ts` 与 route tests
- `src/lib/video-submit-draft.ts`、草稿测试
- `src/lib/daily-report-data-source.ts` 与 `supabase/migrations/20260907100000_daily_report_data_source.sql`
- `docs/reference/截图上传维护手册.md`

### 方案约束

- 原始值必须按字段保存，至少覆盖播放、点赞、评论、分享、收藏、涨粉和已支持的留存指标；以实际表单字段为准，不臆造字段。
- OCR 新结果替换该字段的 OCR 原值；用户手工编辑后，当前显示值不得被恢复动作覆盖，手工来源标记沿用现有 `manual` 规则。
- “恢复识别值”只恢复字段原值，不重跑 OCR、不发请求、不改变截图资产。
- 草稿保存/恢复后，字段当前值、OCR 原值、confidence 和来源状态彼此一致；旧草稿无新字段时按“未知/无原始值”兼容，不推断历史 OCR 值。
- 提交仍写当前显示值。原始 OCR 值不得写入现有业务指标列；如确需数据库持久化，先提交 schema/隐私/保留期设计并停止等待审批，不在本子项自行新增 migration。
- 不改 OCR 服务商、模型路由、识别 prompt、截图上传接口和错误降级行为。

### 施工步骤与验收

1. 画出状态转换：OCR 初识别、二次识别、手工覆盖、恢复原值、保存草稿、恢复草稿、提交。
2. 先实现纯状态转换 helper 或扩展既有状态函数，不在组件里增加散落的 setState 副作用。
3. 补状态测试：字段级原值恢复；只恢复未被手改字段；二次 OCR 刷新原值；旧草稿兼容；提交 payload 使用当前值；识别失败不擦除既有有效值。
4. 仅在现有 UI 可清楚承载时接入恢复操作；不得增加新页面或视觉重构。
5. 验收命令按实际修改文件列出，不得用源码字符串断言替代状态行为测试：

```bash
npx tsx --test "src/app/(app)/dashboard/video-submit-form-state.test.ts" "src/app/(app)/dashboard/video-submit-form-model.test.ts" src/lib/dashboard-logic/use-ocr-upload.test.ts
npx tsc --noEmit --pretty false
git diff --check
```

缺少其中某个测试文件时，先以 `rg --files` 查实际入口并更新定向命令，不得静默删去验证。

### 停止条件

- 需要改数据库才能满足“跨会话恢复”，但原始值保留期限、可见角色或隐私边界未定。
- 现有手工/OCR 来源状态的含义与需求冲突。
- 无法保证手改值不会被恢复动作覆盖。
- 同一路径连续两次定向验证失败。

## B1-2 岗位管理组员只读查看视频复盘

### 目标与硬边界

岗位管理组员可点击作品并打开视频复盘抽屉，仅查看，不获得视频复盘页面入口或任何写操作。待办已明确：不得复用 `review_content`，否则可能激活入库/移出选题库等操作。候选权限键 `view_video_review` 必须先查全链路影响再定名。

### 先核实

- `docs/plans/2026-09-22-岗位管理对组员放开本公司范围-实施方案.md` 第 4.5、8 节及 D-6
- `docs/权限与安全说明.md` 的角色权限矩阵、接口权限和范围规则
- `src/lib/permission-contract.ts`、`src/lib/route-permissions.ts`、权限解析与对应 tests
- `src/app/(app)/admin/collaboration/collaboration-workbench.tsx`
- `src/app/api/admin/collaboration/work-video/route-core.ts` 与 tests
- `/admin/content` 页面、`content-detail-dialog.tsx`、内容写操作入口与 tests
- `docs/全站模块地图.md` 对岗位管理和视频复盘的描述

### 施工步骤

1. 列完整受影响文件和权限矩阵：member/admin/company_owner/group mode；梳理 `review_content` 每个消费点，证明新键不会被它替代或合并。
2. 新增独立只读权限能力（名称由当前项目规则确认；推荐 `view_video_review`），仅授予应能在岗位管理看作品的 member。
3. 在 `work-video` 接口按该权限开放读取，并继续执行公司范围和视频归属校验；不得因请求参数扩大范围。
4. 抽屉只渲染查看能力；隐藏或禁用入库、移出选题库、异常处理、回收站、归属编辑等所有写控件。服务端每个写接口继续拒绝 member。
5. `/admin/content` 路由本身仍不可由 member 进入；只开放岗位管理内触发的授权只读抽屉。
6. 把原 403 提示改成用户能理解的结果：权限未开放时说明“当前账号不能查看此作品复盘”，不能显示通用页面故障。
7. 更新权限文档、模块地图及定向 tests。

### 验收

- 单测：permission contract、route permissions、`work-video/route.test.ts`、所有受影响写入口权限测试。
- 静态：`npx tsc --noEmit --pretty false`、`git diff --check`、确认 `review_content` 的原有授权语义未改变。
- 真实角色浏览器：
  - member 在岗位管理点本公司作品可打开抽屉并查看；跨公司/不可见作品仍拒绝。
  - member 看不到或不能触发入库、移出选题库、回收站、异常处理、补归属等写操作；直接请求写接口仍 403。
  - member 直接访问 `/admin/content` 仍被拒绝。
  - admin、company_owner、group mode 行为不回归。
- 只跑受影响的 Playwright 场景；如没有适用测试，新增独立定向测试，不扩大现有全站浏览器门禁。

### 停止条件

- 权限键会间接授予 `review_content` 能力或页面路由访问。
- 任一写入口依赖该新键且无法保持 member 403。
- 公司范围校验只能通过放大全局 `DataAccessScope` 实现。
- 缺少真实 member 测试环境或跨公司拒绝证据。

## B1-3 异常处罚类型废弃项清理

### 目标与边界

业务已确认现役选项仅为“限流”“删稿”。全仓清除“投流”“活动干预”的死引用，但历史数据必须保真，不把历史值偷偷改写成新类型。

### 施工步骤

1. 盘点 `src/`、`supabase/`、测试和当前文档，逐条分类：现役写入口、读/展示兼容、数据库约束/类型、历史 migration、测试夹具、纯历史文档。
2. 删除现役选择器、类型联合、校验/归一化中的废弃选项；保留对历史行的安全读取（若存在），显示可理解的历史兼容文案，不允许重新提交废弃值。
3. 数据库约束如仍允许旧值，只能新增前向 migration；先检查线上分布和写入方。不得改写历史记录，除非另有明确授权和逐行决策。
4. 测试覆盖：当前选项集合只有两个现役类型；历史旧值读取不会崩溃/不会自动转换；新写请求拒绝废弃值。
5. 当前事实文档只改本任务命中的入口；归档历史文档不批量改写。

### 验收

```bash
npx tsx --test src/lib/video-anomaly.test.ts src/app/api/video-submit/validation.test.ts
npx tsc --noEmit --pretty false
git diff --check
```

执行前检查测试文件实际存在；按新增/受影响入口补充定向测试。最终 `rg -n '投流|活动干预' src supabase` 的命中必须逐条解释：历史兼容读路径可保留并注明，不得只为了 grep 零命中破坏旧数据读取。

### 停止条件

- 发现生产约束拒绝历史值且改 schema 会影响线上数据。
- 发现当前数据包含旧类型并需要清理/迁移。
- 旧类型出现于当前接口契约但调用方不明。
