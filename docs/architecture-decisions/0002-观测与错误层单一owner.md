# 决策 0002：观测与错误层不建平行层

**背景**：A、B 两份方案曾分别列出错误、观测和请求上下文能力，重复建设会产生两套结果语义。
**决定**：扩建现役 `observed-mutation`、Sentry 脱敏与日志能力；不建平行层，唯一 owner 是 A 方案 Phase 1。B 和审批专项复用它。
**后果**：错误、requestId、结构化观测和性能指标只有一套入口；审批的分层结果必须落在现役 outcome/stage 之上。
