## 已确认口径与范围

- 入口：管理中心 → 数据口径 → 评价标准；公司统一，负责人可修改，普通管理员只读。此前筛选栏入口已被否决，不再使用。
- 前端遵循现行设计一页纸与规范：页签、裸铺分区、三列表单；不增加卡片嵌套。每项数字前直接显示 ≤ / ≥ / >，区分好红、差绿、中间普通。
- 可填六项表现界限：2 秒跳出、5 秒完播、均播时长、整体完播、核心指标达成率、互动率达成率；另可填复盘点赞/干货收藏/互动/转粉达标基准及颜色判断最低播放量。
- 默认值沿用已确认标准：25/35、60/50、40/20 秒、10/5、100/60；播放门槛 3000；基准 2%/2%/3.5%/1%。2 秒跳出严格 > 差线才为差。
- 参与着色的播放门槛与综合评级、异常提醒的播放门槛分别维护；本轮没有改动后两者的判定数字，也没有改变原始视频数据或计算公式。

## 实现边界

- `evaluation-standards.ts` 提供类型、严格校验和默认值；`evaluation-standards-store.ts` 使用服务端 `system_settings` 保存，键为可信权限上下文的 `evaluation_standards:{teamId}`。公司范围不由浏览器提交。
- 公司无配置记录才使用默认值；无公司归属的个人业务沿用默认规则而不读其他公司，设置接口仍拒绝其访问。查询失败或保存记录损坏明确报错。保存带版本校验、条件更新；旧页面不得覆盖新版本。记录包含上一版完整标准与更新时间，当前记录保留操作者。
- GET `/api/admin/evaluation-standards`：普通管理员与负责人可读；PUT：同时要求负责人身份及系统管理能力。成员、缺公司归属、未知字段、无效/重叠标准、跨站请求均拒绝。
- 当前标准注入复盘列表/详情、协作质量统计/个人卡、选题作品、评级说明；个人卡缓存键包含标准，协作原始数据缓存之外重算。
- 列表 SQL 原先硬编码基准；配套迁移 `20261028045959_evaluation_standard_rating_targets.sql` 保持函数签名和 service_role 权限不变，只将达标基准改为服务端传入，未传仍用原默认值。
- 未完成该迁移时，保存自定义达标基准会明确拒绝；消费端同样检查版本，避免“显示与筛选使用不同标准”。其他表现颜色设置不依赖该 SQL 升级。
- 截图授权只核对作品证据，不依赖评价标准配置；本轮新增读取依赖的回归已移除。
