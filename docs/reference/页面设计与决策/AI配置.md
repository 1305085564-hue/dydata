## 历史决策

<a id="第1条"></a>

### 1 页面上只有一个心智：业务选模型，模型里排渠道

**分类**：业务　**状态**：有效　**日期**：2026-11-05　**拍板人**：阿禅（8 条口径）
**背景**：少一个看不见的设置；想调顺序只有一个地方。
**决定**：业务只选模型，删掉「钉渠道」；只剩一种顺序，就是模型卡里渠道的排队顺序，删掉渠道优先级数字；渠道状态只说三句人话：「能用」「暂时歇着（系统会自己再试）」「需要你处理（附原因）」，自己关掉的显示灰色。顶班时写「X 暂时不可用，当前优先使用默认 Y」。
**后果**：停摆提醒只做页面标红和顶部摘要，不做站内通知和飞书推送（CC 裁定，以后要再加）。
**证据**：[AI 配置页口径重整总方案](../../plans/2026-11-05-AI配置页口径重整与链路精简-总方案.md)。

<a id="第2条"></a>

### 2 配置页是用来「找」的，不是用来「读」的

**分类**：设计　**状态**：有效　**日期**：2026-11-05　**拍板人**：阿禅
**背景**：开关和状态标签要是藏起来，就看不出哪条渠道关着。
**决定**：高密度排布；停用的模型默认收起，但「为此模型找渠道」、开关、状态标签和改名铅笔始终显示。模型卡按「有业务在用 → 能用 → 暂时不可用 → 已停用」排，各列表能用的在上；进页面、切视角、打开弹窗时排一次，操作中不跳行；渠道排队顺序不动。
**证据**：[AI 配置页高密度改版任务书](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-11-05-AI配置页高密度改版-Antigravity任务书.md)；[11-05 日志](../../archive/日志/2026-11/2026-11-05.md)。

### 3 模型视角和渠道视角地位对等

**分类**：设计　**状态**：有效，取代 10-09 早先「渠道只是模型下面一层明细」（已明确作废）　**日期**：2026-10-09　**拍板人**：待核（文件写「决策方：阿禅」，这条没见逐句原话）
**背景**：原文没写理由。
**决定**：模型视角和渠道视角是同一份数据的两种分组，随时切换，任一视角都能完成全部管理动作。
**证据**：[AI 算力储备三视角纠偏返工执行规格](../../archive/2026-11-09-A批文档治理/计划原稿/2026-11-09-计划收尾/2026-10-09-AI算力储备三视角纠偏返工-执行规格.md)。

### 5 收走已确认失效的模型不再二次确认，其余危险动作要列名单

**分类**：业务　**状态**：有效　**日期**：2026-10-10　**拍板人**：阿禅（点头）；「列名单、取不到就拒绝」是同批冻结裁决，没写阿禅
**背景**：名单已经显示在同一面板上，后端有依赖检查兜底，审计写失败会自动回滚。
**决定**：同步弹窗里，单条收走和「一键收走全部已确认失效模型」不再弹确认；只限「清单里没有 + 实测不通」两个信号同时成立的模型，「疑似」的不给收走入口。停用或删除接入点、全站下架、跨渠道批量启用仍要确认，确认时必须逐条列出被牵连对象的真实名称，取不到完整名单就拒绝执行。
**证据**：[AI 算力储备概念补全与危险动作治理执行规格 v2](../../archive/2026-11-09-A批文档治理/计划原稿/2026-11-09-计划收尾/2026-10-09-AI算力储备概念补全与危险动作治理-执行规格v2.md)。
