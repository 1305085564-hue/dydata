## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。全站通用的角色和数据范围见[权限链路](../链路设计与决策/权限链路.md#现行设计)。最后对过代码：2026-10-31。

<a id="现行-权限"></a>

### 一、谁能看（按权限链路的六件事登记）

成员主页是只读的成长档案页，是数据管理个人档案抽屉「可分享、可独立打开」的版本。

| 维度 | 规则 |
|---|---|
| 身份 | 必须已登录，未登录跳登录页 |
| 功能 | 不新增权限键，沿用「只读查看本公司数据」的既有范围，不依赖任何写权限 |
| 范围 | `visibleUserIds` 包含目标成员才能看；不在范围内一律显示「无权查看」，不返回任何数据 |
| 当前与历史 | 访问者本人必须在职（归档账号拒绝，和 `/topics` 一样由页面自查）；被查看的成员可以是归档的，历史档案保留可查 |
| 对象归属 | 目标 `userId` 来自网址，由服务端按 `visibleUserIds` 核对，不相信浏览器传参 |
| 入口安全 | 页面是 Server Component，不在 `src/middleware.ts` 的匹配范围内（同 `/topics`），鉴权全靠页面自查：`getCurrentUserContext` 取会话 → 本人在职门禁 → `getCurrentPermissionContext` → `resolveCollaborationScope` 求 `visibleUserIds` → 命中才读数。伪造他人 `userId` 的链接取不到数据 |
| 数据库 | 读数走 `createAdminClient()`（与数据管理只读模块同源），因为登录身份受「只能看自己」的行级权限限制、跨成员读不到；安全性压在上面的 `visibleUserIds` 校验上 |

- 数据管理个人档案抽屉的取数接口 `/api/admin/collaboration/person` 用同一套 `resolveCollaborationScope` + `visibleUserIds` 门禁，两边口径必须一致。

### 二、入口、代码与验证

- 入口：`/people/[userId]` → `src/lib/collaboration/data/person-profile-loader.ts`；规则在 `src/lib/collaboration/domain/person-profile-rules.ts`，可见范围与数据管理同源。
- 必须保持：访问者已登录且在职；目标先过可见集合校验再读数；可见的归档成员历史保留；service role 不代替鉴权。

## 历史决策

<a id="第1条"></a>

### 1 谁能看谁的主页，主页只读

**分类**：业务　**状态**：有效；「组员只能看自己」（方案写法）和「看得到可见范围内的人」（权限文档写法）两处说法不一致，组员实际能看谁未核　**日期**：2026-10-17　**拍板人**：待核（阿禅要求登记权限，规则由 CC 按既有范围写入，未见逐条确认）
**背景**：沿用「只读查看本公司数据」的既有范围，不新增权限。
**决定**：只能看自己可见范围内的成员，越权一律显示「无权查看」、不返回任何数据；看的人自己必须在职，被看的人归档后历史档案仍可查。主页纯只读，不放任何写操作。
**后果**：读数用服务端管理通道（登录身份受「只能看自己」限制，跨成员读不到），安全全靠页面门禁，改门禁要同步看[权限链路](../链路设计与决策/权限链路.md)。
**证据**：[本文件·谁能看](#现行-权限)；[成员主页方案](../../plans/2026-10-17-成员主页方案.md)；[10-17 日志](../../../日志/2026-10-17.md)。

<a id="第2条"></a>

### 2 主页不放「近 30 天作品质量」

**分类**：设计　**状态**：有效　**日期**：2026-10-17　**拍板人**：阿禅
**背景**：和数据管理档案抽屉里的折线图重复。
**决定**：删掉主页「最近状态」里的「近 30 天作品质量」整块，只留「异常作品」。
**证据**：[10-17 日志（17:10 条）](../../../日志/2026-10-17.md)。

<a id="第3条"></a>

### 3 主页不再有「擅长什么 · 按题材」

**分类**：业务　**状态**：有效　**日期**：2026-11-12　**拍板人**：随日报 AI 视频标签整体下线（见核对文件）
**背景**：题材来自日报的 AI 视频标签，这套标签整体下线了。
**决定**：主页的「擅长什么 · 按题材」区块和对应取数一并下线。
**证据**：[日报 AI 视频标签下线与数据清理](../2026-11-12-日报AI视频标签下线与数据清理.md)。

<a id="第4条"></a>

### 4 不复活六维能力雷达图和加权互动率

**分类**：业务　**状态**：有效　**日期**：2026-10-17　**拍板人**：阿禅（拍板做主页时一并定）
**背景**：这两个口径早已废弃。
**决定**：主页不再出现六维能力雷达图和加权互动率。
**证据**：[成员主页方案](../../plans/2026-10-17-成员主页方案.md)；[10-17 日志（10:35 条）](../../../日志/2026-10-17.md)。

<a id="第5条"></a>

### 5 档案抽屉的开合以地址栏为准，浏览器后退就是关抽屉

**分类**：设计　**状态**：有效，取代同日早先「后退键不关抽屉」　**日期**：2026-10-17　**拍板人**：CC（阿禅要求处理地址栏与抽屉不一致）
**背景**：地址栏和抽屉状态对不上；在人名上原地展开档案，用户心里「后退」就是收起来。
**决定**：打开档案时压一个浏览记录，后退即关抽屉；数据管理的小队详情用同一做法。
**证据**：[10-17 日志（17:10 条）](../../../日志/2026-10-17.md)。
