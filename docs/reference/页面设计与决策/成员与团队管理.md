## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。最后对过代码：2026-11-18。

<a id="现行-生命周期"></a>

### 一、成员生命周期

| 动作 | 怎么走 |
|---|---|
| 入职 | 添加成员 → 账号状态为在职（`active`）→ 关联团队 → 可选分配工作组 |
| 归档 | 状态改为归档（`archived`），先封禁登录；团队写入归档快照。历史数据保留（`visibleUserIds`），各种候选名单排除（`activeVisibleUserIds`） |
| 恢复 | 状态改回在职，角色恢复为普通组员、权限清空，归档快照删除；团队按归档快照带回（`buildRestoreMemberProfilePatch`），原团队管理员在成员列表里能看到他。归档前的团队已被删除时不分配团队，恢复后弹出明确提示，由管理员重新分配 |

<a id="现行-入团"></a>

### 二、入团申请的驳回原因

- 管理员驳回入团申请时可以填原因（选填，最多 200 字，写入 `team_join_requests.review_note`）；同意时不写固定备注。
- 申请人的横幅读取最近一次已处理的申请：被驳回显示「入团申请未通过」和「未通过：原因」，并可重新申请；之后通过就已有团队，横幅不再出现。

## 历史决策

<a id="第1条"></a>

### 1 组长只管本团队的成员

**分类**：业务　**状态**：有效，取代 09-13「组长是管理层、管全公司」　**日期**：2026-09-16　**拍板人**：阿禅
**背景**：原文只写「阿禅确认此口径」。
**决定**：组长只能看到、管理自己团队里的在职成员；不能管理组长、负责人和自己，不能把组员升为组长。
**后果**：[权限链路](../链路设计与决策/权限链路.md)里还有一处写「管理角色 = 当前公司」，与本条不一致，待核。权限申请发给谁见[审批链路](../链路设计与决策/审批链路.md)，「不参与考核」谁能设也在审批链路。
**证据**：[权限架构改造施工方案](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-09-15-权限架构改造施工方案-激进版.md)；[09-16 日志](../../../日志/2026-09-16.md)。

<a id="第2条"></a>

### 2 恢复成员时带回原团队，角色是组员

**分类**：业务　**状态**：有效，取代 08-04「恢复后不自动回原团队」　**日期**：2026-11-18　**拍板人**：阿禅
**背景**：原文没写理由。08-04 不自动恢复，是怕恢复后意外拿回旧的管理员权限。
**决定**：恢复归档成员时，原团队还在就带回原团队，不在就置空并提示；角色一律是组员，功能权限清空。
**证据**：[11-18 拍板清单 D6](../../archive/2026-11-18-计划归档/计划原稿/2026-11-18-业务逻辑治理-审计结论与拍板清单.md)。

<a id="第3条"></a>

### 3 拒绝入团要写真实原因，并告诉申请人

**分类**：业务　**状态**：有效（原文写「可填原因」，是否必填没写）　**日期**：2026-11-18　**拍板人**：阿禅
**背景**：原来拒绝原因是写死的一句「通过管理工作台一键审批」。
**决定**：拒绝时可以填原因；被拒的人在横幅上看到「未通过：原因」。
**证据**：[11-18 拍板清单 D11](../../archive/2026-11-18-计划归档/计划原稿/2026-11-18-业务逻辑治理-审计结论与拍板清单.md)；[业务逻辑治理上线核对](../../archive/2026-11-20-参考归档/参考原稿/2026-11-18-业务逻辑治理上线核对.md)。

<a id="第4条"></a>

### 4 调整角色要二次确认

**分类**：业务　**状态**：有效　**日期**：2026-09-13　**拍板人**：阿禅
**背景**：降为组员会悄悄清空这个人的功能权限，归档有确认、调角色却没有。
**决定**：切换角色前弹一个简单确认，不做完整的影响范围页。
**证据**：[成员管理页面 UX 修复施工方案](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/成员管理页面UX修复施工方案-2026-09-13.md)。

<a id="第5条"></a>

### 5 数据范围由角色决定，不能手动设

**分类**：业务　**状态**：有效　**日期**：2026-09-13　**拍板人**：阿禅（选方案 A）
**背景**：原来页面上有个能点的「数据范围」，其实改不了任何东西；真去改权限核心风险太高。
**决定**：数据范围只读展示，跟着角色走：组员看自己，管理角色按所属范围。
**证据**：[成员管理页面 UX 修复施工方案](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/成员管理页面UX修复施工方案-2026-09-13.md)。

<a id="第6条"></a>

### 6 归档不删账号，必须填原因

**分类**：业务　**状态**：有效（现行做法）　**日期**：2026-08-04　**拍板人**：待核
**背景**：归档在业务上等于「删除使用资格」，但账号和数据关联必须保留。
**决定**：不提供物理删除账号；归档要高风险确认并必填原因；归档后只保留历史记录供有权的人查。
**证据**：[成员生命周期管理方案](../../archive/2026-08-22-文档瘦身/plans/成员生命周期/2026-08-04-成员生命周期管理方案.md)。
