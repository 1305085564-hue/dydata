# 新增接口操作步骤

> 适用范围：`src/app/api/**/route.ts`。每一步均对应现役代码与门禁，参考样板见 `src/app/api/admin/videos/[videoId]/patch-24h/route.ts`（写接口）与 `src/app/api/admin/content/list/route.ts`（读接口）。

1. **建路由与运行声明**
   - 在 `src/app/api/<领域>/route.ts` 建路由，写接口或依赖 Node 能力时声明 `export const runtime = "nodejs"` 与 `export const dynamic = "force-dynamic"`。
   - 把核心处理抽成可注入依赖的纯函数 `buildXxxResponse(request, deps)`；现役样板的真实函数名是 `buildPatch24hResponse`（写）和 `buildAdminContentListResponse`（读）。路由出口 `GET`/`POST` 只做观测包裹与参数转发，方便无库单测。
   - 严守分层：`src/lib` 不得反向引用 `src/app`（`eslint.config.mjs` 拦截）。

2. **接统一鉴权并收窄范围（不得丢弃返回值）**
   - 管理端：调 `requireAdminContext({ requiredPermission })` 或 `requireAdminActor({ requiredPermission })`（`src/lib/admin-auth.ts`，兼容入口 `src/app/api/admin/auth-helper.ts`）；若无参调用必须再做 `canAccessAdminPath` / 能力或范围收窄，且必须检查 `"error" in auth`。
   - 员工端：调 `getCurrentUserContext()`（`src/lib/current-user-context.ts`）或 `resolvePermissionCore()`（`src/lib/current-permission-context.ts`），查询条件绑定本人或范围 ID。
   - 定时任务：调 `isCronAuthorized(request)`（`src/lib/cron-auth.ts`）。
   - 有意公开的接口必须登记进 `src/app/api/route-auth.coverage.test.ts` 的 `PUBLIC_ROUTES` 并写明保护方式；鉴权在委托文件里的登记到 `DELEGATES`。

3. **参数校验（新代码统一用 `zod`）**
   - 仓库已内置 `zod`（见 `package.json`），新接口参考 `src/app/api/admin/videos/[videoId]/patch-24h/route.ts`，统一用 `z.object(...).safeParse(rawBody)` 校验请求体和查询参数（存量老接口仍有多处手写校验，不要照抄）。
   - 路径或参数中的 UUID 复用 `UUID_PATTERN`（`src/lib/api-path-validation.ts`）；JSON 解析失败或 `safeParse` 失败一律在查库前返回 `400`。

4. **带 `requestId` 观测与脱敏日志**
   - 写接口：外层包 `observeMutation("/api/...", handler, { createRequestId: () => resolveObservedMutationRequestId(request) })` 与 `appendObservedMutationResult(response, observation)`（`src/lib/observed-mutation.ts`、`src/lib/observed-mutation-result.ts`），或直接用 `observeMutationRequest`；关键阶段调 `observation.mark("auth" | "validate" | "scope" | "read" | ...)`。
   - 读接口：外层用 `createRequestContext({ request, route, operation })`（`src/lib/request-context.ts`）+ `observeRequest(context, handler)`（`src/lib/observability.ts`）。
   - 两者均自动写入 `x-dydata-request-id` 响应头并经 `src/lib/api-logger.ts` 脱敏落日志；禁止把请求正文、token、cookie、密码塞进日志。

5. **通过转接层查库并守住单一真源**
   - 统一从 `@/lib/supabase/server`（`createClient`）或 `@/lib/supabase/admin`（`createAdminClient`）取客户端；禁止业务代码直引 `@supabase/supabase-js` 运行时代码（`eslint.config.mjs` 拦截）。
   - 数据范围统一取自 `src/lib/data-access-scope.ts`：当前操作候选只用 `activeVisibleUserIds`，历史统计用 `visibleUserIds`，不可混用。
   - 长查询与外部请求套 `withTimeout`（`src/lib/timeout.ts`）；业务日期/发布时间一律用 `src/lib/business-time.ts`；指标数字解析用 `src/lib/dashboard-logic/metric-input-cleaner.ts`。

6. **规范错误出口，严禁回传数据库原始报错**
   - 使用 `AppError`、`toErrorResponse` 或 `toStringErrorResponse`（`src/lib/errors.ts`）返回固定中文提示、错误码与 `requestId`。
   - 禁止把数据库或底层 `.message` / `.details` / `.hint` 直接放进返回对象（`scripts/forbidden-list-gate.mjs` 的 `db-error-leak` 拦截）。

7. **补齐同目录失败路径测试**
   - 在同目录建 `route.test.ts`（参考 `src/app/api/admin/videos/[videoId]/patch-24h/route.test.ts`），通过依赖注入测真实行为，**禁止读取 `.ts` 源码做文字匹配**（`scripts/source-text-test-gate.mjs` 拦截）。
   - 至少覆盖并断言 4xx/5xx 状态码（`scripts/api-failure-path-gate.mjs` 强制要求）：未登录/无权限 `401/403`、参数非法 `400`、越界 `403`、依赖或写库失败 `500`（以及部分成功不伪装成功）。
   - 资源读取接口若用 `404` 表示资源确实不存在、用 `5xx` 表示服务异常，测试同时断言状态码、稳定错误码和响应文案；不要让前端根据一次 `<img onError>` 自行猜原因。

8. **跑齐检查与构建**
   ```sh
   npx tsx --test <新接口同目录测试路径>    # 路径含 [id] 时去掉 --test，改用 npx tsx "<路径>"
   npx tsx --test src/app/api/route-auth.coverage.test.ts
   npm run gate:static
   npm run build
   ```
