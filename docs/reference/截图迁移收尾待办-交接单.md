| 步骤 | 判定 |

| 1. 等一次真实投稿（真人员工，不是脚本） | — |
| 2. 日志出现 `event:"write"` 且 `backend:"cos"` | 有 = 通过；无 = 停，先查 `SCREENSHOT_STORAGE` 是否被改回 |

## 4. 回退（一页，照做就行）

**触发条件**（任一）：回退率 > 5%、`read_failed` 连续非 0、页面出现大面积裂图、写失败持续。

**动作**：Vercel 把 `SCREENSHOT_STORAGE` 改回 `supabase` → 重新部署 → 用命令 ① 验一张图。

**回退能救什么**：历史 3,264 张都在 Supabase，改回即恢复原状。
**回退救不回什么**：**COS 写失败的那批新图**（接口当时返回 500，用户重传即可）。其余切换后上传的图，回退后读逻辑会自动转去 COS，仍能显示，只是慢一点。

**不要**：回退时顺手改 `COS_BUCKET` / `COS_REGION` / 超时。一次只改一个变量。
