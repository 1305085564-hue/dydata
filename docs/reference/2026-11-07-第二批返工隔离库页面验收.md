## 一、环境

- Docker 运行时：Colima 启动后，本机既有的本地 Supabase 项目 `dydata` 随容器策略自动恢复（Kong `54321`、Postgres `54322`）。仓库没有 `supabase/config.toml`；本轮**没有**新建或修改任何 Supabase 项目文件，也没有连接生产库。
- 隔离库现状：`auth.users=4`、`profiles=4`、`ai_provider_key_models=122`、`schema_migrations=221`（最大版本 `20261022120000`），含 `disabled_by_model` 等本批所需字段。
- 被测应用：`git archive HEAD`（`92f84a8d`）复制到 `/tmp`，软链参照仓库 `node_modules`，用 `.env.ai-test.local` 的环境变量执行 `next build --webpack` 后 `next start -p 3100`；浏览器统一用 `http://localhost:3100`。
- 首次尝试的 `next dev` 在临时副本里因跨源开发资源限制没有水合（页面停在骨架、不发取数请求），改用生产构建 + `next start` 后正常；该现象是验证环境问题，不是业务缺陷。
- 夹具：1 个提供方、4 条渠道、5 个模型（A 顺位锁定、A 单渠道、B 排序、B 恢复零条、B 恢复混合），通过本地 `psql` 写入；验收后按提供方级联删除，复查提供方 0、`verify-%` 模型 0。

## 二、A 顺位锁定与合法交换

| 场景 | 实测结果 |
|---|---|
| 顺位 `1 可用 → 2 休眠 → 3 可用 → 4 停用` | 休眠行上/下移按钮均禁用，提示「休眠期间顺位锁定，恢复后可调整」 |
| 首条可调度行 | 上移禁用「没有可交换的可用渠道」，下移可用「下移顺位」 |
| 末条可调度行 | 上移可用「上移顺位」，下移禁用「没有可交换的可用渠道」 |
| 已停用折叠区（1 条） | 点击展开后行内两键均禁用，提示「该渠道当前不可调度，不能调整顺位」，未产生交换请求 |
| 顺位 1 下移（跳过休眠的 2、与 3 交换） | `POST /api/admin/ai-config` 200，页面顺序变为 3、2、1、4 |
| 反向还原（3 下移与 1 交换） | 200，顺序回到 1、2、3、4；刷新后仍为真实顺位 |
| 仅 1 条可调度渠道 | 上/下移均禁用「没有可交换的可用渠道」 |

共 2 次交换请求，均 200；不可调度行的交互零请求。

## 三、B 行序冻结与恢复提示

| 场景 | 实测结果 |
|---|---|
| 正常在岗顺位 1、待复测顺位 2 | 初始显示 1、2（待复测未被置顶） |
| 第 1 条下移 | 200，显示 2、1；再下移还原为 1、2；刷新后保持 |
| 全部手动关闭后「恢复模型」 | 提示「本次未恢复任何渠道供应；手动停用的渠道需逐条开启」，库内两行仍为关闭 |
| 整体停用 + 手动关闭混合后「恢复模型」 | 提示「已重新开启 1 条渠道供应」；库内整体停用影响的行已开启，手动关闭的行仍关闭；主列表回到 1 行，折叠区保留 1 条 |

B 期间共 4 次写请求（2 次交换 + 2 次恢复），均 200。

## 五、C5 历史日报发布时间：产品上是只读

- 方案 C1 的「目标月等于父级已记录月份仍要跳转」已由 C1b 在视频复盘日历实测覆盖。
- 若未来放开发布时间编辑，需要单独产品决策，不在本批范围。
