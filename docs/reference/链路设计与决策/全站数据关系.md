## 现行设计

<a id="现行-数据表"></a>

### 一、核心数据表关系

```
profiles (用户)
  ├→ daily_reports (日报)
  ├→ videos (视频)
  ├→ douyin_account_bindings (抖音授权绑定)
  ├→ exemption_request (豁免申请)
  │    ├→ exemption_request_date (逐日审批)
  │    └→ exemption_grant (批准生效投影)
  ├→ fulfillment_appeals (补交申请)
  ├→ sub_topic_claims (选题写作)
  └→ notifications (待办)

videos (视频)
  ├→ video_metrics_snapshots (快照)
  ├→ douyin_external_videos (抖音作品暂存与精确关联)
  ├→ video_tags (手动标签；历史 AI 标签已下线)
  ├→ sub_topics (videos.topic_id 关联子题)
  └→ video_screenshot_replacement_history (截图替换)

teams (团队)
  ├→ profiles (成员)
  ├→ work_groups (小队)
  └→ fulfillment_records (履约记录)

topics (母题)
  └→ topic_groups (分组)
       └→ sub_topics (子题)
            ├→ sub_topic_claims (写作状态)
            └← videos.topic_id (作品绑定)
```

<a id="现行-连带"></a>

### 二、牵一发动全身

- **`daily_reports` 是全站命根子表**：工作台、发布管理、数据管理、导出、提醒、提交接口全依赖它。动它的结构或口径，等于动全站。
- **`videos` 跨模块共享**：视频复盘（在用、回收站）和提交接口都查它。改 `lifecycle_state` 的过滤会影响多个模块。
- **`profiles`**：所有和用户有关的操作都依赖它；`membership_status` 和归档快照决定 `visibleUserIds` 怎么算。
- 旧 `/video-review` 页面已删除，但仍在用的豁免两个申请入口（见[审批链路](审批链路.md#现行-入口)）不随旧页面清理。
- 选题库的「建议」是纯本地排序，不走 AI；旧的推荐链路（复用文案工具）已随文案工具下线删除。
- `lib/case-library`、`lib/conversion-hub` 已随旧功能下线删除；提交接口不再依赖话术表（表和历史数据保留）。

<a id="现行-接口存活"></a>

### 四、怎么判断接口还在不在用（不要凭本文件删接口）

- 判死必须逐个查：路由定义、前端调用、被其他接口内部调用、测试和外部触发。静态搜不到前端调用不等于闲置。清理按[上线与运维·发布硬边界](上线与运维（全站通用）.md#现行-发布边界)逐个验证，禁止批量删。反例：`/api/admin/first-screen-monitor`（2026-09-27 核对仍在用）。
- 各模块「入口、代码与验证」一节里的测试命令都在仓库根目录执行，覆盖已列的旧场景和核心规则，不替代真实角色、页面、数据库验收。文件名带 `[id]` 的测试按[上线与运维·门禁](上线与运维（全站通用）.md#现行-门禁)的写法单独跑，避免零测试假绿。
