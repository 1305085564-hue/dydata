# 数据复盘页广州读缓存测速报告

> 日期：2026-10-22
> 性质：**只读测速**。未迁移数据库、未改生产数据库结构、未改 Auth/RLS/Realtime/Storage 主逻辑、未改业务代码、未发布。
> 被测页面：`/admin/content`（导航名「视频复盘」；本报告按要求称"数据复盘页"，见第 1 节口径说明）
> 账号：组长测试账号（自动化专用），同一账号、同一默认筛选、第一页 20 条。
> 网络：本机（深圳）**绕过本地代理直连**；浏览器 Chromium 1440×900，冷/热各 5 次。
> 原始数据：`/tmp/dydata-gz-perf/baseline-runs.json`、`content-list-payload.json`、`gz-cache-result.json`

> **2026-10-23 复核说明**：视频复盘默认口径已随日期分页上线改为“最近有数据的一天”，本报告原始对照是旧版“默认第一页 20 条”。本轮重新打开当前线上页面，结果见第 2.3 节；广州写入实验不重跑，旧广州读数只保留为历史数据层证据。

## 1. 当前链路（实测定位）

| 项 | 事实 |
|---|---|
| 路由 | `/admin/content`（`src/app/(app)/admin/content/page.tsx`） |
| 首屏取数 | 服务端组件 `ContentDataContainer` → `loadAdminContentListData` → Supabase RPC `admin_content_list_page` |
| 分页 | **已服务端分页**，默认每页 20 条（`DEFAULT_CONTENT_PAGE_SIZE = 20`） |
| 客户端二次请求 | `/api/admin/content/topic-library-status`（列表加载后触发，冷/热都存在） |
| 数据库与计算 | Supabase 新加坡；Vercel Function 新加坡 `sin1` |

**口径说明**：仓库内没有名为"数据复盘"的路由。按"一次性读取大量历史数据、历史性能报告所指页面"这一特征，本次锁定 `/admin/content`（视频复盘）。`/admin/collaboration`（数据管理）与 `/admin/pulse`（每日大盘）**未测**。

**与 10-18 审计报告的差异（重要）**：审计报告里的"整库 13.7MB、一次取 2,320 条作品"已被 2026-10-21 上线的服务端分页取代。本次实测首页只返回 **20 行 / 36.5KB**，但数据库仍要为这 20 行扫描 **2,436 条候选作品 + 2,407 条快照**（RPC 内部计算量未减）。

## 2. 一次打开页面的实测拆解

### 2.1 数据接口（`/api/admin/content/list`，一次采样）

| 项 | 数值 |
|---|---:|
| HTTP | 200 |
| 返回 JSON | **36,544 B**（20 行作品 + 20 条快照） |
| 数据库扫描行 | 2,436 作品 / 2,407 快照 |
| 鉴权 auth | **112.2 ms** |
| 权限上下文 context | 23.6 ms |
| **RPC 计算 rpc** | **1,338.0 ms** |
| 序列化 serialize | **0.3 ms** |
| 数据阶段 data | 1,382.2 ms |
| 接口总耗时 total | 1,519.7 ms |

结论：**慢点已经不在"搬数据"，而在"为 20 行结果重新算一遍全量候选"**（1.34 秒），加上跨境 TTFB。

### 2.2 页面级（浏览器实测，状态码全部 200，错误 0）

| 指标 | 冷缓存 p50 | 冷缓存 p95 | 热缓存 p50 | 热缓存 p95 |
|---|---:|---:|---:|---:|
| 打开→列表可用（首行出现） | **2,917 ms** | **3,558 ms** | **1,575 ms** | **1,890 ms** |
| TTFB | 2,368 ms | 2,932 ms | 1,504 ms | 1,838 ms |
| 文档加载完成（DOMContentLoaded） | 3,450 ms | 4,566 ms | 1,678 ms | 2,019 ms |
| 全部资源传输 | 503,414 B | 504,022 B | 2,233 B | 2,233 B |
| 请求数 | 39 | 39 | 40 | 40 |

拆分：单次接口采样的鉴权 112ms、权限上下文 24ms、数据阶段 1,382ms、序列化 0.3ms。页面 TTFB 至列表可用相差约 71ms（热 p50）/ 549ms（冷 p50）；这段**包含响应流传输、脚本执行和渲染，不能单独当作渲染耗时**。冷缓存传输了约 503KB 资源，但尚未单独量化其耗时。

最慢请求（热）：`/api/admin/content/topic-library-status` **1,635–1,740 ms**；它在列表可用之后才返回，**不阻塞首屏**，但仍是超 1.2s 预算的存量瓶颈。

### 2.3 当前线上口径复核（2026-10-23）

当前 `/admin/content` 默认返回最近有数据的一天，实测为 15 行、30,477 B，`pageSize=100`、`totalVideos=15`；服务端阶段为 auth 154.2ms、context 45.9ms、RPC 312.1ms、data 356.1ms、total 557.7ms，仍扫描 2,457 作品和 2,428 快照。浏览器冷/热各 5 次、状态码 200、错误 0：

| 指标 | 冷 p50 / p95 | 热 p50 / p95 |
|---|---:|---:|
| 打开→列表可用 | 2,710 / 2,911 ms | 1,364 / 1,582 ms |
| TTFB | 2,183 / 2,360 ms | 1,281 / 1,531 ms |
| 全部资源传输 | 510,365 / 511,579 B | 2,122 B |
| 请求数 | 40 / 40 | 41 / 41 |

当前结果说明页面和 RPC 已明显不同于 10 月 22 日旧口径；它只能用于判断当前页面仍有约 0.3 秒 RPC 计算和约 1.3 秒热首屏等待，不能与旧版 20 行结果直接做收益百分比。

## 3. 广州只读缓存对照（实测）

| 项 | 结果 |
|---|---|
| 缓存位置 | 腾讯云 COS 广州 `ap-guangzhou`，独立私有测试桶 `dydata-cache-gz-1409482292`；本次原始记录显示创建接口返回 409，说明当次测速前桶已存在，不能据此声称当次新建成功 |
| 对象 | `perf-cache/admin-content/v1/<范围指纹>/page-1.json`，37,063 B |
| 内容 | 生成时间、筛选条件（view/page/pageSize/sort）、范围指纹、行数、快照数、payload SHA-256、60 秒过期时间、schemaVersion |
| 写入 | 200，198–331 ms |
| 服务端读取（本机深圳直连广州） | 冷 p50 **105 ms**（96–188），热 p50 **102 ms**（84–112） |
| 数据一致性 | 缓存回读 SHA-256 与源接口**完全一致**；行数 20/20/20（缓存/源/实时） |
| 实时漂移 | 约 30 分钟后实时首页与缓存**恰好差 1 条作品**（新作品把末位挤出），两次实时请求之间稳定不变 |
| 浏览器直读（预签名 URL） | 预签名本身 200（37KB），但响应**无 CORS 头**，浏览器 `fetch` 被拦：`TypeError: Failed to fetch` → **BLOCKED** |
| 截图生产桶 | 前序试验曾误写 1 个测试对象，前序会话记录其已删除（204）；本次未重新列举全桶，残留状态未独立核实 |

**关键限制**：生产服务端在**新加坡 sin1**，本报告测到的 105ms 是"深圳→广州"。**sin1→广州的真实耗时未测**，因此不能从深圳读数推出生产服务端读取耗时，也不能据此断定两地缓存的快慢。

## 4. 三方案对比

| 方案 | 冷缓存 p50 | 冷缓存 p95 | 热缓存 p50 | 热缓存 p95 | 返回大小 | 错误数 |
|---|---:|---:|---:|---:|---:|---:|
| A. 旧口径原始链路（2026-10-22） | 2,917 ms | 3,558 ms | 1,575 ms | 1,890 ms | 36.5KB 数据 / 503KB 全页 | 0 |
| A′. 当前线上口径（2026-10-23） | 2,710 ms | 2,911 ms | 1,364 ms | 1,582 ms | 30.5KB 数据 / 510KB 全页 | 0 |
| B. 当前鉴权 + 广州缓存（**页面级未接入**） | 未测 | 未测 | 未测 | 未测 | 37.1KB | 0（数据层） |
| B′. 同上，仅数据层实测 | — | — | 105 ms / 102 ms（深圳→广州） | 188 ms / 112 ms | 37.1KB | 0 |
| C. 浏览器直读广州缓存 | BLOCKED（CORS 未开） | BLOCKED | BLOCKED | BLOCKED | 37.1KB | 1（浏览器拦截） |

单次接口与五次页面测速不是同一批请求，不宜将阶段耗时相加还原某次页面耗时。B 若要成立，需把数据阶段换成一次缓存读取；**页面级是否真的变快未测**。

> 读表提醒：B 行是**页面级**，未接入所以写"未测"；B′ 行只是**数据层**（一次缓存 GET）实测，**不能当作 B 的页面级结论**。

---

## 5. 结论

1. **广州缓存没有在本轮证明能降低"用户打开页面"的完整耗时。** 页面级 B 未接入，不能把"接口数据层 105ms"当成"页面变快"；当前线上口径也已变化，旧版页面 p95 不能直接套用。
2. **实测的主要服务端耗时在结果计算**：接口只传 36.5KB，RPC 单次耗时 1,338ms；是否由重复计算造成、缓存能节省多少，尚需 A/B 页面级实测。广州与新加坡缓存孰快也尚未实测。
3. 冷缓存传输约 503KB 页面资源；其具体耗时及对首屏的影响未单独测量。
4. 按判定规则：**整体页面 p95 未实测到 ≥30% 的下降 → 当前不值得扩大（广州读缓存这条路线）**。
5. 真正值得单独立项的是**服务端结果缓存**（共享缓存，解决 serverless 实例间 60 秒内存缓存不共享的问题），缓存位置应贴近新加坡，而不是广州。该方向本轮**未验证、未实施**。

## 6. 权限与一致性风险检查

| 项 | 结果 |
|---|---|
| 私有性 | 独立桶 + `x-cos-acl: private`；预签名 URL 300 秒。浏览器直读被 CORS 拦；CORS 不能代替访问控制，预签名 URL 在有效期内仍应视作敏感凭据 |
| 跨用户复用 | 本次键含"账号指纹 + 范围指纹 + 行 ID 集合"，但**未含完整 `visibleUserIds`**。账号范围变更（调组/降权）后存在短暂复用旧结果的风险 → **不合格，需补范围指纹** |
| 过期/刷新 | 元数据声明 60 秒 TTL，但测试读取未执行过期检查；约 30 分钟后实时数据差 1 条属预期过期现象。若要接入生产，需服务端强制过期并定义写入后刷新策略 |
| 失败回退 | 未接入应用，**无回退路径可验**（BLOCKED）；按设计应为"读缓存失败→走原 RPC"，未实现 |
| 数据副本 | 测试对象含作品标题/账号名/播放数。测速后已删除对象与测试桶（均返回 204），**不留业务数据副本** |
