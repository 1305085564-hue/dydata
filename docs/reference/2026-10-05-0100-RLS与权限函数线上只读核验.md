```sql
select tablename, count(*) as policies,
       string_agg(distinct cmd, '/' order by cmd) as cmds,
       string_agg(distinct roles::text, ',' order by roles::text) as roles
from pg_policies
where schemaname='public'
  and tablename in ('profiles','daily_reports','exemption_request','exemption_grant','audit_log','sub_topic_claims','videos')
group by tablename order by tablename;
```

```
     tablename     | policies |            cmds             |          roles
-------------------+----------+-----------------------------+--------------------------
 daily_reports     |        8 | DELETE/INSERT/SELECT/UPDATE | {authenticated},{public}
 exemption_grant   |        2 | SELECT                      | {authenticated}
 exemption_request |        8 | DELETE/INSERT/SELECT/UPDATE | {authenticated}
 profiles          |        6 | ALL/INSERT/SELECT/UPDATE    | {authenticated},{public}
 sub_topic_claims  |        1 | SELECT                      | {authenticated}
 videos            |        8 | INSERT/SELECT/UPDATE        | {authenticated},{public}
(6 行记录)
```

`daily_reports`、`profiles`、`videos` 出现了 `{public}` 角色。**这在 PostgreSQL 里 `public` 是伪角色、包含 `anon`**，所以必须逐个看 `qual` 表达式，不能只看角色名。抽查结论：这些都是 `((profile_id = auth.uid()) OR is_admin())` 一类的**带 uid 守卫**表达式，不是无条件放行。无条件放行的项单独列在第五节。

## 四、权限函数核验（SECURITY DEFINER / search_path / ACL）

```sql
select p.proname,
       pg_get_function_arguments(p.oid) as args,
       p.prosecdef as security_definer,
       coalesce(array_to_string(p.proconfig, ','), '(none)') as proconfig,
       coalesce(array_to_string(p.proacl, ','), '(default)') as proacl
from pg_proc p join pg_namespace n on n.oid = p.pronamespace
where n.nspname='public'
  and p.proname in ('has_permission','is_admin','is_owner','is_admin_or_owner',
                    'get_role_permissions','visible_user_ids','current_profile_role')
order by p.proname;
```

```
       proname        |                      args                       | security_definer |           proconfig            |                                proacl
----------------------+-------------------------------------------------+------------------+--------------------------------+----------------------------------------------------------------------
 get_role_permissions | p_role text, p_group_mode boolean DEFAULT false | f                | search_path=""                 | postgres=X/postgres,authenticated=X/postgres,service_role=X/postgres
 has_permission       | perm text                                       | t                | search_path=""                 | postgres=X/postgres,authenticated=X/postgres,service_role=X/postgres
 is_admin             |                                                 | t                | search_path=""                 | postgres=X/postgres,authenticated=X/postgres,service_role=X/postgres
 is_admin_or_owner    |                                                 | t                | search_path=""                 | postgres=X/postgres,authenticated=X/postgres,service_role=X/postgres
 is_owner             |                                                 | t                | search_path=""                 | postgres=X/postgres,authenticated=X/postgres,service_role=X/postgres
 visible_user_ids     | p_actor_id uuid DEFAULT auth.uid()              | t                | search_path=pg_catalog, public | postgres=X/postgres,authenticated=X/postgres,service_role=X/postgres
(6 行记录)
```

```sql
select count(*) as security_definer_functions
from pg_proc p join pg_namespace n on n.oid=p.pronamespace
where n.nspname='public' and p.prosecdef;
```

```

----------------------------
                         78
(1 行记录)
```

**判定：通过。** 六个权限函数：
- 五个 `SECURITY DEFINER`（`get_role_permissions` 不是，它是静态映射表，不需要提权——与 `docs/权限与安全说明.md` B.3 描述一致）。
- `search_path` 全部**显式钉死**（五个为 `""`，`visible_user_ids` 为 `pg_catalog, public`），不存在 search_path 劫持面。
- ACL 只有 `postgres / authenticated / service_role` 有 EXECUTE，**`anon` 和 `PUBLIC` 都没有**。

```
(8 行记录)
```

### 应当处理（2 项）

| 表 | 策略 | 角色 | 问题 |
|---|---|---|---|
| `script_document` | `script_document_public_read` | `{public}` | **`public` 含 `anon`，即未登录者可读全表**。需确认脚本文档是否真的公开 |
| `tag_definition` | `tag_definition_read` | `{public}` | **同上，未登录者可读全表标签定义**。标签定义通常是内部配置 |

### 属预期、不需处理（6 项）

| 表 | 策略 | 角色 | 为什么不是问题 |
|---|---|---|---|
| `fulfillment_appeals` / `fulfillment_records` / `system_settings` | `Service role full access …` | `{service_role}` | 显式给 service role 放行；service role 本来就绕过 RLS，这是冗余但无害 |
| `teams` / `violation_case_visual_tags` / `visual_tags` | `*_read` / `*_select_all` | `{authenticated}` | **仅登录用户可读**，是刻意的共享主数据 |
