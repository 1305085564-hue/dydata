# 新增页面操作步骤

> 适用范围：`src/app/(app)/**/page.tsx`。视觉与布局基准见[效率美学](效率美学.md)与[美学宝典](美学宝典.md)；参考样板见 `src/app/(app)/admin/pulse/page.tsx` 与 `src/app/(app)/admin/fulfillment/page.tsx`。

1. **确定路由与布局壳**
   - 登录后员工页放 `src/app/(app)/<模块>/page.tsx`，管理页放 `src/app/(app)/admin/<模块>/page.tsx`；管理页用 `AdminWorkspaceLayout`（`src/components/admin-workspace-layout.tsx`）保持页面轨道一致。
   - 严守分层：共享纯逻辑放 `src/lib/<领域>/`，可复用叶子界面放 `src/components/`，只服务本页的拼装组件留在本页目录；`src/components` 不得反向引用 `src/app`（Server Action 除外，`eslint.config.mjs` 拦截）。

2. **登记路由权限、标题与导航入口**
   - 管理页必须在 `src/lib/route-permissions.ts` 的 `ROUTE_PERMISSIONS` 登记所需 `PermissionKey`（未登记的 `/admin/*` 路由会被 `canAccessRoute` 默认拒绝），并同步补 `src/app/(app)/admin/layout.tsx` 的 `MODULE_TITLES`。
   - 需要出现在导航栏时，在 `src/lib/navigation/domain/navigation.ts` 的 `getNavGroups` 注册入口，并确认不影响手机底栏前 4 项顺位规则。

3. **页面入口鉴权与写操作收口**
   - 服务端组件首行调 `getCurrentPermissionContext("company", null)`（`src/lib/current-permission-context.ts`）：未登录 `redirect("/login")`，无权访问（`canAccessAdminPath(pathname, perm.role, perm.permissions)` 为 `false`，`src/lib/analytics-access.ts`）时 `redirect("/dashboard")`。
   - 业务写操作优先走 `/api/*`；若确需新增管理端 Server Action，放入 `src/app/(app)/admin/actions.ts`，或建新文件后登记进 `src/app/(app)/admin/actions.permission-inventory.probe.mjs` 的 `ACTION_MODULES`，确保无权限拦截在碰库之前。

4. **用 `zod` 校验 URL 参数与表单输入**
   - Next.js 16 的 `searchParams` 为 `Promise`，先 `await searchParams`，再用 `zod` 的 `safeParse` 归一与回退默认值（新页面与新表单统一用 `zod`，不沿用老页面的手写解析）。
   - 涉及指标输入清洗统一用 `src/lib/dashboard-logic/metric-input-cleaner.ts`，业务日期和发布时间统一用 `src/lib/business-time.ts`，豁免类别文案统一用 `src/lib/exemption-category.ts`。

5. **编排首屏取数与 `requestId` 观测**
   - 首屏数据由服务端加载器（`src/lib/loaders/`）或本页数据容器组件取数，用 `<Suspense fallback={...}>` 包裹避免阻塞整页；耗时首屏查询用 `createRequestContext({ route, operation })` + `observeOperation(context, ...)`（`src/lib/request-context.ts`、`src/lib/observability.ts`）记下 `requestId` 与耗时。
   - 客户端请求后端接口出错时，把接口返回的 `requestId` / `x-dydata-request-id` 一并透传到错误提示或日志；控制首屏请求数与耗时满足 `src/lib/performance-gate.ts` 的 `PERFORMANCE_ROUTE_BUDGETS`。

6. **补齐异常边界 `error.tsx` 与空态**
   - 同目录建 `"use client"` 的 `error.tsx`（参考 `src/app/(app)/admin/fulfillment/error.tsx`），展示 `RouteErrorState`（`src/components/ui/route-error-state.tsx`）提供重试入口，并在 `useEffect` 中调用 `captureRouteError(error, "<boundary>")`（`src/lib/sentry/capture-route-error.ts`）上报 Sentry。
   - 区分加载中、空数据与加载失败三种状态，不能把接口失败伪装成 0 或空列表。

7. **遵守设计令牌封闭系统**
   - 只用允许的字号（`12/13/14/20/28px`）、28 色、字重 400、衬线 ≥20px、圆角与阴影令牌（由 `scripts/design-token-gate.mjs` 拦截）；`#A8A29E` 仅用于空值/占位/禁用，不得用于有内容文字。

8. **补齐失败路径与行为测试**
   - 在本页目录补行为测试（参考 `src/app/(app)/admin/fulfillment/error.test.tsx`、`src/app/(app)/admin/modules/page.test.ts`），覆盖：无权限拦截、非法 `searchParams` 降级、加载失败/`error.tsx` 渲染及交互失败反馈；改了 `ROUTE_PERMISSIONS` 同步补 `src/lib/route-permissions.test.ts`。
   - 图片或文件资源的失败态要分别覆盖 `404`、网络异常和 `5xx` 的最终显示；如果需要二次探测状态码，探测完成前保持加载/探测态，不得先渲染“点击重试”再改成“资源已丢失”。
   - 严禁新增读取 `.ts`/`.tsx` 源码做文字匹配的测试（`scripts/source-text-test-gate.mjs` 拦截）。

9. **跑齐检查与构建**
   - 在隔离区运行 Next.js 构建时，`node_modules` 必须是隔离区内的目录（可用本机文件硬链接复用内容），不要软链到工作区外；Turbopack 会拒绝这类路径。
   ```sh
   npx tsx --test <新页面相关测试路径> src/lib/route-permissions.test.ts
   npm run gate:design
   npm run gate:static
   npm run build
   ```
