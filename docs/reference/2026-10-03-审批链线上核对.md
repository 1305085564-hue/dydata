## 七、取数通道盘点

### 7.1 Vercel 日志能查多久（实测）

```sh
vercel logs --json --since 2026-10-01T06:00:00Z -n 1000   # 拉到 10-01，仍只返回 n=11，最早 16:52:11Z
vercel logs --json --since 2026-10-02T16:30:00Z --until 2026-10-02T17:30:00Z -n 100   # n=2，落在窗口内
vercel logs --json --since 2026-10-01T06:00:00Z --until 2026-10-01T09:00:00Z -n 1000  # n=0（周四业务时段，必有流量）
```

取数时刻 17:48Z，可查到的最早一条 16:52:11Z（距今 56 分钟）；把 `--since` 往前拉到 10-01 不会多出一条，说明这是**约 1 小时的滚动保留窗口**，不是流量为零。该档期与团队/项目属性一致（个人档 `1305085564-1671's projects`，无 Observability 相关能力位）。

### 7.2 过滤能力（够用）

```sh
vercel logs --json --since <ISO> -n <N> \
  -q 'requestPath:"/api/admin/fulfillment/appeal/handle"' \
  --status-code 4xx|5xx --source serverless|edge-middleware
```

- `requestPath`／`status` 等字段是 Vercel 原生列，可直接过滤；`message` 字段是**我们自己的单行 JSON**（`kind/route/method/status/durationMs/outcome/detail`，detail 里含三态、`stage`、`release`），所以能一条命令拿到全链路。
- 坑：`--request-id` 过滤的是 **Vercel 自己的请求 ID**（形如 `2z4wb-…`），填我们的 `requestId` 返回 0 条；要按我们的 requestId 串联，只能拉回本地后在 JSON 里筛（本次即用此法）。
- `--until` 与相对时间（如 `--since 12h --until 10h`）实测返回 0 条，改用 ISO 绝对时间才可靠。

### 7.3 其它通道

| 通道 | 能拿什么 | 能不能支撑 10-10 报表 |
|---|---|---|
| 生产数据库（`fulfillment_appeals`／`audit_logs`／`notifications`） | 审批次数、审批人动作、审计条数、通知创建与完成时间；**可回溯全历史** | 能支撑「量与账」这一半；拿不到 HTTP 状态码、耗时、失败分类 |
| Sentry（生产已配 `SENTRY_DSN`／`NEXT_PUBLIC_SENTRY_DSN`） | 未预期异常（含 thrown 态上报），保留期按 Sentry 项目设置 | 能支撑「有没有崩」这一半；不记录成功请求，无法算请求量与健康度 |
| Vercel 日志 | 请求量、状态码、我们自报的耗时与三态 | **不能**——只有 1 小时 |
| `DYDATA_PERF_LOG` | 性能日志开关 | 生产环境变量清单里没有这个键，即性能日志线上未开 |

### 7.4 结论：取数通道是否满足 10-10 出报表

**不满足。** 「改前 7 天 vs 改后 7 天」的 HTTP 层对照（请求量比例、4xx/5xx 明细、P95 耗时）需要跨 14 天的日志，而 Vercel 只给最近约 1 小时，**改前窗口的 HTTP 日志在本次核对时已经永久不可回溯**；改后窗口再等到 10-10 也只是累积 7 天新的请求，无法补回对照的另一半。

要在 10-10 交出有意义的报表，必须现在二选一：

1. **把日志留下来**：工作日时段定时（或每天一次）跑 `vercel logs --json --since 1h` 把结果落盘（不进仓库），或开通 Vercel Log Drains／Observability 付费档外发到可查存储。只有这么做才保留「改后 vs 改前」里改后的一半，改前一半仍只能靠数据库口径。
2. **改口径，不用 HTTP 日志**：把 §八 的健康度指标重新定义为「数据库可算的」＋「Sentry 可算的」——审批笔数、审计 1:1 率、通知 1:1 率、异常上报条数、以及一条真实审批的 requestId 定点抽查。这条路今天就能落地，代价是 P95 耗时这一格永久缺数据（除非开日志外发）。

推荐 **2 为主、1 为辅**：2 立刻可执行且不花钱，1 在真正关心耗时之前不必上。
