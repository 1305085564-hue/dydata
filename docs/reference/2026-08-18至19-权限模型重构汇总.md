# DYData 权限模型重构任务汇总（2026-08-18 至 2026-08-19）

## 任务背景

**发起时间：** 2026年8月18日
**完成时间：** 2026年8月19日晚
**参与 AI：** Claude Code (claude-3p)、Codex、Terra、Antigravity、Luna
**任务性质：** 极难，生产写入，两天完成

**核心问题：**

1. owner 身份既管公司又管集团，权限边界不清
2. 系统设置权限被锁死（manage_system 只在集团模式，但无人能进）
3. 日报截图公开可访问（283条数据泄露）
4. 16个 migration 漂移（本地有、生产无）

**解决方案：**

- 引入 company_role 三级体系（member/admin/company_owner）
- 剥离公司所有者的集团属性
- manage_system 移至 company_owner
- 截图私有化
- migration 对账并全部上线

## 权限对比

### 变更前

| 角色 | 范围 | 权限 | 问题 |
|------|------|------|------|
| owner | 全公司/全集团（模糊） | 全部 | 边界不清 |
| admin | 本团队 | 部分 + manage_members | 能改角色 |
| member | 自己 | 无 | — |

### 变更后

| 角色 | company_role | 范围 | 权限 | 说明 |
|------|--------------|------|------|------|
| 公司所有者 | company_owner | 本公司 | 11项（含 manage_system、manage_members） | 管本公司全部 |
| 主管 | admin | 本公司在职 | 7项（不含 manage_members） | 只管日常业务 |
| 组员 | member | 自己 | 无 | 只能提交申请 |

**核心区别：**

- 公司所有者不再有集团属性
- 主管不能改角色、归档、重置密码
- manage_system 从"集团模式独占"变为"公司所有者固定权限"

## 经验教训

> 详细分析见 [复盘文档](./2026-08-18至19-权限重构复盘.md)

### 预期 vs 实际

- 预期 1天（10小时）→ 实际 2天（30+小时），极难任务预期时间 ×2 = 实际时间
- 验收类任务最容易被过度工程化（×3-4 倍时间）

### 必须拆分的信号

- 预期超过 4 小时的任务 → 多对话
- 每 4 小时连续对话 = 强制拆分点（避免上下文压缩）
- 按"独立交付物"拆分（诊断 / 代码 / 测试 / 生产写入 / 验收）

### 提示词设计原则

- **验收类任务第一句必须写"不要写脚本，直接手工操作"**
- 用祈使句，列出具体步骤，不要让 AI 自己规划
- 明确错误含义（401=未登录，403=拒绝，400=文件不存在）
- 给出时间上限："X 分钟内完成，超时立刻停下"
- 提示词写 3 遍：第一遍完整，第二遍删废话，第三遍加禁止项

### 生产写入模式

- 快照 → 逐步执行 → 每步复查 → 记账
- Migration 原子化：每个不超过 200 行，只做一个操作
- 遇到错误先诊断，不要自动回滚

### Token 管理

- SQL 查询结果只保留摘要，不要完整 JSON
- 测试输出只保留失败项，不要全部通过的项
- Migration 文件只读一次，后续用摘要
