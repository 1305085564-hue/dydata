## 权限模型

- 新业务角色只有：`member`、`admin`、`company_owner`。
- 旧数据库 `role=owner` 只在迁移边界映射为 `company_owner`，不再表示集团全局权限。
- `member` 只能操作自己；`admin` 和 `company_owner` 默认只管理当前 `team_id` 公司；归档成员不能参与当前操作。
- 集团模式不是独立日常角色；在职 `company_owner`（旧 `role=owner` 兼容）可在网页内直接进入，普通 `admin/member` 和归档账号由服务端拒绝。
- 集团模式令牌只保存哈希，新会话由老板手动退出；历史 `expires_at` 仍兼容处理，没有公司归属不能扩大为集团范围。
- 11 个功能权限由角色固定表决定，旧 `permissions` JSON 仅作迁移兼容，不是新规则来源。
- 旧 `data_scope` 仅作迁移兼容；新范围由公司角色、集团模式和 `team_id` 共同决定。
- 当前操作使用 `activeVisibleUserIds`，历史查询使用 `visibleUserIds`。
- 当前代码已接入新核心；集团模式收口 migration 为 `20260820100000_owner_group_mode_access.sql`，生产执行、schema cache 刷新和真实角色验收仍需单独确认。
- 首个 `owner`：`1305085564@qq.com`，迁移后对应本公司 `company_owner`。

## 废弃机制

- 不从旧设计文档里恢复功能，必须先用当前代码验证是否上线。
- `sop_review_scores` 六维评分和 `content_feedback_cards` 反馈闭环均不参与当前视频复盘主流程；视频复盘只保留异常证据、内容归因与 `content_analysis` 内部分析。
- SOP 5 卡点状态追踪、审核中心、全域矩阵未作为当前 dashboard 入口上线。
- 旧 AI 配置入口 `/admin/ai-channels`、`/admin/ai-features` 统一重定向到 `/admin/ai-config`。
