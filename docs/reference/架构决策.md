# 架构决策

> 这里记已拍板的取舍和「为什么这么定」。本文件是唯一的总目录；每条决定的正文在下表的页面文件和链路文件里。入口与调用关系见[模块地图](../系统架构与设计/全站模块与数据关系.md)，业务规则见[核心业务流程](../系统架构与设计/核心业务流程与异常边界.md)，统计口径见[数据口径](../系统架构与设计/数据口径与计算规则.md)。

## 怎么用

- **改某个页面前**：读这个页面的文件，再读它「牵涉链路」里列出的链路文件。
- **记新决定**：只影响一个页面，记在页面文件；影响两个以上页面或全站，记在链路文件。同一条只写一处，别处放链接。
- **编号**：每份文件各自从 1 排起，新的一条取本文件最大号加一，写在文件末尾。引用别的文件时写「数据上传链路第 3 条」，并链到那一条。
- **新决定取代旧决定**：旧条目不删，在它的状态里写「已被第 N 条取代」；新条目的状态里写取代了哪条。
- **拍板人**：写实际拍板的人；找不到阿禅原话的写「待核」。产品和业务逻辑的取舍必须由阿禅拍板。
- **新页面或新链路**：照现有文件的开头格式新建，并加进下表。

## 每条怎么写

```
<a id="第N条"></a>

## N 标题

**分类**：业务 / 设计 / 性能 / 代码　**状态**：有效 / 已被第 N 条取代　**日期**：YYYY-MM-DD　**拍板人**：阿禅
**背景**：为什么要定
**决定**：定了什么
**后果**：代价、放弃了什么、以后必须保持什么（没有可省）
**证据**：链接
```
