# 06 · 未来文档架构设计建议

> 定位：**架构建议**，非现状描述。核心判断：现有"产品全书+三文件夹+plans/reference/archive 生命周期"骨架是对的，且执行质量在核心圈已被实测验证（03 号报告）。**不建议推倒重来或加新层级**；要补的是四个机制缺口（05 号报告末），并做三处收敛。

## 一、分层模型（五层，映射现有目录，不新建）

| 层 | 职责 | 落位 | 变更频率 |
|---|---|---|---|
| L0 规则层 | Agent 行为与纪律 | AGENTS.md（唯一原稿）+ CLAUDE.md 指针 | 低（每次改判必须同步 L1 引用面） |
| L1 索引层 | 任务→文件路由 | **仅** docs/DYData产品全书.md | 中（新增正式文档当日登记） |
| L2 事实层 | 长期有效知识 | docs/业务逻辑/ + docs/系统架构与设计/ + **docs/architecture-decisions/**（收编） | 中（改判即回写） |
| L3 执行层 | 在办任务 | docs/plans/ 根（严格=在办） | 高（交付即归档，见机制③） |
| L4 证据层 | 历史/验收/流水 | docs/reference/ + docs/archive/ + docs/plans/历史-*/ + 日志/ | 只追加，不回写 |

**收敛动作（对应 B-03/B-06/B-07）**：
1. 路由唯一化：文档与维护规范§一表、README"文档导航"节改为**一句话+链接全书**；AGENTS.md 内散链（:53/:91/:132）保留（属规则正文必需），:101-110 目录表与全书§二重叠部分压缩为"见全书"。
2. `docs/页面功能/`：若"按页面写功能说明书"仍是长期方向→收编进 L2 并登记全书、给行数档；若属试验→整目录归 archive。二选一，不能裸奔（当前 446 行无上限、无索引、内容过时三态叠加）。
3. reference 内 ~10 份活体规范逐份定性：仍有效的迁 L2（如截图上传维护手册）；已完成方案加"不授权施工"边界声明（模板=架构与性能双层门禁设计:4）；失效的（懒加载索引规范）移 archive。

## 二、每类文档职责契约（写什么/不写什么/更新触发）

| 类型 | 写 | 不写 | 权威 | 更新触发 | 退役 |
|---|---|---|---|---|---|
| AGENTS.md | 行为纪律 | 文件路径清单、业务细节 | 规则唯一原稿 | 改判当场 | 不退役 |
| 产品全书 | 路由、目录定义、行数档 | 业务规则本体 | 索引唯一 | 新增正式文档当日；文内"最后更新"随提交刷新 | 不退役 |
| 业务/架构事实 | 当前有效事实+代码指针+核对日期 | 变更流水（"某次改成X"） | 各自主题唯一 | 相关代码/口径变更的**同一轮** | 机制下线→条目移全站模块地图废弃名单 |
| ADR | 背景/决定/后果/证据链+**状态字段** | 操作手册 | 决策留档 | 被取代时改状态"已被 ADR-00NN 取代"，不删 | 永不删，只标状态 |
| plans 在办 | 目标/规格/验收 | — | 任务唯一 | 交付即整包归档+改链 | 归档 |
| reference/archive/日志 | 带日期证据 | 现行规范 | 无（候查） | 只追加 | 历史区默认不搬迁 |

**关键新规（治 A-01 根源）**：任何"改判"（AGENTS.md 划删除线的动作）必须在同一提交内 grep 全活跃区旧口径并回写——AGENTS.md 防伪表已有"前后端同步闭环/清理死代码"精神，把它延伸到**文档域**即可，不需新文件。

## 三、防失散机制（登记/命名/状态/链接）

1. **登记**：全书纪律 5 已有，缺执行钩子→把"新增 docs 顶层文件/目录未在全书登记"做成 `gate:static` 检查项（脚本比对 git 新增 md 路径与全书链接集，白名单豁免 reference/archive/日志/plans）。
2. **命名**：核对类定模板 `YYYY-MM-DD-HHmm-<主题>-推送后线上核对.md`（只约束新增，存量 47 份不改名——改名断链成本>收益）；交接类沿用 `交接-日期-关键词.md`✓已合规。
3. **状态标识**：仅两类需要——ADR 加"状态：有效/已被取代"行；历史区**规范性质**文件加首行 banner（A-02/C-x 的根治）。普通记录靠目录语义，不加标签（文档与维护规范§三"不给所有文档加重复标签"的原则正确，保留）。
4. **链接体检**：把本次审计用的断链扫描固化为 `scripts/doc-link-check.mjs`：只检活跃区（排除 archive/reference/日志/plans 历史），目标不存在即 gate 红；同时反向拦截"入库文档引用 output/"。待办清单:69 已自登记 10 处断链=人工版已存在，脚本化后该债自动归零。
5. **搬迁改链**：plans/README:41 已有规则，加机械兜底——归档提交前对移动路径跑一次全仓 grep，引用处同提交更新（git mv + grep 清单可写进 06 的归档 SOP）。

## 四、AI 读取成本（任务触发式，现状已 80 分，补 20 分）

现状正确的部分（保留不动）：全书场景路由、设计三卷"常驻第 0-1 章+按需下钻"、行数上限档、plans 分诊一行制。需补：

1. **L4 默认不可见**：全书:37 已写"三处都是候查资料"，再加一句硬规则——"AI 开工不主动读 reference/archive/日志，仅当任务需要既往证据时按日期定向读取"。
2. **ADR 进路由**：全书加一行"做架构取舍/恢复被禁机制前→读 docs/architecture-decisions/README 索引"。这解决"唯一入口没登记的权威=不存在"。
3. **每任务必读集收敛为 3**：AGENTS.md + 全书路由命中的 1-2 份事实文档 + （前端任务）设计主卷第 0-1 章。其余全部按需。文档与维护规范§一"什么时候读"列已是此思路，路由唯一化后自然继承。
4. **禁止整目录扫读**：多 Agent 并行时按"模块→文档"映射（全站模块与数据关系.md 补全 pulse/成员主页后即是模块索引）读，不读 plans 根全量。

## 五、文档↔系统一致性维护

| 手段 | 覆盖对象 | 成本 |
|---|---|---|
| 已有：design-token-gate/maintainability-gate/performance-gate 与文档数值对账 | 设计令牌、棘轮、性能预算 | 0（已运行，补文档登记即可） |
| 新增：doc-link-check（活跃区断链+output 反向引用） | 引用完整性 | 低 |
| 新增：全书登记检查（git 新增 md vs 索引） | 孤儿文档 | 低 |
| 约定：口径类文档每条带"代码指针 file:symbol"，抽查时按指针 diff | 数值漂移（:249 型残留） | 中（写文档时顺手） |
| 人工：改判回写纪律（§二新规）+ 季度一次本审计脚本复跑 | 语义冲突 | 低 |
| **不做**：文档内容自动从代码生成、强制 frontmatter 元数据、给历史区补台账 | — | 高成本低收益，明确排除 |

## 六、目标形态一句话

**目录不变、层级不加；路由收成一表、改判必回写、交付必归档、搬迁必改链、历史必挂牌、孤儿必登记——六条全部要么进 gate 脚本、要么进 AGENTS.md 一行纪律，不再新增第四份规范文件。**
