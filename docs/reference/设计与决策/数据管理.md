## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。改规则时先改这一段，再在文件末尾加一条历史决策写明为什么改。评级、良优率、条均播放和文案结算见[作品评级链路·现行设计](作品评级链路.md#现行设计)。最后对过代码：2026-11-19。

<a id="现行-归属"></a>

### 一、作品算谁的

- 作品按有效发布时间的上海自然日进入所选月份，没有有效发布日的历史记录回退日报归属日。候选日报仍受 `report_date >= 2026-07-27` 的历史起点限制。
- **达人**：按账号主人（`accounts.profile_id`）认定，汇总名下账号当月的作品。
- **文案**：按署名（`script_author_user_id`）归属，先认定岗位再统计全量：管理员认证后进入文案岗，之后统计本人当月署名的全部文案，包括给自己账号写的。是否给别人写过不再是入场条件；已认证但没有作品显示 0。认证不推断运营身份。
- **剪辑**：按剪辑署名（`video_editor_user_id`）归属，只算给别人账号剪的；给自己账号剪的不进剪辑岗。
- **运营**：按运营署名（`operator_user_id`）归属，只算为别人孵化、负责的账号；本人孵化本人账号算达人工作。
- 账号主人统一按 `accounts.profile_id` 判断；账号没绑主人时按别人的账号算，避免漏掉真实协作。只服务一个别人的账号、只干过一两条也照常展示，不设最低条数。
- 运营、文案、剪辑是服务岗，不要求本人有达人账号；没有自有账号不影响按真实协作进对应岗位，也不能当成异常账号或待清理的依据。一人兼多岗各算各的。

<a id="现行-岗位表"></a>

### 二、按岗位查看

- 四个岗位页签用日报口径：作品数按岗位责任人对应的日报条数累计；总播放是这些日报的播放之和；条均播放见作品评级链路。
- 数字标色按[作品评级链路·标准线与颜色](作品评级链路.md#现行-颜色)执行（好红差绿：岗位表与个人作品明细用公司 `minPlayCount` 默认 5,000 门槛，小队列表与小队详情用 2,000 门槛）。
- 个人档案的 `records`、`currentMonth` 展示该成员全部日报记录（含给自己账号干的），只有 `operatorSummary` 和服务岗页签同口径。

<a id="现行-小队表"></a>

### 三、按团队（小队）查看（2026-09-22 起）

- 按工种小队（文案、达人、运营）展示，指标和视频复盘抽屉同源：每条作品取最新 24h 快照，先加总再相除。署名归属和按岗位一致。
- 默认列：作品数（当月署名作品总数）、总播放（快照播放合计）、条均播放、转粉率（Σ涨粉 ÷ Σ播放）、互动率（Σ(赞+评+分享+藏) ÷ Σ播放）、综合达成（互动达成 + 留存达成）。播放合计为 0 时比率显示「—」。
- 点「展开明细」：互动率拆成点赞率、评论率、分享率、收藏率（同样 Σ ÷ Σ播放，四项相加等于互动率，三种小队都有）；文案和达人小队另拆出五项留存原始值，取播放达到 2,000 且算得出留存的作品做算术平均（与留存达成均值同一批作品，不按播放加权；某项全缺显示「—」）。
- 每组第一行是「组综合」：组内全部署名作品一次聚合，比率按合计重算，不是成员比率的平均。组内名单包括没有产出的在职成员（数值 0、比率「—」）。没同步复盘的作品只计入作品数，不参与播放和比率。历史月份按当前编制回看。

<a id="现行-个人曲线"></a>

### 四、个人档案的近 30 天曲线（2026-09-28 起）

- 窗口固定为上海时区含今天往前 30 个自然日，不跟随页面顶部选的月份。
- 作品归属和四个岗位榜单同源；抽屉从哪个岗位页签打开就只取该岗位的作品，小队详情里按小队工种换算。
- 三条率取每条作品最新 24h 快照，按单条视频口径算：没采快照、播放为 0 或指标缺值时为空（折线在这里断开，不折成 0%），这条作品只在图底挂一颗灰色虚环点，并提示「数据待采集（未满 24 小时）」；真实的 0% 照常连线。
- 「近 30 天均值」是加权口径（分子合计 ÷ 播放合计，只算已同步快照的作品），和岗位榜单、小队详情是同一个数，不是单条比率的算术平均。
- 代码：`src/lib/collaboration/domain/report-rules.ts#selectGrowthReports`、`src/lib/collaboration/domain/person-rules.ts#buildPersonGrowth`。

<a id="现行-入口"></a>

### 五、入口、代码与验证

- 入口：`/admin/collaboration` → `collaboration-data-container.tsx` → `src/lib/collaboration/data/dataset.ts` → 领域汇总。`src/lib/collaboration/domain/` 分担岗位、小队、个人的计算；范围用 `resolveCollaborationScope`。接口字段见[协作管理接口文档](../协作管理接口文档.md)。
- 必须保持：比率先合计再除；没有快照的作品不稀释均值；日期口径按本文件「作品算谁的」，和履约函数分场景使用。组员的只读放宽范围不传写入口；没有公司归属时退回本人。
- 验证（旧场景：本人降级后名单一致；小队汇总口径与角色隔离；范围另跑权限链路的验证）：

  ```sh
  npx tsx --test 'src/app/(app)/admin/collaboration/collaboration-scope-narrowing.test.ts' src/app/api/admin/collaboration/work-group-views.test.ts
  ```

## 历史决策

<a id="第1条"></a>

### 1 小队上限维持 20，前端刻意不禁选

**状态**：有效。实现验收另查当时证据。

**背景**：实际一次分配最多约 10 人；逐人写入仍需服务端护栏，但把几乎不会发生的场景做成前端禁选和计数器会增加交互复杂度。
**决定**：服务端去重后最多 20 人，超限在任何写入前拒绝；维持上限 20，前端不做禁选和人数计数器，只展示真实拒绝原因。
**后果**：安全边界在服务端，正常选择流程保持简洁；超限测试需证明零写入。
**证据**：[原始证据（38-64,80-83,137-155行）](../../archive/2026-11-09-A批文档治理/计划原稿/历史-项目/根治工程/2026-10-02-成员小队批量分配-架构重构方案.md)；[任务总纲](../../archive/2026-11-09-A批文档治理/计划原稿/历史-项目/根治工程/2026-10-02-全站架构根治工程-任务总纲.md)「五、决策记录」。
**日期**：2026-10-02

<a id="第2条"></a>

### 2 运营、文案、剪辑只算「给别人干的活」

**分类**：业务　**状态**：有效　**日期**：2026-08-31　**拍板人**：阿禅
**背景**：实查 8 月数据，33 个运营里 27 个是达人在运营自己的账号，刷满了运营列表。
**决定**：运营只算孵化别人的账号，纯自营的归达人；剪辑只算帮别人剪；文案当月至少帮别人写过 1 篇才入岗，入岗后统计当月全部署名文案（含自己账号），纯自写不入岗。
**证据**：[08-31 日志](../../archive/日志/2026-08/2026-08-31.md)；[岗位管理服务岗口径交接](../../archive/2026-11-09-A批文档治理/计划原稿/上下文交接/交接-2026-08-31-岗位管理服务岗口径.md)。

<a id="第3条"></a>

### 3 组员能看本公司所有人的数据

**分类**：业务　**状态**：有效，取代原先「组员只读自己」　**日期**：2026-09-23　**拍板人**：阿禅
**背景**：阿禅要组员能看本公司所有人的数据。
**决定**：组员可见本公司全体成员（含已归档成员的历史数据），「按团队」视图给组员看完整花名册和组汇总。
**后果**：当时一并接受了「计费条数与绩效明细对全员公开」；2026-11-19 起文案的计费明细已随 [作品评级链路第 2 条](作品评级链路.md#第2条) 从页面删除，结算只看「优」条数。
**证据**：[岗位管理对组员放开本公司范围实施方案](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-09-22-岗位管理对组员放开本公司范围-实施方案.md)；[09-23 日志](../../archive/日志/2026-09/2026-09-23.md)。

### 4 主表留哪些列

**分类**：业务　**状态**：有效　**日期**：2026-11-18，2026-11-19　**拍板人**：阿禅
**背景**：原文没写理由；阿禅原话「转粉和互动要，独立完成不要」。
**决定**：保留转粉率、互动率、互动数据、留存数据、良优率、导粉、账号排行、岗位归属提示、运营和剪辑页签；删掉独立完成、环比（连同只为环比载入的上月日报）、有效作品、优秀作品。

### 5 默认按总播放排，标题只写事实、不点名谁掉队

**分类**：业务　**状态**：有效　**日期**：2026-11-18　**拍板人**：阿禅
**背景**：要写「谁掉队」就得先定掉队标准，等于新定一条考核口径，不该由 AI 定。
**决定**：默认按总播放排序；标题只写事实，比如「11 月 · 全团 291 篇，良优率 35%」。
**证据**：[协作管理重塑方案](../../archive/2026-11-19-计划归档/计划原稿/2026-11-18-协作管理重塑方案.md)。

### 6 「具体数」和「达成比值」分开，小队表默认合并

**分类**：业务　**状态**：有效　**日期**：2026-11-19　**拍板人**：阿禅
**背景**：阿禅区分「具体数」与「达成比值」。

### 7 没认证的文案也进表，绩效先记「—」

**分类**：业务　**状态**：有效（现行做法）　**日期**：2026-09-08　**拍板人**：待核（开发施工记录，没见阿禅确认；涉及绩效）
