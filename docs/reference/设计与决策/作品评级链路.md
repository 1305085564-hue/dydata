## 现行设计

> 系统现在怎么算，以这里为准；为什么这样定，看下面的历史决策。改规则时先改这一段，再在文件末尾加一条历史决策写明为什么改。最后对过代码：2026-11-19。

<a id="现行-指标"></a>

### 一、基础指标

| 指标 | 怎么算 | 代码 |
|---|---|---|
| 24h 播放量 | 发布满 24 小时的播放量，原始值，是所有比率的分母 | `play_count` |
| 互动率 | (点赞 + 评论 + 收藏 + 分享) ÷ 播放 | `interactionRate()` |
| 点赞率 | 点赞 ÷ 播放 | `likeRate()` |
| 收藏率 | 收藏 ÷ 播放 | `favoriteRate()` |
| 转粉率 | 涨粉 ÷ 播放 | `followerConversionRate()` |
| 导粉率 | 导粉 ÷ 播放 | `fanConversionRate()` |

- 比率函数都在 `src/lib/video-metrics.ts`，按函数名找。比率叫「互动率」「转粉率」，原始计数叫「涨粉数」。互动率只有 `interactionRate()` 一种，已下线成长页的加权互动率不算现行规则。
- 点赞率、收藏率、转粉率、导粉率只作参考展示，不参与综合评级。话题分类只用于展示和选题分析，读取失败不影响评级计算。
- 主页访问率 2026-09-21 撤下：没有任何采集来源，写入恒为 0。字段和历史数据保留。
- 看结果先看 24h 播放；看单条好不好先看综合评级；看吸引力先看互动率，再看转粉率、导粉率。播放高、转化弱，先查内容承接；播放低、转化高，先查分发和选题。

<a id="现行-达成"></a>

### 二、互动达成与留存达成

- 两项都是相对「好标准」的达成比值，用百分数表示，可以超过 100%。
- **互动达成** = 互动率 ÷ 互动好标准 × 100%（标准线见[第 7 条](#第7条)）。
- **留存达成**（也叫留存分）由五项留存合成。高值指标按「实际值 ÷ 好标准 × 100%」，低值指标（2 秒跳出率）按「好标准 ÷ 实际值 × 100%」，跳出率实际为 0 时按 200% 计。

| 留存项 | 默认好标准 | 默认差线 | 权重 |
|---|---|---|---|
| 2 秒跳出率（越低越好） | 25% | >30% | 35% |
| 5 秒完播率 | 60% | ≤50% | 30% |
| 均播时长 | 50 秒 | ≤30 秒 | 合计 20% |
| 平均播放占比 | 25% | <20% | （与均播时长各算达成后取平均） |
| 整体完播率 | 10% | ≤5% | 15% |

- 均播时长和平均播放占比两项都有就取平均；只有一项时由它独占 20%，并记下折算方式；两项都没有，或另外三项任一缺失、不是有效数字，不生成留存分。
- 平均播放占比在快照里按 0–1 的小数存，展示和评价时换成百分数。
- 负责人可在评价标准页改留存好线、差线和四项权重，权重合计必须是 100%。
- 差线只用于页面上的不合格提示，不改变达成率、档位和评级。
- 单项档位：≥100% 为优，≥80% 为良，其余为普，没有劣。
- 代码：`src/lib/content-quality.ts`（留存计分与综合质量），文案和达人的单篇算法共用 `src/lib/collaboration/content-quality-contract.ts`。

<a id="现行-评级"></a>

### 三、综合评级

- 只用互动达成和留存达成两项，取平均：≥100% 为优，≥80% 为良，其余为普。
- 弱项最多被强项拉高一档：要拿优，两项都不能低于 80%；要拿良，两项都不能低于 60%。例如 200% 和 0%，平均 100%，但综合最多是普。
- 再按播放封顶，播放只会压低评级：播放未采集或为 0 不评级；低于 2,000 直接评普；2,000 至不足 5,000 最高普；5,000 至不足 15,000 最高良；15,000 起不封顶。这组门槛固定，不受公司「颜色样本下限」影响。
- 任一输入缺失不评级。状态有 `rated`、`unlinked`、`pending_snapshot`、`invalid_play`、`missing_metrics`、`topic_unavailable`；话题标签查询成功但没有标签按 `other`。
- 详情页的评级徽章直接用统一结果里的 `overallGrade`，不在详情里重算。
- 代码：`src/lib/breakout-rating.ts`（档位、拉高上限、播放门槛）。

<a id="现行-汇总"></a>

### 四、汇总：均值、良优率、条均播放

- 互动均值、留存均值只算播放 ≥2,000 且该项算得出的作品；2,000 以下多半被限流，数据失真。
- **良优率** = 评级为优或良的作品数 ÷ 已评级作品数；分母包含播放不足直接评普的作品。文案按署名日报计，达人按账号主人计；作品按日报条数计，作品去重只用于批量读取。
- **条均播放**：数据管理各表、个人档案和作者作品档案都用同一个函数 `averagePlayOf`（`src/lib/metrics/caliber.ts`）。只算有效样本里播放 ≥2,000 的作品，取整；有效样本里一条都不到 2,000 时为 0；完全没有有效样本时为空，不显示成 0。

<a id="现行-颜色"></a>

### 五、标准线与颜色

- 视频复盘列表和详情里的数字颜色按公司评价标准：好的标红、差的标绿，好线和差线就是上面的留存表；互动率按互动标准线。
- 颜色样本下限默认 5,000，公司可在评价标准页调整（`minPlayCount`）。
- 复盘队列的异常提醒线固定：播放 5,000、2 秒跳出 30%、5 秒完播 50%、均播时长 30 秒、整体完播 5%，不随公司设置变化。
- 列表里的核心指标保留自己的颜色表现，不替代互动和留存考核。

<a id="现行-结算"></a>

### 六、结算，以及已下线和未实现的口径

- **文案结算**只看综合评级为「优」的署名作品条数（文案表「优条数」，与良优率同源，按署名日报计）。单价不在系统里，由结算方按条数核算；未认证的文案不计。
- 文案、达人表的互动列叫「互动达成」，和互动率并存；达人个人明细的转粉率、涨粉评级已退出，岗位汇总里的转粉率和个人 30 日曲线保留，不参与评级。
- **已下线**：2026-11-19 删除爆款概念（爆款系数、账号基线冷启动、岗位「爆款数」、口径页的爆款判定），以及有效作品（播放 >500）、优秀作品（播放 ≥3 万）、绩效条数、计费明细与对账、运营和达人表的有效与优秀列、运营个人档案「爆款作品」、达人表「独立完成」、运营表与运营档案的「环比」。旧口径只在 git 历史里。
- **已下线**：个人成长页的六维能力口径，2026-09-26 随成长页一起下线，没有任何在用的地方。历史契约见 `docs/archive/个人成长数据契约.md`，不能拿来当新功能的依据。
- **未实现**：下滑判定（近 7 条播放中位数比前 7 条下降 30% 以上；两个窗口都要有足够样本，前 7 条中位数为 0 或为空不判定）只是备查口径。2026-09-27 核对时全仓没有任何实现，任何页面都没有生效。

## 历史决策

<a id="第1条"></a>

### 1 互动留存三档评级与主指标下线

**状态**：有效，2026-11-16 定稿。

**决定**：达人岗与文案岗共用互动达成、留存达成两项评级，综合只输出优/良/普；播放低于 2000 直接评普，历史缺平均播放占比时按均播时长独占组合权重。主指标从展示和计算概念中移除，点赞率、收藏率、转粉率只作参考。

**后果**：质量均值使用 2000 播放线，颜色使用 5000 播放线；接受均播折算可能偏向长视频，本轮不修正。数据库先保留兼容列并返回空值，待新页面核对后再删列。

<a id="第2条"></a>

### 2 以综合评级「优」取代爆款与按条数计费

**状态**：有效，2026-11-19 本地完成，尚未 push。取代数据口径第 3 节的爆款系数口径与第 11 节「岗位质量与文案计费（2026-09-07）」。

**背景**：爆款规则和有效条数服务于旧的按条计费：文案按署名条数扣 25 条基准算钱，播放不足 500 的不算有效。现在拿钱看综合评级「优」，内容好是目的，流量是附带结果。旧概念并存会让同一页面出现两套"好"的定义，其中爆款系数在生产代码里早已无调用方。

**决定**：删除爆款系数、账号基线冷启动、岗位管理「爆款数」和数据口径页的爆款判定；删除岗位表的「有效作品」「优秀作品」及文案的绩效条数、计费明细与对账；文案表新增「优条数」，与良优率同源。文案结算只看优条数，单价不入系统。评级播放门槛不变：低于 2000 评普且不进均值，5000 以下最高普，5000 至不足 15000 最高良，15000 起不封顶。复盘页「昨日爆款」改名「昨日评优」，其筛选本来就是综合评级为优。同日追加：删除达人表「独立完成」（达人几乎都自己包办，数字区分不出差别）与运营表、运营个人档案的「环比」（只看总播放涨跌），连带删除仅为环比服务的上月日报载入；文案、达人表的「互动数据」列改名「互动达成」；转粉率、导粉、账号排行、岗位归属提示、运营与剪辑页签经阿禅确认保留。第三轮：区分「定量的数」（互动率、赞评转藏率、2 秒跳出率等原始值）和「相对标准的达成比值」（互动达成、留存达成），文案、达人表的「留存数据」列实为达成比值，改名「留存达成」；小队表的「内容质量」改称「综合达成」（= 互动达成 + 留存达成），默认只看合并总数，点「展开明细」拆出互动四项（点赞、评论、转发、收藏率，四项相加等于互动率）和留存五项（2 秒跳出率、5 秒完播率、均播时长、播放占比、整体完播率；按作品算术平均，样本与留存达成相同）。点赞率、收藏率因此从默认表头收进明细。文案表、达人表本轮未加展开。

**后果**：旧计费口径只留在 git 历史。岗位表不再有按播放量判断的指标。运营个人档案少一格。`historyRows` 仅服务爆款数，一并从数据集与个人档案载入中移除，不影响取数范围（月报日报一次查询的范围不变）。文案岗位本身与认证流程保留。

**日期**：2026-11-19

<a id="第3条"></a>

### 3 平均播放只算播放 2000 以上的作品

**分类**：业务　**状态**：有效　**日期**：2026-10-15；2026-11-18 作者档案对齐　**拍板人**：待核（方案写「老板拍板的业务理由」，由规划方照写）；作者档案对齐为阿禅
**背景**：没跑起来的作品不代表真实水平；跑了一万被限流的数据依然有效，无效的是压根没播放的。
**决定**：播放低于 2000 的作品不进「平均播放」；数据管理、作者档案、口径页都用同一条线。
**证据**：[数据口径说明页与一致性修复](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-10-15-数据口径说明页与一致性修复.md)；[11-18 拍板清单 D9](../../archive/2026-11-18-计划归档/计划原稿/2026-11-18-业务逻辑治理-审计结论与拍板清单.md)。

### 4 综合评级取两项平均，弱项最多被拉高一档

**分类**：业务　**状态**：有效，取代「取两项里最低的一档」　**日期**：2026-09-30，2026-10-12　**拍板人**：阿禅
**背景**：阿禅原话：「不再按照最低那个算了。」又要防止偏科严重的作品被另一项拉得太高。
**决定**：综合档位按两项平均达成定，但不能比较差那一项高出一档以上。

### 5 播放量给综合评级封顶：不到 5000 最高普，不到 15000 最高良

**分类**：业务　**状态**：有效　**日期**：2026-11-16　**拍板人**：阿禅（原话带「还得讨论一下」，施工已按此落地）
**背景**：阿禅原话：「只分三档优良普，没有劣了……15000 是优的底线，良才是 5000–14999，普是 5000 内。」旧规则让 5000–14999 的作品永远到不了良。
**决定**：播放只封顶、不直接定档：低于 5000 最高普，5000–14999 最高良，15000 以上才可能优；低于 2000 直接评普。

### 8 数字颜色：好的标红、差的标绿，只标单个数字

**分类**：设计　**状态**：有效　**日期**：2026-10-24，2026-10-27　**拍板人**：阿禅
**背景**：财经语境「红涨绿跌」：好用红，差用绿；普通的不上色。
**决定**：每个数据格只做好 / 普通 / 差三种标注，不给整条作品打「数据优秀 / 异常」的总评；阈值全公司一套（见数据口径页）。

### 10 留存数据和良优率是两个指标，两个都要

**分类**：业务　**状态**：有效　**日期**：2026-11-16　**拍板人**：阿禅
**背景**：页面曾把良优率标成了「留存数据」。
**决定**：两个名字、两个数各自显示，不能合并。
**证据**：[互动留存三档评级与主指标下线评审稿](../../archive/2026-11-18-计划归档/计划原稿/2026-11-16-互动留存三档评级与主指标下线-施工.md)。
