## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。完整数据字段与顺位契约见[AI 配置数据契约](../2026-11-05-AI配置重整-数据契约.md)。最后对过代码：2026-11-27。

<a id="现行-布局与视角"></a>

### 一、权限与页面结构

- 权限：进入 `/admin/ai-config` 先核对 `manage_system` 权限（`canAccessAdminPath`），未登录跳转 `/login`，无权跳转 `/admin`。
- 双区块布局（`src/app/(app)/admin/ai-config/ai-config-shell.tsx`）：
  1. **「功能用哪个模型」**（`BusinessFunctionsPanel`）：列出各已启用 AI 业务及唯一「全局默认」行（`key="default"`），直接展示服务端计算的正常 / 顶班 / 停摆状态；出现停摆或顶班时提供「去修 →」滚动定位到下方对应模型卡；「截图识别」行附带「测速台账」抽屉入口（最近 1000 次耗时汇总 + 最近 100 笔明细）。
  2. **「模型从哪些渠道来」**（`ComputePoolPanel`）：支持「模型视角」与「渠道视角」对等切换。模型视角展示每个标准模型（`canonical_model_id`）下的渠道排队顺序、可用数、单点提醒及「为此模型找渠道」；渠道视角支持接入新密钥、同步上游真实清单、勾选在供模型、整渠道或单供应测试。
- 顶部标题由 `buildAiConfigHeadline(bundle.availability.businessSummary)` 动态汇总当前业务保障与需处理渠道数。

<a id="现行-操作与检测"></a>

### 二、唯一状态源与操作守则

- 页面所有状态统一读取 `GET /api/admin/ai-config` 返回的 `bundle.availability`，不在前端依据开关或失败次数重算可用性；密钥在接口层仅返回末四位掩码。
- 所有写操作统一走 `POST /api/admin/ai-config`（`useAiConfig().runCommand`）；停用或删除会令活跃业务无可用模型时，后端先返回 409 与影响名单（`requiresConfirmation`），经管理员确认后才执行；修改共享地址影响多条渠道时另行触发 `confirm_shared_address` 确认。
- 批量检测（顶部「检查一遍」与渠道「检测此渠道」）前端采用 120 秒有界刷新；接口中断或超时不自动重跑检测，最终读取失败时常驻显示未同步提示与手动重读入口。
- 废弃旧列治理与报错收口（2026-11-27）：应用层已彻底清零对 4 个废弃旧列（`global_is_enabled`、`provider_key_model_id`、`priority` 等）的业务读写，且全组 AI 配置接口失败统一返回友好中文提示与 `requestId`（不透传底层数据库或模型原文）；暂缓删列迁移 `supabase/deferred-migrations/20261105072558_ai_config_drop_legacy_columns.sql` 保持暂缓，待新版稳定运行满 3 天并跑完前置只读核查零依赖后择机执行。

## 历史决策

<a id="第1条"></a>

### 1 页面上只有一个心智：业务选模型，模型里排渠道

**分类**：业务　**状态**：有效　**日期**：2026-11-05　**拍板人**：阿禅（8 条口径）
**背景**：少一个看不见的设置；想调顺序只有一个地方。
**决定**：业务只选模型，删掉「钉渠道」；只剩一种顺序，就是模型卡里渠道的排队顺序，删掉渠道优先级数字；渠道状态只说三句人话：「能用」「暂时歇着（系统会自己再试）」「需要你处理（附原因）」，自己关掉的显示灰色。顶班时写「X 暂时不可用，当前优先使用默认 Y」。
**后果**：停摆提醒只做页面标红和顶部摘要，不做站内通知和飞书推送（CC 裁定，以后要再加）。
**证据**：[AI 配置页口径重整总方案](../../plans/2026-11-05-AI配置页口径重整与链路精简-总方案.md)。

<a id="第2条"></a>

### 2 配置页是用来「找」的，不是用来「读」的

**分类**：设计　**状态**：有效　**日期**：2026-11-05　**拍板人**：阿禅
**背景**：开关和状态标签要是藏起来，就看不出哪条渠道关着。
**决定**：高密度排布；停用的模型默认收起，但「为此模型找渠道」、开关、状态标签和改名铅笔始终显示。模型卡按「有业务在用 → 能用 → 暂时不可用 → 已停用」排，各列表能用的在上；进页面、切视角、打开弹窗时排一次，操作中不跳行；渠道排队顺序不动。
**证据**：[AI 配置页高密度改版任务书](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-11-05-AI配置页高密度改版-Antigravity任务书.md)；[11-05 日志](../../archive/日志/2026-11/2026-11-05.md)。

<a id="第3条"></a>

### 3 模型视角和渠道视角地位对等

**分类**：设计　**状态**：有效，取代 10-09 早先「渠道只是模型下面一层明细」（已明确作废）　**日期**：2026-10-09　**拍板人**：待核（文件写「决策方：阿禅」，这条没见逐句原话）
**背景**：原文没写理由。
**决定**：模型视角和渠道视角是同一份数据的两种分组，随时切换，任一视角都能完成全部管理动作。
**证据**：[AI 算力储备三视角纠偏返工执行规格](../../archive/2026-11-09-A批文档治理/计划原稿/2026-11-09-计划收尾/2026-10-09-AI算力储备三视角纠偏返工-执行规格.md)。

<a id="第4条"></a>

### 4 渠道名在界面上就地改，不做自动清洗

**分类**：业务　**状态**：有效；模型显示名的改名入口 11-15 从渠道行移到了模型标题（修误改同型号的问题）　**日期**：2026-10-09　**拍板人**：阿禅
**背景**：不跑数据清洗、不猜、不做映射。
**决定**：存量渠道名由阿禅在界面上逐条定名，渠道名支持就地改。
**证据**：[AI 算力储备两视角重定执行规格](../../archive/2026-11-09-A批文档治理/计划原稿/2026-11-09-计划收尾/2026-10-09-AI算力储备两视角重定-执行规格.md)；[模型显示名修复上线核对](../../archive/2026-11-20-参考归档/参考原稿/2026-11-15-模型显示名修复与工作台累计上线核对.md)。

<a id="第5条"></a>

### 5 收走已确认失效的模型不再二次确认，其余危险动作要列名单

**分类**：业务　**状态**：有效　**日期**：2026-10-10　**拍板人**：阿禅（点头）；「列名单、取不到就拒绝」是同批冻结裁决，没写阿禅
**背景**：名单已经显示在同一面板上，后端有依赖检查兜底，审计写失败会自动回滚。
**决定**：同步弹窗里，单条收走和「一键收走全部已确认失效模型」不再弹确认；只限「清单里没有 + 实测不通」两个信号同时成立的模型，「疑似」的不给收走入口。停用或删除接入点、全站下架、跨渠道批量启用仍要确认，确认时必须逐条列出被牵连对象的真实名称，取不到完整名单就拒绝执行。
**证据**：[AI 算力储备概念补全与危险动作治理执行规格 v2](../../archive/2026-11-09-A批文档治理/计划原稿/2026-11-09-计划收尾/2026-10-09-AI算力储备概念补全与危险动作治理-执行规格v2.md)。
