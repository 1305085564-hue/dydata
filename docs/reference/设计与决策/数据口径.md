## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。指标公式与评级阈值真源见[作品评级链路·现行设计](作品评级链路.md#现行设计)。最后对过代码：2026-11-27。

<a id="现行-双页签"></a>

### 一、权限与双页签结构

- 入口与权限：`/admin/caliber`（页头「数字怎么算，多少算好」）先做 `canAccessAdminPath("/admin/caliber", ...)` 校验，未登录跳转 `/login`，无权跳转 `/admin`。服务端通过 `loadEvaluationSettings` 读取当前公司的评价标准；**仅公司负责人可编辑保存**（`canEditEvaluationStandards`），其他有访问权的管理员只读查看。
- 页面由 `EvaluationStandardsTabs` 分为两个页签：
  1. **「口径说明」**：以卡片逐条说明全站 8 条核心业务规则（产量口径、平均播放有效线 `2,000`、互动率/转粉率加总再除、归属日期、补交门禁 `72 小时`【注：C3「72 小时超期先交后核」规则待对话 2 合并后同步更新】、三个岗位视角与达人总产量、双截图识别+人工核对、未绑作品老日报口径）。所有规则数字直接读取 `CALIBER`（`src/lib/metrics/caliber.ts`），不在页面文案里手写硬编码。
  2. **「评价标准」**：全公司共用一套标准，可配置标色样本下限 `minPlayCount`（默认 5,000，优质/标色统计基础）、互动率与转粉率基准、互动达成好/差线、五项留存好/差线（默认含平均播放占比差线 20%）与四项留存权重（合计必须为 100%）。

<a id="现行-边界"></a>

### 二、可配置范围与固定红线

- 本页保存的 `minPlayCount` 仅控制视频复盘与协作管理岗位表/个人作品明细的「好红差绿」标色样本门槛（小队表固定按 2,000 综合基础降灰）。
- 两组固定规则**不随本页配置变化**：① 综合评级的播放封顶门槛（2,000 / 5,000 / 15,000）；② 复盘队列的异常提醒线（播放 5,000、2 秒跳出 30%、5 秒完播 50%、均播时长 30 秒、整体完播 5%）。

## 历史决策

<a id="第1条"></a>

### 1 评价标准全公司一套，只有负责人能改

**分类**：业务　**状态**：有效，取代 10-24「阈值第一期写死在代码里」　**日期**：2026-10-24，2026-10-28　**拍板人**：阿禅
**背景**：每个人看到的颜色必须一致。
**决定**：评价标准全公司一套，不做按人配置；只有负责人能改，普通管理员只读；入口在本页「评价标准」，不放在视频复盘的筛选栏里。
**证据**：[视频复盘阈值与颜色分档补充单](../../archive/2026-11-09-A批文档治理/计划原稿/2026-11-09-计划收尾/2026-10-24-视频复盘阈值与颜色分档-补充单.md)；[10-28 日志](../../archive/日志/2026-10/2026-10-28.md)；[评价标准本地验收](../../archive/2026-11-09-A批文档治理/参考原稿/2026-10-28-评价标准本地验收.md)。

<a id="第2条"></a>

### 2 异常提醒的线固定，不跟评价标准变

**分类**：业务　**状态**：有效（现行做法）　**日期**：2026-09-26 起　**拍板人**：待核
**背景**：原文只写「固定」，没写理由。
**决定**：视频复盘队列的异常提醒固定用播放 5000、2 秒跳出 30%、5 秒完播 50%、均播 30 秒、整体完播 5%，不随公司评价标准变。
**证据**：[作品评级链路·标准线与颜色](作品评级链路.md#现行-颜色)。

<a id="第3条"></a>

### 3 页面上的数字只从一个地方读

**分类**：代码　**状态**：有效　**日期**：2026-10-15　**拍板人**：CC（规划方案）
**背景**：页面手写数字的话，代码改了页面没改，老板会拿着错的规则做决策，比没有说明更危险。
**决定**：口径页只读系统统一的口径常量，页面文案里不手写任何数字。
**后果**：评价标准的颜色阈值现在存在公司设置里，不在口径常量里，两处并存，改口径时两边都要看。
**证据**：[数据口径说明页与一致性修复](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-10-15-数据口径说明页与一致性修复.md)。
