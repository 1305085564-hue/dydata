# 设计与决策总纲

> DYData 设计与决策体系总纲：页面与链路的模块地图、文件写作规范。执行规则与高频文档映射见 [`AGENTS.md`](../../../AGENTS.md)。

## 一、模块地图

**页面**（详见本文件夹内页面文件）：数据上传（工作台）、视频复盘、数据管理、发布管理、审批工作台、选题库、成员主页、每日大盘、AI配置、数据口径、成员与团队管理、登录与注册

**链路**（详见本文件夹内链路文件）：数据上传、审批、作品评级、权限、AI调用、选题入库

> 无单独页面文件的底层模块：通知系统（待办推送，完成和已读直连接口）、提醒（只留 `/api/remind/count` 供豁免弹窗读计数）、定时任务（保活数据库、清理过期通知）。已废弃页面见[工程底座·已废弃](../工程底座.md#现行-已废弃)，禁止复活。

## 二、文件写作规范

- **唯一规则真源（禁建平行副本）**：全站业务口径与产品规则只维护本目录这一套长期真源。新建任何规则、规范或总览前，必须先检查现有页面/链路文件能否复用与承载，禁止在仓库别处另起第二套常驻规则文件（避免双份维护和口径漂移）；对外需要给团队看白话摘要时，按需从本目录现行设计临时提炼即可。
- **两段式结构**：页面、链路文件分「现行设计」（上段，只写现况，不写过程）和「历史决策」（下段，记为什么这么定、放弃了什么、谁拍的板；只往后加，旧条不改正文）。
- **归口原则**：只影响一页记页面文件；跨两页以上记链路文件。同一件事只写一处，别处放链接；先改上段，再在下段末尾按 `1..N` 顺编一条（新条目取代旧条目时互注）。找不到原话的拍板人写「待核」，产品/业务取舍必须由阿禅拍板。
- **代码对账**：上段与代码冲突时先核真实代码，上段写错了当场改上段，代码偏了交阿禅定。
- **新建页面或链路文件格式**：按下面结构新建，并加进上面模块地图：

```markdown
# 页面：名字（或「链路：名字」）

> 地址或范围｜牵涉链路或涉及页面

<a id="现行设计"></a>

## 现行设计

> 最后对过代码：YYYY-MM-DD

<a id="现行-小节名"></a>

### 一、小节名

## 历史决策

<a id="第N条"></a>

### N 标题

**分类**：业务 / 设计 / 性能 / 代码　**状态**：有效 / 已被第 N 条取代　**日期**：YYYY-MM-DD　**拍板人**：阿禅
**背景**：为什么要定　**决定**：当时定了什么　**后果**：代价、放弃了什么、以后必须保持什么（可省）　**证据**：链接
```
