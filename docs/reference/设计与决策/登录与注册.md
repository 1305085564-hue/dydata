## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。最后对过代码：2026-11-27。

<a id="现行-登录"></a>

### 一、登录流程（`/login`）

- 入口：`src/app/(auth)/login/page.tsx`（Server Action `loginAction`）+ `login-form.tsx`，底层统一经 `@/lib/supabase/server` 转接腾讯云 CloudBase 认证。
- 表单校验：邮箱与密码必填；提供「保持登录（30 天免密）」勾选项，勾选后写入 `HttpOnly` 30 天 Cookie（`KEEP_LOGGED_IN_COOKIE_NAME`），不勾则随浏览器会话失效。
- 在职门禁：认证通过后立即读取 `profiles`（`role`、`membership_status`）。若资料缺失或 `membership_status === "archived"`，立刻执行 `signOut()` 并清空截图票据 Cookie（`GRANT_COOKIE_NAME`），拦截登录并提示联系负责人恢复。
- 登录后跳转：按 `getPostLoginRedirectPath(profile.role, params.next)` 安全跳转（校验 `next` 防开放重定向）。

<a id="现行-注册与找回"></a>

### 二、注册与找回密码

- **注册（`/register`）**：`src/app/(auth)/register/page.tsx` 调用 `registerUser`（`src/lib/auth-registration.ts` → `runCloudBaseRegistrationFlow`）。**无需邀请码**，选择目标团队后提交创建账号并进入团队审核流程；任一步失败带 `requestId` 写结构化错误日志并自动执行 `rollbackCloudBaseEmployee` 回滚。
- **找回 / 重置密码（`/forgot-password`、`/reset-password`）**：均渲染 `PasswordResetNotice` 组件，明确提示自助邮件改密渠道尚未启用，引导联系管理员在后台手工重置密码（正式邮件找回列在待办 C7）。
- **性能保护**：首页及登录、注册、找回密码页的相互跳转链接统一关闭 Next.js 预加载（`prefetch={false}`），降低无效请求。

<a id="现行-入口"></a>

### 三、入口、代码与验证

- 入口：`src/app/(auth)/{login,register,forgot-password,reset-password}/page.tsx`、`src/lib/auth-password.ts`、`src/lib/auth-registration.ts`、`src/app/api/cloudbase/auth/{signin,refresh,signout}/route.ts`。
- 验证：`npx tsx --test src/app/api/cloudbase/routes.test.ts src/middleware-member-lifecycle.test.ts`。

## 历史决策

<a id="第1条"></a>

### 1 忘记密码只提示联系管理员重置

**分类**：业务　**状态**：有效（正式邮件找回列在待办，切换后立项）　**日期**：2026-11-02　**拍板人**：阿禅
**背景**：找回密码功能一直是坏的，现在由管理员手工给员工重置。
**决定**：登录页「忘记密码」直接提示「修改密码渠道暂时还没启用，请联系管理员为你重置密码」，不进坏掉的流程，也不发旧通道的邮件。
**证据**：[11-02 日志](../../archive/日志/2026-11/2026-11-02.md)；[密码找回入口止血验收](../../archive/2026-11-09-A批文档治理/参考原稿/2026-11-02-密码找回入口止血验收.md)。

<a id="第2条"></a>

### 2 注册不要邀请码，选团队后等审核

**分类**：业务　**状态**：有效（现行做法）　**日期**：2026-05-11　**拍板人**：待核（只有开发交付记录）
**背景**：登录验证码早已取消，注册邀请码没同步处理，事情做了一半。
**决定**：注册不需要邀请码，只选想加入的团队；注册后账号处于待审核。旧的邀请码表和校验函数保留，没删。
**后果**：待审用户是「进系统后顶部横幅提示」还是「登录后拦在等待页」，方案和现状不一致，现状未逐行核对。
**证据**：[申请审批制注册方案](../../archive/2026-08-22-文档瘦身/plans/_跨模块/申请审批制注册方案.md)；[05-11 补录日志](../../archive/日志/2026-05/2026-05-11-补录.md)。

<a id="第3条"></a>

### 3 勾选「保持登录」30 天免密

**分类**：业务　**状态**：有效（现行做法）　**日期**：2026-07-17　**拍板人**：待核
**背景**：原文没写理由。
**决定**：登录页的勾选框从「记住邮箱」改成「保持登录（30 天免密）」；勾选后登录状态保留 30 天，不勾就随浏览器会话结束。
**证据**：[07-17 日志](../../archive/日志/2026-07/2026-07-17.md)。

<a id="第4条"></a>

### 4 登录、注册、找回密码页关掉链接预加载

**分类**：性能　**状态**：有效　**日期**：2026-11-05　**拍板人**：待核（排查服务器超额时定的）
**背景**：为了降低重复页面请求和服务器负担。
**决定**：首页、登录、注册、找回密码以及「返回登录」链接不预加载，接受点击后稍等一下；登录后的工作台和数据页面不受影响。
**证据**：[CPU 超额调查与降耗](../../archive/2026-11-09-A批文档治理/参考原稿/2026-11-05-CPU超额调查与降耗.md)。
