<a id="现行设计"></a>

## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。最后对过代码：2026-11-18。

<a id="现行-结构"></a>

### 一、选题的结构

- 母题（`topics`）→ 分组（`topic_groups`）→ 子题（`sub_topics`）。
- 点「开始写作」，`sub_topic_claims` 记录在写、取消、完成；作品通过 `videos.topic_id` 关联子题。
- 多人同时在写同一题时，展示真实的写作动态。

## 历史决策

<a id="第1条"></a>

### 1 选题入库门槛固定为 30000

**状态**：有效。实现验收另查当时证据。

**背景**：自动入库方案的配置化会引入第二个口径，且没有确认的消费者、作用域、历史重算和回滚规则。
**决定**：入库门槛写死 `30,000`，关闭配置化；不新增配置字段、配置入口或 migration。
**后果**：所有入库、达标作品数和筛选语义继续使用固定常量；未来若重开，必须先补齐产品决策与数据口径。
**证据**：[原始证据（10-24,70-81行）](../../archive/2026-11-09-A批文档治理/计划原稿/历史-项目/根治工程/2026-10-02-选题自动入库与认领-架构重构方案.md)（明确“不施工”、不得配置化）。
**日期**：2026-10-02

<a id="第2条"></a>

### 2 选题库只收干货，复盘不进；转推和无标签按复盘算

**分类**：业务　**状态**：有效　**日期**：2026-08-29，2026-09-21　**拍板人**：阿禅
**背景**：复盘根本不是选题来源，播放再高也不该进库。
**决定**：只有干货作品达标才进选题库，复盘永远不进，所以选题库也不设「干货 / 复盘」筛选；视频转推和没打标签的作品一律按复盘处理。
**证据**：[选题库 V3 五批进度（已确认的产品方向）](../../archive/2026-11-09-A批文档治理/计划原稿/历史-报告/2026-08-29-Topics-V3-五批进度.md)；[09-21 日志（20:05 条）](../../archive/日志/2026-09/2026-09-21.md)。

<a id="第3条"></a>

### 3 达标的干货自动进库，不经管理员审核

**分类**：业务　**状态**：有效　**日期**：2026-08-29　**拍板人**：阿禅
**背景**：阿禅原话：「不要管理员审核以后进入，而是默认进入，管理可以看到哪些进入、各自怎么样，可以选择移除哪些。」
**决定**：达到门槛（[第 1 条](#第1条)）的干货默认进库；管理员事后看、事后移出。
**证据**：[选题库 V3 五批进度](../../archive/2026-11-09-A批文档治理/计划原稿/历史-报告/2026-08-29-Topics-V3-五批进度.md)。

<a id="第4条"></a>

### 4 移出是软移出，不删数据，不会被自动恢复

**分类**：业务　**状态**：有效　**日期**：2026-09-12　**拍板人**：阿禅（补充的施工边界）
**背景**：原文没写理由。
**决定**：移出只改状态并留审计，题目、作品、写作记录、复盘、导入历史都保留；管理员移出的题，任何刷新、重复提交都不会把它恢复，只能管理员手动恢复。
**证据**：[09-12 日志](../../archive/日志/2026-09/2026-09-12.md)；[选题库接口文档](../选题库接口文档.md)。

<a id="第5条"></a>

### 5 选题库按团队隔离；管理端的选题状态全公司可见

**分类**：业务　**状态**：有效　**日期**：2026-09-04，2026-09-12　**拍板人**：阿禅
**背景**：原文没写理由；管理端全公司可见是盲审时被当成问题，阿禅确认是有意的。
**决定**：选题库只按成员所属团队隔离，不引入集团范围；管理端查看选题库状态是全公司视图。
**证据**：[09-12 日志](../../archive/日志/2026-09/2026-09-12.md)；[第二轮全站质量盲审](../../archive/第二轮全站质量盲审-系统内部视角-2026-09-04.md)。

<a id="第6条"></a>

### 6 选题三个来源：作品自动进库、批量导入、手动录入

**分类**：业务　**状态**：有效　**日期**：2026-08-29　**拍板人**：阿禅（三个来源）；「批量导入只给管理员」没见阿禅原话
**背景**：批量导入和手动录入职责不同。
**决定**：选题来自三处：自己的作品数据自动进库、批量导入、手动录入。批量导入只给管理员；手动录入在页面里，成员可用；不恢复旧的全局悬浮录入。
**证据**：[选题库 V3 五批进度](../../archive/2026-11-09-A批文档治理/计划原稿/历史-报告/2026-08-29-Topics-V3-五批进度.md)。

<a id="第7条"></a>

### 7 同一个题允许多人同时写，没有名额

**分类**：业务　**状态**：有效，取代 07-15 规格和 07-23 实现里的「候选 5 条上限、满了要替换」　**日期**：2026-08-29　**拍板人**：阿禅
**背景**：阿禅原话：「好的选题就是会被重复写，重复爆，永久保留。」认领不是抢占。
**决定**：同一子题多人可以同时写，页面上叫「在写」；不做撞车拦截、名额限制、替换认领；好选题永久保留。
**证据**：[选题库 V3 五批进度](../../archive/2026-11-09-A批文档治理/计划原稿/历史-报告/2026-08-29-Topics-V3-五批进度.md)；[选题库接口文档](../选题库接口文档.md)。
