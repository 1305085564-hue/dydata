## 现行设计

> 系统现在怎么做，以这里为准；为什么这样定，看下面的历史决策。最后对过代码：2026-11-27。

<a id="现行-结构"></a>

### 一、入口、分区与角色边界

- 入口：不设独立审批页面，由顶部导航栏「待办 N」触发全站抽屉（`src/components/approval-workbench/approval-workbench.tsx`）。
- 角色视图：管理员可见「待处理」与「已处理记录」双视图，其中「待处理」分 **「等你批」**（请假/免交申请 + 补交申诉，按涉及日期由近到远排序）和 **「等你处理」**（待办通知跳转）；普通成员仅见「等你处理」列表，无审批队列与历史 tab。
- 权限申请不并入审批工作台，仍在成员与团队管理页处理。

<a id="现行-卡片与操作"></a>

### 二、卡片内容、就地操作与撤回

- **卡片内容**（`queue-item.tsx`）：申请人头像与姓名、团队、类型与天数（如「请假 2 天」「长期免交」「补交申请」）、涉及业务日期、申请理由及附件，**保留「本月已批天数」**（`getMonthContext`，2026-11-27 阿禅拍板保留），不展示当月履约率或出勤统计。
- **操作方式**：支持整单/逐日点击「同意」；点「拒绝」在卡片内就地展开原因输入框（`RejectReason`，回车确认、Esc 收起，不弹窗）；管理员顶部提供「全部同意」，确认前校验快照 ID 集合是否变化，若队列变动则中止并刷新。
- **撤回与打回**：撤回提示固定在底栏（`use-approval-undo-queue.ts`），列表不跳动；「已处理记录」（`history-list.tsx`）支持管理员打回重审。
- **键盘导航**：打开后焦点重置首行（从待办入口进入落到待办第一条），支持键盘操作与 Esc 关闭；关闭时自动收起未提交的拒绝原因框。
- **超期/手改时间事后核查（C3，2026-11-27 落地）**：`review_mode='post_submit'` 卡片展示触发原因与作品链接，提供「确认正常」与「标为无效（不计优结算）」（点击就地展开原因输入、原因必填）；标为无效自动同步 `videos`/`daily_reports` 的 `settlement_excluded=true` 并从文案优条数剔除，已处理记录点「打回待处理」对称恢复。历史遗留 `pre_submit` 前置补交单继续按原「同意/拒绝」兼容处理。

## 历史决策

<a id="第1条"></a>

### 1 不做：卡片第三个按钮、员工「申请进度」视图、独立审批页面

**分类**：业务　**状态**：有效。2026-10-15 有一份需求稿提出员工侧「我的申请」台账，状态是待阿禅评审，没有施工　**日期**：2026-10-03　**拍板人**：阿禅
**背景**：原文只写「已明确否决，任何阶段禁止顺手加回」，没写理由。
**决定**：卡片右侧不加「批注」第三个按钮；不给员工做「申请进度」视图；不做独立的审批页面，审批只在导航栏的待办面板里做。
**证据**：[审批工作台体验重塑施工单](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-10-03-审批工作台体验重塑-施工单.md)。

<a id="第2条"></a>

### 2 补交申诉并入「待审批」，权限申请不并进来

**分类**：业务　**状态**：有效；10-08 一次界面改版写过「权限申请等待办合流到待处理主流」，没见阿禅确认，现状待核　**日期**：2026-10-03　**拍板人**：阿禅
**背景**：原文没写理由。
**决定**：补交申诉和请假、豁免一起放在「待审批」里处理；权限申请不收编进审批。
**证据**：[审批工作台体验重塑施工单](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-10-03-审批工作台体验重塑-施工单.md)。

<a id="第3条"></a>

### 3 卡片只放这一单相关的数字

**分类**：业务　**状态**：有效（2026-11-27 阿禅拍板明确保留卡片上的「本月已批天数」，不视作违规；其余当月履约率或出勤统计仍不放进卡片）　**日期**：2026-10-03，2026-11-27　**拍板人**：阿禅（2026-11-27 复核确认）
**背景**：当月履约率、出勤统计在审批的那一刻就会变，放上去会误导。
**决定**：卡片只放类型、业务日期、缺勤天数、理由、附件；不放当月履约率或出勤统计。
**证据**：[审批工作台体验重塑施工单](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-10-03-审批工作台体验重塑-施工单.md)；[11-18 重做上线核对](../../archive/2026-11-20-参考归档/参考原稿/2026-11-18-审批工作台重做上线核对.md)。

<a id="第4条"></a>

### 4 拒绝不弹窗，在卡片上直接填原因

**分类**：设计　**状态**：有效　**日期**：2026-10-03　**拍板人**：阿禅
**背景**：原文没写理由。
**决定**：点「拒绝」在卡片里就地展开原因输入框，回车确认、Esc 收起，不弹窗。补交的原因必填，请假和免交可以不填（这个区分是 11-18 施工时定的，没见阿禅确认）。
**证据**：[审批工作台体验重塑施工单](../../archive/2026-11-09-A批文档治理/计划原稿/历史-方案/2026-10-03-审批工作台体验重塑-施工单.md)；[11-18 重做浏览器验收交接](../../archive/2026-11-19-计划归档/计划原稿/2026-11-18-审批工作台重做-浏览器验收交接.md)。

<a id="第5条"></a>

### 5 2026-11-18 重做：分「等你批」「等你处理」两段

**分类**：设计　**状态**：有效，取代此前五个类型标签和逐日铅笔批注　**日期**：2026-11-18　**拍板人**：阿禅（界面推倒重写，审批逻辑保留）
**背景**：原文没写理由。
**决定**：去掉五个类型标签，改成「等你批 / 等你处理」两段；按涉及日期由近到远排；逐日去掉铅笔批注；撤回固定在底栏。
**证据**：[11-18 日志](../../../日志/2026-11-18.md)；[11-18 重做上线核对](../../archive/2026-11-20-参考归档/参考原稿/2026-11-18-审批工作台重做上线核对.md)。

<a id="第6条"></a>

### 6 入口从铃铛换成文字「待办 N」

**分类**：设计　**状态**：本地已提交、尚未上线　**日期**：2026-11-19　**拍板人**：阿禅（按 CC 方案做，未逐条确认）
**背景**：旧铃铛悬停会转、会放大，角落只有灰色小数字。
**决定**：入口改成文字「待办 3」：有事深字、没事浅字。待办面板本身不动。
**证据**：[站内外框重写方案](../../plans/2026-11-19-站内外框重写方案.md)。
