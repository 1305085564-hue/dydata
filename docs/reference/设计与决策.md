## 二、每份文件怎么写 & 全站模块地图

- **两段式结构**：页面、链路与工程类文件分「现行设计」（上段，只写现况，不写过程）和「历史决策」（下段，记为什么这么定、放弃了什么、谁拍的板；只往后加，旧条不改正文）。
- **归口原则**：只影响一页记页面文件；跨两页以上记链路文件；全站通用规则记全站文件。同一件事只写一处，别处放链接；先改上段，再在下段末尾按 `1..N` 顺编一条（新条目取代旧条目时互注）。找不到原话的拍板人写「待核」，产品/业务取舍必须由阿禅拍板。
- **代码对账**：上段与代码冲突时先核真实代码，上段写错了当场改上段，代码偏了交阿禅定。
- **全站规范类文件**（后端工程规范、效率美学、美学宝典、纠错索引）整份都是现行规则，不分两段，改规则直接改原文。
- **新建页面或链路文件格式**：按下面结构新建，并加进下表：

```markdown
# 页面：名字（或「链路：名字」）

> 地址或范围｜牵涉链路或涉及页面

<a id="现行设计"></a>

## 现行设计

> 最后对过代码：YYYY-MM-DD

<a id="现行-小节名"></a>

### 一、小节名

## 历史决策

<a id="第N条"></a>

### N 标题

**分类**：业务 / 设计 / 性能 / 代码　**状态**：有效 / 已被第 N 条取代　**日期**：YYYY-MM-DD　**拍板人**：阿禅
**背景**：为什么要定　**决定**：当时定了什么　**后果**：代价、放弃了什么、以后必须保持什么（可省）　**证据**：链接
```

## 三、目录分工、行数上限与维护纪律

### 目录分工

| 目录 | 用途与收尾方式 |
|---|---|
| `docs/reference/` | 本总入口与局部接口契约，以及 `页面设计与决策/`、`链路设计与决策/`、`全站设计与决策/`；历史账本（如 `截图迁移进度.md`）仅保留参考读数，当前收尾看 `待办清单.md` |
| `docs/plans/` | 待做与在办方案（按「日期-主题」命名平铺，写明状态与待办）；续工交接放「上下文交接」子目录。**完成后当轮退出**：结论写入对应现行文件，原稿/派单/过程记录归入 `docs/archive/` 并更新引用 |
| `docs/archive/` | 只供追溯的历史原稿（被仓库根 `.ignore` 默认跳过，不作施工依据） |
| `docs/通用管理/` | `待办清单.md`、`上下文交接.md`（永久模板，禁止直接改写为交接稿）、`测试账号.md`（本机凭据，不入库） |
| `docs/ux-audit/` | 独立的 UX 审计产物 |

### 行数上限（提醒 + 1.5 倍硬拦）

按文件性质分档，由 `npm run doc:size` 在推送前检查：**超过上限只提醒（退出码 0）**，留待文档维护任务统一压；**超过 1.5 倍硬拦**。超限时按「① 压缩（合并重复、长段改表）→ ② 清理失效条目与流水账 → ③ 拆子文件留索引」顺序处理。

| 档位 | 上限 | 硬拦（1.5 倍） | 适用文件 |
|---|---:|---:|---|
| **大**（天天查、内容厚） | **300** | 450 | `页面设计与决策/` 与 `链路设计与决策/` 全部文件、`工程底座`、`上线与运维` |
| **中**（总入口、规范类） | **200** | 300 | `设计与决策`、`后端工程规范`、`纠错索引`、`AGENTS.md` |
| **小**（附属台账） | **100** | 150 | `待办清单`、`上下文交接` |
| **设计系统**（两卷一档） | 主卷 **450** · 辅卷 **400** | 675 · 600 | `效率美学`（主卷）、`美学宝典`（辅卷） |

### 维护纪律

1. **与代码冲突以代码为准**：先核真实代码/数据库，再当场修文档；未核实的边界写「待核」，不默认现行。
2. **同一结论只留一处**：业务流程、口径、权限、已拍板取舍不另开平行文档，别处只放链接；一次性方案放 `docs/plans/`，完成后不回流正文。
3. **只记现况，不写变更流水**：已完成的改动过程不留正文（历史看 git 或 `docs/archive/`）；规则变动只改本文件与 `AGENTS.md` 对应处。
4. **日志只留近 14 天**：更早按月移入归档目录（`npm run logs:archive`）；`日志/` 出现超过 45 天的文件时推送门禁拦下。
5. **无引用旧截图可删**：删除清单与找回提交号记在 `docs/archive/README.md`。
