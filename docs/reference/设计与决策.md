# 设计与决策

> 系统现在怎么做、当初为什么这么定，都记在这里。本文件是唯一的总目录，正文在下表的页面文件和链路文件里。入口与调用关系这类长期不变的事实见[模块地图](../系统架构与设计/全站模块与数据关系.md)。

## 每份文件分两段

- **现行设计**（上段）：系统现在怎么做，以这里为准。只写现在的样子，不写过程。
- **历史决策**（下段）：当初为什么这么定、放弃了哪些做法、谁拍的板。只往后加，旧条目不改正文。

改一件事只动一份文件：先把上段改成新的样子，再在下段末尾加一条，写明为什么改。上段和代码对不上时，先查代码看实际怎么跑：上段写错了就改上段；代码偏了，交阿禅定。

## 怎么用

- **改某个页面前**：读这个页面的文件，再读它「牵涉链路」里列出的链路文件。
- **放哪份文件**：只影响一个页面，记在页面文件；影响两个以上页面或全站，记在链路文件。同一件事只写一处，别处放链接。
- **编号**：历史决策每份文件各自从 1 排起，新的一条取本文件最大号加一，写在文件末尾。引用别的文件时写「数据上传链路第 3 条」，并链到那一条。现行设计的小节用 `现行-小节名` 做锚点。
- **新决策取代旧决策**：旧条目不删，在它的状态里写「已被第 N 条取代」；新条目的状态里写取代了哪条。
- **拍板人**：写实际拍板的人；找不到阿禅原话的写「待核」。产品和业务逻辑的取舍必须由阿禅拍板。
- **新页面或新链路**：照现有文件的格式新建，并加进下表。

## 文件格式

```
# 页面：名字（或「链路：名字」）

> 地址或范围｜牵涉链路或涉及页面

<a id="现行设计"></a>

## 现行设计

> 最后对过代码：YYYY-MM-DD

<a id="现行-小节名"></a>

### 一、小节名

## 历史决策

<a id="第N条"></a>

### N 标题

**分类**：业务 / 设计 / 性能 / 代码　**状态**：有效 / 已被第 N 条取代　**日期**：YYYY-MM-DD　**拍板人**：阿禅
**背景**：为什么要定
**决定**：当时定了什么
**后果**：代价、放弃了什么、以后必须保持什么（没有可省）
**证据**：链接
```
