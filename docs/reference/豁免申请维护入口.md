# 豁免申请维护入口

两个申请入口共用 `src/lib/exemption-application-precheck.ts:checkPendingExemptionOverlap`，只负责读取和判定同一申请人、同一分类、待审批日期是否重叠。它使用入口传入的用户 Supabase 客户端，不负责登录、写入或日志。

| 入口 | 校验后的日期来源 | 成功写入 | 返回与刷新 |
|---|---|---|---|
| Dashboard `submitExemptionRequestWithClient` | `buildRequestDraft` 或 `buildRequestDraftsForDates` 生成的 drafts | 一次批量写入 `exemption_request` | 返回 `submittedDates`；外层 Server Action 刷新 `/dashboard` |
| REST `POST /api/exemptions/apply` | 输入 `dates` 或区间经 `expandDates` 解析，再按连续日期分段 | 逐段写 `exemption_request`，随后批量写 `exemption_request_date`；失败清理本轮已建 pending 主表行 | 保留 201 `data`、409 重叠、500 预检失败等原响应；第 1 批观测仍在 POST 外层 |

预检先按 `applicant_user_id`、`request_status=pending`、`exemption_category` 查申请主表（最多 500 条），有申请 ID 才查逐日明细。日期状态由 `getPendingExemptionDatesFromRequests` 判定：有明细时仅 `pending` 日期阻拦；无明细时按存量主表区间兼容。`end_date=null` 在本预检中只按开始日处理。任一查询失败返回阶段和原错误，由入口映射既有用户文案与日志；不继续写入。

修改预检规则时运行：

```sh
npx tsx --test src/lib/exemption-application-precheck.test.ts 'src/app/(app)/dashboard/actions.test.ts' src/app/api/exemptions/apply/route.test.ts src/lib/豁免.test.ts src/lib/豁免流程.test.ts
npx tsc --noEmit --pretty false
git diff --check
```

真实写入验收需先确认隔离环境、专用成员、申请主表/逐日明细/可能授予投影的对象闭包及安全回收入口；单测通过不代表页面和生产写入已验。权限与审批规则以 `docs/权限与安全说明.md` 为准。
