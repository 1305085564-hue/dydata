## C · GET `/api/admin/collaboration/person` 个人作品质量

当请求带 `role=writers` 时，个人响应在原有 `growthWorks` 之外增加 `writerQuality`。当请求带 `role=talents` 时，账号主人归属的 `records[]` 增加 `contentQuality`，使用相同单篇质量结构；达人专属 `followerAchievement`、`followerGrade`、`overallGrade` 不再返回。下方数字用于示意字段，实际基准随公司规则返回。

```jsonc
{
  "writerQuality": {
    "state": "ready", // "ready" | "error"
    "rules": {
      "dryGoods": { "interaction": 0.035, "core": 0.02 },
      "review": { "interaction": 0.035, "core": 0.02 },
      "gradeThresholds": { "excellent": 100, "good": 80, "fair": 60 },
      "playFloors": { "floor": 2000, "good": 15000, "excellent": 15000 },
      "retentionBands": {
        "bounceRate2s": { "good": 25, "poor": 35 },
        "completionRate5s": { "good": 60, "poor": 50 },
        "avgPlayDuration": { "good": 50, "poor": 30 },
        "avgPlayRatio": { "good": 25, "poor": 20 },
        "completionRate": { "good": 10, "poor": 5 }
      },
      "retentionWeights": { "bounceRate2s": 35, "completionRate5s": 30, "avgPlayBundle": 20, "completionRate": 15 }
    },
    "monthSummary": { "totalCount": 0, "achievementSampleCount": 0, "interactionSampleCount": 0, "coreSampleCount": 0, "ratedCount": 0, "avgInteractionAchievement": null, "avgCoreAchievement": null, "avgContentAchievement": null, "overallGradeCounts": { "excellent": 0, "good": 0, "fair": 0, "poor": 0 }, "goodExcellentRate": null },
    "monthWorks": [],
    "growthSummary": null
  }
}
```

`growthWorks[].contentQuality` 与 `monthWorks[].contentQuality` 使用同一单篇结构：互动数据和留存数据按作品独立展示。留存数据由 2 秒跳出率、5 秒完播率、均播时长、平均播放占比、整体完播率按公司可编辑权重合成，结果称为留存达成率或留存分；均播时长与平均播放占比共用 `avgPlayBundle`，各占该项一半。高值指标按实际值 ÷ 好标准 × 100% 计算，低值指标按好标准 ÷ 实际值 × 100% 计算，低值实际值为 0 时按 200% 计，达成率允许超过 100%。差线只生成不合格提示，不改变达成率、留存档位或综合评级。五项留存值缺一项时 `contentAchievement`、`contentGrade` 和 `overallGrade` 均为空，互动数据或留存分缺失时也不生成 `overallGrade`。`goodExcellentRate` 的分子是综合评级为优/良的作品数，分母是综合评级非空的署名日报数。综合评级取互动达成率和留存达成率（留存分）的平均值，并保留弱项最多被强项拉升一档的限制，播放低于 2,000 判劣，2,000 至不足 15,000 最高为普。留存档位为优 ≥100%、良 ≥80%、普 ≥60%、劣 <60%。作品数量按署名日报计数，查询 video_id 去重只用于读取。达成率字段为百分数数值，原始率仍为 0–1 小数。

指标颜色默认使用评价标准表中的五项好线和差线，默认颜色样本下限为 3,000；公司保存的 `minPlayCount` 只改变颜色显示的样本门槛。复盘队列异常提醒固定使用播放 5,000、2 秒跳出 30%、5 秒完播 50%、均播时长 30 秒和整体完播 5%，综合评级固定使用 2,000 / 15,000 播放门槛，这两组固定规则不随公司评价配置变化。

达人 `records[].contentQuality` 复用上述单篇结构和状态，作品范围仍按账号主人归属；个人档案中的转粉率等岗位业绩统计仍按原口径返回，不参与该评级。

`ContentQualityStatus` 取 `rated`、`unlinked`、`pending_snapshot`、`invalid_play`、`missing_metrics`、`topic_unavailable`；标签查询成功但没有标签按 `other`，查询失败返回 `state=error`，不能混同。

## E · PATCH `/api/admin/collaboration/attribution`

### Request Body

```jsonc
{
  "reportId": "uuid",
  "scriptAuthorUserId": "uuid-or-null",
  "videoEditorUserId": "uuid-or-null",
  "operatorUserId": "uuid-or-null"
}
```

三个岗位字段必须出现，值允许为 UUID 或 `null`。只允许 `admin` 或 `company_owner` 在授权范围补录。拒绝冲突身份、本人提交的日报和不在当前可操作范围的对象。

### 返回 JSON

```jsonc
{
  "ok": true,
  "videoUpdated": true,
  "message": null
}
```

视频软配对失败时事务仍会提交日报更新：

```jsonc
{
  "ok": true,
  "videoUpdated": false,
  "message": "暂未匹配到视频，日报已保存，后续可手动关联"
}
```

失败结构：

```jsonc
{ "ok": false, "error": "错误说明" }
```

## F · Work Groups（工种小队编制与按团队分组 · 2026-09-22）

### 1. 视图结构（`buildWorkGroupViews`）

协作页容器加载 `loadCollaborationMonthDataset` 后调用 `src/lib/collaboration/domain/work-group-rules.ts` 的 `buildWorkGroupViews`，供「按团队」列表和详情使用。

```jsonc
{
  "ready": true, // 库是否已执行 work_groups migration
  "groups": [
    {
      "id": "uuid",
      "teamId": "uuid",
      "name": "短剧一组",
      "kind": "writer", // "writer" | "talent" | "operator"
      "memberCount": 4, // 编制内成员总数（含零产出在职成员）
      "aggregate": {
        "reportCount": 18,
        "effectiveCount": 14,
        "excellentCount": 2,
        "totalPlay": 340000,
        "avgPlay": 18888,
        "billingCount": 18, // 仅文案组（未认证个人为 null，合计只累加已认证）
        "accountCount": 3,  // 涉及账号并集去重
        "momChange": null   // 仅运营组（按组总播放月环比）
      }
    }
  ],
  "details": [
    {
      "summary": { /* 对应 groups 元素 */ },
      "members": [
        /* 组内成员列表（按对应岗位 builder 行组件形状，含零产出 0 / — 行） */
      ]
    }
  ]
}
```

### 2. 写接口 Server Actions（`work-group-actions.ts`）

所有写操作仅供服务端调用，门禁口径统一为 `manage_members + 限本公司`（操作人团队必须与小队/成员 teamId 匹配）。操作成功统一写 `audit_logs`。

| Action | 参数 | 审计类型 | 说明 |
|---|---|---|---|
| `createWorkGroupAction` | `{ name: string, kind: "writer"\|"talent"\|"operator" }` | `create_work_group` | 同公司组名唯一；挂操作人当前公司 |
| `renameWorkGroupAction` | `{ groupId: string, name: string }` | `rename_work_group` | 限改本公司小队；不能与同公司其他小队重名 |
| `deleteWorkGroupAction` | `{ groupId: string }` | `delete_work_group` | 删组后成员归属自动置空（ON DELETE SET NULL） |
| `assignWorkGroupMemberAction` | `{ groupId: string, userId: string }` | `assign_work_group` | 同槽位换组**就地自动替换**原归属（文案/达人二选一、运营至多一个），不要求先取消；运营可与文案/达人兼任；限本公司成员，跨公司一律 403；返回值含 `replacedGroupName` |
| `assignWorkGroupMembersAction` | `{ groupId: string, userIds: string[] }` | `assign_work_group` | 批量分配与单人入口分开，服务端上限见[决定 0004](架构决策.md#adr-0004) |
| `unassignWorkGroupMemberAction` | `{ groupId: string, userId: string }` | `unassign_work_group` | 清除该成员的小队槽位归属 |
