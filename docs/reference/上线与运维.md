### 一、部署、域名与上线后核对

- **截图桶版本保留（2026-11-23 起）**：截图桶已开版本保留，旧版本 30 天后自动清理；误删时按版本号找回（未完成分片上传 7 天后自动清理）。使用仓库签名工具查询历史版本并按版本号取回示例（凭据从 `.env.local` 读取，不打印密钥）：

- **正式发布方式**：云托管当前不随 `git push` 自动发版。先按门禁正常 `git push` 干净的 `main`（自动写入与当前 `HEAD` 一致的检查通过标记 `dydata-gate-pass`），再在本机执行正式手动部署命令；发版脚本会自动校验：① 检查通过标记与 `origin/main` 一致；② 线上云托管环境变量覆盖 `.env.example` 全部 `[必填]` 项（缺失立即阻断）；③ 仅向 Dockerfile 注入公开 `NEXT_PUBLIC_*` 参数并保留 UTF-8 中文路径（详见[发布适配说明](../../scripts/cloudbase/README.md#云托管发版与通知清理2026-11-21)）：

  ```sh
  # 单独只读核对线上设置项（仅列变量名，绝不读/打印值）
  node scripts/cloudbase/check-env-vars.mjs

  # 正式发版（内置上述对账与门禁标记校验）
  CLOUDBASE_MCP_MODULE="$(find "$HOME/.npm/_npx" -path '*/@cloudbase/cloudbase-mcp/dist/index.cjs' -print -quit)" \
    node scripts/cloudbase/deploy-service.mjs
  ```

- **上线后必须跑这两条核对**（国内直连 `--noproxy '*'`）：

  ```sh
  curl --noproxy '*' -sS 'https://dydata.cc/api/health?check=cloudbase'   # 期望 HTTP 200 且 checks.cloudbase.status="up"
  curl --noproxy '*' -sS 'https://dydata.cc/deployment.json'               # 期望 commit 等于刚发布的 HEAD 且 backend="cloudbase"
  ```

- **发版回滚步骤**（版本异常需要立刻止血时）：
  1. **只读核对保留版本**：确认上一个健康版本仍在云托管历史列表中且状态为 `normal`（如当前 `dydata-026` 流量 100%，上一版 `dydata-025` 状态 `normal`、流量 0%）：
     - 控制台路径：腾讯云云开发控制台 → 环境 `dydata-d6g0gd1v37fcddf21` → 云托管 → 服务 `dydata` → **版本列表**。
     - 本机只读核对命令（不改流量、不打印密钥）：通过 `DescribeCloudBaseRunServer` 查 `VersionItems` 的 `VersionName`/`Status`/`FlowRatio`。
  2. **切换流量回上一版**（例如从 `dydata-026` 切回 `dydata-025`）：
     - 在云托管服务 `dydata` → **流量配置**（或版本列表操作列「流量分配/回滚」），将目标旧版本（如 `dydata-025`）流量调为 `100%`，问题版本（如 `dydata-026`）流量调为 `0%` 并确认生效。
     - 注意：如果本次发布含数据库迁移，**不能靠切回旧镜像回滚库结构**；涉及数据库变更的回滚需结合发布前导出的只读备份另案处理。
  3. **记录回滚原因**：把回滚时间、从哪版切回哪版、线上症状与触发原因记进当天日志 `日志/YYYY-MM-DD.md`；如属可复发缺陷，同步补记一条进[纠错索引](纠错索引.md)并写明后续要补什么检查。
  4. **切回后必查三项**：
     - 两个体检地址：`curl --noproxy '*' -sS 'https://dydata.cc/api/health?check=cloudbase'` 返回 HTTP 200 且 `checks.cloudbase.status="up"`；`curl --noproxy '*' -sS 'https://dydata.cc/deployment.json'` 里的 `commit` 已回到目标旧版本对应的提交号；
     - 最近 10 分钟报错：查看腾讯云云托管 `dydata` 最近 10 分钟运行日志（确认无持续 5xx / 启动崩溃）与 Sentry 最近 10 分钟错误趋势；
     - 用测试账号只读走一遍故障对应页面，确认恢复正常。
  - 历史记录：原 Vercel/Supabase 备用入口已取消退出，不再回切。
- `/api/health` 不用登录：基础检查返回 200、`status:"ok"`、`checks.server:"up"`；带 `check=cloudbase`（或 `check=database`）时，正常返回 200 和 `"up"`，连不上返回 503 和 `"down"`，缺配置返回 503 和 `"unconfigured"`，都不暴露底层错误（`check=supabase` 已移除）。健康检查只证明连得通，不证明权限、口径或页面链路正确。
- 域名解析与 SSL 证书：域名 `dydata.cc`（阿里云万网注册）DNS 托管已于 2026-11-22 零停机迁至腾讯云 DNSPod（免费版，权威 NS：`sweater.dnspod.net` / `booth.dnspod.net`；保留记录：`@ CNAME -> dydata.cc.tcbaccess.tencentcloudbase.com`、`_cloudbase-challenge` / `_cloudbase-challenge.www` / `_dnsauth` TXT 等，`direct CNAME -> cname.vercel-dns.com` 为原备用记录，2026-11-23 已在 DNSPod 暂停（Vercel 项目同日暂停、未删），不设 CAA 与 `www`；Cloudflare 旧区配置暂留兜底），国内直连解析命中腾讯云大陆节点（`106.55.209.168` / `1.14.236.147` / `124.223.x.x`）。SSL 免费证书 `cY9xJauu`（有效期至 `2027-02-19`）已绑定云托管 `dydata.cc`，HTTP 网关协议已设为 `HTTP_TO_HTTPS`（强制 307 跳转 HTTPS，避免 `http://dydata.cc` 进站触发写操作 403「请求来源不可信」）。注意不得启用 Cloudflare 代理或海外根域名 CNAME 展平（否则会将国内用户导至新加坡节点 `43.173.x.x`）。
- 历史记录（原 Vercel 备用端核对说明，已退出）：Vercel 构建曾显式关闭独立服务器输出，现仅保留腾讯云容器构建；历史用 `vercel CLI` 查备用端时曾需清除本机代理变量（2026-10-05 实测）。Vercel 免费额度 2026-11-05 临时解封至 12-05 的历史记录见[解封记录](../archive/2026-11-09-A批文档治理/参考原稿/2026-11-05-Vercel免费额度封停与解封申请.md)、[降耗实测](../archive/2026-11-09-A批文档治理/参考原稿/2026-11-05-CPU超额调查与降耗.md)。

### 现行-备份与恢复

- **何时必须先导出**：写正式库、删数据、执行数据库迁移（含清理旧 schema）之前，必须先做一次只读全量导出。
- **导出命令**：`node scripts/cloudbase/db-export.mjs`（需额外导出遗留 schema 时加 `--schemas s1,s2`；仅读不写，自动导出 `public` 全表与 `auth` 核心账号表）。
- **备份位置**：仓库外 `~/.local/share/dydata/db-export/YYYY-MM-DD-HHMM/`（目录 `700`、文件 `600`），含 `manifest.json`、`schema.json` 与逐表 `.jsonl.gz`，严禁提交或上传。
- **本机恢复与核对**：`node scripts/cloudbase/db-restore-local.mjs [--backup-dir DIR]`；自动起临时 Docker Postgres、跑迁移、列出并补齐结构差异、灌入数据并逐表校验行数。

### 二、推送前检查与门禁

- **推送前检查与自动同步**：`npm run hooks:install` 安装薄转发钩子，本机永远直接执行当前工作树里的最新版 `scripts/git-hooks/pre-commit` 与 `scripts/git-hooks/pre-push`（不再需要改完钩子手拷）。推送前依次跑 9 步检查：① `node scripts/doc-health-check.mjs --links`（文档死链）；有 `supabase/migrations` 改动时自动跑本机迁移重放 `npm run db:replay`；② `npx tsc --noEmit --pretty false`；③ `npm test`（全部单元测试与脚本测试）；④ `npm run lint`（含分层边界与 `@supabase/supabase-js` 仅允许转接层引入检查）；⑤ `npm run gate:design`；⑥ `node scripts/maintainability-gate.mjs --base=origin/main`（含北京时间唯一出处检查）；⑦ `node scripts/source-text-test-gate.mjs`（**禁止新增读代码文字的测试，存量只减不增**）+ `node scripts/forbidden-list-gate.mjs --base=origin/main`（**统一禁用清单**：已下线功能不准加回、迁移只准新增、数据库原始报错不回页面、已收成一份的规则不准抄第二份、四个名单只减不增且新增须写理由，每条报错写明「该用什么」）；⑧ `node scripts/doc-size-check.mjs`；⑨ `node scripts/api-failure-path-gate.mjs --base=origin/main`。改了 `src/` 的批次再跑 `npm run build`。全部通过后自动写入 `dydata-gate-pass` 标记（发版脚本强制校验），严禁用 `--no-verify` 跳过。迁移改动另用 `npm run db:drift` 对账。
- **类型错误会拦构建**（2026-11-08 起 `next.config.ts` 关闭 `ignoreBuildErrors`；之前曾因此把截图识别全量故障推上线，见[截图识别止血核对（已归档）](../archive/2026-11-20-参考归档/参考原稿/2026-11-07-截图识别止血修复推送核对.md)）。
- **测试入口**（`scripts/run-tests.mjs`）：`npm test` 跑全部不依赖外部服务的单元测试与脚本测试，任何环境都必须全绿。原依赖本机 Supabase 跑的 `*.real-db.test.ts` 与 `test:real-db` 已随单一后台收口移除。`npm run lint` 已锁死警告上限（`eslint --max-warnings=21`，只准减不准增），新增警告会拦下推送前检查。`gate:roles`、`gate:browser` 不在静态门禁里。
- **接口鉴权清点**：`src/app/api/route-auth.coverage.test.ts` 要求每个 `route.ts` 调用统一鉴权入口，或登记为有意公开并写明保护方式；不带权限要求的 `requireAdminActor()` 后面必须再做能力或范围收窄。新接口忘了鉴权会在 `npm test` 报红。
- **可维护性门禁**按相对基座的差异检查，工作树干净不等于全仓合规；它只拦本次改到的文件，基座里已超上限的会点名但不拦无关改动，谁再改谁先压回上限。另拦新增代码手写 `+08:00` / `Asia/Shanghai` 或用 `toISOString()` 切业务日期（北京时间 0–8 点差一天），统一用 `src/lib/business-time.ts`；确属纯日历运算的写 `// gate:utc-date-ok <理由>`。
- 发布执行 `npm run preflight:release` 并留档；全勾之后还要按上一节核对健康和实际运行版本。
- 浏览器门禁 `npm run gate:browser` 是登录态显式门禁，首批覆盖 `/topics`、`/dashboard`、`/admin/content`、`/admin/collaboration`；稳定规则硬阻断，时间预算先只报告，没有浏览器报告不能说浏览器性能通过。正式 `gate:roles` / `gate:browser` 被安全删除护栏（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`）或隔离工作树依赖问题阻断时，相关验收一律标 BLOCKED，不能用「等价 Playwright 跑过」或「构建主体成功」改写成通过。
- **路径带中括号的测试不能用 `npx tsx --test "<path>"` 单跑**：`[id]` 会被当成通配符，实测报 `tests 0` 却退出码 0，是假绿（2026-10-02 复验命中）。单跑用 `npx tsx "<path>"`（不带 `--test`），或交给已转义方括号的 `npm test`；核对绿数要看 `ℹ tests`，不能只看退出码。

### 三、本机、端口与两道防误写正式库保护

- **本机只连线上、只读**：本机开发服务器（`~/Library/LaunchAgents/com.dydata.local-dev.plist` 拉起、3000 端口、加载 `.env.local`）指向腾讯云正式环境，**只能看不能改**。涉及改数据的功能不再依赖本机 Supabase 库，改为「自动单元测试 + 发版后用测试账号在线上验收、验完清理测试数据」。
- **本机只读连正式库怎么配（2026-11-23 补齐）**：Next.js 只读**项目目录自己的** `.env.local`，主目录那份不会自动被隔离工作树继承，所以主目录和每一份隔离工作树各要一份。服务端连正式库至少要这三项，缺任一项的典型症状是登录被拦成 403「请求来源不可信」（`src/lib/csrf.ts` 拿不到 `SITE_ORIGIN` 时拒绝一切带 Origin 的写请求）：
  - `CLOUDBASE_ENV_ID`：填 `cloudbaserc.json` 里的环境 ID；
  - `CLOUDBASE_SERVICE_API_KEY`：值取自密钥文件 `~/.local/share/dydata/keys/腾讯云CloudBase.txt`（服务端专用，不加 `NEXT_PUBLIC_` 前缀）；
  - `SITE_ORIGIN`：填本机实际访问地址，开发服务器在 3000 端口就写 `http://localhost:3000`；换端口要同步改，否则写请求一律 403。
  - 截图相关另需 `COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_BUCKET`、`COS_REGION`、`SCREENSHOT_GRANT_SECRET`，清单见 `.env.example`；本机旧 Supabase 行留着不影响（代码已不读）。改动 `.env.local` 后要重启该目录的开发服务器才生效。
  - 这里只写变量名和取值来源，实际值只存在本机 `.env.local`：禁止打印、禁止贴到别处、禁止提交（`.gitignore` 的 `.env*` 已覆盖，仅放行 `.env.example`）。
  - 配完的自检：用测试账号登录 → 打开工作台、`/admin/collaboration`、`/admin/content`、`/admin/fulfillment` → 再发一个写请求，应被防误写保护拦成 403「本机预览连的是正式数据库，只能看不能改」。
- **两道防误写正式库保护（第三批固化，禁止绕过或删除）**：
  1. **门禁保护（R5）**：`scripts/assert-local-gate-env.mjs` 拒绝将 `cloudbaserc.json` 中的正式环境 ID 用作门禁环境（单测 `scripts/cloudbase-gate.test.mjs` 守护）；
  2. **开发中间件保护（R6）**：`src/middleware.ts` 的 `shouldBlockDevProductionWrite` 在 `NODE_ENV=development` 且环境 ID 命中正式环境时，拦截除登录/退出/续期及两个只读预览接口外的全部写请求（返回 403，单测 `src/middleware-dev-production-write.test.ts` 守护）。
- **端口约定**：`3100` 只给正式 `gate:roles` / `gate:browser`；其他开发、验收、复现一律用 `32xx`（例如 `3217`），不和门禁共用。
- `DYDATA_PERF_LOG=1` 打开加载器和接口的分步耗时；门禁报告不能保存密码、Cookie、登录态文件、请求正文或用户 ID。

### 四、定时任务、日志与环境变量

- **生产定时任务（腾讯云）**：云函数 `dydata-notifications-cleanup` 按北京时间每天 02:00 通过 GET 调用 `https://dydata.cc/api/notifications/cleanup`（携带 `Authorization: Bearer <CRON_SECRET>`）清理过期通知。保活任务已随备用退出下线（CloudBase 无需保活，原 `vercel.json` 与 `/api/supabase-keepalive` 已删除）。原抖音同步定时任务及接口已于 2026-11-22 下线删除。失败统一上报 Sentry，配了 `FEISHU_ALERT_WEBHOOK_URL` 时同时通知负责人。定时任务鉴权兼容 `CRON_SECRET`、`REMIND_SECRET`：定时触发用 `Authorization: Bearer`，手动触发可带 `?secret=`。
- **线上运行日志**：生产日志在腾讯云云托管控制台（服务 `dydata`）查看；应用每个请求落一条结构化记录（`api-logger` 单行 JSON：`requestId/route/method/status/durationMs/outcome/detail`；写请求观测封装的日志带 `detail.release`，健康日志不保证带）；`/api/*` 都返回 `x-dydata-request-id` 响应头。生产没配 `DYDATA_PERF_LOG`，性能日志线上没开。（历史记录：原 Vercel 端日志仅保留约 1 小时，2026-10-03 实测）。
- 登录校验、限流和清缓存都在 `src/middleware.ts`；单个用户异常可以让他访问 `?__clear_site_data=1` 清掉本地缓存和登录态。

<a id="现行-发布边界"></a>

### 五、发布硬边界

- 一次提交、一次上线只做一个领域：视觉、业务逻辑、性能、文件搬迁和数据库迁移分开。
- 迁移只能新增，不能改旧文件；不能让数据库先行、造成旧应用读到已删除结构的窗口。数据库和应用的先后顺序只认[项目规则「数据与生产库」](../../AGENTS.md#数据与生产库)；新字段发布要核验迁移实际生效、PostgREST 结构缓存刷新和真实角色请求，这份核验清单不等于可以无条件先动数据库。
- 工作区里可能有其他会话的改动：提交只精确暂存本任务的文件，禁止 `git add .`、`git add -A`、`git add -u`。
