<a id="现行-部署"></a>

### 一、部署、域名与上线后核对

- 正式部署平台只有 Vercel，推 `main` 就触发部署。OpenNext、Cloudflare 只是历史实验，不能恢复为正式入口。
- 正式域名 `https://dydata.cc`。推送后必须跑这两条核对：

  ```sh
  curl -s https://dydata.cc/api/health?check=supabase   # 期望 checks.supabase=up
  env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy -u ALL_PROXY -u all_proxy \
    npx vercel ls dydata --json   # 第一条部署的 meta.githubCommitSha 应等于刚推的 HEAD
  ```

- 为什么要清代理变量（2026-10-05 实测）：本机 FlClash 常驻 `127.0.0.1:7890`，但 `no_proxy` 白名单含 `vercel.com`、`supabase.co`、`*.cn`，Vercel、Supabase、GitHub 走直连且可达。curl 认 `no_proxy` 所以一直好使；vercel CLI 会认 shell 代理变量、把请求交给 FlClash 后挂掉（报 `fetch failed`），和网络通不通无关。CLI 登录态（`~/Library/Application Support/com.vercel.cli/auth.json`）能直连就会自动续期。
- `/api/health` 不用登录：基础检查返回 200、`status:"ok"`、`checks.server:"up"`；带 `check=supabase` 时，正常返回 200 和 `supabase:"up"`，连不上返回 503、`status:"degraded"`、`supabase:"down"`，缺配置返回 503 和 `supabase:"unconfigured"`，都不暴露底层错误。健康检查只证明连得通，不证明权限、口径或页面链路正确。
- Supabase 主库 `gcrhhxaopomtposmahsw`，区域新加坡；11-04 回切见[第 2 条](#第2条)，现况以健康检查为准。
- 腾讯云迁移准备期间，`dydata.cc` 仍由 Vercel 服务；云托管默认域名单独验收。云托管目前不随 push 自动发版，正式手动命令为 `CLOUDBASE_MCP_MODULE="$(find "$HOME/.npm/_npx" -path '*/@cloudbase/cloudbase-mcp/dist/index.cjs' -print -quit)" node scripts/cloudbase/deploy-service.mjs`。命令只发布已推送的干净 `main`，沿用服务变量，注入公开构建参数并保留中文路径；详见[发布适配说明](../../../scripts/cloudbase/README.md#云托管发版与通知清理2026-11-21)。默认域名加 `/deployment.json` 查实际提交号，加 `/api/health?check=cloudbase` 核对 HTTP 200 与 `checks.cloudbase.status="up"`。Vercel 构建显式关闭独立服务器输出，容器构建保留。
- 生产回滚优先在 Vercel 把上一个 Ready 部署 Promote / Instant Rollback；代码层撤销和重新发布要另外核对范围。
- 2026-11-05 两个域名报 HTTP 402，经临时解封恢复为 200；平台当时给了约 3 倍 Fluid CPU 额度、标记 12-05 到期，现况要查控制台。见[解封记录](../../archive/2026-11-09-A批文档治理/参考原稿/2026-11-05-Vercel免费额度封停与解封申请.md)、[降耗实测](../../archive/2026-11-09-A批文档治理/参考原稿/2026-11-05-CPU超额调查与降耗.md)。

### 二、推送前检查与门禁

- **推送前六项检查**：`npx tsc --noEmit --pretty false`、`npm test`、`npm run lint`、`npm run gate:design`、`node scripts/maintainability-gate.mjs --base=origin/main`、`node scripts/api-failure-path-gate.mjs --base=origin/main`；改了 `src/` 的批次再跑 `npm run build`。`npm run hooks:install` 安装同一组检查，不能用 `--no-verify` 跳过。同一命令还安装提交前钩子：主目录（不是隔离区）不在 main 上时提交会被拦下，见[第 9 条](#第9条)。迁移改动先跑 `npm run db:replay -- --keep`，再用 `npm run db:drift` 对账。
- **类型错误会拦构建**（2026-11-08 起 `next.config.ts` 关闭 `ignoreBuildErrors`；之前曾因此把截图识别全量故障推上线，见[截图识别止血核对（已归档）](../../archive/2026-11-20-参考归档/参考原稿/2026-11-07-截图识别止血修复推送核对.md)）。
- **测试分组**（入口 `scripts/run-tests.mjs`）：`npm test` 只跑不依赖外部服务的测试，任何环境都必须全绿；`*.real-db.test.ts` 归 `npm run test:real-db`，连本地隔离库、串行执行（并行会因改表结构死锁），库没起来直接失败并提示 `colima start` / `supabase start`。`gate:static` 两组都跑，另跑 `scripts/*.test.ts`。lint 没设「警告即失败」，门禁全绿不等于没有警告。`gate:roles`、`gate:browser` 不在静态门禁里。
- **接口鉴权清点**：`src/app/api/route-auth.coverage.test.ts` 要求每个 `route.ts` 调用统一鉴权入口，或登记为有意公开并写明保护方式；不带权限要求的 `requireAdminActor()` 后面必须再做能力或范围收窄。新接口忘了鉴权会在 `npm test` 报红。
- **可维护性门禁**按相对基座的差异检查，工作树干净不等于全仓合规；它只拦本次改到的文件，基座里已超上限的会点名但不拦无关改动，谁再改谁先压回上限。另拦新增代码用 `toISOString()` 切业务日期（北京时间 0–8 点差一天），统一用 `formatShanghaiDateOnly` / `shiftDateOnly`；确属纯日历运算的写 `// gate:utc-date-ok <理由>`。
- 发布执行 `npm run preflight:release` 并留档；全勾之后还要按上一节核对健康和实际运行版本。
- 浏览器门禁 `npm run gate:browser` 是登录态显式门禁，首批覆盖 `/topics`、`/dashboard`、`/admin/content`、`/admin/collaboration`；稳定规则硬阻断，时间预算先只报告，没有浏览器报告不能说浏览器性能通过。正式 `gate:roles` / `gate:browser` 被安全删除护栏（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`）或隔离工作树依赖问题阻断时，相关验收一律标 BLOCKED，不能用「等价 Playwright 跑过」或「构建主体成功」改写成通过。
- **路径带中括号的测试不能用 `npx tsx --test "<path>"` 单跑**：`[id]` 会被当成通配符，实测报 `tests 0` 却退出码 0，是假绿（2026-10-02 复验命中）。单跑用 `npx tsx "<path>"`（不带 `--test`），或交给已转义方括号的 `npm test`；核对绿数要看 `ℹ tests`，不能只看退出码。

<a id="现行-本机"></a>

### 三、本机、端口与写验收

- **真实写验收禁止用仓库主目录 3000 端口的开发服务器**：它由 `~/Library/LaunchAgents/com.dydata.local-dev.plist`（`KeepAlive=true`）拉起、加载 `.env.local`，指向生产库。写验收必须用隔离工作树 + 独立端口 + 本地 Supabase 容器，结束后核对测试数据净零（2026-10-02 审批试点实测，相关前缀计数归零）。为什么这样定见[第 3 条](#第3条)。
- **端口约定**：`3100` 只给正式 `gate:roles` / `gate:browser`；其他开发、验收、复现一律用 `32xx`（例如 `3217`），不和门禁共用。多个会话共用本地库和门禁端口时要安排独占验收。
- `DYDATA_PERF_LOG=1` 打开加载器和接口的分步耗时；门禁报告不能保存密码、Cookie、登录态文件、请求正文或用户 ID。

<a id="现行-运维"></a>

### 四、定时任务、日志与环境变量

- Vercel 定时任务两个：每天 06:30 调 `/api/supabase-keepalive` 保活数据库，每天 18:00 调 `/api/notifications/cleanup` 清理过期通知；时间表以 `vercel.json` 为准。抖音夜间任务已停用。失败统一上报 Sentry，配了 `FEISHU_ALERT_WEBHOOK_URL` 时同时通知负责人。定时任务鉴权兼容 `CRON_SECRET`、`REMIND_SECRET`：Vercel 用 `Authorization: Bearer`，手动触发可带 `?secret=`。
- **线上运行日志只能回溯约 1 小时**（2026-10-03 实测）：跨周的改前改后对照（请求量、状态码、耗时）在这里取不到，要长期指标得走数据库账本、Sentry 或每天自己落盘。命令：`vercel logs --json --since <ISO> -n <N> -q 'requestPath:"<路由>"'` 可用，`--status-code 4xx|5xx`、`--source` 可用；`--request-id` 是 Vercel 平台自己的请求 ID，不能拿应用的 `requestId` 过滤；`--until` 传相对时间实测返回 0 条，必须用 ISO 绝对时间。
- 应用每个请求只落一条结构化记录（`api-logger` 单行 JSON：`requestId/route/method/status/durationMs/outcome/detail`；写请求观测封装的日志带 `detail.release`，可核对线上提交号，健康日志不保证带）；`/api/*` 都返回 `x-dydata-request-id` 响应头。生产没配 `DYDATA_PERF_LOG`，性能日志线上没开。
- 登录校验、限流和清缓存都在 `src/middleware.ts`；单个用户异常可以让他访问 `?__clear_site_data=1` 清掉本地缓存和登录态。
- 公开环境变量主要是 `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`。服务端关键变量有 `SUPABASE_SERVICE_ROLE_KEY`、`FEISHU_WEBHOOK_URL`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_ENCRYPT_KEY`、`FEISHU_APP_VERIFICATION_TOKEN`、`CRON_SECRET`、`REMIND_SECRET`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`DYDATA_PERF_LOG`、`BAIDU_OCR_API_KEY`、`BAIDU_OCR_SECRET_KEY`。这里只记名称和用途边界，实际值只在 `.env.example`、`.env.local`，不能写进代码、日志或文档样例。`SUPABASE_DB_URL`、`SUPABASE_ACCESS_TOKEN` 只用于迁移或临时 SQL；`DYDATA_E2E_EMAIL`、`DYDATA_E2E_PASSWORD` 只给受控浏览器门禁读。
- Git 远程用 SSH：`git@github.com:1305085564-hue/dydata.git`，禁止改成 HTTPS；提交邮箱应为 `1305085564@qq.com`。

<a id="现行-发布边界"></a>

### 五、发布硬边界

- 一次提交、一次上线只做一个领域：视觉、业务逻辑、性能、文件搬迁和数据库迁移分开。
- 迁移只能新增，不能改旧文件；不能让数据库先行、造成旧应用读到已删除结构的窗口。数据库和应用的先后顺序只认[项目规则「数据与生产库」](../../../AGENTS.md#数据与生产库)；新字段发布要核验迁移实际生效、PostgREST 结构缓存刷新和真实角色请求，这份核验清单不等于可以无条件先动数据库。
- 工作区里可能有其他会话的改动：提交只精确暂存本任务的文件，禁止 `git add .`、`git add -A`、`git add -u`。

<a id="现行-skill"></a>

### 六、多 Agent Skill 接线

- 分层标准（唯一来源）：离开本仓库还有用吗？有用是通用，没用是项目专属。

| 层 | 真源位置 | 分发方式 | 进 git |
|---|---|---|---|
| 通用 skill | `~/.agents/skills/`（单一真源） | 各 Agent 全局目录只放软链指向它，不放实体 | 否（想版本化另建 dotfiles 仓库） |
| 项目专属 skill | `<仓库>/.claude/skills/` | 项目 `.agents/skills/` 放软链指向 `.claude/skills/`（Trae 兼容） | 是（按 `.gitignore` 白名单逐个放行） |

- 铁律：① 同名不两立：项目里出现和全局同名的 skill 实体拷贝就是错误（会漂移），要么删掉用全局的，要么改名 fork；② 只改真源，不改拷贝；③ 新增项目 skill 时同步加 `.gitignore` 白名单行。Trae 的编号中文 skill 由 hub 云端下发，不手动增删，也不重复链入。
- 已接线到 `~/.agents/skills/`：Claude Code（`~/.claude/skills`）、Antigravity（`~/.cc-switch/skills`，经 `~/.gemini/config/skills.json` 继承）、Codex（`~/.codex/skills`）、opencode（`~/.config/opencode/skills`）、workbuddy（`~/.workbuddy/skills`）、qoder（`~/.qoder/skills`），2026-10-06 实测都是软链、没有悬空。
- 项目专属 skill 目前只有「网站体检」；其余原项目专属的已于 2026-10-06 升格为全局共享。

### 1 账实分叉期禁止 `supabase db push`

**状态**：有效（仅账实分叉期间适用；2026-11-18 补齐记账后对账检查已通过，分叉是否已解除、本条是否可撤待阿禅定）

**背景**：线上存在已执行但未登记或已登记但对象缺失的迁移版本，整体推送可能重跑历史策略并把数据库卡在半迁移状态。
**决定**：账实分叉期禁止 `supabase db push`；上线只能取单个迁移在事务内手工执行，随后向 `supabase_migrations.schema_migrations` 幂等登记，并用 `pg_policy`、`pg_proc` 等真实对象核验。
**后果**：迁移发布步骤变长但可回滚、可逐对象核实；账本记录不能单独证明线上生效。
**证据**：[迁移账与对象核账手势](纠错索引.md#补交审批迁移账与函数对象对账)；[任务总纲](../../archive/2026-11-09-A批文档治理/计划原稿/历史-项目/根治工程/2026-10-02-全站架构根治工程-任务总纲.md)「三、跨阶段硬边界」。

### 7 类型检查必须阻断生产构建

### 9 主目录只停在 main，用提交前钩子看住

**分类**：代码　**状态**：有效，补充第 4 条的执行方式　**日期**：2026-11-20　**拍板人**：阿禅
**背景**：第 4 条定了所有 AI 都在主线上工作，但没有任何东西拦着。2026-11-20 实测：主目录停在落后线上 28 次提交的支线上；有 68 处说不清是谁留下的未提交改动；本机挂着 18 个隔离区、11 条本地支线。当天新写的两份方案也提交在这条支线上，从主线开工的 AI 看不到。最近 7 天日志里实际在用的 Agent 有 6 家，规则只写了 3 家。
**决定**：主目录不在 main 上不准提交，由提交前钩子拦下；收工不留未提交改动；一个目录同一时间只给一个写代码的会话；隔离区用完即删。分工表按实际占比列 Codex、Claude Code、Antigravity，其余 Agent 归成一行，规则相同。不加开工体检之类的开工步骤（阿禅：开工前要做的事已经太多，只减不加）。
**后果**：要并行就必须开隔离区；钩子装在仓库公用的钩子目录里，本机所有隔离区和所有 Agent 共用，但只在执行过 `npm run hooks:install` 的机器上生效，换机器或重装后要重跑一次。
**证据**：`日志/2026-11-20.md`；`scripts/git-hooks/pre-commit` 及测试 `scripts/pre-commit-hook.test.mjs`。
