# 2026-10-13 作品日期错位与日报绑定根因核对

## 结论

10 月图片识图修正解决的是“截图里的发布时间被识别错”这一层，没有核验修正后的作品是否完整走完“视频 → 24 小时快照 → 截图/OCR → 日报 → 页面”的链路。因此，识图结果改对后，提交接口仍可能把新作品写到同账号同业务日的旧日报上，继续出现作品无数据、作品与日报错配。

这次生产只读审计覆盖 2026-10-01 至 2026-10-13：

| 链路事实 | 数量 |
| --- | ---: |
| 发布作品 | 176 |
| 有 24 小时快照 | 176 |
| 有截图证据 | 160 |
| 有发布时间 OCR 证据 | 157 |
| 没有有效日报 | 16 |
| 同一视频绑定多条有效日报 | 0 |
| 只有作废日报 | 0 |
| 日报归属日与作品发布日期不同 | 75 |

16 条无有效日报的作品中，15 条已有截图，14 条已有发布时间 OCR；说明“图片没识别出来”不是这批异常的主因。157 条带 OCR 的作品中，只有 3 条 OCR 日期与 `videos.published_at` 的上海日期不同，属于需要单独人工复核的识图/原始平台日期问题，不能解释 16 条无日报。

75 条“日报归属日不同”只是字段差异计数，不代表 75 条都是错数据：`report_date` 是提交/编辑/追溯日期，可能与发布日期不同。判断作品显示日期是否错，要核对 `videos.published_at` 与截图/OCR 证据。

## 已实测的根因

生产旧版本 `8b58e3c6` 的 `/api/video-submit` 在新建或异常提交的持久化阶段，按 `account_id + report_date` 查找日报并使用单条结果。这个查询把“同账号同业务日”误当成“本次作品的日报”：

1. 同账号同业务日已有旧日报时，新作品会更新旧日报的 `video_id` 和数据，原作品保留视频、快照和截图，但失去日报。
2. 同账号同业务日有多条记录时，单条查询会出现多行歧义，提交链路可能直接失败。
3. 后续页面按视频绑定或发布日期读取时，就表现为“明明上传了，作品没有数据”或“数据跑到了另一条作品”。

周文杰的生产数据能直接复现这条覆盖关系：

- 2026-10-08 19:27 发布的《10.9周五大盘预测》有 24 小时快照、2 张截图和高置信度发布时间 OCR，但没有有效日报。该视频于 2026-10-09 10:54:11（上海时间）上传；生产中的日报行在 10:54:12 创建，却已绑定到另一条视频。
- 这条日报当前绑定的另一视频于 2026-10-12 11:22 才上传。日报创建时间与第一条作品上传时间几乎一致，绑定目标却是三天后上传的作品，直接证明同一账号/日期日报被后续提交复用并改写。
- 同样的作品有视频快照、却没有当前日报绑定的情况，也出现在 2026-10-10 上海时间凌晨发布的另一条作品上。

另一个容易混淆的点是日期粒度：`videos.published_at` 是作品真实发布日期，`daily_reports.report_date` 是提交/编辑/追溯用的业务日期。周文杰 10 月 7 日看到的日报可能对应 10 月 6 日发布的作品；如果只按日报日期看，会把“有日报但不是这条作品”和“这条作品没有日报”混在一起。

## 本次修复

- 新建和异常提交不再按账号、业务日期读取旧日报，始终为当前 `video_id` 插入新日报。
- 编辑只更新已经按原 `video_id` 校验过的那一条日报；原绑定缺失时直接停止，不新建替代记录。
- 同一作品重复提交继续返回 `409`，防止同一 `video_id` 产生第二条有效日报。
- 审计脚本增加视频优先模式，逐条检查快照、截图/OCR、有效日报绑定和日期差异；快照按 `captured_at` 选择最新记录，避免查询返回顺序影响结论。
- 生产历史 16 条异常本轮只审计、不自动改绑，等待逐条确认，避免把日报绑定到相似标题的错误作品。
