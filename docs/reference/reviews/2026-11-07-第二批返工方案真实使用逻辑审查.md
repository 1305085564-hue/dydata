# 第二批返工方案：真实使用逻辑审查

审查日期：2026-11-07。审查对象：阿禅粘贴的《第二批返工施工方案（A/B/C/D + E）》，对照工作区同名 `.trae/documents/2026-11-07-第二批返工施工方案.md` 与当前源码。基线：`2680c16d`，含既有未提交 A 部分改动。

**结论：建议退回修订后再施工。** 方向合理，但当前方案存在三处直接影响使用的逻辑错误、两处施工/规则缺口，以及一处验收范围遗漏。此次只审方案，不修改业务代码，不执行生产操作。原始 11-07 施工派令未单独取得，因此不宣称已经完整核对派令授权及冻结清单。

## 一、必须修订的问题

### R1 · P1 · C2：滚到旧月份后，下一月按钮仍可能被锁住

- 用户路径：本月为 11 月，打开工作台日历或豁免弹窗，滚到 9 月，点击下一月。
- 按方案结果：父级月份仍是 11 月，`canGoNext` 仍为 false，按钮无法点击，不能从 9 月前往 10 月。
- 原因：C1 明确滚动不回写父级，C2 却保留按父级月份计算的 `canGoNext`，并声称边界会自然正确。这两个要求互相矛盾。
- 源码证据：`src/components/submission/submission-calendar.tsx:85-91,126`；`src/app/(app)/dashboard/redesign/exemption-dialog-v2.tsx:75-81,201`。每日大盘同样通过 `date-pagination.tsx:203` 按父级月份限制下一月。
- 推荐修订：翻月目标、按钮可用性都以当前正在看的月份判断，并沿用各入口已有的日期上限。此次不改变哪些日期可选，不扩展到冻结的 minDate 修复。

### R2 · P1 · C1：翻回打开时的月份，可能点了没有反应

- 用户路径：历史日报发布时间选择器打开在 11 月，滚到 10 月，点击下一月回 11 月。
- 按方案结果：目标算对了，但父级年月本来就是 11 月；只更新同样的年月，不会触发既有滚动效果，视图可能继续停在 10 月。
- 原因：方案删除点击时的内部滚动，完全依赖只监听父级年月变化的效果；相同年月的导航指令不会产生变化。换一个对象或 Date 也不能解决，因为效果监听的是年月数值。
- 源码证据：`src/components/calendar/month-calendar.tsx:111-128` 的依赖为 `viewMonth.year/viewMonth.month`；历史选择器使用两个年月状态（`history-report-edit-form.tsx:377-380`）。其余调用方也受同一组件机制影响，是否先被 R1 拦住取决于入口。
- 推荐修订：保证每次合法翻月操作都会执行跳转，包括目标等于父级已记录月份的情况；内部点击与外部跳转共用一个执行入口。不能仅以“目标月份计算正确”判通过。

### R3 · P1 · B2/B3：零条恢复不等于“本来就是开着的”

- 用户路径：某模型的两条供应都被逐条手动关闭，用户看到并点击“恢复模型”。
- 后端实际行为：只恢复因“整体停用模型”而关闭的供应；手动关闭的供应保持关闭，返回 `changedSupplyCount = 0`。
- 按方案结果：提示“模型供应本来就是开着的；个别渠道是手动关闭的”，实际可能一条都没开。没有供应的模型也不能根据零条修改推出已经开启。
- 源码证据：`src/app/api/admin/ai-config/route.ts:252-268`；模型按钮依据是否存在非 disabled 渠道判断开启状态，见 `model-family-card.tsx:95-101,190-213`。
- 推荐最小修订：零条时提示“本次未恢复任何渠道供应；手动停用的渠道需逐条开启”；大于零时提示“已重新开启 N 条渠道供应”。不要把开启供应开关说成已经识别成功或恢复健康。若要区分“本来已开”“全部手动关闭”“尚无供应”，应读取返回的真实状态再分别说明。
- 确认后重试路径须使用 `retryRes.body`，不能照抄方案示例中的 `res.body` 读取第一次失败的结果；缺少修改条数字段也不能直接推断本来已开。

### R4 · P2 · B1：调整真实排队顺序后，页面可能完全不动

- 用户路径：A 正常在岗、真实顺位 1；B 待复测、真实顺位 2。方案比较规则始终把 B 提到 A 上方。用户把 A 下移，与 B 交换真实顺位后，页面仍显示 B、A。
- 影响：用户看不出调整是否生效，而且按钮方向与上下位置可能不一致。方案承诺“顺位变化后正常重排”，目前没有做到。
- 原因：B1 在重排时仍让待复测身份优先于真实顺位；仅按真实顺位排序的 `sortedChannels` 只用于寻找交换对象，没有用于主列表展示。
- 依据：方案 B1 的比较函数；`src/lib/ai-config/availability.ts:277` 的既有待复测置顶行为；现行总方案 `docs/plans/2026-11-05-AI配置页口径重整与链路精简-总方案.md` 口径 4 要求模型卡只有一种排队顺序。
- 推荐：模型内渠道按真实顺位展示；测试更新状态时保持位置，用户主动改顺位时按新顺位排列。若坚持待复测置顶，需要先确认如何让用户读懂真实顺位，不能声称现方案已满足。

### R5 · P2 · A1/A3：方案要求的休眠查找测试与函数本身矛盾

- A3 要求 `findMoveTarget([A可用,S休眠,B可用], "S", 1)` 返回 null。
- A1 函数只判断目标能否调用，没有判断起点 S 能否调用，因此实际返回 B。原样施工必然无法满足这条测试。
- 当前主列表按钮已有起点限制，但已停用折叠区仍按数组位置开放按钮，见 `model-family-card.tsx:278-291`；`handleMoveOrder:107-110` 也只依赖查找结果。不能因为主列表禁用了休眠按钮，就认定所有入口已锁住。
- 推荐：在已有查找入口同时判定起点和目标能否参与交换；两个展示区域统一按钮判定，保留 A3 的业务断言。补上失效行和已停用折叠区的按钮禁用、点击不发请求验证。

### R6 · P2 · C3/第四节：最终浏览器范围遗漏实际受影响入口

- C3 要查历史日报发布时间与豁免/请假，第四节却把范围限定成 AI 配置、数据复盘、工作台日历三处，前后矛盾。
- 四个日历直接调用方之外，`DatePagination` 还被每日大盘复用，见 `src/app/(app)/admin/pulse/pulse-client.tsx:89-94`；其日期上限为昨日，与视频复盘不同。
- 推荐：统一写成 AI 配置及五个日历使用场景（视频复盘、每日大盘、工作台、豁免/请假、历史日报发布时间）；按场景验收，无需扩展为全站走查。

## 二、建议冻结的真实操作验收

| 场景 | 必须看到的结果 |
|---|---|
| 休眠/失效/已停用渠道 | 主列表和停用折叠区均不能调顺位，点击不发交换请求 |
| 两个可用渠道中间隔休眠渠道 | 交换成功，反向还原成功；刷新后保持真实顺位 |
| 正常在岗与待复测渠道互换 | 可见位置和真实排队顺序一致，按钮方向符合可见位置 |
| 测试通过/失败但顺位未变 | 状态更新、行位置保持；主动调整顺位仍能重排 |
| 全部供应手动关闭后恢复模型 | 不提示已经开启；手动关闭的供应保持关闭，并说明逐条开启入口 |
| 曾整体停用模型，混有手动关闭供应 | 只重新开启整体停用影响的供应，提示实际条数，不承诺已经识别成功 |
| 本月打开、滚到上上月、点下一月 | 按钮可用，从可见月份前进一个月 |
| 非受上限拦截的入口：打开11月、滚到10月、点下一月 | 确实滚回11月，即使父级记录本来就是11月 |
| 旧月出发连续翻月直到本月或业务上限 | 中间均可前进，到上限才禁用；前后方向、跨年正确 |
| 每日大盘、历史日报发布时间、豁免/请假 | 各自完整走一次滚动后翻月、选日和原业务动作；翻月本身不改变选中日期 |

## 三、可以保留与证据边界

- A 锁住不可参与交换的渠道、跳过它们寻找交换对象，方向正确。修改行组件输出提示有必要，不构成视觉改版。
- B 使用渠道标识和顺位构造重置标记，能区分测试状态变化与主动排序变化；稳定非空输入下，既有 hook 不会因此无限更新。新增/删除成员会改变标记，因此会重新排序，不应同时把其行为描述成单纯追加末尾。
- D 只删无引用组件、保留仍使用的摘要与结果类型，原则合理，执行时按全库引用核对。
- 纯函数、静态渲染、真实浏览器三类验证可以配合使用，无需新增 DOM 测试依赖。仓库已有 Playwright；关键点击场景可用既有浏览器能力覆盖。
- E 应保留“生产写入未验收”，不提前宣布通过。但 A/B/C/D 本身不修改 OCR 写账链路，不能仅因这几项尚未 push 就推断 E 一定不具备条件。执行前应核对台账所需版本、表及账号是否已经在线；本次未连接生产，未断言可以立即执行，也未核实生产历史记录条数。
- 方案关于“不会409”的绝对承诺应改成“当前状态一致时满足交换契约”；服务端仍可能在状态刷新后正常拒绝操作，沿用现有错误提示即可，无需增加并发治理。
- 现有 A 部分改动应逐块复核后修正；不建议为审查而直接 `git restore`，以免丢失其他会话工作。
- 分笔定向验证、最后执行完整静态门禁即可。`gate:static` 已含全量测试、类型、检查和构建，每笔重复运行整套收益有限；范围外既有失败按冻结清单记录，不自动扩大返工。
