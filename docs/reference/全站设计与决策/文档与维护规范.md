# DYData 文档与维护规范

> 任务从[产品全书](../DYData产品全书.md)进入。施工和发布纪律见[项目规则](../../../AGENTS.md)。当前、历史与待核的判断见[文档归口现状](../文档归口现状.md)。2026-11-19 更新目录分工。

| 目录 | 用途 |
| --- | --- |
| `docs/reference/` 根目录 | [产品全书](../DYData产品全书.md)（总入口）和[设计与决策总目录](../设计与决策.md)；另有以后还会用的已确认依据（接口契约、按日期命名的验收与核对），按版本、日期和验收范围引用 |
| `docs/reference/页面设计与决策/` | 每个页面一份：现行设计 + 历史决策 |
| `docs/reference/链路设计与决策/` | 跨页面的业务链路（上传、审批、评级、权限、AI 调用、选题入库）：现行设计 + 历史决策 |
| `docs/reference/全站设计与决策/` | 与具体业务无关的全站规则：工程底座、上线与运维（分两段）；后端工程规范、效率美学、美学宝典、文档与维护规范、CLAUDE.md写作指南、纠错索引（规范类，整份都是现行规则） |
| `docs/plans/` | 待做、在办方案与续工材料 |
| `docs/archive/` | 只供追溯的历史原稿和过程材料 |
| `docs/通用管理/` | 日常工作文件：待办清单、上下文交接、测试账号（本机凭据，不入库） |
| `docs/ux-audit/` | 独立的 UX 审计产物 |

1. 先查产品全书和现有原稿。同一现行结论维护一处，其他位置链接。业务流程、统计口径、权限、模块入口与调用关系、工程事实，一律写入[设计与决策](../设计与决策.md)对应页面、链路或全站文件的「现行设计」，不另开事实文档。
2. 已拍板且需要追溯理由的取舍，记录在[设计与决策](../设计与决策.md)同一份文件的「历史决策」：只影响一个页面的记页面文件，跨页面的记链路文件，与具体业务无关的全站取舍记工程底座或上线与运维，同一条只写一处。改变生产架构、数据归属、成本或回退方式的取舍必须登记；被新决定替代时，在同一条注明替代关系。各条说明有效或被替代的状态。改规则时先改「现行设计」，再在「历史决策」末尾加一条写明为什么改，不另开文档。
3. 参考保留已确认、后续仍会用的接口、验收或调查结论。注明适用版本、日期或未覆盖范围。多份记录回答同一问题时，更新现有依据或合并独有事实，再归档旧稿。
4. 计划收尾按[计划目录约定](../../plans/README.md)办理。已结束的材料退出计划区。能复用的结论归参考，只需追溯的原稿归档。
5. 交接传递续工上下文。能长期使用的事实先复核，再写入对应原稿。
6. 核实代码、运行记录或业务决定后，按实际范围更新文档。证据缺口标明待核。搬迁时同步更新可用引用，保留原始记录的日期与语境。

## 行数上限（提醒 + 极限硬拦）

按文件性质分档，不逐个文件定数字。**超过上限只提醒、不拦推送**（`npm run gate:maintainability` 输出一行"文档超限提醒"，退出码 0），不要为此中途停下压文档，留给下一次文档维护任务统一处理；**超过上限的 1.5 倍才拦**，这是防失控的底线。

| 档 | 上限 | 硬拦（1.5 倍） | 文件 |
|---|---:|---:|---|
| **大**（天天查、内容厚） | **300** | 450 | 设计与决策下每份页面、链路文件，以及全站的工程底座、上线与运维 |
| **中**（地图、索引、规范类） | **200** | 300 | 设计与决策总目录、后端工程规范、纠错索引、文档与维护规范、CLAUDE.md写作指南 |
| **小**（附属文件） | **100** | 150 | 产品全书、待办清单、上下文交接 |
| **设计系统**（两卷一档） | 主卷 **450** · 辅卷 **400** | 675 · 600 | 效率美学（主卷：内核 / 决策树 / 任务型路由 / 失败模式）、美学宝典（数值与组件字典） |
| **规则文件** | **200** | 300 | `AGENTS.md`（含 next 自动生成的段落） |

测试账号是 gitignored 凭据文件，不受上限约束。设计系统主卷是"开工必读量"与"总行数"分离的文档：开工先读 §0 内核 + §4 任务型路由，再按决策树走。

**超限时按顺序处理，不跳步**：① 压缩（重复条目合并、长段落改表格，信息不丢）；② 清理（删已失效内容和"某次改成什么"的变更流水，历史看 git 或 `docs/archive/`）；③ 前两步做完仍超才拆子文件，母文件留索引。不许硬破 1.5 倍线。

## 纪律

1. **与代码冲突时以代码为准**：发现冲突当场修正文档。
2. **执行方案不在长期文件里**：一次性方案进 `docs/plans/`，完成后不回流。
3. **已完成的不记录**：只记当前状态，历史看 git；不写"某次改成什么"这类变更流水。
4. **同一结论只留一份原文**：其他文档只链接它，不复制第二份现行规则。
5. **日志只留最近 14 天**：更早的移入 `docs/archive/日志/YYYY-MM/`（`npm run logs:archive`）；`日志/` 里出现超过 45 天的文件，推送前检查会拦下。
6. **没人引用的旧截图可以删**：图片历史在 git 里随时找得回，删除记录见 `docs/archive/README.md`。
