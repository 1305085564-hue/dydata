**日期**：2026-10-02
**范围**：生产只读；没有 DDL、DML、migration、版本登记或绑定改写。判断依据是 `pg_proc`、权限、依赖对象和真实列，不以 `schema_migrations` 判生效。

## 命令与原始输出

```sh

```

## 结论

**能否真的打开熔断：能。** 线上 `pg_proc` 已存在新版函数；函数为 `SECURITY DEFINER`、固定 `search_path=public`，失败次数达到 3 时写入 UTC 5 分钟 `unhealthy_until`，且只给 `service_role` 执行，匿名和普通认证角色均无执行权。目标表、所需列和索引均存在，因此“函数缺失导致熔断永远打不开”的旧结论已被本轮线上对象证据推翻。

首轮依赖查询曾误写 `pg_indexes.indexrelid`，实际返回错误：

```text
ERROR:  column "indexrelid" does not exist
LINE 1: select 'indexes', indexrelid::regclass, indexdef from pg_ind...
```

这是探针列名错误，不是生产对象失败；改为 `indexname,indexdef` 后查询成功。因函数已存在，本轮**没有生成迁移草案**，也没有执行任何修复。
