# 架构决策

> 这里记录已拍板的取舍和原因。分两类：**页面文件**只记某一个页面自己的取舍；**链路文件**记跨页面的业务线，以及全站通用的工程取舍。跨页面的一律记到链路文件。
> 本目录只回答"为什么这么定"。入口与调用关系写在[模块地图](../../系统架构与设计/全站模块与数据关系.md)，业务规则写在[核心业务流程](../../系统架构与设计/核心业务流程与异常边界.md)，统计口径写在[数据口径](../../系统架构与设计/数据口径与计算规则.md)。

## 怎么用

| 场景 | 做法 |
|---|---|
| 改某个页面 | 开工前读该页面文件，以及它"牵涉链路"里列出的链路文件 |
| 新拍板一条取舍 | 只影响一个页面 → 页面文件；影响两个以上页面或全站 → 链路文件。同一条只写一处，别处放链接 |
| 新页面或新链路 | 按现有文件的开头格式新建，并加进下面的表 |
| 新决定取代旧决定 | 旧条目不删，在它的状态里写"已被 00xx 取代" |

## 每条怎么写

编号全站连续，新建前先查本目录里最大的号。每条格式：

```
<a id="adr-00NN"></a>

## 00NN 标题

**分类**：业务 / 设计 / 性能 / 代码　**状态**：有效 / 已被 00xx 取代　**日期**：YYYY-MM-DD　**拍板人**：阿禅
**背景**：为什么要定
**决定**：定了什么
**后果**：代价、放弃了什么、以后必须保持什么
**证据**：链接
```
