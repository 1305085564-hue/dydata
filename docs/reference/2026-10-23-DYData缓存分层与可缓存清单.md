# DYData 缓存分层与可缓存清单

## 结论

可以把“公开、所有人看到都一样”的内容交给 Cloudflare；登录后的业务数据不能放公共缓存。视频复盘页面的主要数据属于用户、团队和公司范围，继续走数据库和服务端的短时私有缓存，不能用一个广州的公共缓存给所有人共用。

本轮已完成两件事：

1. 注册页的公开团队列表现在带 60 秒浏览器缓存、300 秒 CDN 缓存；接口失败时明确禁止缓存空结果。
2. 注册页前端不再强制每次都绕过缓存，重复打开注册页可以直接使用短缓存。

## 可以安全增加的缓存

### 1. 注册页团队列表

这是本轮已经改好的项目内部分。团队名称变化不频繁，最多延迟 5 分钟被看到；失败结果不会被缓存，避免短暂故障把“没有团队”留在用户页面上。

Cloudflare 需要新增一条优先级高于现有“API 全部绕过”的规则：

- 条件：主机名为 `dydata.cc`，路径精确等于 `/api/register-teams`。
- 动作：允许缓存，边缘缓存 300 秒，浏览器缓存 60 秒。
- 现有 API 绕过规则继续保留，并排在这条规则之后。

### 2. 公开协议页

`/privacy` 和 `/terms` 是公开页面，部署后可以设置 1 小时的页面缓存。它们不是视频复盘数据，且修改频率很低。当前生产域名对这两个路径返回 404，说明本地新增页面尚未上线；因此本轮不把它们算作线上收益。

## 明确不能使用公共缓存的内容

以下内容都带登录人、公司、团队或权限范围，放进 Cloudflare 公共缓存会造成不同用户看到同一份数据：

- 视频复盘列表、单条视频详情、复盘状态和选题库状态。
- 首页登录后的看板、排行榜、活动、待办数量和人员信息。
- 选题池、主题列表、团队协作、抖音账号与指标、审批、申诉、履约、导出。
- 所有写入接口、登录接口、授权回调、同步任务、AI 操作和通知接口。

这些接口可以继续使用“按用户/团队隔离的服务端短缓存”，但必须保持 `private`，并以用户、公司、团队、可见人员范围作为缓存边界。现在视频复盘列表已经有 60 秒私有缓存，这比把它公开给 Cloudflare 更安全。

## 下一步操作

只需要在 Cloudflare 控制台把 `/api/register-teams` 加到现有 API 绕过规则之前，然后访问注册页两次核对第一次回源、第二次命中即可。不要把整个 `/api/*` 放开缓存，也不要把视频复盘接口改成公共缓存。
