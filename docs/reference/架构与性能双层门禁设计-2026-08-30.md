# 架构与性能双层门禁设计（2026-08-30）

> 状态：已完成；本地生产构建首轮验收通过，时间预算暂不阻断。
> 使用边界：本文件是已完成方案与验收记录，不单独授权新增施工。
> 当时总目标来源：`docs/架构与性能总纲.md`；该总纲于 2026-09-02 归档，当前项目预算与事实来源改为 `docs/工程运行事实.md`。本文件只保留 2026-08-30 的门禁方案与验收历史。

## 一、目标与非目标

建立两层性能门禁：第一层不依赖账号和网络，作为每次交付必跑的确定性阻断；第二层使用专用账号在真实浏览器中采集登录后页面证据，先作为显式验收命令，基线稳定后再决定是否接入 CI 时间阻断。

本批不修改业务页面、数据库、RLS 或权限，不为通过门禁而隐藏当前性能债，也不把本地生产构建结果写成 Vercel 生产结论。

## 二、方案

### 第一层：确定性门禁

- 新增纯函数预算与报告模块，统一定义首批四个页面的请求数和接口预算。
- 单元测试覆盖预算合法性、HTTP 4xx/5xx、重复请求、Topics 首屏禁止提前调用 `/api/topics/*`、时间预算“先报告、可显式升级为阻断”。
- `npm run gate:static` 串联现有测试、脚本测试、独立 TypeScript 检查、lint 和生产构建。
- 不连接 Supabase、不读取测试账号、不运行 migration、seed 或任何写数据脚本。

### 第二层：登录态浏览器门禁

- 使用 Playwright 和环境变量 `DYDATA_E2E_EMAIL`、`DYDATA_E2E_PASSWORD` 登录；凭据、Cookie 和浏览器状态不写入仓库或报告。
- 默认针对本地生产构建，也允许通过 `DYDATA_E2E_BASE_URL` 指向受控部署。
- 首批只读覆盖 `/topics`、`/dashboard`、`/admin/content`、`/admin/collaboration`。
- 硬阻断：页面打不开、业务 API 4xx/5xx、控制台 error、请求数超预算、相同方法+URL+正文的重复请求、明确禁止的提前加载接口。
- 首阶段只报告时间预算；设置 `DYDATA_PERF_ENFORCE_TIMING=1` 后才把时间和单接口预算升级为阻断。
- 报告只保存页面路径、数量、状态和耗时，不保存请求正文、查询参数、用户 ID 或凭据。

## 四、验收

1. 回归测试必须先在模块不存在时失败，再在实现后通过。
2. `npm test`、脚本测试、`npx tsc --noEmit --pretty false`、lint、生产构建通过。
3. Playwright 配置和测试可被发现；有专用账号时完成真实四页只读运行。
4. 缺少账号时显式报错，不跳过后伪装成门禁通过。
5. 结果同步写入性能台账和项目日志；没有 Vercel 实测就不宣称生产通过。

## 五、完成结果

- 第一层：`npm run gate:static` 通过，包括 1255 项项目测试、2 项账号脚本测试、独立 TypeScript 检查、eslint 和 Next.js 生产构建。
- 第二层：最终正式命令在本地生产构建真实登录态覆盖四页，确定性硬规则全部通过；`/topics` 首屏 1 个业务请求且 0 个 `/api/topics/*`，`/dashboard` 2 个，`/admin/content` 5 个，`/admin/collaboration` 1 个。
- 时间报告：最终一轮四页首屏绘制分别约 0.71s、0.23s、0.64s、0.67s；`/admin/content` 最慢业务接口约 2.91s，`/admin/collaboration` 约 0.94s，超过各自预算，当前只报警并进入台账。
- 稳定性边界：链式后台请求必须等待到业务请求全部完成且安静 500ms 后再判定，最长等待 20 秒，避免晚启动的状态请求被误判为无响应。
- 安全边界：关闭 Playwright trace、截图、视频和失败页面快照，不生成浏览器登录状态；报告只保留路由、计数、状态和耗时。失败调试产物已从工作区移入废纸篓，未进入 Git。
- 环境边界：以上只证明 2026-08-30 当前工作树的本地生产构建，不代表 Vercel 生产已通过。
