# 新增定时任务操作步骤

> 适用范围：腾讯云定时云函数触发的后端任务接口。唯一现役样板：`src/app/api/notifications/cleanup/route.ts` + `scripts/cloudbase/notifications-cleanup/index.js`。严禁恢复已退出的 `vercel.json` Cron 配置。

1. **先定契约、幂等策略与唯一负责人**
   - 动手前明确：任务中文名、北京时间触发周期、重复触发时的幂等策略、以及**唯一负责人**（谁看告警、谁负责修与下线）。
   - 上线前同步登记进[上线与运维·定时任务](上线与运维.md#现行-运维)（写明云函数名、周期、接口路径、开关名与负责人）。

2. **建触发接口并接统一密钥鉴权**
   - 在 `src/app/api/<领域>/<任务>/route.ts` 建路由，入口首行调用 `isCronAuthorized(request)`（`src/lib/cron-auth.ts`），兼容定时云函数的 `Authorization: Bearer <CRON_SECRET>` 与手动演练 `?secret=`；未通过直接返回 `401`。
   - `src/app/api/route-auth.coverage.test.ts` 已把 `isCronAuthorized` 纳入统一鉴权清单，无需加进 `PUBLIC_ROUTES`。

3. **加不用发版就能关掉的开关**
   - 在 `system_settings` 表约定布尔键（参考 `src/app/api/admin/system/settings/route.ts` 的 `feishu_fulfillment_reminder_enabled`），由服务端 `createAdminClient()` 读取；为 `false` 时跳过核心逻辑并返回 `200 { ok: true, skipped: true, reason: "disabled" }`。
   - 线上紧急止血两道开关：优先把 `system_settings` 对应键切为 `false`（后台系统设置或经审批改配置，免发版生效），次选在腾讯云云函数控制台直接禁用定时触发器。

4. **用 `zod` 校验手动触发参数与日期**
   - 手动补跑或演练常带 `dryRun`、`date` 等查询参数或 JSON 正文，统一用 `zod` 的 `safeParse` 校验，非法参数在碰库前返回 `400`。
   - 所有业务日期计算一律走 `src/lib/business-time.ts`（北京时间），严禁手写 `+08:00` 或用 `toISOString().slice(0, 10)`。

5. **带 `requestId` 观测、超时与失败告警**
   - 外层用 `createRequestContext({ request, route, operation })`（`src/lib/request-context.ts`）+ `observeRequest(context, handler)`（`src/lib/observability.ts`），把 `x-dydata-request-id` 带回响应头并写入 `src/lib/api-logger.ts` 结构化日志；长查询或外部调用套 `withTimeout`（`src/lib/timeout.ts`）。
   - 执行失败时调用 `reportCronFailure("<任务中文名>", error)`（`src/lib/cron-failure.ts`）上报 Sentry 并触发 `FEISHU_ALERT_WEBHOOK_URL` 告警；HTTP 响应走 `toStringErrorResponse`（`src/lib/errors.ts`），带 `requestId` 且不泄露数据库原始报错。

6. **建腾讯云定时云函数脚本**
   - 在 `scripts/cloudbase/<任务目录>/index.js` 参照 `scripts/cloudbase/notifications-cleanup/index.js` 编写触发器：从环境变量读 `TARGET_URL` 与 `CRON_SECRET`，发带 `Authorization: Bearer` 与超时限制的请求，非 2xx 抛错让云函数平台记失败。
   - 腾讯云云函数触发器使用 7 位北京时间 cron（如每日 02:00 为 `0 0 2 * * * *`）；若新增应用环境变量，同步登记进 `.env.example`（标明 `[必填]` 或 `[可选]`）。

7. **补齐同目录失败路径测试**
   - 在同目录建 `route.test.ts`，覆盖并断言 4xx/5xx（满足 `scripts/api-failure-path-gate.mjs`）：未带/错密钥返回 `401`、非法参数返回 `400`、开关关闭时跳过核心逻辑返回 `200`、数据库/外部依赖失败时调用 `reportCronFailure` 并返回 `500` 且不含原始 SQL 文本。
   - 禁止新增读源码文字测试（`scripts/source-text-test-gate.mjs` 拦截）。

8. **跑齐本地门禁与上线首跑核对**
   ```sh
   npx tsx --test <新任务测试路径> src/lib/cron-auth.test.ts
   npm run gate:static
   npm run build
   node scripts/cloudbase/check-env-vars.mjs
   ```
   - 发版并配置云函数后，用 `Authorization: Bearer <CRON_SECRET>` 手工触发一次，核对返回 `x-dydata-request-id` 与云托管日志能串上。

9. **下线办法（退场四步，不留孤儿调度）**
   1. 先关开关（`system_settings` 置 `false`）并在腾讯云云函数控制台禁用定时触发器，观察一个周期确认零触发；
   2. 删除腾讯云云函数与触发器，删除仓库 `scripts/cloudbase/<任务目录>/` 与 `src/app/api/<领域>/<任务>/` 路由及测试；
   3. 若有专属环境变量，待去掉代码读取的新版本线上稳定后，再删云托管配置与 `.env.example` 对应行；
   4. 从[上线与运维·定时任务](上线与运维.md#现行-运维)移除并记入[工程底座·已废弃](工程底座.md#现行-已废弃)，当天写进 `日志/YYYY-MM-DD.md`。
